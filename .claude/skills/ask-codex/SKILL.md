# Codex とディスカッションする

Claude 1 人の視点だけで考えると、同じ仮定の上で堂々巡りになりやすい。詰まったら Codex に読み取り専用で質問し、反論を受けて考え直す。Codex はリポジトリを読めるが、ファイルは書き換えない（sandbox は `read-only`）。

ラッパー: `.claude/scripts/ask-codex.sh`（モデルは `CODEX_MODEL`、既定 `gpt-6.2-sol`）。

## いつ相談するか

- 実験の結果が仮説と合わず、原因の候補を絞れない
- 同じ問題で 2 回以上手を変えても改善しない
- 結果の読み・指標の解釈・学習則の数理に自信がない
- 次の実験を登録する前に、仮説と判定条件の穴を探したい
- ユーザーに「codex に聞いて」と言われた

trivial な作業や、コードを読めば分かる事実の確認には使わない。

## 手順

### 1. 質問を書く

Codex は会話の経緯を知らない。質問だけで判断できるよう、次を入れる。

- 目的と仮説（何が分かれば支持/棄却か）
- やったことと結果の数字（表のまま貼ってよい）
- 自分の今の解釈と、それに自信がない理由
- 読むべきファイルのパス（`exp/<name>/README.md`、関連するコード）
- 聞きたいこと（「原因の候補を挙げて」「この解釈の穴を指摘して」など、具体的に）

結論を誘導しない。自分の仮説を「正しいか確認して」ではなく「反例や別の説明はあるか」と聞く。

### 2. 聞く

長い質問は heredoc で stdin から渡す。推論に時間がかかる（xhigh では数分〜10 分超）ので、**Bash の `run_in_background: true` で実行し**、完了の通知を待つ。

```bash
.claude/scripts/ask-codex.sh <<'EOF'
（質問）
EOF
```

- 最後の行に `codex-thread: <id>` が出る。続けて話すときはこの id を使う
- 推論の深さは `-e low|medium|high|xhigh`（省略時は `~/.codex/config.toml` の設定）。軽い確認は `-e low`
- worktree の中で実行すると、Codex はその worktree を読む

### 3. 議論を続ける

Codex の答えを鵜呑みにしない。根拠をコードや数字と突き合わせ、同意できない点は反論を返す。

```bash
.claude/scripts/ask-codex.sh -r <id> <<'EOF'
（反論・追加の数字・次の問い）
EOF
```

意見が割れたら、どちらが正しいかを決める実験や確認を一緒に設計する。決着しないままの論点は、どちらの説も書いてユーザーに渡す。

### 4. 残す

- 議論で決まったこと・採った案と退けた案は、実験の `README.md` や memory に、自分の言葉で残す（「Codex がこう言った」ではなく、根拠ごと）
- ユーザーへの報告では、Codex に相談したこと、主な指摘、それをどう扱ったかを短く書く

## 注意

- 質問の内容（リポジトリの中身を含む）は OpenAI に送られる。秘密情報・個人情報を質問に入れない
- Codex に編集させない。修正は Claude が自分で行い、CLAUDE.md の規約と検証の手順に従う
- `codex` が無い・認証が切れているときは、ラッパーがエラーを出して止まる。そのときはユーザーに伝える
