# 実験の結果を 1 枚の HTML 資料にまとめる

実験の `README.md` は数字の記録で、読み手は実験した本人を想定している。この skill で作る `report.html` は、実験に関わっていない人が上から読んで「何をして、何が分かったか」を掴むための資料にする。手本は [exp/video/report.html](../../../exp/video/report.html)。迷ったらこれを開いて構成と書き方を真似る。

関連: skill [yomiyasu](../yomiyasu/SKILL.md)（日本語の推敲。**必須**）、skill `dataviz`（グラフの形と色を選ぶとき）。

## 守ること

- **数字は `README.md`（とそこからリンクした `results/`）と `runs/` にあるものだけを使う**。資料のために新しく計算した値（比、平均など）は、元の数字と計算方法を図の説明に書く。推測で埋めない
- **1 ファイルで完結させる**。データは `<script type="application/json" id="data">` に埋め込み、グラフは素の JavaScript と SVG で描く。外部から読むのは Google Fonts のスタイルシートだけにする（オフラインでもフォールバックのフォントで読める）
- **生成スクリプトや抜き出した JSON は commit しない**。scratchpad に置く。commit するのは `report.html` と、`README.md` からのリンクだけ
- 重い元データ（動画のフレーム全体、全ステップのログ）はそのまま埋め込まない。間引く、区間を切る、状態から描き直すなどで、ファイルを数 MB 以下に保つ（手本は約 300 KB）
- **日本語の本文は書き終えたら必ず skill yomiyasu で推敲する**（手順 5）。yomiyasu を通していない資料を commit しない

## 構成

手本の順序を基本にする。実験に無い節は省いてよいが、「結論を先に」と「再現の付録」は必ず入れる。

| 節                   | 中身                                                                                                                                   |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| ヘッダー             | eyebrow（`mujou-exp · exp/<name> · 期間`）、`h1` は実験の問いを平たく言ったもの、リード文 2〜3 文、メタ情報（学習則、mujou の SHA、PR 番号、計算環境）、目次 |
| 分かったこと         | 結論を 2〜4 枚のカードで。各カードに対応するマイルストーン（`M9` など）と、1〜3 文の結果を書く                                       |
| 実験の仕組み         | モデルとノードの構成図（インライン SVG）。続けて「指標の読み方」を `dl` で。指標ごとに、何を測り、大きい／小さいどちらが良いかを書く |
| 入力                 | 入力データが目に見えるもの（動画・画像）なら、実際に見られるようにする（canvas で再生、区間の切替、スクラブ）                         |
| 進め方               | マイルストーンの時系列。計画の順序と変わった点があれば理由を書く                                                                       |
| 結果の節（複数）     | 1 つの問いに 1 節。「問い → 図 → 図から読めること」の順。節の eyebrow にマイルストーンを書く                                         |
| 仮説の判定           | 表で、仮説・判定（`chip` の 支持 / 棄却 / 保留）・根拠の数字。判定の閾値を実行前に決めたことを書く                                   |
| 次に持ち込むもの     | 次の段で使う設定と、残る課題                                                                                                           |
| 付録: 再現           | mujou の SHA、run を作ったコマンド、数字の在りか（`README.md`）                                                                         |

## 図と表

- 図の種類は言いたいことから選ぶ。時間の推移は折れ線、条件の比較は点（seed ごとの点を並べる dot plot）、成否の一覧は表、1 つの数字の強調はタイル。迷ったら skill `dataviz` を読む
- すべての図に `fig-title`、凡例、`figcaption` を付ける。`figcaption` には**条件**（seed 数、時間、固定したハイパーパラメータ、評価の間隔）と、図の読み方（「左ほど良い」「線が切れているのは発散」）を書く
- 触れると値が出るようにする（折れ線は十字線と全系列の値、点は個々の値）。ただし、触らなくても本文と図だけで結論が読めるようにする
- seed ごとのばらつきは平均で潰さず、点や細い線で全部見せる
- 崩壊・発散・NaN の run は図から消さず、途切れた線や「発散」の表記で残す

## 見た目

手本の `<style>` を出発点にコピーしてよい。押さえる点は次のとおり。

- 色は `:root` のトークン（`--bg`、`--ink`、`--s1`〜`--s4`、`--good` / `--bad` / `--warn` など）で定義し、ダークモードを `@media (prefers-color-scheme: dark)` の `:root:not([data-theme="light"])` と `:root[data-theme="dark"]` の両方で上書きする。`body` に背景色を明示する
- 本文の列幅は約 46rem、図は 60rem まで広げる。幅 560px 以下でも横スクロールが出ないようにする（左右 16px の余白、表と図は `overflow-x: auto` の箱に入れる）
- フォントは本文が Zen Kaku Gothic New、数字とコードが IBM Plex Mono（`font-variant-numeric: tabular-nums`）
- 系列の色は資料全体で意味を固定する（例: SGD はいつも `--s1`）

## 文章

- 読み手は「機械学習は分かるが、この実験は知らない人」。初出の用語（`preq`、`stop_target`、κ など）はその場で説明するか、「指標の読み方」に入れる
- 文末は「です・ます」。1 文に 1 つのことを書く
- 結果の節では図の前に問いと条件、図の後に「図から何が言えるか」を数字つきで書く。図に描いていない主張を足さない
- 不都合な結果（仮説の棄却、発散、未解決の課題）も同じ重さで書く

## 手順

### 1. 材料を集める

`exp/<name>/README.md` とそこからリンクした `results/`（数字の正）、`PLAN.md`、`MILESTONES.md`、`runs/` の中身を読み、どの節にどの数字と図を置くかを決める。`runs/` に必要なログが無ければ、run をやり直す前にユーザーに確認する。

### 2. データを抜き出す

scratchpad に Python のスクリプトを書き、`runs/` から図に要る値だけを 1 つの JSON にまとめる。浮動小数点は有効数字 4〜5 桁に丸めてサイズを抑える。スクリプトは `uv run python` で動かす。

### 3. HTML を書く

構成の表に沿って `exp/<name>/report.html` を書く。手本の `lineChart` のような小さな描画関数を作って使い回し、図ごとに描画コードを書き散らさない。JSON は手順 2 の出力を `<script type="application/json" id="data">` に流し込む（手で貼らず、スクリプトで HTML に差し込むと作り直しが楽）。

### 4. 確かめる

- 本文と図の数字を `README.md` と突き合わせる（seed、条件、桁）
- ブラウザで開き、ライトとダーク、幅 375px 前後で崩れないか、コンソールにエラーが出ないかを見る。ブラウザが使えない環境なら、その旨をユーザーに伝えて確認を頼む
- ファイルサイズを確認する（`wc -c`）

### 5. yomiyasu で推敲する（必須）

日本語の本文（リード文、カード、本文、図の説明、表の根拠）を skill yomiyasu で推敲する。Skill ツールで `yomiyasu` を呼び、HTML から抜き出した本文を渡し、推敲後の文を HTML に戻す。数字・コード・用語は変えない。推敲で意味が変わっていないかを、手順 4 と同じく `README.md` と突き合わせて確かめる。

### 6. リンクして commit する

`exp/<name>/README.md` の冒頭付近に、資料の範囲（どのマイルストーンか）と開き方を 1 文で書いてリンクする（手本: 「M6〜M10 の結果を、入力の動画とグラフで読める 1 枚のページにまとめたものが [report.html](report.html)」）。`just run` を通してから `docs(<name>): add a report page of ...` で commit する。

資料を claude.ai で共有したいと言われたら、Artifact ツールで同じファイルを publish する。言われなければ publish しない。
