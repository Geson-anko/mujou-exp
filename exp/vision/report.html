RMSProp（τ = 104）は、3 つの seed と 3 つの σ² のすべてで学べました。AdamW（τ = 105）も学べました。SGD は、学習率・momentum・モデル・stack の枚数・σ² のどれを変えても学べませんでした（14 設定）。

1

実験の仕組み

入力は、0.1 秒ごとの 8 枚の画像（64×64 ピクセル）を積み重ねたもので、これを stack と呼びます。stack は 0.1 秒ごとに 1 つ届きます。同じ stack が 2 度来ることはありません。

モデルは 8 つのノードに分かれています。エンコーダ（ViT-S を 4 つに分けたもの）が stack を潜在変数 z（256 次元）に写し、デコーダが z から最後の 1 枚を描き戻します。各ノードは、隣のノードと値と誤差だけをやり取りします。そして、1 フレーム（0.1 秒）に 1 回、自分の誤差で重みを更新します。ネットワーク全体をまたぐ誤差逆伝播はしません。

指標の読み方

誤差は、どれも「平均の stack を出したときの誤差」を 1 とする比で表します。1 を下回れば、どの入力にも平均の画像を出すより良いということです。

システムの
デコーダの誤差
学習しているモデルそのもの（エンコーダ → z → デコーダ）が、stack をどれだけ描き戻せるかです。小さいほど良い。V1〜V7 では学習に使わない Zurich の動画で測り、stack_mse と呼びました。V8 では学習のストリームで測り、学習した区間のものを span、その後の区間のものを after と呼びます。
学習中の誤差
stack が流れてきた瞬間の、まだその stack で学ぶ前の誤差です（pre）。走りながらの成績にあたります。
recon_blur
止めたエンコーダの z から、別に学んだデコーダで最後の 1 枚を描き戻したときの誤差です（ぼかした画像どうしで比べます）。小さいほど、z に入力の情報が残っている。4 つの seed で当てはめ、平均と標準偏差を出します。
dyn_1/copy_1
z の 0.1 秒先を線形の式で予測したときの誤差を、「変わらない」と予測したときの誤差で割ったものです。小さいほど、z の動きを予測しやすい。ただし、z がほとんど動かなくなっても下がります（V2〜V5）。
rank
z の実効ランクです。z がいくつの方向に広がっているかを表します。小さすぎるときは、z の広がりが失われています。
dec_spread
評価の窓をまたいだ、システムのデコーダの出力のばらつきです。0 に近ければ、どの入力にも同じ画像を出しています（V2〜V7）。
忘却
過去の stack の今の誤差から、その stack が流れたときの学習中の誤差を引いたものです。小さいほど、忘れていない。負なら、流れたときより今の方がよく描けます（V8）。
τ
optimizer の時定数で、学習率の逆数にあたります。大きいほど、ゆっくり学ぶ。RMSProp と AdamW では、1 回の更新で各重みが動く量が約 0.1/τ になります。

SGD で学べる学習率はあるか

問い　出発点の設定（ViT-S、8 枚、SGD）で、1800 秒のあいだ発散せずに学べる τ はあるか。

条件　τ = 104、105、106、107、seed 0、1800 秒。Zurich の 10 個の窓で、0・60・300・600・1200・1800 秒のチェックポイントを評価しました。

図から読めること

  • τ = 105 と 106 は、最初の 60 秒で 6.7 から 1.2〜1.4 まで下がりますが、その後は 1 を上回ったまま上下します（1800 秒で 1.518、1.492）。
  • 当時の 3 条件（stack_mse・recon_blur・dyn_1/copy_1 が 0 秒より下がる）は、τ = 105 と 106 で満たしました。τ = 107 は dyn_1/copy_1 で外れました。

分かったこと　「初期化より下がる」という条件を満たしても、システムのデコーダは入力を描き戻していませんでした。そこで V2 から、「誤差が 1 より小さい（平均の画像より良い）」を判定の条件に足しました。z の実効ランクは 80.6 から 10.2 まで縮みました。

問い　モデル、momentum、stack の枚数、optimizer のどれかを変えると、学べるようになるか。

条件　V1 の τ = 105 の SGD を出発点にし、1 つの設定だけを変えました（seed 0、1800 秒）。ResNet-S と ResNet-L は τ = 105 で数秒のうちに発散したので、τ = 106 で回し直しました。V6・V7 の run も、同じ図に並べます。

判定　1800 秒の時点で次の 4 つをすべて満たせば「学べた」とします。stack_mse が 0 秒より小さく、1 より小さい。recon_blur の差が、標準誤差を合わせたものの 2 倍より大きい。dyn_1/copy_1 が 0 秒より小さい。

  • V2〜V5 で学べたのは、RMSProp τ = 104 の 1 本だけです（stack_mse 0.640）。
  • ほかの run は stack_mse が 1 を上回ります（1.03〜1.59）。モデルを大きくしても、momentum を足しても、stack の枚数を変えても、1 を下回りません。
  • ResNet は、recon_blur が 0.40〜0.48 で、ViT（0.21〜0.22）より大きくなりました。dyn_1/copy_1 も 0 秒より上がりました。

KL と再構成の釣り合いが効いているのか

背景　VAE の損失では、再構成の誤差を σ²（出力の分散）で割ります。σ は学習で決まるので、σ² が大きいほど KL の重みが相対的に強くなります（σ = 1 の β-VAE の β = 2σ² にあたります）。下の図のとおり、学習の終わりの σ² は、SGD と RMSProp で大きく違っていました。RMSProp で学べた理由が optimizer にあるのか、σ² の違いにあるのかを、分けて調べる必要があります。

図から読めること

  • SGD の σ² は、1 秒ごとに大きく揺れます。V1 の τ = 105 では、600 秒以降も 0.003〜0.11 の間を行き来します。τ = 105〜106 の SGD の run（V1〜V4）では、最後の 60 秒の平均は 0.025〜0.029 です。README の V2〜V5 に書いた「1800 秒の σ²」（0.006〜0.011）は、1800 秒ちょうどの 1 点の値で、平均より低めに出ていました。
  • RMSProp τ = 104 の σ² はほとんど揺れず、0.054 に落ち着きます。τ = 105 の RMSProp と AdamW では、σ² は初期値からほとんど動いていません（0.073）。
  • どちらにしても、σ² は SGD より RMSProp の方が約 2 倍大きく、KL の重みは RMSProp の方が相対的に強くなっています。
  • 学習の最後の 60 秒の KL は、どの run でも約 300〜800 nat あります。潜在変数はつぶれていません。

やったこと　σ を学ばず、σ² を 0.01・0.03・0.1 に固定して、SGD と RMSProp のそれぞれで回しました（seed 0、1800 秒）。0.01 は README で SGD の値として読んだもの（上のとおり 1 点の値）、0.03 は SGD の平均に近い値、0.1 は RMSProp の値より大きい値です。3 つとも試したので、この比べ方の結論は、σ² の読み違いに左右されません。

反証の規則　SGD の 0.1 で学べたら、RMSProp で学べたのは主に釣り合いの効果とみなします。RMSProp の 0.01 でも学べたら、optimizer の効果とみなします。

分かったこと　RMSProp の 0.01 でも学べたので、事前に決めた規則により、RMSProp で学べたのは釣り合いではなく optimizer の効果とみなします。RMSProp は、σ² を 10 倍の範囲で変えても stack_mse（0.654〜0.678）も recon_blur（0.228〜0.232）もほとんど変わりません。SGD は、σ² を V1 の 10 倍にしても、デコーダが z を使いませんでした。SGD の 0.01 と 0.03 の発散は予想していませんでした。σ を固定すると、最初から再構成の勾配が 0.0743/σ² 倍になり、τ = 105 では大きすぎたためと考えられます。

学習のストリームそのもので評価し直す

なぜ評価をやり直したか　V1〜V7 では、学習を止めたモデルを、学習に使わない Zurich で評価しました。しかし、ストリームから学ぶとは、学び続けることです。そこで、学習に使ったデータ全体で評価することにしました。過去の stack の誤差が大きければ、忘れています。未来の stack の誤差が小さければ、汎化しています。今の stack の誤差は、ある程度学ぶまで意味を持ちません。

やったこと　V1〜V7 で発散しなかった 26 設定を、チェックポイントを 60 秒ごと（31 個）にして回し直しました。学習の設定は変えていません（V7 の run と、それを回し直した V8 の run で、1800 秒の値が完全に一致しました）。各チェックポイントで、学習区間の 5 秒ごとの stack（360 個）と、その後の 3000 秒の 10 秒ごとの stack（300 個）の誤差を測りました。

判定　1800 秒の時点で次の 4 つをすべて満たせば「学べた」とします。

  1. span の誤差が 0 秒より小さく、1 より小さい
  2. after の誤差が 0 秒より小さい
  3. span の recon_blur が、0 秒より、標準誤差を合わせたものの 2 倍を超えて小さい
  4. span の dyn_1/copy_1 が 0 秒より小さい

図から読めること

  • 学べたのは 7 本で、Zurich で判定した V2〜V7 と同じ run でした（RMSProp τ = 104 の 3 つの seed と 3 つの σ²、AdamW τ = 105）。span は 0.71〜0.78、after は 0.72〜0.81 です。
  • SGD の 14 本は、どれも span が 1 を上回りました（1.06〜1.91）。
  • RMSProp τ = 105 は、V6 と同じく dyn_1/copy_1 だけが下がりませんでした（0.994 → 1.005）。
  • 300 秒以上前の忘却は、RMSProp τ = 104 の 6 本で 0.24〜0.29、SGD τ = 105 で 1.33 でした。SGD にも忘却の小さい run が 2 本あります（momentum τm = 10 秒の 0.03、SGD τ = 107 の 0.52）。どちらも学ぶのが遅く、span は 1 を下回りません。
26 本の判定の表をすべて見る

今（学習中）: 1800 秒の直前 10 秒の stack の誤差。括弧の中は、その stack が流れたときの学習中の誤差。忘却: 見た時期ごとに、1800 秒の誤差から、流れたときの学習中の誤差を引いたもの。recon_blur の括弧の中は、0 秒からの差と閾値。判定の × の括弧は、満たさなかった条件（span_lt1: span < 1、dyn_down: dyn_1/copy_1 が下がる）。

学習の経過

図から読めること

  • SGD は、止めたモデルで測ると 300 秒までに約 1.7 まで下がって止まり、その後はチェックポイントごとに 1.3〜2.7 と大きく揺れます。しかし学習中の誤差は 0.2〜0.5 と小さく、RMSProp と同じくらいです。走っている最中は描けるのに、止めると描けません。
  • RMSProp τ = 104 は、最初の 60 秒で 2 を下回り、その後も下がり続けます。ときどき大きく上がります（1140 秒、1500 秒）。
  • τ = 105 の RMSProp と AdamW は、なめらかにゆっくり下がり、900 秒ごろに RMSProp τ = 104 に並びます。
  • 学べた run は、1800 秒でもまだ下がっています。RMSProp τ = 104 は、1500 秒の 0.85 から 1800 秒の 0.71 まで下がりました。
  • span と after は、どの run でも、どのチェックポイントでもほぼ同じ値でした。学習区間だけに合わせた覚え方はしていません。

何を覚え、何を忘れているか

問い　SGD のデコーダは「今の場面を重みで追っている」のか。学べた run は、学んだものをどれだけ残しているか。チェックポイント × stack の誤差の表を、いくつかの切り口で見ます。この節の値は、判定には使っていません。

図から読めること　SGD では、T の瞬間の stack だけ誤差が小さく（T = 900 秒で 0.26）、5 秒前・5 秒後の stack では 1.6〜1.8 に戻ります。スライダーを動かすと、この谷もチェックポイントに合わせて動きます。RMSProp τ = 104 にも谷はあります（T = 900 秒で 0.33）が、それ以外の stack でも 1 前後か、それを下回ります。

図から読めること

  1. 相対時刻 0 の誤差は、学習中の誤差とほぼ同じです。SGD は 0.31、RMSProp τ = 104 は 0.33 で、同じ時期の学習中の誤差（0.31、0.35）とほぼ同じでした。止めたモデルの誤差と学習中の誤差は測り方が違いますが、その差は小さいので、「忘却」の値はそのまま読めます。
  2. SGD は数秒で忘れます。5 秒離れると 1.19、10 秒で 1.51、それより遠くでは 1.6〜1.8 になります。過去と未来がほぼ対称で、過去の方が良いということがありません。SGD の重みにあるのは今の場面だけです。
  3. RMSProp τ = 104 も今の場面を重みで追いますが、それとは別に残るものがあります。相対時刻 0 で 0.33 まで下がり、離れても 0.8〜1.0 にとどまります。60 秒より前（0.91〜0.95）と 60 秒より先（0.98〜1.00）の差は小さく、学んだものの多くは、まだ見ていない場面にも効きます。
  4. τ = 105 の RMSProp と AdamW は、今の場面を追う力が弱く、そのぶん忘れにくい run です。相対時刻 0 での下がりは小さいです（0.65、0.74）。

図から読めること　RMSProp τ = 104 は、2 分後に +0.11 ですが、10〜20 分後に −0.28、20〜30 分後に −0.55 です。長い目で見ると、前に見たものもよく描けるようになります。SGD は、2 分後以降ずっと +0.18〜+0.31 です。τ = 105 の RMSProp と AdamW が −2 まで下がるのは、学習の初めに見た stack を、見た直後（まだ学べていない時期）より今の方がずっとよく描けるからです。

長く学ぶと、どこまで下がり、何が残るか

問い　V8 で学べた run は、1800 秒の時点でも誤差が下がり続けていました。そこで、run を 6000 秒に延ばしました。調べるのは、学び続けると誤差がどこまで下がるかと、別の都市の動画を学んだ後も Amsterdam で学んだものが残るかの 2 点です。

条件　RMSProp τ = 104、AdamW τ = 105、対照の SGD τ = 105 を、seed 0 で 1 本ずつ回しました。ストリームは動画を名前順につないだもので、Amsterdam は 0〜4912 秒です。6000 秒の run は、次の動画の最初の約 1090 秒も学びます。評価は V8 と同じで、学習区間（span）は 0〜6000 秒、その後の区間（after）は 6000〜9000 秒です。判定も V8 と同じ 4 条件で、6000 秒と 0 秒を比べます。

  • RMSProp と AdamW は 4 条件を満たし、span は 0.520 と 0.472 まで下がりました。予想（0.6 を下回る）のとおりです。
  • SGD は 6000 秒でも span が 1 を上回りました（1.816）。60 秒以降のどのチェックポイントでも 1 を下回りません。
  • 最後の 1200 秒でも、span は RMSProp で 0.656 → 0.520、AdamW で 0.507 → 0.472 と下がりました。どちらも頭打ちにはなっていません。ただし AdamW は、下がり方が小さくなってきています。

図から読めること

  • 別の都市を学んでも、Amsterdam で学んだものは消えませんでした。RMSProp と AdamW では、Amsterdam の最初の 1800 秒の誤差が、1800 秒 → 4860 秒（次の動画に入る直前）→ 6000 秒で、0.695 → 0.673 → 0.539、0.747 → 0.499 → 0.481 と下がりました。次の動画を約 1090 秒学んだ後も上がっていません。回す前に決めた破滅的忘却の条件（6000 秒の値が 1800 秒の値を上回る）には当たりません。
  • まだ見ていない都市も、学んだ都市とあまり変わらない誤差で描けます。次の動画の誤差は、まだ見ていない 4860 秒の時点で、同じ時点の Amsterdam よりわずかに大きいだけでした（RMSProp 0.745 対 0.673〜0.692、AdamW 0.507 対 0.493〜0.499）。学んだ後の 6000 秒では下がりました（0.450、0.426）。
  • SGD は、どの区間も 1.2〜2.8 の間で揺れ続けます。
  • SGD は、V8 と同じく今の stack だけを描けます（0.33）。5 秒離れると 1 を超えます。
  • RMSProp は、今の場面の小さな誤差（0.33）を保ったまま、それ以外の誤差が V8 の 0.8〜1.0 から 0.5〜0.8 まで下がりました。
  • AdamW では、今の場面だけ誤差が小さくなることはありません（−10〜0 秒で 0.53）。今の場面を重みで追わず、過去（0.53）も近い未来（0.62〜0.65）も、同じ程度の誤差で描きます。

まとめ　学び続けると、RMSProp も AdamW も誤差が下がり続けました。別の動画に入っても、前に学んだ Amsterdam の誤差は上がらず、さらに下がりました。この長さでは、破滅的忘却は見えません。1800 秒の時点では RMSProp τ = 104 の誤差が最も小さかったのですが、6000 秒では AdamW τ = 105 の方が小さくなりました。ただし、どちらも seed 1 本の結果です。

エンコーダの種類と大きさを変えると

問い　V2 では、エンコーダの種類（ViT・ResNet）と大きさ（S・M・L）を SGD で比べたため、どのモデルも学べず、違いを読めませんでした。V8 で学べた最良の設定（RMSProp τ = 104）で比べ直します。

条件　5 つの腕（ViT-M・L、ResNet-S・M・L）を seed 0・1・2 で回しました（15 本）。ViT-S は同じ設定の V8 の 3 本を使います。1800 秒、チェックポイントは 60 秒ごとです。デコーダはどの腕でも同じです。エンコーダのパラメータ数は、S が ViT 6.83M・ResNet 5.91M、M が 9.99M・9.44M、L が 16.31M・16.50M です。

判定　run ごとに V8 の 4 条件で判定し、3 seed がすべて満たせば、その腕は「学べた」とします。2 つの腕の値は、3 seed の範囲（最小〜最大）が重ならないときだけ「違う」とします。τ = 104 で発散した腕は τ = 105 で回し直す予定でしたが、発散した run はありませんでした。

図と表から読めること

  • 学べたのは ViT だけでした。ViT-S・M・L は 3 seed とも 4 条件を満たしました。ResNet-S・M・L は 3 seed とも、span が 1 を下回らず（1.329〜1.658）、dyn_1/copy_1 も 0 秒より上がりました。どの run も発散はしていません。
  • ViT-M は ViT-S と区別できません。4 つの値のどれでも、3 seed の範囲が重なります。
  • ViT-L は ViT-S より悪くなりました。span（0.792〜0.927）と 300 秒以上前の忘却（0.32〜0.46）で、ViT-S と範囲が重なりません。after と recon_blur は重なります。
  • ResNet は、すべての値で ViT より悪くなりました。recon_blur は 0.618〜0.679 で、ViT（0.439〜0.470）より大きく、画像がぼやけています。ResNet の中では、span で L が S より悪く、範囲が重なりません。
  • ViT は、どの大きさも 1800 秒まで下がり続けています。ViT-L は 1000 秒ごろから S・M より高い値で推移します。ただし、1800 秒の値はチェックポイントごとの揺れが大きく（ViT-S は 1500 秒で 1.00〜1.04、1800 秒で 0.71〜0.78）、1500 秒より後の 5 個の平均では、ViT-L（0.833〜0.949）と ViT-S（0.783〜0.853）の範囲は重なります。ViT-L が悪いという判定は 1800 秒の値では成り立ちますが、差は小さいものです。
  • ResNet は 300〜500 秒までに下がった後、それ以上は下がりません。最も小さい span は 1.06〜1.32 で、9 本のうち 6 本は 360〜480 秒に出ました。V8 の SGD の run と同じく、1 より上で止まります。
  • 誤差が上がる時刻と下がる時刻は、すべての run でそろっています。直前に流れた場面によって、どの run の誤差も同じように上下します。

まとめ　RMSProp τ = 104 で学べたのは ViT だけでした。ResNet は発散しませんが、span は 1 を下回らず、z の時間の動き（dyn_1/copy_1）も学べません。モデルを大きくしても良くならず、L はどちらの種類でも S より悪くなりました。ViT-S を上回る腕はないので、回す前に決めたとおり、出発点は ViT-S のままにします。今の限界は、エンコーダの大きさ以外のところ（デコーダの形、run の長さ）にあるとみなします。

なお、ResNet について言えるのは「τ = 104 では学べない」ことまでで、「ResNet では学べない」とは言えません。学習率は発散しないことだけを基準に選ぶ方針なので、発散しなかった τ = 104 の結果を、この比べの答えとしました。

次に持ち込むものと、残る課題

持ち込むもの　出発点は ViT-S、RMSProp τ = 104 のままにします。評価は、V8 と同じ学習のストリームでの評価にします。AdamW τ = 105 は、6000 秒では RMSProp より誤差が小さかったので（seed 1 本）、長い run の候補として seed を足して確かめます。

まだ分からないこと

  • なぜ RMSProp で学べるのか。RMSProp は、重みごとに一歩の大きさをそろえます。そのため、勾配の小さい「z からデコーダへの経路」の重みも動けるようになる、という説明が考えられます。まだ確かめていません。
  • なぜ ResNet は τ = 104 で学べないのか。ResNet-M・L では、z で使われている次元（rank）が 1.9〜5.3 と、ViT（19.7〜23.8）より少なくなっています。学習率は発散しないことだけを基準に選ぶ方針なので、τ を変えた比べはしていません。
  • 画像はまだぼやけています。学べた run でも、システムのデコーダが描けるのは明暗の大まかな配置だけです。限界はエンコーダの大きさ以外（デコーダの形、run の長さ）にあるとみなしています。
  • stack の枚数は SGD でしか比べていません。RMSProp で回し直す必要があります。
  • 計画にある評価が未実施です。未実施なのは、拡散モデルのデコーダ（細部が z に残っているか）と、Imagenette での linear probe です。
