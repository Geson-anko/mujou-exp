01

何を学ばせているか

なぜここから始めるのか

この実験では、評価の物差しを学習の目的に合わせて選びます。そのため、まず学習が何を目指しているかを押さえます。

入力：動画の短い切れ端

データは、街を歩きながら撮った動画です。連続する 8 フレーム（0.8 秒分）を 64×64 画素に縮めて重ねたものを、1 つの入力にします。この単位を stack と呼びます。学習には Zurich 以外の動画を使い、Zurich の動画は評価だけに使います。

トークン・エンコーダ・予測器

stack を 8×8 画素の小区画（パッチ）に切ると、縦横 8 個ずつ、計 64 個になります。各パッチの画素を並べたベクトルを、トークンと呼びます。

エンコーダは、64 個のトークンを受け取り、位置ごとに 1024 個の数の並び（ベクトル）を出すネットワークです。このベクトルを「表現」と呼びます。表現は、その場所に何が写っているかを数で表したものです。

学習では、画像の一部を隠します。隠し方は、画像を 4×4 の粗いマスに分け、そのうち 4・8・12 マスを隠すというものです（隠す割合 r = 0.25・0.5・0.75）。1 マスは 2×2 のパッチなので、隠すトークンは 16・32・48 個になります。

予測器は、見えている部分の表現から、隠した位置の表現を推し量る小さなネットワークです。

的（正解）と損失

予測の的は、全体を見たエンコーダの出力 hp（1024 次元）を、固定の乱数の行列 R で 16 次元に縮めた tp = R hp です。R は学習しません。学習で写し方を選べると、当てやすい方向だけを残す恐れがあるからです。

損失は 2 つの項の和です。

損失 = (1 − λ) · L_pred + λ · S
  • L_pred は、隠した位置での予測と的の二乗誤差です。
  • S は SIGReg です。各 stack の 64 個の t を並べ、別の固定の乱数の行列 W で写したものを z（1024 次元）とします。SIGReg は、1 回に使う 128 個の z の分布が、標準正規分布にどれだけ近いかを測ります。崩壊（3 節）を防ぐための項です。
  • λ は、2 つの項の釣り合いを決める数です。V18c では 0.5・0.8・0.95 を試しました。

なぜ画素ではなく表現を当てるのか

画素には、見えている部分からは決まらない細部が多く含まれます。葉の一枚一枚の形や、通行人の正確な位置などです。画素を当てさせると、モデルは当てられない細部にも力を割きます。表現を当てさせると、モデルは予測できる内容、つまり場面の構造や種類のような抽象的な特徴に集中できます。これが JEPA（Joint-Embedding Predictive Architecture）の考え方です。

学習の単位: 重みを 1 回更新することを 1 step と呼び、1 回に 128 個の stack を使います。長い run は 60000 step 学びます。学習の途中で保存した重みを checkpoint と呼びます。乱数の種（seed）だけを変えて同じ設定を 2 回回し、結果の揺れを見ます。

02

評価で何を見たいか

なぜこれを決めるのか

何を測るかを先に決めないと、数値が良くなったのか悪くなったのかを言えません。物差しが学習の目的と食い違うと、正しく学べていても「悪化した」と読んでしまいます。この実験でも、実際にそうなりました。

描き戻しの誤差で起きたこと

前の V18・V18b では、表現から画像を描き戻すデコーダの誤差（recon_blur）を主に見ていました。長く学ぶと、この誤差は 6000 step から悪くなりました（パッチ 16 の run で +0.14〜+0.18）。私たちは、これを「表現が情報を失った」と読みました。

ユーザーは、描き戻した画像を見て判断しました。誤差は悪化しても、どの画像かを見分けられる程度には描けています。JEPA は細部を捨てて抽象的な特徴を残す仕組みなので、描き戻しの精度が上がることは期待できません。そのため、recon_blur を判定から外しました（2026-11-24）。

ユーザーの方針

その後、主の指標を 3 回作り直し、どれも事前の確かめで止まりました（4 節）。それを受けて、ユーザーは次の方針を示しました（2026-11-25）。

下手に人間のドメイン知識を入れても問題。マスク部の補完能力こそ真に見られるべき（未来予測タスクも含めて）。再構成も、分類も、本質的なモデルの評価とは言い難い。

この方針を、評価の決まりに直すと次のとおりです。

  • 主に見るのは、隠した部分（後には未来）を、見えている部分からどれだけ補えるかです。
  • 外部の分類器の特徴、人が付けたラベル、画素の描き戻しを、正解にしません。
  • 数値が悪化したら、学習の目的を変える前に、物差しが目的に合っているかを疑います。
評価の型正解に使うものこの実験での扱い
再構成元の画素主にしない。JEPA は細部を残すことを目指していない
分類人が付けたラベル主にしない。ラベルの粒度が場面と合わないことがある
外部の特徴での同定別に学習した分類器の特徴主にしない。物差しの側の癖が混ざる
補完の同定モデル自身が全体を見て作った表現主の候補（5〜8 節）
03

表現を当てる学習の落とし穴：崩壊

なぜこれを測るのか

表現を当てる学習には、ずるい近道があります。近道に落ちたモデルは、補完の力がなくても予測の誤差を小さくできます。補完の力を測る前に、近道に落ちていないことを確かめます。

JEPA では、正解の表現もモデル自身が作ります。そのため、エンコーダがどの画像にも同じ表現を出せば、予測は必ず当たり、L_pred は 0 になります。このように、表現が画像の違いを映さなくなることを「崩壊」と呼びます。

SIGReg は、崩壊を防ぐための項です。健全な表現なら z は標準正規分布に近く、S は約 1.05 になります。全部が同じ値なら、S は約 52.3 に大きくなります。

崩壊は、学習の最後の checkpoint で次の 3 つの量を見て検出します。どれか 1 つでも当てはまれば崩壊とします。線の値は、V18c の掃引の物差しから決まりました。

名前何を見るか崩壊とする線
K1（定数）sigreg_heldin：学習に使っていないデータで測った SIGReg の値26.69 以上
K2（次元）rank：z が実質的に使っている方向の数（実効ランク）12.5 未満
K3（stack の中で一定）token_r2：ある位置の表現から、別の位置の表現を線形に当てたときの当てはまり（全部が同じ情報なら 1、独立なら 0）0.490 以上
  • K1 の線は、健全な値 1.046 と定数の値 52.34 の中点です。
  • K2 の線は、パッチごとの平均の色を表現とみなした物差し（12.5）と、学習前の表現（95.2）の小さい方です。
  • K3 の線は、物差しの値の大きい方（−0.020）と、崩壊したときの値 1 の中点です。

的を 16 次元に縮めた理由

的を縮めずに 1024 次元のまま当てさせると、K3 の形の崩壊でも S は 1.08 にとどまり、健全な表現と区別がつきません。そのうえ L_pred は 0 になるので、K3 がどの λ でも損失の最小になってしまいます。的を 16 次元に縮めると、K3 の z は 16 方向に縮み、S は 2.9〜3.0 になります。これで λ が 0.5 以上なら、K3 は最小になりません。

V18c の掃引の 15 本（6000 step）は、どれも崩壊しませんでした。sigreg_heldin は 1.31〜1.40、rank は 119〜145、token_r2 は 0.004〜0.013 でした。

この検出で分かること

K1〜K3 は、近道に落ちていないことを確かめるだけです。通ったからといって、表現が良いとは言えません。また、見えるトークン全体で 1 つの情報を分け持つ「大域の解」は、batch 128 の SIGReg ではほとんど罰せられず、K1〜K3 でも捕まりにくい形です。これは 6 節の swap で見張ります。

これまでの 3 回の試み

なぜ経緯を知る必要があるのか

今の指標には、外部の物差しを使わない、数値を見る前に確かめ方を決める、といった特徴があります。どれも、前の 3 回の失敗を受けて決めたものです。経緯を知ると、指標の形の理由が分かります。

3 回とも、同じ手順で進めました。まず、数値を読む前に「有効性の確かめ」を決めます。これは、正解の分かっている物差し（画素の主成分分析や VAE など、情報を持つと分かっている表現）で、指標が理屈どおりの順に並ぶかを調べるものです。確かめが外れたら、その指標の数値は読まずに止めます。

05

自分の表現空間での補完の同定

なぜこれを測るのか

補完の力を、外部から何も持ち込まずに測りたいからです。正解には、同じエンコーダが画像全体を見て作った表現（本物）を使います。ただし、予測が本物に近いかだけを見ると、平均的な表現を出すだけでも誤差は小さくなります。そこで「他のフレームではなく、このフレームの本物だ」と言い当てられるかを測ります。これを同定と呼びます。

手順 1：隠して予測する

画像の四半分 Q（粗いマスの 2×2）をいつも隠します。隠すマスの数 k は 4・8・12 の 3 通りで、4 なら Q だけ、8 なら Q を含む上か下の半分、12 なら対角の四半分だけを残して隠します。採点するのは、いつも Q の位置だけです。V18c の長い run は r = 0.5 で学んだので、k = 8 を主に読みます。

Q には 16 個のトークンがあり、各トークンの的は 16 次元です。これを並べた 256 次元のベクトルを、予測と本物で比べます。

手順 2：候補を並べる

候補は、Zurich の動画から 1 秒おきに取った 3899 個の stack の、同じ位置 Q の本物の表現です。易しい候補と難しい候補の 2 種類を使います。

難しい候補は、場面・天気・日の当たり方が似ています。そのため、場面の大まかな情報だけでは当てにくくなります。ただし、ゆっくり変わる成分だけを持つ予測でも、2 秒離れれば自分を当てることがあります。そのため、難しい候補で偶然を上回っても、それだけでは位置ごとの補完の証拠にしません。その役目は 6 節の対照との差が受け持ちます。

手順 3：平均を引いてから、向きで比べる

予測と本物のそれぞれから、決まった平均を引きます（中心化）。平均は、Zurich 以外の学習の動画から取った約 6000 個の stack（参照の組）で計算し、段・四半分・マスクごとに固定します。

  • 平均を引かないと、どの問い合わせも同じ候補に引き寄せられます。1 回目の指標では、1 つの候補に選択の 8〜11% が集まりました（偏りがなければ約 0.2%）。
  • 平均を参照の組から固定するのは、問い合わせや候補の選び方で値が変わらないようにするためです。問い合わせの組ごとに平均を取ると、完全な予測でも得点が下がる例があります（Codex さんの反例）。

比べるときは、ベクトルの長さではなく向きの近さ（cos）を使います。二乗誤差を小さくするように学んだ予測は、本物より短くなりがちです。その縮み方は当てやすさで決まり、「どのフレームか」とは別の量だからです。

手順 4：対の勝率 A で採点する

問い合わせ 1 つについて、正解の候補（自分の本物）との類似度と、他の候補 1 つずつとの類似度を比べます。正解の方が高ければ勝ち、同じなら半分の勝ちとします。勝った割合がその問い合わせの An で、すべての問い合わせで平均したものが対の勝率 A です。

An = 1/(c − 1) · Σm≠n ( [s(n,n) > s(n,m)] + ½ · [s(n,n) = s(n,m)] )　　c は候補の数
  • A は、偶然なら 0.5、完全なら 1 です。候補の数によらないので、易しい候補と難しい候補で同じ目盛りになります。
  • top1 は副に並べます。33 個の候補でいつも 1 つだけ正解より上にある予測は、A = 31/32 でも top1 = 0 になります。top1 だけでは、この差が見えません。
  • 主に読むのは、難しい候補の A です。副として、top1、ユークリッド距離で比べた版（l2）、難しい候補の 33 個の平均で中心化し直した版（hard_c）も並べます。

逃げ道の塞ぎ方：対照との差

なぜこれを測るのか

A が高くても、隠した所を補ったからとは限りません。周りの平均を写すだけで当たる場合や、場面の明るさだけで当たる場合があるからです。そこで、それぞれの近道だけでどこまで当たるかを「対照」で測り、予測の値と比べます。読むのは、予測と対照の差です。

対照作り方差し引くもの
pool見えている部分のトークンの平均を、Q のすべての位置に置く周りの平均を写すだけで当たる分
flat予測の Q の 16 個を、その平均で置き換える四半分の平均だけで当たる分。pred − flat は四半分の中の配置の分
interp隠した画素を、見えている画素から滑らかに補間した画像を、全体を見るエンコーダに通す学習の要らない滑らかな延長で当たる分
難しい候補同じ動画の前後 ±2〜±32 秒の候補で比べる場面・照明だけで当たる分

flat は四半分の中の配置まで求める、高い基準です。pred − flat が 0 に近くても、補完がないとは言いません。そのときは pool・interp との差と swap で読みます。

swap：場所を取り違えないか

swap は、(A, B) と (B, A) の 2 つの向きで平均します。差を先に作るので、位置によらない予測（複製の K3）では、値がちょうど 0.5 になります。3 節の「大域の解」もこの形で見張ります。ただし、位置ごとに符号を反転させるような崩壊（K3 の仲間）では 0.5 になりません。K3 の仲間すべてを捕まえる量ではないので、3 節の K1〜K3 と並べて読みます。

相方：空間がどれだけのことを表しているか

同定には弱点があります。候補を見分けるのに足る成分が 1 つあれば、満点になります。たとえば、予測が本物の一部の成分だけを当て、残りをまったく当てなくても、A は 1 になりえます。そこで、A が高いことを「隠した所の多様な成分を補った」とは読みません。次の 3 つを「相方」として必ず並べます。

  • スペクトルと participation：本物の表現が、いくつの方向に広がっているか。
  • 帯ごとの pred_ratio：本物の主成分を 1〜4・5〜16・17〜64・65〜256 番目の帯に分け、帯ごとに予測の誤差の比を出したもの。pred_ratio は、参照の組の平均を予測とみなしたときの誤差に対する、予測の誤差の比です。1 なら平均と同じ、0 なら完全です。
  • 補空間での同定：分散の大きい上位 4 個・16 個の主成分を取り除いた残りで、同定をやり直したもの。

局所性の確かめ：画素の移植

なぜこれを測るのか

5・6 節の同定と対照との差で満点を取れる、ずるい表現があります。隠した所のトークンに、その場所の中身ではなく、周りの情報を詰めておく表現です。これを見抜けるのは、画素を入れ替える介入だけです。

例として「鏡の符号」を考えます。各マスのトークンが、自分のマスではなく、180° 回した反対側のマスの画素を表す表現です。この表現では、隠した四半分 Q の本物は、反対側の見えている四半分の画素で決まります。予測器はそれを写すだけで本物を当てられるので、同定も、pool・flat との差も満点になります。しかし、隠した所を補ったわけではありません。

移植のしかた

そこで、Q の画素だけを別の画像のものに入れ替えた画像を作り、全体を見るエンコーダに通します。その Q のトークンを候補にして、同定をやり直します。

表現の種類順向きの候補での同定逆向きの候補での同定
局所な符号（各トークンが自分のパッチの画素だけを表す）自然な候補と同じ値全部が引き分け（A = 0.5）
鏡の符号（周りの情報を詰めた表現）全部が引き分け（A = 0.5）自然な候補と同じ値
複製の K3flat と同じ値flat と同じ値

逆に、複製の K3 は移植では捕まりません。こちらは flat・swap と、下の L が受け持ちます。どの対照も、それぞれ別の逃げ道を塞いでいます。

局所性の量

移植したとき、トークンがどこで動いたかも測ります。Q の画素を m のものに替えたときのトークンの変化 Δp と、画像全体を m に替えたときの変化 δp を比べます。

  • aU：Q の中で、Δ が δ に沿う割合。局所な符号では 1、鏡の符号では 0 です。
  • aV：Q の外で、Δ が δ に沿う割合。局所な符号では 0 です。
  • L = aU − aV：入れ替えた場所のトークンだけが動くほど 1 に近づきます。複製の K3 では 0 です。
  • このほか、外で動いた大きさ ρV、内積に出ない Q の中の変化 ηU、継ぎ目に接するマスとそれ以外の別も記録します。

画素は介入にだけ使う

移植では画素を扱いますが、画素を正解にはしません。正解はいつも、エンコーダが作った表現です。画素は「この場所の中身を変えたら、どのトークンが動くか」を調べるための介入にだけ使います。2 節の方針（画素の再構成を正解にしない）と食い違わないのは、このためです。

文脈 j の選び方

文脈には、学習のデータの順で最初に現れる 4 本の動画の、それぞれ最初の stack を使います。Amsterdam のフレーム 100、Bangkok のフレーム 9、Chiang_Mai のフレーム 9、Istanbul のフレーム 22 です。同じ動画の近い時刻の stack は使いません。近い時刻だと、正解の候補を移植した画像がいちばん自然に見えてしまい、それだけで正解が当たりやすくなるからです。

読むときの注意

  • 移植した画像は、エンコーダが学習で見たことのないパッチの組み合わせです。継ぎ目に反応する表現では、移植の値はどんな値にもなりえます。
  • 周りの文脈をよく混ぜる健全なエンコーダでも、移植の値は下がります。そのため、移植で値が下がっても、ずるい表現の証拠とはしません。「同定のうち Q の画素で説明できる分がそれだけだった」と読みます。

実装の確かめと事前登録

なぜこれを測るのか

物差しの実装が間違っていれば、出てきた数値はどれも意味を持ちません。そこで、答えが式で厳密に決まる合成の例を物差しに通し、その答えが出るかを確かめます。外れたら止めて報告し、条件を変えて通るまで探すことはしません。

2 種類の対照を分ける

対照には 2 種類あります。1 つは、恒等式や閉じた式で値が厳密に決まるものです（定数、局所な符号、鏡の符号など）。これだけを合否に使います。もう 1 つは、学習前のモデルや崩壊した run のように、値が厳密には決まらない実物の対照です。こちらは数値を並べるだけにします。

この区別は、1 回目の失敗がもとになっています。前の評価 E1 は、別のフレームの予測（shuf）と崩壊した run（M）を合否に使い、どちらも外れました。調べると、shuf の偏りは動画のゆっくりした変化によるもので、M は厳密な K3 ではありませんでした。実装の誤りではなく、値の決まらない対照を合否に使った設計の問題でした。

  • V-s4（局所な符号）：順向きの候補は A = 1・top1 = 1 で、自然な候補とビットまで同じでした。逆向きの候補は、易しい 512 個・難しい 502 個のすべての問い合わせが、すべての候補と引き分けました。aU の 1 からのずれは最大 2.2 × 10−16、aV はどれも 0 でした。
  • V-s5（鏡の符号）：自然な候補の top1 は 1、順向きの候補は A = 0.5・top1 = 0 ですべて引き分け、逆向きの候補は自然な候補とビットまで同じでした。aU はどれも 0 でした。

次の 3 つは、数値を 1 つも出す前に、ユーザーが承認・決定しました。

  1.   2. swap を V-s5 の合否から外し、記述にしました。鏡の符号の swap は、位置の順を反転すると局所な符号の swap と同じ量になり、鏡の符号を何も見分けていません。実データでも、2 つの符号の swap はどちらも 0.948 で、512 個の問い合わせのすべてで一致しました。合否に入れていたら、512 個のうち 94 個が 1 にならず、V-s5 は外れていました。
  3. 文脈 j の取り方を直しました。最初の登録は「参照の組の 4 本の動画から 1 つずつ」でした。しかし参照の組（5998 stack）は Amsterdam（4905）と Bangkok（1093）の 2 本だけで、確かめのプログラムが止まりました。そこで、7 節のとおり、学習のデータの順で最初に現れる 4 本の動画から取ることにしました。参照の組そのものは変えていません。

事前登録をする理由

結果を見てから規則を変えると、望む結果が出るまで物差しを直せてしまいます。それでは、物差しが学習の良し悪しではなく、私たちの期待を測ることになります。そのため、規則と閾値は数値を見る前に README に書き、結果を見た後の変更は、理由とともに別に書きます。上の 3 つの変更も、数値を出す前の決定として記録しました。

言えること・言えないこと

なぜこれを確かめるのか

どの指標にも、届く範囲があります。範囲の外のことを読むと、数値は正しくても結論を誤ります。そこで、言えることと言えないことを、数値を見る前に分けておきます。

言えること

  • それぞれの run の表現空間の中で、予測が本物を他のフレームから見分けるかどうか。
  • 対照（pool・flat・interp・難しい候補・swap・移植）ごとに、予測がどれだけ上回るか。

言えないこと

  • 表現空間の違う run どうしの大小。学習した射影と固定の R、パッチの大きさが違えば、空間が表せる情報の量も違います。
  • step をまたぐ単純な比べ。step ごとに正解（本物）も変わるので、「それぞれの課題での同定の移り変わり」として読みます。
  • 「同定が高いので、隠した所の多様な成分を補った」という読み。識別に足る成分が 1 つあれば満点になるからです（6 節の相方と並べて読みます）。
  • 「移植で値が下がったので、ずるい表現だ」という読み（7 節）。
  • 画素の主成分分析や VAE のような外部の物差しとの大小。原理的に同じ目盛りに載りません。

数値の書き方

揺れは、連続した問い合わせのまとまり（8 個、約 61 秒と、16 個）を単位に引き直すブートストラップ（2000 回）で求め、大きい方を標準誤差 SE* とします。差を「上回る」と書くのは、2 つの seed がどちらも同じ向きで、それぞれ 2 SE* を超えるときだけです。それ以外は「区別できない」と書きます。これは記述の言葉づかいで、仮説の支持や棄却ではありません。

V18c と V19 での使い方

  • V18c では、この指標で長い run の良し悪しを判定せず、設定も選びません。値と揺れを並べて記述します。
  • V19 では、主の指標の候補にします。見分けたい最小の差 Δ* は理論では決まらないので、V18c の値と揺れを見てから、ユーザーと決めます。
  • 主の量を何にするかも、V19 で決めます。Fable さんは「移植した難しい候補での A の pred − flat」を推しました。Codex さんは、1 つの量だけを主にすることに反対し、継ぎ目や文脈 j を変えても読みが変わらないこと、比べたい差の区間の幅が Δ* より小さいこと、床や天井に張り付いていないことを条件に挙げました。
  • 未来の予測も、同じ枠組みで V19 から測る予定です。

時間の線形性と情報の幅：なぜ測るのか

なぜこれを測るのか

ここまでの指標は、隠した所を補えるかを見ました。ここからは別の性質を見ます。符号の空間で、動画の時間の流れがどれだけ真っすぐかです。これは合否の指標ではなく、記述です（ユーザーの決定、2026-11-25）。

画素の平均は二重写しになる

動画から、Δ 秒ずつ離れた 3 つの時刻 t − Δ、t、t + Δ のフレームを取ります。前後の 2 枚を画素の空間で平均すると、動いた物が両方の位置に半分の濃さで写ります。これを二重写しと呼びます。本物の中間のフレームでは、物は途中の 1 か所に写っています。画素の平均は、中間のフレームの良い近似になりません。

整った空間なら、平均に意味がある

符号の空間が整っていれば、事情が変わるかもしれません。前後 2 つの時刻の符号の平均 m が、本物の中間の時刻の符号 z(t) に近ければ、その空間では「足し算が効く」と言えます。正解である本物の中間は、動画の中にあります。そのため、人のラベルもデコーダも要りません。

知覚のまっすぐ化

Hénaff ら（2019）は、自然な動画のフレームの並びが、画素の空間では大きく曲がった軌跡になり、人の知覚の空間ではほぼ真っすぐになることを示しました。上の直観の、心理物理の実験による裏づけです。一方で、分類を学んだ CNN や、不変性で学ぶ手法は、自然な動画を真っすぐにしないことも報告されています（Hénaff 2019、Niu 2024）。真っすぐさは、どんな学習でも自然に生まれる性質ではありません。

ダイナミクスモデルの予測と、長い記憶

潜在の時間の流れが真っすぐなら、次の時刻の符号を、それまでの符号から予測しやすくなります。最も単純な予測は、等速の外挿 2z(t) − z(t − Δ) です。1 歩の予測が単純な式で当たれば、何歩も先まで予測を重ねても、誤差が積み上がりにくくなります。ユーザーは、この性質が、長い記憶を持って世界をシミュレートするために重要だと考えています。この評価の本命の使い道は、V19 の未来予測で、等速の外挿を対照にすることです。

何を測り、何を測らないか

  • Q1（時間の線形性）：前後 2 時刻の符号の平均は、本物の中間の符号にどれだけ近いか。画素や他の符号と比べてどうか（11 節）。
  • Q2（情報の幅）：Q1 の値は、情報を捨てて遅くなったせいではないか。離れた時刻の符号は、どれだけ多くの独立な変化を表すか（13 節）。
  • 因子が空間の中で別々の方向に分かれているか（狭い意味の disentanglement）は、人のラベルを使わない 2 次の統計では測れません。この評価では扱いません。

Q1 と Q2 は並べて記述し、1 つの数にまとめません。「良い表現」の順位にもしません。JEPA の検証項目（K1〜K3・局所性・自己同定）は、この評価で置き換えません。

三つ組と中点の誤差

なぜこの形にするのか

「軌跡が真っすぐか」を、どの符号にも同じ手順で計算できる 1 つの数にします。そのうえで、その数の目盛りを理論で決めておきます。目盛りがあれば、値を見たときに「どの程度真っすぐか」を読めます。

三つ組

Zurich の動画の全ての stack（0.1 秒おき、38989 個）を符号にします。刻み Δ を決め、3 つの時刻 t − Δ、t、t + Δ の符号を 1 組にします。これを三つ組と呼びます。刻みは 0.8・1.6・3.2・6.4・12.8・25.6 秒の 6 つです。0.8 秒より短い刻みは、隣の stack と入力のフレームを共有するので使いません。動画は 128 秒のブロックに切り、3 つの stack が 1 つのブロックに収まる三つ組だけを使います。どの符号にも同じ三つ組を使います。

場面の切り替わり（カット）をまたぐ三つ組は、主の比べから外します。カットを含まない三つ組を in の層と呼び、主の値は in で読みます。カットの規則は入力の画素だけで決め、全ての符号に同じものを使います。

中点の誤差 Gmid

a = w(t) − w(t−Δ)　　b = w(t+Δ) − w(t)　　m = ½ (w(t−Δ) + w(t+Δ))
G_mid(Δ) = Σ ‖w(t) − m‖² ／ Σ ½ (‖a‖² + ‖b‖²)

w は、12 節で説明する白色化した符号です。分子は、前後の平均 m と本物の中間 w(t) の距離の二乗を、全ての三つ組で足したものです。分母は、1 歩の変位 a・b の大きさの二乗の平均を、同じように足したものです。分母で割るので、Gmid は「1 歩の動きに比べて、中点がどれだけ外れたか」を表す相対誤差になります。小さいほど、軌跡が真っすぐです。

遅さ s

s(Δ) = D̄(Δ) ／ (2V)

D̄ は、1 歩の変位の二乗の平均です。これは、前の時刻の符号をそのまま答えにする予測（copy）の誤差でもあります。V は、評価の全 stack の分散の合計です。無関係な 2 つの stack の差の二乗の平均は 2V になります。そのため、s は「その刻みで、全体の変動のうちどれだけが動くか」を表します。s = 0 なら符号は止まっており、s = 1 なら無関係な 2 枚と同じだけ動きます。遅い符号ほど s は小さくなります。

目盛り：0、s/2、3/4、そして s

Gmid には、理論で決まる目盛りがあります。Gmid は s を横軸にして描きます。

  • 0：等速で直線を進む軌跡です。中点がちょうど本物に重なります。
  • s/2：時間で性質が変わらない（定常な）系列では、Gmid は s/2 より小さくなれません。s/2 に等しくなるのは、変化が 1 つの時間尺度（1 つの周波数）だけでできているときです。そのため、Gmid が s/2 に近いことを「時間尺度がそろっている」と書きます。
  • 3/4：時刻ごとに独立な白い雑音や、時刻を並べ替えた系列の値です。このとき s = 1 です。時間の構造が無いと、この値になります。
  • s：横軸の目盛りです。0 は止まった符号、1 は時間の構造が無い符号です。同じ Gmid でも、s が小さい（遅い）符号と大きい符号では意味が違うので、2 つを組で見ます。

時間の相関が指数で減る過程（OU 過程）では、Gmid = (2 + s)/4 になり、0.5 から 3/4 の間に入ります。

等速の外挿との関係

等速の外挿 2w(t) − w(t − Δ) で w(t + Δ) を当てる誤差を D̄ で割ると、三つ組ごとにちょうど 4Gmid になります。外挿の誤差は b − a で、これは中点のずれ w(t) − m の −2 倍だからです。一方、copy の誤差を D̄ で割った値は、実データでほぼ 1 です。したがって、等速の外挿が copy に勝つには、ほぼ Gmid < 1/4 が要ります。Gmid は、等速の外挿がどれだけ効くかを、そのまま表す量でもあります。

白色化：VAE・MAE・JEPA を同じ物差しに載せる

なぜ白色化するのか

符号は、モデルごとに次元も尺度も軸の向きも違います。そのまま距離を測ると、分散の大きい少数の方向だけで値が決まります。そうなると、モデルどうしを同じ目盛りで比べられません。そこで、どの符号も同じ手順で「丸い雲」に直してから測ります。

白色化の手順

  1. 参照の組（Zurich でない学習の動画 Amsterdam・Bangkok の 5998 stack）で、符号の平均と共分散を求めます。
  2. 評価の符号から参照の平均を引き、共分散の上位 k 個の主成分の方向に射影します。主の k は 64、副の k は 16 と 256 です。
  3. 各方向を、参照でのその方向の分散の平方根で割ります。こうして得た座標が w です。

参照と評価が同じ分布なら、w はどの方向にも分散が 1 の、丸い雲になります。

なぜこれで比べられるのか

白色化すると、可逆な線形変換（回転、軸ごとの伸び縮み、軸の混ぜ合わせ）の違いが消えます。全次元で白色化すれば、符号に可逆なアフィン変換をかけても Gmid と s は変わりません。実装の確かめ V-d0c で、相対 10−8 以内で一致することを確かめました。

残るのは、時間の自己相関、つまり「各方向が時間とともにどう変わるか」だけです。定常なら、Gmid と s は、白色化した符号の時間のスペクトル（どの速さの変化がどれだけあるか）だけで決まります。そのため、VAE の μ、MAE の潜在、JEPA の z のように、作り方も次元も違う符号を、同じ目盛りで比べられます。比べるときは、各モデル自身の潜在（VAE の μ、JEPA の z、V18b の M の zpca）と、共通の h_mean（エンコーダの最後の LayerNorm の後のトークンを、位置で平均した 1024 次元）を、別々に使います。

白色化の限界

  • k の選び方で値が変わります。上位 k 方向だけを残すので、k を変えると数える方向が変わります。白色化すると、分散の小さい方向も同じ重みで数えられます。画素の PCA の 17 番目より後ろの方向は細かい模様で、速く変わります。そのため k を上げると、画素の Gmid は大きく上がると考えられます。実際に、画素と学習した符号を比べた向きは、k = 16・64・256 で変わりました（結果は report-jepa.html）。
  • 2 次の統計しか見ません。1 つの量を広げたチェビシェフ展開と、独立な 64 個の因子は、全ての刻みで値が同じになりえます。因子が分かれているかは測れません。
  • 参照と評価がずれていると、少数の方向が値を支配します。15 節の診断で確かめます。

情報の幅：TwoNN と、2 つを並べる理由

なぜ並べるのか

中点の誤差は、情報を捨てると見かけ上良くなります。そこで、符号がどれだけ多くの独立な変化を表しているかを、別の量で測って並べます。

真っすぐさは、潰すと見かけ上良くなる

ある符号が、動画のほとんどの情報を捨てて、ゆっくり変わる 1 つの量だけを残したとします。この符号の軌跡は遅く滑らかで、中点の誤差も小さくなりえます。しかし、それは世界を良く表したからではありません。表すものを減らしたからです。中点の誤差だけを見ると、このような符号を「良い」と読み違えます。

TwoNN による内在次元

点の集まりは、見かけの次元より低い次元の面の上に乗っていることがあります。その面の次元を内在次元と呼びます。TwoNN（Facco ら 2017）は、各点から最も近い点までの距離 r1 と、2 番目に近い点までの距離 r2 の比 μ = r2/r1 を使います。d 次元の面に点が一様に散っていれば、μ は d で決まる分布に従います。そこで、全ての点の μ から d を推定し、d̂ と書きます。次元が高いほど、2 番目の近傍は 1 番目とほぼ同じ距離になり、μ は 1 に近づきます。

点の取り方と、読むときの注意

  • 点は、Zurich の 1 秒おきの格子を 8 秒おきに間引いた約 487 点です。開始の秒をずらした 8 通りの平均を取ります。近い時刻の点どうしが、軌跡の 1 次元を拾うのを避けるためです。
  • 主の値は、PCA64 で白色化する前の座標（pre）で測ります。これを「観測の尺度での局所の次元」と書き、「情報の量」や「因子の数」とは書きません。
  • 487 点では、値は強く下に偏ります。真の次元が 64 の等方ガウスでも、33〜36 になります。この偏りは補正しません。
  • 点の間に時間の相関があると、TwoNN は 16 次元より上の順位を保ちません。相関が 0.5 のとき、d = 32 と 64 の順が逆になりました。そのため、d̂ が 20 を超える符号どうしの順位には頼りません。

2 つを並べても、決め手にはならない

2 つの量を並べても、「情報を捨てずに真っすぐになった」とは言い切れません。真の次元が 1 の合成の符号 cheb_c は、中点の誤差が下限の線にほぼ乗ります。それでいて TwoNN では、64 個の因子と同じ程度の値（約 35）になります。つまり、2 つの量を同時にすり抜ける符号があります。書けるのは、それぞれの値と、合成の対照のどの失敗の形に近いかまでです。

有効性の確かめと、区別したい最小の差 Δ*

なぜこれを確かめるのか

物差しの実装が正しく、実データで差を見分けられることを、モデルの値を見る前に確かめます。そのうえで、「どれだけの差を、実用上の差とみなすか」を決めます。

実装の確かめ（外れたら止める）

合否は、恒等式と閉じた式だけで決めます。等速の直線で Gmid = 0 になること、白い雑音や OU などの合成の系列で式の値が出ること、アフィン変換や時間の逆順で値が変わらないこと（V-d0a〜V-d0f）、実データの恒等式（V-d0h）を調べ、すべて通りました。

V-d1：読める刻みがあるか

定常なら Gmid ≥ s/2 なので、外挿の誤差 4Gmid は 2s 以上になります。s ≥ 1/2 の刻みでは、どの符号でも等速の外挿が copy に勝てず、「足し算が効く」と言える刻みがありません。そこで、0.8 秒の s に 2SE* を足しても 1/2 未満であることを確かめました。pca は 0.347、学習前の V18c（init_c）は 0.443 で、通りました。

V-d2：作った差を回収できるか

pca の白色化した座標に、時間に独立な雑音を足すと、Gmid は決まった式に従って上がります。足す量を選べば、0.005〜0.08 の差 δ をちょうど作れます。この差を、同じ三つ組の対の差で回収しました。作れた 19 個のすべてが、閾値の中で回収できました。ただし、雑音を足しても Gmid は 3/4 を超えないので、作れる差は 3/4 − G より小さくなります。

Δ* の決め方

Δ* は、実用上区別したい最小の差です。理論では決まらないので、物差しの揺れを見て、モデルの値を見る前にユーザーが決めました（2026-11-26）。

  • Gmid の Δ* = 0.03（全ての刻みで同じ値）。k を 48・96 に変えたときの値の動き（0.8 秒で最大 0.030）を超える大きさです。学習前のエンコーダの seed だけを変えた差（0.8 秒で 0.017）は、「小さい」に入ります。
  • d̂ の Δ* = 4（pre・k = 64・8 秒おき）。開始の秒による揺れ（1 つの符号で最大 3.5）を超えます。学習前の seed だけの差（2.1）は、「小さい」に入ります。

言葉づかいの 3 つの分類

比べるのは、同じ読む場所の中で、同じ刻みの対の差（同じ三つ組、同じブロックの引き直し）だけです。対の差の区間（± 2SE*）を、次の規則に当てます。

書き方条件
実用上の差を区別できた区間が、同じ向きに Δ* を丸ごと超えた
実用上の差は小さい区間全体が [−Δ*, Δ*] の中に入った
解像度が足りないそれ以外（区間が ±Δ* の境をまたぐ）

長い刻みは比べられない

6.4 秒より長い刻みでは、どの物差しも Gmid が 0.71〜0.75 に集まります。刻みが長くなると、前後の stack はほとんど無関係になり、値は時間の構造が無いときの 3/4 に近づくからです。Gmid が上に動ける余地 3/4 − G は、pca で 6.4 秒が 0.026、12.8 秒が 0.009、25.6 秒が 0.007 しかありません。V-d2 で作れた差も、6.4 秒で 0.02 まで、12.8・25.6 秒で 0.005 だけでした。どれも Δ* = 0.03 に届きません。

ユーザーは、Δ* 以上の差を作れない刻みについて、「解像度が足りない」という判定をしないことに決めました。この刻みは記述だけにします。判定するのは 0.8・1.6・3.2 秒です。その後、3.2 秒の「区別できた」は、「解像度が足りず、確かめられていない」と読み替えました（23 節）。

白色化した評価の分散の診断

なぜこれを確かめるのか

白色化で雲が丸くなるのは、参照と評価が同じ分布のときだけです。2 つがずれていると、少数の方向が値を支配し、時間の幾何ではなく「参照と評価のずれ」を測ってしまいます。この節では、そのずれを見る 3 つの値と、境の決め方を説明します。境はいま仮の値で、ユーザーがこの解説を読んでから決め直します。

何を確かめるのか

白色化の物差し（平均と共分散）は参照の組（Amsterdam・Bangkok）から作り、値は Zurich で測ります。参照では分散が小さく、Zurich では分散が大きい方向があるとします。白色化では参照の分散の平方根で割るので、その方向は大きく引き伸ばされます。すると、その方向が V と D̄ の大半を占めます。s と Gmid は、全ての方向の和の比なので、その 1 方向の時間の振る舞いだけを映すようになります。符号どうしの差も、時間の幾何の差ではなく、参照と評価のずれの差になりえます。小さな数 ε（cε = 10−6）を分散に足していますが、これはこのずれをほとんど抑えません。

3 つの値

白色化した評価の座標 w の共分散を求め、その固有値（評価自身の主成分の方向の分散）を大きい順に並べます。そこから次の 3 つを計算します。

方向の分散の最大いちばん大きい固有値11 つの方向の飛び出し
上位 5 方向の割合大きい順に 5 つの固有値の和が V に占める割合5/k = 0.078（k = 64）少数の方向への集中

失敗の形の例

合成の符号 ou_mix_30 は、半分の次元が OU 過程で、残りの半分は自己相関がガウス型でとても遅い過程です。これを、同じ過程の別の実現を参照にして白色化しました。遅い半分は変化がゆっくりなので、38989 歩あっても、独立とみなせる標本は 32 次元に対して約 23 個しかありません。そのため参照の共分散はほぼ特異になり、白色化すると評価の分散が少数の方向に集まりました。3 つの値は 9.14・195・0.81 です。このとき 0.8 秒の s は 0.013（理論 0.111）、25.6 秒の Gmid は 0.474（理論 0.726）で、理論から大きく外れました。母集団の共分散で白色化すると、理論の値と合いました。診断の 3 つの値が大きく外れると、s と Gmid がこのように別の量になりうる、という例です。

仮の境とその理由

ユーザーは、次の境を仮に決めました（2026-11-26、モデルの値を見る前）。3 つのどれか 1 つでも境を超えたら、その符号の Gmid と s に「計量が参照と評価のずれに依存する」と書き添えます。

  • V/k が [0.5, 2] の外：全体の大きさが、理想の 2 倍以上または半分以下にずれた場合です。物差しは 0.80〜0.98 でした。
  • 方向の分散の最大が 10 を超える：物差しの最大 2.9 の約 3.5 倍です。失敗の形の 195 よりは 1 桁以上小さい値です。
  • 上位 5 方向の割合が 0.4 を超える：物差しの最大 0.20 の 2 倍です。5 つの方向が全体の 4 割を占める状態です。失敗の形は 0.81 でした。

線形の幅：なぜ測るのか

なぜこれを測るのか

10〜15 節では、決まった 6 つの刻みで、中点がどれだけずれるかを記述しました。ここからは問いを変えます。どの刻みを選ぶかではなく、どの刻みまで「今の速さのまま進む」予測が成り立つかを測ります。この長さを線形の幅と呼びます。16〜23 節の定義と規則は、実データの細かい刻みの値を 1 つも計算する前に決めました（2026-11-26）。

テイラー展開から見た線形の幅

符号の軌跡 z(t) が時間について滑らかなら、テイラー展開で z(t + Δ) ≈ z(t) + Δ·z′(t) と書けます。0 次の項だけを使う予測は、今の符号をそのまま答えにする予測です。これを copy と呼びます。1 次の項まで使う予測は、今の速さのまま進む予測です。速さ z′(t) を直前の変位 z(t) − z(t − Δ) から見積もると、予測は 2z(t) − z(t − Δ) になります。これを等速の外挿と呼びます。

Δ が小さいうちは、2 次より上の項は小さいので、等速の外挿は copy より当たります。Δ を大きくすると、軌跡の曲がりが効いてきます。そして、どこかで外挿は copy に負けます。ユーザーの考えでは、JEPA で大事なのは、この「1 次で近似できる区間」を広げることです。

何に効くのか

符号の時間の動きを学ぶモデルを、ダイナミクスモデルと呼びます。線形の幅が広い符号では、ダイナミクスモデルが、遠い先まで単純な規則で予測できます。予測を何歩も重ねても、誤差が積み上がりにくくなります。ユーザーは、これが長い記憶を持った世界のシミュレーションに効くと考えています。

他の手法とは「平均的な幅」で比べる

測るのは、1 つの刻みでの値ではありません。どの刻みまで線形性が成り立つかです。VAE・MAE・JEPA などの符号を、同じ物差し（12 節の白色化した PCA64）に載せ、「平均的な線形の幅」で比べます。

ただし、幅だけを見ると、ずるができます（20 節）。そこで、崩壊の指標と、拡散のデコーダで意味が保たれているかどうかという 2 つで見張ります（21 節）。これをガードと呼びます。拡散のデコーダのガードは確かめで外れたので、作り直しています（24〜28 節）。

等速の外挿と copy の勝ち負け

なぜこの形にするのか

線形の幅を決めるには、まず 1 つの三つ組で、外挿が勝ったか負けたかを決める必要があります。11 節の中点の誤差を三つ組ごとに見ると、勝ち負けを曲がりの角度で読めます。

続く 2 つの変位の相関 ρ

白色化した符号 w（12 節）の三つ組 w(t − Δ)、w(t)、w(t + Δ) を取ります。前の変位を a = w(t) − w(t − Δ)、後の変位を b = w(t + Δ) − w(t) とします。

ρ_t = ⟨a, b⟩ ／ ½ (‖a‖² + ‖b‖²)
三つ組の中点の誤差 = ‖w(t) − m‖² ／ ½ (‖a‖² + ‖b‖²) = (1 − ρ_t) / 2

ρt は、続く 2 つの変位の相関です。同じ向きに同じ長さで進めば 1、直角に曲がれば 0、まっすぐ引き返せば −1 になります。三つ組の中点の誤差は、この相関だけで決まります。これは恒等式で、定常などの仮定を使いません。

等速の外挿の誤差は ‖b − a‖² で、中点のずれの二乗の 4 倍です。そのため、外挿の誤差が、2 つの変位の二乗の平均 ½(‖a‖² + ‖b‖²) を下回るのは、中点の誤差が 1/4 未満のときです。つまり ρt > 1/2 のときです。このとき「外挿が copy に勝つ」と言います。copy の誤差を、前後の変位の二乗の平均で測った形です。時間を逆に流しても、勝ち負けは変わりません。

2 つの境：60° と 90°

2 つの変位の長さが等しいとき、ρt は曲がりの角度 θ の cos です。境は 2 つ置きます。

  • 主の境 1/4：ρt > 1/2、つまり曲がりが 60° 未満なら勝ちです。等速の外挿の誤差が copy の誤差より小さい、という境です。
  • 副の境 1/2：ρt > 0、つまり曲がりが 90° 未満なら勝ちです。前の変位と次の変位が同じ側を向いている、という緩い境です。

主の境を 1/4 にしたのは、「0 次のテイラー（copy）より 1 次のテイラー（等速の外挿）が良い」という線形の幅の意味そのものだからです。経験から選んだ値ではありません。

勝つ瞬間の割合 p(Δ) と、幅の読み方

なぜ瞬間ごとに数えるのか

動画には、まっすぐ進む瞬間も、急に曲がる瞬間もあります。全体を 1 つに足し合わせると、大きく動いた少数の瞬間が値を決めてしまいます。そこで、瞬間ごとに勝ち負けを数え、勝つ割合が刻みとともにどう変わるかを見ます。

p(Δ)

刻み Δ ごとに、三つ組のうち外挿が勝つものの割合を p(Δ) とします。どの瞬間も同じ重みで数えます。これを時間の重みと呼びます。

  • 刻みは、0.1〜25.6 秒の 0.1 秒おきの 256 個です。主に読む範囲は 0.8〜25.6 秒です。
  • 数える三つ組の中心は、全ての刻みで同じ集合にします。25.6 秒の三つ組でもカットをまたがない中心です（V18c の組で約 14100 個）。刻みごとに集合を変えると、数える瞬間が入れ替わるだけで p が動くからです。
  • 動かない三つ組（変位が 0）は除かず、負けに数えます。除くと、止まった場面で符号を固めるだけで p が上がってしまうからです。

窓と、局所の幅の中央値 Δtyp

p(Δ) ≥ 1/2 となる刻みの、連続した区間を窓と呼びます。窓が 2 つ以上あれば、最も短い刻みの側の区間を使います。これを最初の窓と呼びます。最初の窓の上端を Δtyp と書き、局所の幅の中央値と呼びます。

中央値と呼ぶ理由は次のとおりです。瞬間ごとに幅 Wt があり、それより短い刻みでは勝ち、長い刻みでは負けるとします。すると p(Δ) は「幅が Δ を超える瞬間の割合」になります。p が 1/2 を横切る刻みは、Wt の中央値です。

条件を満たす刻みが 1 つも無ければ、「窓が無い」と書き、数を出しません。範囲の外に伸ばして推定することもしません。

主の幅 Δ1：最初の窓の上端までの積分

Δ₁ = 0.8 + ∫ p(Δ) dΔ　（積分は 0.8 秒から Δ_typ まで。単位は秒。窓が無ければ 0.8 秒）

p を積分すると、幅 Wt の平均に当たる量になります。主の幅 Δ1 は、この積分を最初の窓の上端で止めたものです。符号どうしの比べは、V19 の判定も含めて、この Δ1 で行います（ユーザーの決定、2026-11-26）。

なぜ周期の戻りを数えないのか

周期のある動き（例えば回転）では、外挿はいったん負けた後、周期の倍数の近くでまた勝ちます。周期 T の回転なら、kT ± T/6 の近くで何度でも勝ちます。しかし、この勝ちは 1 次の近似が効いているからではありません。動きが周期で元に戻っただけです。テイラー展開が保証するのは、短い刻みの側から続く区間だけです。

戻りまで足すと、周期的な動きの多い動画ほど、幅が大きく出ます。これでは、符号の違いではなく、動画の性質を測ることになります。合成の確かめでは、周期 20 秒の帯に雑音を足した系列で、全域の積分 Δ の 6 割が戻りから来ていました。そこで、主の幅は、途切れずに線形で予測できる長さだけを数える Δ1 にしました。戻りの区間は「再出現」として記録します。

並べる副の量

  • 平均の幅 Δ：p を 0.8 秒から 25.6 秒まで積分して 0.8 を足した値です。戻りも含みます。窓の有無によらず定義できます。
  • プールの横切り：全ての三つ組の和で取った Gmid(Δ)（11 節）が 1/4 を下回る刻みの窓です。必ず並べます。プールした値は、変位の大きい瞬間（速い出来事）に重みがかかります。時間の重みの幅と順位が食い違えば、両方を書きます。
  • 生き残りの曲線 S(Δ)：瞬間ごとに、最初に勝つ刻みから続けて勝つ区間を取り、その上端が Δ 以上である瞬間の割合です。S が 1/2 を横切る刻みが Δtyp から離れていれば、「中央値」という読みは成り立たないと書きます。瞬間の半数ずつが別々の刻みの帯で勝つと、窓はつながって見えても、全域で勝つ瞬間は 1 つも無いことがあるからです。
  • 方向ごとの幅の分布 Nlin(T)：白色化した 64 の方向のそれぞれで幅を測り、幅が T 以上の方向の数を数えます。方向を選ぶブロック（偶数番）と、値を測るブロック（奇数番）を分けます。プールした値は最も速い方向に支配されるので（20 節）、それを補う記述です。区間は付けず、「因子の数」とは書きません。
  • 副の境 1/2 でも、同じ量を出します。

区間と、区別したい最小の差 Δ*

揺れは、11〜14 節と同じブロックのブートストラップ（128 秒と 256 秒のブロック、2000 回）で見ます。抽出ごとに窓と幅を求め直し、2.5% 点と 97.5% 点を区間にします。比べる量は、幅の比のオクターブ log2(Wa / Wb) です。2 つの符号は同じ抽出で対にします。

区別したい最小の差 Δ* は 0.5 オクターブ、幅の比で √2 ≈ 1.41 倍です。言葉づかいの 3 つの分類（区別できた・小さい・解像度が足りない）は、14 節と同じ規則で当てます。ただし「小さい」と書くのは、2 つの符号のどちらも、窓が有る抽出が 97.5% 以上のときだけです。両方とも窓が無いと、Δ1 はどちらも 0.8 秒になり、比が 0 になってしまうからです。

0.8 秒より短い刻み

0.8 秒より短い刻みの値は、記述として出し、必ず mean8 と並べます。stack は 8 枚のフレームを重ねるので、8 枚を平均するだけで見かけの窓ができるからです。合成の確かめでは、時定数 0.8 秒と 8 秒の OU を 8 枚で平均すると、0.34 秒と 0.45 秒までの窓ができました。この範囲の窓は、符号器の成果とは読みません。

雑音があると、幅は窓になる（U 字）

なぜ「窓」なのか

テイラー展開を素直に読むと、幅は 0 から始まる区間になるはずです。しかし実際の符号では、とても短い刻みで外挿が負けることがあります。その理由を説明します。

符号に、フレームごとに独立な小さな揺れ（白い雑音）が混ざっているとします。刻みがとても短いと、本当の動きはほとんど進まず、変位は雑音で決まります。前の変位は雑音で行き過ぎた分を含み、次の変位はそれを戻す向きになりがちです。そのため、続く 2 つの変位は逆向きになり、外挿は copy に負けます。雑音だけなら ρ = −1/2、Gmid = 3/4 です。

刻みを伸ばすと、本当の動きが雑音より大きくなり、外挿が勝ち始めます。さらに伸ばすと、今度は軌跡の曲がりで負けます。Gmid を刻みに対して描くと U 字になり、1/4 を下回る部分が窓 [Δlo, Δhi] になります。

式で書くと次のとおりです。滑らかな成分が 1 つの帯だけで、その遅さが s（帯だけなら G = s/2）、雑音の分散の比が ν のとき、Gν = (s·G + ¾ν) / (s + ν) です。境 1/4 の窓ができるのは、ν < 1/16 のときだけです。境 1/2 なら ν < 1/2 です。ν = 1/32 なら、窓は s が 0.073 から 0.427 の間で、周期 20 秒の帯では 1.23〜3.06 秒になります。

実データでは

Fable さんの検討では、V18c の物差しは、0.8 秒ですでに、続く変位の相関が負でした（pca −0.18、mean8 −0.07、init_f −0.39）。相関が負なら、プールした中点の誤差は 1/2 より大きく、境 1/4 からは遠い状態です。そのため、0.8 秒以上では、物差しに窓は無い見込みです（推測）。課題は、幅を広げることより前に、窓を作ることかもしれません。

広げることと遅くすること、ずるの形

なぜこれを知っておくのか

幅は広いほど良さそうに見えます。しかし、意味を捨てても幅は広がります。どんなずるがありうるかを知っておくと、ガード（21 節）の役目が分かります。

幅を広げるには、遅くなるしかない

11 節で、時間で性質が変わらない（定常な）系列では Gmid ≥ s/2 だと説明しました。境 1/4 を下回るには、s/2 < 1/4、つまり s < 1/2 が要ります。ある刻みまで幅を伸ばすには、その刻みで符号が、全体の変動の半分より少ししか動かないことが必要です。定常で有界な符号では、線形の幅を広げることは、符号を遅くすることと同じです（定理）。

遅くするには 2 つの道があります。1 つは、速く変わる内容を捨てることです。もう 1 つは、同じ内容を、時間に対してまっすぐな座標に並べ直すことです。前者はずるで、後者が望む改善です。時間の 2 次の統計（Gmid・s・p）だけでは、この 2 つを分けられません。分けるのは、ガードの役目です。

ずるの形

  • 時間の平均：符号を時間でならすと、遅く滑らかになり、幅が伸びます。ただし、1 つの stack しか見ないエンコーダがならせるのは、stack の 0.8 秒の中だけです。3.2 秒以上の幅は、時間をならすだけでは作れません。
  • 速い方向を捨てる：速く変わる方向を符号から落とすと、残りは遅くなり、幅が伸びます。
  • 状態を持つモデル：過去の状態を持つモデル（V19 の再帰など）は、入力と無関係に滑らかな符号を出せます。例えば、速度が OU 過程に従う「OU の積分」は、入力の情報を何も持たなくても、速度の時定数 τ の 1.151 倍の幅を持ちます。

有効性の確かめ V-h2 では、pca の符号から、はじめの 2 つのずるを強さを変えて作ります。過去だけの時間の平均（0.8〜12.8 秒）と、速いほうから 16〜56 の方向を捨てる射影です。幅が主張できるほど伸びた全ての強さで、ガードが「割れた」と答えるかを確かめます。

プールした値は、最も速い方向に支配される

プールした Gmid は、方向ごとの Gi を、その方向の動きの大きさ si で重みづけた平均です。速い方向ほど重みが大きくなります。64 の方向のうち、白い雑音のように動く方向が 4 つあれば、残りが 1 つの滑らかな帯でも、境 1/4 の窓は無くなります。3 つなら窓は残ります。時間の重みの p(Δ) も、三つ組ごとの ρt から求めます。この ρt は、方向ごとの値を変位の大きさで重みづけた和です。そのため、この支配は取り除けません。方向ごとの Nlin(T) を並べるのは、このためです。

まっすぐさは、予測しやすさの一部だけを見る

回転は、線形の予測器なら何歩先でも誤差なく当たります。しかし等速の外挿では、幅は周期の 1/6 しかありません。線形の幅は、「線形に予測しやすいか」を最も厳しく見た量です。そのため「予測しやすい」「良い表現」とは書かず、「等速の外挿が copy に勝つ刻みの幅」の略としてだけ使います。

ガード：崩壊の指標と、拡散のデコーダ

なぜガードが要るのか

幅は、意味を捨てても広がります（20 節）。そこで、幅を「広い」と書いてよいのは、符号が崩れておらず、外挿した点にまだ意味が残っているときだけにします。それを確かめる 2 つの仕組みがガードです。

この節は、はじめに登録した設計です。拡散のデコーダのガードは、確かめ V-h2 でずるを捕まえられず、止めました（25 節）。作り直した内容のガードは 26・27 節で説明します。

崩壊の指標

3 節の K1〜K3（sigreg_heldin・rank・token_r2）で、符号が崩壊していないことを確かめます。どの画像にも同じ符号を出せば、符号は止まり、幅はいくらでも広く見えます。崩壊した符号の幅は読みません。

拡散のデコーダで、外挿した点を絵にする

潜在の外挿 2z(t) − z(t − Δ) は、符号の空間の 1 点です。この点を拡散（flow）のデコーダで絵にし、正しい時刻の絵になっているかを確かめます。デコーダは、どの符号に対しても同じ形のものを、後から学びます。条件には、幅を測った座標そのもの（白色化した PCA64）を使い、判定用に新しく学びます。

絵の正しさは、距離や FID では読みません。時間の近い 9 個の候補から、正しい時刻を当てられるかで読みます。外挿の的の時刻は t + Δ で、候補は時刻 t + Δ + jΔ（j = −4〜4）の本物のフレームです。描いた絵と候補を Inception の特徴で比べ、最も近い候補を選びます。偶然なら 1/9 です。刻みは 0.8・1.6・3.2・6.4 秒で、各刻みで 512 個の錨（三つ組の中心 t）を使います。

天井と床

  • 天井 c：本物の符号 z(t + Δ) を描いた絵が、的を当てる割合です。デコーダと Inception で、どこまで当てられるかの目安です。
  • 床 f：今の符号 z(t)（copy）を描いた絵が、的を当てる割合です。
  • e：外挿の点を描いた絵が、的を当てる割合です。

天井が床から十分に離れていない刻みでは、この仕組みで時刻を見分けられません。そこで、天井 − 床 − 2SEtot が 0 を超える刻みでだけ、ガードが読めるとします。これを「天井が床から離れる」と言います。SEtot は、錨の選び方による揺れ（ブロックのブートストラップの SE*）と、デコーダの学習の揺れ σdec を合わせたもので、SEtot = √(SE*² + σdec²) です。σdec は、pca のデコーダを 3 つの seed で学んだ揺れから導きます（V-h3）。値は、モデルの値を見る前に README に書きます。幅は、天井が床から離れる刻みでだけ数えます。

判定

ガードの 4 つの刻みのうち、潜在で外挿が勝つ（p ≥ 1/2）全ての刻みで、次の 2 つを見ます。(1) 天井が床から離れる。(2) 外挿の絵が copy の絵より的を当てる（e − f − 2SEtot > 0）。

書き方条件
ガードを通った潜在で勝つ全ての刻みで (1) と (2) を満たした
ガードで確かめられないどれかの刻みで (1) を満たさない（解像度が足りない）
ガードが割れた(1) を満たし、e − f の区間の上端が 0 を下回った（外挿の絵が copy の絵より当てない）
保留(1) を満たし、e − f の区間が 0 をまたいだ

(2) の境 0 は、幅の定義（外挿が copy に勝つ）を絵の側に当てたものです。経験則の閾値ではありません。ガードの刻みで潜在が 1 度も勝たなければ、幅を「広い」とは言いません。6.4 秒より長い刻みで勝てば、「ガードの範囲外」と添えます。

潜在の中点 ½(z(t − Δ) + z(t + Δ)) を描いた絵も副として並べますが、判定には使いません。中点は未来の端点を使うので、過去から未来へ伸ばす外挿の問いとは違うからです。

対照

同じ錨と同じ候補で、次の対照も並べます。画素の平均の画像、Inception の特徴の平均、pca の中点と外挿、条件なしのデコーダ（uncond）、選択が 1 つの候補に集まる割合（pick_max）、同じ場面の中で錨を入れ替えた条件です。外挿の点は、本物の符号より外側に出やすい性質があります。そこで、本物の符号を同じ距離だけ動かした点の絵も、陽性の対照として記録します。

ガードが保証しないこと

ガードを通っても、「速い内容を捨てていない」とは言えません。Inception が主に遅い背景で候補を見分け、デコーダが速い物体をそれらしく描けば、速い内容を捨てた符号でも通るからです。ガードを通ったときに書けるのは、「外挿した潜在の絵が、時間の近い候補の中で、正しい時刻を copy より当てた」までです。

V-h0i が外れた理由

V-h0i は、区間の被覆の確かめです。帯 + 雑音（V-h0d と同じ系列）の 200 の実現のそれぞれで 95% 区間を作り、真値を含む割合を数えます。主の幅 Δ1 は 0.935、Δ は 0.96、Δtyp は 0.955 で、どれも 0.90 を超えました。外れたのは、プールの窓の上端（境 1/4）で、0.51 でした。

原因は、真値の置き方にありました。真値は、閉じた式の G が 1/4 を横切る、連続の刻み 3.05693 秒でした。一方、推定では、0.1 秒の格子の点（3.0 秒と 3.1 秒）の G を log Δ について直線でつなぎ、横切りを求めます。曲線を直線に置き換えるので、横切りは少しずれます。同じ閉じた式の G を、推定と同じ方法でつなぐと 3.05584 秒になります。連続の真値より 0.0011 秒小さい値です。

200 の実現の区間の中点の平均は 3.05580 秒で、実現の間の標準偏差は 0.00055 秒でした。つまり区間は、格子でつないだ値をよく捉えています。ところが区間の幅（中央値 0.0022 秒）がとても狭いので、格子による 0.0011 秒のずれだけで、半数近くの区間が連続の真値を外しました。真値を含んだのは 102 回で、残りの 98 回は、どれも区間の上端が真値より下でした。

真値の直し

被覆は、推定が目指している量（推定の的）に対して確かめるものです。推定は格子の上で横切りを求めます。そのため的は、閉じた式の G を同じ格子で同じようにつないだ値（3.05584 秒）です。V-h0i の結果を見た後に、ユーザーの承認を得て、真値をこの値に直しました（2026-11-26）。区間は計算し直さず、判定だけをやり直しました。判定し直した被覆は 0.935 で、閾値 0.90 を超えて通りました。実現・seed・閾値は変えていません。

これは、通る条件を探した結果ではありません。真値と推定の的を、同じ定義にそろえる直しです。連続の値との差 0.0011 秒は、格子で区切ったことによる決まった偏りです。この差は、格子の幅（0.1 秒）や Δ*（0.5 オクターブ）より 2 桁以上小さい値です。格子を細かくすると、差は格子の幅の 2 乗に比例して 0 に近づきます。閾値 0.90・実現・seed は変えていません。V-h0d は、はじめから「真値を含む格子の間」で照合しているので、この偏りの影響を受けずに通っています。Δ1・Δ・Δtyp の真値は、長さ 100 倍の実現に同じ推定を当てた値なので、この偏りを持ちません。

直した後も、読み方に 1 つ制限を付けます。プールの横切りでは、格子の解像度（0.1 秒）より細かい差は読みません。直した後の判定は、README の「線形の幅の有効性」に記録します。この直しで変えるのは、合成の確かめの真値の置き方だけです。実データの幅の定義・境・Δ*・区間・ガードは変えていません。

記録として分かったこと

V-h0k では、帯の周期を √2 倍にした対で「区別できた」が 0/200、2 倍にした対で 200/200 でした。周期を √2 倍にしても、Δ1 の真の差は 0.360 オクターブで、Δ* = 0.5 オクターブより小さくなります。0.8 秒から積分を始めることなどが理由です。そのため、「区別できた」が 0 なのは規則どおりです。周期 2 倍の真の差は 0.752 オクターブでした。

探索と確証の区別

なぜ分けるのか

数値を見てから規則を決めると、見た数値に都合の良い規則を選んでしまうおそれがあります。線形の幅では、関連する値の一部をすでに見ています。そこで、どの値を「探索」とし、どの値で「確証」するかを分けます。

V18c までのモデルの 6 つの刻み（0.8〜25.6 秒）の Gmid は、10〜15 節の評価ですでに見ています。線形の幅の定義は、その後に決めました。そのため、V18c までの符号（pca・color・mean8・学習前・v16・v17・V18・V18b・V18c）に当てる細かい刻みの値は、探索の記述とします。判定の言葉を使うときも「探索の記述」と添え、仮説の支持や棄却には使いません。

確証は V19 の checkpoint で行います。次のものは、V19 の値を見る前に固定しました（事前登録）。

  • 幅の定義（p、共通の中心、最初の窓、Δtyp、Δ1、Δ、プールの横切り）
  • 境（1/4 が主、1/2 が副）と、主の範囲（0.8〜25.6 秒）
  • Δ* = 0.5 オクターブと、区間の作り方
  • ガードの手続きと判定、σdec（V-h3 で決まる値）
  • 言葉づかいの規則

V19 での主の比べと、判定の言葉

主の比べは、V19 ともう 1 つの腕との Δ1 の比です。もう 1 つの腕は、batch・FIFO・更新の数・入力の集合を V19 とそろえ、入力の順序だけをシャッフルしたものです。この対で、「ストリームの時間の相関が幅を変えるか」を、他の違いを混ぜずに問えます。

「V19 の線形の幅は、実用上広いと区別できた」と書けるのは、次の 3 つを全て満たすときだけです。(i) 比の区間が +Δ* を丸ごと超える。(ii) V19 の幅がガードを通る。(iii) 崩壊の指標が崩壊でない。言える範囲は、Zurich の 1 本の動画の中での、その checkpoint の比べまでです。

後から定義を変えたくなったら

探索の値を見て定義を変えたくなったときは、変えた定義を V19 の確証には使いません。V19 の後の、別の確証に回します。Fable さんの検討で未決だった点（Nlin を記述として足すこと、主の範囲を 0.8 秒以上にすること、σdec の導き方など）は推奨案として置いており、ユーザーが後から覆せます。覆すときは、覆したことと、覆す前の定義での読みを両方書きます。

既存の結果への注

同じ考えで、10〜15 節の時間の線形性の結果にも注を付けました。計画の V-d2 の注「区間全体が Δ* を超えるかは、その 2 倍の δ で見る」を当てると、Δ* の 2 倍（0.06）以上の登録した差（δ = 0.08）を作れたのは、1.6 秒まででした。3.2 秒では作れないので、3.2 秒の「区別できた」は「解像度が足りず、確かめられていない」と読み替えました（README の表では「区別†」）。

拡散のデコーダのガードは、ずるを捕まえられなかった（V-h2）

なぜ止めたのか

ガードの役目は、ずるで広げた幅を「広い」と言わせないことです（20・21 節）。そこで、pca の符号からわざとずるを作り、ガードがそれを捕まえるかを確かめました。捕まえられなかったので、規則どおりここで止めました。

過去の時間の平均を長くすると、主の幅 Δ1 は 0.8 → 0.8 → 1.07 → 1.54 → 1.92 秒と伸びました。20 節の定理（幅を広げるには遅くするしかない）のとおりです。幅の物差しは、ずるに正しく反応しました。強さ 0 より主張できるほど伸びたのは、6.4 秒と 12.8 秒の平均です。

ところが、この 2 つのずるが潜在で copy に勝つのは、0.8 秒と 1.6 秒の刻みだけでした。その刻みでは、24 節で見たとおり、pca 自身の天井も床から離れません。ガードには何も見えないので、判定は「確かめられない」になりました。登録の規則では、「確かめられない」はずるを捕まえたことになりません。

速い方向を捨てるずる（16〜56 方向）では、どの強さでも 0.8 秒に窓ができず、Δ1 は 0.8 秒のままでした。主張できる差が出なかったので、この族では確かめられませんでした。

理由は 2 つある

  • 解像度が足りない：ずるが幅を稼ぐ短い刻みで、デコーダの絵に時刻の情報が残っていません。実装の誤りは見つかりませんでした。
  • 問いの形にも穴がある：時刻の同定は、「残った内容で、近い候補の中から正しい時刻を選べるか」を問います。遅い内容さえ残っていれば、速い内容を全て捨てても選べます。Codex さんの反例では、周期 30 秒と 0.9 秒の回転を足して 9 フレームで平均すると、速い回転は消えます。それでも、遅い回転から全ての刻みで時刻を当てられ、幅だけが伸びます。

閾値・刻み・候補の間隔・seed を変えて、通る条件を探すことはしません。ガードを作り直すなら、それは新しい設計です。V19 の値を見る前に登録し直します。

内容のガード：幅と保たれた内容の 2 本の軸で読む

なぜこの形にしたのか

幅を広げるには、符号を遅くするしかありません（20 節）。遅くする方法には、速い内容を捨てるもの（ずる）と、同じ内容をまっすぐな座標に並べ直すもの（望む改善）があります。幅だけでは、この 2 つを区別できません。そこで、幅と「保たれた内容」の 2 本の軸で読むことにしました。

内容を、観測の再構成で測る

内容の軸は、「同じ時刻の符号から、その時刻の観測をどれだけ戻せるか」で測ります。観測は、stack の最後のフレームを 32×32 画素に縮めたものです。符号は、幅を測った座標そのもの（白色化した PCA64）です。符号から観測を戻す小さなネットワーク（MLP）を、読み出しと呼びます。読み出しは Zurich 以外の動画で学び、Zurich で評価します。並べ直した符号を罰さないように、読み出しは線形ではなく非線形にしました。

  • 現在の内容 E：観測の分散のうち、読み出しで説明できた割合です。1 なら完全に戻せ、0 なら平均の絵と同じです。
  • 変化の内容 Ed：0.1 秒の観測の変化のうち、読み出しの差で説明できた割合です。画面の一部だけの速い動きは、全画面の誤差には小さくしか効きません。そこで、変化そのものを的にした量も並べます。

比べ方

2 つの符号 a・b の内容の比を、ψ = log2(Ea / Eb) とします。負なら、a が内容を落としています。変化の内容でも、同じ形の ψd を作ります。許す損失 ψ* は 0.1 オクターブ（説明された分散の 6.7%）です。これは理論から導いた値ではなく、実用上の選択として登録しました。

  • 幅の比が +Δ* を丸ごと超え、ψ・ψd の下端がどちらも −ψ* を超える：内容を落とさずに、幅が実用上広いと区別できた
  • 幅の比が +Δ* を丸ごと超え、どちらかの上端が −ψ* を下回る：幅は広いが、内容を落とした（前線の上を動いただけ）
  • 比べる相手の E・Ed の下端が 0 を超えないときは、「内容を比べられない」とし、幅を広いとは言いません。

速い方向を捨てる射影のように、同じ時刻の符号の関数で作ったずるでは、読み出しの最良の誤差は、元の符号より小さくなりません（命題 1）。ただしこの命題は、読み出しが族の中の最良に届くことを前提にしています。

V-h4b3実データ：本物の物差しを「落とした」と言わない外れた 物差しの 9 個全てで Ed の比べる条件を満たさない

外れた理由 1：読み出しが、学んだ区間を覚えてしまった

読み出しの MLP は、相関の強い 512 個の区間を約 39 周して学びます。訓練に使っていない区間（分布は訓練と同じ）で確かめると、どの符号でも MLP の E が最小二乗の E を下回りました（pca で 0.609 対 0.737）。時間の平均の符号は、1 つの区間の中でほとんど動きません。そのため MLP は、「区間の名前」から「その区間の平均の絵」への対応を覚えたと考えます。訓練の外では、この対応は平均の絵より悪くなり、E が負になりました（12.8 秒の平均で −1.659）。命題 1 の前提「読み出しが族の中の最良に届く」が、同じ分布の上で崩れていました。

外れた理由 2：水準の読み出しの差では、変化を測れない

Ed では、変化を、水準を戻す読み出しの差 g(ct) − g(ct−1) で予測します。この差の誤差は、隣り合う時刻の水準の誤差の差です。水準の誤差の自己相関を ρ とすると、差の誤差は約 2(1 − ρ) × 水準の誤差 になります。Zurich では、0.1 秒の変化の分散が、水準の分散の 7.25% しかありません。pca では、ρ = 0.90 でも、差の誤差が変化の分散とほぼ同じ大きさになり、Ed ≈ 0 になりました。そのため、本物の物差しを含む全ての符号で Ed ≤ 0 でした。

外れた理由 3：合成の確かめが、この 2 つを捕まえられなかった

合成の符号は 2〜4 次元と小さく、訓練の系列は 1 本の長い連続した系列でした。実データの「相関の強い 512 個の区間」という構造がないので、過学習も Ed の問題も起きなかったと考えます（推測）。

最小二乗の読み出しは、ここで外れた形を示しませんでした（捨てる方向を増やすと単調に下がる）。しかし、最小二乗は、非線形に並べ直した符号を罰してしまいます。この結果を見てから最小二乗に切り替えると、通る条件を探すことになるので、記録にとどめました。

いま言えること：「狭い」はガード無しで言える

なぜガード無しで言えるのか

ガードは、内容を捨てて幅を見かけ上広げる操作を防ぐためのものです。こうした操作で、幅が狭く見えることはありません。そのため、「物差しより狭い」という結果は、ガードが無くても言えます。ガードが必要になるのは、「広い」と主張するとき（V19 以降）です。

実データの結果（探索の記述）

学習した符号 34 個（V18・V18b・V18c・VAE）と物差しの線形の幅を測りました。結果は report-jepa.html の 18 節に図でまとめています。23 節のとおり、これらは探索の記述です。

  • 0.8 秒以上には、どの符号にも窓がありません。Δ1 は全て 0.8 秒で、0.8 秒以上の幅では符号の違いを言えません。
  • 0.8 秒未満でも、学習した符号は画素の物差しより幅が狭い。窓の上端は、学習した符号で 0.138〜0.310 秒か窓が無い状態で、pca の 0.388 秒、mean8 の 0.437 秒より短い値です。
  • 学習前に窓が無かった符号の多くで、学習後に 0.2〜0.3 秒の窓が現れました。V18c（学習率 10−4）の λ = 0.8・0.95 では、60000 step で窓が消え、0.8 秒のプールの G が 0.69〜0.72 に上がりました。λ = 0.5 では、境 1/2 の Δ が伸びました（1.75 秒、pca は 1.37 秒）が、窓はありません。この伸びが内容を保ったものかは、ガードが無いので言えません。

作り直しの方向

いまは、ガードを作り直している最中です。理論から出る方向は次の 3 つで、どれも V19 の値を見る前に登録し直します。

  1. 読み出しを、族の中の最良に近づける：訓練の外の区間の誤差で、学習を止める時点などを選びます。命題 1 は母集団の誤差についての命題なので、同じ分布の独立な区間で選ぶことは、その前提に近づける操作です。
  2. 変化を、変化を的にした読み出しで測る：前後 2 時刻の符号から、観測の変化を直接に読みます。水準の誤差の自己相関に左右されなくなります。
  3. 合成の確かめも、区間の構造にそろえて回し直す：実データで起きた 2 つの問題を、合成でも捕まえられるようにします。
