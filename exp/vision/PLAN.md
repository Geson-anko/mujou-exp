# vision: 単一ストリームから PC-ALM で VAE のエンコーダを学ぶ

2026-11-18 にユーザーと決めた計画。`exp/video`（M0〜M18）の続きにあたるが、基礎を詰め直すため、番号を V0 から振り直す。`exp/video` は凍結し、レポートと結果の保管庫として残す。

## 目的

Walking Tours の単一ストリームから、視覚の入力を低次元の「良い」特徴量へ写すエンコーダを、PC-ALM だけで学ぶ。「良い」とは次の 2 つを満たすこと。

- この先で学ぶ動力学モデルが予測しやすい
- 入力の情報がある程度保たれている

M18 では、PC-ALM でも VAE のエンコーダがある程度学べることが分かった。V では、VAE が安定して学べる設定と、その限界を探る。

## 前提（2026-11-18 の決定）

| 項目 | 決定 |
| ---- | ---- |
| データ | Walking Tours（`exp/video` と同じ）。0.1 秒間隔で $n$ 枚を積む。$n \in \{4, 8, 16\}$、基準は 8。解像度は 64×64（128 は確かめにだけ使う） |
| 目的の式 | VAE（ELBO）。潜在空間をガウスに寄せるため。デコーダは軽い形でシステムの中に置き、エンコーダと一緒に学ぶ |
| 学習則 | エンコーダもデコーダも PC-ALM だけで学ぶ。BP の run は回さない（テストのオラクルとしての BP の勾配は使う） |
| 実行 | `mujou.run_manually`（`ManualRun`、全ノードを同時に更新する Jacobi）。実時間で進む `mujou.run` は使わない |
| モデル | ViT と ResNet。ノード数は大きさによらず固定し、S・M・L は 1 ノードの中の層の数で分ける。同じ大きさの 2 つはパラメータ数を揃える。デコーダはどの大きさでも同じものを使う |
| optimizer | SGD から始め、時定数の momentum（下の節）、RMSProp、AdamW の順に試す。学習率は安定して動く程度に選び、性能のために詰めない |
| 初期化 | 既定の初期化を使う。安定して学べないときに考える |

ノード数を固定するのは、Jacobi の実行では credit が 1 ステップに 1 ノードずつ戻るためである。ノード数が変わると credit の遅れも変わり、モデルの大きさの効果と交絡する。

## 評価

判定の中心は「初期化時より下がること」。copy の予測より良いかどうかは問わない。学習の目的の式は ELBO だが、評価で見る損失は再構成誤差だけで、ELBO 全体・KL・bpd は判定に使わない。

- 再構成誤差
- posthoc の `recon_blur`（後から学ぶデコーダ。M17・M18 と同じ物差し）
- `dyn_1/copy_1`（潜在空間の上の線形の動力学。この先の動力学モデルのために必要）
- 定性評価: 再構成の画像を目で見る
- 参考: Imagenette の linear probe の精度

### 評価の拡張: 軽量の拡散デコーダ（2026-11-18 決定）

抽象的な特徴量では細部が失われ、決定的なデコーダの再構成がぼやける可能性がある。複雑な生成分布を暗にモデル化できるデコーダで、細部の欠落が符号のせいかデコーダのせいかを切り分ける。V0 には入れず、V1 で checkpoint が出始めた頃に並行して作る。

- 形: checkpoint のエンコーダを止め、その $\mu$ を条件にした $p(x \mid z)$ を posthoc で BP で学ぶ。評価の道具なのでシステムには入れず、`exp/lib` に置く
- 方式: flow matching（rectified flow）。損失は速度の二乗誤差だけで、サンプリングは Euler 法
- ネット: 64×64 の小さな U-Net。$z$ は FiLM で入れる
- 対象: stack の最後の 1 フレーム。train の区間で学び、val で評価する
- かける checkpoint: 各 run の最後と初期化時、ほかに選んだ数点

拡散のサンプルは、$z$ に無い細部ももっともらしく描く。サンプルと $x$ の二乗誤差は、条件付きの分散のぶんだけ決定的なデコーダより大きくなる。このため `recon_blur` の代わりにはせず、次の 3 つに使う。判定はほかの指標と同じく、初期化時の checkpoint との比べ。

1. 目視: 同じ $z$ から数枚サンプルし、平均とピクセルごとの標準偏差を並べる。標準偏差の地図が、$z$ で決まっていない所（符号が失った情報）を示す
2. 情報量の推定: 同じネットを $z$ なし（無条件）でも学び、flow matching の尤度の上界の差から $I(x; z)$ を推定する。上界どうしの差なので厳密な界ではなく推定値
3. Inception V3 の特徴の誤差: サンプルと $x$ を 299 にアップサンプルして比べる。参考にとどめる

## momentum を時定数で定義する

mujou の optimizer は経過時間 $\Delta t$ で進むので、momentum も 1 更新あたりの $\beta$ ではなく、時定数 $\tau$（秒）で定義する。

$$
v \leftarrow e^{-\Delta t/\tau}\, v + \left(1 - e^{-\Delta t/\tau}\right) g, \qquad
\theta \leftarrow \theta - \eta\, \Delta t\, v
$$

勾配の指数移動平均の形にしておくと、勾配が一定のときの一歩の大きさは SGD と同じになる。違いは「過去 $\tau$ 秒の勾配を平均するかどうか」だけになり、実効の学習率を揃える必要がない。$\tau \to 0$ で SGD に戻り、更新の頻度（`learn_interval`）を変えても意味が変わらない。RMSProp の二乗平均も同じように時定数で定義する。どちらも mujou の `pc.optim` に足して PR を送る（skill `mujou-upstream`）。

ストリームでは隣り合う時刻の勾配が強く相関するので、momentum が学習にどう作用するかを見るのが V の問いの 1 つである。

## 進め方

決まった順番にはこだわらない。VAE が安定して学べる設定と、その限界を行き来しながら探る。

- 出発点: ViT-S・64×64・8 枚・SGD
- 動かす軸の候補

| 軸 | 値 |
| -- | -- |
| モデル | {ViT, ResNet} × {S, M, L} |
| momentum | SGD と $\tau$ の数点（例: 0.1・1・10 秒） |
| stack の枚数 | {4, 8, 16} |
| 適応的な optimizer | RMSProp、AdamW |

全部の組み合わせは回さない（3 × 6 × 4 を超え、PC-ALM の run は B = 1 で 1 本 1 時間以上かかる）。1 軸ずつ動かし、絞り込みは 1 seed、選んだ点だけ seed を足す。

### V0: 土台

1. mujou を `origin/main` に上げる（`run_manually`、Jacobi、`g_in` を緩和後の δ から返す変更を取り込む）
2. mujou に時定数の momentum 付き SGD と RMSProp を足し、PR を送る
3. `exp/vision` を作る。`exp/video` から、テストで裏付けのある部品だけを移す（Walking Tours の読み込み、posthoc、VAE の PC-ALM の組み方）
   - データ: 0.1 秒間隔の stack、64×64
   - モデル: ViT と ResNet、固定のノード数、S・M・L、パラメータ数の表
   - VAE の PC-ALM と `run_manually` のループ
   - 評価: 上の「評価」の、拡張以外の全部
4. 小さなネットで、PC-ALM の勾配を BP の勾配のオラクルと比べるテスト
5. bench で全モデルの速さを測る（リアルタイムの目標との比べ。[memory の feedback_realtime_speed](../../memory/feedback_realtime_speed.md)）
6. 出発点の設定で試しの run を回す

### V1 以降

各 run の前に、判定の基準と予想を results に書いてから回す（[exp/README.md](../README.md) と同じ運用）。番号は、動かす軸の区切りごとに振る。

## 運用

- 1 区切り 1 PR。ブランチは `exp/<日付>/vision-v<n>-<内容>`
- run は std-00〜03（4090、ssh）で、4 台に分けて並列に回す。mini-00（5070 Ti）は試しの run とデバッグにだけ使う
- run の投入・監視、posthoc、表の集計などのルーティンワークは、sonnet のサブエージェントか Workflow に任せる。計画・判定・結果の読みはメインで行う
- 再現性: seed、設定、mujou の SHA を run に記録する（`exp/lib/provenance.py`）
