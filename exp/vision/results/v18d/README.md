## 回す前に決めたこと（2026-11-27 改訂）

**時空間の補完の V18d の値は、まだ 1 つも出していない。** 学習も評価も回していない。ここに書く数は、既存の結果の引用と理論値だけである。腕・掃引・選び方・判定は、私たち（Claude）の決定である（ユーザーは「判断を仰がず試行を続けて」と任せている。ユーザーが覆せる）。目的の方向（時空間の補完、非再帰、今・未来・過去の統合）と、評価を今・過去・未来で別々に出すことは、ユーザーの決定である。V18d は探索の段で、判定は 2 つの seed での再現の確かめとして報告する。

**置き換えた版について**: 2026-11-27 の初めの登録（コミット 300327b）は、線形の時間の予測器の項を足す版だった。ユーザーの方向で、値を見る前に時空間の補完へ一般化して置き換えた。その版の短い run 27 本と選択の数の一部は NAS で計算されたが、この登録を書いた段では読んでおらず、新しい設計の選択にも判定にも使わない（下の「置き換えた版の記録」）。

### 問いと仮説

- **問い**: 学習の目的を、時間に並んだ 4 つの stack の時空間の格子の補完（今の空間・未来・過去・間を 1 つのマスクの族で隠し、1 つの非再帰の予測器で当てる）に一般化すると、今・過去・未来のそれぞれの評価で、V18c までの符号が届かなかった「予測が良い」になるか。そのとき、観測の内容を V18c より落とさないか
- **仮説 H1F（主。未来）**: 時空間の補完を学ぶと（腕 ST）、dyn/copy（未来 F）の copy と clim の両方の分母で、`pca`、同じ設定の V18c、自分の学習前より予測が良くなる。同時に、内容のガードの最小二乗の読み出しの $E$（水準）と $E^d$（変化）は V18c より下がらない
  - $E^d$ を足した理由: 導出（計画の (d)）で、遅くするずるは 2 つの分母の規則を「良い」で通り、変化 $E^d$ で最もよく捕まる（`pca` を時間で平均すると $E^{d,\mathrm{lin}}$ が 0.0638 から 0.0189〜0.00847 へ下がる）。dyn/copy の「良い」の条件も、水準と変化の両方の非劣性を求める
  - 最小二乗にする理由: 内容のガード v3 は V-h5a1（合成の陽性の対照）で外れた。MLP の読み出しが区間を記憶し、非線形な符号の $E$ を約 0.14 低く読む。最小二乗は記憶しない。代わりに、非線形に並べ直した内容を低く読む。支持しても言えるのは「線形に読める内容を V18c より落とさなかった」までで、「内容の比べは未確立」と添え、「良い」とは書かない
  - **H1F の支持だけでは「観測の予測が良くなった」とは言わない。** 内容を保ったまま、予測しやすいが観測の内容を持たない成分を足した符号は、H1F の全ての条件を通りうる（計画の表の (i)）。それを分けるのが H2 である
- **仮説 H1P（副。過去）**: 同じ ST は、過去の予測 P でも、同じ 3 つの相手より良く、内容を落とさない
- **仮説 H1N（副。今）**: 同じ ST は、今の予測 N（同じ時刻の重ならない 2 つの半分の符号の間の予測）でも、同じ 3 つの相手より良く、内容を落とさない
- **仮説 H2（副。観測の予測）**: 同じ ST は、全ての符号で同じ的（Zurich の未来・過去の 32×32 の観測、今は隠した半分の観測）に対する予測の誤差 $\overline{\log F_X}$ でも、`pca` と同じ設定の V18c より良い。切り口 $X \in \{F, P, N\}$ ごとに判定する
- **仮説 H3（副。自分の空間での補完の同定）**: ST の予測器は、自分の表現空間で、隠した時刻のトークンを copy の対照より正しく同定する（計画の「自分の予測器による補完の同定」）
- 帰属（記述）: 上の各切り口で、ST と時間の対応を壊した ST-perm の比べを並べ、改善が正しい時間の対応から来るかを書く

### 腕と学び方

| 腕 | 損失 | 備考 |
| -- | -- | -- |
| S（対照） | V18c の $(1 - \lambda) L_{\mathrm{pred}} + \lambda S$ | 既存の run（短い run は `runs/v18c-screen`、長い run は `runs/v18c-long`）。$K = 1$ の場合 |
| **ST（主）** | $(1 - \lambda) L_{\mathrm{ST}} + \lambda S$ | $K = 4$、マスクは管 436 + 時間の側 6（各 step 64 clip ずつ）、SIGReg は時刻の番号ごと |
| ST-perm（対照） | ST と同じ。番号ごとに役の範囲から独立に stack を引き直し、時間の対応を壊す | ST で選んだ設定だけ |

- 刻み $n$ は clip ごとに $\log n \sim U[\log 8, \log 512]$（0.8〜51.2 秒）。予測器の位置の符号は $e_P(p) + \phi(u_i) + \psi(\log_2(n/8))$
- ほかは V18c と同じ: ViT-S（幅 1024・μP・パッチ 8）、固定の $R$・$W$、予測器（幅 256・4 段、入力 $h$）、AdamW、$B = 128$ clip、warmup 1000 step と cosine、$r = 0.5$、データは Zurich 以外の訓練の動画の全て
- **揃え方**: step 数と clip の数（= マスクの数、SIGReg の番号ごとの $N$）で V18c と揃える。1 step に見る stack は 4 倍（512）になり、それは ST-perm で外す（計画の「揃えるもの・揃わないもの」）

### 掃引（短い run、6000 step、seed 0）

ST の学習率 $\{10^{-5}, 3 \cdot 10^{-5}, 10^{-4}\}$ × $\lambda$ $\{0.5, 0.8, 0.95\}$ の **9 本**。$r = 0.5$。checkpoint は step 0・1000・2000・4000・6000。名前は `v18d-st-lr<lr>-lam<λ>-r0.5-s0`。マスクの族の軸は掃かない（2 つの側の重み 1/2 は取り決めで、値を見て動かさない）。ST の選択が済んだら、選んだ設定の ST-perm の短い run を 1 本足す（記述。選択には使わない）。

- **試し**（空いている 4090 で、ST と ST-perm、学習率 $10^{-4}$・$\lambda$ 0.5 を 200 step）: 40〜200 step の平均の秒 / step $t$ と `max_mem` を測る。`max_mem` が 22 GiB を超えたら `--checkpoint-blocks`（値は変わらない）で測り直す。データの先読みが詰まっていないか（GPU の使用率）も見る
- **予算**: 短い run の全体の時間 $W = 10 \cdot 6000\,t / G$（ST-perm の 1 本を含む。$G$ は使える 4090 の数。GPU の 2 本目は 1 本目の使用率が 60% 未満でメモリに余裕があるときだけ数える）。見込み（推測）は $t$ = 0.38〜0.48 秒、1 本 40〜50 分、$G = 4$ で 3 巡、2〜2.5 時間。**$W$ が 24 時間を超えたら**、学習率 $3 \cdot 10^{-5}$ の列を削る（V18c に同じ学習率の長い run が無い列）。それでも超えたら回さずに報告する
- **実行の順**: 試し → 学習率 $10^{-4}$（判定保留の基準）→ $10^{-5}$ → $3 \cdot 10^{-5}$
- fleet: std-00〜03 の 4090、コンテナ `mujou-exp-dev-1` の中。snapshot を固定する job スクリプト（`/nas/geson/mujou-exp/runs/v18d-st-*/scripts/`、v18c-width・v18c-dyn の形）。環境は `OMP_NUM_THREADS=1 CUBLAS_WORKSPACE_CONFIG=:4096:8 MUJOU_EXP_DATA=/data/geson/mujou-exp/.fleet/data`。CPU は 1 台 14 プロセスまで

### 短い run の判定（step 6000。Zurich を使わない）

崩壊・発散・判定保留の形は V18c の「回す前に決めたこと」の規則のとおりにする。V18c が Zurich で測っていた量は、全て dyn/copy の組の**検証の動画**（seed 4101 の置換の 2 本目。JEPA の訓練には入っている）で測る。閾値の物差し（V18 の `color`、`color8`、`init_c`）は、置き換えた版の段で検証の動画で測った `runs/v18d-select/yard` をそのまま使う（物差しの値で、V18d の値ではない）。

- **崩壊**: K1 `sigreg_heldin` ≥ 26.7（4 つの番号の平均）、K2 検証の動画の `rank` が `color` と `init_c` の小さい方より小さい、K3 検証の動画の `token_r2` ≥ $\theta_3 = (1 + \max(\texttt{token\_r2}(\texttt{color8}), \texttt{token\_r2}(\texttt{init\_c})))/2$。発散も不合格
- **判定保留**: 同じ $\lambda$ の、崩壊していない run のうち学習率が最大のものを基準にする。基準でない run は、`sigreg_heldin` か検証の補完の損失 $L^{\mathrm{rel}}_{\mathrm{ST}}$ が基準より 0.05 を超えて大きければ、判定保留とする
- **合格**: 崩壊・発散・判定保留でなく、`sigreg_heldin` < 2.0、$L^{\mathrm{rel}}_{\mathrm{now}}$ < 0.95、かつ $L^{\mathrm{rel}}_{\mathrm{time}}$ < 0.95（2 つの側のそれぞれで、自分の予測器が位置ごとの平均の予測を 0.05 を超えて下回る。片方の不足を他方で相殺しない）
- $L^{\mathrm{rel}}_X$ は、検証の動画の全体から引いた固定の 512 個の clip（13 点の刻みの格子に均等）に、時間の側の 6 つと固定した 8 個の管をかけた、位置ごとの平均を分母にした相対の二乗誤差。$L^{\mathrm{rel}}_{\mathrm{ST}} = \tfrac12 (L^{\mathrm{rel}}_{\mathrm{now}} + L^{\mathrm{rel}}_{\mathrm{time}})$（計画の「検証の補完の損失」）
- 制限: 判定保留の規則は、短い run で損失を早く下げる設定を優遇する。6000 step で完結する cosine と、60000 step の cosine の途中では学習率が違う（Codex さんの指摘）。短い run の選択は長い run の性質を保証しない

### 長い run の選び方（値を見る前に固定）

1. 候補は、短い run の合格
2. **内容の適格**: 候補と、同じ学習率・$\lambda$ の V18c の短い run（step 6000）に、内容のガード v3 の手順（`content_eval real3 --model --no-eval`。Zurich を出さない経路）を当て、最小二乗の読み出しの $E^{\mathrm{lin}}$・$E^{d,\mathrm{lin}}$ を**検証の区間**（訓練の動画の、読み出しの当てはめに使っていない区間）で出す。V18c の 9 本の値は、置き換えた版の段で計算した `runs/v18d-select/content3` の V18c の行をそのまま使う（同じ手順・同じ区間）。$D = E_a - 2^{-0.1} E_b \ge 0$（点推定）を $E$ と $E^d$ の両方で満たせば適格とする。V18c の値が `fidelity.comparable` の条件（検証の区間のブロックの抽出で下端 > 0）を満たさない量は、その量の確かめを外して記録する
3. 適格な候補のうち、$L^{\mathrm{rel}}_{\mathrm{ST}}$ が最小のものを選ぶ。最小から 0.01 以内にほかがあれば、その中で検証の区間の $E^{\mathrm{lin}}$ が最大のもの。それも同じなら学習率の大きいもの
4. 適格な候補が無ければ、合格のうち $\min(D_E, D_{E^d})$ が最大のものを選び、「内容の適格なし」と書く
5. 合格が 1 本も無ければ、長い run を回さない。そのこと自体を結果とし、原因を目的の式の導出と照らして調べる。H1F〜H3 は「判定できない」とする
6. 内容のガードが測れない（`Whitener` が採点できないなど）候補は、合格から外す

内容の適格を課す理由: 導出 (d) で、$L_{\mathrm{time}}$ は遅くするずるで下がり、SIGReg はそれを罰しない。補完の損失だけで選ぶと、規則は系統的に、ずるが最も進んだ設定を選ぶ。

**長い run**（60000 step、seed {0, 1}、checkpoint は V18c の長い run と同じ 0・2000・6000・10000・20000・30000・40000・50000・60000。名前は `v18d-st[perm]-long-lr<lr>-lam<λ>-r0.5-s<seed>`）:

- ST の選んだ設定 × 2 seed、**同じ設定の ST-perm × 2 seed** の 4 本
- 対照の V18c の長い run は、学習率 $10^{-4}$・$10^{-5}$ × $\lambda$ 全て × seed 0・1 が既にある。**選んだ学習率が $3 \cdot 10^{-5}$ なら、同じ設定の V18c の長い run（seed 0・1）も回す**
- 見込み（推測）: 1 本 6.5〜8 時間。4 台の 4090 で 1 巡

  - 今 N: 左右・上下の半分の符号の間の 1 点入力の予測。copy の分母は平均で補正した copy。V-p2d を N で回す

### 有効性の確かめ（新しい評価。値を見る前に固定。外れたら止めて直す）

既存の F は dyn/copy の V-p1・V-p2 を通っている。新しい P・N・B と H2・H3 の段は、実データの符号に当てる前に次を通す。外れたら、その切り口の判定は出さず記述に下げる。刻み・格子・閾値を変えて通る条件を探さない。

- **V-r1（P の時刻）**: フレームの番号を値にした合成の符号で、P の的が $w_{u-n}$、入力が $[w_u, w_{u+n}]$ であることを手計算と照合する
- **V-r2（P の神託）**: OU（既知の $r$）で P の線形の $R_{\mathrm{clim}} = 1 - r^2$、$R_{\mathrm{copy}} = (1 + r)/2$（長い実現で、推定の SE の 3 倍以内）。白色化した VAR(1) の正規でない例で、1 点入力の線形の $A$ が 0（同）、2 点入力の対数の行列式が F と P で等しい
- **V-r3（P の帰無）**: dyn/copy の V-p1h と同じ形で、同じ過程の独立な 2 つの符号に P の判定を当て、「区別できた」が 200 のうち 13 以下
- **V-b1（B の恒等式）**: 中点の $R_{\mathrm{copy}} = G_{\mathrm{mid}}$、等速の F・P と中点の分子が 4:4:1（相対 $10^{-10}$）
- **V-n1（N の漏れ）**: 他の半分の画素を乱数に替えても、$e_H$ がビットまで変わらない（学習前と ST の checkpoint の両方で）
- **V-n2（N の神託）**: 左右の符号を既知の相互共分散の結合ガウスにした合成で、線形の $R$ が閉じた式に一致（推定の SE の 3 倍以内）。半分ごとに違う定数を足しても、補正した copy の $R_{\mathrm{copy}}$ が変わらない（相対 $10^{-10}$）
- **V-n3（N の帰無）**: V-r3 と同じ形で、「区別できた」が 200 のうち 13 以下
- **V-p2d（切り口ごと）**: dyn/copy の V-p2d と同じ規則を P と N で回す。通らない切り口は主の族を線形にする（値を見る前に決めた切り替えの規則）
- **V-f1〜V-f3（H2）**: 前の版の登録のとおり。V-f1（時刻の取り違え）は F・P・N の全てで、V-f2（恒等の読み出し）、V-f3（`clock` 対 `pca` で $\phi_F$ の区間が 0 より下に出ない）
- **H3**: `self_eval` の既存の V-s0〜V-s6 を時間の切り口でも回す。加えて、`copy` の対照に的そのものを置くと $A = 1$（的の時刻と同じ stack の行が候補にあるため）、`const` で全て引き分け

### H1F の判定（主。ST、seed ごと）

各 seed $s$ で、ST（step 60000）について:

- **seed で支持**: 次を全て満たす
  1. 対 `pca`・対 V18c$_s$・対 学習前$_s$ の全てで、F の主の族で「a の予測が b より良いと区別できた」（$\psi_{\mathrm{copy}}$・$\psi_{\mathrm{clim}}$ の区間がどちらも 0 より下）
  2. 崩壊していない
  3. 対 V18c$_s$ で、最小二乗の $E^{\mathrm{lin}}$ と $E^{d,\mathrm{lin}}$ の $D$ の区間がどちらも 0 より上（「保つ」）。ただし V18c$_s$ の $E_b$ の区間の下端が正でない量は比べられないとし、その seed は保留にする（Codex さんの指摘）
- **seed で棄却**: 次のどれかに当たる
  1. 3 つの相手のどれかに対して、「b の予測が a より良いと区別できた」か「分母で向きが割れた」
  2. 対 V18c$_s$ で、$E^{\mathrm{lin}}$ か $E^{d,\mathrm{lin}}$ の $D$ の区間が 0 より下（「落とす」）
  3. 崩壊した
- **それ以外は seed で保留**。「区別できない」と、内容の「分けられない」「比べられない」はここに入る。検出できないことを棄却に数えない
- **H1F**: 2 つの seed がどちらも支持なら**支持**、どちらも棄却なら**棄却**、それ以外は**保留**
- 多重性: H1F は主なので、区間の倍率は dyn/copy のまま（±2SE）。2 つの seed は Zurich と `pca` を共有し、seed 0 は選択にも使うので、誤りの確率を 2 乗できない。判定は探索の再現の確かめとして報告する
- 支持のときも「内容の比べは未確立（v3 が V-h5a1 で外れた。最小二乗の範囲での非劣性）」と添える
- **帰属**: 対 ST-perm$_s$ の F の判定の言葉を並べる。H1F が支持で、対 ST-perm が「区別できない」なら、「改善は時間の対応ではなく、4 倍の stack か動画の中の共有で説明できる可能性がある」と書く（H1F の判定は変えない）
- 自分の学習前との比べの線形の族、0.1〜0.8 秒は記述として並べる。言える範囲は、Zurich の 1 本の動画の中での、PCA64 の計量の比べまでで、学習した刻みの範囲（0.8〜51.2 秒）の中での、未知の動画への潜在の予測しやすさの転移である

### H1P・H1N の判定（副）

H1F と同じ規則を、P と N の主の族で当てる。ただし副の 2 つを独立に判定するので、区間は Bonferroni（$m = 2$、倍率 2 を $z_{1 - 0.025/2} = 2.24$ に替える。dyn/copy の「V19 で確証する手順」の 3 と同じ形）にする。内容と崩壊の条件は H1F と同じ（同じ符号なので共有）。H1P・H1N は H1F を救わない（H1F が保留・棄却のとき、P や N の支持で「良い」とは書かない）。3 つは並べて読む。

### H2 の判定（副。ST、seed ごと、切り口ごと）

切り口 $X$ ごとに、V-f1〜V-f3 が全て通ったときだけ判定する。対 `pca` と対 V18c$_s$ の $\phi_X$ の区間がどちらも 0 より下なら seed で支持、どちらかが 0 より上なら seed で棄却、それ以外は保留。2 つの seed で揃えば支持・棄却、それ以外は保留。区間は Bonferroni（$m = 3$、倍率 $z_{1 - 0.025/3} = 2.39$）。対 ST-perm と画素の持続・`pixel` は記述として並べる。

### H3 の判定（副。ST、seed ごと）

時間の 3 つの切り口（未来・過去・間）のそれぞれで、刻み $n \in \{8, 32, 128\}$ の平均の $A(\texttt{pred}) - A(\texttt{copy})$ と、今の切り口の $A(\texttt{pred}) - A(\texttt{pool})$ の区間（Zurich の候補の 128 秒のブロックの抽出、2000 回、±2SE）を出す。

- **seed で支持**: 4 つの切り口の全てで区間が 0 より上
- **seed で棄却**: どれかで区間が 0 より下
- それ以外は保留。2 つの seed で揃えば支持・棄却、それ以外は保留
- 対照として ST-perm の同じ量を並べる（記述）。V18c には時間の切り口が無いので、今の切り口だけを並べる
- 自分の空間の中の量で、空間が何を持つかは測らない。崩壊の指標と並べて読み、H3 の支持だけでは良い表現とは言わない

### 条件つきの次の段（値を見る前に登録する）

次の 2 つを両方満たしたら、予測器の入力を $t = R h$ にした腕 ST-t を、選んだ学習率・$\lambda$ で長い run（seed 0・1）として回し、同じ規則で判定する（計画の自明な解 (c)）。

1. H1F が支持でない
2. 固定したエンコーダの上の予測器の学び直しで、`pathway_gap` = $\log L^{\mathrm{rel}}_{\mathrm{time}}(t) - \log L^{\mathrm{rel}}_{\mathrm{time}}(h)$ が、2 つの seed の両方で 0.1 を超える（$h$ の通り道が、時間の補完の誤差を 10% を超えて下げている）

0.1 は、dyn/copy の探索で MLP と線形の差が −0.010〜+0.001 だったことに比べて十分大きい幅として、値を見る前に置いた取り決めである。

### 予想（私たち（Claude）の推測。数はどれも推測）

1. 短い run は K1・K2 で崩壊しない。K3 は目的の式で排除される（$\lambda \ge 0.5$、計画の (b)）ので起きない。$L^{\mathrm{rel}}_{\mathrm{now}}$ は V18c の `pred_ratio_calib` と同じ程度（0.5〜0.8）、$L^{\mathrm{rel}}_{\mathrm{time}}$ は 0.6〜0.9 で、$\lambda$ が小さいほど低い
2. 内容の適格: $\lambda = 0.5$ の学習率 $10^{-4}$ は $E^{d,\mathrm{lin}}$ で適格から外れる見込みがある（遅くする向き）。$\lambda \ge 0.8$ は適格になる見込みが高い
3. 長い run の F: 対 V18c で $\psi_{\mathrm{clim}} < 0$（−0.05〜−0.3）になる。同時に $\Delta\overline{\log(V/D)} > 0$（遅くなる）なので、$\psi_{\mathrm{copy}}$ は $\psi_{\mathrm{clim}}$ より 0 に近い。言葉は「区別できない」か「分母で向きが割れた」（copy で高く clim で低い、遅くなった形）が多い
4. P: 学習の課題は反転で対称なので、F とほぼ同じ判定になる。線形の矢 $A$ は ST・`pca`・V18c のどれも 0 に近く、ST と `pca` の差は区間の中に入る
5. N: 管の課題は V18c にもあるので、対 V18c は「区別できない」が最も多い。管が他の時刻の文脈を使えるぶん、1 つの stack の空間の予測しやすさを作る圧力は V18c より弱く、N はやや悪くなる側を予想する
6. 対 ST-perm: ST-perm も遅くなる（動画の平均を当てるには、動画の中で変わらない量を持つのが得なので）。ST との差は ST と V18c の差より小さい
7. H2: V18c の $E^{\mathrm{lin}}$ は `pca` の 0.776 より低い 0.35〜0.64 なので、観測の予測では `pca` に負けやすく、H2 は棄却か保留
8. H3: 未来・過去の短い刻み（$n = 8$）では copy が強く、`pred` − `copy` は小さい。$n = 128$ では `pred` が copy を上回る。全体で保留の見込みが最も高い
9. 見込み: H1F は棄却 40%、保留 45%、支持 15%。H1P は H1F とほぼ同じ。H1N は保留 60%、棄却 30%、支持 10%

### 予想が外れたときの読み

- **対 V18c の $\psi_{\mathrm{clim}}$ が区別できない**: 時空間の補完は、評価の PCA64 で見える予測しやすさを作らなかった。予測器の段の比べと `pathway_gap` で、どこで差が消えたかを見る
- **F と P で判定が分かれる**: 学習の課題は反転で対称なので、差はデータの時間の矢を符号が拾った分か、遅さ以外の向きのある構造である。矢 $A$ の族ごとの値で読む（遅さでは説明できない）
- **N だけが良い**: 時間の文脈が、1 つの stack の空間の構造を作る助けになった。管の値と H3 の今の切り口で確かめる
- **崩壊**: 導出の表と照らす
- **H1F が支持で H2 が棄却**: 潜在は予測しやすくなったが、その予測しやすさは観測の予測に移らなかった（内容の無い予測しやすい成分を足した形）と書く
- **H1F と H2 が支持**: V19（ストリーム）の目的にも時空間の補完を入れるかをユーザーに示す

## 学習の実装（2026-11-27、値を出す前）

計画の「学習の実装」の段を実装した。時空間の補完の V18d の値は、まだ 1 つも出していない（下の GPU での試しは、時間とメモリを測るためだけの 60 step で、損失の値は読んでいない）。

- **`jepa.py`**: `time_masks(k)`（$\lvert J \rvert = k/2$ の部分集合、`itertools.combinations` の順。$k = 1$ では空）、`st_masks`（前半 $B/2$ の clip を管、後半を時間の側にする。$k = 1$ では全てを管にし、V18c の `draw_masks` と同じ乱数の消費になる）、`sincos_1d`、`Predictor.st_positions`（$e_P(p) + \phi(u_i) + \psi(\ell)$）、`st_predict`（補完）と `st_terms`（損失と番号ごとの SIGReg）
- **`iid.py`**: `Units.draw_clips(lags, k, perm)`。前の版の `draw_triplets` を $K$ 個の等間隔へ一般化して置き換えた。ST-perm では同じ動画・同じ $n$ のまま、番号ごとにその役の範囲から独立に引き直す。各 stack が終わるフレームの番号も返す
- **`jepa_iid.py`**: `--st K`（既定 0 は V18c の計算のまま）、`--st-perm`、`--st-lags lo:hi`。`jepa.json` に `st`・`st_perm`・`st_lags`・`st_bands`・`time_masks`・`seeds.delta`・`seeds.perm` を書く。`train.jsonl` の行に `sigreg_times`・`pred_now`・`pred_time`・`pred_masks`（`time_masks` の行ごと）・`pred_bands`（刻みの 3 つの帯 8〜32・32〜128・128〜512）・`overlap`（2 つの stack がフレームを共有する clip の割合。ST-perm の監査）を足した。$z$ の統計（`z_var` など）は全ての stack で測る
- **前の版のコードを外した**: `TimePredictor`・`knot_weights`・`time_errors`・`jepa_time_terms`・`TIME_ARMS`・`TIME_KNOTS`、`build_jepa` の `time_knots`、`jepa_iid` の `--time-arm`・`--time-weight`・`--time-lr`・`--time-lags`、`time_val` の時間の予測器の損失の行。`draw_lags` と `time_val` の崩壊の数の枠組み（`ValStacks`）は残した

計画から実装で変えた点（どれも値を見る前）:

1. $\phi$・$\psi$ を固定の buffer にせず、呼ぶたびに `sincos_1d` で計算する。$\ell$ は clip ごとに連続の値をとるので、表にできない。値は同じで、学習パラメータも buffer も増えない
2. 引数の形を `draw_clips(b, k, gen_n)` から `draw_clips(lags, k, perm)` にした。刻みは `jepa_iid` が `draw_lags` で引く（`draw_triplets` と同じ分け方）
3. checkpoint の時刻 $t$ は、V18c と同じ「step × clip の数 × 0.1 秒」にした。1 step に見る stack は 4 倍だが、step で揃えるので、同じ step の checkpoint が V18c と同じ名前になる
4. $\lvert U \rvert$ が全ての clip で同じなので、`pred_now`・`pred_time` は clip ごとの平均の誤差から出す。行の `pred` は 2 つの側の平均にちょうど等しい
