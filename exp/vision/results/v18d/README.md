## 回す前に決めたこと（2026-11-27）

**V18d の値はまだ 1 つも出していない。** 学習も評価も回していない。ここに書く数は、既存の結果の引用と理論値だけである。腕・掃引・選び方・判定は、私たち（Claude）の決定である（ユーザーは「判断を仰がず試行を続けて」と任せている。ユーザーが覆せる）。V18d は探索の段で、判定は 2 つの seed での再現の確かめとして報告する。

### 問いと仮説

- **問い**: 学習の目的に時間の予測（同じ動画の $(t - \Delta, t, t + \Delta)$ の 3 つの stack で、$z_{t+\Delta}$ を $(z_t, z_{t-\Delta})$ から当てる項）を入れると、主の評価 dyn/copy で、V18c までの符号が届かなかった「予測が良い」になるか。そのとき、観測の内容を V18c より落とさないか
- **仮説 H1（主。潜在の予測の比と、線形に読める内容の非劣性）**: 空間のマスクの目的（V18c）に時間の予測の項を足すと（腕 S+T）、dyn/copy の copy と clim の両方の分母で、`pca`、同じ設定の V18c、時間の対応を壊した S+T-perm より予測が良くなる。同時に、内容のガードの最小二乗の読み出しの $E$（水準）と $E^d$（変化）は V18c より下がらない
  - 課題文の H1 は $E$ だけを挙げていた。$E^d$ を足したのは、導出（計画の (a)）で、遅くするずるが 2 つの分母の規則を「良い」で通り、変化 $E^d$ で最もよく捕まるからである（`pca` を時間で平均すると、$E^{d,\mathrm{lin}}$ が 0.0638 から 0.0189〜0.00847 へ下がる）。dyn/copy の「良い」の条件も、水準と変化の両方の非劣性を求めている
  - 相手に S+T-perm を足したのは、S と S+T の差に混ざる「標的側で 3 倍の stack を見ること」と「動画の ID を持つ動機」を外し、正しい時間の対応の寄与を問うためである（Codex さんの指摘）
  - 最小二乗にする理由: 内容のガード v3 は V-h5a1（合成の陽性の対照）で外れた。MLP の読み出しが区間を記憶し、非線形な符号の $E$ を約 0.14 低く読む。最小二乗は記憶しない。代わりに、非線形に並べ直した内容を低く読む。比べる 2 つ（V18d と V18c）はどちらも学習した非線形な符号なので、この偏りは両方にかかるが、打ち消し合う保証は無い。だから、支持しても言えるのは「線形に読める内容を V18c より落とさなかった」までである。dyn/copy の規則どおり「内容の比べは未確立」と添え、「良い」とは書かない
  - **H1 の支持だけでは、「観測の予測が良くなった」とは言わない。** 内容を保ったまま、予測しやすいが観測の内容を持たない成分を足した符号は、H1 の全ての条件を通りうる（計画の「導出のまとめ」の最後の行）。それを分けるのが H2 である
- **仮説 H2（副。未来の観測の予測）**: 同じ S+T は、全ての符号で同じ的（Zurich の未来の 32×32 の観測）に対する予測の誤差 $\overline{\log F}$ でも、`pca` と同じ設定の V18c より良い（計画の「未来の観測の予測」）。有効性の確かめ V-f1〜V-f3 を値を見る前に固定し、1 つでも外れたら H2 は判定せず記述に下げる

### 腕と学び方

| 腕 | 損失 | 備考 |
| -- | -- | -- |
| S（対照） | $(1 - \lambda) L_S + \lambda S$ | 既存の V18c の run（短い run は `runs/v18c-screen`、長い run は `runs/v18c-long`） |
| **S+T（主）** | $(1 - \lambda)(L_S + w L_T) + \lambda S$ | $w \in \{0.25, 1\}$。V18c の損失に $(1 - \lambda) w L_T$ を足しただけ |
| S+T-perm（対照） | S+T と同じで、標的 $z_+$ を同じ動画の一様に引いた stack に置き換える | S+T で選んだ設定だけ |
| T（副） | $(1 - \lambda) L_T + \lambda S$ | 空間の項を外しても学べるか、という別の問い |

- $L_T$: 刻みに滑らかに依存する線形の予測器（2 点入力・切片つき、$\log n$ の節 8・32・128・512 の間を線形に補間）の、$z$（$D$ = 1024）の座標あたりの二乗誤差。刻み $n$ は三つ組ごとに $\log n \sim U[\log 8, \log 512]$（0.8〜51.2 秒）。勾配は 3 つの $z$ の全てに流す。予測器は 0 から始め、学習率 $10^{-3}$ を頂点にする（計画の「2 つの時間の尺度」）
- $S$: 中心の 128 個の $z_t$ だけの SIGReg（V18c と同じ $N$）。$L_S$ も中心の 128 個だけ（V18c と同じ $r$ = 0.5 のマスク）
- ほかは V18c と同じ: ViT-S（幅 1024・μP・パッチ 8・seed 0）、固定の $R$・$W$、AdamW、batch 128（三つ組）、warmup 1000 step と cosine、データは Zurich 以外の訓練の動画の全て、checkpoint の時刻

### 掃引（短い run、6000 step、seed 0）

学習率 $\{10^{-5}, 3 \cdot 10^{-5}, 10^{-4}\}$ × $\lambda$ $\{0.5, 0.8, 0.95\}$ × 腕（S+T の $w$ = 0.25、S+T の $w$ = 1、T）の **27 本**。$r$ = 0.5。checkpoint は step 0・1000・2000・4000・6000。名前は `v18d-<ST|T>[-w<w>]-lr<lr>-lam<λ>-r0.5-s0`。S+T の選択が済んだら、選んだ設定の S+T-perm の短い run を 1 本足す（記述。選択には使わない）。

- **試し**（空いている 4090 で、S+T $w$ = 1 と T、学習率 $10^{-4}$・$\lambda$ 0.5 を 200 step）: 40〜200 step の平均の秒 / step $t$ と `max_mem` を測る。`max_mem` が 22 GB を超えたら `--checkpoint-blocks`（値は変わらない）で測り直す。データの先読みが詰まっていないか（GPU の使用率）も見る
- **予算**: 短い run の全体の時間 $W = 28 \cdot 6000\,t / G$（$G$ は使える 4090 の数。GPU の 2 本目は、1 本目の使用率が 60% 未満でメモリに余裕があるときだけ数える）。見込み（推測）は $t$ = 0.25〜0.40 秒、1 本 25〜40 分、$G$ = 4 で $W$ は 3〜5 時間。**$W$ が 24 時間を超えたら**、学習率 $3 \cdot 10^{-5}$ の列を削る（V18c に同じ学習率の長い run が無く、長い run の対照を新しく回す必要がある列である）。それでも超えたら T の腕を削る。それでも超えたら回さずに報告する
- **実行の順**: 試し → 学習率 $10^{-4}$（判定保留の基準）→ $10^{-5}$ → $3 \cdot 10^{-5}$。腕は S+T を先にする
- fleet: std-00〜03 の 4090、コンテナ `mujou-exp-dev-1` の中。snapshot を固定する job スクリプト（`/nas/geson/mujou-exp/runs/v18d-*/scripts/`、v18c-width・v18c-dyn の形）。環境は `OMP_NUM_THREADS=1 CUBLAS_WORKSPACE_CONFIG=:4096:8 MUJOU_EXP_DATA=/data/geson/mujou-exp/.fleet/data`。CPU は 1 台 14 プロセスまで

### 短い run の判定（step 6000。**Zurich を使わない**）

崩壊・発散・判定保留の形は V18c の「回す前に決めたこと」の規則のとおりにする。ただし、V18c が Zurich で測っていた量は全て、dyn/copy の組の**検証の動画**（seed 4101 の置換の 2 本目。JEPA の訓練には入っている）で測る（Codex さんの指摘）。閾値の物差し（V18 の `color`、`color8`、`init_c`）も同じ検証の動画で測り直す。

- **崩壊**: K1 `sigreg_heldin` ≥ 26.7、K2 検証の動画の `rank` が `color` と `init_c` の小さい方より小さい、K3 検証の動画の `token_r2` ≥ $\theta_3 = (1 + \max(\texttt{token\_r2}(\texttt{color8}), \texttt{token\_r2}(\texttt{init\_c})))/2$。発散も不合格
- **判定保留**: 同じ腕（$w$ も同じ）・同じ $\lambda$ の、崩壊していない run のうち学習率が最大のものを基準にする。基準でない run は、`sigreg_heldin` か検証の時間の損失 $\overline{L}^{\mathrm{rel}}_T$ が基準より 0.05 を超えて大きければ（S+T では検証の動画の `pred_ratio_calib` も同じ規則）、判定保留とする
- **合格**: 崩壊・発散・判定保留でなく、`sigreg_heldin` < 2.0、$\overline{L}^{\mathrm{rel}}_T$ < 0.95（自分の予測器が、自分の符号の平均の予測を 0.05 を超えて下回る）。S+T では、さらに検証の動画の `pred_ratio_calib` < 0.95
- $\overline{L}^{\mathrm{rel}}_T$ は、検証の動画の共通の中心で、checkpoint の予測器が出す「自分の $R_{\mathrm{clim}}$」の、$n$ = 8〜512 の 13 点の $\log n$ の台形の平均（計画の「検証の時間の損失」）
- 制限: 判定保留の規則は、短い run で損失を早く下げる設定を優遇する。6000 step と 60000 step では cosine の予定が違い、V18c でも長く学ぶと $E^d$ が落ちた（Codex さんの指摘）。短い run の選択は長い run の性質を保証しない

### 長い run の選び方（値を見る前に固定）

腕ごと（S+T と T。S+T は 2 つの $w$ を 1 つの候補の集まりにする）に 1 つの設定を選ぶ。

1. 候補は、短い run の合格
2. **内容の適格**: 候補と、同じ学習率・$\lambda$ の V18c の短い run（`runs/v18c-screen` の $r$ = 0.5、step 6000）に、内容のガード v3 の手順（`content_eval real3 --model`。選択の段では Zurich を出さない経路で）を当て、最小二乗の読み出しの $E^{\mathrm{lin}}$・$E^{d,\mathrm{lin}}$ を**検証の区間**（訓練の動画の、読み出しの当てはめに使っていない区間。エンコーダの訓練には入っている）で出す。$D = E_a - 2^{-0.1} E_b \ge 0$（点推定）を $E$ と $E^d$ の両方で満たせば適格とする。V18c の値が `fidelity.comparable` の条件（検証の区間のブロックの抽出で、下端 > 0）を満たさない量は、その量の確かめを外して記録する
3. 適格な候補のうち、$\overline{L}^{\mathrm{rel}}_T$ が最小のものを選ぶ。最小から 0.01 以内にほかがあれば、その中で検証の区間の $E^{\mathrm{lin}}$ が最大のもの。それも同じなら学習率の大きいもの
4. 適格な候補が無ければ、合格のうち $\min(D_E, D_{E^d})$ が最大のもの（内容の点で H1 に最も有利な設定）を選び、「内容の適格なし」と書く
5. 合格が 1 本も無い腕は、長い run を回さない。そのこと自体を結果とし、原因を目的の式の導出と照らして調べる。S+T に合格が無ければ H1 は「判定できない」とする
6. 内容のガードが測れない（`Whitener` が採点できないなど）候補は、合格から外す

**内容の適格を足した理由**（課題文の「崩壊していないことと検証の時間の損失で選ぶ」からの変更）: 計画の導出 (a) で、$L_T$ は遅くするずるで下がり、SIGReg はそれを罰しない。だから $L_T$ だけで選ぶと、規則が系統的にずるの最も進んだ設定を選ぶ。内容の適格は、最終の判定が棄却に使う量（$E$・$E^d$）と同じものを、Zurich を使わずに選択の段階で見る。

**長い run**（60000 step、seed {0, 1}、checkpoint は V18c の長い run と同じ 0・2000・6000・10000・20000・30000・40000・50000・60000。名前は `v18d-long-<arm>[-w<w>]-lr<lr>-lam<λ>-r0.5-s<seed>`）:

- S+T の選んだ設定 × 2 seed、**同じ設定の S+T-perm × 2 seed**、T の選んだ設定 × 2 seed の最大 6 本
- 対照の V18c の長い run は、学習率 $10^{-4}$・$10^{-5}$ × $\lambda$ 全て × seed 0・1 が既にある。**選んだ学習率が $3 \cdot 10^{-5}$ なら、同じ設定の V18c の長い run（seed 0・1）も回す**
- 見込み（推測）: 1 本 4〜7 時間。4 台の 4090 で 2 巡、10〜14 時間

### H1 の判定（主の腕 S+T、seed ごと）

各 seed $s$ で、S+T（step 60000）について:

- **seed で支持**: 次を全て満たす
  1. 対 `pca`・対 V18c$_s$・対 S+T-perm$_s$ の全てで「a の予測が b より良いと区別できた」（$\psi_{\mathrm{copy}}$・$\psi_{\mathrm{clim}}$ の区間がどちらも 0 より下）
  2. 崩壊していない
  3. 対 V18c$_s$ で、最小二乗の $E^{\mathrm{lin}}$ と $E^{d,\mathrm{lin}}$ の $D$ の区間がどちらも 0 より上（「保つ」）
- **seed で棄却**: 次のどれかに当たる
  1. 3 つの相手のどれかに対して、「b の予測が a より良いと区別できた」か「分母で向きが割れた」
  2. 対 V18c$_s$ で、$E^{\mathrm{lin}}$ か $E^{d,\mathrm{lin}}$ の $D$ の区間が 0 より下（「落とす」）
  3. 崩壊した
- **それ以外は seed で保留**。「区別できない」（改善を検出できない）と、内容の「分けられない」はここに入る。検出できないことを棄却に数えない（Codex さんの指摘で、初稿から改めた）。実用上の余裕は dyn/copy で未決なので、「改善の幅を区間で排除した」ことによる棄却は置かない
- **H1**: 2 つの seed がどちらも支持なら**支持**、どちらも棄却なら**棄却**、それ以外は**保留**
- 多重性: 主の腕を S+T の 1 つに固定したので、腕の間の補正は要らない。1 つの腕の中で全ての条件を同時に求めるので、一律の補正も掛けない。区間の倍率は dyn/copy のまま（±2SE）。2 つの seed は Zurich と `pca` を共有し、seed 0 は選択にも使うので、誤りの確率を 2 乗できない。判定は探索の再現の確かめとして報告する
- 支持のときも「内容の比べは未確立（v3 が V-h5a1 で外れた。最小二乗の範囲での非劣性）」と添える。記述の「この時間の平均の対照に負けた」が成り立てば併記する（判定は変えない）
- 対 S+T-perm だけ「区別できない」で、対 V18c と対 `pca` で支持の条件を満たした seed は、保留にしたうえで「改善は時間の対応ではなく、標的側の計算か動画の中の共有で説明できる可能性がある」と書く
- **T の腕**（副）は、同じ規則で相手を `pca`・V18c$_s$（T と同じ学習率・$\lambda$）にして判定し、H1 とは別に「T の判定」として書く
- 自分の学習前との対の比、線形の族、0.1〜0.8 秒は記述として並べる。言える範囲は、Zurich の 1 本の動画の中での、PCA64 の計量の比べまでで、学習した刻みの範囲（0.8〜51.2 秒）の中での、未知の動画への潜在の予測しやすさの転移である

### H2 の判定（S+T、seed ごと）

V-f1〜V-f3 が全て通ったときだけ判定する。各 seed で、対 `pca` と対 V18c$_s$ の $\phi$ の区間がどちらも 0 より下なら seed で支持、どちらかが 0 より上なら seed で棄却、それ以外は保留。2 つの seed で揃えば支持・棄却、それ以外は保留。対 S+T-perm と画素の持続・`pixel` は記述として並べる。

### 予想（私たち（Claude）の推測。数はどれも推測）

1. 短い run は、どの腕でも K1・K2 で崩壊しない。K3 は、S+T の $\lambda$ = 0.5 だけが目的の式で排除されない（計画の (d)）が、起きないと予想する。T の腕の `token_r2` は V18c より高いが、$\theta_3$ には届かない
2. $\overline{L}^{\mathrm{rel}}_T$ は、T の腕で 0.4〜0.7、S+T の $w$ = 1 で 0.5〜0.8、$w$ = 0.25 で 0.6〜0.9 まで下がる。$\lambda$ が小さいほど低い（導出 (a')）
3. 内容の適格: T の腕は、$\lambda$ = 0.5 で $E^{d,\mathrm{lin}}$ が適格から外れる見込みが高い。S+T の $w$ = 0.25 は適格になる見込みが高い
4. 長い run の dyn/copy: S+T は対 `pca` と対 V18c で $\psi_{\mathrm{clim}} < 0$（−0.05〜−0.3）になる。同時に $\Delta\overline{\log(V/D)} > 0$（遅くなる）なので、$\psi_{\mathrm{copy}}$ は $\psi_{\mathrm{clim}}$ より 0 に近いか正になる。言葉は「a が良い」か「分母で向きが割れた」（copy で高く clim で低い向き、遅くなった形）
5. 対 S+T-perm: S+T-perm も遅くなる（動画の平均を当てるには、動画の中で変わらない量を持つのが得なので）。S+T との差は S+T と V18c の差より小さい
6. 内容: T の腕は V18c より $E^{\mathrm{lin}}$・$E^{d,\mathrm{lin}}$ を落とす。S+T は V18c と分けられないか、$E^d$ だけを落とす
7. H1 の見込み: 棄却 45%、保留 40%、支持 15%。H2 は、H1 が支持でも保留になる見込みが高い（V18c の $E^{\mathrm{lin}}$ は `pca` の 0.776 より低い 0.35〜0.64 なので、未来の観測では `pca` に負けやすい）
8. 遅さを合わせた対照: T の腕は `pca-mean-W` の族（3.2〜6.4 秒）に、3 つの量で同時に負けると予想する

### 予想が外れたときの読み

- **対 V18c の $\psi_{\mathrm{clim}}$ が区別できない**: 時間の項は、評価の PCA64 で見える予測しやすさを作らなかった。予測器の段の比べ（`own` → `refit1024` → `lin`）で、どこで差が消えたかを見る。`refit1024` で良く `lin` で消えれば、改善は PCA64 の外（分散の小さい方向）にある
- **崩壊**: 導出の表と照らす。T の腕の低い $\lambda$ での階数の縮みは導出 (a') が予言する
- **H1 が支持で H2 が棄却**: 潜在は予測しやすくなったが、その予測しやすさは観測の予測に移らなかった（内容の無い予測しやすい成分を足した形）と書く
- **H1 と H2 が支持**: 「この時間の平均の対照に負けた」かを確かめ、V19（ストリーム）の目的にも時間の項を入れるかをユーザーに示す
