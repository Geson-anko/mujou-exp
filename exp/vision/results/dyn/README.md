## 回す前に決めたこと（2026-11-26）

**V19 の値は見ていない。dyn/copy の値は 1 つも計算していない。** 下の数値は、閉じた式（神託）で出した理論値だけである。

- **主の量**: 白色化した PCA64 の座標で、2 点 $(w_t, w_{t-\Delta})$ から $w_{t+\Delta}$ を当てる予測器の誤差を、copy の誤差で割った $R_{\mathrm{copy}}(\Delta)$。低いほど良い。平均の予測の誤差で割った $R_{\mathrm{clim}}(\Delta)$ を必ず並べる
- **主の 1 つの数**: 0.8〜25.6 秒の $\log R$ の、$\log\Delta$ についての平均 $\overline{\log R}$。半オクターブの格子の 11 点（$n$ = 8・11・16・23・32・45・64・91・128・181・256 stack）で台形で求める。0.1〜0.8 秒は記述
- **族**: 線形（切片つきの ridge。$\alpha$ は検証の組で選ぶ）と、線形 + 残差 MLP（幅 512 の 2 層、出力 0 初期化、3 seed、検証の組で step を選ぶ。step 0 = 線形を含む）。主は MLP。ただし記録の組での MLP の非劣性（V-p2d）を物差しの全てで通ったときだけで、通らなければ線形を主にする。線形を必ず並べる
- **組**: Zurich 以外の 9 本の動画を、seed 4101 の置換で記録 1 本・検証 1 本・訓練 7 本に分け（動画で分ける）、128 秒のブロックに切る。評価は Zurich の共通の中心（約 14100 個）。三つ組は全ての刻みで同じ中心を使う
- **区間**: Zurich の 128 秒・256 秒のブロックの抽出（2000 回、seed 101）の SE の大きいほうと、MLP の seed の揺れ $\sigma_{ab} = \max(\sigma_{\mathrm{rot}}, s_{ab})$ を合わせた $\pm 2\,\mathrm{SE}_{\mathrm{tot}}$
- **判定の言葉**: 「a の予測が b より良いと区別できた」は、$\psi_{\mathrm{copy}}$ と $\psi_{\mathrm{clim}}$ の区間が両方 0 より下のときだけ。向きが逆なら「分母で向きが割れた」。さらに崩壊の指標を通り、内容のガード v3 で水準と変化の両方の非劣性が示されること。v3 の有効性が確かめられるまでは「内容の比べは未確立」と添え、「良い」とは書かない。実用上の余裕は置かない（未決）
- **知っている限界（神託の理論値）**: 時間の平均は 2 つの分母の規則を通る（OU $\tau$ = 3.2 秒を幅 3.2 秒で平均すると $(\psi_{\mathrm{copy}}, \psi_{\mathrm{clim}}) = (-0.078, -0.485)$）。だから内容のガードが要る。白い方向の注入は「分母で向きが割れた」になる（$(-0.157, +0.120)$）。内容を保ったまま予測できる成分（時計）を足す符号は、どの規則でも捕まらない場合がある（`clock` で大きさを記録する）
- **確かめ**: V-p1（合成。推定量と神託の一致、恒等式、MLP の陰性・陽性の対照、判定の規則、区間の被覆、帰無の対の誤った判定）と V-p2（実データの物差し。`rot` 対 `pca` の線形の不変性と実装の保証が合否、MLP の非劣性で主の族を決める、値は記録）。外れたら止める。通る条件を探して規則を変えない

## 実装（2026-11-26、値を計算する前）

計画のとおりに実装した。置き場所は次のとおりである。

- `exp/lib/dynpred.py`: 族、比、主の数、神託
- `exp/lib/synth_series.py`: S3・S7・S8 の系列と自己共分散、箱で平均した AR(1)
- `exp/vision/dyn_eval.py`: 組、符号化、行、V-p1、V-p2、CLI
- `exp/vision/results/dyn/judge_dyn.py`: 区間、判定の言葉、段

`exp/lib/linear_dyn.py` には `fit_scales` を足した。これはモーメントを 1 回だけ数え、全ての $\alpha$ で解く関数である。また、入力と出力の幅が違う組（128 → 64）も解けるようにした。これまでは同じ幅の組しか解けなかった。

テストのオラクルは次のとおりである。

- 1 次元の OU で、神託が $(1 + r)/2$ と $1 - r^2$ になること。
- 1 次元の閉じた FVU。
- 決定論的な回転で 0 になること。
- 固定した係数の誤差を、手計算と照合した。
- ridge の正規方程式。
- 等速の系列を、族が 0 で当てること。
- 直交変換をしても、線形の比と選んだ $\alpha$ が変わらないこと（ridge を含む）。
- MLP の step 0 が、線形とビットで一致すること。
- 早期終了の選択（同点なら早い時点を選ぶ）。
- 並べた学習と、1 本だけの学習が一致すること。
- $\overline{\log R}$ の台形を、手計算と照合した。
- フレームの番号を値にした動画で、符号化の時刻を照合した。
- 確かめを分けて回して合わせた行と、一括の行がバイトで一致すること。

計画の文面から、実装で決めた点は次のとおりである（値を見る前に決めた）。

1. **神託の登録値を再現した。** 実装の神託で、計画の V-p1e の 5 つの値を 3 桁まで再現した（S10: $(-1.112, -1.285)$、S6 対 S4: $(-0.157, +0.120)$、S5 の幅 3.2 秒: $(-0.078, -0.485)$、12.8 秒: $(-0.201, -1.538)$）。S5 の「過去の箱」は、直近の $W$ 個（$x_{t-W+1} .. x_t$）の平均である。$W + 1$ 個の平均では値が合わない（3.2 秒で $(-0.083, -0.503)$）。
2. **`clock` の速い方向は、訓練の組で選ぶ。** 計画には「参照の組の 0.8 秒の $s_i$」と書いてあった。しかし参照の組は、訓練の流れから飛び飛びに取った stack であり、時系列ではない。そのため $s_i$ を測れない。そこで、計画が同じ箇所で挙げた「V-h2 と同じ方向の選び方」（訓練の動画で測る）に従う。dyn の訓練の組の共通の中心で、0.8 秒の $s_i$ を測る。
3. **V-p1a' の $R^*$ は、評価の組の重みの神託の最良とした。** $R(\hat M)$ は、評価の組の重みのモーメントで採点する。同じ関数の最小でなければ、$R(\hat M) \ge R^*$ は保証されない。S7 の「訓練の重みで作った最良の係数を評価で採点した値」は、`trainbest` として記録する。
4. **MLP の初期値とバッチは seed ごとに 1 つ。** 同じ seed の MLP は、全ての刻みで同じ初期値から始まり、同じ中心のバッチを引く。刻みごとに独立に学ぶことは変わらない。step 0 の値は、線形の和そのものを使う（$g \equiv 0$ なので厳密である）。
5. **行の和の形。** `rec` と `zurich` はブロックの和を持つ。`train` と `val` は合計だけを持つ。これは V-p2b と記述に足りる。また、256 刻みの行を小さくできる。
6. **合成の乱数。** 符号は「族」ごとに、実現の seed と族の番号から作った生成器で引く。族とは、同じ乱数から作る符号の組である。OU 系は S4・S5・S6・S9-S4、回転系は S1・S10 である。こうすれば、どの単位を分けて回しても値は変わらない。V-p1h の S4' は、別の族の乱数で引く。

## レビューによる直し（2026-11-26、V-p1 を回す前）

実装のレビューの指摘を受けて、次を直した。V-p1f の直しだけは**値を見た後の直し**である。ほかは値を見る前の、登録した規則と実装のずれの直しである。

### V-p1f の的（値を見た後の直し）

- **元の結果**: レビューで、登録済みの seed 5101〜5140（40 の実現）について V-p1f を計算した。区間が神託の最良の $\psi^*$ を含む割合は、copy・clim とも 0.725 だった。これは閾値 0.90 を割る
- **理由**: 区間は、学んだ予測器を固定した条件つきである（計画の「区間」）。ところが V-p1f は、区間を $\psi^*$ と比べていた。的が合っていない。訓練が有限であることによる超過誤差は、符号ごとに違う。200 の実現の平均で、$\overline{\log R_{\mathrm{copy}}}$ の超過（学んだ予測器の値 − 神託の最良）は、S10a が $1.33 \times 10^{-3}$、S10b が $3.29 \times 10^{-3}$ だった。このため、$\psi$ の差では超過誤差が打ち消し合わない。実現ごとの的と $\psi^*$ の差は、200 の実現の平均で $-0.00196$（標準偏差 0.00012）だった。区間の SE は約 0.00139（最初の 40 の実現の平均）である。したがって、偏りは SE の約 1.4 倍になる
- **直し**: V-p1a と同じく、的を実現ごとの条件つきの値にした。実現ごとに、学んだ $(\hat M, \hat b)$ を `fixed_error` に通す。評価の重みの $\Gamma$ で母集団の $\overline{\log R}$ を出し、その差 $\psi(\hat M_a, \hat M_b)$ を的にする（`dyn_eval._pop_psi`）。$\psi^*$ を含む割合は、記録として残す（`share_star`）
- **直した後の結果**: 同じ 40 の実現で、的を含む割合は copy・clim とも 0.95 だった。登録の 200 の実現（seed 5101〜5300）では、copy・clim とも 0.945 となり、閾値 0.90 を通る。$\psi^*$ を含む割合は、200 の実現で copy 0.68・clim 0.745 だった。この 200 の実現の値は、手元の Mac の CPU で、このコミットのコードを使って出した（`check_parts(CheckConf(), ["V-p1f"])` を 7 つに分けて回し、`_vp1f` で合わせた）。V-p1 の本番では、ほかの確かめと一緒に回し直す
- **読み**: 実データの線形の区間も、同じ条件つきである。線形は $\sigma_{ab} = 0$ なので、訓練の組を引き直したときの揺れは区間に入らない（計画の「区間」に明記した）

### 値を見る前の直し

1. **$\sigma_{ab}$ に $s_{ab}$ を入れた。** `judge_dyn` の yard と apply の段では、MLP の対に、$\sigma_{\mathrm{rot}}$ の copy と clim の大きいほうだけを渡していた。登録した規則は $\sigma_{ab} = \max(\sigma_{\mathrm{rot}}, s_{ab})$ である。この $s_{ab}$（対そのものの 3 seed の $\psi_s$ の標本標準偏差）を計算していなかった。これは、区間が登録より狭くなる側の逸脱である。いまは `pair` の中で $s_{ab}$ を出し、$\psi_{\mathrm{copy}}$ と $\psi_{\mathrm{clim}}$ で別々に `sigma_ab` を使う。合成の V-p1c・V-p1d の $\sigma_{\mathrm{rot}}$（`dyn_eval._sigma_rot`）も、分母ごとに別々にした
2. **ずらしたブロックの区間を並べた。** 計画の感度（ブロックの起点を 64 秒ずらす）が、どの段にも無かった。`pair` が `shifted` として並べて出す
3. **V-p1g の記録を、計画のとおりに揃えた。** 合成の MLP について、選んだ時点に加えて、訓練・検証・記録・評価の組での線形と MLP の $R_{\mathrm{copy}}$・$R_{\mathrm{clim}}$ を出す。S5 の表（設計メモ §3.2）と、神託の値・長い実現の推定も並べる。神託は、表の 5 つの刻み（$n$ = 16〜256）で、表と 0.001 以内で一致した（離散の箱と連続の箱の違いの範囲）
4. **「測れない」を実装した。** 共通の中心で copy の分母が 0 の刻みを持つ符号は、`judge_dyn.unmeasurable` が見つける。`summary` は理由だけを返し、`pair` は区間を出さず、V-p2d には入れない
5. **V-p2d に無効な抽出の規則を当てた。** 無効な抽出が 2.5% を超えたら、SE を出さず、通らないとする（`psi_interval` と同じ規則）
6. **V-p2a が何を確かめるかを書いた。** `rot` は、白色化した後の座標に直交行列を掛ける（V-h4b と同じ）。だから、確かめられるのは当てはめの不変性であり、`Whitener` を通した不変性ではない。この点を、計画の V-p2a の行に書いた

**V-p1b の S9-S8（値を見た後の直し）**

- **元の結果**: S9-S8 の「S9 の線形の値が元と一致」が外れた。$R_{\mathrm{copy}}$ の相対の差は、$n$ = 1 で $7.6 \times 10^{-11}$、$n$ = 2 で $1.08 \times 10^{-10}$ だった。閾値は相対 $10^{-10}$ なので、$n$ = 2 で超えた。$n \ge 3$ では $3 \times 10^{-11}$ 以下で、選んだ $\alpha$ は全て一致した
- **理由**: S8 はほぼ決定論的で、短い刻みの $R_{\mathrm{copy}}$ は $10^{-5}$ の桁である。残差 $y - \hat y$ は $y$ の大きさの項どうしの差なので、丸めは $\epsilon \lVert y \rVert$ の桁になる。そのため分子 $\sum\lVert y - \hat y\rVert^2$ の丸めは $\epsilon \lVert y - \hat y\rVert \lVert y \rVert$、つまり $\sqrt{\mathrm{num} \cdot V}$ の桁になる。分子に対する相対では、丸めは $1/\sqrt{R_{\mathrm{clim}}}$ 倍に増える（$n$ = 1 で約 6600 倍）。相対 $10^{-10}$ で丸めを抑えられるのは、$R$ が 0 から離れた符号だけである。登録した閾値の物差しの取り方が、ほぼ決定論的な符号に合っていなかった
- **直し**: S9 の分子の一致を $\lvert \mathrm{num}_a - \mathrm{num}_b \rvert \le 10^{-10}\sqrt{\mathrm{num}_b \cdot V_b}$ にした（`dyn_eval._same_num`）。copy の分母は相対 $10^{-10}$ のまま比べる。閾値の数 $10^{-10}$ は変えていない。テストでは、$R \approx 10^{-5}$ の系列を直交変換したときの丸めが通ることを確かめる。分子の相対 $10^{-6}$ の本当の違い（物差しの $3 \times 10^{-9}$）が外れることも確かめる
- **直した後の結果**: S9-S8 は通る（$\lvert \mathrm{num}_a - \mathrm{num}_b \rvert / \sqrt{\mathrm{num}_b V_b}$ の最大は $7.8 \times 10^{-14}$）。S9-S4 は直しの前後とも通る。V-p1 は 41 / 41

### 符号化のメモリの直し（値を変えない直し）

`init_m` の V-p2 は、初めの 3 回とも、ホストのメモリが足りずに落ちた（rc 137）。`init_m` の自分の潜在は平らなトークン（16384 次元）で、訓練の動画の約 47 万 stack を float32 で持つと約 31 GB になる。fleet のホストは 61 GB で、並行する workflow の処理が 30 GB 前後を使っていた。次の 2 つを直した。どちらも値を変えない。

1. `encode_layout` は、ブロックごとの符号を、あらかじめ確保した集合の長さのテンソルに書き込む（リストを作ってから `torch.cat` で繋ぐと、終わりに 2 倍の大きさが要る）。`init_f` を新しいコードで回し直し、前の行とバイトまで一致した（3106 行、`recheck-blockmap/`）
2. `own` が `zpca`（V18b M）の符号では、参照の組で当てた `_zpca_map` を、訓練の動画の符号化の中でブロックごとに当てる（初めは、集合を全部持ってから当てていた）。写像は行ごと（$(z - \mu) W^\top$）なので、集合全体に当てた値と同じである。テストは、合成の動画で、ブロックごとに写した値と全体を写した値が一致することを確かめる。`zpca` の符号は物差しでは `init_m` だけで、初めの形では一度も回せていないので、比べる前の値は無い
