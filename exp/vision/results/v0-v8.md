# V0〜V8 のまとめ（2026-11-19）

各段の判定基準・予想・数値の詳細は [../README.md](../README.md) にある。ここでは、V0 から V8 までを通して何が分かったかを順に説明する。

## 1. この実験の目的

Walking Tours の動画を 1 本のストリームとして流し、画像を低次元の特徴量（潜在変数 $z$）に写すエンコーダを学ぶ。学習には PC-ALM だけを使い、誤差逆伝播（BP）は使わない。目的の式には VAE（変分自己符号化器）を使う。潜在空間をガウス分布に近づけるために選んだ。

良い特徴量の条件は次の 2 つである。

- この先で学ぶ動力学のモデルが、$z$ の時間変化を予測しやすい
- 入力の情報が、ある程度 $z$ に残っている

V では、VAE が安定して学べる設定と、その限界を探る。

## 2. 共通の設定

| 項目 | 設定 |
| -- | -- |
| データ | Walking Tours、64×64、10 fps。0.1 秒間隔の 8 枚を積んだもの（stack）が 0.1 秒ごとに 1 つ来る。ストリームは Amsterdam の先頭から始まる |
| 評価のデータ | 学習のストリームそのもの（V8 から）と、学習に使わない Zurich の動画 |
| モデル | エンコーダ 4 ノード、潜在 1 ノード、デコーダ 2 ノード、出力 1 ノード。基準のエンコーダは ViT-S |
| 学習 | 各ノードが、1 フレームに 1 回、自分の誤差だけで重みを更新する |
| 実行 | `mujou.run_manually` で、全ノードを同時に少しずつ進める |
| 長さ | 仮想時間で 1800 秒（18000 フレーム）。Amsterdam の最初の 30 分にあたる。1 つの設定につき 1 本（seed 0）を基本とする |

## 3. 評価の方法

### 3.1 2 つの評価

V1〜V7 では、学習を止めたモデルを、学習に使わない Zurich の動画で評価した。

V8 では、評価を学習のストリームそのものに移した。ストリームから学ぶとは学び続けることなので、学習に使ったデータ全体で評価する。60 秒ごとのチェックポイントで、次のように読む。

| 対象 | 誤差が大きいとき・小さいときの意味 |
| -- | -- |
| 過去（もう流れた stack） | 大きければ、忘れている |
| 未来（まだ流れていない stack） | 小さければ、汎化している |
| 今（流れている stack） | ある程度学ぶまでは意味を持たない |

### 3.2 指標

| 指標 | 意味 | 良い向き |
| -- | -- | -- |
| システムのデコーダの誤差 | システムの中のデコーダが stack をどれだけ描き戻せるか。平均の stack を出したときの誤差を 1 とする。V1〜V7 では Zurich で測り、`stack_mse` と呼んだ。V8 では、学習区間（span）と、その後の Amsterdam（after）で測る | 小さい。1 を下回れば、平均の画像を出すより良い |
| `recon_blur` | 止めたエンコーダの $z$ から、別に学んだデコーダで最後の 1 枚を描き戻したときの誤差（ぼかして比べる） | 小さい。$z$ に入力の情報が残っているほど小さい |
| `dyn_1/copy_1` | $z$ の 0.1 秒先を線形の式で予測したときの誤差を、「変わらない」と予測したときの誤差で割ったもの | 小さい |
| 忘却 | 過去の stack の今の誤差から、その stack が流れたときの学習中の誤差を引いたもの | 小さい |

### 3.3 「学べた」の判定

初期化の時点（0 秒）と比べて、次の条件をすべて満たしたときに「学べた」とする。V8 の形で書く。

1. 学習区間の誤差が、0 秒より小さく、1 より小さい
2. 学習区間の後の誤差が、0 秒より小さい
3. `recon_blur` が、0 秒より、誤差の揺れを超えて小さい
4. `dyn_1/copy_1` が、0 秒より小さい

1 の「1 より小さい」は、V1 の結果を見て V2 から足した。V1 では、ほかの条件を満たしても、デコーダがどの入力にも同じ画像を出していたからである。

各段では、回す前に判定基準と予想を README に書いた。

## 4. 各段の問いと結果

### V0: 土台の確認

**問い**: 実装は正しく、走らせられるか。

**結果**

- 小さなネットで、各ノードの勾配が BP の勾配と一致した
- 止めて再開した run が、止めない run と完全に同じになった
- 速さは 1 秒あたり約 6 フレーム（4090）で、モデルの大きさによらない。実時間（1 秒あたり 10 フレーム）には届かない
- 120 秒の試しの run が最後まで走った

### V1: SGD の学習率

**問い**: SGD で、発散せずに学べる学習率はあるか。

**やったこと**: SGD の $\tau$（学習率の逆数にあたる時定数）を $10^4$〜$10^7$ の 4 点で回した。

**結果**

- $10^4$ は 2 秒で発散した。$10^5$ と $10^6$ は、当時の 3 条件（上の 1 の「1 より小さい」を除いたもの）を満たした
- しかし、画像を見ると、システムのデコーダは評価のどの窓にも同じ画像を出していた。`stack_mse` は 1.5 で、平均の画像を出すより悪い

**分かったこと**: 「初期化より下がる」だけでは、学べたかどうかを判断できない。このため、V2 から「1 より小さい」を条件に足した。

### V2〜V5: 1 つずつ設定を変える

**問い**: モデル、momentum、stack の枚数、optimizer のどれかを変えると、学べるようになるか。

**やったこと**: V1 の $\tau = 10^5$ の SGD を出発点に、1 つの設定だけを変えた 19 本を回した（発散した ResNet-S・L を $\tau = 10^6$ で回し直した 2 本を含む）。

| 段 | 変えたもの | 結果 |
| -- | -- | -- |
| V2 | モデル（ViT-M・L、ResNet-S・M・L） | どれも学べない。ResNet は ViT より悪く、S と L は数秒で発散した |
| V3 | momentum（0.1・1・10 秒） | どれも学べない |
| V4 | stack の枚数（4・8・16） | どれも学べない |
| V5 | RMSProp・AdamW（$\tau = 10^2$〜$10^4$） | **RMSProp $\tau = 10^4$ だけが学べた**（`stack_mse` 0.640） |

**分かったこと**

- 学べない run では、システムのデコーダが $z$ を使っていない。どの入力にも同じ画像を出す
- ただし、学習中のデコーダの誤差は小さい（平均の画像の約 0.37 倍）。デコーダは $z$ を使わず、自分の重みを速く書き換えて、いま流れている場面を追っている
- KL は 300〜700 nat あり、潜在変数がつぶれている（事後分布の崩壊）わけではない。後から学んだデコーダは $z$ から画像を描けるので、$z$ には入力の情報がある
- optimizer の学習率が小さすぎる腕では、$z$ がほとんど動かなくなった。このとき `dyn_1/copy_1` だけが大きく下がる。`dyn_1/copy_1` が下がったことだけで、良い特徴量と判断してはいけない

### V6: RMSProp の再現

**問い**: RMSProp $\tau = 10^4$ は、seed を変えても学べるか。

**結果**

- seed 0・1・2 の 3 本とも学べた。`stack_mse` は 0.640〜0.676 でそろった
- AdamW $\tau = 10^5$ も学べた。RMSProp $\tau = 10^5$ は `stack_mse` が 0.708 まで下がったが、`dyn_1/copy_1` が下がらなかった

### V7: KL と再構成の釣り合い

**問い**: RMSProp で学べたのは、optimizer のおかげか。それとも、KL と再構成の釣り合いが変わったからか。

**背景**: VAE の損失では、再構成の誤差を $\sigma^2$（出力の分散）で割る。$\sigma$ は学習で決まるので、$\sigma^2$ が大きいほど KL の重みが相対的に強くなる（β-VAE の β にあたる）。V2〜V5 では、学習の終わりの $\sigma^2$ が SGD で約 0.009、RMSProp で約 0.054 と違っていた（SGD の値は 1800 秒ちょうどの 1 点の値である。SGD の $\sigma^2$ は 1 秒ごとに大きく揺れ、最後の 60 秒の平均は 0.025〜0.029 だった。RMSProp は 0.054 でほとんど揺れない）。

**やったこと**: $\sigma^2$ を 0.01・0.03・0.1 に固定し、SGD と RMSProp のそれぞれで回した。

**結果**

| | $\sigma^2$ = 0.01 | $\sigma^2$ = 0.03 | $\sigma^2$ = 0.1 |
| -- | -- | -- | -- |
| SGD $\tau = 10^5$ | 1 秒で発散 | 2 秒で発散 | 学べない（どの入力にも同じ画像） |
| RMSProp $\tau = 10^4$ | 学べた（0.664） | 学べた（0.654） | 学べた（0.678） |

括弧の中は `stack_mse`。

**分かったこと**: RMSProp は、$\sigma^2$ を 10 倍変えても同じように学べる。SGD は、$\sigma^2$ を大きくしても学べない。学べるかどうかを決めているのは、KL と再構成の釣り合いではなく、optimizer である。

### V8: 学習のストリームで評価し直す

**問い**: 学習に使ったストリーム全体で評価し直すと、結論は変わるか。忘却と汎化はどうなっているか。

**やったこと**: V1〜V7 で発散しなかった 26 本を、チェックポイント 60 秒ごとで回し直した。各チェックポイントで、学習区間（5 秒ごと）と、その後の 3000 秒（10 秒ごと）の stack の誤差を測った。

**結果**

- 学べた run は、Zurich で判定した V2〜V7 と同じ 7 本だった（RMSProp $\tau = 10^4$ の 3 つの seed と 3 つの $\sigma^2$、AdamW $\tau = 10^5$）。学習区間の誤差は 0.71〜0.78、その後の Amsterdam は 0.72〜0.81
- SGD の 14 本は、どれも学習区間の誤差が 1 を上回った（1.06〜1.91）

チェックポイントから見た相対時刻（stack の時刻 − チェックポイントの時刻）ごとに誤差を並べると、次のようになる（600〜1740 秒のチェックポイントで平均）。

| run | 30〜5 分前 | 10 秒前 | 5 秒前 | 今 | 5 秒後 | 10 秒後 | 5〜50 分後 |
| -- | -- | -- | -- | -- | -- | -- | -- |
| SGD $\tau = 10^5$ | 1.72 | 1.51 | 1.19 | 0.31 | 1.22 | 1.49 | 1.76 |
| RMSProp $\tau = 10^4$ | 0.91 | 0.81 | 0.67 | 0.33 | 0.79 | 0.89 | 1.00 |
| AdamW $\tau = 10^5$ | 0.89 | 0.86 | 0.78 | 0.74 | 0.95 | 0.93 | 1.03 |

**分かったこと**

- **SGD は数秒で忘れる。** 今の stack の誤差は小さい（0.31）が、5 秒離れると 1.19、10 秒で 1.51 になる。過去と未来がほぼ同じで、過去の方が良いということがない。SGD のデコーダが重みに持っているのは今の場面だけである。学んだものは残らない
- **RMSProp $\tau = 10^4$ は、今の場面を追いながら、その下に残るものがある。** 離れても 0.8〜1.0 にとどまり、過去と未来の差は小さい。学んだものの多くは、まだ見ていない場面にも効く
- **AdamW $\tau = 10^5$ は、今の場面を追う力が弱く、そのぶん忘れにくい。** 学習の初めに見た stack は、流れたときより今の方がよく描ける
- **$z$ の中身には大きな差がない。** 後から学んだデコーダは、SGD の $z$ からも場面を描ける。差は、システムのデコーダが $z$ を使うかどうかにある
- **学べた run は、1800 秒でもまだ下がっている。** RMSProp $\tau = 10^4$ の学習区間の誤差は、1500 秒の 0.85 から 1800 秒の 0.71 まで下がった

## 5. 全体から分かったこと

1. **PC-ALM の VAE は、RMSProp $\tau = 10^4$ で学べる。** 3 つの seed と、3 つの $\sigma^2$ で再現した。Zurich でも、学習のストリームでも、システムのデコーダは平均の画像より良く描く（誤差 0.64〜0.78）。AdamW $\tau = 10^5$ も学べる
2. **SGD では学べない。** 学習率、momentum、モデル、stack の枚数、$\sigma^2$ を変えても、デコーダは $z$ を使わなかった
3. **SGD のデコーダは、$z$ ではなく重みで今の場面を追い、数秒で忘れる。** 学習中の誤差は小さいが、5 秒離れた場面には平均の画像より悪い
4. **学べた run では、忘れる量が小さく、まだ見ていない場面にも効く。** 過去と未来の誤差の差は小さく、学習区間の後の誤差も 1 を下回る
5. **KL と再構成の釣り合いは、この範囲では決め手ではない。** $\sigma^2$ を 0.01〜0.1 で変えても、RMSProp の結果はほぼ同じだった
6. **`dyn_1/copy_1` は単独では使えない。** $z$ が動かなくなると、それだけで下がる

## 6. まだ分からないこと

- **なぜ RMSProp で学べるのか。** RMSProp は、パラメータごとに一歩の大きさをそろえる。そのため、勾配の小さい「$z$ からデコーダへの経路」の重みも動けるようになる、という説明が考えられる。ただし、この説明はまだ確かめていない
- **画像はまだぼやけている。** 学べた run でも、システムのデコーダが描けるのは明暗の大まかな配置だけである
- **1800 秒では学習が終わっていない。** どこまで下がるか、別の都市に移ったときに忘れるかは、まだ分からない
- **V2 と V4 は SGD で判定した。** モデルの種類や stack の枚数の効果は、RMSProp で確かめ直す必要がある

## 7. 次の候補

1. 学べた設定（RMSProp $\tau = 10^4$ と AdamW $\tau = 10^5$）で run を Amsterdam の終わりまで長くし、どこまで下がるか、次の都市でどうなるかを見る（V9）
2. RMSProp $\tau = 10^4$ を新しい出発点にして、モデル（ViT と ResNet、S・M・L）と stack の枚数を回し直す
3. 計画にある評価を足す。拡散のデコーダ（細部が $z$ に残っているか）と、Imagenette の linear probe
4. RMSProp が効く理由を確かめる。たとえば、SGD でデコーダの最初の層だけ学習率を上げる
