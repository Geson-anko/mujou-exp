流れ続ける動画を長く見せると、PC-ALM の VAE はどこまで良くなるか

前の資料（V11〜V16）では、同じモデルを普通の深層学習で 600 万 stack 学ぶと、描き戻した画像で場面を見分けられるまで良くなりました。ストリームの run が見たのは 1.8 万 stack だけでした。この資料では、PC-ALM で 1 本のストリームを 480 万 stack まで見せた V17 の結果をまとめます。長く回すための学び方が、本来の 1 本のストリームの学び方（B = 1）とどれだけ違うかも、あわせて調べました。

本番

長く見せると、span は 0.211 まで下がる

480 万 stack を見たところで、span は 0.211 になりました。学習に一度も使わない Zurich の場面でも 0.177 まで下がりました。全動画を 1 周した後も下がり続け、忘れて悪くなる様子はありませんでした。描き戻した画像で場面を見分けられます。

検証・追加の調査

100 stack をまとめて学ぶと、B = 1 より遅い

本番では、計算を速くするため、1 本のストリームの連続する 100 stack を 1 回にまとめて学びました。この学び方は、全動画の 1 周目のあいだ、B = 1 より span が 0.06〜0.12 大きくなりました。2 周目以降も約 0.04 大きいままでした。学習率を上げても、差は縮みませんでした。

追加の調査

10 stack なら、B = 1 とほぼ同じ

まとめる数を 10 にして、時定数を 10 分の 1 にすると、全動画の 1 周（48000 秒）まで、B = 1 との差は 0.01 以内でした。長い 1 本のストリームを速く回すときは、この学び方が使えます。

追加の調査

seed による揺れは 0.025 以内

B = 1 を 4 つの seed で回すと、span の幅は最大 0.025 でした。曲線の凸凹は 4 本ともそろっているので、seed ではなくそのとき見ている場面によるものです。

実験の仕組み

入力は、街を歩きながら撮った動画（Walking Tours）です。0.1 秒ごとの 8 枚の画像（64×64 ピクセル）を 1 組にしたものを stack と呼びます。Zurich を除く動画をつなぐと、全部で 47935 秒（約 48 万 stack）になります。モデルは前の資料と同じ VAE（ViT-S・幅 1024・μP・RMSProp）で、8 つのノードがそれぞれ自分の誤差で学びます。

本来の学び方は、1 本のストリームから 0.1 秒ごとに届く stack で、1 回ずつ学ぶことです（B = 1）。この学び方で 600 万 stack を見せると、2〜4 週間かかります。そこで本番では、1 本のストリームの連続する 100 stack（動画の 10 秒）を 1 回にまとめて学びました（layout=chunk）。見る順序は B = 1 と同じです。違うのは、10 秒ぶんの勾配を平均して、重みを 1 回だけ動かす点です。

時刻の表し方

この資料の時刻は、どれも動画の時刻（1 本のストリームが歩いた秒数）です。stack の数は、動画の時刻の 10 倍です。例えば 480000 秒は 480 万 stack で、全動画を約 10 周したところです。c = 100 の run では、run の中の 1 秒が動画の 100 秒に当たります。

指標の読み方

誤差は、どれも「どの入力にも平均の stack を出したときの誤差」を 1 とする比です。1 を下回れば、平均の画像を出すより良いということです。

span
動画の 0〜6000 秒の場面から 4 秒ごとに stack を選び、学習しているモデル（エンコーダ → z → デコーダ）で描き戻したときの誤差です。小さいほど良い。全動画を何周もするので、場面は 0〜6000 秒に固定して比べます。
after
6000〜9000 秒の場面での同じ誤差です。2 周目からは、学習に使った場面になります。
zurich
学習に一度も使わない Zurich の動画での同じ誤差です。新しい場面でどれだけ描けるかを表します。
z の差
デコーダが z を使っているかを調べる値です。各 stack を、その stack の z と、離れた別の場面の z の 2 通りで描き戻し、誤差の差をとります。0.2 を超えれば z を使っているとみなします。
d(t)
同じ時刻 t での span の差（比べる run − B = 1）です。正なら、B = 1 より悪いということです。前の資料までと同じく、差が 0.07 より小さいものは区別しません。

まとめて学んでも、B = 1 と同じになるか

問い　連続する 100 stack をまとめて学ぶと、B = 1 と同じ速さで良くなるか。どの τ が B = 1 に最も近いか。

条件　B = 1 は τ = 105 で 6000 秒、seed 0〜3（seed 1 は 48000 秒まで）。c = 100 は τ = 103・3·103・104、seed 0。合格は、1800 秒と 6000 秒で |d| < 0.07、かつ 6000 秒の z の差 > 0.2 としました。

4 · 追加の調査

遅れは何から来るか

問い　c = 100 の遅れは、1 回の更新が小さすぎるためか、それとも勾配を平均すること自体によるのか。

条件　まとめる数 c を 10・30・100 にし、時定数は B = 1 の c 分の 1（線形）を基本にしました。c = 100 では、τ を 103 より小さくした run（100・300）も回しました。どれも動画の 6000 秒まで、seed 0 です（τ = 103 だけ seed 1 も回しました）。

読めること

  • まとめる数が少ないほど、B = 1 に近づきます。|d| の平均は、c = 10 で 0.014、c = 30 で 0.045、c = 100 で 0.136 でした。1800 秒の差は、+0.004、+0.066、+0.186 です。
  • c = 100 で τ を小さくする（1 回の更新を大きくする）と、差はかえって広がりました。1800 秒の差は、τ = 300 で +0.333、τ = 100 で +0.563 です。最も近いのは τ = 103 でした。
  • このことから、遅れは 1 回の更新の大きさではなく、10 秒ぶんの勾配を平均して 1 回だけ動かすこと自体によると考えられます。
5 · 本番

480 万 stack まで見せると

問い　1 本のストリームを長く見せると、span はどこまで下がるか。1 周した後も下がり続けるか、それとも忘れて悪くなるか。

条件　本番の c = 100 は 3 つの τ で 480000 秒まで。比べるために、B = 1（seed 1）を 48000 秒（約 1 周）まで、c = 10（τ = 104）を 120000 秒まで回しました。普通の学習（V16、全動画、AdamW、学習率 3·10-4）を点線で添えましたが、span を測る場面の範囲が違う（V16 は 0〜1800 秒）ので、参考にとどめます。

動画の時刻（秒）60001800048000120000180000300000480000

読めること

  • 本番（τ = 103）の span は、6000 秒の 0.501 から、480000 秒の 0.211 まで下がりました。1 周目（48000 秒）を過ぎても下がり続け、48000 秒以降の 10 点で、それまでの最小の値を上回ったことはありません。
  • 学習に使わない Zurich でも、0.547 から 0.177 まで下がりました。覚えた場面だけでなく、新しい場面でも誤差が下がっています。
  • B = 1 に近い c = 10 は、どの時刻でも本番より良い値でした。本番との差は、1 周目のあいだ 0.06〜0.12、60000 秒以降は 0.04〜0.06 です。本番の値は、B = 1 なら届く値より悪い側にあると考えられます。
  • 480000 秒では、τ = 103 が 0.211、3·103 が 0.226、104 が 0.252 でした。103 と 3·103 の差は 0.07 未満で、区別しません。
  • 480000 秒の z の差は +1.605 で、デコーダは z を使い続けています。

次の実験で使うものと、残る課題

  • 長い 1 本のストリームは、c = 10 で回します。時定数を B = 1 の 10 分の 1 にすれば、B = 1 とほぼ同じに学べます。c = 100 は、B = 1 の代わりには使いません。
  • 次は、検証する対象を VAE から JEPA に移します。VAE では、ストリームの PC-ALM でも、長く見せれば場面を描けるまで学べることが分かりました。
  • B = 1 そのもの（または c = 10）を 480 万 stack まで回した値は、まだありません。本番の 0.211 は、それより悪い側の値です。
  • 普通の学習（V16）と、同じ場面の範囲で比べてはいません。
  • std-03 の 4090 で、B = 100 の run が 3 回 CUDA error: an illegal memory access で落ちました。どれも別の run と GPU を分け合っていたときで、mini-00 では完走しました。原因は切り分けていません。
