## 目的の式

### 記号

- $x_u$: 単位 $u$（0.1 秒刻み）から始まる 8 枚の stack（0.8 秒）。V18c と同じ `iid.Units` の単位
- エンコーダ・固定の $R$・$W$ は V18c と同じ: $t_p = R h_p(x)$（16 次元 × 64 トークン）、$z(x) = W\,\mathrm{vec}(t) \in \mathbb{R}^{D}$、$D$ = 1024
- 刻み $n$（stack の数、$\Delta = n/10$ 秒）。三つ組 $(x_{u-n}, x_u, x_{u+n})$ は同じ動画の中から取る。$z_- = z(x_{u-n})$、$z_0 = z(x_u)$、$z_+ = z(x_{u+n})$

### 時間の項 $L_T$

$$
L_T = \frac{1}{B D} \sum_{b=1}^{B} \bigl\lVert f_\phi(z_{0,b}, z_{-,b}; n_b) - z_{+,b} \bigr\rVert^2
$$

- **予測器 $f_\phi$ は、刻みに滑らかに依存する線形写像**: $f_\phi(z_0, z_-; n) = \sum_{j=1}^{J} h_j(\log n)\,(A_j z_0 + C_j z_- + c_j)$。$h_j$ は $\log n$ の上の区分線形の山形の基底（節は $n$ = 8・32・128・512 の $J$ = 4 個、隣り合う節の間を線形に補間する。$\sum_j h_j = 1$）。$A_j, C_j \in \mathbb{R}^{D \times D}$、$c_j \in \mathbb{R}^D$。パラメータは $4 \cdot (2 \cdot 1024^2 + 1024) \approx 840$ 万
  - **線形にした理由**（自明な解 (c) の導出）: 予測器が非線形で強いと、エンコーダの $z$ が線形には予測しにくいまま、予測器が力わざで損失を下げられる（予測器がエンコーダの仕事を肩代わりする）。dyn/copy の主の数は、評価の側で当て直した予測器（線形と、線形を含む残差 MLP）で測る。さらに dyn/copy の探索では、1.6 秒以上の刻みで MLP の寄与は −0.010〜+0.001 と小さかった。線形の予測器なら、損失を下げる道はエンコーダが $z$ を線形に予測しやすくすることだけになる。予測器の族が評価の線形の族と同じ形（2 点入力・切片つき）なのは意図したもので、目的と評価を合わせる原則に従う。寄せすぎの危険への対策は下の「評価に寄せすぎる危険」
  - 刻みごとに別の行列を持つ形（評価の線形と同じ）にしないのは、学習の刻みを連続にする（下）ためである。節の間の線形補間は、刻みに滑らかに依存する係数の最も単純な形である
  - 族は copy（$A = I$、$C = 0$、$c = 0$）、平均の予測（全て 0）、等速の外挿（$2I$, $-I$）を含む
- **刻みの引き方**: 三つ組ごとに独立に、$\log n$ を $[\log 8, \log 512]$ の一様から引き、$n$ を整数に丸める（seed + `DELTA_SEED` の生成器）。$\Delta$ は 0.8〜51.2 秒
  - 下端 0.8 秒: $n < 8$ では 3 つの stack がフレームを共有するので、共有したフレームの内容を持つだけで $L_T$ が下がる。dyn/copy が 0.8 秒未満を主にしない理由（stack の重なり）と同じである
  - 上端 51.2 秒: 評価の主の範囲（0.8〜25.6 秒）の上端を、学習の分布の端にしない（端の刻みは学習の重みが薄い）。dyn/copy と同じ $\log n$ の一様の重みで、評価の範囲の外へ 1 オクターブ延ばした
  - 評価の格子（半オクターブの 16 点）と同じ離散の格子にしない理由は、下の「評価に寄せすぎる危険」
- **三つ組の引き方**: まず $n$ を引き、次に中心 $u$ を、$x_{u-n}$・$x_u$・$x_{u+n}$ の全てのフレームが同じ動画に入る単位から一様に引く（`Units` と同じ「動画の切れ目をまたがない」規則。V18c と同じ生成器 seed + `DRAW_SEED` を使う）。動画の端から $n$ 以内の中心は除かれるので、中心の分布は一様からわずかにずれる（動画は 1 本 約 5 万単位なので、$n$ = 512 でも除かれるのは約 2%）
- **勾配**: $z_-$・$z_0$・$z_+$ の全てに流す。stop-gradient も EMA も使わない（LeJEPA の形、V18c と同じ）
- **予測器の初期値と学習率**: $A_j$・$C_j$・$c_j$ は 0 で初期化する（平均の予測から始める）。予測器の学習率は、エンコーダの学習率によらず $10^{-3}$ を頂点にし、同じ warmup と cosine を掛ける（Adam、重みの減衰なし）
  - 理由（2 つの時間の尺度）: 線形の予測器の最良の要素は $O(1)$ である（copy なら対角が 1）。Adam の 1 step の動きは学習率の程度なので、学習率 $10^{-5}$ では copy に届くだけで約 $10^5$ step かかり、6000 step の run の中で予測器が今のエンコーダの最良に届かない。下の導出は「予測器はそのときのエンコーダに対して最良」を前提にする。予測器を速くすると、この前提に近づく。$10^{-3}$ は dyn/copy の評価の MLP と同じ学習率で、$10^3$ step 程度で $O(1)$ に届く
  - 0 から始める理由: copy から始めると、長い刻みで copy の誤差（$2(1 - r)$、$r \approx 0$ で約 2）が平均の予測（約 1）より大きく、初めの勾配がエンコーダを遅くする向きに強く働く。0 から始めると、初めの勾配は標的側の $z_+$ を 0 へ縮める向きになる。SIGReg がこれを打ち消す保証は無い（有限標本の V 統計量は、i.i.d. のガウスでも分散 1 の点で期待値の微分が 0 でない。Codex さんの指摘）。予測器が速いので縮める向きは初めの数百 step に限られると見込むが、推測である。そのため、学習の経過で $z$ の座標の分散（`mix_var`）を記録し、下の「予測器が最良に届いているか」の確かめで、0 の初期値と $10^{-3}$ が妥当だったかを値で見る

### SIGReg

$S$ = `sigreg(z_0, z_0[:0], A)`。**中心の 128 個の $z_0$ だけ**にかける（データポイント = stack ごと、V18c と同じ $N$ = 128、方向の引き方も同じ）。

- 中心は i.i.d. に引いた 128 個の stack なので、V18c の 1 step の 128 個と同じ性質を持つ。$z_\pm$ も同じエンコーダの同じ周辺分布（端の除外を除く）なので、期待値の上では中心の SIGReg が $z_\pm$ の分布も縛る
- 3 つの組を全てかけない理由: $N$ = 128 の SIGReg の罰の尺度（$N$ 倍の形）と、中心が i.i.d. であることを V18c と揃える。3 つを合わせた 384 個は三つ組の中で相関するので、i.i.d. の前提が崩れる

### 空間の項 $L_S$

V18c の $L_{\mathrm{pred}}$ そのもの（$r$ = 0.5、粗い 4×4 の族 $F_8$ を 2 倍に広げたマスク、隠した位置の $t_p$ の座標あたりの二乗誤差）を、**中心の 128 個にだけ**かける。マスクの生成器（seed + `MASK_SEED`）も同じである。

### 腕と損失

| 腕 | 損失 | 掃引する重み |
| -- | -- | -- |
| S（対照。既存の V18c の run） | $(1 - \lambda) L_S + \lambda S$ | — |
| T | $(1 - \lambda) L_T + \lambda S$ | — |
| S+T | $(1 - \lambda)(L_S + w L_T) + \lambda S$ | $w \in \{0.25, 1\}$ |
| S+T-perm（対照） | S+T と同じ。ただし標的 $z_+$ を、同じ動画の一様に引いた別の stack に置き換える | S+T で選んだ設定だけ |

- **S+T は V18c の損失に $(1 - \lambda) w L_T$ を足しただけ**にする（$(1 + w)$ で割って正規化しない）。S との違いが厳密に 1 つの項になる。代わりに、予測の側と SIGReg の重みの比が $w$ で変わる（下の導出で扱う）
- $L_S$ と $L_T$ は、どちらも座標あたりの二乗誤差で、平均で当てる自明な予測の値が約 1（$t$ と $z$ の座標の分散が約 1）なので、尺度が揃う
- **主の腕は S+T である**（Codex さんの指摘で、初稿の「どちらかの腕」から改めた）。「時間の項を足すと良くなるか」を問えるのは、S（V18c）に 1 つの項を足した S+T だけである。T は「空間の項を外しても学べるか」という別の問いで、副として同じ言葉で書く。初稿は T を S+T の $w \to \infty$ の極と書いたが、$\lambda$ を固定して $w \to \infty$ にすると、時間の項に対する SIGReg の重みが 0 に近づくので、T（SIGReg の重みが $\lambda$）はその極に当たらない
- $w$ を {0.25, 1} にした理由: $w$ = 1 は 2 つの項が釣り合う点、$w$ = 0.25 は V18c に近く、空間の項の内容を保ったまま時間の項を少し足す点である。仮説 H1 は「内容を V18c より落とさない」を含むので、V18c に近い点を置く
- **S+T-perm（時間の対応を壊した対照）**: S+T と同じ三つ組の引き方・同じ step・同じ予測器・同じ損失の重みで、標的だけを「同じ動画の、一様に引いた単位の stack」に置き換える（予測器の入力 $(z_0, z_-)$ と $n$ はそのまま）。標的側で見る stack の数・計算・動画の ID の手がかり・周辺分布は S+T と同じで、正しい時間の対応だけが無い。この腕の最良の予測器は、入力から推定した動画の平均を返すことである。だから、S+T と S+T-perm の差は「正しい時間の対応」の寄与になり、S と S+T の差に混ざる「標的側で 3 倍の stack を見ること」と「動画の ID を持つ動機」を外せる（Codex さんの指摘、同意）。置き換えの stack は seed + `PERM_SEED` の生成器で引く
- **T の腕でも空間の予測器を作る**（V18c と同じ乱数で初期化し、checkpoint の形を揃える）。損失に入らないので勾配は流れず、更新されない

### 1 step の計算

- 128 個の三つ組を引く（384 stack）。3 つの組を標的側のエンコーダに通す（1 回の呼び出しに並べる）。S+T では中心の 128 個に文脈側の計算と空間の予測器をかける
- V18c の 1 step（標的 128 + 文脈 128）に比べて、標的側の計算が 3 倍になる。見込み（推測）: 4090 で 0.25〜0.40 秒 / step（V18c の実測は 0.117 秒）、メモリ 12〜16 GB（V18c は 4.8 GB）。データの読み出しは 1 step 384 stack なので、先読みのスレッドが詰まらないかを試しで確かめる
- **step 数を揃えると、見る stack の数は 3 倍になる**。S と S+T の違いには、時間の項に加えて、標的側で見る stack の数の違いが混ざる。ただし、空間の項と SIGReg は中心の 128 個だけで、V18c と同じ数である。この混ざりは S+T-perm との比べで外す（見る stack と計算が同じ）。V18c を 3 倍の step で回す対照は回さない（更新の数と cosine の予定も変わるので、因果の切り分けには置換の対照の方が直接である。Codex さんの指摘）

## 自明な解とずるの導出

比べるのは、目的の式の大域的な最小どうしの値で、学習の動きの議論ではない（V18 と同じ）。予測器は、そのときのエンコーダに対して最良とする（上の「2 つの時間の尺度」）。SIGReg の超過は V18・V18c の展開 $\approx 0.241 N (1/r_2 - 1/D)$（$r_2$ は participation ratio、$N$ = 128）を使う。

### 準備: SIGReg の下での $L_T$ の下限は、自分の符号の $R_{\mathrm{clim}}$ である

SIGReg が満たされると $z_0 \sim N(0, I_D)$ に近い。刻みごとに別の係数を持つ最良の線形予測器の $L_T$ は、dyn/copy の神託の式（plans/dyn.md）で $\Gamma(0) = I$ としたもの

$$
L_T^*(n) = \frac{1}{D}\mathrm{tr}\bigl(I - K \Sigma^{-1} K^\top\bigr),\quad K = [\Gamma(n), \Gamma(2n)],\quad \Sigma = \begin{bmatrix} I & \Gamma(n) \\ \Gamma(n)^\top & I \end{bmatrix}
$$

になり、これは**全ての $D$ 方向で白色化した座標での $R_{\mathrm{clim}}(n)$** に等しい（平均の分母が $\mathrm{tr}\,\Gamma(0) = D$）。

- **これは実際の $L_T$ の下限である**（Codex さんの指摘で、初稿の「等しい」を改めた）。実際の予測器は係数を節の間で補間して共有するので、刻みごとの最良に対する近似の誤差が加わる。等号が成り立つには、さらに刻みごとの標的の分散が $D$ であること（端の除外で中心と標的の分布がずれない）と、予測器が最良に届いていることが要る
- この但し書きのもとで、$L_T$ を $\log n$ について平均したものは、dyn/copy の $\overline{\log R_{\mathrm{clim}}}$ の、対数を取らない・PCA64 に絞らない版にあたる。**目的は $R_{\mathrm{clim}}$ を下げる向きに働く。$R_{\mathrm{copy}}$ は直接は下げない**（$R_{\mathrm{copy}} = (V/D) R_{\mathrm{clim}}$ なので、$V/D$ が動けば $R_{\mathrm{copy}}$ は別に動く）
- 自由な線形の予測器が拾うのは、遅さだけではなく、回転や負の相関を含む線形の予測しやすさ全てである（下の (e)）

### (a) 遅くする（時間の平均）ずる

- **導出**: SIGReg は stack ごとの周辺分布だけを縛り、時間の構造を見ない。$z$ の各方向を、周辺分布を $N(0, 1)$ に保ったまま、より遅く変わる関数に替えると、自己共分散 $\Gamma(n)$ が大きくなり、$L_T^*$ は下がる。予測器を copy に固定した場合、$\Gamma(0) = I$ のもとで $L_T$ を最小にするのは、まさに slow feature analysis（単位分散・無相関の制約で $E\lVert z_{u+n} - z_u \rVert^2$ を最小にする）である。自由な線形の予測器では、遅さは $L_T$ を下げる道の 1 つで、唯一の道ではない（(e)）。その最小は、stack から取り出せる最も遅い $D$ 個の関数（場面の明るさ・色・構図のような、数十秒かけて変わる量）になる。**SIGReg は遅さを罰しないので、どの $\lambda$ でもこの向きは排除されない**
- **階数の縮みとの組み合わせ**: 遅い量の数が $D$ より少なければ、エンコーダは分散を少数の遅い方向に寄せたい。ランク $q$ に寄せた符号の超過は約 $0.241 \cdot 128\,(1/q - 1/1024)$（$q$ = 128 で 0.21、64 で 0.45、16 で 1.9）。寄せて $L_T$ が $g$ 下がるなら、T の腕は $(1 - \lambda) g > \lambda e_q$ のとき寄せる。$g \le 1$ なので、$q$ = 128 は $\lambda \ge 0.83$ で、$q$ = 64 は $\lambda \ge 0.69$ で、$q$ = 16 は $\lambda \ge 0.35$ で排除される。**$\lambda$ = 0.5 では、128 次元程度の遅い符号への寄せは排除されない。** S+T では予測の側の重みが $(1 + w)$ 倍に近づくので、閾値はさらに上がる（$g$ を $w g$ に読み替える）
- **dyn/copy での見え方**（plans/dyn.md の「ずるとガード」）: 遅くすると $R_{\mathrm{clim}}$ は全ての刻みで下がり、$R_{\mathrm{copy}}$ は短い刻みで下がり、平均の幅の 1〜2 倍の刻みで上がる。主の範囲の $\overline{\log R}$ では、OU（$\tau$ = 3.2 秒）を幅 3.2・12.8 秒で平均すると $(\psi_{\mathrm{copy}}, \psi_{\mathrm{clim}})$ = (−0.078, −0.485)・(−0.201, −1.538) で、**2 つの分母の規則を「良い」で通る**（V-p1e (iii) の神託の値）
- **捕まえる指標**:
  1. **内容のガードの変化 $E^d$**: 遅い符号は 0.1 秒の変化を読めない。v3 の表で、`pca` の時間の平均の族の最小二乗の $E^{d,\mathrm{lin}}$ は 0.0638（`pca`）から 0.0189・0.0105・0.00863・0.00847（平均 0.8・3.2・6.4・12.8 秒）に下がる。水準の $E^{\mathrm{lin}}$ も 0.776 から 0.705・0.596・0.513・0.419 に下がる。だから判定は、水準と変化の**両方**の非劣性を求める（dyn/copy の「良い」の条件と同じ）
  2. **遅さの分解**: 分子が共通なので $\psi_{\mathrm{copy}} = \psi_{\mathrm{clim}} + \Delta\overline{\log(V/D)}$ が恒等的に成り立つ（results/dyn/README.md）。$\Delta\overline{\log(V/D)}$ はモデルによらない遅さの差である。遅くするずるは $\psi_{\mathrm{clim}} < 0$ と $\Delta\overline{\log(V/D)} > 0$ を同時に出す。予測器だけが良くなる本物の改善は、$V/D$ を変えずに $\psi_{\mathrm{copy}} = \psi_{\mathrm{clim}} < 0$ を出す。この 2 つを並べて書く
  3. **遅さを合わせた対照**（新しく足す物差し）: `pca` を過去だけの箱で時間平均した符号 `pca-mean-W`（$W$ = 0.8・3.2・6.4・12.8 秒。内容のガード v3 の `mean-8`〜`mean-128` と同じ作り方）に dyn/copy を当てる。v3 の内容の値は既にある。V18d が、この族のどれかに $\psi_{\mathrm{clim}}$（対 `pca`）・$E^{\mathrm{lin}}$・$E^{d,\mathrm{lin}}$ の 3 つで同時に負ける（族のある $W$ が、$\psi_{\mathrm{clim}}$ で V18d 以下、$E^{\mathrm{lin}}$・$E^{d,\mathrm{lin}}$ で V18d 以上）なら、「この時間の平均の対照に負けた」と書く（記述。点推定で比べる）。`pca-mean-W` は 0.8 秒より長い過去を見られる（V18d のエンコーダは 0.8 秒の stack しか見ない）ので、負けても「V18d が時間の平均そのものだ」とまでは言わない（Codex さんの指摘）
  4. 線形の幅（副）: 遅くすると境 1/2 の $\bar\Delta$ が伸び、0.8 秒未満の窓が短くなる（V18c の学習率 $10^{-4}$・$\lambda$ 0.5 の step 60000 と同じ形）

### (b) 内容を捨てて、時計や動画の ID のような予測しやすい成分だけを持つ解

- **入力によらない時計は作れない**: エンコーダは 1 つの stack（0.8 秒）だけの関数である。絶対の時刻は、内容（日の傾き・照明の変化）を通してしか読めない。内容から読める時計は遅い量なので、(a) に含まれる
- **動画の ID**: 訓練の 9 本の動画を見分ける成分は、動画の中で一定なので $L_T$ をその方向で 0 にする。純粋な ID は 9 点の離散分布で、SIGReg に強く罰せられる。しかし、$k$ 個の方向だけに ID を載せ、残りを健全に保つと、ランダムな方向への射影は $k/D$ の重みでしか離散を混ぜないので、罰は小さい。だから少数の方向の ID は排除されない
  - **評価では効かない**: Zurich は 1 本の動画なので、ID の方向は Zurich の中でほぼ一定になる。dyn/copy の分子・2 つの分母のどれにもほとんど寄与しない（比は方向の和の比なので、分散の小さい方向は効かない）。ただし、白色化の参照の組が複数の動画を含むと、ID の方向は参照で分散が大きく PCA64 の枠を占め、Zurich で評価される方向が減る。そのため記録として、PCA64 の白色化した 64 方向のうち、Zurich の分散が参照の 0.1 倍未満の方向の数を出す
  - **内容のガード**: ID の方向は観測の画素をほとんど説明しないので、$E$・$E^d$ は変わらない。もし ID のために内容の方向を減らせば、$E$ が下がる
- **場面の ID**（動画の中で数十秒ごとに変わる大域の量）: 連続な量にして周辺分布をガウスに保てるので、SIGReg に罰せられない。これは (a) の遅い符号そのものである
- **S+T-perm で見る**: 動画の ID は、S+T-perm でも同じだけ $L_T$ を下げる（動画の平均が最良の予測なので、ID はむしろ S+T-perm の方で効く）。だから S+T が S+T-perm より良いと区別できれば、改善は動画の ID では説明できない
- **照明・構図・歩行や露出の周期**: どれも符号が持てて、2 つの比を下げうる（Codex さんの指摘）。照明と構図は遅い量（(a)）、周期は (e) である。これらを個別に読み出す物差し（輝度・大域のフロー・歩行の位相）は足さない。人の知識で選んだ量を物差しにしない方針（[memory/feedback_eval_matches_objective.md](../../../memory/feedback_eval_matches_objective.md)）に反するうえ、どの近道が効いたかを名指すより、改善が観測の予測に移ったかを全ての符号で同じ的で測る方が、近道の全体をまとめて捕まえるからである（下の「未来の観測の予測」）

### (c) 予測器がエンコーダの代わりをする解

- 線形の予測器では、予測器がエンコーダの代わりに非線形な特徴を作ることはできない。$L_T$ を下げる道は、エンコーダが $z$ を線形に予測しやすくする（遅くするか、線形の作用で進む成分を持つ）ことだけである。これが線形にした主な理由である
- 残る形: 予測器が、$z$ の分散の小さい方向の信号を増幅して当てる。$W$ の特異値は 0.0012〜2.01 と広く、$W W^\top$ の participation ratio が約 511 でも SIGReg の罰の上乗せは約 0.03 しかない（V18c の導出）ので、分散の小さい方向は SIGReg にほとんど縛られない。増幅は排除できない（初稿の「罰則は要らない」は強すぎた。Codex さんの指摘）。PCA64 の評価は分散の大きい 64 方向だけを見るので、この形の改善は評価に出にくい
- **見え方**（段を分けて比べる。Codex さんの指摘）: 同じ組（検証・記録・Zurich）・同じ平均で、(1) V18d 自身の予測器を $z$ の 1024 次元のまま当てた値（`own`）、(2) $z$ の 1024 次元で刻みごとに線形を当て直した値（`refit1024`）、(3) 評価の PCA64 の線形（`lin`）を並べる（記述）。(1)→(2) の差は、予測器の学習の不足と節の補間の近似の誤差である。(2)→(3) の差は、白色化と 64 方向への絞り込みで失われた分である。どの段で差が生まれたかを書く
- **予測器が最良に届いているか**: 固定した checkpoint の $z$ で、(1) と、同じ節の補間の形を最小二乗で当てた値（`knot-ls`）と、(2) を検証の動画で比べる。(1) と `knot-ls` の差が、0 の初期値と学習率 $10^{-3}$ の予測器が最良に届かなかった分である（記録）

### (d) 定数と、stack の中で一定の解

- 定数・位置だけの関数: $L_T = L_S = 0$、$S$ の超過 51.3。V18 と同じく、$\lambda > \ell/(\ell + 51.3)$ で排除される（$\lambda \ge 0.5$ で常に）
- K3（$d$ = 16、ランク 16）: 超過約 1.9。T の腕では空間の項が無いので、K3 を選ぶ利点は $L_T$ だけにある。$\lambda \ge 0.5$ で、$L_T$ の差が 1.9 以下なら排除される（$L_T \le 1$ 程度なので常に）。S+T では利得が $\Delta L_S + w\,\Delta L_T$ なので、$w$ = 1 では利得が 1.9 を超えうる（$\Delta L_S$ は V18c の `pred` の 0.4〜0.9 程度、$\Delta L_T$ は 1 以下）。$\lambda$ = 0.5 の S+T では、K3 は目的の式だけでは排除されない（Codex さんの指摘で、初稿の「常に」を S+T では外した）
- この結論は、導出した線形の族（$t_p = A_p u$ のランク 16）に限る。各トークンが同じ少数の場面の量を、トークンごとに違う**非線形**な関数で持つと、$z$ の共分散は高いランクになり、線形の `token_r2` も低くできる（Codex さんの指摘）。この形は崩壊の指標では捕まらず、内容のガードと未来の観測の予測で見る
- 大域の解（V18c の導出 6）: S の腕で残る穴で、S+T でも残る。T の腕では空間の項が無いので、トークンごとの内容を持つ理由は SIGReg の階数の罰（上の (a)）と、時間の項（トークンの内容が時間に沿って予測しやすければ残る）だけである。**T の腕は、トークンごとの内容を S より保たないと予想する**（`token_r2` と内容のガードで見る）

### (e) 振動と対称の構造（Codex さんの反例）

- 自由な線形の予測器は、遅さでない線形の予測しやすさも拾う。例: $z_u = (-1)^u g$（$g \sim N(0, I)$ を系列ごとに引く）は周辺が標準ガウスで、全ての整数 $n$ で $z_{u+n} = z_{u-n}$ が成り立つ。全ての節で $C = I$（$A = 0$）にすれば誤差は 0 である。エンコーダが 0.1 秒ごとに符号の反転する量（圧縮の周期・露出のちらつきなど）を stack から読めれば、この解は SIGReg にも崩壊の指標にも捕まらない
- 一般の周期 $T$ の回転は、最良の係数が $n$ について $\cos(2\pi n/T)$ のように振動するので、$\log n$ の 4 つの節の補間では表せない。表せるのは、係数が $\log n$ について緩やかに変わる構造（減衰・遅い流れ）と、上の反転のように $n$ によらない係数で済む構造である。**節の補間は、振動より遅さを有利にする偏りを持つ**（私たち（Claude）の導出）。これは評価の刻みごとの線形との違いで、(c) の段の比べ（`own` 対 `refit1024`）に現れる
- 評価の線形は刻みごとに当て直すので、反転の構造も拾う。だから (e) は 2 つの比を下げうる。捕まえるのは、未来の観測の予測（反転する量が観測の内容を持たなければ、観測の予測は良くならない）である

### 未来の観測の予測（全ての符号で同じ的。Codex さんの指摘で足した）

内容を保ったまま、予測しやすいが観測の内容を持たない成分（時計・反転・ID）を足した符号は、$E$・$E^d$（現在の観測を読む）を落とさずに 2 つの比を下げる（plans/dyn.md の「内容の無い時計」）。これを分けるには、**符号の座標によらない同じ的**で比べる必要がある。plans/dyn.md の「V19 で確証する手順」の 4 が V19 に予定していた「未来の観測の予測」を、V18d に前倒しする。ただし、読み出しは内容のガード v3 の MLP ではなく、記憶しない最小二乗にする。

- **定義**: 内容のガード v3 の観測 $y$（最後のフレームを 32×32 に平均で縮めた画素、Zurich と訓練の区間は v3 と同じ）と、v3 の水準の最小二乗の読み出し $g$（符号 $w$ から $y$ を読む。v3 の `lin` の当てはめ）を使う。dyn/copy の評価の予測器（主の族）で出した $\hat w_{t+\Delta}$ を $g$ に通し、$\hat y_{t+\Delta} = g(\hat w_{t+\Delta})$ とする。誤差の割合 $F(\Delta) = \sum_t \lVert \hat y_{t+\Delta} - y_{t+\Delta} \rVert^2 / \sum_t \lVert \bar y - y_{t+\Delta} \rVert^2$（$\bar y$ は訓練の組の観測の平均）。主の範囲の 11 点で $\overline{\log F}$ を台形で求める
- **画素の対照**: 画素の持続 $\hat y_{t+\Delta} = y_t$ の $F$ と、符号 `pixel`（観測 $y$ そのものを参照で白色化した PCA64）を同じ手続きに通した $F$ を並べる
- **比べ**: 対の比 $\phi = \overline{\log F_a} - \overline{\log F_b}$。区間は dyn/copy と同じブロックの抽出で $\hat\phi \pm 2\,\mathrm{SE}_{\mathrm{tot}}$（$\sigma_{ab}$ は dyn/copy の MLP の規則と同じ。線形なら 0）
- **有効性の確かめ**（値を見る前に固定する。外れたら H2 は記述に下げ、刻み・格子・閾値を変えて通る条件を探さない）:
  - V-f1（時刻の取り違え）: フレームの番号を値にした合成の観測と符号で、$\hat y_{t+\Delta}$ の的が $y_{t+\Delta}$、入力の端が $t$・$t - \Delta$ であることを手計算と照合する（V-h0l と同じ）
  - V-f2（恒等の読み出し）: 符号が `pixel` のとき、$g$ が PCA64 の逆写像と一致し、`pixel` の $F$ が「画素の PCA64 の座標で dyn/copy の予測器を当て、逆写像で戻した誤差」と一致する（相対 $10^{-6}$）
  - V-f3（無内容の成分を罰する）: `clock`（plans/dyn.md の V-p2 の符号。`pca` の速い 8 方向を入力によらない回転に置き換えたもの）対 `pca` で、dyn/copy の 2 つの比は下がりうるが、$\phi$ の区間は 0 より下に出ない（`clock` は観測の内容を減らすので、$F$ は下がらない）。dyn/copy の `clock` の値は既にある
- H1 の判定には入れない（新しい量で、有効性の確かめが V18d の中で初めて回るため）。副の仮説 H2 として、事前に判定を書く（README）

## 評価に寄せすぎる危険

目的の予測器は、評価の線形の族と同じ形（2 点入力・切片つき）で、刻みの重みも同じ $\log n$ の一様である。評価に寄せすぎると、評価の手続きだけに合った改善（その格子・その族でだけ予測しやすい）を拾う危険がある。対策:

1. **主の数は、評価の側で当て直した予測器で測る**。V18d の予測器は評価に使わない（記述の行だけ）。評価は PCA64 の白色化した座標で、刻みごとに ridge と MLP を当て直す
2. **刻みは連続で、範囲も違う**（学習は 0.8〜51.2 秒の連続、評価は 0.8〜25.6 秒の 11 点）
3. **評価の組と Zurich は、学習にも選択にも使わない**。選択は、検証の動画の上の自分の損失・崩壊の指標と、内容のガードの検証の区間だけで行う（README の「長い run の選び方」）。V18c の短い run の判定は崩壊の指標（`rank`・`token_r2`・`pred_ratio_calib`）を Zurich で測っていたが、V18d の選択ではこれらを検証の動画で測り直す（Codex さんの指摘）。検証の動画も内容のガードの検証の区間も、JEPA の訓練には入っている（V18c と同じ訓練のデータを保つため）。だから選択は訓練の分布の中で行われ、別の動画への汎化を選んではいない
4. **主の範囲の刻みは全て学習の刻みの範囲の中にある**ので、主の数が示すのは「学習した刻みの範囲での、未知の動画への潜在の予測しやすさの転移」までである（Codex さんの指摘）。学習の範囲の外の刻みでの汎化は主張しない
5. **評価の手続きに無い形の量を並べる**: 0.1〜0.8 秒の記述、0.1 秒刻みの全格子の線形、1 点入力の線形、線形の幅、内容のガード、未来の観測の予測、拡散のデコーダの復元
6. 評価の線形の族と同じ形にしたのは、ユーザーの方針（評価と目的を合わせる）に従う意図した選択である。危険は「評価が拾える改善を、評価が拾えないずるで作る」ことで、それはガード（内容・崩壊）と上の (a)〜(d) で見張る

## 学習の実装（`jepa.py`・`jepa_iid.py` の変更）

- **引数**: `--time-arm {none,T,ST,STperm}`（既定 `none` = V18c と同じ計算）、`--time-weight w`（`ST` のとき）、`--time-lr 1e-3`、`--time-lags 8:512`。V18d の run は V18c の引数に `--time-arm T|ST` を足す
- **予測器** `TimePredictor`（module 名 `tpred`）: 節 `TIME_KNOTS = (8, 32, 128, 512)`、$A_j$・$C_j$・$c_j$ を 0 で初期化。checkpoint の modules に `tpred` を足す（V18c の run は `tpred` なしのまま読める）
- **データ**: `Units.draw_triplets(b, gen_n)`（新規）。$n$ を引き、動画の切れ目をまたがない中心を引き、`(b, 3, n_frames, 3, S, S)` と $n$ を返す。先読みのスレッドで次の batch を読む
- **乱数**: `DELTA_SEED`（新規、seed に足す）を刻みに使う。初期値（エンコーダ・空間の予測器）・中心・マスク・方向の生成器は V18c と同じ。中心は棄却があるので、同じ seed でも V18c と同じ stack にはならない
- **optimizer**: 時間の予測器は別の param group（学習率 `--time-lr` × `lr_at` の形、μP の倍率なし）
- **損失**: `jepa_terms` に $L_T$（`time`）を足す。`train.jsonl` に `time`（$L_T$）と、刻みの 3 つの帯（節の間: $8 \le n < 32$、$32 \le n < 128$、$128 \le n \le 512$）ごとの $L_T$ の平均を足す。log 一様では $n \ge 256$（25.6〜51.2 秒）が刻みの約 1/6 を占めるので、帯ごとに書く
- **役割と帯の監査**（記録。Codex さんの指摘）: 100 step ごとに、$z_-$・$z_0$・$z_+$ の座標の平均と分散を帯ごとに `train.jsonl` に残す。端の除外で役割ごとの分布がずれていないかを見る。ずれが見えても、値を見た後で目的（SIGReg を役割ごとにかけるなど）は変えない。README に書き、次の段の設計に回す
- **S+T-perm**: `--time-arm STperm`。標的の stack を、中心と同じ動画の一様な単位から引き直す（seed + `PERM_SEED`）
- **`jepa.json`**: `time_arm`・`time_weight`・`time_lr`・`time_lags`・`time_knots`・`seeds.delta`
- **評価の側**: `jepa_eval.build_run_jepa` が `time_arm` を読み、`tpred` を作る。崩壊の量（`sigreg_heldin`・`rank`・`token_r2`・`pred_ratio_calib`）は V18c のまま測れる（中心の $z$ と同じ符号）
- **検証の時間の損失**（`exp/vision/time_val.py`、新規。選択に使う）: dyn/copy の組（plans/dyn.md の「組」、seed 4101 の置換）の**検証の動画**の 128 秒のブロックで、共通の中心（$n$ = 512 の三つ組が入る中心）と刻みの格子 $n \in \{8, 11, 16, 23, 32, 45, 64, 91, 128, 181, 256, 362, 512\}$ の三つ組を作る。checkpoint の $z$ と、checkpoint の予測器 $f_\phi$ で、刻みごとに $\hat L^{\mathrm{rel}}_T(n) = \sum\lVert f_\phi - z_+ \rVert^2 / \sum\lVert z_+ - \bar z \rVert^2$（$\bar z$ は検証の組の平均。自分の予測器の $R_{\mathrm{clim}}$）を出し、$\log n$ について台形で平均する（$\overline{L}^{\mathrm{rel}}_T$）。S の腕（V18c）には予測器が無いので、検証の動画の前半で線形を当て直して後半で測る値を記述として並べる
  - 検証の動画は JEPA の訓練の 9 本の 1 本である（V18c と同じ訓練のデータを保つため、外さない）。だから「検証」は、選択の規則が評価の組と Zurich を見ないという意味で、標本の外という意味ではない（制限として書く）
- **遅さを合わせた対照の符号**: `dyn_eval yard` に `pca-mean-W`（$W$ = 8・32・64・128 stack、過去だけの箱）を足す。内容のガード v3 の `mean-W` と同じ作り方
- **自分の予測器の行**: `dyn_eval run` に `--own-predictor` を足し、$z$ の座標のまま、checkpoint の予測器で各組の 2 つの比を出す（`family = own`）。あわせて、$z$ の 1024 次元で刻みごとに当て直した線形（`family = refit1024`）と、同じ節の補間の形の最小二乗（`family = knot-ls`）を出す（(c) の段の比べ）
- **未来の観測の予測**: `dyn_eval` に `future` の段を足す（上の定義。v3 の観測と最小二乗の読み出しを使う）。符号 `pixel` を物差しに足す
- **Zurich で分散の小さい方向の数**: `dyn_eval` の行に、白色化した 64 方向のうち Zurich の分散が参照の 0.1 倍未満の方向の数を足す
- **内容のガードの最小二乗の区間**: `judge_content` の models3 の段に、最小二乗の読み出しの $E^{\mathrm{lin}}$・$E^{d,\mathrm{lin}}$ の $D$ の区間（同じブロックの抽出、$\sigma_{ab} = 0$。最小二乗は seed を持たず、直交変換で不変）を足す。既に無ければ実装する

## 実装のテスト（理論のオラクル）

- **予測器**: 節の上で $h_j$ が one-hot、節の間で線形、$\sum_j h_j = 1$。0 の初期値で $f = 0$。$A_j = I$ の全ての節で copy、$(2I, -I)$ で等速の外挿にちょうど一致する
- **最良の予測の閉じた式**: 1 次元の OU の系列（$\Gamma(n) = r^n$）を $z$ として与え、予測器だけを（エンコーダを固定して）学ばせると、$L_T(n)$ が神託の $1 - r^{2n}$（2 点入力の最良は 1 点と同じ、OU はマルコフ）に、刻みの節の上で標準誤差の範囲で一致する。**節の間**の刻み（$n$ = 16・64・256）では、学んだ値が神託以上で、同じ節の補間の形の最小二乗の値（`knot-ls`、閉じた式）と標準誤差の範囲で一致する（補間の近似の誤差を、学習の不足と分ける）
- **振動**: 反転の系列 $z_u = (-1)^u g$ で、学んだ予測器の $L_T$ が全ての $n$ で 0 に近づく（$C = I$）。周期 12.34 秒の回転では、節の補間の `knot-ls` が刻みごとの最良（誤差 0）より大きい（(e) の偏りの確かめ）
- **三つ組**: 3 つの stack の全てのフレームが同じ動画に入る。時刻の取り違え（フレームの番号を値にした合成の動画で、$x_{u-n}$・$x_u$・$x_{u+n}$ の最初のフレームが $u - n$・$u$・$u + n$）。$n$ の分布が $\log$ の一様（丸めた後の度数が理論の確率と、カイ二乗で一致）
- **既定で V18c と同じ**: `--time-arm none` で、小さな設定の 2 step の損失と勾配が変更前とビットまで一致する
- **T の腕**: 空間の予測器の勾配が None で、2 step の後もビットまで同じ。損失が $(1 - \lambda) L_T + \lambda S$ に一致
- **S+T の腕**: 損失が V18c の損失 $+ (1 - \lambda) w L_T$ にちょうど一致する
- **SIGReg が中心だけ**: $z_\pm$ を変えても $S$ が変わらない
- **勾配**: $L_T$ の勾配が $z_-$・$z_0$・$z_+$ の全てに届く（有限差分と一致）
- **予測器の学習率**: 時間の予測器の param group の学習率が `--time-lr` × `lr_at` の形
- **検証の時間の損失**: 符号を「真の過程」にした合成（OU、既知の $r$）で、最良の係数を入れた予測器の $\hat L^{\mathrm{rel}}_T(n)$ が $1 - r^{2n}$ に一致。copy の係数で $2(1 - r^n)$ に一致
- **`pca-mean-W`**: 内容のガード v3 の `mean-W` と同じ符号（同じ参照・同じ箱）になる
- **S+T-perm**: 置き換えた標的が中心と同じ動画に入り、置き換えが中心の時刻によらない（中心をずらしても置き換えの分布が同じ）。予測器の入力と $n$ は S+T と同じ
- **未来の観測の予測**: V-f1・V-f2 をテストにも入れる。符号が観測と時間の線形な関係を持つ小さな合成（$y = B w$、$w$ は既知の AR(1)）で、$F$ が閉じた式に一致する

## Codex さんの批判を受けた直し（値を出す前、2026-11-27）

初稿への批判の全文は [memory/agents/codex/v18d-critique.md](../../../memory/agents/codex/v18d-critique.md) にある。Fable さんの視点（目的の式から自明な解を導出し直す）も、同じ質問の中で Codex さんに頼み、私たち（Claude）の導出 (e) の節の補間の偏りと合わせた。

同意して入れたもの:

1. **選択から Zurich を外した**（致命的）。V18c の規則では崩壊の指標と `pred_ratio_calib` を Zurich で測っていた。V18d の選択では、これらを検証の動画で測り直し、閾値の物差し（`color8`・`init_c`）も検証の動画で測る。選択が訓練の分布の中で行われることを明記した
2. **未来の観測の予測を足した**（致命的）。内容を保ったまま無内容の予測しやすい成分を足す符号は、現在の観測を読む $E$・$E^d$ を素通りする。全ての符号で同じ的（未来の 32×32 の観測）にする量を、副の仮説 H2 として事前に登録した。H1 には入れない（有効性の確かめ V-f1〜V-f3 が V18d で初めて回るため）。代わりに、H1 の名前を「潜在の予測の比と、線形に読める内容の非劣性」に絞り、H1 の支持だけでは「観測の予測が良くなった」と言わないと書いた
3. **$L_T$ と $R_{\mathrm{clim}}$ の関係を下限に改め**、自由な線形の予測器が遅さ以外（反転・回転）も拾う反例を (e) に入れた。固定した符号で、自分の予測器・同じ節の最小二乗・刻みごとの最小二乗を比べる段を足し、テストに節の間の刻みと振動を入れた。帯ごとの記録を足した
4. **導出の強すぎる言い方を直した**: 0 の初期値の縮める勾配を SIGReg が打ち消す保証は無い。分散の小さい方向の増幅は排除できない。K3 は S+T の $\lambda$ = 0.5 では排除されない。K3 の結論は線形のランク 16 の族に限る（非線形に分け持つ解は `token_r2` で捕まらない）
5. **時間の対応を壊した対照 S+T-perm を足した**（重要）。同じ stack・計算・動画の ID の手がかりで、正しい時間の対応だけを外す。S と S+T の差に混ざる「3 倍の stack を見ること」も外せる。T は S+T の極ではない、という指摘も入れ、主の腕を S+T の 1 つに固定した（腕の多重性もこれで無くなる）
6. **判定で、検出できないことを棄却に数えない**。初稿は「区別できない」を seed の棄却にしていたが、保留に改めた。実用上の余裕は dyn/copy で未決（plans/dyn.md の未決 1）なので、「改善の幅を区間で排除した」ことによる棄却は今回は置かない。2 つの seed は Zurich と `pca` を共有し、seed 0 は選択にも使うので、誤りの確率を 2 乗できないと書き、V18d の判定は探索の再現の確かめとして報告する
7. **内容の適格を比から差に変えた**: $E^d_b$ が 0 に近いと比は不安定なので、$D = E_a - 2^{-0.1}E_b \ge 0$（点推定）にした。V18c の値が `fidelity.comparable` の条件を満たさない量は、適格の確かめから外して記録する。候補なし・同点・測れない場合の扱いを固定した
8. **`own` と PCA64 の差の読み方を段に分けた**（`own` → `refit1024` → `lin`）。帯の数を 3 に直した
9. `pca-mean-W` に負けても、「この時間の平均の対照に負けた」までしか言わない（長い過去を見られる対照なので）。役割（$z_-$・$z_0$・$z_+$）と帯ごとの平均と分散を記録する

入れなかったもの:

- **照明・大域のフロー・歩行の位相の読み出しを、近道の物差しとして足すこと。** 人の知識で選んだ量を物差しにしない方針（[memory/feedback_eval_matches_objective.md](../../../memory/feedback_eval_matches_objective.md)）に反する。近道の全体は、未来の観測の予測でまとめて見る
- **検証の動画を、全ての腕の学習から外すこと**（選択を別の動画への汎化にする案）。S を取り直す必要があり、既存の V18c と同じ訓練のデータを保つ「1 つの要素だけ変える」原則と両立しない。選択が訓練の分布の中であることを明記して受ける
- **SIGReg を役割ごとにかけること。** 役割ごとの分布のずれを記録し、効いていたら次の段で考える。値を見た後で目的を変えると、通る条件を探すことになるため
- **予測器を MLP にすること。** Codex さんも、MLP は非線形な動きを拾える一方、動画や場面ごとの近道も拾えるので、遅さへの対策としての根拠は無いと述べた。線形のまま、(c) の段の比べで予測器の限界を見る
