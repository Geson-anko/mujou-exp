# 基礎から組み直す: 1 つの stack の中の時空間の補完（2026-11-27）

V18 から V18d までに、評価の作り直し（主の指標 3 回、ガード 3 回）と目的の変更が積み重なった。この文書は、それを白紙に戻して、問い・原理・評価・段の順序を一度に決め直すものである。ここに書いていないことは、これからの判定に使わない。ユーザーが問いと進め方を確かめてから回す。

材料: Fable さんの提案 [memory/agents/fable/st-completion-instack.md](../../../memory/agents/fable/st-completion-instack.md)、ユーザーの決定（[memory/project_jepa_plan.md](../../../memory/project_jepa_plan.md) の 2026-11-27 の段落）。

## 1. 問い

**単一の視覚のストリームから、1 つの stack の中で空間にも時間（今・過去・未来）にも補完できる潜在を、JEPA + SIGReg で学べるか。**

成功の最低線（ユーザー、2026-11-27）: **未来と過去の予測しやすさで、画素の PCA（`pca`）を超える。** そのうえで、それが「遅くするだけ」「中身を捨てる」などのずるでないことを、ガードで示す。

## 2. ここまでで分かったこと（残す事実）

確かめを通った道具で得た結果だけを残す。

- **今の JEPA（V18〜V18c）は、時間の予測に向いた潜在になっていない。** 34 個の符号のどれも、2 時点の予測器の dyn/copy で `pca` より良いと区別できなかった。0.8 秒未満では `pca` より予測しにくい（[results/dyn/README.md](../results/dyn/README.md)）
- **理由は目的にある。** V18〜V18c の目的は 1 つの stack の中の空間の補完だけで、early fusion のためトークンに時刻が無い。時間を予測しやすくする理由が目的に無い
- **0.8 秒より先は、どの符号も平均の予測をほとんど超えない**（25.6 秒の R_clim 0.96〜1.00、`pca` も含む）。時間の予測しやすさで差がつくのは主に 0.8〜数秒の範囲と見込む
- **ずるの形は 2 つ分かっている。** 遅くする（時間の平均）と、雑音を足す。copy の誤差と平均の誤差の 2 つの分母を並べれば、この 2 つは逆向きに動くので見分けられる。中身の無い時計の成分は、この規則でも捕まらない（物差しで実際に出た）

残す道具: 学習の基盤（`jepa_iid.py`、BP + AdamW、i.i.d. なミニバッチ）、崩壊の指標（K1〜K3）、白色化 PCA64 の座標、2 つの分母の考え方とその確かめ（V-p1・V-p2）、物差し（`pca`・`mean8`・`color`・学習前）。

置くもの（記録に残し、判定に使わない）: 場面のカテゴリ・Inception の同定・320 px の的の主の指標、内容のガード v2・v3（MLP の読み出しが区間を記憶して外れた）、線形の幅（dyn/copy の特別な場合として残るので、独立には読まない）、4 つの stack の V18d（[plans/v18d.md](v18d.md)、run は `runs/v18d-st-long`）。

## 3. 原理（学習）

Fable さんの提案を土台にする。変えるのは **トークンの箱の形だけ** である。箱の空間の大きさは、提案の 16×16 ではなくユーザーの指摘で 8×8 にした（64×64 のフレームには 8×8 がちょうどよい）。

- **stack**: 始点 $\tau$ と間隔 $s$ の 8 枚のフレーム $x_\tau, x_{\tau+s}, \dots, x_{\tau+7s}$（$s$ は 0.1 秒の単位）
- **トークン**: 続く 2 枚 × 8×8 画素の tubelet。格子は $\Omega = T \times P$（時刻 4 × 空間 8×8 = 256 個）。V18c は 8 枚 × 8×8 画素の箱で、格子が時刻 1 × 空間 8×8 だった。**空間の細かさ（パッチ 8）は V18c と同じで、違いは stack の時間を 4 つに分けたことだけ**（ユーザー、2026-11-27: 64×64 のフレームならパッチは 8×8 がちょうどよい）。early fusion は「時刻が 1 点の特別な場合」として含まれる
- **トークンの次元**: $d = 16$（V18c と同じ）。平らにした列は $256 \times 16 = 4096$ 次元で、固定の $W$ を $4096 \times 4096$ の正方にし、$z = W\,\mathrm{vec}(t) \in \mathbb{R}^{4096}$ とする。本家の I-JEPA・V-JEPA は的をエンコーダの幅のままにするが、崩壊を EMA と stop-gradient で防いでいる。EMA を使わず SIGReg だけで防ぐこの形では、トークンの次元 $q$ が K3（全てのトークンが同じ符号）の罰 $0.241\,N\,(1/q - 1/D)$ を決める（$N = 128$）。幅のまま（$q = 1024$）では罰が約 0.03 で K3 が素通りし、$d = 16$・$D = 4096$ では 1.92 で V18c（1.90）と同じ強さで排除される（ユーザー、2026-11-27: $d = 4$ は細かすぎる）。「時間に沿って一定のトークン」の罰は約 0.02 で弱く、学習の側では防げないので、ガードの `time_r2` で必ず見る
- **計算量**: トークンが V18c の 4 倍で、1 step は 3〜4 倍、長い run 1 本は 6〜8 時間と見込む（推測。F1 の試しで測る）
- **エンコーダ**: V18c と同じ ViT（時刻も位置もまたいで attention、**再帰なし**）。見えるトークンだけを通す
- **符号**: $z = W\,\mathrm{vec}(t(\Omega)) \in \mathbb{R}^{4096}$、stack ごとに 1 つ（$t = R h$、固定の $R$ は V18c と同じ 16 × 1024）
- **目的**:

$$
L = (1-\lambda)\, E_{x,s}\, E_{U \sim \mu}\Bigl[\tfrac{1}{|U| d} \textstyle\sum_{\omega \in U} \lVert g(c_V, V, \omega) - t(\omega) \rVert^2\Bigr] + \lambda\, \mathrm{SIGReg}(\{z_b\}_{b=1}^{128})
$$

  V18c の式の空間の格子 $P$ を時空間の格子 $\Omega$ に読み替えただけ。stop-gradient も EMA も無い
- **マスクの族**（ユーザー、2026-11-27: JEPA は multi-block のはず）: V-JEPA の multi-block を時空間の格子に広げる。
  - 空間の側は V-JEPA の公開設定のまま、トークンの解像度（8×8）で、短距離（面積 15% のブロック 8 個）か長距離（面積 70% のブロック 2 個）を引く。縦横比は 0.75〜1.5
  - 時間の側として足すのは 1 つだけ: ブロックごとに時間の長さを $\{1,2,3,4\}$ から均等に、置く位置を均等に引く。時間の反転と平行移動で分布は変わらない
  - 隠すのはブロックの和集合 $U$、文脈は残り $V = \Omega \setminus U$（空なら引き直す）。隠す数は固定しない（本家と同じ。2026-11-23 の「ちょうど $k$ 個」を置き換える）。損失は隠したトークンの数で割る
  - 特別な場合: 全てのブロックが全時間なら V-JEPA、時刻が 1 つなら I-JEPA の multi-block。全時間のブロックが今（空間）の補完、長距離のブロックが時間の一部を覆えば未来・過去・間の補完になる。今・過去・未来を別々に読むのは評価の側（決まったマスク）で行い、学習の族は刻まない
- **時間の尺度**: $\log s$ を一様に引く（$s = 1$〜128。隣の時刻の差は 0.2〜25.6 秒）。伸縮で格子が自分に写るので、どの尺度も優先しない。$s$ はエンコーダに渡さない（符号を画素だけの関数に保つ）。予測器には渡す

**再帰を使わない理由**（ユーザー）: 再帰のあるエンコーダは、潜在空間がループするだけになるおそれがあり、ガードが複雑になる。

**目的から出る自明な解**（Fable さんの導出）: 定数（排除される）、K3（λ ≥ 0.5 で排除）、**時間に沿って一定のトークン**（SIGReg の超過が約 0.02（d = 16）で、λ = 0.5 では排除されない。stack した理由を失う解なので必ず見る）、遅くする、予測器が代わりをする、隠した所に周りの情報を詰める（鏡の符号）。

## 4. 評価

学習の目的（今・過去・未来の補完）と対になるように、**今・過去・未来を別々に** 出す。主は未来と過去。

### 4.1 未来と過去: minGRU のダイナミクスモデル（主）

- **入力の系列**: 評価の動画（Zurich）と学習の動画の、重ならない stack（$s = 1$、0.8 秒おき）の $z$ を、参照の組で白色化した PCA64 の座標 $w$ にした系列
- **モデル**: 状態を持つ minGRU（[exp/video/dyn/](../../video/dyn/) と同じ系統）。系列を読んで、各時刻で刻み $\Delta \in \{0.8, 1.6, \dots, 25.6\}$ 秒先の $w_{t+\Delta}$ を、刻みごとの線形の頭で直接に当てる（巻き戻しはしない。誤差の積み重ねと選択を増やさないため）
- **過去**: 同じ作りの minGRU を、時間を反転した系列で学ぶ
- **分母**: copy の誤差（$R_{\mathrm{copy}}$）と平均の予測の誤差（$R_{\mathrm{clim}}$）の 2 つ。主の数は 0.8〜25.6 秒の $\log R$ の平均
- **下限**: 線形のモデル（2 時点、既存の dyn/copy）を並べる。閉じた式で確かめられる
- **比べ**: 同じ minGRU を、同じ学習の組・同じ早期終了の規則で、全ての符号（`pca`・VAE の `v16`・`v17` などの他の手法を含む）に当てる。判定の言葉は dyn/copy と同じ（2 つの分母の区間が同じ向きに良いときだけ「良い」）

### 4.2 今: stack の中の補完

- 立方体の格子を空間の軸で半分に切り、一方の半分だけを見た符号から他方を当てる（Fable さんの「半分の視野」、6 節）。同じ形で時間の軸で切れば、stack の中の未来・過去になる（記述として並べる）
- 学習した予測器自身による同定（自分の表現空間での補完）も、今・過去・未来の切り口ごとに並べる

### 4.3 ガード（壊れていないこと）

- **崩壊**: K1〜K3 と、その時間の版 `time_r2`（トークンの分散のうち、時間に沿った平均で説明できる割合）。閾値は学習前と物差しから、値を見る前に決める
- **内容**: 観測を符号から **線形（ridge、検証の組で α を選ぶ）だけ** で読み出す忠実さ $E^{\mathrm{lin}}$ と、その変化の版 $E^{d,\mathrm{lin}}$。MLP の読み出しは使わない（v3 で区間の記憶が確かめられたため）。線形の読み出しは非線形な符号の内容を低く読むので、「下がった」は保守的な警告として読む
- **復元の定性評価**: 符号から画像を復元して並べ、内容の数値と見た目が合うかを確かめる

**「良い」と書くのは**: 未来と過去の両方で、2 つの分母がそろって `pca` より良く、崩壊なし、`time_r2` が閾値の内、$E^{\mathrm{lin}}$ が `pca` か学習前に対して非劣のときだけ。

## 5. 段の順序

1 段に 1 つの要素だけ変える。各段の「何が分かれば次へ進むか」を回す前に書く。**比べる相手は他の手法（`pca`・VAE の `v16`・`v17`・`mean8` などの物差し）だけで、以前の JEPA（V18〜V18d）の結果とは比べない**（ユーザー、2026-11-27）。段どうしの差は、何が効いたかを読むための記述である。

| 段 | 中身 | 次へ進む条件 |
| -- | -- | -- |
| F0 | **評価の土台**。minGRU の評価を作り、合成で確かめる（OU、ガウスの状態空間モデルではカルマンの最良に近づくこと、定常なら未来と過去の誤差が一致すること）。物差し（`pca`・`mean8`・VAE の `v16`・`v17`・学習前）に当てる。学習はしない | 合成の確かめが全て通る。物差しの順序が既存の dyn/copy と矛盾しない |
| F1 | **T0**: tubelet の箱で、全てのブロックを全時間にする（V-JEPA の multi-block そのもの、今だけ） | 崩壊しない。今・過去・未来の評価を `pca`・VAE と並べる |
| F2 | **S1**: ブロックの時間の長さも引く（族の全体）、$s = 1$ | 崩壊しない（`time_r2` を含む）。T0 より未来・過去の評価が良くなるか（時間の補完の効果）を読む |
| F3 | **Sσ**: 同じ、$\log s$ を一様に | S1 より良くなるか（時間の尺度の効果）を読む。**ここで `pca` と VAE を超えたかを判定する** |

各段は、短い run（6000 step、学習率 × λ の掃引）→ 長い run（60000 step、seed 2 つ）。長い run の設定は、検証の動画の補完の損失と崩壊の指標で選ぶ（評価の動画 Zurich は選択に使わない）。長い run 1 本は 6〜8 時間の見込み（4 枚の 4090 で並べる）。

F3 の後に、元の計画の流れ（ストリーム、時間相関の SIGReg、PC-ALM）へ戻る。

## 6. 決めていないこと（F0 の前に決める）

- `time_r2` と $E^{\mathrm{lin}}$ の非劣性の余裕
- $s$ の範囲の上端（128）が動画の長さと読み出しの速さで実際に回るか
