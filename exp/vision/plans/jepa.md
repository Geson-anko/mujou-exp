# JEPA: 単一ストリームから SIGReg で JEPA を学ぶ（計画、2026-11-23）

V17 で VAE の検証を締めくくり、検証する対象を JEPA に移す（[memory/project_v17_to_jepa.md](../../../memory/project_v17_to_jepa.md)）。`exp/video` の M17 で決着しなかった JEPA の問いに、VAE と同じ順序で答えを出す。番号は `exp/vision` の V18 から続ける。

## 背景

- **VAE は、普通の学習を先に確かめる順序で決着した。** V16 で、BP と i.i.d. なミニバッチなら同じモデルが学べる（span 0.164）ことを確かめた。そのうえで V17 で、ストリームの PC-ALM でも長く学べば下がる（480 万 stack で span 0.211）ことを示した
- **M17 の JEPA は、この順序を踏んでいなかった。** BP と i.i.d. なミニバッチで JEPA + SIGReg が学べることを確かめないまま、B = 1 のストリームで崩壊への対処に追われていた。そのため、学べない原因が (1) 実装・モデル・評価、(2) 学習の設定、(3) ストリームの相関のどれなのかを分けられなかった
- **評価にも穴があった。** M17 の再構成の基準は、tubelet ごとの平均の色だけの符号でも満たせた。V16 では、後から学ぶデコーダの `recon_blur` が頭打ちになり、符号の差を映さなかった
- **ユーザーの仮説**: SIGReg は、標本が i.i.d. であることを前提にした検定統計量である。ストリームでは時間相関のためにデータポイントを独立に扱えず、前提が成り立たない。一方で、時間相関はそれ自体が手がかりにもなる

## 共通の設計

- **モデル**: V14・V16・V17 と同じ ViT-S（幅 1024、μP、patch 16、64×64、8 枚の stack を early fusion）。VAE の頭（`2D` への写像）を除いたエンコーダを使い、VAE と同じ物差しで比べる。トークンは 4×4 = 16 個
- **表現**: トークンごとに $d$ = 64 次元に写し、平らにした列 $z \in \mathbb{R}^{D}$（$D$ = 1024）とする（2026-11-13 の決定。$D$ が十分小さいことだけが制約）
- **目的**: LeJEPA の形にする。エンコーダは 1 つで、EMA のターゲットも stop-gradient も入れない。予測器が、見えるトークンから隠した位置のトークンの埋め込みを当てる。損失は $(1 - \lambda) L_{\mathrm{pred}} + \lambda\, \mathrm{SIGReg}$
- **マスク**: 空間のブロックを stack の全フレームに同じ位置で掛ける（V-JEPA の tube）。early fusion なので、課題は空間の補完だけで、未来のフレームの補完は含まない
- **SIGReg**: データポイント（stack）ごとに $z$ にかける（トークンごとにはかけない。位置だけの解が安く通るため、2026-11-13 に棄却）。実装は `exp/lib/sigreg.py` の Epps–Pulley を使う
- **バッファ**: 過去の $z$ のバッファは FIFO にする（2026-11-23、ユーザーの決定）。これまでのランダムな置き換え（`insert_`）は、各行の生存時間が確率的になる。FIFO なら、バッファは直近の決まった時間の幅をちょうど覆う

## V18: BP と i.i.d. なミニバッチで学べるか（詳細設計、2026-11-23）

run の一覧・判定・長い run の規則・予想・反証は [README の「V18」の節](../README.md)（回す前に決めたこと）に書いた。ここには、実装できる粒度の設計と、目的の式の自明な解の導出を書く。

### ユーザーが決めたこと

- early fusion のまま（8 枚 × 3 チャネル = 24 チャネル、64×64、patch 16 → 4×4 = 16 トークン）。patch 8 にはしない
- **マスク率に注意する**: トークンが 16 個しかないので、隠すトークンの数をちょうど $k$ 個に固定する。マスク率 $r \in \{0.25, 0.5, 0.75\}$（$k$ = 4、8、12）を掃引の軸にする。$r$ = 0.75 でも見えるトークンが 4 個残る
- batch は 128。SIGReg は batch の中の標本だけで計算する（バッファは V19 から）
- 掃引: 学習率 $\{10^{-4}, 10^{-3}\}$ × $\lambda$ $\{0.005, 0.05, 0.5\}$ × $r$ の 18 本、seed 0、6000 step。長い run は 60000 step

`exp/video/jepa` は import しない。M17 の `block_masks` と `multiblock_masks` は使わない。`block_masks` は平面の上に一様に置くので、中央の位置ほど多く隠れる。`multiblock_masks` は、ちょうどの数にするために見える patch をランダムに足して隠すので、ブロックの形が崩れる。移すのは、矩形を格子に塗る考え方（`paint`）だけである。

### エンコーダと表現

- **エンコーダ**: `build_vae(conf, seed=conf.seed)` と同じ手順・同じ seed で ViT（`_vit_parts`）を作り、node 4 の `head` だけを使わない（最後の `LayerNorm` は使う）。head は node 4 の最後に引かれるので、ブロックの初期値は V16 の VAE（`b2006f0a-s0` の config、seed 0）とちょうど一致する（テストで確かめる）。config は V16 と同じ `config.yaml` を読む。デコーダと $\ln\sigma$ は作らない
- **射影**: $P$ = `Linear(1024 → 64)`、全位置で共有。トークン $h_p$（最後の `LayerNorm` の後）から $z_p = P h_p \in \mathbb{R}^{64}$。$z = (z_1, \dots, z_{16}) \in \mathbb{R}^{1024}$（位置は行優先）
- **標的側**: stack の 16 トークンすべてをエンコーダに通して $z$ を作る。stop-gradient も EMA もない
- **文脈側**: 同じエンコーダに、見える $16 - k$ 個のトークンだけを通す。パッチの埋め込みに位置の符号を足した後で、隠したトークンを落とす（V-JEPA と同じ）。注意は見えるトークンの中だけで働くので、隠した patch の画素は文脈側の出力に影響しない（テストで確かめる）。$k$ は batch の中で同じなので、形は `(B, 16 - k, 1024)` にそろう
- **予測器**: 幅 256、4 head（`HEAD_DIM` = 64）、pre-norm の `Block` を 4 段（エンコーダと同じ段数）。V-JEPA の予測器と同じ形で、次の順に計算する
  1. 文脈側の出力（幅 1024）を `pred_embed` = `Linear(1024 → 256)` で写し、その位置の符号 `sincos_2d((4, 4), 256)` を足す
  2. 隠した位置には、学習する 1 本のベクトル（mask token、256 次元）にその位置の符号を足したものを置く
  3. 16 個を `Block` 4 段に通し、`LayerNorm` の後、`pred_out` = `Linear(256 → 64)` で写す。隠した位置の出力を $\hat z_p$ とする
- 予測器の大きさは掃引しない。下の導出では、予測器が弱いほど健全な解の予測の損失 $\ell_H$ が大きくなり、stack の中で一定の解が有利になる。そこで段数はエンコーダにそろえ、弱くはしない

### μP での役割

エンコーダは VAE と同じ規則（`mup_roles`・`mup_lr`・`_mup_init_`、$k_w$ = 1024 / 256 = 4）。新しいパラメータは次のとおり。予測器の幅は 256（= `BASE_WIDTH`）に固定し、エンコーダの幅とともには変えない。

| パラメータ | 役割 | 学習率の倍率 | 初期値 |
| -- | -- | -- | -- |
| エンコーダ（パッチの埋め込み・ブロック・`LayerNorm`） | VAE と同じ（input・hidden・vector） | `mup_lr` と同じ | `build_vae` と同じ |
| 射影 $P$（幅 1024 → 64） | output（VAE の head と同じ、幅から固定の大きさへ） | $k_w^{-1}$ = 1/4 | LeCun（std $1/\sqrt{1024}$）× $k_w^{-1/2}$、bias 0 |
| `pred_embed`（幅 1024 → 256） | output（エンコーダの幅から固定の大きさへ） | $k_w^{-1}$ = 1/4 | 同上 |
| 予測器のブロック（256 → 256） | hidden（幅 256 なので $k$ = 1） | 1 | `_init_vit` の std 0.02 |
| `pred_out`（256 → 64） | output（$k$ = 1） | 1 | LeCun |
| mask token・bias・`LayerNorm` | vector | 1 | mask token は std 0.02 の truncated normal、他は `_init_vit` |

### マスク

- **族 $F_k$**: 4×4 の格子をトーラス（上下・左右の端をつないだもの）とみる。高さと幅が 1〜4 の矩形を 1 つ、または 2 つ置いた和集合のうち、ちょうど $k$ 個の位置を覆うものを、重複を除いた集合として列挙する。$|F_4|$ = 632、$|F_8|$ = 436、$|F_{12}|$ = 232（うち矩形 1 つのものは 24、8、8）
- **引き方**: 各 stack に、$F_k$ から一様に 1 つ選ぶ（batch の中で独立、`seed + MASK_SEED` の生成器）。early fusion なので、同じ位置が stack の 8 枚すべてで隠れる（V-JEPA の tube にあたる）
- **位置ごとに一様**: $F_k$ はトーラスの平行移動で閉じているので、族の上の一様分布では、各位置が隠される確率はちょうど $k/16$ になる。族の上で数えると、各位置を覆う要素は $k$ = 4 で 158、8 で 218、12 で 174 個（どれも $k|F_k|/16$）
- **トーラスにした理由**: 平面の上に一様に置くと、中央の位置ほど多く隠れる。代わりに、端をまたぐブロックは、平面では反対側の端にある 2 つの矩形になる
- **形の分布**（トーラスの上でつながった成分の数）: $k$ = 4 は 1 成分 280・2 成分 352、$k$ = 8 は 392・44、$k$ = 12 は 232・0。テストで、この数を別の書き方の総当たりと照合する
- **マスク率と形の交絡**: 2 成分の割合は、$k$ = 4 で 56%（1×1 の孤立したセルを含む）、8 で 10%、12 で 0% である。そのため $r$ の効果には、隠したブロックがまとまっているかの効果が混ざる。V18 では分けない（$r$ ごとに族を変えずに一様に引くことを優先した）。$r$ の差を読むときは、この交絡を併記する

### 損失

$$
L = (1 - \lambda)\, L_{\mathrm{pred}} + \lambda S, \qquad
L_{\mathrm{pred}} = \frac{1}{B k d} \sum_{n=1}^{B} \sum_{p \in M_n} \lVert \hat z_{n,p} - z_{n,p} \rVert^2
$$

- $M_n$ は stack $n$ の隠した位置（ちょうど $k$ 個）、$d$ = 64。$L_{\mathrm{pred}}$ は座標あたりの二乗誤差で、LeJEPA と同じ尺度である。SIGReg が満たされると $z$ の座標の分散は 1 なので、位置ごとの平均で当てる自明な予測の $L_{\mathrm{pred}}$ は約 1 になる
- $S$ = `exp.lib.sigreg.sigreg(z, z[:0], A)`。batch の $N = B$ = 128 個の $z \in \mathbb{R}^{1024}$ の Epps–Pulley の統計量（`T_POINTS` の 17 点）を、$M$ = 1024 本の方向 $A$ で平均したもの。$A$ は step ごとに `seed + DIRECTION_SEED` の生成器から引き直す（標準正規を引いて長さ 1 にする。batch の中では同じ方向）
- 統計量は $N$ 倍の形（LeJEPA と同じ）で、$z \sim N(0, I)$ なら $N$ によらず約 1.05 になる

### 自明な解の導出（$N$ = 128、$D$ = 1024）

統計量の期待値（$t$ は全実数で積分。台形則の 17 点でもほぼ同じ値になる）:

- **健全な解** $z \sim N(0, I_D)$: $E[N\lvert\hat\varphi - \varphi\rvert^2] = 1 - e^{-t^2}$ なので、$E[S] = \int (1 - e^{-t^2})\, e^{-t^2/2}\, dt = \sqrt{2\pi} - \sqrt{2\pi/3} = 1.059$。$N$ によらない
- **定数** $z_n = c$: 方向 $a$ への射影は定数 $s = a^\top c$ で、$s = 0$ のとき最小。$S = N \int (1 - e^{-t^2/2})^2 e^{-t^2/2}\, dt = N(\sqrt{2\pi} - 2\sqrt{\pi} + \sqrt{2\pi/3}) = 0.409 N$ = 52.3
- **共分散 $\Sigma$（$\mathrm{tr}\,\Sigma = D$）のガウス**: 射影の分散 $a^\top \Sigma a$ が方向によって揺れる分だけ罰を受ける。揺れが小さいとして展開すると、超過は $\frac{N}{4} \int t^4 e^{-3t^2/2}\, dt \cdot \mathrm{Var}_a(a^\top \Sigma a) \approx 0.241\, N\, (1/r_2 - 1/D)$。$r_2 = D^2 / \mathrm{tr}\,\Sigma^2$（participation ratio）
- **数値で確かめた値**（`epps_pulley`、$M$ = 1024、$N$ = 128、方向を引き直した平均）: 健全 1.05、定数 52.3、stack の中で一定 1.55、$\Sigma$ のランク 1 で 22.4、16 で 3.4、64 で 1.38、128 で 1.32

健全な解の予測の損失を $\ell_H$ とする（座標あたり、0〜1 程度）。3 つの自明な解は次のとおり。

1. **定数**: $L_{\mathrm{pred}} = 0$、$S$ の超過は 51.3。目的の式が健全な解を選ぶのは $\lambda > \ell_H / (\ell_H + 51.3)$ のとき。$\ell_H \le 1$ なら $\lambda > 0.019$ で排除される。**$\lambda$ = 0.005 では、$\ell_H > 0.26$ なら排除されない**
2. **位置だけの関数** $z_{n,p} = g(p)$: stack の単位で見ると、$z_n$ は入力によらない定数なので、1 と同じ（超過 51.3）
3. **stack の中で一定** $z_{n,p} = h(x_n)$、$h \sim N(0, I_{64})$: $\Sigma = (\mathbf{1}\mathbf{1}^\top) \otimes I_{64}$ で $r_2$ = 64、超過は約 0.45（数値では 0.50）。$h$ を、どの見える部分からも推定できる量（場面全体の明るさ・色・種類）にすれば $L_{\mathrm{pred}} \approx 0$ になる。排除されるのは $\lambda > \ell_H / (\ell_H + 0.50)$ のときで、$\ell_H$ = 0.3、0.5、0.8 では 0.38、0.50、0.62。**$\lambda \in \{0.005, 0.05\}$ では排除されない。$\lambda$ = 0.5 でも、$\ell_H > 0.5$ なら排除されない**
   - **この解は族をなす**: 位置ごとの可逆な線形写像 $A_p$（直交行列 $R_p$ など）を掛けた $z_{n,p} = A_p h(x_n)$ でも、$L_{\mathrm{pred}} = 0$ のままにできる。予測器は位置を知っているので、$A_q A_p^{-1}$ で写せばよい。$A_p$ が直交なら $\Sigma$ のスペクトルは変わらず（$r_2$ = 64）、SIGReg の超過も同じになる。共有の $P$ の前のトークン $h_p$ は位置の符号を持つので、エンコーダはこの形を作れる。数値（$N$ = 128、$D$ = 1024、$M$ = 1024）: 恒等の版は $S$ = 1.62・`rho_in` = 0.000・実効ランク 49.5、$R_p$ で回した版は $S$ = 1.63・`rho_in` = 0.932・実効ランク 49.5。独立なガウスでも `rho_in` は 0.937 である。したがって `rho_in` は恒等の版しか捕まえられない。評価では、族全体で 1 になる、基底によらない量 `token_r2`（下）で測る

一般に、エンコーダは、見える部分から予測できない位置ごとの内容を捨てて $r_2$ を下げると、$L_{\mathrm{pred}}$ を下げる代わりに約 $0.241 N\, \Delta(1/r_2)$ の罰を払う。罰は $N$ に比例するので、$N$ = 128 の batch の SIGReg は、$r_2$ を $N$ 程度まで下げることをほとんど罰しない。$N$ = 1024 なら、stack の中で一定の解の超過は 3.46（数値）で、$\ell_H$ = 0.5 なら $\lambda > 0.13$ で排除される。V18 では $N$ を変えない（バッファで標本を増やすのは V19）。この解は目的の式では排除されないので、評価で直接測る（下の `token_r2`）。崩壊が起きたら、まずこの導出と照らし合わせる（[memory/feedback_simple_fundamental.md](../../../memory/feedback_simple_fundamental.md)）。

この結論は 3 の解に限らない。「トークンごとに違う線形の読み出しで、どの見える部分からも推定できる約 128 次元の大域的な潜在を表す」符号（$r_2 \approx N$ = 128）の超過は、約 $0.241 \cdot 128 \cdot (1/128 - 1/1024) \approx 0.21$ しかない。この符号は $L_{\mathrm{pred}} \approx 0$ と両立し、`token_r2` ≈ 1、`rho_in` ≈ 15/16 になる。さらに、位置ごとの内容を一部だけ捨てた符号は、`token_r2` が 1 より小さいまま、同じ方向に寄る。したがって、崩壊の極端な形（3 の族）は `token_r2` で捕まえられるが、どこまで位置ごとの内容を残したかは、SIGReg の値でも `token_r2` でもなく、probe（`recon_blur`）でしか分からない。

上の比較は、目的の式の大域的な最小どうしの値の比較であって、学習の動きの議論ではない。勾配法の初期の動きでは、SIGReg は $N$ 倍の形なので 1 標本あたりの勾配が $O(1)$、$L_{\mathrm{pred}}$ は平均なので 1 標本あたり $1/B$ になる（LeJEPA と同じ尺度）。1 標本あたりの実効的な重みの比は $\lambda B / (1 - \lambda)$ で、例えば $\lambda$ = 0.005 でも約 0.64 である。どちらの解に向かって動くかは、この導出だけでは決まらない。

### 学習（`jepa_iid.py`）

- **データ**: `iid.Units(conf, root, "all", seed=conf.seed + DRAW_SEED)` から 128 stack を、一様に、重複を許して引く（V16 の `all`）。次の batch はスレッドで先に読む（V16 と同じ）
- **optimizer**: AdamW（$\beta$ = 0.9・0.999、eps 1e-8、weight decay 0）。`jepa_mup_lr` の倍率ごとに param group を分ける。clip しない。学習率は `iid.lr_at`（最初の 1000 step で線形に上げ、`--steps` で cosine で 0 に下げる）
- **乱数**: 生成器を分ける。初期値（エンコーダは seed、射影は seed + `PROJ_SEED`、予測器は seed + `PREDICTOR_SEED`）、stack（seed + `DRAW_SEED`）、マスク（seed + `MASK_SEED`）、方向（seed + `DIRECTION_SEED`）。`configure_determinism` を使う
- **checkpoint**: step $s$ の時刻は、見た stack × 0.1 秒（V16 と同じ）で、$t = 12.8 s$ 秒。短い run は step 0、1000、2000、4000、6000（$t$ = 0、12800、25600、51200、76800 秒）。長い run は 0、2000、6000、10000、20000、30000、40000、50000、60000（$t$ = 768000 秒まで）。長い run の 6000 step は、短い run の 6000 step とは学習率の予定が違うので同じではない
- **出力** `<out>/`:
  - `config.yaml`（読んだ config、`device` を書き換えたもの）
  - `jepa.json`: $r$、$k$、$\lambda$、$d$、$M$、予測器の形、学習率、steps、batch、warmup、seed たち、optimizer、族の大きさ $|F_k|$、units の数、determinism
  - `train.jsonl`: 100 step ごとの平均。`loss`、`pred`、`sigreg`、`grad_norm`（clip の前）、batch の `z_var`（座標ごとの分散の平均）と `rho_in`、`lr`、`sec`
  - `jepa.json` の `provenance`: `provenance.of_diagnosis` の記録（host の `code/<snap>` から走らせれば、その `CODE.json`。snapshot と mujou のコミットを含む）、host、コマンド行、環境
  - `ckpt/<t>.pt`（`ckpt.save_eval`、program `"jepa"`、modules は `encoder`・`proj`・`predictor`）
- 損失が有限でなくなったら止める（`FloatingPointError`、V16 と同じ）

### 評価（`jepa_eval.py`）

符号は、どれも「stack → 符号のベクトル」の関数として扱う。JEPA の符号は標的側の平らな $z$（1024 次元）。VAE の `VaeCode` の `decode`（システムの描き戻し）は使わない。

- **probe**（`stream_eval.StreamEvaluator` の部品、`--span 6000` の視点）: 学習のストリームの 0〜6000 秒の奇数番目の 10 秒の区間の約 6000 組で、後から学ぶデコーダ（4 seed × 2000 step）と線形の動力学を当てはめる。span・after・zurich（val の 1024 窓）で、`recon_blur`、`dyn_1/copy_1`、`rank` を出す
  - V16 は 1800 秒ぶん（1800 組）で当てはめた。V17 は 6000 組で、同じ学習前のモデルの zurich の `recon_blur` が 0.502 から 0.404 に下がった。当てはめる組の数が値を決めていたので、V17 と同じ 6000 秒にそろえる
  - `StreamEvaluator.probes` のうち `decode` を使う部分（絵の 2 段目）を、符号だけのものでは外せるようにする。VAE の行は変えない（`tests/vision/test_stream_eval.py` はそのまま通す）
- **JEPA の量**（zurich の val の各窓の最初の stack、$N$ = 1024、checkpoint ごと）
  - `pred`: 固定したマスク（各 stack に $F_k$ から 8 個、`EVAL_MASK_SEED`）での $L_{\mathrm{pred}}$。`pred_triv`: 同じマスクで、隠した位置を「位置ごとの $z_p$ の平均」（当てはめの組の stack で求めたもの）で当てたときの値。`pred_ratio` = `pred` / `pred_triv`。`pred_triv` は学習のストリームの平均で zurich を当てるので、ドメインのずれの分だけ大きくなる。読みの幅を見るため、zurich 自身の calib の窓の位置ごとの平均で当てた `pred_triv_calib` と `pred_ratio_calib` も並べる
  - `sigreg_zurich`: zurich の 1024 個の $z$ の $S$（固定した 1024 本の方向、`EVAL_DIRECTION_SEED`）。同じ方向・同じ $N$ での、$N(0, I)$ の標本の値（約 1.06）と定数の値（0.409 $N$ = 419）を同じ行に書く。zurich は 1 本の動画なので、健全でも $N(0, I)$ の値には届かない。並べるだけにする
  - `sigreg_heldin`: 学習の units から一様に引いた 128 stack × 16 batch の $S$ の平均（固定した方向と生成器）。学習中の $S$ と同じ尺度で、参照は 1.05 と 52.3（評価が同じ方向で計算して行に書く）
  - `token_r2`: 1 つのトークン $z_p$ から別のトークン $z_q$ を線形回帰（切片つきの ridge、$\alpha_p$ = `TOKEN_RIDGE` × $\mathrm{tr}(X_p^\top X_p)/d$）で当てたときの $R^2$ を、順序つきの組 $p \ne q$（240 組）で平均したもの。回帰は当てはめの組の stack で求め、zurich で評価する。導出の族 $z_{n,p} = A_p h(x_n)$ なら、どの可逆な $A_p$ でも 1、位置どうしが独立なら 0。K3 に使う
  - `participation`: zurich の $z$ の共分散の participation ratio $r_2 = (\mathrm{tr}\,\Sigma)^2 / \mathrm{tr}\,\Sigma^2$（超過の式の $r_2$）。標本の値は低く偏る（$N(0, I_D)$ で約 $N D/(N+D)$ = 512）。並べるだけ
  - `rho_in`: stack の中の分散の割合。$u_{n,p} = z_{n,p} - \bar z_p$（$\bar z_p$ は位置 $p$ の、stack をまたいだ平均）、$\bar u_n = \frac{1}{16} \sum_p u_{n,p}$ として、$\rho_{\mathrm{in}} = \sum_{n,p} \lVert u_{n,p} - \bar u_n \rVert^2 / \sum_{n,p} \lVert u_{n,p} \rVert^2$。stack の中で一定なら 0、位置どうしが無相関で分散が等しければ 15/16。基底に依存するので（3 の族を $R_p$ で回すと 0.93）、恒等の版の診断として並べるだけにする
  - `z_var`: 座標ごとの分散の平均（SIGReg の目標は 1）
- **絵**: probe の checkpoint ごとに `<t>-zurich.png` と `<t>-span.png`（本物の最後のフレームと、後から学ぶデコーダの seed 0 の描き戻し）
- **物差し**（`python -m exp.vision.jepa_eval --yardsticks`、1 回だけ）: 同じ probe に通す。トークンを持つもの（`init`・`color`）は `token_r2` と `rho_in` も出す
  - `init`: JEPA の step 0（seed 0。18 本とも同じ初期値）
  - `init256`: `init` の $z$ を、当てはめの組の stack での PCA で 256 次元（VAE の $\mu$ と同じ）に落としたもの。符号の次元をそろえた参照（下の「次元の偏り」）
  - `color`: パッチごと・チャネルごとの画素の平均（16 トークン × 24 チャネル = 384 次元）。学習しない符号で、M17 の `tube` にあたる
  - `pca`: 当てはめの組の stack（平らにした 24×64×64）の画素の PCA、1024 成分（`exp.lib.pca`、seed + `PCA_SEED`）。上側の参照で、並べるだけ
  - `v16`: V16 の `all`・学習率 $3 \cdot 10^{-4}$ の最後の checkpoint の $\mu$（256 次元）
  - `v17`: V17 の本番（$\tau = 10^3$、`v0-base-49b81800-s0`）の `04800.0` の $\mu$。V17 の値（zurich の `recon_blur` 0.2136、`dyn_1/copy_1` 0.768）を再現するかで、評価の経路を確かめる
- **次元の偏り**: 後から学ぶデコーダと ridge の線形動力学に入る次元は、VAE の $\mu$ が 256、`init`・JEPA・`pca` が 1024、`color` が 384 である。入力は標準化されるが、デコーダの容量と動力学の自由度は次元とともに増える。そのため VAE は `init` を下回りにくく、物差しの有効性の規則（README）では組が「使えない」と判定されやすい（保守的な方向）。run と `init` の比較は同じ 1024 次元で公平である。`init256` との差で、この偏りの大きさを見る
- **span**: 既定は `SPAN` = 6000 秒（`--span` を省いても 6000 組で当てはめる）。V16 の config の `measure.duration`（1800 秒）に知らないうちに戻らないようにした
- **出力**: run の `posthoc_jepa/`（`config.json`、`probes.jsonl`、`jepa.jsonl`、絵）。物差しは `runs/v18-jepa/yardsticks/posthoc_jepa/`（行に `code` の名前）

### 実行

- 先に mini-00 で 100 step の試しを回し、1 step の時間・GPU メモリ・`train.jsonl` の値が有限であることを確かめる
- 短い 18 本は、std-00〜03 の 4090 と 4060 に、1 GPU に 1 本ずつ（std-03 で同居させたとき illegal memory access が出た）。1 step 約 0.1 秒の見込みで（V16 の VAE は batch 100 で 0.073 秒）、6000 step は約 10 分
- 出力は NAS の `/nas/geson/mujou-exp/runs/v18-jepa/<name>/` に置き、ckpt 以外を `./runs/v18-jepa/` に pull する。名前は `jepa-r<r>-lam<λ>-lr<lr>-s<seed>`（例 `jepa-r0.5-lam0.05-lr1e-3-s0`）、長い run は `jepa-long-r<r>-lam<λ>-lr<lr>-s<seed>`

### 実装のテスト（理論のオラクル）

- **マスク**: 族のすべての要素がちょうど $k$ 個を覆う。族の大きさ（632・436・232）、矩形 1 つの数、成分の数が、別の書き方の総当たりと一致する。トーラスの平行移動で閉じている。族の上で、各位置を覆う要素の数がちょうど $k|F_k|/16$。$10^5$ 回引いた位置ごとの頻度が、二項分布の 4σ の中にある
- **文脈側**: 隠した patch の画素を変えても、文脈側の出力がまったく同じ
- **損失**: 手で計算できる小さな例と一致する。定数の $z$ で $S$ が $0.409 N$（台形則の誤差の中）。stack の中で一定のトークンと、見えるトークンを写すだけの予測器で $L_{\mathrm{pred}} = 0$。標的側の $z$ にも $L_{\mathrm{pred}}$ の勾配が届く（stop-gradient がない）
- **初期値**: エンコーダのブロックが、同じ seed の `build_vae` のものと一致する
- **μP**: 役割と倍率が上の表のとおり。エンコーダの倍率が `mup_lr` と一致する
- **学習**: 小さな設定で 2 step 回し、同じ seed で同じ値になる（決定性）。checkpoint の時刻が $t = 12.8 s$
- **評価**: `color` の符号が手計算と一致する。`rho_in` が、stack の中で一定なら 0、位置が独立な標本なら 15/16 に近い。`token_r2` が、stack の中で一定なら 1、それを位置ごとの直交行列で回しても 1（このとき `rho_in` は 0.85 より大きい）、位置が独立なら 0、半分を共有する $z_p = (s + e_p)/\sqrt 2$ なら 1/4。`participation` が、等方的な標本で $N D/(N+D)$、直線の上で 1、stack の中で一定で約 $d$
- **予測器の順序**: ブロックを恒等にした予測器の出力が、隠した位置の昇順で $\mathrm{out}(\mathrm{LN}(\text{mask token} + \mathrm{pos}_p))$ に一致する

## V18b: トークンを細かくする（詳細設計、2026-11-23）

run の一覧・判定・長い run の規則・予想・反証は [README の「V18b」の節](../README.md)（回す前に決めたこと）に書いた。ここには、実装できる粒度の設計と、腕ごとの自明な解の導出を書く。V18 から変えるところだけを書き、書いていないところは V18 の節のとおりにする。

### ユーザーが決めたこと

- パッチを 16×16 から **4×4** に変える。64 px で 16×16 = 256 トークン、トークンの入力は 8 × 3 × 4 × 4 = 384 次元。V18 の診断で、トークンが粗いために近くから当てられる成分で予測が済んでいる可能性が残ったため。そのあとで未来予測の学習（V18c、今回は範囲外）に進む
- ハイパラを広げて調べる（学習率と $\lambda$）
- SIGReg のデータ点として**トークン平均**を試す。ただし平均だけの SIGReg は「stack の中で全トークンが同じ」族（V18 の K3）を罰しないので、平らに並べる腕と並べて比べる

推奨で進めたこと（ユーザーは異を唱えていない）: 腕 F・M・P16 の形、マスクの画素の領域を V18 と同じにすること、Imagenette を副の基準に足すこと、Codex さんの助言（pred と $S$ を別々に追う、初期値の近くに留まった run は判定保留）。

### 腕

| 腕 | パッチ | トークン $T$ | $d$ | 平らな $z$ | SIGReg のデータ点 | SIGReg の次元 $D_S$ | 予測の的 |
| -- | -- | -- | -- | -- | -- | -- | -- |
| F（平らに並べる） | 4 | 256（16×16） | 4 | $\mathbb{R}^{1024}$ | 平らにした $z$ | 1024 | 隠した位置の $z_p \in \mathbb{R}^4$ |
| M（トークン平均） | 4 | 256 | 64 | $\mathbb{R}^{16384}$ | $\bar z = \frac1T \sum_p z_p$ | 64 | 隠した位置の $z_p \in \mathbb{R}^{64}$ |
| P16（比較） | 16 | 16（4×4） | 64 | $\mathbb{R}^{1024}$ | 平らにした $z$ | 1024 | 隠した位置の $z_p \in \mathbb{R}^{64}$（V18 と同じ） |

- **F は V18 とトークンの細かさだけが違う。** $D$ = 1024 も、画素あたりの圧縮率（6144 → 64 と 384 → 4、どちらも 96 分の 1）も V18 と同じである。F と P16 の差が、トークンの細かさの効果になる
- **M は F とデータ点だけが違う**（$d$ は、平均を 64 次元にするため 64 にした）。エンコーダは F と同じパッチ・同じ seed なので、初期値はちょうど一致する（テストで確かめる）
- **P16 は V18 そのもの**（同じ config・同じコード経路）。V18 の run を再利用できる条件は下の「実行」に書く
- 3 つの腕で、エンコーダ（ViT-S・幅 1024・μP・4 ブロック）・予測器（幅 256・4 段）・optimizer・batch 128・warmup 1000 step と cosine・データの引き方・seed の分け方は V18 と同じである

### エンコーダと予測器（パッチ 4）

- **config**: V16 と同じ `config.yaml` を読み、`model.patch` だけを 4 に替える（`jepa_iid --patch 4`）。`ModelConf` に、パッチの大きさを制約する検査はない。`PatchEmbed` は `Linear(24·4·4 = 384 → 1024)` と位置の符号 `sincos_2d((16, 16), 1024)` になり、`grid = size // patch` = 16 から、そのまま 256 トークンを出す（コードの変更は要らない）
- **初期値の引き方**: `build_jepa` は `build_vae` と同じ手順で ViT を作ってから head を捨てる。パッチ 4 では head が `Linear(256·1024 = 262144 → 512)`（1.3 億個のパラメータ、CPU で約 0.5 GB）になるが、作って捨てるだけで、乱数の消費も含めて V18 と同じ手順である。ただし、パッチの埋め込みの行列の大きさが変わるので乱数の消費が変わり、**P16 と F・M のブロックの初期値は一致しない**（同じ seed の別の引き直しにあたる）。F と M の間では一致する
- **予測器**: 位置の符号を `sincos_2d((16, 16), 256)` にする（`Predictor(grid=16)`、`build_jepa` は `grid` を config から求めるので変更は要らない）。入口の `embed` は `Linear(1024 → 256)` のまま、出口の `out` を `Linear(256 → d)` にする（F は 4、M と P16 は 64）。予測器に入るトークンは 256 個（見える $256 - 16k$ 個と mask token $16k$ 個）
- **射影**: $P$ = `Linear(1024 → d)`。`TOKEN_DIM` を定数から run の設定（`--token-dim`、既定 64）に替える。$P$ の乱数（`seed + PROJ_SEED`）は形が変わるので、F と M・P16 で一致しない
- **注意の計算量**: `Block` の注意は $(B, h, T, T)$ の行列を作る。$T$ = 256 では 1 ブロックで $128 \cdot 16 \cdot 256^2$ = 1.3 億個（float32 で 0.54 GB）になる。線形の部分はトークン数に比例して 16 倍、注意の行列は 256 倍になる。トークンあたりの計算では、線形の部分（$12 w^2$ ≈ 1260 万の積和）が注意（$2 T w$ ≈ 52 万）の約 24 倍なので、1 step の計算は V18 の約 17 倍とみる。V18 の 4090 の長い run は 0.036〜0.044 秒 / step だったので、パッチ 4 は 0.4〜0.75 秒 / step の見込みである（実測は試しの run で行う）
- **メモリの見込み**: backward のために保持する活性は、標的側（256 トークン）で 1 ブロックあたり約 4.6 GB（LN・qkv・注意の行列 3 つ・MLP の $4w$ の 2 つなど）、4 ブロックで約 18 GB である。文脈側を足すと、$r$ = 0.25 で約 30 GB、0.5 で約 25 GB になり、4090（24 GB）を超える見込みである。超えたら、エンコーダのブロックごとに activation checkpointing（`torch.utils.checkpoint`、`--checkpoint-blocks`）を使う。backward のときに同じ演算で前向きを計算し直すだけなので、値は変わらない（テストで、勾配がちょうど一致することを確かめる）。計算は約 1.33 倍になる。使うかどうかは試しの run の実測で決め（下の「実行」）、F と M のすべての run で同じにする。`scaled_dot_product_attention` への置き換えや bf16 は、数値が V18 と変わるので使わない

### μP での役割

役割と倍率は V18 の表のまま変えない（`jepa_mup_roles`・`jepa_mup_lr`）。変わるのは次の 2 つで、どちらも μP の規則が幅だけを扱うことから来る。

- **パッチの埋め込み**（input の役割）: fan-in が 6144 から 384 に変わる。初期値は LeCun（std $1/\sqrt{\text{fan-in}}$）なので、0.0128 から 0.051 になり、出力の大きさ（画素の 2 乗平均 × 1）は変わらない。学習率の倍率は幅によらず 1 のままにする。ただし Adam の 1 step の重みの変化は座標あたり約 $\eta$ なので、埋め込みの出力の変化は約 $\eta \sum_i \lvert x_i \rvert \propto \eta \cdot \text{fan-in}$ になる。同じ $\eta$ では、**パッチ 4 の埋め込みは P16 より約 16 分の 1 しか動かない**。μP は入力の次元を固定の定数として扱い、この依存を定めない。ここで倍率 16 を足すのは導出の裏付けのない変更になるので、足さない。そのかわり、埋め込みとブロックが初期値からどれだけ動いたか（下の `drift`）を checkpoint ごとに測り、腕の比較に並べる。埋め込みが動かないことは、初期値の情報を残す向き（H-coarse に有利な向き）に効く
- **射影 $P$ と予測器の `out`**: output の役割のまま。F では $d$ = 4 になるが、output の倍率（$P$ は $k_w^{-1}$ = 1/4、`out` は 1）と初期値（LeCun、$P$ は × $k_w^{-1/2}$）の規則は出力の次元によらない

### マスク（4×4 から 16×16 へ広げる）

V18 の族 $F_k$（4×4 のトーラスの上の、矩形 1〜2 個の和集合でちょうど $k$ 個を覆うもの）をそのまま使い、引いたマスクを細かい格子に広げる。画素の領域が V18 とまったく同じになるので、マスクの形の違いとトークンの細かさが混ざらない。

- **写像**: 粗い格子を $G$ = 4、細かい格子を $g$ = size / patch、$s = g / G$（パッチ 4 で 4、パッチ 16 で 1）とする。細かい位置 $p = g i + j$（行優先）を、粗い位置 $c(p) = G \lfloor i/s \rfloor + \lfloor j/s \rfloor$ に対応させ、$m_{\mathrm{fine}}[p] = m_{\mathrm{coarse}}[c(p)]$ とする（`expand_masks(mask, s)`、`(B, 16)` → `(B, 16 s^2)`）。粗い 1 マスは、細かい $s \times s$ = 4×4 のブロックになる
- **隠す数**: $k_{\mathrm{fine}} = s^2 k$。$r$ = 0.25・0.5・0.75 で 64・128・192 個（見える数は 192・128・64）。マスク率 $r = k/16$ は V18 と同じ
- **画素の領域が同じこと**: 細かい位置 $p$ の画素は、行 $[4i, 4i+4)$・列 $[4j, 4j+4)$ で、粗い位置 $c(p)$ の 16×16 画素のブロックに含まれる。$c(p) = c$ となる $p$ は $s^2$ = 16 個で、合わせて $16 \cdot 4^2 = 16^2$ 画素なので、粗いマスの画素とちょうど一致する
- **位置ごとの確率**: $P(m_{\mathrm{fine}}[p]) = P(m_{\mathrm{coarse}}[c(p)]) = k/16$。族の上で数えると、各細かい位置を覆う要素は $k|F_k|/16$ 個（158・218・174）のまま
- **引き方**: V18 と同じ生成器（`seed + MASK_SEED`）で $F_k$ から粗いマスクを引き、広げる。そのため、**同じ seed の F・M・P16 は、step ごとにまったく同じ画素を隠す**。評価の固定したマスク（`EVAL_MASK_SEED`、各 stack に 8 個）も同じように広げる
- **トーラス**: 広げたマスクは、16×16 のトーラスの上でも（4 の倍数にそろった）矩形 1〜2 個の和集合である。パッチ 4 の族を新しく列挙することはしない（形の分布が V18 と変わるため）

### 損失

$$
L = (1 - \lambda)\, L_{\mathrm{pred}} + \lambda S, \qquad
L_{\mathrm{pred}} = \frac{1}{B k_{\mathrm{fine}} d} \sum_{n=1}^{B} \sum_{p \in M_n} \lVert \hat z_{n,p} - z_{n,p} \rVert^2
$$

- $L_{\mathrm{pred}}$ は V18 と同じく座標あたりの二乗誤差である
- $S$ は腕で変わる（`--sigreg-on flat|mean`、既定 `flat`）。F と P16 は $S = \mathrm{SIGReg}(\{z_n\})$、$z_n \in \mathbb{R}^{Td}$ = $\mathbb{R}^{1024}$。M は $S = \mathrm{SIGReg}(\{\bar z_n\})$、$\bar z_n = \frac1T \sum_p z_{n,p} \in \mathbb{R}^{64}$。方向は $M$ = 1024 本を $\mathbb{R}^{D_S}$ の球面から step ごとに引き直す（`directions(1024, D_S, gen)`、生成器は V18 と同じ）
- EMA も stop-gradient も使わない。標的側の $z$（M では $\bar z$ も）に勾配が届く

### 自明な解の導出（$N$ = 128、腕ごと）

数値は `exp.lib.sigreg.sigreg`（17 点の Epps–Pulley、$M$ = 1024 本、方向を 8 回引き直した平均）で求めた。

| 解 | F（$D_S$ = 1024、$d$ = 4） | M（$D_S$ = 64） | P16（V18） |
| -- | -- | -- | -- |
| 健全 $z \sim N(0, I)$（M は $\bar z \sim N(0, I_{64})$） | 1.06 | 1.06 | 1.05 |
| 定数 | 52.3（$0.409 N$） | 52.3 | 52.3 |
| 位置だけの関数 $z_{n,p} = g(p)$ | 52.3 | 52.3（$\bar z$ が定数） | 52.3 |
| K3: stack の中で一定 $z_{n,p} = h(x_n)$ | **8.37**（超過 7.3） | **1.06**（超過 0） | 1.51（超過 0.5） |
| K3 を位置ごとの直交行列で回したもの | 8.39 | 下を参照 | 1.63 |
| K3 に位置だけの項を足したもの $h(x_n) + g(p)$、$\sum_p g(p) = 0$ | 8.37 以上（共分散は K3 と同じで、平均のずれ $g$ の分だけ大きい） | **1.06**（超過 0） | — |
| 約 128 次元の大域的な潜在 $z_{n,p} = B_p\, g(x_n)$、$g \in \mathbb{R}^{128}$ | **1.28**（超過 0.22） | — | 約 1.26（超過 0.21） |
| 位置どうしが独立、座標の分散 1 | 1.06 | **51.5**（$\bar z$ の分散が $1/T$） | 1.05 |

健全な解の予測の損失を $\ell_H$（座標あたり、0〜1 程度）とする。

**腕 F**

1. 定数と位置だけの関数は、V18 と同じく $\lambda > \ell_H / (\ell_H + 51.3)$ で排除される
2. **K3（全トークンが同じ $h \in \mathbb{R}^4$）は強く罰せられる。** $\Sigma = (\mathbf 1 \mathbf 1^\top) \otimes I_4$ のランクは 4 なので、$S$ は 8.37（超過 7.3）になる。排除されるのは $\lambda > \ell_H/(\ell_H + 7.3)$ のときで、$\ell_H$ = 0.5・1 で 0.064・0.12 である。掃引の $\lambda \ge 0.5$ では排除される。位置ごとの直交行列 $R_p$（4×4）で回しても、スペクトルは同じなので 8.39 で変わらない
3. **大域的な潜在の解は残る。** トークンごとに違う線形の読み出し $B_p \in \mathbb{R}^{4 \times q}$ で、どの見える部分からも推定できる $q$ 次元の潜在 $g$ を表す符号 $z_{n,p} = B_p g(x_n)$ は、$q$ = 128 で $S$ = 1.28（超過 0.22）、16 で 2.80、64 で 1.54、256 で 1.15 である。$L_{\mathrm{pred}} \approx 0$ と両立し、1 つのトークン（4 次元）から別のトークンを線形に当てる `token_r2` は約 $4/q$ と小さいので、K3 の検査に掛からない。V18 の P16 の同じ解（超過 0.21）と同じ大きさである。**したがって、目的の式は F でも「位置に固有で当てにくい内容を捨てる」道（Codex さんの見立て、H-target）を閉じない。** H-coarse が当たるなら、その理由は目的の大域的な最小の比較にはなく、学習の動き（その解に向かわないこと）にある
4. トークンの次元が 4 しかないので、1 つのトークンには大域的な潜在の 4 次元ぶんしか載らない。大域的な符号は、必ずトークンに散らして持つことになる

**腕 M**

$\bar z_n = \frac1T \sum_p z_{n,p}$ とし、$z_{n,p} = \bar z_n + u_{n,p}$（$\sum_p u_{n,p} = 0$）に分ける。

1. **$S_M$ は $\bar z$ だけで決まり、$u$ によらない。** 勾配で書くと $\partial S_M / \partial z_{n,p} = \frac1T \nabla S(\bar z)_n$ で、$p$ によらない。つまり SIGReg は、stack の全トークンを同じベクトルだけ動かし、stack の中のばらつき $u$ には一切働かない。$u$ を動かすのは $L_{\mathrm{pred}}$ だけである
2. **K3 は罰せられない。** $u = 0$、$\bar z_n = h(x_n) \sim N(0, I_{64})$ とすると、$S_M$ は健全な値 1.06 そのものになる。$h$ を、どの見える部分からも推定できる量（場面全体の明るさ・色・種類）にすれば、$L_{\mathrm{pred}} = E\lVert \hat z_p - h \rVert^2 \approx 0$ にできる。そのため、どの $\lambda \in [0, 1)$ でも、K3 は目的の式の下限 $\lambda \cdot 1.06$ に届く。V18（超過 0.5）とも F（超過 7.3）とも違い、**K3 を排除する $\lambda$ はない**
3. 位置だけの項を足した $h(x_n) + g(p)$（$\sum_p g = 0$）も同じで、$S_M$ = 1.06、$L_{\mathrm{pred}} = 0$（予測器は位置を知っている）である
4. **M は stack で共有する成分を強く好む。** 位置どうしが独立で座標の分散が 1 のトークンでは、$\bar z$ の分散は $1/T$ = 1/256 になり、$S_M$ は 51.5（ほぼ定数の値）になる。$\bar z$ の分散を 1 にするには、トークンの分散を $T$ = 256 倍にする必要があり、そのぶん当てられない内容の $L_{\mathrm{pred}}$ も 256 倍になる。SIGReg を満たしやすいのは、分散 1 の共有の成分を持つ符号である
5. K3 を位置ごとの写像 $A_p$ で回した $z_{n,p} = A_p h(x_n)$ では、$\bar z = \bar A h$（$\bar A = \frac1T \sum_p A_p$）になる。$A_p$ がばらばらの直交行列なら $\bar A$ は小さくなるので、$h$ を大きくしないと $S_M$ が罰する。恒等の版（$A_p = I$）にはその必要がなく、SIGReg は $u$ を動かさないので、学習は恒等の版に向かうとみる

**P16**: V18 の導出のとおり（K3 の超過 0.5、大域的な潜在の超過 0.21）。

上の比較は、どれも目的の式の大域的な最小どうしの値の比較で、学習の動きの議論ではない。

### `rho_in` の腕 M での使い方

`rho_in` = $\sum \lVert u_{n,p} - \bar u_n \rVert^2 / \sum \lVert u_{n,p} \rVert^2$（V18 の定義。$u$ は位置ごとの、stack をまたいだ平均を引いたもの、$\bar u_n$ は stack $n$ のトークンの平均）は、K3 の恒等の版で 0、位置どうしが独立なら $(T-1)/T$ = 255/256 になる。K3 では 1 ではなく **0 に近づく**。

- 腕 M では、分子は「位置ごとの平均を引いたうえで、SIGReg が見ない成分（stack の中のばらつき）」そのものである。導出の 1 から、M の SIGReg はこの成分に働かない。したがって `rho_in` は、M で SIGReg の外に残った内容の割合を、基底によらずに表す（M の SIGReg が $\bar z$ だけを見るので、V18 で問題になった位置ごとの回転は、上の 5 のとおり起きにくい）
- 腕 M の `rho_in` は、学習の `train.jsonl`（batch の値、100 step ごと）と評価（zurich、checkpoint ごと）の両方に出す。K3 の判定は V18 と同じく `token_r2`（基底によらない）で行い、`rho_in` は並べるだけにする。予想（README）は `rho_in` の値でも書く
- 腕 F と P16 の `rho_in` は V18 と同じく並べるだけにする

### 学習（`jepa_iid.py` の変更）

- **引数**: `--patch`（既定は config の値）、`--token-dim`（$d$、既定 64）、`--sigreg-on`（`flat` か `mean`、既定 `flat`）、`--checkpoint-blocks`（既定なし）。既定のままなら V18 とまったく同じ計算になる
- **ログ**: `train.jsonl` は V18 の列に加えて、`zbar_var`（$\bar z$ の座標ごとの分散の平均。M で SIGReg の目標が 1 になる量）と `max_mem`（`torch.cuda.max_memory_allocated`、GB）を出す。`z_var` と `rho_in` はトークンの $z$ で、V18 と同じ
- **`jepa.json`**: V18 の項目に、`patch`、`grid`（16 か 4）、`coarse_grid`（4）、`expand`（$s$）、`k_fine`、`token_dim`、`sigreg_on`、`sigreg_dim`（$D_S$）、`checkpoint_blocks` を足す
- **checkpoint の時刻**: V18 と同じ（$t = 12.8 s$ 秒）。短い run は step 0・1000・2000・4000・6000。長い run は step 数 $s_{\mathrm{long}}$（README の規則で決める）が 60000 なら V18 の `LONG_CKPT`。60000 より小さければ、0・2000・6000 と、$s_{\mathrm{long}} \cdot j / 6$（$j$ = 1〜6）を 2000 の倍数に切り下げたもの
- **出力**: V18 と同じ形（`config.yaml`、`jepa.json`、`train.jsonl`、`ckpt/<t>.pt`）。ckpt は 1 つ約 0.22 GB（パッチの埋め込みが小さくなる分だけ V18 より小さい）

### 評価（`jepa_eval.py`・`jepa_diag.py` の変更）

`jepa.json` の `patch`・`token_dim`・`sigreg_on` から腕を読み、次の符号を同じ probe（`StreamEvaluator.probes`、`SPAN` = 6000 秒、6000 組、デコーダ 4 seed × 2000 step）と統計に通す。

| 腕 | 判定に使う符号（主） | 並べる符号 | `sigreg_heldin`・`sigreg_zurich`・K1 の対象 | K3 の対象 |
| -- | -- | -- | -- | -- |
| F | `z`（平らな $z$、1024） | `h_mean`（1024）。長い run は `h_pool`（16384） | `z`（$D_S$ = 1024） | $z_p$（256 個 × 4） |
| M | `zpca`（平らな $z$、16384 を、当てはめの組の stack の PCA で 1024 次元にしたもの） | `zbar`（$\bar z$、64）、`zflat`（16384）、`h_mean`。長い run は `h_pool` | `zbar`（$D_S$ = 64） | $z_p$（256 個 × 64） |
| P16 | `z`（1024、V18 と同じ） | `h_mean`。長い run は `h_flat`（16384、V18 の診断と同じ） | `z` | $z_p$（16 個 × 64） |

- **次元をそろえる**: 判定の符号は 3 つの腕で 1024 次元にそろえる。M の平らな $z$ は 16384 次元あり、そのまま比べると次元の偏り（V18 の「次元の偏り」、`h_flat` の 16384 次元は学習前で 0.109）で有利になる。PCA（`exp.lib.pca`、seed + `PCA_SEED`、V18 の `init256` と同じ作り方）で 1024 次元に落とした `zpca` を主にし、`zflat` は並べるだけにする
- **`h_flat` は外す**: パッチ 4 の $h$ を平らにすると $256 \times 1024$ = 262144 次元になり、線形の動力学（$D \times D$ の行列）が作れない。かわりに `h_pool` を、長い run の probe の checkpoint にだけ出す。$h$ を 16×16 の格子のまま 4×4 のブロックごとに平均し、4×4 = 16 トークン × 1024 = 16384 次元にしたもので、P16 の `h_flat` と同じ次元・同じ画素の領域になる。エンコーダが情報を失うか（V18 の診断の問い 1）を、P16 の `h_flat` と並べて読むためのもので、並べるだけにする
- **`token_r2`**: 順序つきの組 $p \ne q$ のすべて（パッチ 4 で 65280 組）で平均する。$p$ ごとに ridge の解 $(X_p^\top X_p + \alpha_p I)^{-1} X_p^\top$ を 1 回だけ作り、全部の $q$ に一度に掛ける（M で約 1.6 TFLOP）
- **`pred`・`pred_ratio`・`pred_ratio_calib`**: V18 と同じ。固定したマスクを広げて使う
- **`drift`**（新しく足す。checkpoint だけから計算できる）: パッチの埋め込みの行列とエンコーダのブロックの行列のそれぞれで、$\lVert W_t - W_0 \rVert_F / \lVert W_0 \rVert_F$（$W_0$ は同じ run の step 0）。`embed_drift` と `block_drift`（ブロックの行列をつないだもの）を出す。初期値の近くに留まったかを直接見る量で、判定保留の読みと、μP の埋め込みの偏り（上）の確認に使う。並べるだけにする
- **Imagenette の線形 probe**（`jepa_diag imagenette`、V18 の診断と同じ手順・同じデータ・$\delta_a$ = 2.3 ポイント）: 符号は全部の腕の `h_mean` と、F・P16 の `z`、M の `zbar`。短い run は step 0（腕ごとに 1 回）と 6000、長い run は全 checkpoint。パッチ 4 でも 64 px の止まった stack をそのまま入れる
- **物差し**（`jepa_eval --yardsticks --patch 4`、1 回だけ）: `init_f`（F の step 0 の `z`）、`init_m`（M の step 0 の `zpca`、`zbar` も）、`color4`（パッチ 4 のパッチごと・チャネルごとの画素の平均、256 × 24 = 6144 次元。`ColorCode(4)`）。`color4` は K3 の閾値（$\theta_3$）にだけ使い、`recon_blur` は並べるだけにする（16×16 の格子の平均の色は、ぼかした画像をほぼ描き戻せるので、合格の物差しには使わない）。V18 の物差し（`init`・`init256`・`color`・`pca`・`v16`・`v17`）は `runs/v18-baselines/` の値をそのまま使う
- **出力**: run の `posthoc_jepa/`（V18 と同じファイルに、符号ごとの行が増える）、`posthoc_diag/`（`h_pool`・`h_flat`）、Imagenette は `runs/v18b-imagenette/`。物差しは `runs/v18b-baselines/posthoc_jepa/`

### 実装のテスト（理論のオラクル、V18 のテストに足すもの）

- **マスクの写像**: 族 $F_k$ のすべての要素で、(1) 広げたマスクがちょうど $16k$ 個を隠す、(2) 粗いマスクを 16 画素に、広げたマスクを 4 画素に拡大した 64×64 の画素のマスクがちょうど一致する、(3) 族の上で数えた各細かい位置を覆う数が $k|F_k|/16$。$s$ = 1 では恒等になる。同じ生成器から引くと、パッチ 4 と 16 で、広げた後の画素のマスクが step ごとに一致する。`mask_index` が `(B, 256 - 16k)` と `(B, 16k)` を返す
- **文脈側**: パッチ 4 でも、隠した位置の画素を変えても文脈側の出力が変わらない（V18 と同じテストをパッチ 4 で）
- **SIGReg のデータ点**: `mean` で、$S$ が $\bar z$ の SIGReg に一致する。stack の中で一定の $z$（$\bar z \sim N(0, I)$）の $S$ が、健全な $N(0, I_{64})$ の値と同じ分布になる（上の表の 1.06、モンテカルロの誤差の中）。$\partial S / \partial z_{n,p}$ が $p$ によらない（autograd で、全位置で一致）。`flat` で $d$ = 4・$T$ = 256 の stack の中で一定の解が 8.4 前後（上の表）
- **既定の値で V18 と同じ**: `--patch` を省き、$d$ = 64・`flat` で、小さな設定の 2 step の損失と勾配が、変更前の関数で計算した値と一致する
- **初期値**: パッチ 4 の F と M のエンコーダの重みがちょうど一致する
- **activation checkpointing**: 小さな設定で、`--checkpoint-blocks` の有無で損失と全パラメータの勾配が一致する（同じ演算を計算し直すだけなので、CPU で完全に一致する）
- **評価**: `h_pool` が、手で計算した 4×4 のブロックの平均と一致する。`zpca` が、当てはめの組の PCA を通したものと一致する。`drift` が、step 0 で 0、重みに既知の摂動を足すと手計算の値になる。`token_r2` の一括の計算が、組ごとに解いた値と一致する

### 実行

- **試し**（std-00 の 4090。パッチ 4 の run は 5070 Ti の 16 GB に載らない見込みで、時間の予算も 4090 の時間で書くため）: F と M を $r$ = 0.25（文脈が最も多く、最も重い）・学習率 $10^{-4}$・$\lambda$ = 0.5 で 200 step ずつ回し、40〜200 step の平均の秒 / step（$t_F$、$t_M$）と `max_mem` を測る。`max_mem` が 22 GB を超えるか、メモリ不足で落ちたら、`--checkpoint-blocks` で回し直して測り直す。F の試しの run に `jepa_eval --probe-steps 200` をかけ、評価の時間を測る。mini-00 は、`--checkpoint-blocks` つきで 100 step 走るかを見る煙の試しにだけ使ってよい（共有のホストなので、他のコンテナとシステムには触れない）

### 共通 1: Zurich の格子と候補（G・E1・E1g・E2 で同じ）

- **格子**: `jepa_diag.ZurichGrid`（最初のフレームが 10 フレーム = 1 秒おきの stack）。Zurich は 38996 フレームなので、格子は $G$ = 3899 個になる（実装で数えて `config.json` に書く）
- **候補**: $n$ = `N_CAND` = 512 個。候補 $i$ は格子の $c_i = \lfloor i (G - 1) / (n - 1) \rfloor$ 番目の stack で、隣との間隔は 7 か 8 秒になる
- **数と間隔の理由**: (1) 偶然の値は $1/512$ = 0.2% で、正解率 0.5 での標準誤差は $\sqrt{0.25/512}$ = 0.022 になる。符号どうしは同じ候補・同じ雑音で比べるので、差の標準誤差（対の標準誤差、下）はさらに小さい。(2) V18 の診断で、Zurich の 1 秒おきの stack は強く相関していた。7〜8 秒の間隔は stack の幅 0.8 秒よりずっと長く、歩いて 10 m ほど進む。1024 個（約 3.8 秒おき）にすると、ほとんど同じ景色の隣の組が倍になる。128 個（約 30 秒おき）では標準誤差が 0.044 に広がる。(3) 近い候補との取り違えは `top1_adj` と `real_shift`（下）で見る
- **難しい候補（`id_hard`）**: 候補 $i$ に、同じ動画の前後 ±2〜±32 秒（2 秒おき、$c_i + 2m$、$m = \pm 1, \dots, \pm 16$）の格子の 32 個を足した 33 個の中から当てる。偶然の値は 1/33。場面・天気・照明は候補どうしで共通なので、「同じ街角」だけでは当たらない。$c_i < 32$ か $c_i > G - 33$ の候補（両端の約 9 個）は `id_hard` から外し、数を `n_hard` に書く
- 学習の動画は Zurich を含まないので、候補は学習に使っていない。G は Zurich で何も当てはめないので、val や calib の窓と重なってもかまわない
- E1・E1e・E2 の ridge は、$\alpha$ を Zurich の calib の窓で選ぶので、calib の stack が候補と同じか 1 秒以内に重なりうる。重なりは除かない。理由: calib から決まるのは、`linear_dyn.ALPHA_SCALES` の 9 つの尺度から選ぶ 1 つのスカラーだけで（当てはめそのものは学習の動画の組）、9 つから 1 つを選ぶことで候補の採点に持ち込める情報は $\log_2 9 \approx 3.2$ ビットにとどまる。E1 の `oracle`・`pred`・`mean`・`shuf` は同じ $g_U$（同じ $\alpha$）を通るので、段どうしの差には共通に入る。E1e・E2 の符号どうしの比べでは、符号ごとに $\alpha$ を選ぶので漏れは打ち消し合わないが、どの符号も同じ 9 つから同じ規則で選ぶので、大きさは同じ程度とみる

### 共通 2: 外部の特徴（`exp/lib/inception.py`）

### 共通 3: 同定の採点（`exp/lib/metrics.py`）

- **`identification(pred, real, *, center, among=None, ks=(1, 5))`**: 問い $i$ の特徴 $g_i$（$K$ 枚あれば $g_{ij}$）と、候補 $l$ の本物の特徴 $r_l$ を、どちらも `center` を引いてから $\cos$ で比べる。`top1` = $\frac{1}{nK} \sum_{i,j} [\arg\max_l \cos(g_{ij}, r_l) = i]$、`top5` は上位 5 個に $i$ が入る割合。`hits` は候補ごとの $h_i = \frac1K \sum_j [\arg\max_l \cos(g_{ij}, r_l) = i]$。`among` を渡すと、問い $i$ の候補を `among[i]`（`id_hard` の 33 個）に限る。`top1_adj` は、外れたうちで選ばれた $l$ が隣の候補（$\lvert l - i \rvert = 1$）だった割合
- **中心を引く理由**: pool3 の特徴は負でなく、共通の大きな平均を持つので、生の $\cos$ は主にその平均の向きを測る。G では FID の参照の組 $R$（Zurich の 4096 枚、下）の平均を引く。E1・E1e・E2・E1g の的は当てはめの組（学習の動画）の平均で中心化してあるが、同じ理由で、採点では Zurich の格子の全 stack の的の平均を引く（`fill_eval.score`）。学習の動画と Zurich のずれはすべての候補に共通の向きで、0 を中心にすると、その向きが $\cos$ を支配し、ずれに沿う候補に当たりが集まる（hub）。その偏りは符号ごとに違いうる。`swap`（下）も的の側は Zurich の格子の平均を引いたものを使う
- **同点**: 自分と同じだけ近い別の候補は、自分より前に並べる（同点は外れ）。中心にある予測（向きがない）はどの候補も当てない。以前は同点を `among` の先頭（いつも自分）に倒していたので、中心にある予測の `id_hard` が 1 になった
- **対の標準誤差**: 2 つの結果 A・B の差の標準誤差は $\mathrm{SE}_{\mathrm{pair}} = \mathrm{sd}_i(h^A_i - h^B_i)/\sqrt{n}$、1 つの結果の標準誤差は $\mathrm{sd}_i(h_i)/\sqrt{n}$（`top1_se`）。どの行にも `hits` を書き、集計で計算する
- **`identification` の `pick_max`**: $nK$ 個の選択 $\hat l_{ij}$ のうち、1 つの候補に集まった割合の最大（`among` なし）。すべての候補が同じだけ選ばれれば $1/n$。生成した特徴に符号ごとの共通のずれ $b$ があると、$\arg\max_l$ に $b \cdot r_l$ の項が加わり、$b$ に沿う候補に当たりが集まる（hub）。その偏りは符号（デコーダ）ごとに違いうるので、`top1` を読むときに `pick_max` で見分ける。G の行は `pick_max`、E1・E1e・E2・E1g の行は `pick_max_easy`
- **`swap(own, other, real)`**: 行ごとに $(a_i - b_i) \cdot t_i > 0$ なら 1、0 なら 1/2、負なら 0 の平均（E1 の 2 択。3 つとも呼び出し側で中心化したものを渡す）。候補ごとの値も返す。$a_i = b_i$ なら引き分けでちょうど 1/2。$a_i - b_i$ が $t_i$ と独立で 0 について対称なら、$a$ と $b$ の大きさによらず期待値は 1/2（$\cos$ や距離で比べると、雑音の小さい方が選ばれてしまう）

### G: 生成で測る

**1 つの符号の評価の流れ**

1. 符号 $c(x)$ を決める（checkpoint と `z`・`z_w` の組、または物差し）
2. 学習の組（131072 個の stack、すべての符号で同じ）の符号と最後のフレームを作る
3. 符号を条件にした flow matching のデコーダを posthoc に BP で学ぶ
4. 512 個の候補の各符号から 8 枚ずつ生成する
5. 生成と本物の Inception の特徴から、同定の正解率・FID・対の特徴の距離を出す
6. 絵を書き、デコーダの重みを保存する（E1g が使う）

デコーダの初期値・学習の組・batch の引き方・$t$・雑音・サンプルの雑音は、すべての符号で同じ seed から作る（共通の乱数）。符号のあいだの差にはデコーダの乱数の差が入らない。

**符号**

| 名前 | 中身 | 次元 |
| -- | -- | -- |
| `z` | 今までの評価の符号。P16（V18）と F は射影の後の平らな $z$（`JEPAModules.mu`）、M は `zpca`（V18b と同じ） | 1024 |
| `z_w` | $z_W = W \cdot \mathrm{vec}(h)$。$h$ はエンコーダの最後の `LayerNorm` の後のトークン `(B, T, w)`、$\mathrm{vec}$ は位置を行優先で平らにしたもの（`h_flat` と同じ並び）。エンコーダの出力の固定のランダム写像という物差しで、案 B の学習の $z$ とは別の符号 | 1024 |
| 物差し | `color`（384）、`pca`（1024）、`v16`・`v17`（$\mu$、256）、`init_m`（M の step 0 の `zpca`、1024）、`uncond`（条件なし） | 表のとおり |

- **$W$**（`exp/lib/randproj.py` の `gaussian_projection(d_out, d_in, seed)`）: CPU の `torch.Generator().manual_seed(seed)` で `torch.randn(d_out, d_in)`（float32）を一度に引き、$1/\sqrt{d_{\mathrm{in}}}$ を掛ける。seed は `W_SEED` = 61 で、run の seed に足さない（すべての run で同じ $W$）。$d_{\mathrm{in}} = T w$ は P16 で 16384（$W$ は 64 MB）、F と M で 262144（1 GB、CPU で数秒）。$W$ は GPU に置き、batch ごとに `vec(h) @ W.T` を 1 回で掛ける（batch 128 で $\mathrm{vec}(h)$ は 134 MB、積は 1 stack あたり 0.54 GFLOP で、エンコーダの前向き（F で約 26 GFLOP）より軽い）。GPU のメモリが足りなければ、列を `W_CHUNK` = 32768 ずつに分けて部分和をとる。分けると和の順が変わるので、使うかどうかはすべての符号で同じにする
- $z_W$ の座標の分散は $\lVert \mathrm{vec}(h) \rVert^2 / (T w)$、つまり $h$ の 2 乗の平均で、`LayerNorm` の後なら 1 程度である。デコーダの前で標準化するので、尺度は結果に効かない
- **学習の側と同じ関数を使うが、符号は同じではない。** 学習の側（案 B、worktree の commit fa2bf4c）は$R$ = `gaussian_projection(16, 1024, R_SEED = 67)`、$W$ = `gaussian_projection(1024, 16 T, W_SEED = 61)`（パッチ 8 で 1024 × 1024）で $z = W \cdot \mathrm{vec}(R h)$ を作る。旧 checkpoint の `z_w` の $W$ は 1024 × $T w$ で、$R$ を通さない。$R$ は各トークンを 16 次元の部分空間に落とすので、案 B の $z$ は $W \cdot \mathrm{vec}(h)$ より情報が少ない。したがって、旧 checkpoint の `z_w` を「新しい設計と同じ写像」として V18c の $z$ と並べない。`z_w` は「エンコーダの出力の固定のランダム写像」という別の物差しとして読む。案 B と同じ形の符号（例 `z_wr` = $W \cdot \mathrm{vec}(R h)$）を旧 checkpoint に足すかは、未決定（下の「未決定」）
- **定数の置き場所（合流のとき）**: 学習の側は `W_SEED`・`R_SEED`・`LATENT_DIM` を `exp/vision/jepa.py` に、評価の側は `W_DIM`・`W_SEED`・`W_CHUNK` を `exp/vision/jepa_eval.py` に置いた。合流では$W$ の定義を 1 つにするため、`W_SEED` は学習の側の `jepa.py` に寄せ、`jepa_eval.py` はそれを import する（`W_DIM` は `LATENT_DIM` と同じ 1024 なので `LATENT_DIM` を使う。`W_CHUNK` は評価だけの定数なので `jepa_eval.py` に残す）。`jepa_eval.py` の `CODES`・`ARM_CODES`・import と `jepa_diag.py` の `IMAGENETTE_POOLS` は、両方の変更を足し合わせる
- **M の `z_w` と F の `z_w` の step 0 はちょうど一致する。** F と M のエンコーダの初期値は一致し（V18b のテスト）、$z_W$ は射影 $P$ によらないからである。M の `zpca` の step 0 は F と違うので、物差しに `init_m` を足した
- `init` と `init_f` は、V18 の seed 0 と F の seed 0 の step 0 の行をそのまま使う（V18 の 18 本はすべて同じ初期値）。seed 1 の step 0 も同じ評価にかける
- `uncond` はすべての入力で 0 の 1024 次元の符号（標準化を通さない）。同じネット・同じ step 数で学ぶ。同定の偶然の値と、FID の基準になる
- `pca` と `zpca` の PCA は、V18 と同じく probe の当てはめの組の stack で当てはめる（`StreamEvaluator.fit_stacks`、`SPAN` = 6000 秒、seed + `eval.PCA_SEED`）

**学習の組（すべての符号で同じ）**

- **区間**: 学習の動画すべて（`iid.Units(conf, root, "all", seed=GEN_DATA_SEED)`、Zurich を除く 479350 個の単位）から、一様に重複を許して 131072（$2^{17}$）個の stack を引く（`Units.draw`）。`GEN_DATA_SEED` = 53 は run の seed に足さないので、どの run・どの符号でも同じ stack になる（テストで確かめる）
- JEPA の run も `all` から i.i.d. に学んだので、この組はエンコーダにとって学習の分布の中の stack である。測るのは学習に使わない Zurich への一般化である
- V16〜V18 の probe の当てはめの組（span の奇数の区間、約 6000 組）は使わない。拡散のデコーダには少なすぎ、符号と画像の対を覚えてしまうためである
- **対象**: stack の最後のフレーム（8 枚目）u8 `(3, 64, 64)` を $x_1 = 2 \cdot x/255 - 1$ にする
- **符号**: 止めた符号で、`no_grad` のまま `BATCH` ずつ一度だけ計算する。131072 × 1024 の float32 で 0.5 GB（GPU に置く）。最後のフレームは u8 で 1.6 GB（CPU に置き、batch ごとに GPU に送る）
- **標準化**: `eval.Standardizer`（成分ごとの平均を引き、全成分で 1 つの尺度で割る）を学習の組の符号で当てはめ、候補にも同じものを使う

**デコーダ（`exp/lib/flow_decoder.py`）**

目的（rectified flow）: $x_0 \sim N(0, I)$（雑音）、$x_1$（データ）、$t \sim U(0, 1)$、$x_t = (1 - t) x_0 + t x_1$ として

$$
L = \mathbb{E}\, \frac{1}{3 \cdot 64^2} \lVert v_\theta(x_t, t, c) - (x_1 - x_0) \rVert^2
$$

ネット: 64×64 の小さな U-Net（ADM の形を小さくしたもの）。

- 解像度 64・32・16・8 で、チャネルは 32・64・128・256。下りは各解像度に `ResBlock` 2 つ、中央は 8×8 で `ResBlock`・注意・`ResBlock`、上りは各解像度に `ResBlock` 3 つ（下りの出力を連結する）。注意は 16×16 と 8×8 と中央（head の次元 32）。下りは stride 2 の 3×3 の畳み込み、上りは最近傍の 2 倍の拡大と 3×3 の畳み込み。入口は 3 → 32 の 3×3、出口は `GroupNorm`・SiLU・32 → 3 の 3×3
- `ResBlock`: $h = \mathrm{conv}(\mathrm{SiLU}(\mathrm{GN}(x)))$、$h = \mathrm{GN}(h) (1 + \gamma) + \beta$、$h = \mathrm{conv}(\mathrm{SiLU}(h))$、出力は $h$ + skip（チャネルが変わるときは 1×1）。`GroupNorm` は 32 群（チャネルが 32 未満の所はない）。dropout はない
- **条件（FiLM）**: 時刻は $1000 t$ の正弦波の埋め込み 128 次元 → `Linear(128, 512)` → SiLU → `Linear(512, 512)`。符号は標準化した $c$ → `Linear(D, 512)` → SiLU → `Linear(512, 512)`。2 つの和 $e$ から、各 `ResBlock` が `Linear(SiLU(e))` で $(\gamma, \beta)$（$2 \times$ 出力チャネル）を作る。符号の次元 $D$ で入口の行列だけが変わる（1024 で 52 万個、256 で 13 万個）。ほかは全部の符号で同じ
- **大きさ**: この形をそのまま書いた試作（scratch、2026-11-24）で数えると、$D$ = 1024 で 1952 万個のパラメータ、1 枚の前向きは 6.0 GFLOP（3.0 GMAC）だった。実装で数えて `config.json` に書く
- 初期値は PyTorch の既定のまま。EMA・classifier-free guidance・条件の dropout・時刻の重みづけ（logit-normal など）は入れない

学習: batch 128、AdamW（学習率 $2 \cdot 10^{-4}$、betas (0.9, 0.999)、eps $10^{-8}$、weight decay 0）、500 step の線形の warmup のあと 0 までの cosine、勾配のクリップなし。step 数 `FIT_STEPS` は仮に 10000 とし、試しの実測で決める（下の「実行」）。float32 で、`configure_determinism` の下（TF32 なし）で回す。bf16 は使わない。

- 見込み: 前向きと逆向きで 1 枚約 18 GFLOP、batch 128 で 1 step 約 2.3 TFLOP。4090 の float32 で実効 25 TFLOPS なら約 0.09 秒 / step、10000 step で約 15 分
- 乱数: デコーダ $j$（既定は 0 だけ）の初期値・batch の引き方・$t$・雑音は、`DEC_SEED` + 1000 $j$ の生成器から引く。`DEC_SEED` = 67 は run の seed に足さない
- ログ: 200 step ごとの損失の平均を `fit/<step>-<code>-d<j>.jsonl` に書く

**サンプル**

- Euler 法、`SAMPLE_STEPS` = 100、$t_k = k/100$、$x_{k+1} = x_k + \frac{1}{100} v_\theta(x_k, t_k, c)$
- 初期の雑音は`SAMPLE_SEED` = 71 の生成器から `(512, 8, 3, 64, 64)` を一度だけ引く。候補 $i$ のサンプル $j$ の雑音は、すべての符号で同じ
- 最後に $[-1, 1]$ に切り、$\mathrm{round}((x + 1)/2 \cdot 255)$ で u8 にする。本物のフレームと同じ u8 の経路で Inception に入れる
- 4096 枚 × 100 step × 6.0 GFLOP は約 2.5 PFLOP で、4090 で約 2 分

**同定の正解率**: 候補 $i$ のサンプル $j$ の特徴 $g_{ij}$ で、512 個の候補の本物の最後のフレームの特徴 $r_l$ から当てる（`identification`、`center` は $R$ の平均、$K$ = 8）。`top1`・`top5`・`top1_se`・`top1_adj`・`hits` を出す。偶然の値は `top1` が $1/512$、`top5` が $5/512$。`id_hard`（候補を前後の格子に限ったもの）も同じ $g_{ij}$ で出す。

**本物どうしの参照**（デコーダなし、`refs` で 1 回だけ）

- `real_shift`: 生成の代わりに、各候補の 1 秒後の stack（格子の $c_i + 1$）の本物の最後のフレームの特徴で同定したときの `top1`・`top5`。1 秒の景色の変化に対して、候補がどれだけ見分けられるかの目安
- `fid_cand`: 512 個の候補の本物の最後のフレームと $R$ の FID（生成の `fid` と同じ 512 枚の推定量。符号が完全に情報を持ち、デコーダが本物を描くときの `fid` の値で、下限の目安）。以前の `fid_real`（$R$ と、それを 4 フレームずらした組）はほとんど同じ画像の組どうしなので 0 に近く、何の下限も示さないので外した
- `fid_train`: 学習の組の 4096 個の最後のフレームを 512 個ずつ 8 組に分け、各組と $R$ の FID を平均したもの（`fid_train_j` も書く）。学習の動画と Zurich のずれの目安で、学習の分布を完全に写す条件なしのデコーダの `fid` は、この程度になる

**FID**: サンプル $j$（$K$ = 8 個）ごとに、512 枚（各候補 1 枚）と参照の組 $R$ の FID をとり（`fid_j`）、$j$ で平均する（`fid`）。$R$ は Zurich の最後のフレーム 4096 枚（最初のフレームが $\lfloor i (F - 8)/4095 \rfloor$、$F$ = 38996、約 9.5 フレームおき）で、どの符号でも同じ $R$ を使う。4096 枚をまとめて $R$ と比べない理由: 符号が情報を持つほど同じ候補の 8 枚が似てくるので、実質の標本数が 512 に近づく。FID の有限標本の偏り（およそ $1/N$）はそのぶん大きくなり、情報を持つ符号ほど FID が悪く出て、符号どうしの順位が入れ替わりうる（d = 512 のガウスの例で、独立な 4096 個は 19.4、512 個を 8 回ずつ繰り返すと 96.0）。サンプルごとなら、どの符号でも 512 個の別々の候補の 512 枚になる。`fid` は `fid_cand`（下限の目安）と `fid_train`（ドメインのずれの目安）の間で読む。$\mathrm{FID} = \lVert \mu_1 - \mu_2 \rVert^2 + \mathrm{tr}(\Sigma_1 + \Sigma_2 - 2 (\Sigma_1 \Sigma_2)^{1/2})$ を float64 で計算する。$\mathrm{tr}(\Sigma_1 \Sigma_2)^{1/2}$ は対称な $\Sigma_1^{1/2} \Sigma_2 \Sigma_1^{1/2}$ の固有値（負は 0 に切る）の平方根の和で求める（scipy を使わない）。**64 px を拡大した 4096 枚の FID は偏りが大きいので、文献の値とは比べず、この表の符号どうしの比較にだけ使う。**

**対の特徴の距離**: `feat_dist` = $\frac{1}{nK} \sum_{i,j} \lVert g_{ij} - r_i \rVert^2$、`feat_ratio` = `feat_dist` / $\frac{1}{n(n-1)} \sum_{i \ne l} \lVert r_i - r_l \rVert^2$（0 なら本物と同じ特徴、1 なら別の候補の本物と同じくらい遠い）。候補ごとの値 `feat_i` も行に書く（対の標準誤差のため）。

**条件つきの損失**: `fm_zurich` は、512 個の候補の最後のフレームで、固定した $t_m = (m + 0.5)/16$（16 点）と固定した雑音（`FM_SEED` = 73）での $L$。条件なしとの差は $I(x; z)$ の推定（PLAN の 2）に関わるが、並べるだけにする。

**G の出力**

- run の `posthoc_gen/` に書く。1 つの job（checkpoint・符号・デコーダの seed の組）は `rows/<step>-<code>-d<j>.json` に 1 行を書く。別々のホストの job が同じ jsonl に追記しないようにするためで、同じ名前のファイルがあればその job は何もしない（やり直しは消してから）
- 行の項目: `t`、`step`、`code`、`dim`、`dec_seed`、`fit_steps`、`fit_batch`、`fit_loss`（最後の 1000 step の平均）、`fm_zurich`、`top1`、`top5`、`top1_se`、`top1_adj`、`pick_max`、`hits`（512 個）、`hard_top1`・`hard_hits`、`feat_dist`、`feat_ratio`、`feat_i`（512 個）、`fid`・`fid_j`、`sec_encode`、`sec_fit`、`sec_sample`、`max_mem`、`key`
- `config.json`: 定数のすべて、Inception の重みの sha256、`W_SEED`・`W_DIM`・`W_CHUNK`、データの設定（`conf.data.tours`。学習の組・格子・候補はこれで決まり、run の符号と物差しが同じ学習の組を使うことはこの一致に頼るので `key` に入れる）、PCA の seed（`conf.seed` + `PCA_SEED`）と `pca` の成分の数・`zpca` の次元、候補の $c_i$、パラメータの数（job が出会った符号の次元すべて。物差しは 1 符号ずつ回るので、後の job が新しい次元を足す）、`configure_determinism` と `of_diagnosis` の記録、`key`（行が依存する設定の sha256 の先頭 12 桁。Inception は重みのパスでなく sha256 で入れる）
- **設定の照合**: 出力先の `config.json` か行の `key` が今の設定と違えば、job は止まる（黙って再利用しない）。行がすべてあって job を飛ばすときも、先に `config.json` を照合する。Inception は sha256 だけで照合する（重みのパスはホストで違う）。`config.json` の Inception の記録には torchvision の版も書く。試しのように別の設定で回すときは、`--out-name`（既定は `posthoc_gen`）で出力先を分ける。`fill_eval` の `config.json` も、行が依存する設定（`FillConf`、的のキャッシュの `<hash>`、seed、候補）が違えば止まる
- 絵 `<step>-<code>-d<j>.png`: 512 個から 32 個おきの 16 個の候補を行にし、列は本物の最後のフレーム、サンプル 4 枚、8 枚の平均、8 枚の画素ごとの標準偏差（4 倍して表示）
- デコーダの重み `ckpt/dec-<step>-<code>-d<j>.pt`（約 80 MB、E1g が読む）。`ckpt` の下なので `just fleet pull` は持ってこない
- 物差しは `runs/v18c-gen/yardsticks/posthoc_gen/`（行の `code` に名前）。本物どうしの参照は同じ場所の `refs.json`

### 未観測の部分: 評価のマスクと領域（`exp/lib/regions.py`）

**評価のマスク**は、粗い 4×4 の格子の上で決める。行 $a$・列 $b$（0〜3、行優先で位置 $4a + b$）とする。

| 名前 | 隠す粗いマス | $k$ | 画素（64×64 の最後のフレーム） | 族 |
| -- | -- | -- | -- | -- |
| `Q_tl`・`Q_tr`・`Q_bl`・`Q_br` | 四半分の 2×2（例 `Q_tl` は $a, b \in \{0, 1\}$） | 4 | 32×32 | $F_4$ の矩形 1 つ |
| `H_l`・`H_r`・`H_t`・`H_b` | 半分（例 `H_l` は $b \in \{0, 1\}$） | 8 | 64×32 か 32×64 | $F_8$ の矩形 1 つ |
| `R` | 外周（中央の $a, b \in \{1, 2\}$ だけを見せる） | 12 | 幅 16 の枠 | $F_{12}$（トーラスの上で、行 $\{3, 0\}$ × 全列の 2×4 と、行 $\{1, 2\}$ × 列 $\{3, 0\}$ の 2×2 の和） |
| `S_1` = `Q_tl` ∪ `Q_br`、`S_2` = `Q_tr` ∪ `Q_bl` | 対角の 2 つの四半分 | 8 | 32×32 が 2 つ | $F_8$ の矩形 2 つの和 |

- 粗いマスクを `jepa.expand_masks(mask, s)`（$s$ = grid / 4）で広げれば、パッチ 16・8・4 で画素の領域がまったく同じになる（V18b の写像のテストと同じ理由）
- **族に入ること**（Fable さんは導いただけなので、テストで確かめる）: 9 つの評価のマスクと `S_1`・`S_2` が、それぞれ `jepa.mask_family(k, 4)` の行に含まれること
- **分布の中と外**: run のマスク率の $k$ と同じ $k$ のマスクを「分布の中」とし、行に `in_dist` を書く。V18 と V18b の $r$ = 0.25 の run では `Q` が中、`H`・`R`・`S` は外。V18 の $r$ = 0.5 の run では `H` と `S`、0.75 では `R` が中。判定は分布の中のマスクで読み、外のマスクは「分布の外」と明記して並べる。例外は `swap` の 1 つだけで、README の条件 1 が $r$ = 0.25 の run でも分布の外の `S` の `swap` を使う（理由は README）
- **領域の画像**（`region_image(frame, mask)`）: 領域の画素の外接矩形を切り出し、矩形の中で領域に入らない画素を灰色（u8 の 128）で埋める。`Q`・`H` は矩形そのもの（埋める画素はない）、`R` は 64×64 で中央の 32×32 が灰色になる。見える部分 $V$ の画像も同じ規則で作る（`Q` の $V$ は 64×64 で隠した四半分が灰色、`H` の $V$ は残りの半分、`R` の $V$ は中央の 32×32）
- **調和補間**（`harmonic_fill(frame, mask)`、対照 `interp`）: 最後のフレームの隠した画素 $U$ を、見える画素を境界の値にした離散のラプラス方程式の解で埋める。4 近傍のグラフのラプラシアン $L$（画像の端は存在する近傍だけをとる。Neumann の条件にあたる）について $x_U = -L_{UU}^{-1} L_{UV} x_V$。行列 $-L_{UU}^{-1} L_{UV}$（`R` で 3072 × 1024）はマスクごとに 1 回だけ float64 で作り、画像には行列の積で掛ける（反復しないので、収束の判断が要らない）

### 未観測の部分: 的（checkpoint によらないので 1 回だけ作ってキャッシュする）

- **`incep`**: 領域の画像（上の規則）を Inception に通した pool3 の 2048 次元を、領域ごとに、当てはめの組で PCA（`pca.fit_pca`、256 成分、`TARGET_PCA_SEED` = 79）にかけ、当てはめの組の平均を引いて、全成分で 1 つの尺度（`Standardizer` と同じく、成分の標準偏差の 2 乗平均の平方根）で割る
  - 画像の全体を入れた特徴マップの 1 マスを的にしない。Inception の最後の層の受容野は画像のほぼ全体なので、隠した位置のマスにも見える部分の情報が入る（Fable さんの導出）
- **`color`**: 領域の最後のフレームの、8×8 画素のブロックごとの平均の色（`Q` で 16 ブロック × 3 = 48 次元、`H` で 96、`R` で 144、E2 の帯で 72、外側だけの帯で 48）。`incep` と同じく中心化し、1 つの尺度で割る
- 2 つの的を並べるのは、32×32 を 9 倍に拡大した Inception の特徴が、主に色と質感を表すと思われるからである（Fable さんの推測）
- **組**（すべて `jepa_eval` と同じ conf・`SPAN` = 6000 秒）
  - 当てはめ: `StreamEvaluator.fit_stacks`（span の奇数の区間の約 6000 個）
  - $\alpha$ の選択: `StreamEvaluator.zurich_calib_stacks`（Zurich の calib の 1024 窓の最初の stack）
  - 評価: Zurich の格子の全 stack（$G$ = 3899）。512 個の候補と `id_hard` の候補はその部分集合
- **キャッシュ**（`fill_eval targets`）: 9 つのマスクの領域（`S` の四半分は `Q` と同じ）の $U$ と $V$ の `incep`・`color`、`interp` の `incep`・`color`、E2 の帯（下）のもの。Inception に通す画像は約 40 万枚（4090 で 10 分以内の見込み）。保存するのは PCA の後の 256 次元と、PCA の平均・成分・尺度（E1g が生成した画像を同じ空間に写すため）。置き場所は `$MUJOU_EXP_DATA/v18c-targets-<hash>/`（`<hash>` は設定と組の stack の番号の sha256 の先頭 12 桁）で、NAS の `/nas/geson/mujou-exp/cache/` に写しを置く。`targets.json` に組の番号・Inception の sha256・seed を書き、読むときに conf と照らし合わせる

### 未観測の部分: 読み出し（`exp/lib/readout.py`）

- **ridge**: $X$（当てはめの組の入力、$n \times D$）と $Y$（的、$n \times 256$）をそれぞれ当てはめの組の平均で中心化し、$B = (X^\top X + \alpha I)^{-1} X^\top Y$ を float64 で解く。$\alpha = c \cdot \mathrm{tr}(X^\top X)/D$、$c$ は `linear_dyn.ALPHA_SCALES`（$10^{-8}$〜1）
- **$\alpha$ の選び方**: calib の `r2`（下）が最大の $c$（同点なら最初のもの）。**E1 では全体を見たトークン（`oracle` の入力）だけで選ぶ。** 予測器の出力は当てはめにも $\alpha$ の選択にも使わない
- **入力の次元**: $D$ が 1024 を超えたら、当てはめの組で PCA（`pca.fit_pca`、1024 成分、`READOUT_PCA_SEED` = 83）にかけてから ridge に通す。同じ PCA を同じ読み出しに通すすべての段に使う
- **採点**（評価は 512 個の候補）
  - `r2`: 的の座標ごとの $R^2 = 1 - \sum_i (\hat y_{ik} - y_{ik})^2 / \sum_i (y_{ik} - \bar y_k)^2$ の、256 座標の平均（$\bar y$ は候補の平均）
  - `id_easy`: `identification(ŷ, y)`（候補 512 個、偶然 1/512）
  - `id_hard`: `identification(ŷ, y, among=…)`（前後の格子の 33 個、偶然 1/33）
  - `swap`: 下の E1 の 2 択
- Fable さんの案では `id_easy` の候補を 64 個にしていたが、G と同じ 512 個にした。主の指標と同じ候補で読め、偶然の値と標準誤差も小さくなるためである

### E1: 補完の同定（未観測の部分の主）

入力: 候補の stack と評価のマスク。文脈側は見えるトークンだけをエンコーダに通す（`TokenEncoder.forward(images, keep)`）。

- **予測の空間**: V18・V18b の予測器は射影の後の $z_p$ を当てるので、E1 の「トークン」は $z_p$ とする（`JEPAModules.tokens`）。パッチ 8 の学習（案 B、予測の的は $t_p = R h_p$）では $t_p$ とする（`JEPAModules.tokens` が $t_p$ を返す）。領域 $U$ のトークンを位置の昇順に並べて平らにしたもの $z_U$ が読み出しの入力で、P16 と F の `Q` は 256 次元、`H` は 512、`R` は 768（PCA なし）、M の `Q` は 4096 次元（PCA で 1024）になる
- **読み出し $g_U$**: 領域ごと・的ごとに 1 本。入力は**全体を見たとき**（標的側）の $z_U$、出力は $T(U)$。当てはめの組で求めて凍結する
- **4 段と対照**（同じ $g_U$ に通す）
  - `oracle`: 全体を見たときの $z_U$。上限で、エンコーダのトークンがその位置の中身をどれだけ持つかを表す
  - `pred`: 予測器の出力 $\hat z_U$（マスクは $U$ 自身）。**測りたい値**
  - `mean`: 位置ごとの平均のトークン（当てはめの組の $z_U$ の平均）。予測が定数なので、`id_easy` はちょうど偶然の値 1/512 になる（すべての問いが同じ候補を選ぶ）。`id_hard` は問いごとに候補の集合が違うので、定数の予測の向き（Zurich の格子の平均を引いた後の向き）で決まる値になり、1/33 とは限らない。定数の予測の基準として、そのまま `pred` と比べる
  - `shuf`: 別の候補の $\hat z_U$（候補の番号を 256 ずらしたもの）。実装の確かめで、偶然の値に近いはず
  - `interp`: 読み出しを通さず、調和補間で埋めた画像の $T$ をそのまま予測にする。隣の画素の延長で当たる分の目安
- **`swap`**: `S_1` と `S_2` で 2 つの四半分 $A$・$B$ を同時に隠し、$A$ の読み出し $g_A$ が、$A$ の真の特徴を「$A$ の位置の入力」から読むか、「$B$ の位置の入力」から読むかの 2 択にする。段ごとに、$A$ の位置の入力 $x_A$（`pred` なら予測器の出力 $\hat z_A$、`oracle` なら全体を見たトークン、`mean` なら位置ごとの平均のトークン、`shuf` なら 256 ずらした候補の予測）と $B$ の位置の入力 $x_B$（同じく。位置の昇順に平らにすると、同じ形の四半分なので位置が対応する）をどちらも $A$ の PCA（`Reducer`）に通し、候補の平均を引いて $u_A$・$u_B$ とする。$t$ を $A$ の的から Zurich の格子の平均を引いたものとして、$(u_A - u_B) B_A \cdot t > 0$ の割合（`metrics.swap`）をとる。$A$ と $B$ を入れ替えた 2 通り × `S_1`・`S_2` の 4 通りを平均した候補ごとの値を `swap_i` とする。偶然の値は 0.5
  - **導出**: 2 つの位置の入力の差が位置ごとの定数だけの符号（K3 の族 $z_{n,p} = h(x_n) + g(p)$）では $u_A = u_B$ なので、引き分けでちょうど 0.5 になる。四半分どうしの分布が違っても（左上の空と右下の路面）変わらない。`mean` は $u_A = u_B = 0$ なので、どの符号でもちょうど 0.5。入力の差が $t$ と独立な雑音なら、雑音の大きさが位置で違っても期待値は 0.5。0.5 を超えるのは$A$ の位置の入力の候補ごとの動きが、$B$ の位置のものより $A$ の真の特徴の向きに沿うときだけである。`oracle` の同じ 2 択が上限（空と空のように本当に似た組があるので 1 にはならない）。2 つ隠すので $k$ = 8 で、$r$ = 0.5 の run では分布の中、$r$ = 0.25 の run では分布の外になる
  - **はじめの定義を改めた理由**（2026-11-24、実行の前。レビューの指摘）: はじめは$g_A(\hat z_A)$ が $A$ の本物の特徴 $T_A(A)$ と、$B$ の本物の画像を $A$ の PCA と尺度で写した $T_A(B)$ のどちらに $\cos$（中心を引かない）で近いかをとっていた（Fable さんの案）。しかし $T_A(B)$ には平均のずれ $\mu_B - \mu_A$ がそのまま残るので、四半分の分布が違うと、場面だけを表す符号でも $A$ を選べる（合成の数値実験で、場面だけの符号が 1.0、交換可能にした組で 0.46）。Fable さんの「場面や時刻だけを表す符号はちょうど 0.5」は$A$ と $B$ が交換可能なときにしか成り立たない。また `mean` の予測は当てはめの組の的の平均（中心化の後なので丸め誤差だけの $10^{-9}$ 程度のベクトル）になり、中心を引かない $\cos$ ではその向きで値が決まっていた（同じ実験で 0.407）。比べる側を的から入力に移すと、K3 の族と `mean` が定義からちょうど 0.5 になる。$\cos$ でなく内積の符号にしたのは、$\cos$ では雑音の小さい位置の方が選ばれるからである（同じ実験で、場面に、位置ごとに大きさの違う無関係な雑音を足した符号が $\cos$ で 0.618、内積で 0.485）。予測の位置ごとの偏り（予測器の出力の平均が位置で違う分）も候補の平均を引くことで除く
- **まとめ**: $\mathrm{gain} = (\texttt{pred} - \texttt{mean}) / (\texttt{oracle} - \texttt{mean})$ を `r2`・`id_easy`・`id_hard`・`swap` のそれぞれで出す。マスクの種類（`Q` の 4 つ、`H` の 4 つ）は平均した行も書く

### E1e: エンコーダだけの版

- 入力: 文脈側のトークン $h_V$（エンコーダの出力、幅 1024、見える位置の昇順に平らにしたもの）をマスクごとに当てはめの組で PCA 1024 にしてから、$T(U)$ への ridge を当てはめる（$\alpha$ は calib でその符号自身で選ぶ）。P16 の `Q` は 12288 次元、F の `Q` は 196608 次元（当てはめの組で 4.7 GB。4090 に載る）
- 物差し（同じ読み出し）: `init`（同じ run の step 0 の $h_V$）、`color_V`（見える粗いマスの、8 枚 × 3 チャネルの平均の色。V18 の `color` の見える位置、`Q` で 288 次元）、`pca_V`（隠した画素を 0 にした stack の画素の PCA 1024、マスクごとに当てはめの組で求める）、`ext`（見える部分の的 $T(V)$、`incep` の的なら `incep`、`color` なら `color` から $T(U)$ への ridge）
- 1.1 節（Fable さんの報告）のとおり、見える部分の画素が情報の上限なので、物差しとの差だけを読む

### E1g: 仮想の $z$ を拡散のデコーダへ

- G で学んだ、全体の `z` を条件にしたデコーダ（`ckpt/dec-<step>-z-d0.pt`）に、隠した位置を埋めた $\hat z$ をそのまま入れる。デコーダの学習は増えない
- 段: `full`（全部が標的側の $z_p$。G のサンプル 0 と同じ）、`oracle`（見える位置は文脈側の $z_p^{\mathrm{ctx}} = P h_p^{\mathrm{ctx}}$、隠した位置は標的側）、`pred`（見える位置は文脈側、隠した位置は予測器の出力）、`mean`（見える位置は文脈側、隠した位置は位置ごとの平均）。M は埋めた 16384 次元を G と同じ PCA で `zpca` にしてから入れる
- `z_w` の E1g は、V18・V18b の checkpoint では作れない（予測器が $h_p$ ではなく $z_p$ を当てるため）。パッチ 8 の学習（案 B）では隠した位置を予測 $\hat t_p$ で埋めた $\tilde t$ から $\hat z = W \cdot \mathrm{vec}(\tilde t)$ で作れる
- マスクは 9 つすべて、各候補 1 枚（雑音は G のサンプル 0 と同じ）。512 × (1 + 9 × 3) = 14336 枚で、4090 で約 6 分
- 採点: 生成した画像の**隠した領域だけ**を領域の画像にし、E1 と同じ PCA と尺度で写して、本物の同じ領域から当てる（`id_easy`・`id_hard`）。見える領域の同定（`vis_easy`）も並べる（`mean` でも高いはず）
- 絵 `g-<step>-<mask>.png`: 16 個の候補を行にし、列は本物、`full`、`oracle`、`pred`、`mean`（`Q_br` と `R`）

### E2: 画面の外（帯のデータ: `exp/lib/tours/wide.py`）

**帯の切り直し**: 元の動画（`/datasets/walking_tours`、std-00 のコンテナの中）は 854×480 で、いまの 64×64 は中央の 480×480（$x_0$ = 187）を面積の平均で 7.5 分の 1 に縮めたものである（`video_io.ffmpeg_filter`）。同じ縮尺で、中央の左右に 24 画素（元の 180 画素）ずつの帯を切る。

- フィルタ: `fps=10,split=3[a][b][c];[a]crop=180:480:7:0,scale=24:64:flags=area[l];[b]crop=480:480:187:0,scale=64:64:flags=area[m];[c]crop=180:480:667:0,scale=24:64:flags=area[r];[l][m][r]hstack=inputs=3`。1 フレームは u8 `(3, 64, 112)`（列 0〜23 が左の帯、24〜87 が中央、88〜111 が右の帯）。中央の鎖はいまのデータと同じ演算（`fps`・中央の正方形の `crop`・`scale` の area）である
- 一般の形: 入力の高さを $c$ として $x_0 = (W_{\mathrm{in}} - c)/2$、帯の幅は元で $b = 24 c / 64$。$x_0 < b$ なら切らずに止める。対象の 3 本はどれも 854×480（manifest）
- **位置の確かめ**: 中央の 64 列が、いまのデータ（`data_version` `ad6e56b5995e`）の同じ動画のフレームと、全フレームでバイトまで一致し、フレームの数も同じであること。合わなければ書き出さずに止める（帯と中央が同じ時刻のフレームであることの保証）
- `video_io.ffmpeg_frames` に、フィルタの文字列を渡す引数 `vf`（既定は今の `ffmpeg_filter`）を足す
- **対象の動画**: span の当てはめの組が触れる動画（Amsterdam と Bangkok。実装で `locate` から求め、足りなければ止める）と Zurich。動画全体を切る（CPU で 10〜30 分の見込み）
- **置き場所**: `walking_tours` と同じく、各動画を `<out>/<video>/`（`U8Writer`）に書き、`finalize` で `index.json`（動画と各 index の sha256、元の `data_version`、フィルタ、幾何）を書いて `wide-<12 桁>` に名前を変える。std-00 で作り、NAS の `/nas/geson/mujou-exp/cache/wide-<…>/` を経由して各ホストの `$MUJOU_EXP_DATA/wide-<…>/` に置く。既存の `data_version` のデータには触れない
- **stack の位置**: `StackedTourFrames.locate(k)`（足す）が、$k$ 番目の stack の動画の名前とフレームの番号を返す。当てはめの組は `StreamEvaluator` の当てはめの組の $k$ から、Zurich は格子の最初のフレーム + 7 から、帯の最後のフレームを読む

**的**: 左の帯 `L`（64×24）、右の帯 `R`（64×24）、外側だけの帯 `L_out`（左の帯の列 0〜15）・`R_out`（右の帯の列 8〜23）。それぞれ `incep`（299×299 に引き伸ばす）と `color`（8×8 のブロックの平均）。見える端に接する画素は端の延長で当たるので、外側だけの版で接している分を除く。

**入力**: マスクなしの普段の stack の符号。checkpoint の `z`・`z_w` と、G の物差し（`init`・`init_f`・`init_m`・`color`・`pca`・`v16`・`v17`）。1024 次元を超える符号はない。

**対照**: `ext`（中央の最後のフレーム全体の `incep` か `color` から帯の的への ridge）、`interp`（中央の端の列を帯の幅に複製した画像の $T$ を、読み出しなしでそのまま予測にする）、`mean`（偶然の値）。

**読み出しと採点**: 帯ごとに ridge（当てはめは span の約 6000 組、$\alpha$ は calib、評価は 512 個の候補）。`r2`・`id_easy`・`id_hard`。`L` と `R` の平均を `side`、`L_out` と `R_out` の平均を `outer` として行に書く。

### 実装のテスト（理論のオラクル）

- **rectified flow の最適な速度場**: 1 次元で、データ $x_1 \sim N(m, s^2)$ と雑音 $x_0 \sim N(0, 1)$ が独立なら、$v^*(x, t) = \mathbb{E}[x_1 - x_0 \mid x_t = x] = m + \frac{t s^2 - (1 - t)}{(1 - t)^2 + t^2 s^2} (x - t m)$。(1) `flow_loss` を $v^*$ で評価したモンテカルロの値が、閉じた形の最小値 $\mathbb{E}_t[(1 + s^2) - (t s^2 - (1 - t))^2 / ((1 - t)^2 + t^2 s^2)]$ と誤差の中で一致する。(2) $v^*$ に摂動 $\epsilon$ を足すと、損失が $\epsilon^2$ だけ増える。(3) `euler_sample` を $v^*$ で 1000 step 回すと、$N(0, 1)$ の標本が平均 $m$・標準偏差 $s$ に写る（ODE の解 $x_t = t m + \sqrt{(1-t)^2 + t^2 s^2}\, x_0$ との差が step 数の逆数で縮む）
- **決定的なデータ**: $x_1 = c$ のとき $v^*(x, t) = (c - x)/(1 - t)$ で、`euler_sample` はどの step 数でも最後の step でちょうど $c$ に着く
- **U-Net**: 出力の形が入力と同じ。符号を変えると出力が変わり、符号への勾配が 0 でない（FiLM の経路が通る）。同じ seed で同じ重み。パラメータの数が、各層の形から手で数えた数と一致する。小さな版（チャネルを 8 に縮めたもの）で、2 枚の画像を符号 ±1 で条件づけて CPU で数百 step 学ぶと、各符号のサンプルの最近傍が正しい画像になる（`slow`）
- **Fréchet 距離**: 1 次元で $(\mu_1 - \mu_2)^2 + (\sigma_1 - \sigma_2)^2$。対角の共分散で $\sum_k (\sqrt{a_k} - \sqrt{b_k})^2$ と平均の差。共通の直交行列で回しても変わらない。$(a, b)$ と $(b, a)$ で同じ。同じ分布で 0。ランク落ちの共分散（標本の数 < 次元）でも有限で負にならない
- **同定の正解率**: 生成 = 本物なら `top1` = 1。生成がすべて同じなら（本物はばらばら）`top1` はちょうど $1/n$、`top5` はちょうど $5/n$。生成を置換 $\pi$ で並べ替えると `top1` = $\pi$ の不動点の数 / $n$。特徴を正の数倍しても変わらない。`top5` ≥ `top1`。`among` で候補を 1 個（自分だけ）にすると 1
- **`swap`**: $a = t$・$b = 0$ なら 1。$a = b$（0 どうしも）なら各行がちょうど 1/2。$a$・$b$・$t$ が独立なら、$10^4$ 組で 0.5 から二項分布の 4σ の中。共通の部分が $t$ に沿い、$b$ の雑音が $a$ の 30 倍でも、雑音が $t$ と独立なら同じく 4σ の中。E1 の合成の組では四半分の分布を変えても（左上を明るく、右下を暗く）、K3 のエンコーダの `swap` はどの段もちょうど 0.5、パッチのトークンの `oracle` は 0.9 を超え、どのエンコーダでも `mean` はちょうど 0.5
- **Inception**: 前処理が `F.interpolate(..., (299, 299), mode="bilinear", align_corners=False)` と $2x - 1$ の手計算と一致する。重みのファイルがあるときだけ（無ければ skip）: sha256 が `6726825d` で始まる、出力が `(B, 2048)` で負でない、batch の大きさを変えても特徴が $10^{-5}$ の中で同じ。ネットワークには接続しない
- **$W$**: 形と、同じ seed で同じ値。固定したベクトル $v$ について、$\frac{1}{d_{\mathrm{out}}} \lVert W v \rVert^2$ が $\lVert v \rVert^2 / d_{\mathrm{in}}$ にカイ 2 乗の幅の中で一致する。列を分けて掛けた値が一度に掛けた値と float の誤差の中で一致する
- **読み出し**: 雑音のない線形の関係 $Y = XB + b$ で $\alpha \to 0$ の解が $B$ を返し、`r2` = 1。$Y$ が $X$ と独立なら、大きな $\alpha$ で `r2` ≤ 0 に近い。`select_ridge` が calib の `r2` の最大を選ぶ。入力を定数にした予測（E1 の `mean`）の `id_easy` がちょうど $1/n$。`oracle` の入力を `pred` に渡すと `gain` が 1、`mean` を渡すと 0
- **評価のマスク**: 9 つのマスクと `S_1`・`S_2` が `mask_family(k, 4)` の行に含まれる（`tests/vision/`）。`expand_masks` で $s$ = 1・2・4 に広げた画素のマスクが同じ。`Q` の 4 つは互いに重ならず和が全体、`R` の $V$ が中央の 32×32
- **領域の画像**: `Q`・`H` は外接矩形の切り出しと一致し、灰色の画素がない。`R` は中央の 32×32 だけが 128
- **調和補間**: 定数の画像をそのまま返す。埋めた画素のそれぞれが、4 近傍（画像の中にあるもの）の平均に $10^{-6}$ の中で等しい。最大値の原理（埋めた値が見える画素の最小と最大の間）
- **帯のデータ**: 合成の動画（`imageio_ffmpeg` の ffmpeg で `testsrc` から作る 854×480・2 秒、可逆の codec）で、中央の 64 列が `ffmpeg_frames`（いまのフィルタ）の出力とバイトまで一致し、フレームの数も同じ。列ごとに値の違う縦縞の画像で、帯の各列が元の 7.5 列の面積の平均（境界の列は重みつき）と 1 以内で一致する。$x_0 < b$ の動画を断る（`slow`）
- **`locate`**: `locate(k)` の動画とフレームから読んだ stack が、`StackedTourFrames.next()` の $k$ 番目の stack と一致する
- **`gen_eval`・`fill_eval`**: 候補が 512 個で、隣との間隔が 70 フレーム以上、フレームを共有せず、動画の中に収まる。`id_hard` の候補の集合が 33 個で、両端の候補が外れる。学習の組が run の seed によらない（seed 0 と 1 の conf で同じ stack）。M の step 0 の `z_w` が F の step 0 の `z_w` とちょうど一致する。E2 の物差し `init_m`（`v16_config` の当てはめの組で求めた PCA）の行が、M の run 自身の step 0 の `z`（`zpca`、M の conf の当てはめの組）の行とちょうど一致する（2 つの conf は、データ・時間・span・seed が同じで、当てはめの組が同じ）。`uncond` の符号がすべて 0。的のキャッシュの `<hash>` が、組の stack が変われば変わる

## V18c: パッチ 8 と固定のランダム写像（学習の側、詳細設計、2026-11-24）

run の一覧・判定・長い run の規則・予想・反証は [README の「V18c」の節](../README.md)（回す前に決めたこと）に書いた。ここには、実装できる粒度の設計と、目的の式の自明な解の導出を書く。V18・V18b から変えるところだけを書き、書いていないところは V18 の節のとおりにする。新しい評価（拡散のデコーダで生成した画像の Inception の特徴での同定、Fable さんの E1「補完の同定」など）は別の workflow が作っている。この節は学習と、学習の側で測れる量だけを扱う。

### ユーザーが決めたこと（2026-11-24）

- **悪化の原因は、JEPA の学習目的と評価が合っていなかったこと。** 未来予測には進まず、**空間のマスク予測の V-JEPA のまま**進める。`recon_blur` は判定から外す。JEPA は抽象的な特徴を得る仕組みなので、再構成の向上は期待できない（[memory/feedback_eval_matches_objective.md](../../../memory/feedback_eval_matches_objective.md)）
- **パッチ 8**: 64 px で 8×8 = 64 トークン、トークンの入力は 8 × 3 × 8 × 8 = 1536 次元
- **潜在空間は、トークン数 $T$ とトークンの次元 $d$ に依存させない。学習しない固定のランダムな線形写像で決める（案 B）**: 各トークンを固定のランダム行列 $R$ で $d$ = 16 次元に写した $t_p = R h_p$ を予測の的にし、学習する射影 $P$ は無くす。潜在 $z = W\,\mathrm{vec}(t)$（$W$ は固定のランダムのガウス行列、$D$ = 1024）に SIGReg をかけ、評価の符号もこの $z$ にする
- **マスク**: V18 の粗い 4×4 の族 $F_k$（$k$ = 4・8・12）から引き、2 倍に広げる（`expand` = 2）。Fable さんの評価のマスク `Q`・`H`・`R` が族に入ることをテストで確かめる
- 学習は V18 と同じ（BP・i.i.d. なミニバッチ・LeJEPA の形・ViT-S 幅 1024・μP・予測器は幅 256・4 段・batch 128・warmup 1000 step と cosine）
- 掃引は第 1 段（$r$ = 0.5、学習率 $\{10^{-5}, 3 \cdot 10^{-5}, 10^{-4}\}$ × $\lambda$ $\{0.5, 0.8, 0.95\}$）と第 2 段（$r$ = 0.25・0.75）。長い run の設定は、新しい評価が使えるようになってから、掃引の checkpoint にかけて決める
- Codex さんの助言（V18b から引き継ぐ）: `pred` と $S$ を別々に記録して追う。学習率が低く、初期値の近くに留まった run は判定保留にする

### モデルと写像

| 量 | 形 | 作り方 | 学習 |
| -- | -- | -- | -- |
| $h_p$（エンコーダの出力、最後の `LayerNorm` の後） | $T$ = 64 個 × $w$ = 1024 | V18 と同じ ViT（`build_vae` の手順、patch 8） | する |
| $R$ | $d \times w$ = 16 × 1024、全位置で共有 | `gaussian_projection(16, 1024, R_SEED)`（標準正規 × $1/\sqrt{w}$、`R_SEED` = 67） | しない |
| $t_p = R h_p$（予測の的） | 16 次元 × 64 個 | | |
| $\mathrm{vec}(t)$ | $T d$ = 1024 | 位置の行優先、位置の中で座標の順（`tokens.flatten(1)`、$\mathrm{vec}(t)_{16p + i} = t_{p,i}$） | |
| $W$ | $D \times T d$ = 1024 × 1024（パッチ 8 では正方行列） | `gaussian_projection(1024, T d, W_SEED)`（標準正規 × $1/\sqrt{T d}$、`W_SEED` = 61） | しない |
| $z = W\,\mathrm{vec}(t)$（潜在・SIGReg の相手・評価の符号） | $D$ = 1024 | | |
| 予測器の出力 $\hat t_p$ | 16 次元（隠した位置ごと） | `Predictor(out_dim=16)`、V18 と同じ形 | する |

- **正規化の意味**: `LayerNorm` の後のトークンは（gain 1 なら）$\lVert h_p \rVert^2 = w$ なので、$E[(R h_p)_i^2] = \lVert h_p \rVert^2 / w$ = 1。同じく $E[(W v)_j^2] = \lVert v \rVert^2 / (T d)$ なので、$\mathrm{vec}(t)$ の座標の分散が 1 なら $z$ の座標の分散も 1 になる。$z$ の尺度は $T$ にも $d$ にもよらない。$D$ も $T$・$d$ によらず 1024 に固定する（`LATENT_DIM` = 1024）
- **乱数と、評価の側との共有**: $R$ と $W$ は、評価の側が決めた `exp/lib/randproj.py` の `gaussian_projection(d_out, d_in, seed)`（CPU の `torch.Generator().manual_seed(seed)` で `torch.randn(d_out, d_in)` を float32 で一度に引き、$1/\sqrt{d_{\mathrm{in}}}$ を掛ける。truncated normal ではない）で作る。リポジトリの中で $W$ の定義を 1 つにするためである。seed は run の seed に足さない固定の値で、$W$ は評価の側と同じ `W_SEED` = 61、$R$ は `R_SEED` = 67 とする。そのため、すべての run（長い run の seed 0 と 1 も）で $R$ と $W$ は同じで、seed の差は学習の差だけになる。worktree で先に実装するときは、評価の側の計画と同じ中身・同じ場所の `exp/lib/randproj.py` を書き、合流で 1 つにする。グローバルの RNG は使わないので、エンコーダと予測器の初期値の引き方は変わらない。エンコーダは同じ seed・同じパッチの V18 の手順と一致し、予測器は同じ seed・同じ $d$ の学習する射影の run と一致する（テストで確かめる）
- **評価の側の `z_w` との違い**: 評価の側の計画は、$h$ を平らにした $\mathrm{vec}(h)$（パッチ 8 で 65536 次元）を $W$（1024 × 65536、同じ `W_SEED`）で写した `z_w` を符号に足し、パッチ 8 の学習を $z = W\,\mathrm{vec}(h)$ と書いている（案 B の決定の前の形）。案 B の学習の $z = W\,\mathrm{vec}(t)$（$W$ は 1024 × 1024）とは別の符号である。合流のときに、評価の側の「パッチ 8 の学習」の記述（E1g の $\hat z = W\,\mathrm{vec}(\tilde h)$ を含む）を $t$ に読み替える（注: 合流の時点で、評価の側の計画はすでに案 B の形で書き直してあった。案 B では $z = W\,\mathrm{vec}(t)$（$t_p = R h_p$）、E1g は $\hat z = W\,\mathrm{vec}(\tilde t)$ である）
- **保存**: $R$ と $W$ はパラメータにせず、persistent な buffer にする。$R$ は module `proj`（`FixedProj`、buffer `weight` (16, 1024)、bias なし）、$W$ は新しい module `mix`（`Mix`、buffer `weight` (1024, 1024)）に置く。checkpoint の `modules` に `encoder`・`proj`・`predictor`・`mix` が入る（`ckpt.load_eval` は名前の集合の一致を求めるので、V18・V18b の run は `mix` なしのまま読める）。$R$ と $W$ は 4 MB 増えるだけで、ckpt は V18 と同じく 1 つ約 0.23 GB の見込み
- **optimizer**: $R$ と $W$ はパラメータでないので optimizer に入らない（`JEPAModules.parameters()` に出ない）。テストで、学習の step の前後で $R$ と $W$ がビットまで同じことを確かめる
- **ほかは V18 と同じ**: エンコーダ（`build_vae` と同じ手順。patch 8 では head が `Linear(64·1024 = 65536 → 512)` になり、作って捨てる）、予測器（幅 256・4 段、位置の符号 `sincos_2d((8, 8), 256)`、入口 `Linear(1024 → 256)`、出口 `Linear(256 → 16)`）、標的側は全トークン、文脈側は見えるトークンだけ（パッチの埋め込みと位置の符号の後で落とす）、EMA も stop-gradient もない
- **パッチ 8 を受けられること**: `ModelConf` にパッチの大きさの検査はない。`PatchEmbed` は `Linear(24·8·8 = 1536 → 1024)` と `sincos_2d((8, 8), 1024)` になり、`grid = size // patch` = 8 から 64 トークンを出す。`mask_expansion(8)` = 2。V18b で patch 4 を通したのと同じ経路で、コードの変更は要らない（パッチ 8 の形のテストを足す）

### μP での役割

エンコーダと予測器の役割と倍率は V18 の表のまま（`jepa_mup_roles`・`jepa_mup_lr`）。変わるのは次のとおり。

| パラメータ | 役割 | 学習率の倍率 | 初期値 |
| -- | -- | -- | -- |
| パッチの埋め込み（1536 → 1024） | input | 1 | LeCun（std $1/\sqrt{1536}$ = 0.0255） |
| 予測器の `out`（256 → 16） | output（$k$ = 1） | 1 | LeCun（std 1/16） |
| $R$・$W$ | パラメータでない | — | 上の表 |

- **パッチの埋め込み**: V18b と同じ理由で、Adam の 1 step の出力の変化は fan-in に比例する。パッチ 8（1536）は P16（6144）の約 4 分の 1、パッチ 4（384）の 4 倍動く。倍率は足さず、`embed_drift` を並べる（V18b と同じ）
- **$R$ の大きさ**: ユーザーの決定どおり LeCun の大きさ（std $1/\sqrt{w}$）にする。V18 の学習する $P$ の初期値（LeCun × $k_w^{-1/2}$）の 2 倍である。幅は 1024 から変えないので μP の転移には関わらず、$t$ がエンコーダに対して 2 倍敏感になる分は学習率の掃引に含まれる。倍率で補正はしない

### マスク（4×4 から 8×8 へ広げる）

- V18b と同じく、V18 の族 $F_k$ から `seed + MASK_SEED` の生成器で粗いマスクを引き、`expand_masks(mask, 2)` で 8×8 に広げる。粗い 1 マスは細かい 2×2 のブロックになる
- 隠す数 $k_{\mathrm{fine}} = 4k$ = 16・32・48（$r$ = 0.25・0.5・0.75）、見える数は 48・32・16。画素の領域は V18・V18b とまったく同じ（細かい位置の 8×8 画素の 4 つで、粗い位置の 16×16 画素になる）。同じ seed なら、V18・V18b・V18c は step ごとに同じ画素を隠す
- **Fable さんの評価のマスク**（粗い 4×4 の上、行優先の位置 $4i + j$）
  - `Q`（四半分、$k$ = 4）: $\{0, 1\} \times \{0, 1\}$ など 4 通り。$F_4$ に入る
  - `H`（半分、$k$ = 8）: 左・右・上・下の 4 通り。$F_8$ に入る
  - `R`（外周、$k$ = 12）: 中央 $\{5, 6, 9, 10\}$ 以外のすべて。1 通り。$F_{12}$ に入る
  - `mask_family` で確かめた（$|F_4|$ = 632、$|F_8|$ = 436、$|F_{12}|$ = 232 のまま、9 個とも含まれる）。テストでは、評価の側の `exp/lib/regions.py` が合流するまでは上の定義を書き、合流したらそのマスクで確かめる。`R` を 8×8 に広げると、中央の 4×4 の 16 個だけが見え、48 個を隠す
  - 族の上の一様な引き方では、`Q` の 1 つは 1/632、`H` の 1 つは 1/436、`R` は 1/232 の確率で引かれる（学習の分布の中にあるが、多くは引かれない）。族を `Q`・`H`・`R` に寄せることはしない（位置ごとに一様な性質を保つため）

### 損失

$$
L = (1 - \lambda)\, L_{\mathrm{pred}} + \lambda S, \qquad
L_{\mathrm{pred}} = \frac{1}{B k_{\mathrm{fine}} d} \sum_{n=1}^{B} \sum_{p \in M_n} \lVert \hat t_{n,p} - t_{n,p} \rVert^2, \qquad
S = \mathrm{SIGReg}\bigl(\{ W\,\mathrm{vec}(t_n) \}_{n=1}^{B}\bigr)
$$

- $d$ = 16、$B$ = 128。$L_{\mathrm{pred}}$ は V18 と同じく座標あたりの二乗誤差
- $S$ = `sigreg(z, z[:0], A)`。batch の 128 個の $z$（$D$ = 1024）、V 統計量（LeJEPA と同じ、バッファなし）。方向 $A$ は 1024 本を step ごとに `seed + DIRECTION_SEED` の生成器から引き直す（V18 と同じ）
- 標的側の $t$ にも、$z$ を通して $S$ にも勾配が届く。$R$・$W$ には勾配を流すが、パラメータでないので更新しない

### 自明な解の導出（$N$ = 128、$D$ = 1024、$T$ = 64、$d$ = 16）

数値は `exp.lib.sigreg.sigreg`（17 点の Epps–Pulley、$M$ = 1024 本、方向と標本を 8〜32 回引き直した平均）で求めた。1 回の引きのばらつき（標準偏差）は、健全な値で 0.04、K3 で 0.2〜0.3 である。$W$ は 1 つ引いたもの（特異値は最大 2.01・中央値 0.81・最小 0.0012）。

**方向ごとの分散のばらつきと超過**: 共分散 $\Sigma$（$\mathrm{tr}\,\Sigma = D$）のガウスの $S$ の超過は、V18 の展開で $\approx \frac{N}{4} \int t^4 e^{-3t^2/2} dt \cdot \mathrm{Var}_a(a^\top \Sigma a) \approx 0.241\, N (1/r_2 - 1/D)$（$r_2$ は participation ratio）。ランク $q$ の等方的な $\Sigma = (D/q) P_q$ では、一様な単位ベクトル $a$ について $\lVert P_q a \rVert^2 \sim \mathrm{Beta}(q/2, (D-q)/2)$ なので、$a^\top \Sigma a$ の相対的な標準偏差は $\sqrt{2(D-q)/(q(D+2))}$ である（$q$ = 16 で 0.351、$q = D$ で 0）。

| 解 | $z$ の共分散 | $S$（数値） | 健全な値からの超過 | $L_{\mathrm{pred}}$ |
| -- | -- | -- | -- | -- |
| 健全 $z \sim N(0, I_D)$ | $I$ | 1.05〜1.06 | 0 | $\ell_H$ |
| 等方的な $t$（$\mathrm{vec}(t) \sim N(0, I)$、$z = W\,\mathrm{vec}(t)$） | $W W^\top$（$r_2$ = 511） | 1.07〜1.09 | 約 0.03（式で 0.030） | $\ell_H$ |
| 定数 | 0 | 52.3（$0.409 N$） | 51.3 | 0 |
| 位置だけの関数 $t_{n,p} = g(p)$ | 0（$z$ が定数） | 52.3 | 51.3 | 0 |
| **K3**（$d$ = 16）: $t_{n,p} = A_p u_n$、$u_n \sim N(0, I_{16})$ | ランク 16 | **2.9〜3.0**（$A_p = I$ で 2.96・3.02、直交行列で回して 2.88） | **約 1.9**（式で 1.90） | 0（$u$ をどの見える部分からも推定できれば） |
| （比べ）K3、$d$ = 1024（射影なし、$h_p$ を的にし $W$ は 1024 × 65536） | $W' W'^\top$、$W' = \sum_p W_p A_p$ は正方のガウスと同じ分布（$r_2$ = 511） | **1.08** | **約 0.03**（等方的な $t$ と同じ） | 0 |
| 大域の解 $t_{n,p} = B_p g_n$、$g_n \sim N(0, I_q)$、$B_p$ はランダム（16 × $q$） | ランク $q$ | $q$ = 128: 1.31、256: 1.19〜1.21、512: 1.13〜1.17、768: 1.10〜1.14 | 0.26・0.15・0.10・0.07（等方的な $t$ との差は約 0.03 小さい） | 0（$g$ をどの見える部分からも推定できれば） |

健全な解の予測の損失を $\ell_H$（座標あたり、0〜1 程度）とする。比べるのは、目的の式の大域的な最小どうしの値で、学習の動きの議論ではない（V18 と同じ）。

1. **定数と位置だけの関数**: V18 と同じく $\lambda > \ell_H / (\ell_H + 51.3)$ で排除される
2. **$W$ の条件数**: $W$ は正方のガウスなので特異値が 0.0012〜2.0 に広がる。SIGReg の理想は $\mathrm{Cov}(\mathrm{vec}\,t) = (W^\top W)^{-1}$ で、極端に偏っている。しかし等方的な $t$ の超過は約 0.03（$r_2 \approx D/2$）で、$N$ = 128 の SIGReg は $W$ の偏りをほとんど見分けない。健全な解として等方的な $t$ を置いてよい
3. **典型の K3（$d$ = 16）**: どのトークンも stack 全体の符号 $u$ を丸ごと持ち、$t_p = A_p u$ とすると、$\mathrm{vec}(t)$ は 16 次元の部分空間に入り、$z$ の広がりはランク 16 に縮む。超過は約 1.9 で、排除されるのは $\lambda > \ell_H/(\ell_H + 1.9)$ のとき（$\ell_H$ = 0.3・0.5・1 で 0.14・0.21・0.34）。**掃引の $\lambda \ge 0.5$ では、K3 は目的の最小値にならない。** V18 の P16（$d$ = 64、超過 0.5）より 4 倍近く強く罰せられ、V18b の F（$d$ = 4、超過 7.3）より弱い。$A_p$ を位置ごとの直交行列にしてもスペクトルは同じで、$S$ も同じ（2.88）。固定の $R$ は $h_p$ の 16 次元の像しか見ないが、エンコーダは $R h_p = A_p u$ となる $h_p$ を作れるので、K3 の族の形は $R$ で制限されない
4. **射影なし（$d$ = 1024）の K3 は穴になる**: トークンが 1024 次元あれば、$u \in \mathbb{R}^{1024}$ をどのトークンにも丸ごと持たせられる。$z = (\sum_p W_p A_p) u$ の写像は正方のガウスと同じ分布なので、$S$ は等方的な $t$ と同じ 1.08 になり、$L_{\mathrm{pred}} = 0$ と両立する。**どの $\lambda < 1$ でも、K3 が目的の最小値になる**（V18b の M と同じ形）。$d$ を小さくするのは、この穴を閉じるためである（ユーザーの決定の理由）
5. **固定の $R$ と H-target**: 学習する $P$ は、$h_p$ のうち見える部分から当てやすい方向を選んで的にできる（Codex さんの H-target の一部）。固定の $R$ にはその自由がない。ただしエンコーダは $h_p$ そのものを変えられるので、H-target の道（当てにくい内容を $h_p$ から捨てる）は閉じない。$R$ の零空間（1008 次元）にある $h_p$ の成分は、標的側の損失からは制約されない（文脈側の計算と予測器の入力を通してだけ効く）。評価の `h_mean`・`h_pool` は、この成分も含めて測る
6. **大域の解は、どの案でも残る**: 見えるトークン全体で $q$ 次元の大域の符号 $g$ を分け持ち、トークンごとに違う読み出し $B_p$ で表す符号は、$q$ が大きいほど SIGReg に罰せられない。$L_{\mathrm{pred}} = 0$ にするには、隠した位置の $B_p g$ が見えるトークンから決まる必要があり、$q \le$ 見える数 × $d$（$r$ = 0.25・0.5・0.75 で 768・512・256）である。超過は 0.07〜0.15 しかない（等方的な $t$ との差は 0.04〜0.12）。排除されるのは $\lambda > \ell_H / (\ell_H + e)$ のときで、$e$ = 0.05 なら $\ell_H$ = 0.5 で $\lambda > 0.91$。**$\lambda$ = 0.95 だけが、$\ell_H \lesssim 0.9$ の範囲でこの解を目的の最小値から外す。** $\lambda$ = 0.5 と 0.8 では、$\ell_H \ge 0.5$ なら外さない。ただし、この解が $L_{\mathrm{pred}} = 0$ になるのは、$g$ の中身がどの見える部分からも推定できるときだけで、どこまで推定できるかはデータが決める。トークンごとの `token_r2` は約 $d/q$（$q$ = 768 で 0.02）と小さく、K3 の検査に掛からない。そのため崩壊の検出（`token_r2`・`rho_in`・`rank`）に加えて、評価の側の `swap`（大域の符号だけなら 50%、Fable さんの導出）で見張る
7. 学習の動き: 1 標本あたりの勾配の重みの比は $\lambda B / (1 - \lambda)$ で、$\lambda \ge 0.5$ では 128 以上になる（V18 と同じ尺度）。どの解に向かうかは導出だけでは決まらない

**テストのオラクルにする値**（$N$ = 128、$M$ = 1024、方向と標本を 16 回引き直した平均。許容の幅は 1 回の引きの標準偏差 / $\sqrt{16}$ の 4 倍より広くとる）

- 健全 $z \sim N(0, I)$: 1.06 ± 0.05。定数: 52.3（$0.409 N$、台形則の誤差の中）
- 等方的な $t$ を $W$ で写したもの: 1.07〜1.09。健全な値との差が 0.08 未満
- $d$ = 16 の K3（$A_p = I$ と、位置ごとの直交行列）: 2.6〜3.4。両者の差が 0.3 未満
- $d$ = 1024 の K3（射影なし）: 健全な値との差が 0.08 未満（穴があることの確かめ）
- 大域の解: $q$ = 128 で 1.2〜1.45。$q$ = 128・256・768 で $S$ が小さくなっていく（それぞれの間に 0.04 以上の差）
- $a^\top \Sigma a$ の相対的な標準偏差（ランク 16、$D$ = 1024、$10^4$ 本の方向）: 0.351 ± 0.01

### 学習（`jepa.py`・`jepa_iid.py` の変更）

- **定数**: `jepa.py` に `PROJ_KINDS = ("learned", "fixed")`、`LATENT_DIM = 1024`、`R_SEED = 67`、`W_SEED = 61` を足し、`SIGREG_ON` に `"mix"` を足す。`exp/lib/randproj.py` は seed を持たず、評価の側も `jepa_eval.py` に同じ値の `W_SEED` を置いているので、合流のときに 1 か所にまとめる（実装のときに分かった）
- **モジュール**: `FixedProj(weight)`（buffer `weight` (d, w) = $R$、$t = h R^\top$）と `Mix(weight)`（buffer `weight` (D, td) = $W$、$z = \mathrm{vec}(t) W^\top$）。`JEPAModules` に `mix: nn.Module | None = None` を足し、`proj` の型を `nn.Module` にする。`modules()` は `mix` があるときだけ `"mix"` を含める。`tokens(stacks)` は $t$（`proj` の出力）、`mu(stacks)` は `mix` があれば $W\,\mathrm{vec}(t)$、なければ V18 のとおり $\mathrm{vec}(t)$
- **`build_jepa`**: `proj: str = "learned"`、`latent_dim: int | None = None` を足す。`proj="fixed"` なら $R$ を上の規則で作る（μP の $k_w^{-1/2}$ は掛けない）。`latent_dim` が整数なら $W$（`latent_dim` × $T d$）を作る。既定のままなら V18・V18b と同じ
- **`sigreg_points(tokens, on, mix=None)`**: `"mix"` なら `mix(tokens.flatten(1))`（$(B, D)$）。`jepa_terms` は `mods.mix` を渡す。`"mix"` で `mix` がなければ `ValueError`
- **引数**（`jepa_iid`）: `--proj {learned,fixed}`（既定 `learned`）、`--sigreg-on {flat,mean,mix}`（既定 `flat`。`mix` のとき $W$ を作る）。V18c の run は `--patch 8 --token-dim 16 --proj fixed --sigreg-on mix`。既定のままなら V18・V18b とまったく同じ計算になる（既存のテストで確かめる）
- **`jepa.json`**: V18b の項目に `proj`、`latent_dim`（`mix` のとき 1024、ほかは `null`）、`seeds.r`（`fixed` のとき 67）と `seeds.w`（`mix` のとき 61）を足す。`fixed` のときの `seeds.proj` は使わないので `null` にする。`sigreg_dim` は $D$ = 1024
- **`train.jsonl`**: V18b の列（`loss`・`pred`・`sigreg`・`grad_norm`・`z_var`・`rho_in`・`zbar_var`、`lr`・`sec`・`max_mem`）。`z_var` と `rho_in` は $t$ のもの。`mix` の run だけ `mix_var`（$z = W\,\mathrm{vec}(t)$ の座標ごとの分散の平均。SIGReg の目標は 1）を足す
- **checkpoint の時刻**: V18 と同じ（$t = 12.8 s$ 秒）。短い run（掃引）は step 0・1000・2000・4000・6000（$t$ = 0・12800・25600・51200・76800 秒）。長い run は V18 の `LONG_CKPT`（0・2000・6000・10000・20000・30000・40000・50000・60000）。長い run の step 数が 60000 より小さくなったときは V18b の規則（0・2000・6000 と $s_{\mathrm{long}} j/6$ を 2000 の倍数に切り下げたもの）
- **出力** `<out>/`: V18 と同じ形（`config.yaml`、`jepa.json`、`train.jsonl`、`ckpt/<t>.pt`）。ckpt の modules は `encoder`・`proj`・`predictor`・`mix`
- 損失が有限でなくなったら止める（V18 と同じ）

```bash
python -m exp.vision.jepa_iid --patch 8 --token-dim 16 --proj fixed --sigreg-on mix \
    --mask-ratio 0.5 --lam 0.8 --lr 3e-5 --steps 6000 --out <run_dir>
```

### 評価（`jepa_eval.py`・`jepa_diag.py` の変更、学習の側で使うもの）

- **run の読み方**: `build_run_jepa` が `jepa.json` の `proj`・`sigreg_on`・`token_dim`・`latent_dim` を読む（記録がなければ V18 の既定）。V18c の符号は `ARM_CODES["mix"] = ("z", "h_mean")`。`z` は `JEPAModules.mu` = $W\,\mathrm{vec}(t)$、その `tokens` は $t_p$（16 次元 × 64 個）
- **崩壊の量**: `sigreg_heldin`・`sigreg_zurich`・`z_var`・`participation` は $z$ で、`token_r2`（順序つきの組 64 × 63 = 4032 組）・`rho_in` は $t_p$ で測る（`CodeStats.of` はそのまま使える）。`rank` は probe の $z$ の実効ランク
- **予測**: `CodeStats.pred` の `pred`・`pred_ratio`・`pred_ratio_calib` は $t$ の空間（`mods.proj` = $R$、`expand` = 2 で広げた固定のマスク）。変更は要らない
- **`drift`**: `embed_drift`・`block_drift`（V18b と同じ）
- **probe**（`StreamEvaluator.probes`、6000 組）: 符号 `z` と `h_mean` を step 2000・6000 にかけ、`rank`（K2）と、並べるだけの `dyn_1/copy_1`・`recon_blur` を出す。長い run は step 6000・20000・60000 と、`h_pool`（$h$ を 2×2 のブロックごとに平均した 16 × 1024 = 16384 次元）を step 0・6000・20000・60000
- **Imagenette**（`jepa_diag imagenette`、std-01）: `h_mean` と `z`。短い run は step 0（1 回）と 6000、長い run は全 checkpoint
- **物差し**（`jepa_eval --yardsticks --patch 8 --token-dim 16 --proj fixed --sigreg-on mix`、1 回だけ）: `init_c`（V18c の step 0 の `z`、トークンは $t$。掃引の 9 本と第 2 段は seed 0 で同じ初期値）、`init_c_h_mean`、`color8`（パッチ 8 のパッチごと・チャネルごとの画素の平均、64 × 24 = 1536 次元、`ColorCode(8)`）。V18 の物差し（`color`・`v16`・`v17`）は `runs/v18-baselines/` の値を使う
- **新しい評価への引き継ぎ**: 主の指標（生成した画像の同定）は $z$ にかける。E1 は予測の的が $t_p$ なので、$h$ を $t$ に読み替える。E1g は、隠した位置を $\hat t$ で埋めた $\tilde t$ から $\tilde z = W\,\mathrm{vec}(\tilde t)$ を作り、全体の $z$ で学んだデコーダに入れる（`JEPAModules.mix` で計算できる）。どちらも checkpoint だけからかけられる
- **出力**: run の `posthoc_jepa/`、`posthoc_diag/`（`h_pool`）、Imagenette は `runs/v18c-imagenette/`、物差しは `runs/v18c-baselines/posthoc_jepa/`

### 実装のテスト（理論のオラクル、V18・V18b のテストに足すもの）

- **$R$・$W$**: 形が (16, 1024)・(1024, 1024)。run の seed（0 と 1）によらず同じ値で、`gaussian_projection(16, 1024, 67)`・`gaussian_projection(1024, 1024, 61)` とちょうど一致する。要素の標本の標準偏差が $1/\sqrt{1024}$ の ±1% の中。`JEPAModules.parameters()` と optimizer の param group に入らない。2 step 学習した後も、ビットまで同じ。**checkpoint に保存した $R$・$W$ が、seed から作り直したものとちょうど一致する**（保存と再現の両方を確かめる）。V18・V18b の形の run（`mix` なし）の checkpoint が、変更後のコードでそのまま読める
- **写像の式**: `mu` が `tokens(x).flatten(1) @ W.T` とちょうど一致する。`vec` の順が $\mathrm{vec}(t)_{16p + i} = t_{p,i}$。等方的な $\mathrm{vec}(t)$（$10^4$ 標本）で $z$ の座標の分散の平均が 1 ± 0.02（$\mathrm{tr}(W W^\top)/D$ に一致する値、正規化の確かめ）
- **SIGReg**: 上の「テストのオラクルにする値」と、方向の分散の相対的な標準偏差 0.351
- **マスク**: `Q`（4 通り）・`H`（4 通り）・`R`（1 通り）が、それぞれ `mask_family(4|8|12, 4)` の行に含まれる。`expand_masks(·, 2)` が $4k$ 個を隠し、粗いマスクを 16 画素・広げたマスクを 8 画素に拡大した 64×64 の画素のマスクがちょうど一致する。広げた `R` は中央の 4×4 だけを見せる
- **パッチ 8 の形**: トークンが 64 個、`PatchEmbed` の fan-in が 1536、予測器の位置の符号が 8×8。文脈側で、隠した位置の画素を変えても出力が変わらない

### 新しい主の指標の考え方

- 符号は入力の関数なので、情報の量では 64 px の画素そのものに勝てない（データ処理不等式）。測れるのは「容量を固定した線形の読み出しで取り出せる形になっているか」である（E1 の背景と同じ）
- **的は 64 px の画素の関数ではなく、場面の関数にする。** 同じフレームを元の解像度で切り直し、299 px で学ばれた Inception に通す。四半分（160 px → 299 px、1.87 倍）でも、いまの 32 px → 299 px（9.3 倍）よりネットが学んだ入力の範囲に近い
- **pool3 は 8×8 の特徴の地図の平均なので、切り出しの中の位置を持たない。** 四半分ごとに並べると、的は「どの四半分に、どういう種類のものがあるか」を表し、数画素のずれや細い線の位置は入らない
- 生成を通さないので、サンプルの雑音と、生成画像に共通する分布のずれ（G の hub と `feat_ratio` 0.93〜1.0 の原因）が入らない。checkpoint が決まれば決定的に計算できる

### 高解像度のフレーム（`exp/lib/tours/hires.py`）

- 元の動画（854×480、`/datasets/walking_tours`、std-00 のコンテナ）から、いまのデータと同じ中央の 480×480（$x_0$ = 187）を切り、320×320（64 px のちょうど 5 倍）にする。フィルタは `fps=10,crop=480:480:187:0,scale=320:320:flags=area`。一般の形は帯（`wide.py`）と同じく、$c$ = 入力の高さ、$x_0 = (W_{\mathrm{in}} - c)/2$。`band_geometry` と同じ流儀で `hires_filter(geometry, fps, size)` を書く
- **要るフレームだけを残す**: 当てはめの組の stack の最後のフレーム（`FillSets.places["fit"]`、約 6000）と、Zurich の格子の全 stack の最後のフレーム（`places["grid"]`、3899）。動画は E2 と同じ求め方（当てはめの組が触れる動画と Zurich）
- `sem_eval frames --out <json>`: 動画ごとに、要るフレームの番号を重複を除いて昇順に並べた一覧を書く
- `hires prepare <video> --src … --data $MUJOU_EXP_DATA/ad6e56b5995e --frames <json> --out <dir>`: `video_io.ffmpeg_frames(…, vf=…)` で動画を頭から読み、一覧の番号のフレームだけを u8 `(N, 3, 320, 320)` で `U8Writer` に書く。`frames.json` に番号を書く
- **位置の確かめ**（書き出す前、残すすべてのフレーム）: 320 のフレームを 5×5 の平均で 64 に縮め（float のまま、丸めない）、いまのデータの同じ動画・同じ番号のフレーム $x^{64}_f$ と比べる
  - (a) 画素の差の絶対値の平均が 1.0 以下
  - (b) 動いているフレーム（$x^{64}_f$ と $x^{64}_{f \pm 1}$ の差の絶対値の平均が 2 を超えるもの）で、差の平均が $f$ で最小になる（$f \pm 1$ より小さい）。時刻の取り違えを見分ける
  - (a) の根拠: いまの 480 → 64 の area は 7.5×7.5 の面積の平均である。480 → 320 は 1.5 倍で、5×5 の平均と合わせると境界がちょうどそろい、同じ演算になる。違いは 320 を u8 に丸めること（平均すると 1 画素あたり 0.5 以下）と、ffmpeg が色の 4:2:0 を RGB に直す位置の違いだけである。外れたら書き出さずに止める。閾値は緩めない
  - **結果を見た後の変更（ユーザーの決定、2026-11-25）**: 上の形では、(a) が 9897 枚のうち 9052 枚で外れた（README「V18c: 作り直した主の指標の有効性」）。時刻と場所は合っていて、原因は色の変換の順序だった。いまの 64 px のデータは 4:2:0 の YUV のまま縮めてから RGB に直しており、320 px と 64 px では色差の縮める比が違う。そこで次のように変えた
    - 高解像度のフレームは、切ってから RGB に直し、area で縮める（`fps=10,crop=480:480:187:0,format=rgb24,scale=320:320:flags=area`）
    - (a) の参照は、同じ動画から同じ順序で作った 64 px（`…,format=rgb24,scale=64:64:flags=area`、`hires_filter(…, size=64)`）にする。閾値 1.0 と上の根拠（同じ演算で、違いは u8 の丸めだけ）は保つ。先頭の 60 フレームで、この差は 0.26 だった
    - いまのデータとの対応は、色の変換の順序の差（2.3〜3.0）を含むので、相対の確かめだけで見る。(b) はそのまま。(c) を足す: 320 px で上下左右に 1 画素、64 px で上下左右に 1 画素ずらした 8 通りのそれぞれで、ずらさない位置の差（内側だけ、端から 2 画素を除く）がずらした位置の差より小さい。ずらしても平均が変わらない（変化が `MOVING` = 2 以下の）ずらしは、(b) の動かない隣と同じ理由で見分けられないので読まない
    - 的を作る前の場所の確かめ（`build_targets`）も、同じ原因で、いまのデータとの差の絶対値の平均 1.0 以下では外れる。そこで、stack の最後のフレームが、その場所のいまのデータのフレームとビットまで一致すること、および場所で読んだ高解像度のフレームが (b) の形で前後の動くフレームより自分に近いことを確かめる（`sem_eval.check_places`）。データとの差の最大は `places_max_diff` に記録だけする
- `hires finalize <dir>`: `index.json`（動画ごとの番号と sha256、元の `data_version`、フィルタ、大きさ）を書き、`hires-<12 桁>` に名前を変える。std-00 で作り、NAS の `/nas/geson/mujou-exp/cache/` を経由して各ホストの `$MUJOU_EXP_DATA/hires-<…>/` に置く。既存のデータには触れない
- 大きさ: 約 9900 枚 × 307 KB = 3.0 GB

### Zurich の分け方（calib・sel・final）

- 格子（$G$ = 3899、1 秒おき）を、6 つの連続した区間 $s$ = 0〜5 に分ける（長さ $\lfloor G/6 \rfloor$ = 649、最後の区間が余りを持つ）。各区間の先頭の `GAP` = 30 個（30 秒）を捨てる。区間 $s$ は $s \bmod 3$ で、calib（$s$ = 0・3）・sel（1・4）・final（2・5）に入る。各組は約 1238 個
- 理由
  - いまの calib（`StreamEvaluator.zurich_calib_stacks`）は格子と重なる（裁定の表）
  - 1 本の動画を前・中・後に 1 つずつ分けると、組ごとに場面が偏る。2 つずつ離して持たせれば、どの組も動画の前半と後半を含む
  - 30 秒の間は、stack の幅 0.8 秒と、1 秒おきのほとんど同じ景色を十分に超える。数分続く場面の相関は残るので、組どうしは完全には独立ではない。そのことはブロックのブートストラップの長さで扱う
- 使い方: $\alpha$ は calib で選ぶ。長い run の設定は sel で選ぶ。長い run の判定は final で読む（選んだ組で判定すると、選んだことによる上ぶれが入る）。有効性の確かめは sel で判定し、final の値も並べる
- `zurich_split(n_grid, segments=6, gap=30) -> dict[str, Tensor]`（`sem_eval`）: 組ごとの格子の番号と、各番号の区間の番号（ブートストラップのため）

### 的（`sem_eval targets`、checkpoint によらないので 1 回だけ）

- 高解像度のフレームの 4 つの四半分 $q$ ∈ {tl, tr, bl, br}（160×160）と全体（320×320）を、それぞれ Inception（`exp/lib/inception.py`、pytorch-fid と同じ前処理: bilinear で 299×299 にして $2x - 1$）に通した pool3（2048 次元）
- **`sem`（主の的）**: 4 つの四半分の pool3 を tl・tr・bl・br の順に並べた 8192 次元を、当てはめの組で PCA（`pca.fit_pca`、`SEM_DIM` = 64 成分、`SEM_PCA_SEED` = 97）にかける。当てはめの組の平均を引き、成分ごとに当てはめの組の標準偏差で割る（白色化）。64 成分が説明する当てはめの組の分散の割合を `targets.json` に書く
- **`quad/<q>`（E1 の修理の的）**: 四半分 $q$ の pool3 を、同じく PCA 64・白色化（seed は `SEM_PCA_SEED`）
- **`scene`（副、並べるだけ）**: 全体の pool3 を PCA 32・白色化
- **`inc64`（参考の物差しの符号）**: 64 px の最後のフレームを Inception に通した pool3（2048 次元）。当てはめの組と格子について計算する

### 読み出しと採点（`exp/lib/readout.py`）

- ridge は既存の `fit_ridge`（当てはめの組で中心化、$\alpha = c \cdot \mathrm{tr}(X^\top X)/D$、float64）。当てはめは約 6000 組（`fit`）、的は `sem`
- **主の指標** `centered_r2(pred, y)`: 組 $E$ の上で、$\tilde y_i = y_i - \langle y \rangle_E$、$\tilde p_i = \hat y_i - \langle \hat y \rangle_E$ として

$$
m_E = 1 - \frac{\sum_{i \in E} \lVert \tilde p_i - \tilde y_i \rVert^2}{\sum_{i \in E} \lVert \tilde y_i \rVert^2}
$$

- 予測も的も、その組の平均を引く。学習の動画と Zurich のずれ（全 stack に共通）を除くためで、`identification` が格子の平均を引くのと同じ理由である。旧 E1 の step 0 の `pred` の `r2` −10 は、このずれだけで決まっていた。定数の予測はちょうど 0 になる
- $\alpha$: `select_ridge(…, score=centered_r2)` で、calib の $m$ が最大の $c$（同点なら最初）。`select_ridge` に引数 `score`（既定は今の `r2`）を足す。既存の呼び出しの値は変わらない
- **K3 の上限** `rank_bound(y, r)`: 組 $E$ の $\tilde Y$ の共分散の固有値を $\mu_1 \ge \mu_2 \ge \dots$ として、$b_r(E) = \sum_{j \le r} \mu_j / \sum_j \mu_j$
  - 導出: 中心化した予測 $\tilde P$ のランクが $r$ 以下なら、Eckart–Young より $\lVert \tilde Y - \tilde P \rVert_F^2 \ge \sum_{j > r} \sigma_j^2 = \lvert E \rvert \sum_{j > r} \mu_j$（$\sigma_j$ は $\tilde Y$ の特異値）。分母は $\lvert E \rvert \sum_j \mu_j$ なので $m_E \le b_r(E)$
  - `z_k3`・`init_c_k3`（$r$ = 16）では、中心化した予測 $(z_{k3} - \bar z_{k3}) B$ のランクが 16 以下なので、組ごとに**ちょうど**成り立つ（推定の誤差は入らない）
- **項目ごとの値**: $e_i = \lVert \tilde p_i - \tilde y_i \rVert^2$（sel と final、符号ごと）と $v_i = \lVert \tilde y_i \rVert^2$（的のキャッシュに 1 回）。$m_E = 1 - \sum e_i / \sum v_i$
- **当てはめの組を半分にした値**（V-m6 と選び方の安定）: 当てはめの組を、`StreamEvaluator` の span の奇数の区間ごとに交互に 2 つに分け、それぞれで当てはめた $m$（sel）を `m_sel_half` に書く。$\alpha$ はそれぞれ calib で選び直す
- 副: `scene` の $m$、sel の中に入る候補の `id_easy`（`identification`、偶然は $1/n_{\mathrm{sel}}$）。並べるだけ

### 揺れ（ブロックのブートストラップ、`exp/lib/metrics.py` の `block_bootstrap`）

- 組 $E$ の格子の番号を、区間の中で長さ $L$ の連続したブロックに分ける（区間の終わりの余りは直前のブロックに足す）。ブロックを重複を許して同じ数だけ引き直す（`BOOT` = 2000 回、`BOOT_SEED` = 101）。どの符号でも同じ引き方を使い、対にする。各回で $m^* = 1 - \sum e^*_i / \sum v^*_i$ を作る。比べ（差、seed の平均の差）は各回で計算し、その標準偏差を $\mathrm{SE}_{\mathrm{blk}}$ とする。中心化は元の組で 1 回だけ行う（引き直しで平均を取り直す効果は $O(1/\lvert E \rvert)$）
- 関数の形: `block_bootstrap(e: Tensor (C, N), v: Tensor (N,), blocks: Tensor (N,), contrasts: Tensor (Q, C), n: int, gen) -> Tensor (Q,)`。$C$ 個の符号の $e$ を受け取り、係数 `contrasts` で組み合わせた $m$ の差の標準誤差を返す。$m$ の比の形は各回の和から作る
- **$L$ の決め方**（符号によらず、的だけで 1 回）: 格子の並びの上で、白色化した `sem` の 64 成分の自己相関の平均 $\rho(\ell)$ を求める。積分した相関時間 $\tau = 1 + 2 \sum_{\ell = 1}^{\ell^*} \rho(\ell)$（$\ell^*$ は $\rho$ が初めて 0 以下になる手前）から、$L = \min(\max(\lceil 2\tau \rceil, 16), 154)$ とする
  - ブロックが相関の長さより十分長ければ、ブロックの和はほぼ独立になり、ブロックのブートストラップの標準誤差が成り立つ（Künsch 1989）。$2\tau$ は相関の長さの 2 倍
  - 154 は、1 組（約 1238 個）に少なくとも 8 個のブロックを残すための上限である。1 組は 2 つの区間（619 個ずつ。final の後ろの区間だけ 624 個）で、ブロックは区間ごとに切る（余りは直前のブロックに足す）ので、区間ごとに 4 個を残す上限は $\lfloor 619/4 \rfloor = 154$ になる。最初に書いた 155 では区間ごとに 3 個、1 組に 6 個しか残らなかった（数値を読む前のレビューで直した）。上限に当たったら、標準誤差が小さく出ている恐れがあることを README に書く
- 閾値の式（$\delta_w$・$\delta_1$・$\delta_3$・$\delta_y$・$\delta_{yy}$）は README

### 的の感度の確かめ（`sens`、Codex さんの (a)）

pool3 の的が、照明・色・ぼかしより、粗い内容に強く反応するかを確かめる。

- 格子の全 stack の高解像度の最後のフレーム $x$ に、次の変換をかける。4 つの四半分を Inception に通し、`sem` の空間に写す
  - 迷惑の変換 3 つ: 明るさ（全画素 × 0.8、u8 に丸める）、白の釣り合い（チャネルごとに × (1.1, 1.0, 0.9)、255 で切って丸める）、ぼかし（64 px の縮尺で $\sigma$ = 1 画素、320 px で $\sigma$ = 5 のガウス、端は反射）
  - 内容の変更: 同じ組の中で 300 個（5 分）以上離れた格子の stack $x'$ を `SENS_SEED` = 103 で 1 対 1 に引き、チャネルごとの平均と標準偏差を $x$ に合わせてから u8 に丸める（`match(x', x)`）
- 距離: $d_j = \langle \lVert y(T_j x) - y(x) \rVert^2 \rangle$、$d_c = \langle \lVert y(\mathrm{match}(x', x)) - y(x) \rVert^2 \rangle$、比 $\rho_j = d_j / d_c$
- 同じ計算を画素の的でも行う。画素の的は、64 px の最後のフレームの 4 つの四半分の画素を並べ、当てはめの組で PCA 64・白色化したもの。変換は 320 px でかけてから 5×5 の平均で 64 px に縮める（$\rho^{\mathrm{pix}}_j$）
- 変換の大きさは、理論から出る値ではない設計の選択である（明るさ 0.8 は露出で約 1/3 段、$\sigma$ = 1 画素は 64 px の画像の 1 画素の幅）。そのため判定（README の V-m3）は、同じ変換をかけた画素の的との比べで行う
- 費用: 3899 × 4 通り × 4 つの四半分 ≈ 6.2 万枚の Inception

### E1 の修理（`exp/vision/fill_eval.py` の変更）

**1. ずらしの診断（`e1diag`。旧 checkpoint と、既存の的のキャッシュで）**

- `_swap_rows` の各組（pair・向き $u$・的・段）で、候補ごとの差 $d_i$ = `part_u_i` − `part_w_i`（$n \times K$）と真の値 $t_i$（`truth`）から、$P = D T^\top$（$n \times n$、float64）を作る。いまの `swap` は対角の $\frac1n \sum_i \mathbb 1^{\pm}[P_{ii} > 0]$ である（$\mathbb 1^{\pm}$ は正で 1、0 で 1/2、負で 0）
- 出すもの（段は `pred`・`oracle`、的は `incep`・`color`、2 つの pair × 2 つの向きの平均）
  - 内積の平均 $C(\tau) = \frac1n \sum_i P_{(i + \tau) \bmod n,\, i}$ と勝率 $s(\tau) = \frac1n \sum_i \mathbb 1^{\pm}[P_{(i + \tau) \bmod n,\, i} > 0]$、$\tau = 0, \dots, n - 1$
  - 巻き戻しのない版 $C^{\mathrm{nw}}(\tau)$・$s^{\mathrm{nw}}(\tau)$（$i + \tau < n$ の組だけ、$\tau \le n - 64$）
  - 対角以外の全組の内積の平均 $C_{\mathrm{off}}$ と勝率 $s_{\mathrm{off}} = \frac{1}{n(n-1)} \sum_{i \ne j} \mathbb 1^{\pm}[P_{ji} > 0]$
  - 恒等式の残差 $\max_i \lvert \sum_j P_{ji} \rvert / \max \lvert P \rvert$。`_deviation` が候補の平均を引くので $\sum_j d_j = 0$ で、残差は丸め誤差の大きさのはず
- arcsin の換算、「並べ替えの平均が 0.5」の判定、曲線を見てから選んだ遠いずらしの p 値は使わない（裁定の表）
- 対象: V18 の $r$ = 0.25 の seed 0 の step 0・6000・60000、F の seed 0 の 60000、M の 60000、V18 の $r$ = 0.5 の seed 0 の 60000（`S` が分布の中）。観測した偏りそのものを調べるので、いまの設定（512 個の候補、いまの calib、いまの的のキャッシュ）のままにする
- 出力: `posthoc_fill/rows/<step>-e1diag.json`（曲線は配列）と、絵 `e1diag-<step>.png`（$C$ と $s$、巻き戻しのあり・なし、$s_{\mathrm{off}}$ の横線）
- 費用: 512 × 512 の行列が、1 checkpoint あたり 2 pair × 2 向き × 2 的 × 4 段 = 32 枚。予測器の前向きを含めて 1〜3 分

**2. 位置の平均の複製（`oracle_k3`・`pred_k3`、凍結した読み出しの E1 の段に足す）**

- `oracle_k3`: 全体を見たトークンを位置の平均（全 64 位置）で置き換えた符号で、当てはめの組・calib・候補のすべてを作る。読み出し $g_U$ もこの符号で当てはめ直す（場面だけの符号の基準）
- `pred_k3`: 予測器の出力の隠した位置を、隠した位置の平均で置き換える。読み出しは `oracle` の $g_U$ のまま（`pred` と同じ条件）
- `swap`: どちらも 2 つの位置の入力が同じテンソルになるので、`_deviation` の差がちょうど 0 で、全候補が引き分け（ちょうど 0.5）になる。行に引き分けの数 `n_tie` を書く。位置ごとの定数 $g(p)$ は足さない（足すと浮動小数点の丸めで引き分けにならない）
- `id_easy`・`id_hard`・`r2` も出し、「場面だけを表す符号・予測器がどこまで当てるか」の基準として並べる

**3. `shuf`**: 段として残す（ずらし 256）が、合否に使わない。`e1diag` の曲線と並べる。

**4. 当てはめ直す補完のゲート（`e1f`、V18c の checkpoint）**

- **マスク**: 四半分 $Q_q$ を常に隠し、共通の順序でブロックを足す
  - $k$ = 4: $Q_q$
  - $k$ = 8: $Q_q$ と、横に隣り合う四半分（$Q_q$ を含む `H_t` か `H_b`）
  - $k$ = 12: さらに縦に隣り合う四半分（例: `Q_tl` なら `H_t` ∪ `H_l`、2 つの矩形の和。見えるのは対角の四半分だけ）
  - 12 個のマスク（4 つの $q$ × 3 つの $k$）が、それぞれ `jepa.mask_family(k, 4)` の行に入ることをテストで確かめる。採点はいつも $Q_q$ の的 `quad/<q>`
- **入力**（どれも自分の入力で `quad/<q>` への ridge を当てはめ、$\alpha$ は calib で `centered_r2` により選ぶ）
  - `pred`: 予測器の出力 $\hat t$ の $Q_q$ の位置（パッチ 8 で 16 個 × 16 次元 = 256 次元、位置の昇順）。当てはめの組と calib でも、同じマスクで予測器を通す
  - `pool`: `pred` の 16 個の位置の平均（16 次元）。位置をまとめた対照
  - `pred_k3`: `pred` の 16 個を、その平均で置き換えたもの（256 次元。`pool` と同じ情報）。実データの負の対照。$\alpha$ の尺度は選ばず、`pool` で選んだ $c$ の $P$ = 16 倍に固定する（下の導出）
  - `vis_color`: 見える粗いマスの、8 枚 × 3 チャネルの平均の色（$k$ = 4・8・12 で 288・192・96 次元）。同じ見える部分から作る、学習しない基準
  - `oracle`: 全体を見たトークンの $Q_q$ の位置（256 次元）。的がトークンから読めるかの確かめ
  - `mean`: 定数（$m$ はちょうど 0）
- **採点**: `centered_r2` を calib・sel・final で求める。4 つの $q$ は、項目ごとの $e_i$ と $v_i$ をそれぞれ足して 1 つの $m$ にする。sel の候補の `id_easy` は並べるだけ
- **導出（K3 の族 $\hat t_p = A_p u$ の負の対照）**: `pred` の入力は $(A_1 u, \dots, A_{16} u) = A u$（$A$ は 256 × 16）、`pool` は $\bar A u$（$\bar A = \frac{1}{16} \sum_p A_p$）。$\bar A$ が正則なら、どちらも $u$ の線形な 1 対 1 の関数で、当てはめの組の上で同じ列空間を張る。そのため $\alpha \to 0$ の当てはめの予測はちょうど一致し、母集団でも同じ $m$ になる。$\bar A$ が正則で条件数がよい K3 の族では、`pred` − `pool` は 0 になる。Codex さんの例（$A_B = -A_A$ で `swap` が 0.5 にならない族）は四半分どうしの符号の反転なので、1 つの四半分の中の平均は $\bar A = A_A$ のままで、ここに入る
  - **$\bar A$ が特異に近いとき**（レビューで分かった限界）: $A_p = A P_1 + (-1)^p A P_2$（$P_1$・$P_2$ は補い合う射影）は場面だけを持つ K3 の族だが、$\bar A = A P_1$ で $P_2 u$ が `pool` から消え、`pred` が `pool` を上回る。そこで行に `pool` の入力の共分散の条件数 `cond`（四半分ごと、当てはめの組）を残し、C1′ を読むときに見張る
  - **`pred_k3` と `pool` を同じ当てはめにする**: `pool` を $X$（$n \times d$）、`pred_k3` を $X' = X J$、$J = (I_d, \dots, I_d)$（$d \times P d$、$J J^\top = P I_d$）とする。$\mathrm{tr}(X'^\top X') = P\,\mathrm{tr}(X^\top X)$ なので、尺度 $c'$ の $\alpha' = c'\,\mathrm{tr}(X^\top X)/d$。push-through の恒等式 $(J^\top G J + \alpha' I)^{-1} J^\top = J^\top (P G + \alpha' I)^{-1}$ から $X' (X'^\top X' + \alpha' I)^{-1} X'^\top = X (X^\top X + \frac{\alpha'}{P} I)^{-1} X^\top$。同じ $c$ では $u$ にかかる罰則が `pool` の $1/P$ になり、`ALPHA_SCALES` は 10 倍刻みなので、`pool` と同じ罰則の $c$ は格子の上に無い。そこで $c' = P c$（$c$ は `pool` で選んだもの）に固定すると、$\alpha'/P$ が `pool` の $\alpha$ に等しく、予測は丸めを除いて一致する
  - **V-E1′3 の許容 $10^{-6}$**: 2 つは厳密な算術では同じ当てはめなので、差は解く操作の丸めだけである。後退安定な float64 の解法の相対誤差は $\varepsilon \kappa$ 程度で、$\kappa = \mathrm{cond}(X^\top X + \alpha I) \le 1 + \lambda_{\max}/\alpha \le 1 + d/c$（$\alpha = c\,\mathrm{tr}/d \ge c\,\lambda_{\max}/d$）。$d$ = 16、$c \ge 10^{-8}$ では $\kappa \le 1.6 \times 10^9$、$\varepsilon \kappa \approx 3.6 \times 10^{-7}$ なので、$\lvert \Delta m \rvert \le 10^{-6}$ とする（`pred_k3` の 256 次元の系も $\kappa \le 1 + 16/c$ で同じ）。前の $\delta_w$ は、ほぼ同じ 2 つの予測の差を対にした $2\,\mathrm{SE}$ でとても小さく、格子の違いによる決定的な差で偽って外れた（レビューの合成の数値例）
- **対象**: V18c の長い run の step 0・6000・60000（2 学習率 × 2 seed）。選ぶ候補 12 本の step 6000 にもかけて並べる（選ぶのには使わない）
- 出力: `posthoc_fill_sem/rows/<step>-e1f.json`（`--split sem` の E1 と同じ、分け方専用の場所）。行は `k`、`stage`、`alpha`・`scale`（四半分ごと）、`cond`（`pool` だけ）、`m_calib`・`m_sel`・`m_final`、`e_sel`・`e_final`・`v_sel`・`v_final`（項目ごと）、`id_easy_sel`
- 費用（推測）: 1 checkpoint で 12 個のマスクの予測器の前向きを約 1 万 stack ずつ（約 12 万 stack 分）。4090 で 3〜5 分

**5. calib の重なりの解消（V18c にかけるとき）**

- `fill_eval run … --split sem --sem <cache>` で、$\alpha$ を `zurich_split` の calib の格子の stack で選ぶ。凍結した読み出しの E1 の候補は、512 個のうち sel と final に入るものに限る（数 `n_cand` を行に書く。偶然の値は $1/n_{\mathrm{cand}}$）。`id_hard` は前後 ±32 秒の格子が同じ区間に収まる候補だけにする（数を `n_hard`）
- V18c にかける凍結した読み出しの E1 の的は、`color` と `quad`（`--sem` で渡すキャッシュから）にする。32 px の `incep` は、全体を見たトークンからさえ読めなかったので、V18c にはかけない
- 旧 checkpoint の診断（1）は、いまの分け方のままにする（観測した値を調べるため）

### 実装のテスト（理論のオラクル）

- **`centered_r2`**: 予測 = 的なら 1。定数の予測はちょうど 0。予測に定数を足しても変わらない。的と予測を同じ正の数倍しても変わらない。予測を的の行の置換 $\pi$ にしたときの $m = -1 + 2 \sum_i \langle \tilde y_{\pi(i)}, \tilde y_i \rangle / \lVert \tilde Y \rVert^2$ は、一様な置換について平均すると $-1$、不動点の無い置換に限ると $-1 - 2/(n - 1)$ になる（$\pi(i)$ が $i$ 以外で一様なら $\mathbb E\, \tilde y_{\pi(i)} = -\tilde y_i / (n - 1)$）。乱数の置換 $10^4$ 個の平均が、モンテカルロの誤差の中で一致する
- **`rank_bound`**: ランダムなランク $r$ の中心化した予測の $m$ が上限を超えない。$\tilde Y$ の上位 $r$ 個の特異値で切った予測が上限にちょうど届く
- **入れ子**: $c$ を最小（$10^{-8}$）にした当てはめの組の上の $m$ は、`pca16` ≤ `pca64` ≤ `pca256` ≤ `pca1024`（最小二乗の入れ子の性質で、当てはめの組の上では $10^{-6}$ の中で成り立つ）。`color` が `color8` の線形の関数であること（4 つの平均の行列で、ちょうど一致）
- **`z_k3`**: `z_k3` が $W\,\mathrm{vec}(\mathbf 1 \otimes \bar t)$ と一致する。中心化した `z_k3` を並べた行列の数値のランクが 16 以下。`init_c_k3` の $m$ が `rank_bound(…, 16)` を超えない
- **`zurich_split`**: 3 つの組が交わらず、各区間の先頭 30 個がどの組にも入らず、残りの和が格子のすべて。同じ入力で同じ結果
- **`block_bootstrap`**: 独立な項目（分散が既知）で、差の標準誤差が $\sigma/\sqrt n$ にモンテカルロの誤差の中で一致する。ブロックの中で一定の値（ブロックごとに独立）で、標準誤差がブロックの数で決まる値に一致する。同じ符号どうしの差は 0
- **`integrated_time`**: AR(1)（係数 $\phi$）の長い系列で $\tau$ が $(1 + \phi)/(1 - \phi)$ に誤差の中で一致する
- **`hires`**: 合成の動画（`imageio_ffmpeg` の ffmpeg で `testsrc` から作る 854×480・2 秒、可逆の codec）で、320 の 5×5 の平均が、いまのフィルタの 64 px の出力と位置の確かめ (a)・(b) を満たす。1 フレームずらした一覧では (b) が外れて止まる。一覧に無いフレームを書かない（`slow`）
- **的の感度の変換**: 明るさと白の釣り合いが手計算と一致する。ぼかしの核の和が 1。`match` の後のチャネルの平均と標準偏差が、丸める前に $x$ と $10^{-6}$ の中で一致する
- **`e1diag`**: 恒等式の残差が $10^{-9}$ 以下。$s(0)$ がいまの `swap` と一致する。Codex さんの反例（1 次元で $D = T = (-5, 1, -1, 5, 1, -1)$）で、半周のずらしの内積の平均が $-23/3$、勝率が 2/3 になる。$d$ がすべて同じなら（中心化で 0）、どの $\tau$ でも 0.5
- **`oracle_k3`・`pred_k3`**: E1 の合成の組で、`swap` がちょうど 0.5、`n_tie` が候補の数
- **`e1f`**: 12 個のマスクが `mask_family(k, 4)` に入り、どれも $Q_q$ を隠し、$k$ = 12 で見えるのが対角の四半分だけ。`e1f_fits` が `select_ridge` の経路で `pool` の尺度を選んだとき（格子の内側に来る雑音の量で）、`pred_k3` の尺度が `pool` の 16 倍で、2 つの予測が $10^{-9}$ の中で一致する。同じ $c$ では一致しない。合成の K3 の予測器（ランダムな $A_p$、$\bar A$ が正則）で、$c$ を最小にした当てはめの組の上の `pred` と `pool` の $m$ が $10^{-8}$ の中で一致する。位置ごとに違う成分を持つ合成の予測器では、`pred` が `pool` を上回る。`mean` の $m$ はちょうど 0
- **既存の値が変わらない**: `select_ridge` の既定、`Space` の 1 つの尺度、`fill_eval run`（`--split` なし）の行が変更前と一致する

### 実装の注記（2026-11-25、数値を読む前）

上の設計を実装したときに、設計が書いていなかった細部をこう決めた。

- **的の感度の範囲**: 内容の入れ替えの相手は「同じ組の中」から引くので、感度は calib・sel・final に入る格子（各区間の先頭 30 個を除いた約 3714 個）で求める。捨てた 30 個は使わない
- **入れ替えの相手の引き方**（`sem_eval.far_pairs`）: 乱数の置換を直していく方法では、相手が見つからずに止まる組があった（区間が短い合成のデータで確かめた）。そこで、`SENS_SEED` で並べた順に、増加路（幅優先）で 1 対 1 の対応を作る。300 個以上離れた対応が存在すれば、必ず見つかる
- **当てはめの組の半分**: span の奇数の区間 $j$ を、$\lfloor j / 2 \rfloor \bmod 2$ で 2 つに分ける（奇数の区間を交互に）
- **凍結した読み出しの E1（`--split sem`）の $\alpha$**: 選ぶ組だけを `zurich_split` の calib に替え、選ぶ基準は既存の `r2` のままにした（設計は組だけを変えると書いている）。`e1f` は設計どおり `centered_r2` で選ぶ
- **`e1f` の `id_easy_sel`**: 4 つの四半分の予測を横に並べ（$4 \times 64$ 次元）、sel の的の中から、格子の平均を引いた $\cos$ の最近傍で当てる。`mean` は方向を持たないので書かない
- **V-m5 の $\delta_1$**: README の式 $2\sqrt{\mathrm{SE}_{\mathrm{blk}}^2 + 2\sigma_{\mathrm{seed}}^2}$ の $\mathrm{SE}_{\mathrm{blk}}$ を、どの 2 本の差のものにするかは決めていなかった。`judge_m.py` は、同じ学習率の seed 0 の候補のすべての対の差の $\mathrm{SE}_{\mathrm{blk}}$ のうち最大のもの（いちばん厳しい側）を使う
- **V-E1′3 の組**: $\lvert m(\texttt{pred\_k3}) - m(\texttt{pool}) \rvert \le \delta_w$ は、C1′ と同じ final で確かめる
- **テストのための引数**: `sem_eval` と `fill_eval` の評価に `span`（当てはめの組の span、既定は `SPAN`）を足した。合成のデータのテストを速くするためだけで、既定の値と振る舞いは変えていない

レビューを受けて、数値を読む前に次を直し、決めた（2026-11-25）。

- **$L$ の上限**: 155 を 154 に直した（上の「揺れ」の節）。実際の分け方（格子 3899、6 区間、先頭 30 を捨てる）で、上限の長さで各組がちょうど 8 個のブロックになることをテストで確かめる
- **`pred_k3` の $\alpha$**: `pool` で選んだ $c$ の 16 倍に固定し（`fill_eval.e1f_fits`）、V-E1′3 を $\lvert \Delta m \rvert \le 10^{-6}$ の実装の確かめにした（上の導出）
- **K3 の族の言い過ぎ**: 「K3 の族のすべてで 0」を「$\bar A$ が正則で条件数がよい K3 の族で 0」に直し、`pool` の `cond` を行に残す
- **`--split sem` の出力の場所**: `posthoc_fill_sem/`（`fill_eval.OUT_SEM`）に分けた。同じ `posthoc_fill/` に書くと、後で `--split` なしの `run` をかけたときに、`config.json` の照合が分け方の鍵を見ずに通り、分け方の E1 を済んだものとして飛ばして、別の分け方の E1e・E2 を混ぜていた。`config.json` の `cand` と `n_hard` も、512 個のままではなく分け方の候補を書く。これで V18c の長い run にも、`--split` なしの `diag` を `posthoc_fill/` にかけられる
- **V-E1′2**: README どおり V18c の checkpoint で確かめるため、長い run の 0・6000・60000 にも `fill_eval diag` をかけ、その残差で判定する（`judge_m` の `resid`）。旧 checkpoint の残差（`resid_old`）は H-bug の記述に使う
- **$\sigma_{\mathrm{seed}}$**: 学習率ごとに seed 0 の上位 2 設定（選び方の 2）の、3 seed のそろったものだけから求め、自由度を書く。選び方の 3 で足した設定は入れない。「3 seed の設定が 2 つ未満なら止める」は学習率ごとに数える
- **足した seed が落ちた設定**: 選び方の 2 と 4 の候補から外し、`removed` に書く。その設定の seed 0 は、選び方の 1 の最大と 3 の $\delta_1$ の比べに残す（seed 0 の値そのものは、足した seed の合否で変わらないため）
- **選び方の 3 の対象**: seed 0 の最大から $\delta_1$ 以内で、まだ 3 seed がそろわず、落ちた seed も無い設定を `to_add` に書き、それが残る間は選び方の 4 に進まない。選び方の 4 の候補は、最大・選び方の 2・3 の設定のうち 3 seed がそろったもの
- **C4′ の $\delta_w$**: $(p_{60} - q_{60}) - (p_6 - q_6)$ の、係数 $(1, -1, -1, 1)$ の 4 つの符号（final の $e_i$、同じ $v_i$ とブロック）の差の差の $2\,\mathrm{SE}_{\mathrm{blk}}$。60000 の $p - q$ だけの $\delta_w$ は使わない
- **H-time と H-skew のまとめ方**（README は行ごとの条件だけを決めていた）: 行は (checkpoint, 的, 段) ごと。H-time は、step > 0 のすべての行（`pred` と `oracle`）が「$C(1) > 0$、$C(2) > 0$、$C(256) < 0$、$s(256) < 0.5$」を満たし、かつ step 0 の `pred` の行の少なくとも 1 つが満たさないとき。H-skew は、行ごとに「$s_{\mathrm{off}} < 0.5$、かつ $C^{\mathrm{nw}} > 0$ の $\tau$ の過半数と $C^{\mathrm{nw}} < 0$ の $\tau$ の過半数で $s^{\mathrm{nw}} < 0.5$」を判定し、その行が全体の過半数のとき。どちらも記述で、合否には使わない
- **V-m6 の組**: `mean` も含めたすべての物差しの組で確かめる（`mean` の半分の値はちょうど 0）
- **V-m0 の「全フレーム」**: 高解像度のフレームの (a)・(b) は、残したすべてのフレーム（的が読むフレームのすべて）で確かめる。残さないフレームはどの的にも入らない。そのかわり、的を作る前（`sem_eval.build_targets`）に、5×5 で平均した高解像度のフレームと、符号の見る stack の最後のフレーム（`SemSets.last`）の差の絶対値の平均が 1.0 以下であることを確かめ、外れたら止める（`places_max_diff`）。場所から stack への対応も V-m0 に入る（2026-11-25 に、結果を見た後で上の「高解像度のフレーム」の節のとおり替えた）
- **$\alpha$ の格子の端**: `sem_eval` の行に `alpha_edge`（選んだ $c$ が $10^{-8}$ か 1 か）を書き、`judge_m` が端に当たった物差しを並べる
- **再現性**: 的のキャッシュを使い回すときも Inception の sha256 を照らし合わせる。`targets.json` にコードの出どころ（`of_diagnosis` の `code` など）を書く。キャッシュの名前と照合は、結果を変えない `batch` を除いた設定で行う。物差しの行に、`v16`・`v17` の checkpoint と `init_c` の run の場所（`source`）を書く

- V20 で良かった正則化を、ノードの中で閉じた局所的な形にする。時定数は秒で定義し、更新の式にステップ数を含めない
- BP の勾配をオラクルにしたテスト（小さなネットで一致を確かめる）を先に書く
- V22 は V17 と同じく、`data.layout=chunk data.streams=10`、optimizer の時定数は B = 1 の 10 分の 1 で回す
