# JEPA: 単一ストリームから SIGReg で JEPA を学ぶ（計画、2026-11-23）

V17 で VAE の検証を締めくくり、検証する対象を JEPA に移す（[memory/project_v17_to_jepa.md](../../../memory/project_v17_to_jepa.md)）。`exp/video` の M17 で決着しなかった JEPA の問いに、VAE と同じ順序で答えを出す。番号は `exp/vision` の V18 から続ける。

## 背景

- **VAE は、普通の学習を先に確かめる順序で決着した。** V16 で、BP と i.i.d. なミニバッチなら同じモデルが学べる（span 0.164）ことを確かめた。そのうえで V17 で、ストリームの PC-ALM でも長く学べば下がる（480 万 stack で span 0.211）ことを示した
- **M17 の JEPA は、この順序を踏んでいなかった。** BP と i.i.d. なミニバッチで JEPA + SIGReg が学べることを確かめないまま、B = 1 のストリームで崩壊への対処に追われていた。そのため、学べない原因が (1) 実装・モデル・評価、(2) 学習の設定、(3) ストリームの相関のどれなのかを分けられなかった
- **評価にも穴があった。** M17 の再構成の基準は、tubelet ごとの平均の色だけの符号でも満たせた。V16 では、後から学ぶデコーダの `recon_blur` が頭打ちになり、符号の差を映さなかった
- **ユーザーの仮説**: SIGReg は、標本が i.i.d. であることを前提にした検定統計量である。ストリームでは時間相関のためにデータポイントを独立に扱えず、前提が成り立たない。一方で、時間相関はそれ自体が手がかりにもなる

## 共通の設計

- **モデル**: V14・V16・V17 と同じ ViT-S（幅 1024、μP、patch 16、64×64、8 枚の stack を early fusion）。VAE の頭（`2D` への写像）を除いたエンコーダを使い、VAE と同じ物差しで比べる。トークンは 4×4 = 16 個
- **表現**: トークンごとに $d$ = 64 次元に写し、平らにした列 $z \in \mathbb{R}^{D}$（$D$ = 1024）とする（2026-11-13 の決定。$D$ が十分小さいことだけが制約）
- **目的**: LeJEPA の形にする。エンコーダは 1 つで、EMA のターゲットも stop-gradient も入れない。予測器が、見えるトークンから隠した位置のトークンの埋め込みを当てる。損失は $(1 - \lambda) L_{\mathrm{pred}} + \lambda\, \mathrm{SIGReg}$
- **マスク**: 空間のブロックを stack の全フレームに同じ位置で掛ける（V-JEPA の tube）。early fusion なので、課題は空間の補完だけで、未来のフレームの補完は含まない
- **SIGReg**: データポイント（stack）ごとに $z$ にかける（トークンごとにはかけない。位置だけの解が安く通るため、2026-11-13 に棄却）。実装は `exp/lib/sigreg.py` の Epps–Pulley を使う
- **バッファ**: 過去の $z$ のバッファは FIFO にする（2026-11-23、ユーザーの決定）。これまでのランダムな置き換え（`insert_`）は、各行の生存時間が確率的になる。FIFO なら、バッファは直近の決まった時間の幅をちょうど覆う

## V18: BP と i.i.d. なミニバッチで学べるか（詳細設計、2026-11-23）

run の一覧・判定・長い run の規則・予想・反証は [README の「V18」の節](../README.md)（回す前に決めたこと）に書いた。ここには、実装できる粒度の設計と、目的の式の自明な解の導出を書く。

### ユーザーが決めたこと

- early fusion のまま（8 枚 × 3 チャネル = 24 チャネル、64×64、patch 16 → 4×4 = 16 トークン）。patch 8 にはしない
- **マスク率に注意する**: トークンが 16 個しかないので、隠すトークンの数をちょうど $k$ 個に固定する。マスク率 $r \in \{0.25, 0.5, 0.75\}$（$k$ = 4、8、12）を掃引の軸にする。$r$ = 0.75 でも見えるトークンが 4 個残る
- batch は 128。SIGReg は batch の中の標本だけで計算する（バッファは V19 から）
- 掃引: 学習率 $\{10^{-4}, 10^{-3}\}$ × $\lambda$ $\{0.005, 0.05, 0.5\}$ × $r$ の 18 本、seed 0、6000 step。長い run は 60000 step

`exp/video/jepa` は import しない。M17 の `block_masks` と `multiblock_masks` は使わない。`block_masks` は平面の上に一様に置くので、中央の位置ほど多く隠れる。`multiblock_masks` は、ちょうどの数にするために見える patch をランダムに足して隠すので、ブロックの形が崩れる。移すのは、矩形を格子に塗る考え方（`paint`）だけである。

### エンコーダと表現

- **エンコーダ**: `build_vae(conf, seed=conf.seed)` と同じ手順・同じ seed で ViT（`_vit_parts`）を作り、node 4 の `head` だけを使わない（最後の `LayerNorm` は使う）。head は node 4 の最後に引かれるので、ブロックの初期値は V16 の VAE（`b2006f0a-s0` の config、seed 0）とちょうど一致する（テストで確かめる）。config は V16 と同じ `config.yaml` を読む。デコーダと $\ln\sigma$ は作らない
- **射影**: $P$ = `Linear(1024 → 64)`、全位置で共有。トークン $h_p$（最後の `LayerNorm` の後）から $z_p = P h_p \in \mathbb{R}^{64}$。$z = (z_1, \dots, z_{16}) \in \mathbb{R}^{1024}$（位置は行優先）
- **標的側**: stack の 16 トークンすべてをエンコーダに通して $z$ を作る。stop-gradient も EMA もない
- **文脈側**: 同じエンコーダに、見える $16 - k$ 個のトークンだけを通す。パッチの埋め込みに位置の符号を足した後で、隠したトークンを落とす（V-JEPA と同じ）。注意は見えるトークンの中だけで働くので、隠した patch の画素は文脈側の出力に影響しない（テストで確かめる）。$k$ は batch の中で同じなので、形は `(B, 16 - k, 1024)` にそろう
- **予測器**: 幅 256、4 head（`HEAD_DIM` = 64）、pre-norm の `Block` を 4 段（エンコーダと同じ段数）。V-JEPA の予測器と同じ形で、次の順に計算する
  1. 文脈側の出力（幅 1024）を `pred_embed` = `Linear(1024 → 256)` で写し、その位置の符号 `sincos_2d((4, 4), 256)` を足す
  2. 隠した位置には、学習する 1 本のベクトル（mask token、256 次元）にその位置の符号を足したものを置く
  3. 16 個を `Block` 4 段に通し、`LayerNorm` の後、`pred_out` = `Linear(256 → 64)` で写す。隠した位置の出力を $\hat z_p$ とする
- 予測器の大きさは掃引しない。下の導出では、予測器が弱いほど健全な解の予測の損失 $\ell_H$ が大きくなり、stack の中で一定の解が有利になる。そこで段数はエンコーダにそろえ、弱くはしない

### μP での役割

エンコーダは VAE と同じ規則（`mup_roles`・`mup_lr`・`_mup_init_`、$k_w$ = 1024 / 256 = 4）。新しいパラメータは次のとおり。予測器の幅は 256（= `BASE_WIDTH`）に固定し、エンコーダの幅とともには変えない。

| パラメータ | 役割 | 学習率の倍率 | 初期値 |
| -- | -- | -- | -- |
| エンコーダ（パッチの埋め込み・ブロック・`LayerNorm`） | VAE と同じ（input・hidden・vector） | `mup_lr` と同じ | `build_vae` と同じ |
| 射影 $P$（幅 1024 → 64） | output（VAE の head と同じ、幅から固定の大きさへ） | $k_w^{-1}$ = 1/4 | LeCun（std $1/\sqrt{1024}$）× $k_w^{-1/2}$、bias 0 |
| `pred_embed`（幅 1024 → 256） | output（エンコーダの幅から固定の大きさへ） | $k_w^{-1}$ = 1/4 | 同上 |
| 予測器のブロック（256 → 256） | hidden（幅 256 なので $k$ = 1） | 1 | `_init_vit` の std 0.02 |
| `pred_out`（256 → 64） | output（$k$ = 1） | 1 | LeCun |
| mask token・bias・`LayerNorm` | vector | 1 | mask token は std 0.02 の truncated normal、他は `_init_vit` |

### マスク

- **族 $F_k$**: 4×4 の格子をトーラス（上下・左右の端をつないだもの）とみる。高さと幅が 1〜4 の矩形を 1 つ、または 2 つ置いた和集合のうち、ちょうど $k$ 個の位置を覆うものを、重複を除いた集合として列挙する。$|F_4|$ = 632、$|F_8|$ = 436、$|F_{12}|$ = 232（うち矩形 1 つのものは 24、8、8）
- **引き方**: 各 stack に、$F_k$ から一様に 1 つ選ぶ（batch の中で独立、`seed + MASK_SEED` の生成器）。early fusion なので、同じ位置が stack の 8 枚すべてで隠れる（V-JEPA の tube にあたる）
- **位置ごとに一様**: $F_k$ はトーラスの平行移動で閉じているので、族の上の一様分布では、各位置が隠される確率はちょうど $k/16$ になる。族の上で数えると、各位置を覆う要素は $k$ = 4 で 158、8 で 218、12 で 174 個（どれも $k|F_k|/16$）
- **トーラスにした理由**: 平面の上に一様に置くと、中央の位置ほど多く隠れる。代わりに、端をまたぐブロックは、平面では反対側の端にある 2 つの矩形になる
- **形の分布**（トーラスの上でつながった成分の数）: $k$ = 4 は 1 成分 280・2 成分 352、$k$ = 8 は 392・44、$k$ = 12 は 232・0。テストで、この数を別の書き方の総当たりと照合する
- **マスク率と形の交絡**: 2 成分の割合は、$k$ = 4 で 56%（1×1 の孤立したセルを含む）、8 で 10%、12 で 0% である。そのため $r$ の効果には、隠したブロックがまとまっているかの効果が混ざる。V18 では分けない（$r$ ごとに族を変えずに一様に引くことを優先した）。$r$ の差を読むときは、この交絡を併記する

### 損失

$$
L = (1 - \lambda)\, L_{\mathrm{pred}} + \lambda S, \qquad
L_{\mathrm{pred}} = \frac{1}{B k d} \sum_{n=1}^{B} \sum_{p \in M_n} \lVert \hat z_{n,p} - z_{n,p} \rVert^2
$$

- $M_n$ は stack $n$ の隠した位置（ちょうど $k$ 個）、$d$ = 64。$L_{\mathrm{pred}}$ は座標あたりの二乗誤差で、LeJEPA と同じ尺度である。SIGReg が満たされると $z$ の座標の分散は 1 なので、位置ごとの平均で当てる自明な予測の $L_{\mathrm{pred}}$ は約 1 になる
- $S$ = `exp.lib.sigreg.sigreg(z, z[:0], A)`。batch の $N = B$ = 128 個の $z \in \mathbb{R}^{1024}$ の Epps–Pulley の統計量（`T_POINTS` の 17 点）を、$M$ = 1024 本の方向 $A$ で平均したもの。$A$ は step ごとに `seed + DIRECTION_SEED` の生成器から引き直す（標準正規を引いて長さ 1 にする。batch の中では同じ方向）
- 統計量は $N$ 倍の形（LeJEPA と同じ）で、$z \sim N(0, I)$ なら $N$ によらず約 1.05 になる

### 自明な解の導出（$N$ = 128、$D$ = 1024）

統計量の期待値（$t$ は全実数で積分。台形則の 17 点でもほぼ同じ値になる）:

- **健全な解** $z \sim N(0, I_D)$: $E[N\lvert\hat\varphi - \varphi\rvert^2] = 1 - e^{-t^2}$ なので、$E[S] = \int (1 - e^{-t^2})\, e^{-t^2/2}\, dt = \sqrt{2\pi} - \sqrt{2\pi/3} = 1.059$。$N$ によらない
- **定数** $z_n = c$: 方向 $a$ への射影は定数 $s = a^\top c$ で、$s = 0$ のとき最小。$S = N \int (1 - e^{-t^2/2})^2 e^{-t^2/2}\, dt = N(\sqrt{2\pi} - 2\sqrt{\pi} + \sqrt{2\pi/3}) = 0.409 N$ = 52.3
- **共分散 $\Sigma$（$\mathrm{tr}\,\Sigma = D$）のガウス**: 射影の分散 $a^\top \Sigma a$ が方向によって揺れる分だけ罰を受ける。揺れが小さいとして展開すると、超過は $\frac{N}{4} \int t^4 e^{-3t^2/2}\, dt \cdot \mathrm{Var}_a(a^\top \Sigma a) \approx 0.241\, N\, (1/r_2 - 1/D)$。$r_2 = D^2 / \mathrm{tr}\,\Sigma^2$（participation ratio）
- **数値で確かめた値**（`epps_pulley`、$M$ = 1024、$N$ = 128、方向を引き直した平均）: 健全 1.05、定数 52.3、stack の中で一定 1.55、$\Sigma$ のランク 1 で 22.4、16 で 3.4、64 で 1.38、128 で 1.32

健全な解の予測の損失を $\ell_H$ とする（座標あたり、0〜1 程度）。3 つの自明な解は次のとおり。

1. **定数**: $L_{\mathrm{pred}} = 0$、$S$ の超過は 51.3。目的の式が健全な解を選ぶのは $\lambda > \ell_H / (\ell_H + 51.3)$ のとき。$\ell_H \le 1$ なら $\lambda > 0.019$ で排除される。**$\lambda$ = 0.005 では、$\ell_H > 0.26$ なら排除されない**
2. **位置だけの関数** $z_{n,p} = g(p)$: stack の単位で見ると、$z_n$ は入力によらない定数なので、1 と同じ（超過 51.3）
3. **stack の中で一定** $z_{n,p} = h(x_n)$、$h \sim N(0, I_{64})$: $\Sigma = (\mathbf{1}\mathbf{1}^\top) \otimes I_{64}$ で $r_2$ = 64、超過は約 0.45（数値では 0.50）。$h$ を、どの見える部分からも推定できる量（場面全体の明るさ・色・種類）にすれば $L_{\mathrm{pred}} \approx 0$ になる。排除されるのは $\lambda > \ell_H / (\ell_H + 0.50)$ のときで、$\ell_H$ = 0.3、0.5、0.8 では 0.38、0.50、0.62。**$\lambda \in \{0.005, 0.05\}$ では排除されない。$\lambda$ = 0.5 でも、$\ell_H > 0.5$ なら排除されない**
   - **この解は族をなす**: 位置ごとの可逆な線形写像 $A_p$（直交行列 $R_p$ など）を掛けた $z_{n,p} = A_p h(x_n)$ でも、$L_{\mathrm{pred}} = 0$ のままにできる。予測器は位置を知っているので、$A_q A_p^{-1}$ で写せばよい。$A_p$ が直交なら $\Sigma$ のスペクトルは変わらず（$r_2$ = 64）、SIGReg の超過も同じになる。共有の $P$ の前のトークン $h_p$ は位置の符号を持つので、エンコーダはこの形を作れる。数値（$N$ = 128、$D$ = 1024、$M$ = 1024）: 恒等の版は $S$ = 1.62・`rho_in` = 0.000・実効ランク 49.5、$R_p$ で回した版は $S$ = 1.63・`rho_in` = 0.932・実効ランク 49.5。独立なガウスでも `rho_in` は 0.937 である。したがって `rho_in` は恒等の版しか捕まえられない。評価では、族全体で 1 になる、基底によらない量 `token_r2`（下）で測る

一般に、エンコーダは、見える部分から予測できない位置ごとの内容を捨てて $r_2$ を下げると、$L_{\mathrm{pred}}$ を下げる代わりに約 $0.241 N\, \Delta(1/r_2)$ の罰を払う。罰は $N$ に比例するので、$N$ = 128 の batch の SIGReg は、$r_2$ を $N$ 程度まで下げることをほとんど罰しない。$N$ = 1024 なら、stack の中で一定の解の超過は 3.46（数値）で、$\ell_H$ = 0.5 なら $\lambda > 0.13$ で排除される。V18 では $N$ を変えない（バッファで標本を増やすのは V19）。この解は目的の式では排除されないので、評価で直接測る（下の `token_r2`）。崩壊が起きたら、まずこの導出と照らし合わせる（[memory/feedback_simple_fundamental.md](../../../memory/feedback_simple_fundamental.md)）。

この結論は 3 の解に限らない。「トークンごとに違う線形の読み出しで、どの見える部分からも推定できる約 128 次元の大域的な潜在を表す」符号（$r_2 \approx N$ = 128）の超過は、約 $0.241 \cdot 128 \cdot (1/128 - 1/1024) \approx 0.21$ しかない。この符号は $L_{\mathrm{pred}} \approx 0$ と両立し、`token_r2` ≈ 1、`rho_in` ≈ 15/16 になる。さらに、位置ごとの内容を一部だけ捨てた符号は、`token_r2` が 1 より小さいまま、同じ方向に寄る。したがって、崩壊の極端な形（3 の族）は `token_r2` で捕まえられるが、どこまで位置ごとの内容を残したかは、SIGReg の値でも `token_r2` でもなく、probe（`recon_blur`）でしか分からない。

上の比較は、目的の式の大域的な最小どうしの値の比較であって、学習の動きの議論ではない。勾配法の初期の動きでは、SIGReg は $N$ 倍の形なので 1 標本あたりの勾配が $O(1)$、$L_{\mathrm{pred}}$ は平均なので 1 標本あたり $1/B$ になる（LeJEPA と同じ尺度）。1 標本あたりの実効的な重みの比は $\lambda B / (1 - \lambda)$ で、例えば $\lambda$ = 0.005 でも約 0.64 である。どちらの解に向かって動くかは、この導出だけでは決まらない。

### 学習（`jepa_iid.py`）

- **データ**: `iid.Units(conf, root, "all", seed=conf.seed + DRAW_SEED)` から 128 stack を、一様に、重複を許して引く（V16 の `all`）。次の batch はスレッドで先に読む（V16 と同じ）
- **optimizer**: AdamW（$\beta$ = 0.9・0.999、eps 1e-8、weight decay 0）。`jepa_mup_lr` の倍率ごとに param group を分ける。clip しない。学習率は `iid.lr_at`（最初の 1000 step で線形に上げ、`--steps` で cosine で 0 に下げる）
- **乱数**: 生成器を分ける。初期値（エンコーダは seed、射影は seed + `PROJ_SEED`、予測器は seed + `PREDICTOR_SEED`）、stack（seed + `DRAW_SEED`）、マスク（seed + `MASK_SEED`）、方向（seed + `DIRECTION_SEED`）。`configure_determinism` を使う
- **checkpoint**: step $s$ の時刻は、見た stack × 0.1 秒（V16 と同じ）で、$t = 12.8 s$ 秒。短い run は step 0、1000、2000、4000、6000（$t$ = 0、12800、25600、51200、76800 秒）。長い run は 0、2000、6000、10000、20000、30000、40000、50000、60000（$t$ = 768000 秒まで）。長い run の 6000 step は、短い run の 6000 step とは学習率の予定が違うので同じではない
- **出力** `<out>/`:
  - `config.yaml`（読んだ config、`device` を書き換えたもの）
  - `jepa.json`: $r$、$k$、$\lambda$、$d$、$M$、予測器の形、学習率、steps、batch、warmup、seed たち、optimizer、族の大きさ $|F_k|$、units の数、determinism
  - `train.jsonl`: 100 step ごとの平均。`loss`、`pred`、`sigreg`、`grad_norm`（clip の前）、batch の `z_var`（座標ごとの分散の平均）と `rho_in`、`lr`、`sec`
  - `jepa.json` の `provenance`: `provenance.of_diagnosis` の記録（host の `code/<snap>` から走らせれば、その `CODE.json`。snapshot と mujou のコミットを含む）、host、コマンド行、環境
  - `ckpt/<t>.pt`（`ckpt.save_eval`、program `"jepa"`、modules は `encoder`・`proj`・`predictor`）
- 損失が有限でなくなったら止める（`FloatingPointError`、V16 と同じ）

### 評価（`jepa_eval.py`）

符号は、どれも「stack → 符号のベクトル」の関数として扱う。JEPA の符号は標的側の平らな $z$（1024 次元）。VAE の `VaeCode` の `decode`（システムの描き戻し）は使わない。

- **probe**（`stream_eval.StreamEvaluator` の部品、`--span 6000` の視点）: 学習のストリームの 0〜6000 秒の奇数番目の 10 秒の区間の約 6000 組で、後から学ぶデコーダ（4 seed × 2000 step）と線形の動力学を当てはめる。span・after・zurich（val の 1024 窓）で、`recon_blur`、`dyn_1/copy_1`、`rank` を出す
  - V16 は 1800 秒ぶん（1800 組）で当てはめた。V17 は 6000 組で、同じ学習前のモデルの zurich の `recon_blur` が 0.502 から 0.404 に下がった。当てはめる組の数が値を決めていたので、V17 と同じ 6000 秒にそろえる
  - `StreamEvaluator.probes` のうち `decode` を使う部分（絵の 2 段目）を、符号だけのものでは外せるようにする。VAE の行は変えない（`tests/vision/test_stream_eval.py` はそのまま通す）
- **JEPA の量**（zurich の val の各窓の最初の stack、$N$ = 1024、checkpoint ごと）
  - `pred`: 固定したマスク（各 stack に $F_k$ から 8 個、`EVAL_MASK_SEED`）での $L_{\mathrm{pred}}$。`pred_triv`: 同じマスクで、隠した位置を「位置ごとの $z_p$ の平均」（当てはめの組の stack で求めたもの）で当てたときの値。`pred_ratio` = `pred` / `pred_triv`。`pred_triv` は学習のストリームの平均で zurich を当てるので、ドメインのずれの分だけ大きくなる。読みの幅を見るため、zurich 自身の calib の窓の位置ごとの平均で当てた `pred_triv_calib` と `pred_ratio_calib` も並べる
  - `sigreg_zurich`: zurich の 1024 個の $z$ の $S$（固定した 1024 本の方向、`EVAL_DIRECTION_SEED`）。同じ方向・同じ $N$ での、$N(0, I)$ の標本の値（約 1.06）と定数の値（0.409 $N$ = 419）を同じ行に書く。zurich は 1 本の動画なので、健全でも $N(0, I)$ の値には届かない。並べるだけにする
  - `sigreg_heldin`: 学習の units から一様に引いた 128 stack × 16 batch の $S$ の平均（固定した方向と生成器）。学習中の $S$ と同じ尺度で、参照は 1.05 と 52.3（評価が同じ方向で計算して行に書く）
  - `token_r2`: 1 つのトークン $z_p$ から別のトークン $z_q$ を線形回帰（切片つきの ridge、$\alpha_p$ = `TOKEN_RIDGE` × $\mathrm{tr}(X_p^\top X_p)/d$）で当てたときの $R^2$ を、順序つきの組 $p \ne q$（240 組）で平均したもの。回帰は当てはめの組の stack で求め、zurich で評価する。導出の族 $z_{n,p} = A_p h(x_n)$ なら、どの可逆な $A_p$ でも 1、位置どうしが独立なら 0。K3 に使う
  - `participation`: zurich の $z$ の共分散の participation ratio $r_2 = (\mathrm{tr}\,\Sigma)^2 / \mathrm{tr}\,\Sigma^2$（超過の式の $r_2$）。標本の値は低く偏る（$N(0, I_D)$ で約 $N D/(N+D)$ = 512）。並べるだけ
  - `rho_in`: stack の中の分散の割合。$u_{n,p} = z_{n,p} - \bar z_p$（$\bar z_p$ は位置 $p$ の、stack をまたいだ平均）、$\bar u_n = \frac{1}{16} \sum_p u_{n,p}$ として、$\rho_{\mathrm{in}} = \sum_{n,p} \lVert u_{n,p} - \bar u_n \rVert^2 / \sum_{n,p} \lVert u_{n,p} \rVert^2$。stack の中で一定なら 0、位置どうしが無相関で分散が等しければ 15/16。基底に依存するので（3 の族を $R_p$ で回すと 0.93）、恒等の版の診断として並べるだけにする
  - `z_var`: 座標ごとの分散の平均（SIGReg の目標は 1）
- **絵**: probe の checkpoint ごとに `<t>-zurich.png` と `<t>-span.png`（本物の最後のフレームと、後から学ぶデコーダの seed 0 の描き戻し）
- **物差し**（`python -m exp.vision.jepa_eval --yardsticks`、1 回だけ）: 同じ probe に通す。トークンを持つもの（`init`・`color`）は `token_r2` と `rho_in` も出す
  - `init`: JEPA の step 0（seed 0。18 本とも同じ初期値）
  - `init256`: `init` の $z$ を、当てはめの組の stack での PCA で 256 次元（VAE の $\mu$ と同じ）に落としたもの。符号の次元をそろえた参照（下の「次元の偏り」）
  - `color`: パッチごと・チャネルごとの画素の平均（16 トークン × 24 チャネル = 384 次元）。学習しない符号で、M17 の `tube` にあたる
  - `pca`: 当てはめの組の stack（平らにした 24×64×64）の画素の PCA、1024 成分（`exp.lib.pca`、seed + `PCA_SEED`）。上側の参照で、並べるだけ
  - `v16`: V16 の `all`・学習率 $3 \cdot 10^{-4}$ の最後の checkpoint の $\mu$（256 次元）
  - `v17`: V17 の本番（$\tau = 10^3$、`v0-base-49b81800-s0`）の `04800.0` の $\mu$。V17 の値（zurich の `recon_blur` 0.2136、`dyn_1/copy_1` 0.768）を再現するかで、評価の経路を確かめる
- **次元の偏り**: 後から学ぶデコーダと ridge の線形動力学に入る次元は、VAE の $\mu$ が 256、`init`・JEPA・`pca` が 1024、`color` が 384 である。入力は標準化されるが、デコーダの容量と動力学の自由度は次元とともに増える。そのため VAE は `init` を下回りにくく、物差しの有効性の規則（README）では組が「使えない」と判定されやすい（保守的な方向）。run と `init` の比較は同じ 1024 次元で公平である。`init256` との差で、この偏りの大きさを見る
- **span**: 既定は `SPAN` = 6000 秒（`--span` を省いても 6000 組で当てはめる）。V16 の config の `measure.duration`（1800 秒）に知らないうちに戻らないようにした
- **出力**: run の `posthoc_jepa/`（`config.json`、`probes.jsonl`、`jepa.jsonl`、絵）。物差しは `runs/v18-jepa/yardsticks/posthoc_jepa/`（行に `code` の名前）

### 実行

- 先に mini-00 で 100 step の試しを回し、1 step の時間・GPU メモリ・`train.jsonl` の値が有限であることを確かめる
- 短い 18 本は、std-00〜03 の 4090 と 4060 に、1 GPU に 1 本ずつ（std-03 で同居させたとき illegal memory access が出た）。1 step 約 0.1 秒の見込みで（V16 の VAE は batch 100 で 0.073 秒）、6000 step は約 10 分
- 出力は NAS の `/nas/geson/mujou-exp/runs/v18-jepa/<name>/` に置き、ckpt 以外を `./runs/v18-jepa/` に pull する。名前は `jepa-r<r>-lam<λ>-lr<lr>-s<seed>`（例 `jepa-r0.5-lam0.05-lr1e-3-s0`）、長い run は `jepa-long-r<r>-lam<λ>-lr<lr>-s<seed>`

### 実装のテスト（理論のオラクル）

- **マスク**: 族のすべての要素がちょうど $k$ 個を覆う。族の大きさ（632・436・232）、矩形 1 つの数、成分の数が、別の書き方の総当たりと一致する。トーラスの平行移動で閉じている。族の上で、各位置を覆う要素の数がちょうど $k|F_k|/16$。$10^5$ 回引いた位置ごとの頻度が、二項分布の 4σ の中にある
- **文脈側**: 隠した patch の画素を変えても、文脈側の出力がまったく同じ
- **損失**: 手で計算できる小さな例と一致する。定数の $z$ で $S$ が $0.409 N$（台形則の誤差の中）。stack の中で一定のトークンと、見えるトークンを写すだけの予測器で $L_{\mathrm{pred}} = 0$。標的側の $z$ にも $L_{\mathrm{pred}}$ の勾配が届く（stop-gradient がない）
- **初期値**: エンコーダのブロックが、同じ seed の `build_vae` のものと一致する
- **μP**: 役割と倍率が上の表のとおり。エンコーダの倍率が `mup_lr` と一致する
- **学習**: 小さな設定で 2 step 回し、同じ seed で同じ値になる（決定性）。checkpoint の時刻が $t = 12.8 s$
- **評価**: `color` の符号が手計算と一致する。`rho_in` が、stack の中で一定なら 0、位置が独立な標本なら 15/16 に近い。`token_r2` が、stack の中で一定なら 1、それを位置ごとの直交行列で回しても 1（このとき `rho_in` は 0.85 より大きい）、位置が独立なら 0、半分を共有する $z_p = (s + e_p)/\sqrt 2$ なら 1/4。`participation` が、等方的な標本で $N D/(N+D)$、直線の上で 1、stack の中で一定で約 $d$
- **予測器の順序**: ブロックを恒等にした予測器の出力が、隠した位置の昇順で $\mathrm{out}(\mathrm{LN}(\text{mask token} + \mathrm{pos}_p))$ に一致する

## V18b: トークンを細かくする（詳細設計、2026-11-23）

run の一覧・判定・長い run の規則・予想・反証は [README の「V18b」の節](../README.md)（回す前に決めたこと）に書いた。ここには、実装できる粒度の設計と、腕ごとの自明な解の導出を書く。V18 から変えるところだけを書き、書いていないところは V18 の節のとおりにする。

### ユーザーが決めたこと

- パッチを 16×16 から **4×4** に変える。64 px で 16×16 = 256 トークン、トークンの入力は 8 × 3 × 4 × 4 = 384 次元。V18 の診断で、トークンが粗いために近くから当てられる成分で予測が済んでいる可能性が残ったため。そのあとで未来予測の学習（V18c、今回は範囲外）に進む
- ハイパラを広げて調べる（学習率と $\lambda$）
- SIGReg のデータ点として**トークン平均**を試す。ただし平均だけの SIGReg は「stack の中で全トークンが同じ」族（V18 の K3）を罰しないので、平らに並べる腕と並べて比べる

推奨で進めたこと（ユーザーは異を唱えていない）: 腕 F・M・P16 の形、マスクの画素の領域を V18 と同じにすること、Imagenette を副の基準に足すこと、Codex さんの助言（pred と $S$ を別々に追う、初期値の近くに留まった run は判定保留）。

### 腕

| 腕 | パッチ | トークン $T$ | $d$ | 平らな $z$ | SIGReg のデータ点 | SIGReg の次元 $D_S$ | 予測の的 |
| -- | -- | -- | -- | -- | -- | -- | -- |
| F（平らに並べる） | 4 | 256（16×16） | 4 | $\mathbb{R}^{1024}$ | 平らにした $z$ | 1024 | 隠した位置の $z_p \in \mathbb{R}^4$ |
| M（トークン平均） | 4 | 256 | 64 | $\mathbb{R}^{16384}$ | $\bar z = \frac1T \sum_p z_p$ | 64 | 隠した位置の $z_p \in \mathbb{R}^{64}$ |
| P16（比較） | 16 | 16（4×4） | 64 | $\mathbb{R}^{1024}$ | 平らにした $z$ | 1024 | 隠した位置の $z_p \in \mathbb{R}^{64}$（V18 と同じ） |

- **F は V18 とトークンの細かさだけが違う。** $D$ = 1024 も、画素あたりの圧縮率（6144 → 64 と 384 → 4、どちらも 96 分の 1）も V18 と同じである。F と P16 の差が、トークンの細かさの効果になる
- **M は F とデータ点だけが違う**（$d$ は、平均を 64 次元にするため 64 にした）。エンコーダは F と同じパッチ・同じ seed なので、初期値はちょうど一致する（テストで確かめる）
- **P16 は V18 そのもの**（同じ config・同じコード経路）。V18 の run を再利用できる条件は下の「実行」に書く
- 3 つの腕で、エンコーダ（ViT-S・幅 1024・μP・4 ブロック）・予測器（幅 256・4 段）・optimizer・batch 128・warmup 1000 step と cosine・データの引き方・seed の分け方は V18 と同じである

### エンコーダと予測器（パッチ 4）

- **config**: V16 と同じ `config.yaml` を読み、`model.patch` だけを 4 に替える（`jepa_iid --patch 4`）。`ModelConf` に、パッチの大きさを制約する検査はない。`PatchEmbed` は `Linear(24·4·4 = 384 → 1024)` と位置の符号 `sincos_2d((16, 16), 1024)` になり、`grid = size // patch` = 16 から、そのまま 256 トークンを出す（コードの変更は要らない）
- **初期値の引き方**: `build_jepa` は `build_vae` と同じ手順で ViT を作ってから head を捨てる。パッチ 4 では head が `Linear(256·1024 = 262144 → 512)`（1.3 億個のパラメータ、CPU で約 0.5 GB）になるが、作って捨てるだけで、乱数の消費も含めて V18 と同じ手順である。ただし、パッチの埋め込みの行列の大きさが変わるので乱数の消費が変わり、**P16 と F・M のブロックの初期値は一致しない**（同じ seed の別の引き直しにあたる）。F と M の間では一致する
- **予測器**: 位置の符号を `sincos_2d((16, 16), 256)` にする（`Predictor(grid=16)`、`build_jepa` は `grid` を config から求めるので変更は要らない）。入口の `embed` は `Linear(1024 → 256)` のまま、出口の `out` を `Linear(256 → d)` にする（F は 4、M と P16 は 64）。予測器に入るトークンは 256 個（見える $256 - 16k$ 個と mask token $16k$ 個）
- **射影**: $P$ = `Linear(1024 → d)`。`TOKEN_DIM` を定数から run の設定（`--token-dim`、既定 64）に替える。$P$ の乱数（`seed + PROJ_SEED`）は形が変わるので、F と M・P16 で一致しない
- **注意の計算量**: `Block` の注意は $(B, h, T, T)$ の行列を作る。$T$ = 256 では 1 ブロックで $128 \cdot 16 \cdot 256^2$ = 1.3 億個（float32 で 0.54 GB）になる。線形の部分はトークン数に比例して 16 倍、注意の行列は 256 倍になる。トークンあたりの計算では、線形の部分（$12 w^2$ ≈ 1260 万の積和）が注意（$2 T w$ ≈ 52 万）の約 24 倍なので、1 step の計算は V18 の約 17 倍とみる。V18 の 4090 の長い run は 0.036〜0.044 秒 / step だったので、パッチ 4 は 0.4〜0.75 秒 / step の見込みである（実測は試しの run で行う）
- **メモリの見込み**: backward のために保持する活性は、標的側（256 トークン）で 1 ブロックあたり約 4.6 GB（LN・qkv・注意の行列 3 つ・MLP の $4w$ の 2 つなど）、4 ブロックで約 18 GB である。文脈側を足すと、$r$ = 0.25 で約 30 GB、0.5 で約 25 GB になり、4090（24 GB）を超える見込みである。超えたら、エンコーダのブロックごとに activation checkpointing（`torch.utils.checkpoint`、`--checkpoint-blocks`）を使う。backward のときに同じ演算で前向きを計算し直すだけなので、値は変わらない（テストで、勾配がちょうど一致することを確かめる）。計算は約 1.33 倍になる。使うかどうかは試しの run の実測で決め（下の「実行」）、F と M のすべての run で同じにする。`scaled_dot_product_attention` への置き換えや bf16 は、数値が V18 と変わるので使わない

### μP での役割

役割と倍率は V18 の表のまま変えない（`jepa_mup_roles`・`jepa_mup_lr`）。変わるのは次の 2 つで、どちらも μP の規則が幅だけを扱うことから来る。

- **パッチの埋め込み**（input の役割）: fan-in が 6144 から 384 に変わる。初期値は LeCun（std $1/\sqrt{\text{fan-in}}$）なので、0.0128 から 0.051 になり、出力の大きさ（画素の 2 乗平均 × 1）は変わらない。学習率の倍率は幅によらず 1 のままにする。ただし Adam の 1 step の重みの変化は座標あたり約 $\eta$ なので、埋め込みの出力の変化は約 $\eta \sum_i \lvert x_i \rvert \propto \eta \cdot \text{fan-in}$ になる。同じ $\eta$ では、**パッチ 4 の埋め込みは P16 より約 16 分の 1 しか動かない**。μP は入力の次元を固定の定数として扱い、この依存を定めない。ここで倍率 16 を足すのは導出の裏付けのない変更になるので、足さない。そのかわり、埋め込みとブロックが初期値からどれだけ動いたか（下の `drift`）を checkpoint ごとに測り、腕の比較に並べる。埋め込みが動かないことは、初期値の情報を残す向き（H-coarse に有利な向き）に効く
- **射影 $P$ と予測器の `out`**: output の役割のまま。F では $d$ = 4 になるが、output の倍率（$P$ は $k_w^{-1}$ = 1/4、`out` は 1）と初期値（LeCun、$P$ は × $k_w^{-1/2}$）の規則は出力の次元によらない

### マスク（4×4 から 16×16 へ広げる）

V18 の族 $F_k$（4×4 のトーラスの上の、矩形 1〜2 個の和集合でちょうど $k$ 個を覆うもの）をそのまま使い、引いたマスクを細かい格子に広げる。画素の領域が V18 とまったく同じになるので、マスクの形の違いとトークンの細かさが混ざらない。

- **写像**: 粗い格子を $G$ = 4、細かい格子を $g$ = size / patch、$s = g / G$（パッチ 4 で 4、パッチ 16 で 1）とする。細かい位置 $p = g i + j$（行優先）を、粗い位置 $c(p) = G \lfloor i/s \rfloor + \lfloor j/s \rfloor$ に対応させ、$m_{\mathrm{fine}}[p] = m_{\mathrm{coarse}}[c(p)]$ とする（`expand_masks(mask, s)`、`(B, 16)` → `(B, 16 s^2)`）。粗い 1 マスは、細かい $s \times s$ = 4×4 のブロックになる
- **隠す数**: $k_{\mathrm{fine}} = s^2 k$。$r$ = 0.25・0.5・0.75 で 64・128・192 個（見える数は 192・128・64）。マスク率 $r = k/16$ は V18 と同じ
- **画素の領域が同じこと**: 細かい位置 $p$ の画素は、行 $[4i, 4i+4)$・列 $[4j, 4j+4)$ で、粗い位置 $c(p)$ の 16×16 画素のブロックに含まれる。$c(p) = c$ となる $p$ は $s^2$ = 16 個で、合わせて $16 \cdot 4^2 = 16^2$ 画素なので、粗いマスの画素とちょうど一致する
- **位置ごとの確率**: $P(m_{\mathrm{fine}}[p]) = P(m_{\mathrm{coarse}}[c(p)]) = k/16$。族の上で数えると、各細かい位置を覆う要素は $k|F_k|/16$ 個（158・218・174）のまま
- **引き方**: V18 と同じ生成器（`seed + MASK_SEED`）で $F_k$ から粗いマスクを引き、広げる。そのため、**同じ seed の F・M・P16 は、step ごとにまったく同じ画素を隠す**。評価の固定したマスク（`EVAL_MASK_SEED`、各 stack に 8 個）も同じように広げる
- **トーラス**: 広げたマスクは、16×16 のトーラスの上でも（4 の倍数にそろった）矩形 1〜2 個の和集合である。パッチ 4 の族を新しく列挙することはしない（形の分布が V18 と変わるため）

### 損失

$$
L = (1 - \lambda)\, L_{\mathrm{pred}} + \lambda S, \qquad
L_{\mathrm{pred}} = \frac{1}{B k_{\mathrm{fine}} d} \sum_{n=1}^{B} \sum_{p \in M_n} \lVert \hat z_{n,p} - z_{n,p} \rVert^2
$$

- $L_{\mathrm{pred}}$ は V18 と同じく座標あたりの二乗誤差である
- $S$ は腕で変わる（`--sigreg-on flat|mean`、既定 `flat`）。F と P16 は $S = \mathrm{SIGReg}(\{z_n\})$、$z_n \in \mathbb{R}^{Td}$ = $\mathbb{R}^{1024}$。M は $S = \mathrm{SIGReg}(\{\bar z_n\})$、$\bar z_n = \frac1T \sum_p z_{n,p} \in \mathbb{R}^{64}$。方向は $M$ = 1024 本を $\mathbb{R}^{D_S}$ の球面から step ごとに引き直す（`directions(1024, D_S, gen)`、生成器は V18 と同じ）
- EMA も stop-gradient も使わない。標的側の $z$（M では $\bar z$ も）に勾配が届く

### 自明な解の導出（$N$ = 128、腕ごと）

数値は `exp.lib.sigreg.sigreg`（17 点の Epps–Pulley、$M$ = 1024 本、方向を 8 回引き直した平均）で求めた。

| 解 | F（$D_S$ = 1024、$d$ = 4） | M（$D_S$ = 64） | P16（V18） |
| -- | -- | -- | -- |
| 健全 $z \sim N(0, I)$（M は $\bar z \sim N(0, I_{64})$） | 1.06 | 1.06 | 1.05 |
| 定数 | 52.3（$0.409 N$） | 52.3 | 52.3 |
| 位置だけの関数 $z_{n,p} = g(p)$ | 52.3 | 52.3（$\bar z$ が定数） | 52.3 |
| K3: stack の中で一定 $z_{n,p} = h(x_n)$ | **8.37**（超過 7.3） | **1.06**（超過 0） | 1.51（超過 0.5） |
| K3 を位置ごとの直交行列で回したもの | 8.39 | 下を参照 | 1.63 |
| K3 に位置だけの項を足したもの $h(x_n) + g(p)$、$\sum_p g(p) = 0$ | 8.37 以上（共分散は K3 と同じで、平均のずれ $g$ の分だけ大きい） | **1.06**（超過 0） | — |
| 約 128 次元の大域的な潜在 $z_{n,p} = B_p\, g(x_n)$、$g \in \mathbb{R}^{128}$ | **1.28**（超過 0.22） | — | 約 1.26（超過 0.21） |
| 位置どうしが独立、座標の分散 1 | 1.06 | **51.5**（$\bar z$ の分散が $1/T$） | 1.05 |

健全な解の予測の損失を $\ell_H$（座標あたり、0〜1 程度）とする。

**腕 F**

1. 定数と位置だけの関数は、V18 と同じく $\lambda > \ell_H / (\ell_H + 51.3)$ で排除される
2. **K3（全トークンが同じ $h \in \mathbb{R}^4$）は強く罰せられる。** $\Sigma = (\mathbf 1 \mathbf 1^\top) \otimes I_4$ のランクは 4 なので、$S$ は 8.37（超過 7.3）になる。排除されるのは $\lambda > \ell_H/(\ell_H + 7.3)$ のときで、$\ell_H$ = 0.5・1 で 0.064・0.12 である。掃引の $\lambda \ge 0.5$ では排除される。位置ごとの直交行列 $R_p$（4×4）で回しても、スペクトルは同じなので 8.39 で変わらない
3. **大域的な潜在の解は残る。** トークンごとに違う線形の読み出し $B_p \in \mathbb{R}^{4 \times q}$ で、どの見える部分からも推定できる $q$ 次元の潜在 $g$ を表す符号 $z_{n,p} = B_p g(x_n)$ は、$q$ = 128 で $S$ = 1.28（超過 0.22）、16 で 2.80、64 で 1.54、256 で 1.15 である。$L_{\mathrm{pred}} \approx 0$ と両立し、1 つのトークン（4 次元）から別のトークンを線形に当てる `token_r2` は約 $4/q$ と小さいので、K3 の検査に掛からない。V18 の P16 の同じ解（超過 0.21）と同じ大きさである。**したがって、目的の式は F でも「位置に固有で当てにくい内容を捨てる」道（Codex さんの見立て、H-target）を閉じない。** H-coarse が当たるなら、その理由は目的の大域的な最小の比較にはなく、学習の動き（その解に向かわないこと）にある
4. トークンの次元が 4 しかないので、1 つのトークンには大域的な潜在の 4 次元ぶんしか載らない。大域的な符号は、必ずトークンに散らして持つことになる

**腕 M**

$\bar z_n = \frac1T \sum_p z_{n,p}$ とし、$z_{n,p} = \bar z_n + u_{n,p}$（$\sum_p u_{n,p} = 0$）に分ける。

1. **$S_M$ は $\bar z$ だけで決まり、$u$ によらない。** 勾配で書くと $\partial S_M / \partial z_{n,p} = \frac1T \nabla S(\bar z)_n$ で、$p$ によらない。つまり SIGReg は、stack の全トークンを同じベクトルだけ動かし、stack の中のばらつき $u$ には一切働かない。$u$ を動かすのは $L_{\mathrm{pred}}$ だけである
2. **K3 は罰せられない。** $u = 0$、$\bar z_n = h(x_n) \sim N(0, I_{64})$ とすると、$S_M$ は健全な値 1.06 そのものになる。$h$ を、どの見える部分からも推定できる量（場面全体の明るさ・色・種類）にすれば、$L_{\mathrm{pred}} = E\lVert \hat z_p - h \rVert^2 \approx 0$ にできる。そのため、どの $\lambda \in [0, 1)$ でも、K3 は目的の式の下限 $\lambda \cdot 1.06$ に届く。V18（超過 0.5）とも F（超過 7.3）とも違い、**K3 を排除する $\lambda$ はない**
3. 位置だけの項を足した $h(x_n) + g(p)$（$\sum_p g = 0$）も同じで、$S_M$ = 1.06、$L_{\mathrm{pred}} = 0$（予測器は位置を知っている）である
4. **M は stack で共有する成分を強く好む。** 位置どうしが独立で座標の分散が 1 のトークンでは、$\bar z$ の分散は $1/T$ = 1/256 になり、$S_M$ は 51.5（ほぼ定数の値）になる。$\bar z$ の分散を 1 にするには、トークンの分散を $T$ = 256 倍にする必要があり、そのぶん当てられない内容の $L_{\mathrm{pred}}$ も 256 倍になる。SIGReg を満たしやすいのは、分散 1 の共有の成分を持つ符号である
5. K3 を位置ごとの写像 $A_p$ で回した $z_{n,p} = A_p h(x_n)$ では、$\bar z = \bar A h$（$\bar A = \frac1T \sum_p A_p$）になる。$A_p$ がばらばらの直交行列なら $\bar A$ は小さくなるので、$h$ を大きくしないと $S_M$ が罰する。恒等の版（$A_p = I$）にはその必要がなく、SIGReg は $u$ を動かさないので、学習は恒等の版に向かうとみる

**P16**: V18 の導出のとおり（K3 の超過 0.5、大域的な潜在の超過 0.21）。

上の比較は、どれも目的の式の大域的な最小どうしの値の比較で、学習の動きの議論ではない。

### `rho_in` の腕 M での使い方

`rho_in` = $\sum \lVert u_{n,p} - \bar u_n \rVert^2 / \sum \lVert u_{n,p} \rVert^2$（V18 の定義。$u$ は位置ごとの、stack をまたいだ平均を引いたもの、$\bar u_n$ は stack $n$ のトークンの平均）は、K3 の恒等の版で 0、位置どうしが独立なら $(T-1)/T$ = 255/256 になる。K3 では 1 ではなく **0 に近づく**。

- 腕 M では、分子は「位置ごとの平均を引いたうえで、SIGReg が見ない成分（stack の中のばらつき）」そのものである。導出の 1 から、M の SIGReg はこの成分に働かない。したがって `rho_in` は、M で SIGReg の外に残った内容の割合を、基底によらずに表す（M の SIGReg が $\bar z$ だけを見るので、V18 で問題になった位置ごとの回転は、上の 5 のとおり起きにくい）
- 腕 M の `rho_in` は、学習の `train.jsonl`（batch の値、100 step ごと）と評価（zurich、checkpoint ごと）の両方に出す。K3 の判定は V18 と同じく `token_r2`（基底によらない）で行い、`rho_in` は並べるだけにする。予想（README）は `rho_in` の値でも書く
- 腕 F と P16 の `rho_in` は V18 と同じく並べるだけにする

### 学習（`jepa_iid.py` の変更）

- **引数**: `--patch`（既定は config の値）、`--token-dim`（$d$、既定 64）、`--sigreg-on`（`flat` か `mean`、既定 `flat`）、`--checkpoint-blocks`（既定なし）。既定のままなら V18 とまったく同じ計算になる
- **ログ**: `train.jsonl` は V18 の列に加えて、`zbar_var`（$\bar z$ の座標ごとの分散の平均。M で SIGReg の目標が 1 になる量）と `max_mem`（`torch.cuda.max_memory_allocated`、GB）を出す。`z_var` と `rho_in` はトークンの $z$ で、V18 と同じ
- **`jepa.json`**: V18 の項目に、`patch`、`grid`（16 か 4）、`coarse_grid`（4）、`expand`（$s$）、`k_fine`、`token_dim`、`sigreg_on`、`sigreg_dim`（$D_S$）、`checkpoint_blocks` を足す
- **checkpoint の時刻**: V18 と同じ（$t = 12.8 s$ 秒）。短い run は step 0・1000・2000・4000・6000。長い run は step 数 $s_{\mathrm{long}}$（README の規則で決める）が 60000 なら V18 の `LONG_CKPT`。60000 より小さければ、0・2000・6000 と、$s_{\mathrm{long}} \cdot j / 6$（$j$ = 1〜6）を 2000 の倍数に切り下げたもの
- **出力**: V18 と同じ形（`config.yaml`、`jepa.json`、`train.jsonl`、`ckpt/<t>.pt`）。ckpt は 1 つ約 0.22 GB（パッチの埋め込みが小さくなる分だけ V18 より小さい）

### 評価（`jepa_eval.py`・`jepa_diag.py` の変更）

`jepa.json` の `patch`・`token_dim`・`sigreg_on` から腕を読み、次の符号を同じ probe（`StreamEvaluator.probes`、`SPAN` = 6000 秒、6000 組、デコーダ 4 seed × 2000 step）と統計に通す。

| 腕 | 判定に使う符号（主） | 並べる符号 | `sigreg_heldin`・`sigreg_zurich`・K1 の対象 | K3 の対象 |
| -- | -- | -- | -- | -- |
| F | `z`（平らな $z$、1024） | `h_mean`（1024）。長い run は `h_pool`（16384） | `z`（$D_S$ = 1024） | $z_p$（256 個 × 4） |
| M | `zpca`（平らな $z$、16384 を、当てはめの組の stack の PCA で 1024 次元にしたもの） | `zbar`（$\bar z$、64）、`zflat`（16384）、`h_mean`。長い run は `h_pool` | `zbar`（$D_S$ = 64） | $z_p$（256 個 × 64） |
| P16 | `z`（1024、V18 と同じ） | `h_mean`。長い run は `h_flat`（16384、V18 の診断と同じ） | `z` | $z_p$（16 個 × 64） |

- **次元をそろえる**: 判定の符号は 3 つの腕で 1024 次元にそろえる。M の平らな $z$ は 16384 次元あり、そのまま比べると次元の偏り（V18 の「次元の偏り」、`h_flat` の 16384 次元は学習前で 0.109）で有利になる。PCA（`exp.lib.pca`、seed + `PCA_SEED`、V18 の `init256` と同じ作り方）で 1024 次元に落とした `zpca` を主にし、`zflat` は並べるだけにする
- **`h_flat` は外す**: パッチ 4 の $h$ を平らにすると $256 \times 1024$ = 262144 次元になり、線形の動力学（$D \times D$ の行列）が作れない。かわりに `h_pool` を、長い run の probe の checkpoint にだけ出す。$h$ を 16×16 の格子のまま 4×4 のブロックごとに平均し、4×4 = 16 トークン × 1024 = 16384 次元にしたもので、P16 の `h_flat` と同じ次元・同じ画素の領域になる。エンコーダが情報を失うか（V18 の診断の問い 1）を、P16 の `h_flat` と並べて読むためのもので、並べるだけにする
- **`token_r2`**: 順序つきの組 $p \ne q$ のすべて（パッチ 4 で 65280 組）で平均する。$p$ ごとに ridge の解 $(X_p^\top X_p + \alpha_p I)^{-1} X_p^\top$ を 1 回だけ作り、全部の $q$ に一度に掛ける（M で約 1.6 TFLOP）
- **`pred`・`pred_ratio`・`pred_ratio_calib`**: V18 と同じ。固定したマスクを広げて使う
- **`drift`**（新しく足す。checkpoint だけから計算できる）: パッチの埋め込みの行列とエンコーダのブロックの行列のそれぞれで、$\lVert W_t - W_0 \rVert_F / \lVert W_0 \rVert_F$（$W_0$ は同じ run の step 0）。`embed_drift` と `block_drift`（ブロックの行列をつないだもの）を出す。初期値の近くに留まったかを直接見る量で、判定保留の読みと、μP の埋め込みの偏り（上）の確認に使う。並べるだけにする
- **Imagenette の線形 probe**（`jepa_diag imagenette`、V18 の診断と同じ手順・同じデータ・$\delta_a$ = 2.3 ポイント）: 符号は全部の腕の `h_mean` と、F・P16 の `z`、M の `zbar`。短い run は step 0（腕ごとに 1 回）と 6000、長い run は全 checkpoint。パッチ 4 でも 64 px の止まった stack をそのまま入れる
- **物差し**（`jepa_eval --yardsticks --patch 4`、1 回だけ）: `init_f`（F の step 0 の `z`）、`init_m`（M の step 0 の `zpca`、`zbar` も）、`color4`（パッチ 4 のパッチごと・チャネルごとの画素の平均、256 × 24 = 6144 次元。`ColorCode(4)`）。`color4` は K3 の閾値（$\theta_3$）にだけ使い、`recon_blur` は並べるだけにする（16×16 の格子の平均の色は、ぼかした画像をほぼ描き戻せるので、合格の物差しには使わない）。V18 の物差し（`init`・`init256`・`color`・`pca`・`v16`・`v17`）は `runs/v18-baselines/` の値をそのまま使う
- **出力**: run の `posthoc_jepa/`（V18 と同じファイルに、符号ごとの行が増える）、`posthoc_diag/`（`h_pool`・`h_flat`）、Imagenette は `runs/v18b-imagenette/`。物差しは `runs/v18b-baselines/posthoc_jepa/`

### 実装のテスト（理論のオラクル、V18 のテストに足すもの）

- **マスクの写像**: 族 $F_k$ のすべての要素で、(1) 広げたマスクがちょうど $16k$ 個を隠す、(2) 粗いマスクを 16 画素に、広げたマスクを 4 画素に拡大した 64×64 の画素のマスクがちょうど一致する、(3) 族の上で数えた各細かい位置を覆う数が $k|F_k|/16$。$s$ = 1 では恒等になる。同じ生成器から引くと、パッチ 4 と 16 で、広げた後の画素のマスクが step ごとに一致する。`mask_index` が `(B, 256 - 16k)` と `(B, 16k)` を返す
- **文脈側**: パッチ 4 でも、隠した位置の画素を変えても文脈側の出力が変わらない（V18 と同じテストをパッチ 4 で）
- **SIGReg のデータ点**: `mean` で、$S$ が $\bar z$ の SIGReg に一致する。stack の中で一定の $z$（$\bar z \sim N(0, I)$）の $S$ が、健全な $N(0, I_{64})$ の値と同じ分布になる（上の表の 1.06、モンテカルロの誤差の中）。$\partial S / \partial z_{n,p}$ が $p$ によらない（autograd で、全位置で一致）。`flat` で $d$ = 4・$T$ = 256 の stack の中で一定の解が 8.4 前後（上の表）
- **既定の値で V18 と同じ**: `--patch` を省き、$d$ = 64・`flat` で、小さな設定の 2 step の損失と勾配が、変更前の関数で計算した値と一致する
- **初期値**: パッチ 4 の F と M のエンコーダの重みがちょうど一致する
- **activation checkpointing**: 小さな設定で、`--checkpoint-blocks` の有無で損失と全パラメータの勾配が一致する（同じ演算を計算し直すだけなので、CPU で完全に一致する）
- **評価**: `h_pool` が、手で計算した 4×4 のブロックの平均と一致する。`zpca` が、当てはめの組の PCA を通したものと一致する。`drift` が、step 0 で 0、重みに既知の摂動を足すと手計算の値になる。`token_r2` の一括の計算が、組ごとに解いた値と一致する

### 実行

- **試し**（std-00 の 4090。パッチ 4 の run は 5070 Ti の 16 GB に載らない見込みで、時間の予算も 4090 の時間で書くため）: F と M を $r$ = 0.25（文脈が最も多く、最も重い）・学習率 $10^{-4}$・$\lambda$ = 0.5 で 200 step ずつ回し、40〜200 step の平均の秒 / step（$t_F$、$t_M$）と `max_mem` を測る。`max_mem` が 22 GB を超えるか、メモリ不足で落ちたら、`--checkpoint-blocks` で回し直して測り直す。F の試しの run に `jepa_eval --probe-steps 200` をかけ、評価の時間を測る。mini-00 は、`--checkpoint-blocks` つきで 100 step 走るかを見る煙の試しにだけ使ってよい（共有のホストなので、他のコンテナとシステムには触れない）

### ユーザーが決めたこと（2026-11-24）

- **悪化の原因は、JEPA の学習目的と評価が合っていなかったこと。** 未来予測には進まず、**空間のマスク予測の V-JEPA のまま**進める。`recon_blur` は判定から外す。JEPA は抽象的な特徴を得る仕組みなので、再構成の向上は期待できない（[memory/feedback_eval_matches_objective.md](../../../memory/feedback_eval_matches_objective.md)）
- **パッチ 8**: 64 px で 8×8 = 64 トークン、トークンの入力は 8 × 3 × 8 × 8 = 1536 次元
- **潜在空間は、トークン数 $T$ とトークンの次元 $d$ に依存させない。学習しない固定のランダムな線形写像で決める（案 B）**: 各トークンを固定のランダム行列 $R$ で $d$ = 16 次元に写した $t_p = R h_p$ を予測の的にし、学習する射影 $P$ は無くす。潜在 $z = W\,\mathrm{vec}(t)$（$W$ は固定のランダムのガウス行列、$D$ = 1024）に SIGReg をかけ、評価の符号もこの $z$ にする
- **マスク**: V18 の粗い 4×4 の族 $F_k$（$k$ = 4・8・12）から引き、2 倍に広げる（`expand` = 2）。Fable さんの評価のマスク `Q`・`H`・`R` が族に入ることをテストで確かめる
- 学習は V18 と同じ（BP・i.i.d. なミニバッチ・LeJEPA の形・ViT-S 幅 1024・μP・予測器は幅 256・4 段・batch 128・warmup 1000 step と cosine）
- 掃引は第 1 段（$r$ = 0.5、学習率 $\{10^{-5}, 3 \cdot 10^{-5}, 10^{-4}\}$ × $\lambda$ $\{0.5, 0.8, 0.95\}$）と第 2 段（$r$ = 0.25・0.75）。長い run の設定は、新しい評価が使えるようになってから、掃引の checkpoint にかけて決める
- Codex さんの助言（V18b から引き継ぐ）: `pred` と $S$ を別々に記録して追う。学習率が低く、初期値の近くに留まった run は判定保留にする

### モデルと写像

| 量 | 形 | 作り方 | 学習 |
| -- | -- | -- | -- |
| $h_p$（エンコーダの出力、最後の `LayerNorm` の後） | $T$ = 64 個 × $w$ = 1024 | V18 と同じ ViT（`build_vae` の手順、patch 8） | する |
| $R$ | $d \times w$ = 16 × 1024、全位置で共有 | `gaussian_projection(16, 1024, R_SEED)`（標準正規 × $1/\sqrt{w}$、`R_SEED` = 67） | しない |
| $t_p = R h_p$（予測の的） | 16 次元 × 64 個 | | |
| $\mathrm{vec}(t)$ | $T d$ = 1024 | 位置の行優先、位置の中で座標の順（`tokens.flatten(1)`、$\mathrm{vec}(t)_{16p + i} = t_{p,i}$） | |
| $W$ | $D \times T d$ = 1024 × 1024（パッチ 8 では正方行列） | `gaussian_projection(1024, T d, W_SEED)`（標準正規 × $1/\sqrt{T d}$、`W_SEED` = 61） | しない |
| $z = W\,\mathrm{vec}(t)$（潜在・SIGReg の相手・評価の符号） | $D$ = 1024 | | |
| 予測器の出力 $\hat t_p$ | 16 次元（隠した位置ごと） | `Predictor(out_dim=16)`、V18 と同じ形 | する |

- **正規化の意味**: `LayerNorm` の後のトークンは（gain 1 なら）$\lVert h_p \rVert^2 = w$ なので、$E[(R h_p)_i^2] = \lVert h_p \rVert^2 / w$ = 1。同じく $E[(W v)_j^2] = \lVert v \rVert^2 / (T d)$ なので、$\mathrm{vec}(t)$ の座標の分散が 1 なら $z$ の座標の分散も 1 になる。$z$ の尺度は $T$ にも $d$ にもよらない。$D$ も $T$・$d$ によらず 1024 に固定する（`LATENT_DIM` = 1024）
- **乱数と、評価の側との共有**: $R$ と $W$ は、評価の側が決めた `exp/lib/randproj.py` の `gaussian_projection(d_out, d_in, seed)`（CPU の `torch.Generator().manual_seed(seed)` で `torch.randn(d_out, d_in)` を float32 で一度に引き、$1/\sqrt{d_{\mathrm{in}}}$ を掛ける。truncated normal ではない）で作る。リポジトリの中で $W$ の定義を 1 つにするためである。seed は run の seed に足さない固定の値で、$W$ は評価の側と同じ `W_SEED` = 61、$R$ は `R_SEED` = 67 とする。そのため、すべての run（長い run の seed 0 と 1 も）で $R$ と $W$ は同じで、seed の差は学習の差だけになる。worktree で先に実装するときは、評価の側の計画と同じ中身・同じ場所の `exp/lib/randproj.py` を書き、合流で 1 つにする。グローバルの RNG は使わないので、エンコーダと予測器の初期値の引き方は変わらない。エンコーダは同じ seed・同じパッチの V18 の手順と一致し、予測器は同じ seed・同じ $d$ の学習する射影の run と一致する（テストで確かめる）
- **評価の側の `z_w` との違い**: 評価の側の計画は、$h$ を平らにした $\mathrm{vec}(h)$（パッチ 8 で 65536 次元）を $W$（1024 × 65536、同じ `W_SEED`）で写した `z_w` を符号に足し、パッチ 8 の学習を $z = W\,\mathrm{vec}(h)$ と書いている（案 B の決定の前の形）。案 B の学習の $z = W\,\mathrm{vec}(t)$（$W$ は 1024 × 1024）とは別の符号である。合流のときに、評価の側の「パッチ 8 の学習」の記述（E1g の $\hat z = W\,\mathrm{vec}(\tilde h)$ を含む）を $t$ に読み替える
- **保存**: $R$ と $W$ はパラメータにせず、persistent な buffer にする。$R$ は module `proj`（`FixedProj`、buffer `weight` (16, 1024)、bias なし）、$W$ は新しい module `mix`（`Mix`、buffer `weight` (1024, 1024)）に置く。checkpoint の `modules` に `encoder`・`proj`・`predictor`・`mix` が入る（`ckpt.load_eval` は名前の集合の一致を求めるので、V18・V18b の run は `mix` なしのまま読める）。$R$ と $W$ は 4 MB 増えるだけで、ckpt は V18 と同じく 1 つ約 0.23 GB の見込み
- **optimizer**: $R$ と $W$ はパラメータでないので optimizer に入らない（`JEPAModules.parameters()` に出ない）。テストで、学習の step の前後で $R$ と $W$ がビットまで同じことを確かめる
- **ほかは V18 と同じ**: エンコーダ（`build_vae` と同じ手順。patch 8 では head が `Linear(64·1024 = 65536 → 512)` になり、作って捨てる）、予測器（幅 256・4 段、位置の符号 `sincos_2d((8, 8), 256)`、入口 `Linear(1024 → 256)`、出口 `Linear(256 → 16)`）、標的側は全トークン、文脈側は見えるトークンだけ（パッチの埋め込みと位置の符号の後で落とす）、EMA も stop-gradient もない
- **パッチ 8 を受けられること**: `ModelConf` にパッチの大きさの検査はない。`PatchEmbed` は `Linear(24·8·8 = 1536 → 1024)` と `sincos_2d((8, 8), 1024)` になり、`grid = size // patch` = 8 から 64 トークンを出す。`mask_expansion(8)` = 2。V18b で patch 4 を通したのと同じ経路で、コードの変更は要らない（パッチ 8 の形のテストを足す）

### μP での役割

エンコーダと予測器の役割と倍率は V18 の表のまま（`jepa_mup_roles`・`jepa_mup_lr`）。変わるのは次のとおり。

| パラメータ | 役割 | 学習率の倍率 | 初期値 |
| -- | -- | -- | -- |
| パッチの埋め込み（1536 → 1024） | input | 1 | LeCun（std $1/\sqrt{1536}$ = 0.0255） |
| 予測器の `out`（256 → 16） | output（$k$ = 1） | 1 | LeCun（std 1/16） |
| $R$・$W$ | パラメータでない | — | 上の表 |

- **パッチの埋め込み**: V18b と同じ理由で、Adam の 1 step の出力の変化は fan-in に比例する。パッチ 8（1536）は P16（6144）の約 4 分の 1、パッチ 4（384）の 4 倍動く。倍率は足さず、`embed_drift` を並べる（V18b と同じ）
- **$R$ の大きさ**: ユーザーの決定どおり LeCun の大きさ（std $1/\sqrt{w}$）にする。V18 の学習する $P$ の初期値（LeCun × $k_w^{-1/2}$）の 2 倍である。幅は 1024 から変えないので μP の転移には関わらず、$t$ がエンコーダに対して 2 倍敏感になる分は学習率の掃引に含まれる。倍率で補正はしない

### マスク（4×4 から 8×8 へ広げる）

- V18b と同じく、V18 の族 $F_k$ から `seed + MASK_SEED` の生成器で粗いマスクを引き、`expand_masks(mask, 2)` で 8×8 に広げる。粗い 1 マスは細かい 2×2 のブロックになる
- 隠す数 $k_{\mathrm{fine}} = 4k$ = 16・32・48（$r$ = 0.25・0.5・0.75）、見える数は 48・32・16。画素の領域は V18・V18b とまったく同じ（細かい位置の 8×8 画素の 4 つで、粗い位置の 16×16 画素になる）。同じ seed なら、V18・V18b・V18c は step ごとに同じ画素を隠す
- **Fable さんの評価のマスク**（粗い 4×4 の上、行優先の位置 $4i + j$）
  - `Q`（四半分、$k$ = 4）: $\{0, 1\} \times \{0, 1\}$ など 4 通り。$F_4$ に入る
  - `H`（半分、$k$ = 8）: 左・右・上・下の 4 通り。$F_8$ に入る
  - `R`（外周、$k$ = 12）: 中央 $\{5, 6, 9, 10\}$ 以外のすべて。1 通り。$F_{12}$ に入る
  - `mask_family` で確かめた（$|F_4|$ = 632、$|F_8|$ = 436、$|F_{12}|$ = 232 のまま、9 個とも含まれる）。テストでは、評価の側の `exp/lib/regions.py` が合流するまでは上の定義を書き、合流したらそのマスクで確かめる。`R` を 8×8 に広げると、中央の 4×4 の 16 個だけが見え、48 個を隠す
  - 族の上の一様な引き方では、`Q` の 1 つは 1/632、`H` の 1 つは 1/436、`R` は 1/232 の確率で引かれる（学習の分布の中にあるが、多くは引かれない）。族を `Q`・`H`・`R` に寄せることはしない（位置ごとに一様な性質を保つため）

### 損失

$$
L = (1 - \lambda)\, L_{\mathrm{pred}} + \lambda S, \qquad
L_{\mathrm{pred}} = \frac{1}{B k_{\mathrm{fine}} d} \sum_{n=1}^{B} \sum_{p \in M_n} \lVert \hat t_{n,p} - t_{n,p} \rVert^2, \qquad
S = \mathrm{SIGReg}\bigl(\{ W\,\mathrm{vec}(t_n) \}_{n=1}^{B}\bigr)
$$

- $d$ = 16、$B$ = 128。$L_{\mathrm{pred}}$ は V18 と同じく座標あたりの二乗誤差
- $S$ = `sigreg(z, z[:0], A)`。batch の 128 個の $z$（$D$ = 1024）、V 統計量（LeJEPA と同じ、バッファなし）。方向 $A$ は 1024 本を step ごとに `seed + DIRECTION_SEED` の生成器から引き直す（V18 と同じ）
- 標的側の $t$ にも、$z$ を通して $S$ にも勾配が届く。$R$・$W$ には勾配を流すが、パラメータでないので更新しない

### 自明な解の導出（$N$ = 128、$D$ = 1024、$T$ = 64、$d$ = 16）

数値は `exp.lib.sigreg.sigreg`（17 点の Epps–Pulley、$M$ = 1024 本、方向と標本を 8〜32 回引き直した平均）で求めた。1 回の引きのばらつき（標準偏差）は、健全な値で 0.04、K3 で 0.2〜0.3 である。$W$ は 1 つ引いたもの（特異値は最大 2.01・中央値 0.81・最小 0.0012）。

**方向ごとの分散のばらつきと超過**: 共分散 $\Sigma$（$\mathrm{tr}\,\Sigma = D$）のガウスの $S$ の超過は、V18 の展開で $\approx \frac{N}{4} \int t^4 e^{-3t^2/2} dt \cdot \mathrm{Var}_a(a^\top \Sigma a) \approx 0.241\, N (1/r_2 - 1/D)$（$r_2$ は participation ratio）。ランク $q$ の等方的な $\Sigma = (D/q) P_q$ では、一様な単位ベクトル $a$ について $\lVert P_q a \rVert^2 \sim \mathrm{Beta}(q/2, (D-q)/2)$ なので、$a^\top \Sigma a$ の相対的な標準偏差は $\sqrt{2(D-q)/(q(D+2))}$ である（$q$ = 16 で 0.351、$q = D$ で 0）。

| 解 | $z$ の共分散 | $S$（数値） | 健全な値からの超過 | $L_{\mathrm{pred}}$ |
| -- | -- | -- | -- | -- |
| 健全 $z \sim N(0, I_D)$ | $I$ | 1.05〜1.06 | 0 | $\ell_H$ |
| 等方的な $t$（$\mathrm{vec}(t) \sim N(0, I)$、$z = W\,\mathrm{vec}(t)$） | $W W^\top$（$r_2$ = 511） | 1.07〜1.09 | 約 0.03（式で 0.030） | $\ell_H$ |
| 定数 | 0 | 52.3（$0.409 N$） | 51.3 | 0 |
| 位置だけの関数 $t_{n,p} = g(p)$ | 0（$z$ が定数） | 52.3 | 51.3 | 0 |
| **K3**（$d$ = 16）: $t_{n,p} = A_p u_n$、$u_n \sim N(0, I_{16})$ | ランク 16 | **2.9〜3.0**（$A_p = I$ で 2.96・3.02、直交行列で回して 2.88） | **約 1.9**（式で 1.90） | 0（$u$ をどの見える部分からも推定できれば） |
| （比べ）K3、$d$ = 1024（射影なし、$h_p$ を的にし $W$ は 1024 × 65536） | $W' W'^\top$、$W' = \sum_p W_p A_p$ は正方のガウスと同じ分布（$r_2$ = 511） | **1.08** | **約 0.03**（等方的な $t$ と同じ） | 0 |
| 大域の解 $t_{n,p} = B_p g_n$、$g_n \sim N(0, I_q)$、$B_p$ はランダム（16 × $q$） | ランク $q$ | $q$ = 128: 1.31、256: 1.19〜1.21、512: 1.13〜1.17、768: 1.10〜1.14 | 0.26・0.15・0.10・0.07（等方的な $t$ との差は約 0.03 小さい） | 0（$g$ をどの見える部分からも推定できれば） |

健全な解の予測の損失を $\ell_H$（座標あたり、0〜1 程度）とする。比べるのは、目的の式の大域的な最小どうしの値で、学習の動きの議論ではない（V18 と同じ）。

1. **定数と位置だけの関数**: V18 と同じく $\lambda > \ell_H / (\ell_H + 51.3)$ で排除される
2. **$W$ の条件数**: $W$ は正方のガウスなので特異値が 0.0012〜2.0 に広がる。SIGReg の理想は $\mathrm{Cov}(\mathrm{vec}\,t) = (W^\top W)^{-1}$ で、極端に偏っている。しかし等方的な $t$ の超過は約 0.03（$r_2 \approx D/2$）で、$N$ = 128 の SIGReg は $W$ の偏りをほとんど見分けない。健全な解として等方的な $t$ を置いてよい
3. **典型の K3（$d$ = 16）**: どのトークンも stack 全体の符号 $u$ を丸ごと持ち、$t_p = A_p u$ とすると、$\mathrm{vec}(t)$ は 16 次元の部分空間に入り、$z$ の広がりはランク 16 に縮む。超過は約 1.9 で、排除されるのは $\lambda > \ell_H/(\ell_H + 1.9)$ のとき（$\ell_H$ = 0.3・0.5・1 で 0.14・0.21・0.34）。**掃引の $\lambda \ge 0.5$ では、K3 は目的の最小値にならない。** V18 の P16（$d$ = 64、超過 0.5）より 4 倍近く強く罰せられ、V18b の F（$d$ = 4、超過 7.3）より弱い。$A_p$ を位置ごとの直交行列にしてもスペクトルは同じで、$S$ も同じ（2.88）。固定の $R$ は $h_p$ の 16 次元の像しか見ないが、エンコーダは $R h_p = A_p u$ となる $h_p$ を作れるので、K3 の族の形は $R$ で制限されない
4. **射影なし（$d$ = 1024）の K3 は穴になる**: トークンが 1024 次元あれば、$u \in \mathbb{R}^{1024}$ をどのトークンにも丸ごと持たせられる。$z = (\sum_p W_p A_p) u$ の写像は正方のガウスと同じ分布なので、$S$ は等方的な $t$ と同じ 1.08 になり、$L_{\mathrm{pred}} = 0$ と両立する。**どの $\lambda < 1$ でも、K3 が目的の最小値になる**（V18b の M と同じ形）。$d$ を小さくするのは、この穴を閉じるためである（ユーザーの決定の理由）
5. **固定の $R$ と H-target**: 学習する $P$ は、$h_p$ のうち見える部分から当てやすい方向を選んで的にできる（Codex さんの H-target の一部）。固定の $R$ にはその自由がない。ただしエンコーダは $h_p$ そのものを変えられるので、H-target の道（当てにくい内容を $h_p$ から捨てる）は閉じない。$R$ の零空間（1008 次元）にある $h_p$ の成分は、標的側の損失からは制約されない（文脈側の計算と予測器の入力を通してだけ効く）。評価の `h_mean`・`h_pool` は、この成分も含めて測る
6. **大域の解は、どの案でも残る**: 見えるトークン全体で $q$ 次元の大域の符号 $g$ を分け持ち、トークンごとに違う読み出し $B_p$ で表す符号は、$q$ が大きいほど SIGReg に罰せられない。$L_{\mathrm{pred}} = 0$ にするには、隠した位置の $B_p g$ が見えるトークンから決まる必要があり、$q \le$ 見える数 × $d$（$r$ = 0.25・0.5・0.75 で 768・512・256）である。超過は 0.07〜0.15 しかない（等方的な $t$ との差は 0.04〜0.12）。排除されるのは $\lambda > \ell_H / (\ell_H + e)$ のときで、$e$ = 0.05 なら $\ell_H$ = 0.5 で $\lambda > 0.91$。**$\lambda$ = 0.95 だけが、$\ell_H \lesssim 0.9$ の範囲でこの解を目的の最小値から外す。** $\lambda$ = 0.5 と 0.8 では、$\ell_H \ge 0.5$ なら外さない。ただし、この解が $L_{\mathrm{pred}} = 0$ になるのは、$g$ の中身がどの見える部分からも推定できるときだけで、どこまで推定できるかはデータが決める。トークンごとの `token_r2` は約 $d/q$（$q$ = 768 で 0.02）と小さく、K3 の検査に掛からない。そのため崩壊の検出（`token_r2`・`rho_in`・`rank`）に加えて、評価の側の `swap`（大域の符号だけなら 50%、Fable さんの導出）で見張る
7. 学習の動き: 1 標本あたりの勾配の重みの比は $\lambda B / (1 - \lambda)$ で、$\lambda \ge 0.5$ では 128 以上になる（V18 と同じ尺度）。どの解に向かうかは導出だけでは決まらない

**テストのオラクルにする値**（$N$ = 128、$M$ = 1024、方向と標本を 16 回引き直した平均。許容の幅は 1 回の引きの標準偏差 / $\sqrt{16}$ の 4 倍より広くとる）

- 健全 $z \sim N(0, I)$: 1.06 ± 0.05。定数: 52.3（$0.409 N$、台形則の誤差の中）
- 等方的な $t$ を $W$ で写したもの: 1.07〜1.09。健全な値との差が 0.08 未満
- $d$ = 16 の K3（$A_p = I$ と、位置ごとの直交行列）: 2.6〜3.4。両者の差が 0.3 未満
- $d$ = 1024 の K3（射影なし）: 健全な値との差が 0.08 未満（穴があることの確かめ）
- 大域の解: $q$ = 128 で 1.2〜1.45。$q$ = 128・256・768 で $S$ が小さくなっていく（それぞれの間に 0.04 以上の差）
- $a^\top \Sigma a$ の相対的な標準偏差（ランク 16、$D$ = 1024、$10^4$ 本の方向）: 0.351 ± 0.01

### 学習（`jepa.py`・`jepa_iid.py` の変更）

- **定数**: `jepa.py` に `PROJ_KINDS = ("learned", "fixed")`、`LATENT_DIM = 1024`、`R_SEED = 67`、`W_SEED = 61` を足し、`SIGREG_ON` に `"mix"` を足す。`exp/lib/randproj.py` は seed を持たず、評価の側も `jepa_eval.py` に同じ値の `W_SEED` を置いているので、合流のときに 1 か所にまとめる（実装のときに分かった）
- **モジュール**: `FixedProj(weight)`（buffer `weight` (d, w) = $R$、$t = h R^\top$）と `Mix(weight)`（buffer `weight` (D, td) = $W$、$z = \mathrm{vec}(t) W^\top$）。`JEPAModules` に `mix: nn.Module | None = None` を足し、`proj` の型を `nn.Module` にする。`modules()` は `mix` があるときだけ `"mix"` を含める。`tokens(stacks)` は $t$（`proj` の出力）、`mu(stacks)` は `mix` があれば $W\,\mathrm{vec}(t)$、なければ V18 のとおり $\mathrm{vec}(t)$
- **`build_jepa`**: `proj: str = "learned"`、`latent_dim: int | None = None` を足す。`proj="fixed"` なら $R$ を上の規則で作る（μP の $k_w^{-1/2}$ は掛けない）。`latent_dim` が整数なら $W$（`latent_dim` × $T d$）を作る。既定のままなら V18・V18b と同じ
- **`sigreg_points(tokens, on, mix=None)`**: `"mix"` なら `mix(tokens.flatten(1))`（$(B, D)$）。`jepa_terms` は `mods.mix` を渡す。`"mix"` で `mix` がなければ `ValueError`
- **引数**（`jepa_iid`）: `--proj {learned,fixed}`（既定 `learned`）、`--sigreg-on {flat,mean,mix}`（既定 `flat`。`mix` のとき $W$ を作る）。V18c の run は `--patch 8 --token-dim 16 --proj fixed --sigreg-on mix`。既定のままなら V18・V18b とまったく同じ計算になる（既存のテストで確かめる）
- **`jepa.json`**: V18b の項目に `proj`、`latent_dim`（`mix` のとき 1024、ほかは `null`）、`seeds.r`（`fixed` のとき 67）と `seeds.w`（`mix` のとき 61）を足す。`fixed` のときの `seeds.proj` は使わないので `null` にする。`sigreg_dim` は $D$ = 1024
- **`train.jsonl`**: V18b の列（`loss`・`pred`・`sigreg`・`grad_norm`・`z_var`・`rho_in`・`zbar_var`、`lr`・`sec`・`max_mem`）。`z_var` と `rho_in` は $t$ のもの。`mix` の run だけ `mix_var`（$z = W\,\mathrm{vec}(t)$ の座標ごとの分散の平均。SIGReg の目標は 1）を足す
- **checkpoint の時刻**: V18 と同じ（$t = 12.8 s$ 秒）。短い run（掃引）は step 0・1000・2000・4000・6000（$t$ = 0・12800・25600・51200・76800 秒）。長い run は V18 の `LONG_CKPT`（0・2000・6000・10000・20000・30000・40000・50000・60000）。長い run の step 数が 60000 より小さくなったときは V18b の規則（0・2000・6000 と $s_{\mathrm{long}} j/6$ を 2000 の倍数に切り下げたもの）
- **出力** `<out>/`: V18 と同じ形（`config.yaml`、`jepa.json`、`train.jsonl`、`ckpt/<t>.pt`）。ckpt の modules は `encoder`・`proj`・`predictor`・`mix`
- 損失が有限でなくなったら止める（V18 と同じ）

```bash
python -m exp.vision.jepa_iid --patch 8 --token-dim 16 --proj fixed --sigreg-on mix \

```

### 評価（`jepa_eval.py`・`jepa_diag.py` の変更、学習の側で使うもの）

- **run の読み方**: `build_run_jepa` が `jepa.json` の `proj`・`sigreg_on`・`token_dim`・`latent_dim` を読む（記録がなければ V18 の既定）。V18c の符号は `ARM_CODES["mix"] = ("z", "h_mean")`。`z` は `JEPAModules.mu` = $W\,\mathrm{vec}(t)$、その `tokens` は $t_p$（16 次元 × 64 個）
- **崩壊の量**: `sigreg_heldin`・`sigreg_zurich`・`z_var`・`participation` は $z$ で、`token_r2`（順序つきの組 64 × 63 = 4032 組）・`rho_in` は $t_p$ で測る（`CodeStats.of` はそのまま使える）。`rank` は probe の $z$ の実効ランク
- **予測**: `CodeStats.pred` の `pred`・`pred_ratio`・`pred_ratio_calib` は $t$ の空間（`mods.proj` = $R$、`expand` = 2 で広げた固定のマスク）。変更は要らない
- **`drift`**: `embed_drift`・`block_drift`（V18b と同じ）
- **probe**（`StreamEvaluator.probes`、6000 組）: 符号 `z` と `h_mean` を step 2000・6000 にかけ、`rank`（K2）と、並べるだけの `dyn_1/copy_1`・`recon_blur` を出す。長い run は step 6000・20000・60000 と、`h_pool`（$h$ を 2×2 のブロックごとに平均した 16 × 1024 = 16384 次元）を step 0・6000・20000・60000
- **Imagenette**（`jepa_diag imagenette`、std-01）: `h_mean` と `z`。短い run は step 0（1 回）と 6000、長い run は全 checkpoint
- **物差し**（`jepa_eval --yardsticks --patch 8 --token-dim 16 --proj fixed --sigreg-on mix`、1 回だけ）: `init_c`（V18c の step 0 の `z`、トークンは $t$。掃引の 9 本と第 2 段は seed 0 で同じ初期値）、`init_c_h_mean`、`color8`（パッチ 8 のパッチごと・チャネルごとの画素の平均、64 × 24 = 1536 次元、`ColorCode(8)`）。V18 の物差し（`color`・`v16`・`v17`）は `runs/v18-baselines/` の値を使う
- **新しい評価への引き継ぎ**: 主の指標（生成した画像の同定）は $z$ にかける。E1 は予測の的が $t_p$ なので、$h$ を $t$ に読み替える。E1g は、隠した位置を $\hat t$ で埋めた $\tilde t$ から $\tilde z = W\,\mathrm{vec}(\tilde t)$ を作り、全体の $z$ で学んだデコーダに入れる（`JEPAModules.mix` で計算できる）。どちらも checkpoint だけからかけられる
- **出力**: run の `posthoc_jepa/`、`posthoc_diag/`（`h_pool`）、Imagenette は `runs/v18c-imagenette/`、物差しは `runs/v18c-baselines/posthoc_jepa/`

### 実装のテスト（理論のオラクル、V18・V18b のテストに足すもの）

- **$R$・$W$**: 形が (16, 1024)・(1024, 1024)。run の seed（0 と 1）によらず同じ値で、`gaussian_projection(16, 1024, 67)`・`gaussian_projection(1024, 1024, 61)` とちょうど一致する。要素の標本の標準偏差が $1/\sqrt{1024}$ の ±1% の中。`JEPAModules.parameters()` と optimizer の param group に入らない。2 step 学習した後も、ビットまで同じ。**checkpoint に保存した $R$・$W$ が、seed から作り直したものとちょうど一致する**（保存と再現の両方を確かめる）。V18・V18b の形の run（`mix` なし）の checkpoint が、変更後のコードでそのまま読める
- **写像の式**: `mu` が `tokens(x).flatten(1) @ W.T` とちょうど一致する。`vec` の順が $\mathrm{vec}(t)_{16p + i} = t_{p,i}$。等方的な $\mathrm{vec}(t)$（$10^4$ 標本）で $z$ の座標の分散の平均が 1 ± 0.02（$\mathrm{tr}(W W^\top)/D$ に一致する値、正規化の確かめ）
- **SIGReg**: 上の「テストのオラクルにする値」と、方向の分散の相対的な標準偏差 0.351
- **マスク**: `Q`（4 通り）・`H`（4 通り）・`R`（1 通り）が、それぞれ `mask_family(4|8|12, 4)` の行に含まれる。`expand_masks(·, 2)` が $4k$ 個を隠し、粗いマスクを 16 画素・広げたマスクを 8 画素に拡大した 64×64 の画素のマスクがちょうど一致する。広げた `R` は中央の 4×4 だけを見せる
- **パッチ 8 の形**: トークンが 64 個、`PatchEmbed` の fan-in が 1536、予測器の位置の符号が 8×8。文脈側で、隠した位置の画素を変えても出力が変わらない
- **初期値**: パッチ 8 のエンコーダのブロックが、同じ seed・パッチ 8 の `build_vae` のものと一致する。予測器が、同じ seed・$d$ = 16 の学習する射影の run と一致する
- **損失**: 手で計算できる小さな例で、$L_{\mathrm{pred}}$ の正規化（$B k_{\mathrm{fine}} d$）と $S = \mathrm{SIGReg}(W\,\mathrm{vec}(t))$ が一致する。標的側の $t$ に $L_{\mathrm{pred}}$ と $S$ の両方の勾配が届く
- **既定の値で V18 と同じ**: `--proj learned --sigreg-on flat` で、小さな設定の 2 step の損失と勾配が変更前と一致する（V18b のテストをそのまま通す）
- **評価**: V18c の `jepa.json` から `build_run_jepa` が `mix` つきのモジュールを作り、checkpoint を読める。`z` の符号の `tokens` が $t$（16 次元）

### 実行

- **GPU の選び方**: 同じ GPU を評価の側の workflow も使う。ジョブを置く前に `nvidia-smi` で他のプロセスが無い GPU を選び、1 GPU に 1 本にする
