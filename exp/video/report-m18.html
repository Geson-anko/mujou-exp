段 4 · PC-ALM

PC-ALM は BP と同じように VAE のエンコーダを学んだ

4 つの seed のすべてで U を満たしました。4 本の平均と BP の 4 本の平均の差は、recon_blur で 0.00473（BP の範囲 0.0167）、dyn_1/copy_1 で 0.0000125（同 0.00706）です。val の bpd の対の差は 1800 秒のあいだ最大 0.0014 bits/値で、BP の 4 本の範囲を一度も超えませんでした。

段 4 · 限界

一致は、ノードを木の順に歩ませる実行の中で示した

ホストが ManualRun を周期 2 ms で歩ませ、15 歩目に学ぶ実行では、更新が BP の勾配になるのは構成上の性質です。checkpoint の上で、float32 の PC-ALM と float32 の BP の勾配の相対の差は最大 2.9 × 10⁻⁷ でした。mujou の非同期の実行（mujou.run）では試していません。

段 1〜2 · BP

学んだ符号は U を満たすが、単純な物差しには届かない

VAE の recon_blur は 0.138 で、同じ設定の自己符号化器の 0.132 に近く、画素の PCA の符号（0.051）の 2.7 倍です。val の bpd は 7.198 で、pPCA-1024 の 6.887 に届きません。崩壊はせず、平均の積みのガウスの 8.127 より 0.93 bits/値小さい値でした。

1

実験の仕組み

M17 では、再構成の項のない JEPA を Walking Tours の 1 本のストリームから学ぼうとしました。どの設定でも積みの中のトークンの広がりが潰れ、ユーザーの判断で M17 の線を閉じました（results/m17.md）。M18 では目的の式を再構成のある式に替えます。まず決定的な自己符号化器、次に ELBO で学ぶ VAE を、同じストリームから学びます。

エンコーダは M17 の t128 の ViT（8 ブロック）で、16 フレームの積みを 128 個のトークンに分け、トークンごとに 8 次元の潜在の平均 μ と分散 s² を出します（潜在は合わせて D = 1024 次元）。デコーダはそれを裏返した ViT で、積み全体の P = 16 × 3 × 128 × 128 = 786432 個の値を戻します。VAE はスカラーの σ を学ぶガウスの尤度を使い、β = 1 の ELBO を最大にします。

2026-11-16 のユーザーの決定で、M18 の VAE の目的は「mujou + PC-ALM でエンコーダが学べるか」を確かめることになりました。PCA を上回ることは求めません。段 0〜2 の BP は PC-ALM と比べる相手として読みます。

指標の読み方

stack_mse
積み全体の再構成の誤差を、学ぶ積みの平均の積みの誤差で割った比です（val、Zurich）。小さいほど良く、1 なら平均の積みと同じです。
R
val の stack_mse が PCA-1024（9 本の積みを手元に持ってオフラインで解いた線形の最適解）の 0.177 を下回ること。VAE では val の bpd が pPCA-1024 の 6.887 を下回ることです。途中から参考に下げました。
後から学ぶデコーダ
posthoc。checkpoint ごとにエンコーダを止め、符号から最後のフレームへの CNN のデコーダを別に学びます（オフラインで 2000 歩）。符号の側の指標を測る道具で、システムには入れません。
recon_blur
後から学ぶデコーダで戻した最後のフレームの誤差を、ぼかした画像で測った比です。小さいほど良い。
dyn_1/copy_1
符号から次の符号を線形に予測する誤差を、写し（今の符号をそのまま使う）の誤差で割った比です。閉じた形で当てはめます。小さいほど良い。
U
主な判定です。recon_blur と dyn_1/copy_1 の両方が、学習前のエンコーダ（同じ seed）の値を下回ること。seed 100 の学習前の値は 0.318 と 0.653 です。
過学習の確かめ
同じ 256 個の積みを繰り返し見せる腕です（pool_stack_mse・pool_bpd）。1800 秒で 1 個あたり約 210 回見ます。忘却がほとんど入らないので、「この時間と設定で 256 個に合わせきれるか」を見る診断にしました。
own_recon
学習の中で一緒に学ぶデコーダ（システムのデコーダ）の再構成の誤差です。
bpd
VAE の負の ELBO を、値 1 つあたりの bits にしたものです（val）。小さいほど良い。率（KL）と歪み（再構成）の和で、負の対数尤度（−log₂ P）の上界です。
σ と σ*
σ は学ぶ尤度の標準偏差、σ* はそのときのデコーダの誤差から決まる最適値です。
単位/秒
run の 1 単位は動画の 0.1 秒（30 fps の 3 フレーム）です。リアルタイムの目標は 1 単位を壁時計の 0.1 秒以内に終えることで、ストリームが B 本なら 10/B 単位/秒です。

5 · 段 1 · 学習率の掃引 · 深さ

自己符号化器はストリームから学べるか。学習率とデコーダの深さ

段 1 は二乗誤差の自己符号化器を、preset の学習率（RMSProp と AdamW は 2.9 × 10⁻⁵、SGD は 2.05 × 10⁻⁷）で 1800 秒学びました。stack_mse は 1800 秒でも RMSProp と AdamW で 0.602〜0.610 にとどまり、下がり続けていました。そこで学習率を 10 倍刻みで掃引し、ストリームと過学習の確かめの 2 つの腕（B = 1）で回しました。

15 点のどれも過学習の確かめを通りませんでした。pool_stack_mse の最小は AdamW の 1e-2 の 0.204 と RMSProp の 1e-2 の 0.212 です。R も満たされず、val の stack_mse の最小は RMSProp の 1e-3 の 0.239 でした。1e-3 と 1e-2 のストリームは 900 秒ごろから下がらなくなるか、上下しました。

U は 15 点のうち 13 点が満たしました。外れたのは SGD の 4.09e-9 と 4.09e-8 で、recon_blur（0.392、0.376）が学習前の 0.318 より大きくなりました。決めた規則（U を満たす点のうち、後から学ぶデコーダの recon_blur が最小）で、RMSProp の 1e-3（0.141）を選びました。2 番目の AdamW の 1e-3 との差は 0.003 で、seed 1 本の傾向です。

デコーダの深さ

選んだ RMSProp・η = 1e-3 で、デコーダの深さを 2・4・8 に変えました。目的はエンコーダなので、深さはシステムのデコーダの誤差ではなく、符号の側の recon_blur で選びます。

3 つの深さとも U を満たし、1800 秒の recon_blur は深さ 2 で 0.141、4 で 0.132、8 で 0.150 でした。深さ 4 を選びました。深さ 4 は 6 つの checkpoint のすべてで深さ 2 より小さい値でしたが、同じ run の中の値なので互いに独立ではありません。深さ 8 はストリームの stack_mse が 900 秒の 0.265 から 1800 秒の 0.321 に上がりました。同じ深さの過学習の確かめは 0.254 から 0.242 に下がったので、どの積みにも起きる発散ではありません。ストリームの上では、深さ 2 で選んだ η = 1e-3 が深さ 8 には大きい、という読みと合います。ただし外れた理由のもう 1 つの候補とは分けておらず、深さ 8 で η を変えた run もありません。

pool_stack_mse はどの深さも 0.241〜0.242 で、デコーダのパラメータを 316 万から 790 万に増やしても動きませんでした。この η と 1800 秒では、デコーダの容量は 256 個を覚える制約になっていません。

6 · 段 2

ELBO に替えると、崩壊せずに学べるか

深さ 4・RMSProp・η = 1e-3 のまま、目的の式だけを β = 1 の ELBO に替えました（アニーリングも free bits も無し）。腕はストリームの B = 1、ストリームの B = 32、過学習の確かめの 3 つです。

ストリームの B = 1 は 1800 秒で 7.198 で、崩壊の物差し 8.127 より 0.93 bits/値小さい値でした。R の 6.887 には届きません。差の 0.31 bits/値のほとんどは歪みの側にあり、率（KL）の差は pPCA-1024 と比べて 0.0005 bits/値しかありません。B = 1 の曲線は 900 秒より後に 7.114〜7.262 の間を上下し、1800 秒の値はその山の 1 つにあたります。同じフレームを見た自己符号化器にも同じ時刻に山があり、学んでいる場面が原因という読みと合います（確かめてはいません）。

KL は 1800 秒の B = 1 で 3562 nats（1 潜在あたり 3.5 nats）で、pPCA-1024 の 3279 nats の 1.09 倍です。次元ごとの KL の最小は 2.86 nats で、pPCA-1024 の最小 2.58 nats とほぼ同じ所にあります。使われる次元が少なくなる形の崩壊は見えませんでした。VAE は線形の最適解とほぼ同じ率を払い、より悪い歪みを得ています（val の σ*² は pPCA の σ² の 1.63 倍）。

学習中の σ は学んでいる積みの最適値と 7〜8 秒で交わり、そのあとは大きく遅れずについていきました（図には val の σ* だけを描いています）。val の σ と σ* の差は学んでいる場面と val の残差の大きさの差と読みます。

符号の質は同じ設定の自己符号化器とほぼ同じでした。後から学ぶデコーダの recon_blur は 0.138（自己符号化器 0.132）、dyn_1/copy_1 は 0.300（同 0.283）です。seed 1 本の中では dyn_1/copy_1 が 6 つの checkpoint のすべてで VAE のほうが 0.015〜0.027 大きく、ELBO に替えて潜在空間が良くなった印はありません。ただし段 4 で、recon_blur は後から学ぶデコーダの当てはめだけで 1 本あたり標準偏差 約 0.0035 揺れると分かりました。差 0.006 はこの揺れと区別できません。

7 · 段 4

同じ VAE を mujou の PC-ALM で学ぶと、BP と同じように学べるか

段 2 の BP から学習則だけを替えました。モジュール、初期の重み、目的の式、optimizer、データ、ホストが引く雑音は同じです。PC-ALM は 29 ms ごと（15 歩目）に学ぶので、比べる BP も 29 ms ごとに学ぶ設定で回しました。seed は 100・0・1・2 の 4 つ、B = 1、1800 秒です。

回す前に決めた判定は 2 つです。U：PC-ALM の 4 本のそれぞれが同じ seed の学習前の値を両方の指標で下回ること。BP との差：2 つの指標のそれぞれで、PC-ALM の 4 本の平均と BP の 4 本の平均の差の絶対値が、BP の 4 本の範囲（最大 − 最小）以下であること。

U は 4 本のすべてで成り立ちました（recon_blur 0.140〜0.157、dyn_1/copy_1 0.297〜0.304。学習前は 0.302〜0.323 と 0.653〜0.665）。BP との差も両方の指標で範囲に入り、回す前に決めたとおり「mujou + PC-ALM で、ストリームから VAE のエンコーダを BP と同じように学べた」とします。物差しとの位置は段 2 と同じで、recon_blur は画素の PCA の符号の 2.6〜3.0 倍、dyn_1/copy_1 は tube の 1.8 倍です。

対の差（PC-ALM − BP）は dyn_1/copy_1 で −1.9 × 10⁻⁵〜−1.7 × 10⁻⁶ と小さいのに、recon_blur だけが −0.0004〜+0.0139 と大きく、seed 1 で 0.0139 になりました。これは下の「recon_blur の差はどこから来たか」で扱います。

対の差は、はじめは丸めの大きさで、時間とともに増えました。val の bpd の対の差は 600 秒までは 3.1 × 10⁻⁶ 以下で、10⁻⁴ を初めて超えたのは 960〜1380 秒です。1800 秒までの最大は 0.0014 bits/値で、同じ時刻の BP の 4 本の範囲を一度も超えませんでした。float32 の丸めの差が軌道の上で増えたものと読むのが、次の勾配の確かめと合います。ただし、BP 同士で丸めだけを変えた対照の run はありません。

float32 の PC-ALM は正確な値から float32 の BP と同じだけ離れました（5.2 × 10⁻⁷〜4.3 × 10⁻⁶）。float64 で計算すると、PC-ALM と BP の差は float64 の丸めまで縮みます（2.9 × 10⁻¹⁶〜7.4 × 10⁻¹⁶）。28 点のどれでも、損失（QP3）と勾配（QP4）の失敗はありませんでした。run の大部分は reset しない続きのフレームですが、この経路は m18_pc_grad では確かめていません。小さなネットのテストと stream.jsonl の −L の一致で確かめていて、上の bpd の一致もこれと合います。

8 · 段 4

速さはリアルタイムに間に合うか

PC-ALM の B = 1 は 10.65〜10.80 単位/秒で、目標の 10 を 6.5〜8.0% だけ上回りました。BP（71.7〜72.0）の 0.15 倍です。B = 32 は 2.41 単位/秒で、目標 0.3125 の 7.7 倍でした。回す前の予測（QP5）は判定しないと決めていましたが、見込みの範囲（B = 1 で 10.0〜11.3、B = 32 で 2.3〜2.6）には 5 本とも入りました。律速は測っていません。

9 · 段 1〜4

再構成の絵

val の最初の 10 窓の最後のフレームを、上から入力・システムのデコーダ・後から学ぶデコーダの順に並べました。どれも seed 100、1800 秒です（学習前の行と、seed 1 の 2 行を除く）。

段 1 の preset の学習率では、システムのデコーダは patch ごとに 1 つの灰色を塗ったブロックしか描けませんでした。η = 1e-3 では patch の色が出るようになり、屋内の茶色、空の淡い青、人の青いシャツが patch の色として出ます。VAE の g(μ) は自己符号化器の絵とほとんど同じで、PC-ALM と BP の g(μ) は目で区別できません。

seed 1 の後から学ぶデコーダは、PC-ALM と BP で塊の配置は同じですが色が違い、PC-ALM の符号からの絵のほうが屋内で茶色と橙が濃くなりました（色の量 0.0281 と 0.0228）。システムのデコーダは揃っているので、後から学ぶデコーダだけが違う解に落ちた、という読みと合います。事前分布からの標本 g(z) は patch ごとにばらばらの色の塊を並べたモザイクで、場面の形になりませんでした。

意味と限界、次の候補

確かめたこと：この設定（段 2 の VAE、ストリーム B = 1、15 歩目に学ぶ）では、mujou の PC-ALM はエンコーダとデコーダを BP と同じように学びました。判定の 2 つの指標だけでなく、勾配、尤度の経過、システムのデコーダの再構成も、float32 の丸めの範囲か、丸めが軌道の上で増えた範囲で BP と揃いました。

構成上の一致であること：ホストが ManualRun を木の順に周期 2 ms で歩ませると、15 歩目の誤差と λ が BP の credit に一致することは、設計とテストで示してあります。この結果は「PC-ALM が BP と違うものを学ぶか」ではなく、「mujou の実装が実データの 1800 秒で理論どおりに BP の勾配を出し続けたか」を確かめたものです。

確かめていないこと：mujou の非同期の実行（mujou.run。ノードが別々のスレッドで、決まった順に歩まない）では回していません。15 歩より少ない歩数（14 歩目では enc1 が外れることはテストで分かっています）、1800 秒より長い学習、ほかの optimizer も試していません。潜在空間の質は段 2 の BP と同じ所にあり、画素の PCA の符号や tube には届いていません。段 1 の読み「実装かモデルが原因」も解けないまま残っています。

  1. 候補 1
    非同期の実行（mujou.run）で同じ VAE を回す。BP との差（判定と同じ基準）と、val の bpd の対の差（この段では最大 0.0014）がどう変わるかを見れば、mujou の非同期性の上で目的を確かめられます。
  2. 候補 2
    歩数を減らして速さを上げる。PC-ALM の B = 1 は目標の 1.065〜1.08 倍しか余裕がありません。学ぶ歩を 15 歩目より前にすると BP の勾配から外れるので、どこまで減らすと判定が崩れるかを掃引で見ます。
  3. 候補 3
    posthoc の当てはめを平均してから符号を比べる。後から学ぶデコーダを seed を替えて数回当てはめ、平均を取るか揺れを誤差として書きます。今のままでは、1 本あたり標準偏差 約 0.0035 を下回る recon_blur の差は読めません。
