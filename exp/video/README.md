### 段 0: 線形回帰のストリーム（M6、2026-10-30）

**設定**
- $x\in\mathbb R^{32}$、平均は OU 過程（$\sigma_\mu=1$、ゆらぎ 0.3）、$y=w_*^\top x+0.1\,\eta$、600 秒（18,000 フレーム）、30 fps、バッチ 1
- 時間相関は $\tau_x\in\{1,10,100\}$ 秒と i.i.d.（同じ周辺分布）。seed は 0, 1, 2
- `pc.Chain` の 1 層 `Linear(32, 1)`、`learn_interval` 25 ms
- SGD は `tau=10`（1 フレームあたりの学習率 1/300）
- AdamW の向き（`AdamDirection`）は `tau_m` $\in\{0.1,0.3,1,3\}$ 秒、`tau_v=30` 秒。grafting あり（大きさを SGD にそろえる）となし（`tau=10`、要素ごとの歩幅 1/300）
- 指標は後半 300 秒の $\lVert w-w_*\rVert$ の時間平均
- 実行: `uv run python -m exp.video.stage0 run|summarize`（120 本、8 並列で約 25 分）

閾値は PLAN.md 8 節のまま（1.5 倍、10%）で、回す前に変えていない。

**H0 の判定: 棄却**（前半は支持、後半が棄却）
- 前半「歩幅をそろえると、AdamW の向き（$\tau_m=1$ 秒）は時間相関のあるストリームで SGD の 1.5 倍以上」: 支持。3.6〜5.0 倍で、$\tau_x=1$ では発散した。3 seed すべてで同じ
- 後半「i.i.d. にすると差は 10% 以内に縮む」: 棄却。i.i.d. でも 4.4〜4.5 倍のまま。差の大部分は時間相関ではなく、この問題での AdamW の向きそのものの悪さから来る
- 時間相関に固有の害は、$\tau_x\lesssim\tau_m$ のときにだけはっきり出る（grafting なし、$\tau_m=1$、$\tau_x=1$ で i.i.d. の 5〜6 倍）。ストリームが変わった後も、古い方向が momentum に $\tau_m$ の間残るためと読める。$\tau_x\gg\tau_m$（相関時間が momentum より長い）では 1.1 倍程度で、PLAN.md 5 節の「相関した偏りが打ち消されない」という害は、この問題ではほとんど見えない
- SGD は時間相関の影響をほとんど受けない（0.96〜1.25 倍）
- 但し書き: 最適解 $w_*$ が固定の線形回帰では、どの時刻の勾配も同じ $w_*$ を指すので、相関した偏りが害になりにくい。段 2 の世界モデルで見え方が変わるかは別に確かめる

**grafting を使うか: 使う**
- 歩幅で順位が入れ替わった。i.i.d. の grafting なしでは $\tau_m$ による差が無い（2.23〜2.40 倍）。grafting ありでは、$\tau_m$ とともに 1.5 倍から 4.4 倍、そして発散へと順に悪くなる
- PLAN.md 8 節の規則（順位が歩幅で入れ替わるなら、段 2 は grafting ありで比べる）に従う。大きさもそのままの `pc.optim.AdamW` は、実用上の参考として別に回す
- 注意: grafting は、向きが $G$ から遅れると発散しうる（$\tau_m=3$ では i.i.d. でも発散）。歩幅は $\lVert G\rVert$ に比例するのに、向きが誤差を減らす向きとずれるため。段 2 で直交化の向きが発散したら、その結果として記録する

**`learn_interval` と、PC-ALM と BP の差**（2 層 MLP 32-32-1、tanh、$\tau_x=10$、SGD、i.i.d. 損失の後半平均、seed 0/1/2）

| `learn_interval` | PC-ALM                    | BP                        | PC-ALM ÷ BP        |
| ---------------- | ------------------------- | ------------------------- | ------------------ |
| 25 ms            | 0.0154 / 0.0121 / 0.0135  | 0.0154 / 0.0121 / 0.0135  | 1.00 / 1.00 / 1.00 |
| `None`（毎周期） | 0.0162 / 0.0122 / 0.0138  | 0.0158 / 0.0121 / 0.0136  | 1.03 / 1.01 / 1.01 |

- **25 ms を使う**。PC-ALM は 3 桁まで BP と同じで、ストリームでの遅れは見えない。`None` は PC-ALM が BP より 1〜3% 悪く、25 ms より 1〜5% 悪い。計算も多い
- 計算の速さ: 線形回帰 600 秒分のストリームが約 80 秒（CPU 1 スレッド）

### 段 1: 合成動画での勾配の観測（M7、2026-10-30）

**最初の試行で分かったこと（崩壊）**
- $\kappa=0.05$（LeJEPA の既定）で回し始めたところ、180 秒で $z$ の分散がほぼ 0 になった。probe の値も初期から動いていなかった（9 本とも途中で止めた）
- 原因は 2 つ
  - 既定の初期化では $z$ の標準偏差が約 0.002 しかない（フレームの大半が黒いため）
  - $z\approx0$ の近くでは、SIGReg の 1 標本への勾配が $z$ に比例して消える（$\partial\hat\varphi/\partial x\propto t\sin(tx)\approx t^2x$）。概算すると、広げる力は $\kappa C z/D\approx0.0016\,z$ で、予測誤差が縮める力 $2(1-\kappa)/D\approx0.03$ の 1/20 しかない
- 対策 1（コード）: `model.standardize_`。LSUV と同じく、各畳み込みと線形写像の出力の標準偏差を、別の seed の 256 フレームで 1 にそろえる初期化を入れた。最後の写像だけを約 500 倍すると、`G1` へ返る credit も同じだけ増えて発散した（NaN）
- それでも $\kappa=0.05$ では 10〜30 秒で縮む。2 分の試し（学習率 0.03）では、$\kappa=0.5$ と $0.8$ でストリーム上の $z$ の標準偏差は 1.5〜2.5 を保ったが、実効ランクは 5〜36 で揺れた
- そこで段 1 は $\kappa\in\{0.05,0.5,0.8\}$ × 学習率 $\{0.01,0.03,0.1\}$ × seed 3（27 本）で回す。崩壊していたら $\kappa$ を直す、という PLAN.md の規則を前倒しした形になる

**回す前に確定した判定基準**

- 前提（崩壊していない）: 最後の評価で、$z$ の実効ランクが $D/2=32$ 以上、かつ評価クリップの上での $z$ の分散が 0.1 以上。後者は、尺度の崩壊を実効ランクでは検出できなかったので足した
- 採用する $(\kappa, 学習率)$: 前提を 3 seed すべてで満たすもののうち、後半 5 分の prequential 誤差を $z$ の分散で割った値（3 seed の平均）が最も小さいもの。前提を満たすものが無ければ、前提は満たされなかったと記録し、実効ランクの 3 seed の最小値が最も大きいものを使う
- 正直に書いておくと、M5 の 10 秒の試運転で、$\rho(10)\approx0.94$〜$0.99$ はすでに見えていた（学習の最初の 10 秒だけ）

### 表現の崩壊への対処（M9、2026-10-31）

**切り分け**（GPU で BP の短い試し。数字は 10 分後）

### SIGReg による |z| の押し広げと rollout10（M11、2026-11-01）

M10 で残った 2 つの課題を、段 3 の前に合成動画で直す。出発点は M9 の設定（`stop_target` あり、$\kappa=0.8$、SGD）。実行は `uv run python -m exp.video.stability run|summarize`。

**原因の見立て（回す前）**
- |z| の押し広げ: SIGReg（Epps-Pulley、重み $e^{-t^2/2}$）の 1 標本への力は、ほかの標本からの斥力（幅 1 のガウス核）と、原点への引力（$x\,e^{-x^2/4}$）の和になる。似たフレームが続くと、バッファにほぼ同じ $z$ が溜まる。今の $z_k$ はその自分のコピーから斥力を受けて外へ動く。裾では引力が消えるので、押し出しが止まらない（M9 で見た $\lvert z\rvert$ 12→76）
- rollout10: `stop_target` のもとでは、エンコーダは SIGReg からしか学ばない。予測誤差の credit は、目標の側では止められ、文脈の側（$z_{k-1}$）では記憶した定数で止まる。つまり「予測しやすい $z$ にする」信号がどこからも来ない。10 フレーム先が平均より悪いのは、動力学ではなく $z$ そのものが速く変わるためと考える。`persist10`（最後に見た $z$ をそのまま答えた誤差）が 1 を超えていれば、この見立てを支持する

**対策（コード）**
- `ModelConfig.z_norm`: `Z` の最後に係数なしの RMSNorm を置き、$z$ を半径 $\sqrt D$ の球面に載せる。$N(0,I_D)$ の質量が集まる場所で、$\lvert z\rvert$ はそれ以上伸びない。射影 $a^\top z$ はほぼ $N(0,1)$ になるので、SIGReg の目標とも矛盾しない
- `ModelConfig.target_weight`（$w$）: `stop_target` のとき、目標 $z_k$ へ返す予測誤差の credit を 0 ではなく $w$ 倍で返す。BP 版も、値は $z$ のまま勾配だけを $w$ 倍にする。$w=1$ は `stop_target` なし。M9 では $w=1$ で崩壊したが、`z_norm` があれば尺度の崩壊は起きないので、小さな $w$ で次元の崩壊を SIGReg が抑えられるかを見る
- どちらも `Z` と `Compare` の中で閉じる変更で、局所性・非同期性は変わらない（平衡点で `lam` が BP の credit に一致することを、`z_norm` と $w=0.3$ でも CPU と CUDA で確かめた）
- 評価に `persist{n}` を、フレームごとの記録に `z_rms`（$z$ の RMS）を足した

**回す前に確定した判定基準**
- 探索（10 分、seed 0/1/2、PC-ALM）: `z_norm` なし／ありを学習率 0.01・0.03・0.1 で。`z_norm` ありで $w\in\{0.03,0.1,0.3,1\}$ を学習率 0.01・0.03 で。`z_norm` ありの BP を学習率 0.01・0.03 で。計 48 本
- |z| の課題は、30 分の確認で、選んだ設定が PC-ALM と BP の両方・3 seed すべてで発散しないとき「直った」とする（M9 では BP の学習率 0.01 と PC-ALM の 0.03 で発散していた）
- rollout10 の課題は、30 分の確認の最後の評価で、`rollout10` < 1 が 3 seed すべてで成り立ち、同時に実効ランク 32 以上、$z$ の分散 0.1 以上、`rollout1` < 1 を満たすとき「直った」とする
- 選び方: 探索で、3 seed すべてが走り切り、ランク 32 以上・分散 0.1 以上・`rollout1` < 1 を満たすもののうち、`rollout10` の 3 seed 平均が最小のもの。差が 0.05 未満なら学習率の大きいもの

**seed 0 を見た後に足した候補（開ループの学習）**
- seed 0 の 10 分では、`rollout10` < 1 の設定は 1 つも無かった（最良は $w=1$ の 1.34 で、ランクは 12 に崩れた）。`persist10` は 2.0〜2.4 で、$z$ は 10 フレームでほぼ無相関に変わる。それでも開ループの予測は「平均を言う」（1）より悪い。不確かなら平均へ戻るのが最適なのに戻らないのは、動力学が観測した $z_{k-1}$ からしか学んでおらず、自分の予測を入力に戻すと誤差が積み上がるからと見た
- 対策（コード）: `ModelConfig.open_loop`（割合 $f$）と `open_cycle`（$C$ フレーム）。動画の予測を $C$ ずつに区切り、各区切りの後ろ $fC$ 個では、`Dynamics` が記憶する入力を観測した $z_{k-1}$ ではなく、`Compare` から受け取った自分の予測 $\hat z_{k-1}$ にする。比べる相手は観測した $z_k$ のまま。入力は記憶した定数なので credit はそこで止まり、局所性は変わらない（`Compare` から `Dynamics` へ予測を運ぶポートが 1 本増える）。BP 版も同じ規則にした。`preq` は観測を入力にしたフレームだけで測る（開ループのフレームは `open_error`）

**B 本のストリームを並べる（`DataConfig.streams`、2026-11-01）**

ホストは独立な合成動画を B 本、毎フレームまとめてバッチ `(B, ...)` として書く。各ノードはサンプルごとに活動と credit を持ち、バッチの平均の勾配で学ぶ（`pc.Layer` と同じ $g/B$）。ストリームの記憶（$z_{k-1}$、$s_{k-1}$、開ループの数え方、reset）はサンプルごとに持つ。ストリームどうしをつなぐのは、SIGReg の統計量（B 個の今の $z$ とバッファ）だけである。B=1 は前と同じ値になる（ビット単位で確認した）。algorithm-reviewer の監査は approve だった（局所性・非同期性は変わらず、PC-ALM と BP は同じ損失 $\frac1B\sum_b e_b + \kappa S$ の勾配で学ぶ）。

- SIGReg の項はパラメータに B 本分の和として届く。予測誤差の項は平均で届く。このため、同じ $\kappa$ でも B が大きいほど SIGReg が強くなる。サンプルあたりの重みは $\kappa B/(1-\kappa)$ で、B=128 では $\kappa=0.12$ がオフラインの $\lambda=17$ にあたる
- オフライン（SGD、`--local`、$\lambda=17$、学習率 0.1、12000 ステップ）では、窓の数が多いほどよい。128 窓で `rollout10` 0.976・ランク 33.2・`rollout1` 0.15 となり、4 つの条件を満たす。64 窓では 1.012、32 窓では 1.085 だった
- オンラインの B=128 は、学習率 0.03〜0.1 では、M11 の設定（$\kappa=0.8$、`stop_target`）も含めてすべて 1 分以内に崩壊した（評価クリップの分散 0、ランク 5〜12）。学習率 0.01 では崩れない

**位相をずらした B 本のストリーム（`DataConfig.spread`、2026-11-01）**

**rollout10 の判定（M11、見直した条件）**
- 条件を「デコードした予測の画素誤差が、5 フレーム先と 10 フレーム先で平均の画像の 0.95 倍を下回る。あわせて潜在空間で `rollout{n}` < `shrink{n}`」に改める。0.95 の余裕は、1 本の BP（比 0.99）を見た目どおり「動かない」に入れるために、上の 6 つの設定を見て決めた。新しいデータで確かめる必要がある
- この条件では、オンラインの設定はどれも満たさない。オフラインの上限も 5 フレーム先しか満たさない。合成動画でオンラインに 10 フレーム先の動きを学べた設定は、まだ無い

**ノードの数: エンコーダ 3、動力学 3**（`exp/video/latency.py`、RTX 4060）
- 学習を止めて EgoDex を流し、フレームの各ステップで、各ノードの `r + lam` を、同じ時点の状態から autograd で求めた BP の credit と比べた（相対誤差の中央値、100 フレーム）
- 時定数（$\tau_\lambda=2$ ms）が周期と同じなので、各ホップの緩和はほぼ 1 ステップで終わる。遅れはホップの数でほぼ決まる
- 全ノードの誤差が 5% 以内に入るまでの時間（書き込みから）:

| エンコーダ + 動力学 | Gauss-Seidel（手で回す順） | Jacobi（実時間と同じく、どの向きも 1 ホップ 1 周期） |
| ------------------- | -------------------------- | ---------------------------------------------------- |
| 1 + 1 | 4 ms | 8 ms |
| 2 + 1 | 8 ms | 10 ms |
| 3 + 1 | 12 ms | 14 ms |
| 2 + 2 | 8 ms | 14 ms |
| 3 + 2 | 12 ms | 16 ms |
| 2 + 3 | 12 ms | 18 ms |
| **3 + 3** | 12 ms | **20 ms** |

- 学習は書き込みから 26 ms のステップで起きる（`learn_interval` 25 ms）。どの分け方でも credit は学習までに回り切る。3 + 3 は Jacobi で 20 ms なので、残りは 3 ステップ。動力学をもう 1 ノード増やせば 22〜24 ms になり、余裕がほとんど無くなる。そこで **3 + 3** を使う（入力・SIGReg・Compare を足して 9 ノード）
- 実時間（`mujou.run`）では回せない: 3 + 3 を 4090 で 20 秒回すと、フレームの 47% で予測が間に合わなかった。9 ノードがそれぞれ 2 ms ごとに CUDA のカーネルを起動し、それが 1 つの GPU の上で直列になるため。段 1〜2 と同じく、手で回す仮想時間（`mujou.testing.run`）で回す。そこでの遅れは上の Gauss-Seidel の列にあたる
- 速さ: 手で回すと、4090 で実時間の約 6 倍かかる（CPU の 1 コアが律速。GPU は空いている）。5 本を同時に回しても 1 本あたりの時間はほぼ変わらないので、4090 に 2 本、4060 に 1 本の割合で並べる

**M9 の設定（`z_norm` なし）は EgoDex で発散した**
- 3 seed とも、$z$ の RMS が 0.34〜0.42 から 25〜40 まで伸び、ストリームの 1.9〜3.7 秒で NaN になった（1 を超えてから 1.3〜3.0 秒）。隣のフレームがほとんど同じなので、バッファに今の $z$ とほぼ同じ標本が溜まり、自分のコピーからの斥力で外へ押し出される。M11 で見立てた機構が、合成動画よりずっと速く起きた
- `z_norm` だけを入れると（学習率 0.01）、3 seed とも 6 分まで発散しなかった（GPU を空けるためにそこで止めた）
