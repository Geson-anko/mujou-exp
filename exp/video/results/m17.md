[README](../README.md) の結果の 1 節。MILESTONES.md の M17。再構成の項を使わない JEPA（V-JEPA・V-JEPA 2 の入力とマスク、LeJEPA の SIGReg）で、128×128×3・30 fps の Walking Tours のエンコーダを PC-ALM と BP で学ぶ。$z$ からの再構成、予測器を通した復元、$z$ の上の線形の動力学は、エンコーダを止めて後から測る（`task=posthoc`、`measure/encoder_eval.py`）。

この節は回す前に決めたことから書き始める。数字は物差し・試し・study・確認の順に、回した後で足す。

## 設定

- **データ**: `3c3e6805fdaa`（中央の正方形を 128×128 に縮めた、30 fps のまま）。Zurich を評価だけに使い（calib・val・test）、残りの 9 本で学ぶ

## 実装で決めたこと（回す前、2026-11-12）

レビューを受けて、study の前に次を決めた。

### 見える patch の数

マスクはブロックの和集合を守る。見える数は sample ごとに固定（形をそろえるため）で、和集合が残す見える数の下側 4 分位点にする（`masks.expected_keep`）。和集合がそれより少なく残す sample は引き直し（8 回まで）、多く残す sample は余分な見える patch を無作為に隠す（V-JEPA の collator が batch の最小に切り詰めるのと同じ向き）。8 回とも足りない確率は 1.5e-5 以下で、そのときだけ隠した patch を見せる。

| view | 和集合の見える数の平均 | 見える数（空間 64 のうち） | 計画の見積もり |
| -- | -- | -- | -- |
| 短い範囲（8 × 0.15） | 21.4 | 18（28%） | 27% |
| 長い範囲（2 × 0.7） | 9.6 | 8（12.5%） | 9% |

最初の実装は見える数を平均（21 と 10）にそろえていた。和集合が足りない約半分の sample で、隠したはずの patch を無作為に見せていた（長い範囲では context の約 4 割がブロックの中に散らばる。tube なので全フレームで見える）。BP と PC-ALM に同じく効くので比較は公平だったが、予測の課題が易しくなり、ユーザーの規則（ブロックの和集合）から外れていた。

### 探索の目的

$$
J = \log \max\left(\frac{\mathrm{recon}}{\mathrm{recon}_{\mathrm{PCA}}},\ \frac{r_1}{r_{1,\mathrm{PCA}}}\right),\quad r_1 = \mathrm{dyn}_1 / \mathrm{copy}_1
$$

上限は $\log 10$ で、崩壊（`z_spread` < 1e-3）・値の欠け・非有限も $\log 10$。sweep の発散した seed（`DIVERGED`）と同じ値で、PCA の 10 倍悪い符号は崩壊・発散と同じ順位になる（それより下にはならない）。

計画（MILESTONES.md）の式 $\max(\mathrm{recon}/\mathrm{recon}_{\mathrm{PCA}},\ \mathrm{dyn}_1/\mathrm{dyn}_{1,\mathrm{PCA}})$ から 2 か所を変えた。

1. **対数にした**: 最初の実装は比のまま、上限を $\log 10 = 2.30$ で切っていた。比が 2.3 を超える trial は、崩壊した trial や発散した seed と同点になる。smoke では、学習前の ViT と 4 秒学んだ ViT の比がどちらも約 3.7 で、上限に張り付いていた。対数にすると、比 10 までの trial は区別される
2. **動力学の項を写しとの比にした**: PCA の符号は最後の 1 枚から作るが、ViT の $z$ は $N$ 枚の積みから作る。隣り合う積みは $N-1$ 枚を共有するので、積みを読む符号はどれも構造上なめらかで、`dyn_1`（$1-R^2$）が小さく出る。smoke の学習前の ViT の `dyn_1` は 0.0026 で、PCA の 0.061 の 1/23 だった。このままでは $\max$ の動力学の項が効かず、$J \approx \mathrm{recon}/\mathrm{recon}_{\mathrm{PCA}}$ になる。写しの誤差 `copy_1` で割ると、入力の重なりが打ち消される

完了の条件の「`dyn_1` が同じ $D$ の PCA を下回る」も、この交絡のために学習しなくても満たされる。判定では `dyn_1/copy_1` で PCA と比べ、`dyn_1` は同じ積みを見る学習前の ViT と比べる。

### PCA との比べ方の補い

- **デコーダの入力の標準化**: $z$ のデコーダは学ぶ 9 本の $z$ の成分ごとの平均と標準偏差で標準化した $z$ を受け取る。PCA の上位の成分は標準偏差が数十になり、SIGReg で単位の尺度に近い ViT の $z$ と最適化の条件が違っていた。PCA の線形の再構成 `recon_lin` を物差しの行にあわせて載せる
- **白色化した動力学の誤差**: `dyn_h` は全成分の誤差の和を全分散で割るので、分散の大きい成分がゆっくり変わる PCA に有利に出る。SIGReg は $z$ を等方的にするので、速く変わる成分も同じ重みで数えられる。学ぶ側の $z$ の共分散で白色化した座標の誤差 `dynw_h`・`copyw_h` を併記し、PCA と比べるときに使う（$z$ の可逆な線形変換で変わらない）。目的の定義は変えない
- **stride ごとに分ける**: study の `vision.stride` は {2, 3, 6} で、$\Delta$ と一緒に動力学の 1 ステップも 0.067・0.1・0.2 秒に変わる。PCA の物差しは trial ごとに同じ stride で測るので比は部分的に正規化されるが、trial の間で比べている課題そのものが違う。結果は stride ごとの `dyn_1` を分けて載せ、上位を選ぶときに stride が違う trial を同じ土俵で並べていると書く
- **calib と val の近さ**: calib・val・test は、`eval_windows` が Zurich から無作為に選んだ slot を 3 つに分けたもの（M15 と同じ）。時間的に隣り合う slot が calib（ridge の $\alpha$ を選ぶ）と val（目的）に分かれると、ほぼ同じ場面が両方に入りうる。$\alpha$ を calib で選ぶので、val の `dyn_h` は少し楽観的に出うる。test も同じ扱い
- **エンコーダが止まっていること**: posthoc の前後で、エンコーダ・予測器の state_dict がビット単位で変わらないことをテストで確かめる（`tests/video/measure/test_encoder_eval.py::TestEncoderEval::test_the_encoder_is_held_bit_for_bit`）

### 補完の誤差（2026-11-12 に足した指標）

方針の見直し（MILESTONES.md の M17）を受けて、held-out の補完の誤差を指標に足した（`measure/completion.py`）。学習の損失は変えていない。

- **定義**: 隠し方ごとに、隠したトークンの集合 $\Omega$ について $E = \sum_\Omega \lVert \hat s - s \rVert^2 / \sum_\Omega \lVert s - \bar s_\Omega \rVert^2$（$1 - R^2$）。$\hat s$ は学習と同じ道（見えるトークンだけをエンコーダに通し、予測器で当てる）の予測、$s$ は積み全体を同じ重みに通した target のトークン。分母は隠したトークンの分散なので、トークンを縮めても $E$ は下がらない（損失 `pred` は下がる）。$\bar s_\Omega$ を当てると 1、完全に当てると 0
- **隠し方**: `short`・`long`（学習と同じ context view。split ごとに固定のマスク）と `future`（最後の 4 分の 1 の時間の slot のトークンをすべて隠す。$N=16$ では最後の 2 slot = 0.4 秒、$N=8$ では 1 slot。$N=1$ には無い）
- **鍵**: `comp_<kind>`（予測器）、`comp_<kind>_vis`（その積みの見えるトークンの target の平均で当てたもの。見えるトークンは target view の中で隠した位置にも attention しているので、甘い物差し）、`comp_<kind>_mean`（学ぶ 9 本の held-in の積みの target のトークンの、次元ごとの平均で当てたもの）
- **どこに出るか**: run の `evals.jsonl` の val・test の行（split 自身の値）。val の行には calib（`calib_comp_*`）と、学ぶ 9 本から取った固定の held-in の積み（`fit_comp_*`、`encoder_eval.stream_windows` の 256 窓、マスクは seed 2718）も載せ、held-in と held-out の差を見る。`baselines.json` の `init_comp_*` は学習前のネットワーク。posthoc の `metrics.jsonl`（`vit`）と `baselines.jsonl`（`init`。PCA には予測器が無いので無い）にも同じ鍵が出る。TensorBoard では `eval/<split>/comp_*`・`post/<split>/comp_*`・`base/<split>/init/comp_*`
- **目的**: 既定は今の $J$ のまま。`measure.encoder_objective=completion` を選ぶと、val の `comp_<kind>` の平均の対数を目的にする（崩壊・非有限は $\log 10$）。新しい目的の式はまだ決めていないので、暫定の選択肢として置いた
- 今の目的には $z$ の水準の予測が無いので、その $1 - R^2$ はまだ無い。$z$ の予測を足すときに一緒に足す（足した: 下の節の `zcomp_<view>`）

### 監査を受けた直し（2026-11-12、回す前）

試しの run の no-go を受けた監査（mini_train の再現、diag_ckpt）で、崩壊の原因は学習率・warmup・データの順序ではなく目的の式だと分かった。preset の損失（SIGReg を $z$ だけに、sg も EMA もなし）では、トークンをクリップごとの定数にして、context の平均で隠したトークンを当てるのが最適点に近い。i.i.d. の batch でも lr 1e-5 でも同じ崩壊が起きた。直したものと、実験で試せるようにしたもの:

- **補完の誤差の正規化**（不具合）: `comp_<kind>` の分母には積みの間の広がりも入るので、トークンが積みの中でつぶれても小さく出ていた。積みの中の広がりで割る `ncomp_<kind>`（`_vis`・`_mean` も）を足した。崩壊の監視として、行に `tok_within`（積みの平均トークンからのずれ）、`tok_between`（積みの平均トークンの split の中の分散）、`tok_temporal`（同じ空間位置の slot の間のずれ。slot が 2 つ以上のとき）も載せる
- **トークンの崩壊の防止**（不具合）: `vision.token_sigreg` で SIGReg のかけ方を選ぶ。`scaled`（今までどおり、$T$ で割る）、`raw`（割らない）、`clip`（積みの平均を引いたトークン、割らない）。`wt_n16`・`wt_n8`・`wt_n1` の preset は `sigreg_on: both`・`token_sigreg: clip` に直した。preset の損失が、つぶれたトークンより広がったトークンを選ぶことをテストで確かめる（`test_m17_tokens_constant_within_a_stack_are_not_an_optimum`）。直す前の preset はこのテストに落ちる
- **評価の batch**: 損失と SIGReg を出す batch を、split の窓を固定の順に混ぜて組む（`PackedMeasures.order`）。時刻順では 1 本の動画の数分から batch ができ、val の SIGReg が高く出ていた。行の `loss`・`pred`・`sigreg` の値はこの直しで変わる（`rank`・`z_spread`・補完の誤差は変わらない）
- **長い範囲の view の見える数**: 上の表を 6 から 8（12.5%）に直した

レシピとの差は、どれも既定では今までどおりで、設定で選べる:

| 設定 | 内容 |
| -- | -- |
| `optim@optim_vision=adamw_step` | step で数える AdamW（`exp.lib.optim.StepAdamW`、`torch.optim.AdamW` と一致）。`lr` は 1 step あたり、`betas`、`weight_decay`（2 次元以上のパラメタだけ）と `weight_decay_end`（`decay_steps` まで線形）、`warmup_steps`（学習率だけを線形に上げる）、`decay`（`constant` か `cosine`、`min_lr` 倍まで）、`clip`（ノードの勾配のノルム）。preset の値は 7.5e-5、warmup 1800 step、cosine で 18000 step（600 秒）に 1e-3 倍、wd 0.05 |

### 時空間の補完（2026-11-12 に足した目的）

ユーザーの方針（課題は時空間の補完、再構成の項なし、LeJEPA の形でもよい）を、損失の選択肢として入れた（`jepa/loss.py`）。

- **時空間の view**: context の view に `future` を足せる（`{blocks: 8, scale: 0.15, future: 2}`）。最後の `future` 個の時間の slot をまるごと隠すので、その view は過去だけを、ブロックの外だけ見る。`blocks: 0` なら過去を全部見る。見えるトークンがブロックの中にも未来にも無いことをテストで確かめる
- **$z$ の水準の補完**: 各 view の pool $z_v$ を projector に通して $u_v$ とし、context の view の $u_v$（任意で view の種類つきの小さな予測器 $q$）が、積み全体の $u_g$ を当てる。$L = (1 - \lambda)(\beta L^{\mathrm{pred}} + \alpha L^z) + \lambda S$。設定は `vision.z_weight`（$\alpha$）、`vision.token_weight`（$\beta$、0 ならトークンを当てない）、`vision.projector`（各層の幅、最後が出力）、`vision.zpred_hidden`（$q$ の幅、0 なら $q$ なし）。`vision.sigreg_on=views` は view ごとの $u$ の SIGReg（LeJEPA）、`views_tokens` はそれとトークンの SIGReg の平均。損失はすべてヘッドのノードの中にあり、PC-ALM のエンコーダのノードの `lam` が BP の credit と一致することをテストで確かめる。posthoc の特徴量 $z$ は今までどおり（projector の前）
- **指標**: 行に `zcomp_<view>`（held-out の $u_g$ を各 context view から当てる $1 - R^2$。projector が無ければ $z$ そのもの）と、$\alpha > 0$ なら `zpred`（損失のその項）を載せる
- **preset**: `m17/st_n16`（3 つの context view: 短い範囲、長い範囲、過去。$\beta = 0$、`sigreg_on: views`、projector [512, 512, 64]、SIGReg 512 方向、`adamw_step`）と、`m17/st_tok_n16`（同じものに、トークンの予測を $\beta = 0.5$、target は LayerNorm、`views_tokens`・`token_sigreg: clip`）

`exp/video/diag/imagenette.py` は、レシピの §3 の基準の課題（LeJEPA の minimal を Imagenette で）を回す診断のコードで、run の program ではない。`prep` は Imagenette（`imagenette2-160`）の JPEG を ffmpeg で 128 px の u8 にする。`train` は M17 の ViT を画像（64 トークン）で BP と `StepAdamW` で学び、学習前から `--every` step ごとに val の線形 probe（ridge、one-hot）の正解率を `log.jsonl` に書く。`--mode lejepa` は LeJEPA の minimal（拡張した view、projector、view ごとの SIGReg。段階 S2）、`--mode masked` は M17 の packed の形をそのまま画像に（`--objective tokens` はトークンの予測と `clip` の SIGReg、`z` は $u_g$ の補完。段階 S3、EMA なし）。合格の目安は、学習前の probe から 30 ポイント以上。まだ回していない

## 判定基準（回す前に決めた、2026-11-12）

MILESTONES.md の M17「完了の条件」に、上の物差しから閾値を入れたもの。**test**、run の最後のチェックポイントの posthoc、**PC-ALM と BP、seed 0/1/2 のすべて**で次を満たすこと。設定は BP の study（seed 100・101、val、目的 $J$）で選び、確認の seed は選択に使わない。閾値は確認の run の $D$・$N$ の行を使う。$D=256$・$N=16$ では次のとおり。

1. 発散しない（`status` が `completed`）、崩壊しない（`z_spread` ≥ 1e-3）
2. **再構成**: `recon` < 0.180（PCA-256 の `recon_PCA`）。学習前の ViT（0.713）も下回る。$D$ = 128・512 では 0.226・0.140

## 判断（2026-11-12）: study と確認に進まない（no-go）

- **$N$ と run の長さ**: $N=16$・B=32・600 秒（PC-ALM の見積もり 5.8 時間 < 7 時間）。$N=8$ に落とす必要はない。ただし下の理由で、確認の run はまだ回さない
- **no-go の理由**: preset の JEPA（BP）は $N$ = 16・8・1 のどれでも、学ぶほど学習前の ViT より悪くなる（val の `recon` 0.63〜0.66 → 0.75〜0.81、`dyn_1/copy_1` 0.48〜0.84 → 0.95〜1.0）。規則の中で試した 9 つの変更（SIGReg の重み・かけ先、学習率、マスク、sg、B）でも、学習前を下回る設定は無かった。今の探索空間（`studies/m17_wt_bp.toml`）はこれらの軸の組み合わせなので、32 trial の study で判定基準（`recon` < 0.180 は学習前の 0.713 の 1/4）に届く見込みは低い。BP で届かない設定を PC-ALM で確かめる意味もない
- **何が起きているか**: 学ぶ側の SIGReg は 32 本のストリーム（9 本の動画）の間の違いで満たされる。$z$ は場面の色・明るさ（どの動画か）を持ち、1 本の動画の中の違い（建物、道、人）を持たない。トークンの予測は、隠したトークンを場面の平均で当てれば `pred` が下がる。SIGReg を強めると、$z$ は学ぶ 9 本を見分ける向きにだけ広がり、Zurich に移らない
- **評価の側の注意**: ViT の符号は学ぶ側と val の差が大きい（学習前でも `recon_fit` 0.32 と val 0.63）。デコーダは 2048 個の窓（各 9 積み、場面は 2048 か所）から学ぶので、場面を覚えられる。PCA には差がない。符号の比較は val の値で行っているので判断は変わらないが、デコーダの学ぶ窓を増やすと ViT の値は少しよくなりうる

次に決めること（ユーザーの判断が要る。どれも規則「再構成の項なし・EMA なし」の中）:

1. **予測を $z$ の水準でも行う**（LeJEPA の形）: 今は SIGReg を pool した $z$ にかけ、予測はトークンごと。$z$ は予測の損失を直接受けない。context view の $z$ から target view の $z$ を当てる項を足せば、$z$ が場面の中の違いを持つ向きに押される
2. **pool を学ぶ**（attentive pooling、V-JEPA の probe の形）: $z$ は 1 本のベクトルのまま。今の packed は平均の pool だけ
3. **短い run・低い学習率**: 最良のチェックポイントがいつも 300 秒なので、学習率 3e-5〜1e-4 と 300〜600 秒を探す。ただし学習前を下回った run は無く、学習で得をしている証拠はまだない

## 診断（2026-11-12、BP、seed 100）

方針の見直し（MILESTONES.md の M17）を受けて、試しの no-go の原因を切り分けた。腕は 4 つ。

- A: 既知の基準の課題（Imagenette）で、私たちの ViT・SIGReg・optimizer が学べるか
- B: ストリームか i.i.d. か
- C: 学習率と warmup
- D: 目的の式（トークンの予測、時空間の補完、EMA と LN + sg の対照）

どれも BP、seed 100、600 秒。$N=16$ の 6 本（D と、B の時空間の版）のほかは $N=8$。設定は「監査を受けた直し」の後の preset で、トークンの SIGReg は `clip` にしてある。「何が分かれば何と言えるか」は回す前に次のように決めた。A で学習前より 30 ポイント以上上がらなければ、部品に不具合がある。B で i.i.d. だけが下がるなら、原因はストリームの相関にある。C で学習率を下げたほうが良くなるなら、学習率が高すぎた。

コード: run と posthoc は snapshot `dfaa437`、`m17-dx-n8-v2` とその posthoc、Imagenette の 2 本（`nocolor`・`masked-z-lr3e-4`）は `a9cfa9d`（`--no_color` を足した後）。どちらも `d86a328` の上で、mujou は `7a8b72e`（origin にある）、データは `3c3e6805fdaa`。ホストは std-00・02・03 の 4090 と 4060。std-01 は `just fleet doctor` で健全と出た。ただし cordon のまま WT のデータも無いので、Imagenette だけに使った（fleet の外で手で起動）。

### 結論

- **不具合はあった。主因は直した 2 つ（積みの中のトークンの崩壊と、補完の誤差の正規化）だった**。直した後の preset のトークンの予測では、held-out の Zurich の補完の誤差（`ncomp`）が学ぶほど単調に下がる（EMA と LN + sg の対照を除く）。値は学習前のネットワーク（1.65〜1.76）と、自明な予測（見えるトークンの平均 `_vis` 1.06〜1.23、学ぶ側の平均 `_mean` 約 1.2）のどちらよりも小さい。600 秒の時点でもまだ下がっている。held-in（`fit_`）と held-out の差は −0.01〜0.06 で、学ぶ 9 本の場面を覚えているだけではない。学習率 1e-4 以下のトークンの予測の腕では、posthoc の `recon` も学習前より良く、300 秒から 600 秒にかけて良くなる（試しの「最良は 300 秒、その後は悪くなる」は消えた）
- **学習率は高すぎたのではなく、低すぎた**。補完の誤差は学習率とともに単調に良くなる（$N=8$、短い範囲の val: 1e-5 で 0.85、3e-5 で 0.64〜0.69、1e-4 で 0.41〜0.48、3e-4 で 0.19）。warmup は 0 か 6000 step（600 秒の 1/3）かで差が小さく、6000 のほうが少し良い。cosine の減衰を外すと（一定の 1e-4）0.27 まで下がる。`adamw_step` の preset の cosine は 18000 step（1 step ≈ 1 フレームの見積もり）で peak の 1e-3 倍に着く。BP が `time.learn_interval` の 25 ms ごとに学ぶなら、run は約 24000 step 学び、最後の約 4 分の 1 は最小の学習率で進む（step の数は確かめていない。checkpoint に optimizer の状態が無い）
- **ストリームか i.i.d. かは効かない**。同じ目的で、短い範囲の val は 0.525 と 0.511（$N=8$）、時空間の版の `zcomp` は 0.091 と 0.086 だった
- **部品は学べる**。Imagenette の LeJEPA（色の拡張つきの view）では、私たちの ViT・`exp.lib.sigreg`・`StepAdamW` で、線形 probe が学習前の 40.7% から 78.5% に上がった（+37.8 ポイント、合格の目安 +30）。BP で学べない設定ではない
- **限界は目的の式（拡張のない view とマスク）にある**。同じ ViT と Imagenette でも、マスクした view（M17 の packed の形、拡張なし）では、$z$ の補完が 55.9%（+15）、トークンの予測が 47.6%（+7、学習率 3e-4）にとどまる。学習率 2e-3 では 25.8% で、学習前より悪い。LeJEPA から色の拡張だけを外すと 64.1%（-14.4 ポイント）。WT でも、どの腕の posthoc の `recon` も 0.53〜0.74 で、PCA-256（0.180）に遠い。デコーダの像は場面の色と明暗の配置（上が空、下が地面）までで、建物・人の輪郭は出ない。`dyn_1/copy_1` は 0.72〜0.99 で、学習前（0.51）より悪い
- **補完の損失だけでは表現の良さを測れない**。Imagenette では、学ぶにつれて損失は下がり続けるのに、probe は止まる（$z$ の補完: 損失 0.25→0.14 の間に probe 55.7→55.9%。トークン: 0.98→0.59 の間に 47.4→47.6%）。WT の学習率の列では、1e-4 までは `ncomp` が小さい腕ほど posthoc の `recon` も小さかった。ところが 3e-4 では、`ncomp` が一番小さい（0.19）のに、`recon` は 300 秒の 0.578 から 600 秒の 0.614 に悪くなった（val）。補完の誤差が小さいことは必要だが、それだけでは足りない
- EMA（0.996）と、target の LN + sg は、どちらも補完の誤差・`recon` ともに悪くした（ランクだけは 9〜10 に上がる）

### 判断と次の study への推奨

2. **次の study の設定（推奨）**: `+experiment=m17/wt_n8`（または `wt_n16`）に `optim@optim_vision=adamw_step optim_vision.warmup_steps=6000`、`optim_vision.decay=constant`（継続学習には終わりが無いので、V-JEPA 2 の warmup-constant の形）、学習率は [5e-5, 3e-4]（log）。3e-4 では補完の誤差が下がり続けるのに `recon` が悪くなったので、上の端は posthoc を見て決める。トークンの SIGReg は `clip` のまま。ストリームのままでよい（i.i.d. は要らない）。EMA と LN + sg は使わない。時空間にするために、context の view に未来の view（`{blocks: 8, scale: 0.15, future: 2}`）を足す。$z$ の水準の補完（`st_tok`）はランクを上げるが補完の誤差と `recon` を悪くしたので、軸として残す（`vision.z_weight` {0, 1}）
3. **まだ実装していない、効きそうなもの**: view ごとの色の拡張（Imagenette で LeJEPA の probe を 14.4 ポイント上げた）。WT の色の近道を塞ぐので、次の study の前に足すことを勧める
4. **study の目的の案（ユーザーが決める）**: 潜在空間でマスクを予測する損失そのものを held-out で測る（MILESTONES.md の決定）。そのまま `pred` を使うと、トークンを縮めれば小さくなる。そこで、積みの中の広がりで割った次の版を案とする。

$$
J_{\mathrm{comp}} = \log \frac{1}{|K|} \sum_{k \in K} \mathrm{ncomp}_k,\qquad \mathrm{ncomp}_k = \frac{\sum_{i}\sum_{t \in \Omega_{i,k}} \lVert \hat s_{i,t} - s_{i,t} \rVert^2}{\sum_{i}\sum_{t \in \Omega_{i,k}} \lVert s_{i,t} - \bar s_{i} \rVert^2}
$$

  ここで $K$ = {短い範囲, 長い範囲, 未来}、$\Omega_{i,k}$ は積み $i$ で隠したトークン、$\bar s_i$ は積み $i$ の target のトークンの平均（val、Zurich）。崩壊・非有限は $\log 10$。加えて、`tok_within` / (`tok_within` + `tok_between`) < 0.1 か `z_spread` < 1e-3 なら $\log 10$ にする（積みの中のつぶれと $z$ の崩壊の見張り）。今の `measure.encoder_objective=completion` は `comp`（積みの間で割る）なので、`ncomp` に替える必要がある。注意: Imagenette では、損失が下がり続けても probe が止まった。$J_{\mathrm{comp}}$ は同じ目的の族の中で設定を選ぶのに使える見込みがある（WT の学習率の列では 1e-4 までは `recon` と同じ順だったが、3e-4 で外れた）。ただし、目的の式（$\beta$、$\alpha$、view）をまたいで比べると、target が違うので公平でない。目的の式を探索の軸に入れるなら、posthoc の `recon_blur` を並べて見る

### 結論

- **積みの中の崩壊（C）は防げた**。6 本とも発散しなかった。held-out（Zurich の val）の潜在のマスク予測の損失 `pred` は、学習前の 0.74（$d$=16）・0.86（$d$=32）から、600 秒で 0.003〜0.031 まで下がった（ほぼ単調）。held-out のトークンの SIGReg は、最初の 300 秒は 372〜834 で上下し、600 秒で 10〜103 になった。C の値（約 540）より十分小さい。積みの中の広がり `tok_within` は、6 本とも 60 秒以降 0.66〜0.99 で、学習前（0.42 / 0.48）より大きいままだった
- **ただし 600 秒の範囲で、トークンが位置だけの関数 $s(x,p) \approx g(p)$（P）に近づく向きが見えた**。posthoc で平らにしたトークン列の、積みの間の広がり `z_spread` は、学習前の ViT の 0.67 から、300 秒で 0.35〜0.46、600 秒で 0.04〜0.31 に下がった。P に着いた run はない（`z_spread` から見た場合。のちに `comp_*_pos` で直接確かめると、$d$=16・$\lambda$ = 0.0017 は 600 秒で P にほぼ着いていた。下の「ストリームごとのバッファ」）。600 秒のうち前半の 300 秒は学習率の warmup で、ピークの学習率で回したのは後半だけ。この先どこへ行くかは確かめていない
- **再構成は 300 秒から 600 秒で良くなった**。`recon_blur`（val）は 6 本とも下がった（例: $d$=16・$\lambda$ = 0.0017 で 0.31 → 0.25）。デコーダで読める情報は減っていない。それでも学習前の ViT（0.15 / 0.12）には届かない
- **P の SIGReg の値は、標本数 $N$ に比例して大きくなる**（$S_P \approx (N/512)\,c$）。一方、C の値（約 $1.06\,T$ = 542）は $N$ によらない。今の $N$（32 積み + バッファ 8192 個 = 48 積み分）では、ガウスのモデルの下で、どの $\lambda$ でも P か独立なトークンの解（I）が最適になる。これは今の $N$ と、そのモデルの仮定に限った結論である（下の「P の SIGReg と標本数」）
- **判定はつけない**。回す前に置いた基準（`tok_between` が学習前を下回らない）に当てはめると棄却になる。しかし `tok_between` は P に固有の指標ではない。しかもこの基準が記録に現れるのは、結果と同じコミット `80dce42` である（下の「判定の基準」）。P かどうかは、既存の checkpoint で直接確かめる（ユーザーの決定、MILESTONES.md の M17）
- held-out の `pred` と `sigreg` が小さいことだけでは、P を見分けられない。P は `pred` を 0 にするため
- ルール（[memory](../../memory/feedback_simple_fundamental.md)）に従い、目的の式には何も足していない

### 設定

- preset `m17/tok_n16`（`wt_n16` を継承）。0.1 秒おきの 16 フレームの積み、tubelet 2・patch 16 で 8 slot × 64 位置 = 512 トークン。最後の段が各トークンを $d$ 次元に線形に写す（`vision.token_dim`、LeCun の初期値）。積みの $z$ はトークンの平均（監視だけに使う）
- 損失は 1 ストリームあたり $(1-\lambda) L_{\mathrm{pred}} + \lambda S$。$L_{\mathrm{pred}}$ は隠したトークンを予測する二乗誤差（V-JEPA の短い範囲と長い範囲の 2 つの context の view）。$S$ は Epps–Pulley 統計量（256 方向をフレームごとに引き直す。[−5, 5] の 17 点）。標本はいまのターゲットのトークン $B \cdot 512$ 個と、過去のターゲットのトークン 8192 個（`vision.token_buffer`）。過去のトークンは毎フレーム 64 個を有効なストリームから非復元で引いて入れ、満杯の後はランダムな行と入れ替える（`exp.lib.sigreg.insert_`）。$T$ で割らず、積みの平均も引かない（`token_sigreg=raw`、`sigreg_on=tokens`）。勾配はいまのトークンにだけ流れる
- BP、seed 100、600 秒（18000 フレーム）、$B$ = 32。optimizer は `wt_n16` と同じ。格子は $\lambda \in \{0.0017, 0.0026, 0.0038\}$ × $d \in \{16, 32\}$ の 6 本
- 指標（`evals.jsonl` の val、60 秒ごと）:
  - `pred`: held-out の $L_{\mathrm{pred}}$
  - `sigreg`: held-out の $S$（評価の 32 積みだけで、バッファなし。学習中の $S$ と標本数が違う）
  - `tok_within`: 積みの平均トークンからの二乗の広がり
  - `tok_between`: 積みの平均トークンの、積みの間の分散
  - `tok_temporal`: 同じ空間の位置の、slot の間の広がり
- posthoc（`decode.ckpts=all`: 300・600 秒）: 積みの符号は平らにしたトークン列（`measure.posthoc_code=tokens`、$D$ = 512 $d$ = 8192 / 16384）。物差しは同じ次元の画素の PCA と、学習前の同じ ViT（`task=baselines`）

### $\lambda$ の格子の導出

損失は 1 ストリームあたり $(1-\lambda) L_{\mathrm{pred}} + \lambda S$。SIGReg がトークンの周辺分布を $N(0, I)$ に保てば $\mathbb{E} s^2 = 1$ なので、ゼロを予測しても $L_{\mathrm{pred}} \le 1$。健全な解 H $(L_H, S_H)$ を、2 つの自明な解と比べた。

- 積みの中の崩壊 C: 積みの中のトークンが一定。$L = 0$、$S_c = S(1)$
- 独立 I: トークンが iid の $N(0, I)$。$L = 1$、$S_0 = S(0)$

H が C に勝つ条件は $\lambda (S_c - S_H) > (1-\lambda) L_H$、I に勝つ条件は $\lambda (S_H - S_0) < (1-\lambda)(1 - L_H)$。予測で得をするのが積みに共通な成分だけだとするガウスのモデル $s = \sqrt{\rho}\, c + \sqrt{1-\rho}\, e$（$T$ = 512）では、$L_H = 1 - \rho$ で、

$$
S(\rho) = \sqrt{2\pi}\Big[(T-1)\Big(\tfrac{1}{\sqrt{3-2\rho}} - \tfrac{1}{\sqrt 3}\Big) + 1 - \tfrac{1}{\sqrt 3}\Big],\quad S(0) = 1.06,\quad S(1) = 1.059\,T = 542
$$

窓は $\lambda_{\mathrm{lo}} = (1-\rho)/(S(1) - S(\rho) + 1 - \rho)$、$\lambda_{\mathrm{hi}} = \rho/(S(\rho) - S(0) + \rho)$ になる。$\rho$ が小さいと $\lambda_{\mathrm{lo}} \approx 1/542$、$\lambda_{\mathrm{hi}} \approx 1/247.5$ で、$\rho$ にも $d$ にもほとんどよらない。

学習前の ViT のトークンで測った $\rho$（seed 100。256 本のランダムな単位方向に沿った値の平均）は、学習ストリームで 0.122（$d$=16）・0.106（$d$=32）、val で 0.079・0.061。これを入れると、窓は学習ストリームの $d$=16 で $[1.72, 3.79] \times 10^{-3}$、$d$=32 で $[1.74, 3.83] \times 10^{-3}$ になった。格子は両端とその幾何平均の $\{1.7, 2.6, 3.8\} \times 10^{-3}$ とし、$d$ = 16 と 32 で共通に使った。

実測の $S$ では、標準化したトークンが 62 / 81（バッファなし）・87 / 118（バッファあり）、白色化した積みの平均トークンへの強制した崩壊が 612 / 624・563 / 549 だった（$d$ = 16 / 32、学習ストリームの最後の 512 フレームの平均）。与えられた基準 $\lambda > 1/(S_c - S_H + 1)$ に実測値を入れると 1.8〜2.3 × 10⁻³ で、格子の下端 1.7 × 10⁻³ は、学習の初めに C が勝つかどうかの境目にあたる。学習前の生のトークンの $S$（2789〜5108）は C の値より大きいが、これは尺度・平均・位置ごとの平均のずれで、最後の線形層のアフィンで直せる。再現の情報は下に書いた。

### 判定の基準

- 支持: 600 秒で held-out の `pred` が学習前より小さく、崩壊がない。崩壊がないとは、held-out の `sigreg` が C の値（約 540）より十分小さく、`tok_between` が学習前（0.04）を下回らないこと
- 棄却: どの $\lambda$ でも崩壊する

### P の SIGReg と標本数（導出）

3 つ目の自明な解 P を、位置だけの関数 $s(x, p) = g(p)$ とする。$p$ は slot と空間の位置で、512 通りある。

- **予測の誤差は 0**。予測器は隠したトークンの位置を受け取るので（`PackedPredictor` の `mask_token + pos[tgt_ids]`）、$g(p)$ をそのまま出せる。$L_{\mathrm{pred}} = 0$
- **P の SIGReg の値は、標本数 $N$ に比例する**。標本は 512 点 $\{g(p)\}$ を並べたものになる。$S$ は $N$ と、この 512 点の分布と $N(0, I)$ の距離の積なので、$S_P \approx (N/512)\, c$ になる。$c$ は点の置き方で決まる
- **C の SIGReg の値は、$N$ によらない**。C の標本は、$n$ 個の積みの $c(x)$ を 512 回ずつ並べたものになる。$c(x)$ が $N(0, I)$ なら、$n$ 点の分布と $N(0, I)$ の距離はおよそ $1/n$ に比例する。$N = 512\, n$ を掛けると $n$ が消え、約 $1.06\, T$ = 542 が残る（上の $S(1)$）

$g(p)$ を iid の $N(0, I)$ から引いた点にしたときの $S_P$ は次のとおり（$d$ = 16、seed 0、3 回の平均。`exp.lib.sigreg.sigreg` で計算した）。

| $B$ | バッファ | $N/512$ | $S_P$ |
| -- | -- | -- | -- |
| 1 | 0 | 1 | 1.0 |
| 1 | 8192 | 17 | 17.7 |
| 32 | 0 | 32 | 31.5 |
| 32 | 8192（この節の run） | 48 | 51.5 |
| 32 | 65536 | 160 | 212 |
| 32 | 262144 | 544 | 573 |

P は、$N$ が小さいほど安い。$B$ = 1 でバッファがなければ $S_P \approx 1$ で、P はほとんど罰されない。$N/512$ が 500 を超えると、P の値は C の値と同じ程度になる。学習で着いた点の置き方では、$c$ はもっと小さくなりうる（600 秒の学ぶ側の $S$ は 8〜26 で、同じ $N$ の iid の点の 51.5 より小さい）。

前の版では「C と P は対をなす。まとめた SIGReg は C を除き、P を除かない」と書いた。これは誤りだった。P の罰は $N$ とともに大きくなり、C の罰は $N$ によらない。

目的は $J = (1-\lambda) L + \lambda S$ で、P は $J_P = \lambda S_P$ になる。健全な解 H $= (L_H, S_H)$ と比べると、$S_H \ge S_P$ なら、$L_H > 0$ である限り、すべての $\lambda$ で P が勝つ。上のガウスのモデルでは $S(\rho) \approx 1 + 246.5\rho$ である。$S_P$ を 10〜50 とすると、$\rho \gtrsim$ 0.04〜0.2 の H は P に負ける。$\rho$ がそれより小さい H は $L_H \approx 1$ で、P に勝つには $\lambda \gtrsim 1/(S_P - S(\rho) + 1) \approx$ 0.02〜0.1 が要る。一方、H が I に勝つには $\lambda \lesssim 1/247.5 = 0.004$ が要る。両方を満たす $\lambda$ は無い。

この結論は、次の条件に限られる。

- **今の $N$**（48 積み分）。$N$ が大きいと $S_P$ が大きくなり、H が P に勝つ $\lambda$ の窓が開きうる
- **ガウスのモデル**。予測で得をするのは、積みに共通な成分（大域の $\rho$）だけだと仮定している。依存が局所的（近いトークンだけが強く相関する）なら、まとめた SIGReg の罰は小さい。$L_H < 1$ のまま $S_H$ の小さい H がありうる
- **有限個の候補**。比べたのは C・I・P・H($\rho$) だけで、$\lambda$ の窓の導出と同じ限界を持つ。観測した状態は $g(p) + \varepsilon\, h(x, p)$ の形に見え、$\varepsilon$ は $\lambda$ とともに大きい（posthoc の `z_spread` が $\lambda$ とともに増える）。$\lambda$ で決まる内部の解に止まっている可能性を、導出は除いていない

600 秒の `pred`（0.003〜0.031）と `ncomp`（0.003〜0.05）は P と矛盾しない。しかし H でも小さくなるので、P を示す証拠にはならない。

### 判定

- **判定はつけない**（1 seed、600 秒、うち 300 秒は warmup）
  - C は防げた。held-out の `sigreg` は 10〜103 で、`tok_within` は 60 秒以降 0.66〜0.99（学習前 0.42 / 0.48）だった
  - P へ向かう向きは、posthoc の `z_spread`（300 秒の 0.35〜0.46 → 600 秒の 0.04〜0.31）に見えた。ただし `z_spread` は P の直接の指標ではなく、`z_spread` からは P に着いた run は見えない（のちの `comp_*_pos` の確認では、$d$=16・$\lambda$ = 0.0017 が 600 秒で P にほぼ着いていた）
  - 回す前に置いた基準は `tok_between` で崩壊を判定するが、`tok_between` は P を見分けられない。基準を回す前に書いたことも、記録から確かめられない（上の「判定の基準」）
- **言えないこと**: P が目的の最適だという主張は、今の $N$ とガウスのモデルに基づく。より長く回したときの行き先と、seed による違いは確かめていない。1 回の評価の値は、隣の時刻との差が値と同じ桁ある（例: `f8cef62c` の held-out `sigreg` は 540 秒で 191、600 秒で 20.7）
- **主な指標について**: held-out の `pred` と `sigreg` は、どちらも小さいまま P の向きに動いた。この 2 つだけでは P を見分けられない

目的の式は変えない。MILESTONES.md の M17 の決定に従い、次の 4 つを行う。

1. **P を既存の checkpoint で直接確かめる**。学んだ予測器を、位置ごとの平均トークンを出す自明な予測器（`comp_<kind>_pos`）と比べる。P なら `comp_<kind>_pos` と `ncomp_<kind>_pos` が 0 に近い（位置ごとの平均で当たる）。`comp_<kind>` が `comp_<kind>_pos` を下回れば、予測器は位置より多くを文脈から得ている。両者がほぼ等しいだけでは P とは言えない（両方が 1 に近ければ独立なトークンの解 I）
2. **過去のトークンのバッファをストリームごとに持つ**。$B$ 本なら、容量は $B \cdot 2048$ 個で、毎フレーム $B \cdot 512$ 個（有効なストリームのターゲットのトークンすべて）を入れる。ランダムに入れ替えるので、バッファの中のトークンの齢は幾何分布になる。平均は容量 / 挿入 = 4 フレーム（10 fps の学習で、ストリームの 0.4 秒）で、$B$ によらない。$B$ = 32 と $B$ = 1 の両方を回して並べる。標本数は $B$ = 32 で $N/512$ = 160、$B$ = 1 で 5 になり、上の表の $S_P$ が大きく違う
3. **再構成**: マスクしない特徴量（積み全体をエンコーダに通したもの）を、同じトークンのデコーダで描き戻した誤差も測る。予測器を通したマスクの復元と、同じ画素で並べる
4. **画像**: 最後に、入力・再構成・マスクした復元の組を 10 組ほど見せる

$B$ = 1 と $B$ = 32 の比べ方について、回す前に分かっていることを書いておく（2026-11-12）。

- **同じ $\lambda$ でも、同じ折り合いにはならない**。学習の損失は $(1-\lambda)\,\overline{\mathrm{pred}} + \lambda S$ で、$\overline{\mathrm{pred}}$ は $B$ 本のストリームの平均である（`jepa_loss_packed` の `total / b`）。予測の項からトークン 1 個が受ける勾配は $1/B$ に比例する。一方、$S$ は $N$ 個の標本の経験特性関数の距離に $N$ を掛けた値なので、標本 1 個が受ける勾配は $N$ によらない。$S$ の標本は 1 フレームに $B\,(512 + 2048)$ 個で、$B$ = 1 なら 2560 個、$B$ = 32 なら 81920 個になる。同じ $\lambda$ でも、トークン 1 個から見た SIGReg の重みは、$B$ = 32 のほうが約 32 倍大きい。P のコストも $N$ に比例するので、$N/512$ は $B$ = 1 で 5、$B$ = 32 で 160 になる。C のコスト（約 542）は $N$ によらない。両者を揃える割り算は入れない（[memory](../../memory/feedback_simple_fundamental.md)）。そのかわり、両方の $B$ を同じ $\lambda$ の格子で回し、結果ではこの違いを明記する
- **$B$ = 1 は、見る動画が少ない**。ストリームは、学ぶ 9 本を名前の順に繋いだループの上を進む。ストリーム $i$ の出発点は、ループの $\lfloor iL/n \rfloor$ のフレームである（`StackedTourFrames`）。$B$ = 1 のストリームは先頭の Amsterdam から出発し、1800 秒の run で $1800 \times 30 \times 3$ = 162000 フレーム（動画で 5400 秒）進む。Amsterdam は約 4913 秒なので、見るのは Amsterdam の全体と、Bangkok の最初の約 490 秒だけになる。学ぶ 9 本は合わせて約 13.3 時間ある。$B$ = 32 のストリームは約 1500 秒おきに出発するので、9 本すべてを通る。見る積みの数は、$B$ = 1 で 54000、$B$ = 32 では 32 倍になる。$B$ = 1 と $B$ = 32 の差には、SIGReg の標本数だけでなく、データの多様さと量の差も入る。これはシングルストリームの定義そのものなので、コードは変えない。posthoc のデコーダと動力学、`fit_` の補完の参照（`_mean`・`_pos`）は、どちらの $B$ でも 9 本すべてから取る
- **held-out の `loss` と `sigreg` は、学習の目的と同じ標本の値ではない**。held-out の損失は、$B$ によらず 32 積みずつ、バッファなしで測る（$n$ = 16384 トークン、`PACKED_BATCH`）。研究の目的の held-out の `pred` は、積みの数によらない。表に `loss` と `sigreg` を並べるときは、この点を注に書く
- $\lambda$ の値と判定の基準は、回す前に下の「ストリームごとのバッファ」の「回す前に決めたこと」に書き、コミットしてから投げた

### 回す前に決めたこと

**run**: `learner=bp`、`+experiment=m17/tok_n16`（$d$ = 16、1800 秒、300 秒ごとの checkpoint、warmup 300 秒）、seed 100・101。$B$ = 32（既定の `data.streams`）と $B$ = 1（`data.streams=1`）に、それぞれ 3 つの $\lambda$ で、計 12 本（batch `m17-buf-v1`）。posthoc は `decode.ckpts=all`（`m17-buf-post-v1`）。

**$\lambda$ の格子**: 上の「$\lambda$ の格子の導出」と同じ導出を、ストリームごとのバッファに広げた。1 ストリームの標本は $G$ = 512 + 2048 = 2560 個、全体は $N = BG$（$B$ = 32 で $N/512$ = 160、$B$ = 1 で 5）。ストリームどうしは独立なので、健全な解 H と積みの中の崩壊 C の値は 1 ストリームの構造だけで決まり、$B$ にほとんどよらない。

- バッファの行は、いまの積みとほぼ同じ内容を持つ（学習前のトークンで、ラグ 1〜8 フレームの積みの和の相関は、積みの中の相関とほぼ同じ）。そのため H の傾き $k_C = dS_H/d\rho|_0$ は 1225 になり、前の設定（実質 $G \approx 512$）の 246.5 の約 5 倍になった
- C の値は約 2100〜2350（閉じた形 2130 / 2114、実測 2347 / 2140）、I は 1.05〜1.07
- C と I だけと比べた窓は、$B$ = 32 で $[4.49, 7.73] \times 10^{-4}$（$\rho$ = 0.104）、$B$ = 1 で $[4.67, 8.02] \times 10^{-4}$（$\rho$ = 0.0315）。窓の端は $\rho$ にほとんどよらない（lo ≈ $1/S_C$、hi ≈ $1/k_C$）
- 格子は両端とその幾何平均: $B$ = 32 で $\{4.5, 5.9, 7.7\} \times 10^{-4}$、$B$ = 1 で $\{4.7, 6.1, 8.0\} \times 10^{-4}$。前の格子（$1.7$〜$3.8 \times 10^{-3}$）の約 1/4

**P と比べると、どちらの $B$ でも窓は空になる**（ガウスのモデル）。

- P の値は、$g(p)$ を iid の $N(0, I)$ にすると $S_P$ = 197.6（$B$ = 32）・6.5（$B$ = 1）、512 点の置き方を最適化すると 14.1・0.79
- H が P と I の両方に勝つには $(S_H(\rho) - S_0)/\rho < S_P - S_0$ が要る。左辺は $k_C \approx 1225$ 以上で、右辺は 196.5（$B$ = 32）・5.5（$B$ = 1）。どちらも満たさない。$B$ = 1 では $S_P < S_H$ なので、どの $\lambda$ でも P が勝つ
- 位置の成分を単位分散だけ持つときの限界コストは $k_P = f'(0)(N/512 - 1)$（$f'(0)$ = 0.482）で、$B$ = 32 で 76.7、$B$ = 1 で 1.9。内容の成分の $k_C$ = 1225 よりずっと小さい
- したがって、格子の上のモデルの最適は完全な P である。格子は C と I の窓から決めた

**比べ方**:

- 主な指標は、held-out（Zurich の val）の `comp_<kind>_pos`（kind は short・long・future）。隠したトークンの分散のうち、位置ごとの平均で説明できない割合（$1 - R^2$）で、P では 0 に近づく。あわせて `comp_<kind>` と `comp_<kind>_pos` の大小を見る（`comp` < `comp_pos` なら、予測器は位置より多くを文脈から得ている）
- 補助は posthoc の `z_spread`。P に固有ではない（上の節の「posthoc」の読み）
- 研究の目的の held-out の `pred` は、すべての表に載せる。P でも H でも小さくなるので、P を見分けるのには使わない
- 2 つの seed の平均で比べ、両方の値を書く。大小は、2 つの seed の 4 通りの組がすべて同じ向きのときだけ「差がある」とする

**$S_P \propto N$ という説明を支持する・棄却する結果**:

- $B$ = 1 と $B$ = 32 を、格子の同じ位置（lo・mid・hi）、同じ時刻（600 秒と 1800 秒）で比べる。$B$ = 1 の `comp_<kind>_pos` が $B$ = 32 より小さい（P により近い）なら支持。$B$ = 1 のほうが大きいか同じなら棄却
- 前の 6 本（全体で 8192 行のバッファ、$N/512$ = 48）と、新しい $B$ = 32（$N/512$ = 160）を 600 秒で比べる。同じ $\lambda$ の run は無い（格子が約 4 倍違う）。$S_P \propto N$ だけを見れば、同じ $\lambda$ なら $B$ = 32 の P へのずれは前より弱いはずである。しかし格子の $\lambda$ が下がったので、位置の成分のコスト $\lambda k_P$ は前の $\lambda$ = 0.0017・0.0026・0.0038 で 0.039・0.059・0.086、新しい $B$ = 32 で 0.035・0.045・0.059 となり、同じ程度になる。モデルは同じ程度のずれを予測する。$d$ = 16 の前の 3 本と比べるが、これは補助の比較で、判定には使わない。前の run はバッファの齢も違う（1 本あたり 256 行・毎フレーム 2 個で、平均 128 フレーム）
- ストリームの数は、データの量と多様さも変える（上の「次」）。$B$ = 1 と $B$ = 32 の差を、標本数 $N$ の差だけに帰すことはできない

**モデル（ガウス）の予測**:

1. どちらの $B$ でも、`comp_<kind>_pos` は warmup の後に下がり、`comp_<kind>` は `comp_<kind>_pos` に近づく
2. $B$ = 1 は $B$ = 32 より速く、深く P へ向かう（上の支持の条件と同じ）
3. 積みの中の崩壊 C は起きない（held-out の `sigreg` は C の値（約 540）より十分小さく、`tok_within` は学習前より大きいまま）
4. `recon_blur` と `restore_*_mask` は、P へ向かうほど悪くなる

**モデルを棄却する結果**: $B$ = 1 のどれか 1 本で、1800 秒の `comp_short_pos`・`comp_long_pos` が 600 秒の値より小さくならず、しかも `comp_<kind>` < `comp_<kind>_pos` が保たれる（文脈を使う解が残る）。$B$ = 32 だけがこの形を保ち、$B$ = 1 が P へ向かうなら、$N$ への依存は支持され、窓が空というモデルの予測は棄却される。

どの結果でも、目的の式には何も足さない（[memory](../../memory/feedback_simple_fundamental.md)）。較正のスクリプトは `exp/video/diag/lam_calib.py` の `per-stream`（`python -m exp.video.diag.lam_calib per-stream 16 32 768 512`・`per-stream 16 1 3072 2560`）と `exp/video/diag/lam_window.py` の `buffer`（当時は NAS の `tmp` の `lam_calib2.py`・`lam_window.py` を、snapshot `81c2953`、mujou `7a8b72e`、std-00・std-02 の 4090 で回した。seed はモデル 100、方向 5、挿入 7、$\rho$ の方向 3、P の iid の $g$ 12、I 13、最適な置き方 11）。測った値は `exp/video/results/m17-calib/lam_calib2_b32.json`・`lam_calib2_b1.json` にあり、`python -m exp.video.diag.lam_window buffer exp/video/results/m17-calib/lam_calib2_b32.json exp/video/results/m17-calib/lam_calib2_b1.json` で上の値が出る（2026-11-13 にリポジトリに移した。出力は移す前と同じ）。

### 結果（2026-11-13）

#### 結論

- **どちらの $B$ でも、トークンは位置だけの解 P にほぼ着いた**。1800 秒の held-out（Zurich の val）で、隠したトークンの分散のうち位置ごとの平均で説明できない割合 `comp_short_pos` は、$B$ = 32 で $3.7$〜$4.5 \times 10^{-5}$、$B$ = 1 で 0.0018〜0.0019（学習前は 0.92）。どの $\lambda$ でも、2 つの seed の両方で同じだった。研究の目的の held-out の `pred` は、$B$ = 32 で $1.7$〜$2.1 \times 10^{-4}$、$B$ = 1 で 0.0019〜0.0021（学習前 0.82）
- **学んだ予測器は、位置ごとの平均より良くない**。1800 秒で、$B$ = 32 の `comp_short` は `comp_short_pos` の 4.7〜5.0 倍（seed の平均どうしの比）、$B$ = 1 では 1.1〜1.2 倍だった。300 秒ごとの checkpoint で seed の平均を見ると、文脈から位置より多くを得ている印（`comp` < `comp_pos`）が出たのは、$B$ = 32 では $\lambda$ = 0.00077 の 300 秒だけ（0.013 と 0.040。60 秒ごとの評価では 120〜300 秒、両方の seed）、$B$ = 1 では 300・600 秒の 6 つのうち 5 つ（例: $\lambda$ = 0.00047 の 600 秒で 0.0052 と 0.0066）。$B$ = 1 は 600 秒の後も、60 秒ごとの評価で 1 つの seed だけ `comp` < `comp_pos` になる時刻がある（`d27e47c7-s101` の 660・720・960・1080・1140・1260・1620 秒、`60f17821-s101` の 720・960・1080・1140・1260・1620 秒、`d27e47c7-s100` の 720・960・1080 秒、`1e404c20-s100` の 960 秒。差は 0〜13%）。$B$ = 1 の予測器は、位置ごとの平均の前後を行き来している
- **回す前に置いた基準では「$S_P \propto N$ という説明」は棄却になった**（基準: $B$ = 1 のほうが P に近ければ支持）。P により近いのは $B$ = 32 だった。600 秒でも 1800 秒でも、格子の 3 つの位置のすべてで、seed の 4 通りの組のすべてで、$B$ = 32 の `comp_short_pos` は $B$ = 1 より小さい。差は seed の平均どうしで 600 秒に 21〜33 倍、1800 秒に 40〜51 倍、seed の組ごとでは 17〜41 倍と 28〜87 倍だった。ただし、棄却されたのは「$N$ が大きいほど P の罰が大きいので、有限の時間で P へのずれが小さい」というつなぎである。$S_P$ が $N$ に比例すること自体はシミュレーションの事実で、学ぶ側の $S$（$B$ = 32 で約 16、$B$ = 1 で 3〜4）とも矛盾しない。また、静的なガウスのモデルの最適は、どちらの $B$ でも完全な P である（「回す前に決めたこと」）。どちらの $B$ が有限の時間で P に近いかは、モデルから導いていない。「$B$ = 1 のほうが速く深く P へ向かう」は、静的な結果から動きを推した一歩で、導出ではない。この棄却は、その一歩を退けたものとして読む。$B$ はデータの量と多様さ、勾配の雑音と重みも変えるので、この差を $N$ だけに帰すこともできない（下の「言えないこと」）
- **ガウスのモデルは、回す前に置いた棄却の条件には触れなかった。しかし $N$ への依存についての予測は、2 つとも外れた**。棄却の条件（$B$ = 1 のどれかで、1800 秒の `comp_*_pos` が 600 秒より小さくならず、`comp` < `comp_pos` が保たれる）は、どの run でも起きなかった。「格子のどの $\lambda$ でも P が勝つ」とも合う。ただし、この予測はほかの説明でも同じになるので、モデルを区別しない。一方、$N$ への依存から出した 2 つの予測は外れた。予測 2（$B$ = 1 のほうが速く深く P へ）と、補助の比較（新しい $B$ = 32 は前の 8192 行の run と同じ程度に P へずれる）である。補助の比較では、新しい $B$ = 32 のほうが、格子の同じ位置で約 10・60・170 倍 P に近かった（600 秒の `comp_short_pos`、$d$ = 16。$\lambda$ が約 4 倍違うので判定には使わない）。学ぶ側の $S$（バッファ込み、最後の 60 秒）は、$B$ = 32 で 16.2〜16.9 になった。較正で 512 点の置き方を最適化した P の 14.1 に近い。iid の $g$ の P（197.6）、H（135.7）、C（約 2100）よりずっと小さいが、独立なトークンの解 I（1.06）の約 15 倍ある。$B$ = 1 は 2.8〜4.3 で、iid の $g$ の 6.5 と最適な置き方の 0.79 の間にあり、I の 3〜4 倍
- **積みの中の崩壊 C は起きなかった**。held-out の `sigreg` は 1800 秒で $B$ = 32 が 3.2〜3.4、$B$ = 1 が 16〜26 で、C の値（約 540）よりずっと小さい。`tok_within` は 0.95〜0.99（学習前 0.41）
- **既存の 6 本の P の確認（決定 1）**: 600 秒で P にほぼ着いていたのは $d$=16・$\lambda$ = 0.0017 の 1 本だけで、`comp_short_pos` が 0.0020、`comp_short` が 0.0027 だった。$B$ = 1 の 1800 秒（0.0018〜0.0019）と同じ程度なので、同じ言葉で「ほぼ着いた」と呼ぶ。上の節の「P に着いた run はない」は `z_spread` だけから書いたもので、この 1 本については正しくなかった。ほかの 5 本は `comp_short` < `comp_short_pos` で、予測器は位置より多くを文脈から得ていた（`comp_short_pos` 0.013〜0.14）。300 秒では 6 本とも `comp_short_pos` 0.23〜0.36、`comp_short` 0.036〜0.060 だった。600 秒までは P へ向かう途中で、$\lambda$ が大きいほど遠い。新しい $B$ = 32 は、600 秒で 3 本とも `comp_short_pos` 2.0〜3.2 × 10⁻⁴ で、前のどの run より P に近い。$\lambda$ が約 4 倍違うので、同じ $\lambda$ での比較にはならない
- **再構成**: どの run も、学習前の ViT と PCA に届かない。1800 秒の `recon_blur`（val）は、$B$ = 32 で 0.257〜0.266、$B$ = 1 で 0.244〜0.251（学習前の ViT 0.151、PCA 0.068）。隠さないトークンをトークンのデコーダで描き戻した上限 `restore_target_short_mask` は、$B$ = 32 で 0.90〜1.01（平均の画像とほぼ同じ）、$B$ = 1 で 0.54〜0.58、学習前の ViT で 0.20。予測器を通した `restore_short_mask` は、どちらの $B$ も 0.92〜1.01 で、上限との差は $B$ = 32 で 0〜0.08、$B$ = 1 で約 0.4 ある

#### 言えないこと

- $B$ = 1 が $B$ = 32 より P から遠い理由は、この run からは分からない。$B$ を変えると、次のものが一緒に変わる。標本数 $N$ の効果と切り分けていない
  - データの量と多様さ。$B$ = 1 が見る積みは $B$ = 32 の 1/32 で、動画は Amsterdam の全体と Bangkok の先頭だけ
  - 1 フレームの予測の項の勾配の重み（上の「次」）。同じ $\lambda$ なら、トークン 1 個から見た SIGReg の重みは $B$ = 32 のほうが約 32 倍大きい。これは $B$ = 32 を P から遠ざける向きに働くはずで、結果とは逆向きである
  - 勾配の雑音。$B$ = 1 は 1 step に 1 本のストリームの損失を使い、$S$ も 2560 個の標本から見積もる。$B$ = 32 は 32 本の平均をとる。step の数（54000）が同じでも、雑音だけで $B$ = 1 が引き込み先に寄りにくい可能性がある
  - `pred` の大きさ。$B$ = 1 の `pred` は $B$ = 32 の約 10 倍ある
- **seed はデータを変えない**。ストリームの出発点は決定的で（`exp/video/data/frames.py` の `StackedTourFrames`、`arange(n) * L // n`）、$B$ = 1 の 2 つの seed は同じフレーム列を見る。seed で変わるのは初期値とマスクなどだけである。$B$ = 1 の `pred` と `comp_*_pos` の 900 秒の山は、どの $\lambda$ でも両方の seed にあったので、データから来ている見込みが大きい（確かめていない）。「seed の 4 通りの組のすべて」という基準は、$B$ = 1 のデータのばらつきを含まない
- 「P に着いた」は、位置ごとの平均で説明できない分散の割合（`comp_*_pos`）が小さいという意味である。残った小さな違いには、デコーダが画像の一部を読める情報が残っている（`recon_blur` 0.24〜0.27）
- seed は 2 つで、1800 秒より先は見ていない
- $\lambda$ の窓、$S_P$ の値、最適な置き方の 14.1・0.79 を出した較正とシミュレーションのスクリプトと、表と図を作ったスクリプトは、この節を書いた時点では NAS の `tmp` かセッションの作業場所にしかなかった。2026-11-13 に `exp/video/diag/` に移し、テストを付けた（下の「再現の情報」）。CPU のもの（窓・シミュレーション・表・図）は、移す前と同じ出力になることを確かめた。GPU の較正（`lam_calib.py`）は、移した後に回し直していない
- どの結果でも、目的の式には何も足していない（[memory](../../memory/feedback_simple_fundamental.md)）

## データポイントの SIGReg に向けた測定（2026-11-13）

ユーザーの決定（2026-11-13、1 回目）: トークンの SIGReg は棄却し、SIGReg をデータポイントごとの 1 標本に戻す。データポイントは 1 つの積みで、その表現は $T$ 個のトークン × $d$ 次元を平らにした列（$D = Td$）である。SIGReg の標本が LeJEPA の前提する i.i.d. に近くなるように、過去のデータポイントを長期のバッファに、相関が消える間隔で貯める。これでもうまくいかなければ、SIGReg の代わりに I-JEPA の EMA のターゲットを使う。

ユーザーの決定（2026-11-13、2 回目）: 1 回目の測定（画素の相関）で、1 本のストリームから i.i.d. に近い標本を集めるのは難しいと分かった。そこで表現の空間でも相関を一度測り、そのあと I-JEPA の EMA のターゲットモデルに移る。EMA 以外で崩壊を防ぐ方法（1 本の、時間に相関のあるストリームで成り立つ、SIGReg のような方法）は今後の課題とする。

この節は 2 回目の測定の結果である。1 回目の点検で見つかった誤りを直して画素の相関を測り直し、同じ量を表現でも測った。学習は回していない。

### 結論

- **判定の基準は導出から決めた**。$N$ 個の標本の 2 つずつの相関の平均が $\bar r$ なら、SIGReg の偏りは $f'(0)(N-1)\bar r$（$f'(0) = \sqrt{2\pi}/3^{3/2}$ = 0.482）になる（下の「定義」）。$\bar r \le 1/(N-1)$ なら偏りは $f'(0)$ 以下で、有効な標本の大きさ $N/(1+(N-1)\bar r)$ は $N/2$ 以上になる。$N$ = 32・256・1024 について、相関 $\rho(\Delta)$ が $1/(N-1)$（0.032・0.0039・0.00098）以下になる最小のラグを求めた
- **画素では、$N$ = 32 の基準に届くのが 27.3 分、$N$ = 256・1024 は測った最大の 54.6 分でも届かない**。学習の集合の平均で中心化した $\rho$ は、0.1 秒で 0.887、1.6 秒で 0.524、51 秒で 0.134、13.7 分で 0.058、27.3 分で 0.023、54.6 分で 0.015 ± 0.021 だった。27.3 分の値も 95% の上限（0.023 + 2.31 × 0.016）では基準を超える
- **表現は、画素より速く相関が消えることはなかった**
  - 学習前の ViT（`m17/tok_n16`、$d$ = 16）の平らにしたトークン（$D$ = 8192）は、短いラグで画素より少し低い（1.6 秒で 0.449）。長いラグでは画素と同じ（13.7 分で 0.049、54.6 分で 0.018）。$N$ = 32 の基準に届くのは画素と同じ 27.3 分
  - pool した $z$ は画素よりずっと遅い。学習前（$D$ = 16）、試しの run の 300 秒と 1800 秒（`m17-pilot-v1`、$z$ に SIGReg、$D$ = 256）で、51 秒の $\rho$ は 0.47・0.47・0.31、13.7 分で 0.27・0.27・0.21、54.6 分で 0.14・0.07・0.06 だった。どれも 54.6 分のうちに $N$ = 32 の基準に届かない。動画ごとの平均が 2 次のモーメントに占める割合は 19〜21%（画素は 4.6%）で、同じ動画の $z$ は、どれだけ離れてもこの分だけ相関が残る
  - SIGReg で学んだ $z$ は、300 秒から 1800 秒の学習で少し下がるだけだった（6.4 秒で 0.73 → 0.58）
  - 参考: 位置だけの解に近いトークンの run（`m17-buf-v1`、$B$ = 32、$\lambda$ = 4.5 × 10⁻⁴、1800 秒）のトークンは、20 秒で $N$ = 32 の基準に届く。ただしこれは、位置の成分を学習の集合の平均で引いた残り（1 成分あたりの広がり 10⁻⁴ の桁）の相関で、内容の表現の相関ではない。同じ run の $z$（$D$ = 16）は画素と同じ 27.3 分だった

### 定義

- **なぜ相関か**: SIGReg（`exp.lib.sigreg`）は、$N$ 個の標本を単位ベクトルに射影し、Epps-Pulley の統計量で $N(0, 1)$ と比べる。中心化も尺度の正規化もしない。射影が $N(0, 1)$ で、どの 2 つも相関 $r$ を持つとき、$N E|\hat\varphi(t) - e^{-t^2/2}|^2 = (1 - e^{-t^2}) + (N-1)(e^{-t^2(1-r)} - e^{-t^2})$ なので
  $$E\,S = S_0 + f'(0)(N-1)\,r + O(r^2),\quad S_0 = \sqrt{2\pi} - \sqrt{2\pi/3} = 1.06,\quad f'(0) = \int t^2 e^{-3t^2/2}\,dt = \sqrt{2\pi}/3^{3/2} = 0.482$$
  方向 $a$ で平均すると、射影 $a^\top y$ の相関は $\operatorname{tr} C_\Delta / \operatorname{tr} C_0$ になる（$C$ は SIGReg が向かう中心 0 のまわりの 2 次のモーメント）。これが下の $\rho$ で、中心は学習の集合の平均である
- **基準**: $\rho(\Delta) \le 1/(N-1)$ になる最小のラグ $\Delta_N$。表の括弧の中は、95% の上限 $\rho + t_8 \hat\sigma$ が $1/(N-1)$ 以下になる最小のラグ。有効な標本の大きさは $N/(1+(N-1)\rho)$（$1+(N-1)\rho \le 0$ なら書かない）。$\Delta$ おきに並べたバッファの対は $\Delta, 2\Delta, \dots$ 離れるので、$\rho$ が減るなら $\bar r \le \rho(\Delta)$ で、この値は下限である
- **格子と中心**: 学習の 9 本（Zurich を除く）の各動画で、フレーム $t = 0, 3, 6, \dots$（0.1 秒おき）だけを使う。フレームは 128 × 128 × 3 を $[0, 1]$ で平らにしたもの。$m_a$ は動画 $a$ の格子のフレームの平均、$m = \sum_a J_a m_a / \sum_a J_a$（$J_a$ は格子の数）、$d_a = m_a - m$、$y = x - m$（`g`）、$u = x - m_a$（`w`）
- **データポイント**: 画素では、格子で続いた 16 枚の積み $Y_j = (y_{j-15}, \dots, y_j)$。表現では、その積みの符号 1 つ
- **正規化した自己共分散**: ラグ $k$（格子の数）で、$Y_j$ と $Y_{j+k}$ の両方が動画の中にある $j$ について
  $$\rho_a(k) = \frac{\sum_j \langle Y_j, Y_{j+k} \rangle}{\sqrt{\sum_j \lVert Y_j \rVert^2 \sum_j \lVert Y_{j+k} \rVert^2}}$$
  9 本をまとめた $\rho$ は、9 本の和で同じ比をとったもの
- **誤差**: 動画を 1 本ずつ抜いた $\rho_{-a}$ の jackknife、$\hat\sigma^2 = \frac{A-1}{A}\sum_a (\rho_{-a} - \bar\rho_-)^2$（$A$ = 9、中心 $m$ は固定）。± は $\hat\sigma$
- **別々の動画の基準**: 動画 $a$ と $b$ の積みのすべての対の $\langle Y, Y' \rangle$ の平均は $16 \langle d_a, d_b \rangle$（端の 15 個を除く）。9 本をまとめた基準は、$a \ne b$ の対で重みをつけて平均し、全体の 2 乗の平均で割ったもの。誤差は同じ jackknife。表現では符号 1 つが点なので、16 倍しない
- **動画の平均の割合**: $\lVert d_a \rVert^2$（積みでは 16 倍）を、その動画のデータポイントの 2 乗の平均で割ったもの。動画の中のどのラグでも、この分の相関は消えない
- **表現**: 学習の 9 本のすべての積み（約 48 万個）を、各モデルで符号にした。`tokens` は target view のトークンを平らにした列、`z` はその平均（`VisionModules.z_of`）。モデルは次のとおり
  - `tok_init`: `m17/tok_n16`（$d$ = 16）の学習前の ViT（`m17-buf-v1` の `fb043497-s100` の設定、seed 100 の初期値）
  - `pilot_300`・`pilot_1800`: `m17-pilot-v1` の `m17-wt_n16-e662e48b-s100`（$z$ に SIGReg、$D$ = 256）の 300 秒と 1800 秒の checkpoint
  - `buf32_1800`: `m17-buf-v1` の `m17-tok_n16-fb043497-s100`（$B$ = 32、$\lambda$ = 4.5 × 10⁻⁴）の 1800 秒の checkpoint。位置だけの解に近い run なので参考
- **古さ**: 学習の 9 本から取った 2048 個の積み（`encoder_eval.stream_windows`）を、各 checkpoint で表現 $f_t(x)$ にする。間隔 $\Delta$ の 2 つの checkpoint について
  $$\mathrm{drift} = \frac{E_i \lVert f_t(x_i) - f_{t+\Delta}(x_i) \rVert^2}{E_{i \ne j} \lVert f_{t+\Delta}(x_i) - f_{t+\Delta}(x_j) \rVert^2}$$
  1 なら、貯めた表現と今の表現の距離が、別々の積みどうしの距離に等しい。change と apart は、分子と分母を 1 成分あたりにした値

### 読みと限界

- **pool した $z$ は画素より遅く相関が消える**。$z$ は 512 個のトークンの平均なので、場面の大まかな色と明るさが主に残り、それが分の単位で続くとみている（確かめていない）。動画ごとの平均の割合が 19〜21% と画素の 4 倍あるのも、これと合う
- **$\rho$ はトレースの比である**。等方でない表現では、方向ごとの射影の相関は方向でちがい、$\rho$ はその平均にあたる。SIGReg が効いて表現が等方に近づくと、方向ごとの相関は $\rho$ に近づく
- **誤差は 9 本の動画のばらつきで決まる**。$z$ の曲線は動画ごとの差が大きく、10 秒より長いラグで ± が 0.03〜0.1 ある。それでも、どの $z$ も 54.6 分までに $N$ = 32 の基準（0.032）の 95% の上限に届かない
- **最大のラグは 54.6 分**（最も短い動画）。それより長い間隔は 9 本すべてでは測れない。画素の $\rho$ は 27.3 分から 54.6 分の間でも 0.023 → 0.015 としか下がらない
- **試しの run の SIGReg は、データポイントの SIGReg ではない**（$B$ = 32 の今の $z$ と過去の $z$ のバッファ）。データポイントの SIGReg で学んだ表現の相関は測っていない
