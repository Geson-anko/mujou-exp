# 計算時間（M5、2026-10-30）

[README](../README.md) の結果の 1 節。ファイル名とパスは当時のもの。

合成動画（32×32、$D=64$、$d_s=256$）を `mujou.testing.run` で回したときの値。CPU 1 スレッドで、評価は含まない。

| optimizer                                 | 30 秒分のストリーム | 30 分分の見込み |
| ----------------------------------------- | ------------------- | --------------- |
| SGD                                       | 32 秒（実時間の 1.07 倍） | 約 32 分   |
| 白色化（$L, R$ とも、`refresh=1` 秒）     | 84 秒（2.8 倍）     | 約 84 分        |
| 白色化（$L, R$ とも、`refresh=5` 秒）     | 53 秒（1.77 倍）    | 約 53 分        |

- 評価 1 回（クリップ 32 本 × 128 フレーム）は約 1 秒。60 秒ごとなら 30 分で 30 秒
- SIGReg の `g_in` は、同じフレームで $z_k$ が変わらない間は前の値を送り直す（結果はビット単位で同じ）。これで SGD の時間が 3.4 倍から 1.07 倍に下がった
- 白色化の重さは主に `Z` の `Linear(2048, 64)` の $R$（2048×2048）の固有値分解。段 2 では `refresh` を 5 秒にするか、$R$ を外した版から回す（M8 で決める）

**GPU（`Config.device = "cuda"`、2026-10-31）**: 大きなモデル（段 3）のために、すべてのノードと評価を CUDA で計算できるようにした。段 2 の大きさでは CPU より速くないので、段 2 は CPU で回す

| optimizer（$\kappa=0.8$、学習率 0.1） | CUDA（RTX 4090） | CPU |
| -------------------------------------- | ---------------- | --- |
| SGD                                    | 159 秒（5.3 倍） | 120 秒（4.0 倍） |
| 白色化（$L, R$ とも、`refresh=5` 秒）  | 167 秒（5.6 倍） | 201 秒（6.7 倍） |

- 30 秒分のストリーム。どちらも段 2 の 16 本が CPU を埋めている間に測ったので、上の表（空いた CPU で 1.07 倍）より遅い
- バッチ 1、32×32 では、2 ms ごとの小さなカーネルの起動とノードごとの同期が支配的で、GPU は速くならない。固有値分解の重い白色化だけは GPU が速い
- CPU と CUDA は、TF32 を切れば最初の 10 フレームの予測誤差が丸めの範囲で一致する（`test_cuda_streams_as_the_cpu_does`）。SIGReg の方向は、CPU と CUDA で乱数の列が違うので別になる。平衡点で `lam` が BP の credit に一致することも CUDA で確かめた
