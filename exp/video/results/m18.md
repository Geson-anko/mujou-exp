# Walking Tours の単一ストリームから VAE を学ぶ（M18、2026-11-15〜）

[README](../README.md) の結果の 1 節。MILESTONES.md の M18。計画は [plans/m18-vae-stream.md](../plans/m18-vae-stream.md) にある。段 1 は決定的な自己符号化器（$\tfrac12\lVert y - g(f(x))\rVert^2$、$y = x/256$）で、エンコーダは M17 の t128 の ViT、デコーダはそれを裏返した 2 ブロックの ViT である。どちらもシステムの中で BP で学ぶ（`program=ae`、`exp/video/vae/`）。

## 段 0 の測定（2026-11-15）

段 1 の物差しと、学習の設定を導くための値を、run の前に閉じた形で測った。スクリプトは `exp/video/diag/m18_stage0.py`（テストは `tests/video/diag/test_m18_stage0.py`）である。乱数を使うのは power iteration の始めの向き（seed 0）と、過学習の確かめの 256 個の積みの抽出（run の seed 100 + 6）だけである。

### 学ぶ積みの平均と分散

学ぶ 9 本の積みは M17 の PCA と同じ 2048 窓 × 9 個で、$n$ = 18432 個ある（窓が動画をまたいで落ちたものは無い）。1 つの積みは $P$ = 16 × 3 × 128 × 128 = 786432 個の値である。

| 量 | 値 |
| -- | -- |
| 平均の画素（$y = x/256$） | 0.457（R 0.465、G 0.459、B 0.446） |
| $\sigma_0^2$（値ごとの分散の平均） | 0.07431（$\sigma_0$ = 0.273） |
| 共分散の固有値の和 / $P$ | 0.07431（$\sigma_0^2$ と 13 桁で一致。測り方の確かめ） |

平均の積み（`m18-stage0/pca.png`、左が 1 枚目、右が 16 枚目）は、上が明るい灰色の一様に近い画像で、2 枚に違いは見えない。

### 積みの PCA

共分散の固有値は $n \times n$ の Gram 行列を float64 でブロックに分けて計算した。上位 1024 個の主成分の基底 $U$ の直交性のずれは最大 2.4 × 10⁻¹³ だった。

| 量 | 値 |
| -- | -- |
| 0 でない固有値の数 | 18431（$n - 1$） |
| 最大の固有値 $\lambda_1$ | 11257（$\sigma_0^2$ の 1.5 × 10⁵ 倍） |
| 1024 番目の固有値 $\lambda_{1024}$ | 3.66（$\sigma_0^2$ の 49 倍） |
| $\sigma_0^2$ を超える固有値の数 | 15420 |
| 上位 1024 個が占める分散の割合 | 0.847 |

$\lambda_{1024}$ は $\sigma_0^2$ の 49 倍なので、段 2 の pPCA-1024 は時刻 0 の $\sigma_0^2$ のもとで 1024 次元のすべてを使う（計画の「事後分布の崩壊（最適点）」）。ただし $\sigma_0^2$ は $P$ 方向の平均で、標本の共分散の 0 でない固有値は $n - 1$ 個しかない。そのため 15420 という数は$P$ に比べて標本が少ないことにも依る。

### PCA-1024 の `stack_mse`（段 1 の物差し）

`stack_mse` は $\sum\lVert y - \hat y\rVert^2 / \sum\lVert y - m\rVert^2$ で、$m$ は上の平均の積み、$\hat y = m + UU^\top(y - m)$ である。held-out は M17 の評価と同じ窓の最初の積み（各 256 個）、過学習の確かめは `PooledStackedTourFrames` の 256 個（seed 106）である。

| 積み | PCA-1024 の `stack_mse` | 平均の積みの誤差 / $P$ |
| -- | -- | -- |
| val（Zurich） | **0.177** | 0.0696 |
| test（Zurich） | 0.206 | 0.0671 |
| 過学習の確かめの 256 個（学ぶ 9 本） | **0.196** | 0.0762 |

段 1 の R は val の `stack_mse` < 0.177、過学習の確かめの条件は `pool_stack_mse` < 0.196 になる。256 個そのものに当てはめた PCA の最適値は 0 である（256 個は平均を除くと rank 255 以下で、1024 次元で表しきれる）。

最後のフレームだけの PCA-1024 の val の `recon_lin` は 0.087 だった（results/m17.md）。積みの PCA は同じ 1024 次元を 16 枚に使うので、誤差の割合は約 2 倍になる。

### 学習前の損失の Hessian と SGD の学習率

学習前の自己符号化器（seed 100、パラメータ 1105 万）の損失の Hessian に、power iteration（Hessian とベクトルの積は二重の逆伝播）を当てた。積みは学ぶ 9 本の 2048 窓（段 0 の平均の積みと PCA と同じ窓）の最初の積みで、ループに等間隔に並ぶ。スペクトル半径 $\rho$ は単位ベクトル $v$ の $\lVert Hv \rVert$ で見積もった。止める条件は、変化の比から見積もった残りの誤差が $\rho$ の 10⁻⁴ を下回ることである（計画の「SGD の学習率」）。

| 量 | 値 |
| -- | -- |
| 積みの数 | 2048（止まるまでの反復は平均 21 回） |
| 止める条件に届かなかった積み | 5 個（200 回で打ち切り。$\rho$ の見積もりは 5.4 × 10⁵〜1.02 × 10⁶） |
| 絶対値の最大の固有値が負の積み | 668 個（33%） |
| $\rho$ の中央値 | 1.08 × 10⁶ |
| $\rho$ の 90% 点 | 2.02 × 10⁶ |
| $\rho$ の 99% 点 | 3.93 × 10⁶ |
| $\rho$ の 99.9% 点 | 4.69 × 10⁶ |
| $\rho$ の最大 $\rho_{\max}$ | **4.79 × 10⁶**（積み 1603、固有値は負） |
| 最大の固有値が正の積みの中での $\rho$ の最大 | 3.35 × 10⁶ |
| $B$ = 32 の 32 本の流れの最初の積みの平均の損失の $\rho$ | 8.59 × 10⁵（32 個の $\rho$ の平均は 1.16 × 10⁶） |

止める条件に届かなかった 5 個の見積もりは $\rho$ の下界で、$\rho_{\max}$ の 0.21 倍以下である。どれかの真の $\rho$ が $\rho_{\max}$ を超えるなら、その方向の重みは $H^2$ の反復ごとに $(\rho_{\max}/1.02\times10^6)^2 \approx 22$ 倍以上の速さでほかに対して増える。そのため、200 回のあとも見積もりに現れないことはない。99.9% 点は最大の 0.98 倍で、上端は最大の近くで詰まっている。

$\rho$ の最大を $\lambda_{\max}$ の代わりに使う（計画のとおり）。$B$ = 32 の平均の $\rho$ が 32 個の $\rho$ の平均より小さいことは、三角不等式による導出と合う。$B$ = 32 でも同じ学習率で条件を満たす。

SGD の学習率（フレームあたり、`optim_vision.lr`、`scale=none`、preset `m18/ae_t128_sgd`）は次のとおりである。

$$
\mathrm{lr} = \frac{1}{1.02 \times 4.79\times10^6} = 2.05\times10^{-7}
$$

1.02 は一歩の elapsed のフレームに対する最大の比である（`tests/video/vae/test_bp.py`）。発散の境目（$2/\rho_{\max}$ を 1.02 で割った値）は 4.09 × 10⁻⁷ で、この lr はその半分にあたる。RMSProp と AdamW は $\eta$ = 2.9 × 10⁻⁵（`scale=fan_in`）で、$B$ に依らない（計画の「$B$ = 32」）。

**8 個の積みで測った最初の値**: 段 0 の最初の測定はループを 8 等分した位置の 8 個の積みだけで $\rho$ を測り、最大 1.386 × 10⁶ から `lr` = 7.08 × 10⁻⁷ を出していた。8 個からではどの積みでも条件を満たすとは言えないとレビューで指摘され、2048 個で測り直した。8 個は 2048 個の中に同じ積みとして含まれ、値も一致した（積み 0 は 1.38556 × 10⁶）。しかし 1.386 × 10⁶ は 2048 個の 71% 点にすぎない。29% の積みの $\rho$ がこれを超え、76 個（3.7%）はその 2 倍（古い `lr` での発散の境目）を超えた。最大の固有値が正の積みに限っても、4 個が境目を超えた。古い `lr` は採らない。

## 段 1：自己符号化器（回す前に決めたこと、2026-11-15）

計画の「段 1: 決定的な自己符号化器」を、段 0 の値で閉じた形にした。ここに書く値・基準・予測は、run を投げる前にこの節のコミットに入れる。結果はここで決めた基準だけで判定する。

### run

どれも `learner=bp`、seed 100、1800 秒（$F$ = 54000 フレーム）、300 秒ごとの checkpoint、val の `stack_mse` は 60 秒ごとである。warmup も weight decay も無く、学習率は一定とする。

| optimizer | preset と上書き | 学習率（フレームあたり） |
| -- | -- | -- |
| RMSProp | `+experiment=m18/ae_t128` | $\eta$ = 2.9 × 10⁻⁵、`scale=fan_in`、$\tau_v$ = 30 秒 |
| AdamW | `+experiment=m18/ae_t128 optim_vision.kind=adamw` | $\eta$ = 2.9 × 10⁻⁵、`scale=fan_in`、$\tau_m$ = 0.3 秒、$\tau_v$ = 30 秒、weight decay 0 |
| SGD | `+experiment=m18/ae_t128_sgd` | `lr` = 2.05 × 10⁻⁷、`scale=none`（段 0 の $1/(1.02\,\rho_{\max})$） |

それぞれの optimizer で、次の 4 本を回す（`data.tours.sampling` と `data.streams`）。

| 腕 | 上書き | posthoc |
| -- | -- | -- |
| ストリーム | `data.tours.sampling=stream data.streams=1` | あり |
| 並べ替え | `data.tours.sampling=shuffle data.streams=1` | あり |
| 過学習の確かめ | `data.tours.sampling=pool data.streams=1` | なし（`pool_stack_mse` で判定する） |
| ストリームの $B$ = 32 | `data.tours.sampling=stream data.streams=32` | あり |

合わせて、学習の run が 12 本（batch `m18-ae-v1`）、posthoc が 9 本（`m18-ae-post-v1`）、物差しが 1 本（`m18-ae-base-v1`、`+experiment=m18/ae_t128 task=baselines`）である。2 つの preset は optimizer だけが違い、エンコーダとデコーダの初期の重みは同じである（`tests/video/schema/test_presets.py`）。そのため、学習前のエンコーダの物差しは 1 本で 3 つの optimizer に共通する。posthoc の unit 0 も同じ物差しを測るので、`m18-ae-base-v1` と一致するかを確かめる。

並べ替えの対照は計画の未決の 6（ユーザーに説明している）の推奨の形で回す。役目は計画の問い 3 のとおり、原因を順序とそれ以外に分けることだけである。

所要時間は bench（4090）から見積もった。$B$ = 1 の学習は約 11 分、$B$ = 32 は約 32 分で、評価の時間は含まない。1 本の 4090 に 1 本ずつ載せる（M17 と同じ `--gpu-mem 20`）。そうすると、`stream.jsonl` の速さがほかの run の影響を受けない。

### 判定の基準（val、1800 秒）

基準はどれも 1800 秒の値で読む。値の無い基準は「不明」、発散した run の基準は「外れ」とする（M17 と同じ）。

- **R**: `evals.jsonl` の t = 1800 の val の行で、`stack_mse` < 0.177（段 0 の val の PCA-1024）
- **U**: posthoc の `metrics.jsonl` で、1800 秒の checkpoint の val の行（`code=ae`）の `recon_blur` と `dyn_1/copy_1` が、両方とも `m18-ae-base-v1` の `baselines.jsonl` の val の `code=vit`（同じ preset の学習前のエンコーダ）より小さい
- **過学習の確かめ**: 過学習の確かめの run の t = 1800 の val の行で、`pool_stack_mse` < 0.196（段 0 の、同じ 256 個での PCA-1024）

R と U が両方成り立つ run を「学べた」とする。$B$ = 32 の run にも同じ R と U を当てるが、下の読み方の表には入れず、学習の効率として読む。

判定には使わず、並べるものは次のとおりである。

- U の横の参考: posthoc の `refs.jsonl` の val の `tube`（tubelet ごとの平均の色の符号、$D$ = 384）の `recon_blur` と `dyn_1/copy_1`。学んだ符号が平均の色の符号を上回るかを読む
- `stack_mse` < 1 か（平均の積みより良いか）と、時刻 0 の値（run の `baselines.json`）からの動き
- システムのデコーダの `own_recon`・`own_recon_blur` と、その絵（`<t>-own.png`）
- 過学習の確かめの `pool_stack_mse` と val の `stack_mse` の差（どれだけ覚えたか）
- 60 秒ごとの `stack_mse` の経過と、`stream.jsonl` の学習の損失

R は非線形のデコーダ $g$ を通した再構成を線形の最適解と比べる。$g$ が非線形なことも R に寄与しうる。U は後から学ぶ同じデコーダで符号そのものを測るので、$g$ に依らない。

### 回す前の予測

- **Q1**（RMSProp・AdamW）: 過学習の確かめは条件を満たす。256 個は線形でも誤差 0 で表しきれ、run はそれを 54000 歩で繰り返し学ぶ（1 個あたり約 211 回）。そのため、線形の最適解の汎化の値（0.196）より下がる
- **Q2**（RMSProp・AdamW）: ストリームと並べ替えで、R と U の判定は同じになる。窓の中の $\eta$ では、どの $K$ でも $\eta K < 1$ だからである。判定が分かれたら、窓の導出（$K$ の見積もりか、一歩の大きさの目安）が外れている
- **Q5**（RMSProp・AdamW、$B$ = 32 の効率）: 同じ数の積みを見た時点では、$B$ = 1 の 1800 秒の val の `stack_mse` が、$B$ = 32 の 60 秒の値より小さい。60 秒の $B$ = 32 は 1800 歩で 57600 個の積みを見ており、$B$ = 1 の 1800 秒の 54000 個とほぼ同じ数である。Adam 系の一歩は要素あたり約 $\eta$ が上限で、これは $B$ に依らない。そのため 1800 歩で動ける量は最大で $1800\,\eta$ = 0.052 で、窓の下端の条件（$O(1)$ 動ける）に 19 倍足りない。$B$ = 1 は $54000\,\eta$ = 1.57 で条件を満たす。この予測は、$B$ = 1 の 1800 秒の val の `stack_mse` が時刻 0 の値（`baselines.json`）より下がった run に限って判定する
- SGD は R・U・過学習の確かめのどれも予測しない。計画の「SGD の読み」のとおり、run の中で $O(1)$ 動けるのは曲率 $\lambda \ge 1/(F\,\mathrm{lr}) \approx 90$ の方向だけで、それより下の固有値は測っていない

### 読み方

optimizer ごとに、$B$ = 1 の 3 本で計画の表を当てる。

| 過学習の確かめ | 並べ替え | ストリーム | 読み |
| -- | -- | -- | -- |
| × | － | － | 実装かモデルが原因。ストリームの主張の前に直す |
| ○ | × | － | 学習の設定かモデルが原因。手法を判定する前に、段 3 の掃引を自己符号化器で回す |
| ○ | ○ | × | 時間相関のある順序が原因。KL の動きを含まない形で言える |
| ○ | ○ | ○ | ストリームは再構成の目的の妨げではない。段 2（ELBO）に進む |
| ○ | × | ○ | 予想していない。そのまま書く |

並べ替えの列の「○」は、並べ替えの run が R と U を両方満たすことである。

- 段 2 に移す設定は主の RMSProp の行で決める。RMSProp が「段 2 に進む」行なら、段 2 は RMSProp で回す。RMSProp が学べず、AdamW か SGD だけがその行に入ったら、そのまま書き、段 2 の optimizer はユーザーと決める
- どの optimizer もストリームで学べなければ、表の読みに従って段 3 の掃引に進む
- optimizer の間の差は傾向として書き、優劣は書かない（$\eta$ の意味が optimizer と `scale` で違う）
- $B$ = 32 はフレームあたり（同じ時刻の `stack_mse`）と積みあたり（$B$ = 32 の 60 秒と $B$ = 1 の 1800 秒）で $B$ = 1 と並べる。フレームあたりの差は予測しない。Adam 系では $B$ を増やすと勾配の SNR が上がり、一歩の実効の大きさが最大で約 $\sqrt{B}$ 倍になりうる。SGD では一歩の期待値が $B$ = 1 と同じで、雑音が $1/B$ になる。どちらの場合も、32 本の流れはループの全体から積みを見るので、見る場面の広さも $B$ = 1 と違う
- SGD が発散したら、その run は外れとして記録し、段 3 の格子に回す。段 0 の $\rho_{\max}$ は 2048 個の標本の最大で、1 本の run の時刻 0 でそれを超える積みは約 26 個あると見込む（計画の「SGD の学習率」）

### 交絡と限界

- seed は 100 の 1 本で、$B$ = 1 のどの run も同じフレーム列を見る（並べ替えは同じ積みの集まりを別の順に見る）。設定の間の差は傾向として書く
- 1800 秒の $B$ = 1 は動画の 5400 秒、相関時間で 2.5〜8 個しか見ない。ストリームと並べ替えの両方が学べないとき、「場面が足りない」と分けられない
- val は Zurich の 1 本だけである
- $B$ = 32 は $B$ = 1 と比べて、勾配の雑音、見る場面の広さ、Adam 系の一歩の実効の大きさが同時に違う。$B$ = 32 と $B$ = 1 の差をどれか 1 つに帰さない
- SGD の `lr` は学習前の Hessian だけから導いた。学習とともに曲率が変わっても `lr` は変えない
- 速さは判定の基準ではない。`stream.jsonl` の fps は評価の時間を含む run の値なので、リアルタイムの目標と比べるのは段 0 の bench の値とする

### 再現のコマンド

コードはこの節のコミットで、mujou `7a8b72e`、データ `3c3e6805fdaa` である。snapshot はこのコミットの木を `just fleet push` したもので、値は投げたあとに結果の節に書く。保留中の batch（`m17-ssig-v1`、`m16-balls-joint-img-bp-v1`、`m17-tok-v1`）には触れない。

```bash
just fleet push
R=/nas/geson/mujou-exp/runs/m18-ae-v1
for opt in rmsprop adamw sgd; do
  case $opt in
    rmsprop) o=(+experiment=m18/ae_t128) ;;
    adamw)   o=(+experiment=m18/ae_t128 optim_vision.kind=adamw) ;;
    sgd)     o=(+experiment=m18/ae_t128_sgd) ;;
  esac
  for arm in stream:1 shuffle:1 pool:1 stream:32; do
    oo=("${o[@]}" data.tours.sampling=${arm%:*} data.streams=${arm#*:})
    rid=$(just fleet submit --batch m18-ae-v1 "${oo[@]}" --seeds 100 --res 4090 --gpu-mem 20 \
        | awk '$1 == "new" {print $2}')
    [ -n "$rid" ] || { echo "no new run: $opt $arm"; continue; }
    [ "${arm%:*}" = pool ] && continue  # the overfit control has no posthoc
    just fleet submit --batch m18-ae-post-v1 "${oo[@]}" task=posthoc --seeds 100 --res 4090 --gpu-mem 20 \
        --after "$rid" --set parent=$R/$rid --set decode.ckpts=all
  done
done
just fleet submit --batch m18-ae-base-v1 +experiment=m18/ae_t128 task=baselines --seeds 100 --res 4090 --gpu-mem 20
# after the runs
just fleet pull --batch m18-ae-v1
just fleet pull --batch m18-ae-post-v1
just fleet pull --batch m18-ae-base-v1
```
