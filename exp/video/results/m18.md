# Walking Tours の単一ストリームから VAE を学ぶ（M18、2026-11-15〜）

[README](../README.md) の結果の 1 節。MILESTONES.md の M18。計画は [plans/m18-vae-stream.md](../plans/m18-vae-stream.md) にある。段 1 は決定的な自己符号化器（$\tfrac12\lVert y - g(f(x))\rVert^2$、$y = x/256$）で、エンコーダは M17 の t128 の ViT、デコーダはそれを裏返した 2 ブロックの ViT である。どちらもシステムの中で BP で学ぶ（`program=ae`、`exp/video/vae/`）。

## 段 0 の測定（2026-11-15）

段 1 の物差しと、学習の設定を導くための値を、run の前に閉じた形で測った。スクリプトは `exp/video/diag/m18_stage0.py`（テストは `tests/video/diag/test_m18_stage0.py`）である。乱数を使うのは power iteration の始めの向き（seed 0）と、過学習の確かめの 256 個の積みの抽出（run の seed 100 + 6）だけである。

### 学ぶ積みの平均と分散

学ぶ 9 本の積みは M17 の PCA と同じ 2048 窓 × 9 個で、$n$ = 18432 個ある（窓が動画をまたいで落ちたものは無い）。1 つの積みは $P$ = 16 × 3 × 128 × 128 = 786432 個の値である。

| 量 | 値 |
| -- | -- |
| 平均の画素（$y = x/256$） | 0.457（R 0.465、G 0.459、B 0.446） |
| $\sigma_0^2$（値ごとの分散の平均） | 0.07431（$\sigma_0$ = 0.273） |
| 共分散の固有値の和 / $P$ | 0.07431（$\sigma_0^2$ と 13 桁で一致。測り方の確かめ） |

平均の積み（`m18-stage0/pca.png`、左が 1 枚目、右が 16 枚目）は、上が明るい灰色の一様に近い画像で、2 枚に違いは見えない。

### 積みの PCA

共分散の固有値は $n \times n$ の Gram 行列を float64 でブロックに分けて計算した。上位 1024 個の主成分の基底 $U$ の直交性のずれは最大 2.4 × 10⁻¹³ だった。

| 量 | 値 |
| -- | -- |
| 0 でない固有値の数 | 18431（$n - 1$） |
| 最大の固有値 $\lambda_1$ | 11257（$\sigma_0^2$ の 1.5 × 10⁵ 倍） |
| 1024 番目の固有値 $\lambda_{1024}$ | 3.66（$\sigma_0^2$ の 49 倍） |
| $\sigma_0^2$ を超える固有値の数 | 15420 |
| 上位 1024 個が占める分散の割合 | 0.847 |

$\lambda_{1024}$ は $\sigma_0^2$ の 49 倍なので、段 2 の pPCA-1024 は時刻 0 の $\sigma_0^2$ のもとで 1024 次元のすべてを使う（計画の「事後分布の崩壊（最適点）」）。ただし $\sigma_0^2$ は $P$ 方向の平均で、標本の共分散の 0 でない固有値は $n - 1$ 個しかない。そのため 15420 という数は$P$ に比べて標本が少ないことにも依る。

### PCA-1024 の `stack_mse`（段 1 の物差し）

`stack_mse` は $\sum\lVert y - \hat y\rVert^2 / \sum\lVert y - m\rVert^2$ で、$m$ は上の平均の積み、$\hat y = m + UU^\top(y - m)$ である。held-out は M17 の評価と同じ窓の最初の積み（各 256 個）、過学習の確かめは `PooledStackedTourFrames` の 256 個（seed 106）である。

| 積み | PCA-1024 の `stack_mse` | 平均の積みの誤差 / $P$ |
| -- | -- | -- |
| val（Zurich） | **0.177** | 0.0696 |
| test（Zurich） | 0.206 | 0.0671 |
| 過学習の確かめの 256 個（学ぶ 9 本） | **0.196** | 0.0762 |

段 1 の R は val の `stack_mse` < 0.177、過学習の確かめの条件は `pool_stack_mse` < 0.196 になる。256 個そのものに当てはめた PCA の最適値は 0 である（256 個は平均を除くと rank 255 以下で、1024 次元で表しきれる）。

最後のフレームだけの PCA-1024 の val の `recon_lin` は 0.087 だった（results/m17.md）。積みの PCA は同じ 1024 次元を 16 枚に使うので、誤差の割合は約 2 倍になる。

### 学習前の損失の Hessian と SGD の学習率

学習前の自己符号化器（seed 100、パラメータ 1105 万）の損失の Hessian に、power iteration（Hessian とベクトルの積は二重の逆伝播）を当てた。積みは学ぶ 9 本の 2048 窓（段 0 の平均の積みと PCA と同じ窓）の最初の積みで、ループに等間隔に並ぶ。スペクトル半径 $\rho$ は単位ベクトル $v$ の $\lVert Hv \rVert$ で見積もった。止める条件は、変化の比から見積もった残りの誤差が $\rho$ の 10⁻⁴ を下回ることである（計画の「SGD の学習率」）。

| 量 | 値 |
| -- | -- |
| 積みの数 | 2048（止まるまでの反復は平均 21 回） |
| 止める条件に届かなかった積み | 5 個（200 回で打ち切り。$\rho$ の見積もりは 5.4 × 10⁵〜1.02 × 10⁶） |
| 絶対値の最大の固有値が負の積み | 668 個（33%） |
| $\rho$ の中央値 | 1.08 × 10⁶ |
| $\rho$ の 90% 点 | 2.02 × 10⁶ |
| $\rho$ の 99% 点 | 3.93 × 10⁶ |
| $\rho$ の 99.9% 点 | 4.69 × 10⁶ |
| $\rho$ の最大 $\rho_{\max}$ | **4.79 × 10⁶**（積み 1603、固有値は負） |
| 最大の固有値が正の積みの中での $\rho$ の最大 | 3.35 × 10⁶ |
| $B$ = 32 の 32 本の流れの最初の積みの平均の損失の $\rho$ | 8.59 × 10⁵（32 個の $\rho$ の平均は 1.16 × 10⁶） |

止める条件に届かなかった 5 個の見積もりは $\rho$ の下界で、$\rho_{\max}$ の 0.21 倍以下である。どれかの真の $\rho$ が $\rho_{\max}$ を超えるなら、その方向の重みは $H^2$ の反復ごとに $(\rho_{\max}/1.02\times10^6)^2 \approx 22$ 倍以上の速さでほかに対して増える。そのため、200 回のあとも見積もりに現れないことはない。99.9% 点は最大の 0.98 倍で、上端は最大の近くで詰まっている。

$\rho$ の最大を $\lambda_{\max}$ の代わりに使う（計画のとおり）。$B$ = 32 の平均の $\rho$ が 32 個の $\rho$ の平均より小さいことは、三角不等式による導出と合う。$B$ = 32 でも同じ学習率で条件を満たす。

SGD の学習率（フレームあたり、`optim_vision.lr`、`scale=none`、preset `m18/ae_t128_sgd`）は次のとおりである。

$$
\mathrm{lr} = \frac{1}{1.02 \times 4.79\times10^6} = 2.05\times10^{-7}
$$

1.02 は一歩の elapsed のフレームに対する最大の比である（`tests/video/vae/test_bp.py`）。発散の境目（$2/\rho_{\max}$ を 1.02 で割った値）は 4.09 × 10⁻⁷ で、この lr はその半分にあたる。RMSProp と AdamW は $\eta$ = 2.9 × 10⁻⁵（`scale=fan_in`）で、$B$ に依らない（計画の「$B$ = 32」）。

**8 個の積みで測った最初の値**: 段 0 の最初の測定はループを 8 等分した位置の 8 個の積みだけで $\rho$ を測り、最大 1.386 × 10⁶ から `lr` = 7.08 × 10⁻⁷ を出していた。8 個からではどの積みでも条件を満たすとは言えないとレビューで指摘され、2048 個で測り直した。8 個は 2048 個の中に同じ積みとして含まれ、値も一致した（積み 0 は 1.38556 × 10⁶）。しかし 1.386 × 10⁶ は 2048 個の 71% 点にすぎない。29% の積みの $\rho$ がこれを超え、76 個（3.7%）はその 2 倍（古い `lr` での発散の境目）を超えた。最大の固有値が正の積みに限っても、4 個が境目を超えた。古い `lr` は採らない。

### 速さ（`task=bench`、4090）とリアルタイムの目標

std-03 の 4090 で、ほかの run の無いときに測った。BP、`m18/ae_t128`（preset の RMSProp）、seed 100 である。$B$ = 1 は 60 秒（1800 単位）、$B$ = 32 は 20 秒（600 単位）回した。fps は run の開始から数えるので、立ち上がりの時間を含む。短い $B$ = 32 の値はそのぶん遅い側に偏る。

| $B$ | fps（単位/秒） | 積み/秒 | 目標（10/$B$ 単位/秒） | 目標との比 |
| -- | -- | -- | -- | -- |
| 1 | 80.8 | 80.8 | 10 | 8.1 倍 |
| 32 | 28.6 | 914 | 0.3125 | 91 倍 |

リアルタイムの目標は動画の 0.1 秒（`advance=3` の 1 単位）を壁時計の 0.1 秒以内に終えることである（計画の「リアルタイムの目標」）。BP の自己符号化器は $B$ = 1 でも $B$ = 32 でも目標を上回った。仮想時間を壁時計に合わせるもう 1 つの読み方（30/$B$ 単位/秒）でも、$B$ = 1 の 80.8 は 30 を、$B$ = 32 の 28.6 は 0.9375 を上回る。これは段 1 の判定の基準ではない。この速さなら、$B$ = 1 の 1800 秒の run（54000 単位）の学習は約 11 分、$B$ = 32 は約 32 分で終わる見込みである（評価の時間は含まない）。PC-ALM の速さはまだ測っていない。
