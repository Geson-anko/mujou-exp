# 画像・動画の JEPA（M15、2026-11-03〜）

[README](../README.md) の結果の 1 節。MILESTONES.md の M15。動力学を外し、ViT のエンコーダを JEPA の損失（マスクした patch の潜在の予測 + SIGReg）だけで学ぶ。動画は $N$ フレームのまとまり（チャンク）で扱い、$N=1$ が画像。

実行は fleet（`exp/lib/fleet/README.md`）。preset は `exp/video/conf/experiment/m15/`、表は `just fleet table`（`exp.lib.runs`）。

## 設定

- **データ**:
  - 玉: M14 の段 2 と同じ 3 つの玉（半径 0.06・0.08・0.10）を 32×32 に描いた動画、B=128 のストリーム
  - Walking Tours: 10 本を 10 fps・64×64 に縮めたもの（data_version `ad6e56b5995e`、2026-11-03）。Zurich は評価だけに使い、残りの 9 本で学ぶ。画素の平均 0.46・標準偏差 0.28（学ぶ 9 本の 50 フレームごと）で標準化する
- **モデル**: `vit_t`（幅 128、4 head、6 block を 2 つの PC-ALM ノードに分ける、予測器 2 block）。patch は玉で 4、Walking Tours で 8（どちらも 64 トークン）。$N>1$ ではマスクをチャンクの時間方向に通す（tube）
- **学習**: PC-ALM（`exp/video/jepa/nodes.py`）と BP（`jepa/bp.py`、同じ初期値）。optimizer は AdamW
- **評価**（`measure.every` 秒ごと）: 各 split（calib・val・test）の固定したチャンクを符号化し、calib で線形の probe を学び（ridge は calib の中の 5-fold 交差検証と 1 標準誤差の規則）、val・test で $R^2$ を測る
  - 玉: 玉ごとの位置 $(x, y)$ の $R^2$ と、その最小（`probe_pos_min`）。$N>1$ では速度も（`probe_vel_min`）
  - Walking Tours: 灰色の 8×8 の縮小画像の $R^2$（`thumb`）
  - 共通: 実効ランク（`rank`）、次元ごとの標準偏差の最小（`z_std_min`）、標本間の広がり（`z_spread`、1e-3 未満は崩壊とみなす）
  - 物差し（`baselines.json`）: 学習前の同じ ViT（`init_*`）と、8×8 に縮めた画素（`pixels_*`）からの probe
- **後から学ぶデコーダ**（`task=posthoc`）: 各チェックポイントで、ストリームから一様に取った 16384 フレームの $z$ から画像へのデコーダを 2000 ステップ学び、評価のチャンクを描く（`post/decode/<t>.png`）
- **コード**: snapshot `25a3c1d`（mujou `881c4ee`）

## 判定基準（回す前に決めた、2026-11-03）

M16 に持ち込むのは玉の設定（玉の状態で答え合わせができるため）。受け渡しの条件は、**test** のチャンク、run の最後の評価、**PC-ALM と BP、seed 0/1/2 のすべて**で次を満たすこと。run の長さと設定は BP の探索（seed 100/101、val、目的は $1-$ `probe_pos_min`）で決め、確認の seed は選択に使わない。

1. 発散しない（`status` が `completed`）、崩壊しない（`z_spread` ≥ 1e-3）
2. 3 つの玉すべての位置で $R^2 \ge 0.9$（`probe_pos_min` ≥ 0.9）。学習前の ViT と画素の probe も上回る
3. 後から学ぶデコーダの画像（`post/decode/<t>.png`）で 3 つの玉が正しい位置に見える。見たファイル名をここに書く
4. 局所性・非同期性を崩さない（PC-ALM の版はノードをまたぐ `.backward()` と `.grad` を持たない: `tests/video/jepa/test_nodes.py`）

あわせて書くもの（判定には使わない）: $N=4$ の `probe_vel_min`、sg のあり・なしと SIGReg をかける先（`z`・`tokens`・`both`）の比較、実効ランク。`vision.recon` > 0 の run では、`thumb` も「デコーダの再構成」も学習の目的（z から最後のフレームを戻す項）に近いので、独立した判定には使わない。Walking Tours は `thumb` が学習前の ViT と画素を上回るか、デコーダの再構成が平均の画像より細部を描くかを書く。

どの設定も条件 2 に届かなければ、設計 8.4 のとおり別の視覚の損失を検討する（M16 で動力学から credit を戻す案は出さない）。

## 探索（BP、`m15-balls-n1-bp-v1`、玉 $N=1$）と診断

study は sg のあり・なし、SIGReg をかける先（`z`・`tokens`・`both`）と重み、マスクの比率、学習率を探す（32 trial、ASHA）。最初の 6 trial（360 秒まで）では、SIGReg は崩壊を防ぎ（実効ランクが 35 まで上がる trial もある）、それでも `probe_pos_min` は 0.05〜0.2 にとどまり、学習前（0.26）を下回った。z が潰れて SIGReg の値が 52 に張り付いた trial もある。

**診断**（preset のまま、BP、seed 100、600 秒、val、snapshot `cce8616`）: 位置の情報が平均の pool で失われたのか、トークンからも消えたのかを、トークンを平らにした特徴（64 トークン × 128 = 8192 次元）の probe で確かめた。

| 特徴 | 次元 | `probe_pos_min` | 一番大きい玉の $x$・$y$ |
| -- | -- | -- | -- |
| 学習前の $z$ | 128 | 0.27 | 0.72・0.76 |
| 学習前のトークン | 8192 | 0.11 | 0.61・0.62 |
| 600 秒学んだ $z$ | 128 | 0.04 | 0.47・0.43 |
| 600 秒学んだトークン | 8192 | 0.009 | 0.48・0.48 |

pool のせいではなく、学ぶほどトークンからも玉の情報が消える。マスクで隠れた玉は文脈から当てられないので、エンコーダは玉を表さない方向へ動く（設計 8.4 の危険、M13 と同じ向き）。設計 8.4 のとおり、別の視覚の損失として、$z$ から画像を戻す再構成の項 $\mu L^{\mathrm{rec}}$ を JEPA の損失に足す版を作っている（`vision.recon`、既定 0）。動力学からの credit は使わない。

### 再構成の項の試し（`m15-recon-pilot-v1`、BP、seed 100、900 秒、val、snapshot `a783f4e`）

| $\mu$ | 再構成の誤差（平均の画像 = 1） | `probe_pos_min` | 玉 0・1・2 の `probe_x` | 実効ランク |
| -- | -- | -- | -- | -- |
| 1 | 0.29 | 0.21 | 0.30・0.25・0.70 | 23 |
| 10 | 0.094 | 0.13 | 0.13・0.24・0.59 | 52 |
| 100 | 0.062 | 0.034 | 0.03・0.20・0.57 | 77 |

再構成は効き、$z$ は 3 つの玉を描き戻せる情報を持つ。それでも位置は $z$ の線形な関数にならず、$\mu$ を上げるほど $z$ は高いランクの非線形な符号になって probe が下がる。M16 の動力学は $z$ を線形に読む（M14 の段 3 で、線形の入力の動力学は画素から位置を取り出せなかった）ので、線形に読めることは受け渡しの条件として意味がある。次は、位置を線形に持たせる帰納バイアスとして spatial broadcast decoder（Watters et al. 2019。$z$ を各画素に並べ、画素の座標と合わせて画素ごとの MLP で値を出す）を試す。

#### spatial broadcast decoder の試しの判定基準（回す前に決めた、2026-11-03）

`m15-broadcast-pilot-v1`: BP、seed 100/101、1800 秒、val。腕は broadcast（幅 64、`recon_hidden` の既定）の $\mu$ = 1・10・100 と、幅をそろえた対照の mlp（`recon_hidden=64`）の $\mu$ = 10。

- **支持**: ある $\mu$ で、broadcast の 1800 秒の `probe_pos_min` が 2 seed とも 0.5 以上、かつ同じ $\mu$ の mlp を 2 seed とも上回る。支持なら、その腕のまわりで study を回し、受け渡しの条件（0.9）を目指す
- **棄却**: どの $\mu$ でも 2 seed とも 0.5 に届かない。棄却なら、線形に読める位置を目的に直接入れる別の帰納バイアス（例: スロット）を検討する。動力学からの credit には戻さない

#### spatial broadcast decoder の試しの結果（snapshot `67bdd7d`）

1800 秒の val。数字は seed 100・101 の順。

| 腕 | `probe_pos_min` | 玉 0（半径 0.06）の `probe_x` | 再構成の誤差 | 実効ランク |
| -- | -- | -- | -- | -- |
| broadcast $\mu=1$ | 0.29・0.32 | 0.78・0.74 | 0.063・0.053 | 17・17 |
| broadcast $\mu=10$ | 0.29・0.33 | 0.81・0.81 | 0.024・0.030 | 8・8 |
| broadcast $\mu=100$ | **0.90・0.94** | 0.90・0.94 | 0.18・0.16 | 4.3・4.5 |
| mlp（幅 64）$\mu=10$ | 0.047・0.15 | 0.05・0.19 | 0.18・0.18 | 46・45 |

broadcast の $\mu=1$・10 では、最小を決めるのは中くらいの玉（`probe_x1` 0.29〜0.33）。$\mu=100$ の `z_spread` は 0.79・0.83 で、崩壊していない。

**判定: 支持**。broadcast の $\mu=100$ が 2 seed とも 0.5 を大きく超え（0.90・0.94）、同じ幅の mlp を上回った（mlp は $\mu=10$ だけを回したが、幅 256 の mlp の $\mu=100$ は再構成の試し（900 秒）で 0.034 だったので、比べる向きは変わらないとみる）。大きい 2 つの玉は $R^2$ 0.999 で、一番小さい玉（半径 0.06）が最小を決め、1800 秒でもまだ上がっている。$\mu=100$ では $z$ が玉の位置に近い低いランクの符号（実効ランク 4.3〜4.5）になり、再構成の誤差は $\mu=10$ より大きい。broadcast の帰納バイアスが効くのは再構成の項が JEPA の損失より十分重いときで、$\mu \le 10$ では JEPA の損失が玉を消す向きに勝つ（$\mu=1$・10 では中くらいの玉（半径 0.08）の $R^2$ が 0.3 前後にとどまる）。

次は broadcast を固定し、$\mu$（20〜1000）、デコーダの幅、sg、SIGReg をかける先と重み、マスクの比率、学習率を BP の study（`m15-balls-n1-broadcast-bp-v1`、seed 100/101、val、目的は $1-$ `probe_pos_min`）で探す。あわせて、PC-ALM が BP と同じように学ぶかを、この腕（$\mu=100$）の PC-ALM の run（seed 100、val）で先に確かめる。

### broadcast のまわりの探索（`m15-balls-n1-broadcast-bp-v1`、BP、seed 100/101、val、snapshot `e9c37dc`）

32 trial を投げた時点で、1800 秒まで走りきった trial は少なく、ほとんどは ASHA（300・900 秒）で打ち切られた。目立つのは学習の不安定さで、学習率が 3e-4 を超える trial の多くは 300〜600 秒で `probe_pos_min` 0.95 前後に達した後、片方の seed で損失が跳ね（例: #2 の seed 100 は 850 秒あたりで損失が 5 から 195 へ）、$z$ が潰れて（SIGReg の値が 37 から 120 へ）0.2〜0.4 に落ちる。学習率が低い trial は安定するが遅い（#4: lr 5.3e-5、1800 秒で 0.91・0.92、まだ上がっている）。

**PC-ALM の確かめ**（`m15-broadcast-pc-v1`、broadcast の試しの $\mu=100$、seed 100、val）: 480 秒まで BP の同じ腕とほぼ同じ曲線をたどった（`probe_pos_min` 300 秒で PC-ALM 0.54・BP 0.44、480 秒で 0.77・0.67、再構成の誤差 0.46・0.47）。共有の GPU で 2 フレーム/秒しか出ず、確認の run に GPU を空けるため 480 秒で止めた。

#13 は 2 seed とも 300 秒ごとの評価で落ち込みが無く、最後まで 0.95 前後を保った。受け渡しの条件（0.9）に余裕を持って届いたので、32 trial（完了 2、打ち切り 26）の時点で study を止め（調整役を止め、残りの run を取り消した）、#13 を確認に回す。確認が通らなければ study を再開する。
