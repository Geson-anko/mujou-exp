# ストリームに合う optimizer と relaxer（M10、2026-10-31）

[README](../README.md) の結果の 1 節。ファイル名とパスは当時のもの。

M9 の設定（`stop_target` あり、$\kappa=0.8$、SGD は学習率 0.01）の上で、段 2 の比較を回し直す。M8 の判定（H2〜H4）はここで出す。

**relaxer: 候補から外す**
- 測ったもの（M9 の設定、seed 0/1、60 秒、計 3455 フレーム）: 各フレームの最後のステップで、平衡点（$r=0$、$\lambda=-g$）までの残り。$\lVert r\rVert/\lVert\lambda\rVert$ の中央値は `G1` 2.6〜2.9%、`Z` 0.8〜0.9%、Dynamics 0.7〜0.8%（90 パーセンタイルでも 4% 以下）。最後のステップでの $\lambda$ の変化も同じ大きさ
- フレーム内の 16〜17 ステップで、credit は数 % まで BP に届いている。relaxer は平衡点への道筋だけを変えるので、縮められるのはこの数 % だけ。段 0（BP と 3 桁一致）と M9（`rollout10` が BP と同じで、発散しにくい）とも合う
- 決めておいた規則（届いていれば relaxer は外す）に従い、mujou への relaxer の追加はしない

**回す前に確定した判定基準**（`stage2.judge` をそのまま使う。runs は `runs/stage2-m10`）
- 共通: 合成動画 30 分、seed 0/1/2、`stop_target` あり、$\kappa=0.8$、SGD の学習率 0.01。向きはすべて grafting で SGD の歩幅にそろえる。白色化と射影は `refresh=5` 秒、$\tau_L,\tau_R\in\{0.3,3\}$ 秒。`pc.optim.AdamW` は要素ごとの学習率 1e-3（参考）
- 指標、H2〜H4、崩壊した run の扱い、前提（SGD の `rollout1` < 1）は段 2 の節と同じ
- 段 2 との違い: 発散した run は、その seed の基準からも候補からも外す（崩壊と同じ扱い）。H2 の候補が発散したら、その seed では改善なしになる
- 実時間の確認: H2 で最もよかったもの（平均の改善で選ぶ）と SGD を、`realtime: true`（`mujou.run`）で 1 本ずつ 30 分回す。順位（`preq`）が変わらなければ「実時間でも保つ」

- 崩壊: 走り切ったが $z$ の分散が数千倍に伸びる（または 0 になる）か、実効ランクが SGD の半分未満。発散: 途中で NaN になり、走り切れなかった
- **Adam 系は 9 本すべてが崩壊か発散**。要素ごとに歩幅をそろえるので、勾配の小さい方向にも大きく歩く。SIGReg が $\lvert z\rvert$ を外へ押す力をそのまま強めた。grafting で全体の歩幅を SGD にそろえても防げなかった。このため、基準はすべての seed で SGD だけになった
- `preq` は、どの候補も SGD を超えなかった。白色化は $R$ を入れると 13〜21% 悪くなる
- `rollout10` は、射影（rank 4）が 3 seed とも 7〜18% よくした。その代わりに `preq` は 7〜10% 悪い。白色化（$\tau=3$）と射影（rank 16）も 2 seed でよくしたが、残りの 1 seed で崩壊か発散した
- 時間方向の相関を崩すシャッフルは、SGD より `rollout10` が悪い。replay は `preq` と `retention` では SGD と同程度かよいが、`rollout10` は 2.0 を超えて最も悪い

**実時間の確認**（`mujou.run`、seed 0、30 分、1 本ずつ。runs は `runs/stage2-m10-realtime`。評価は止めた後の 1 回）

| 設定 | `preq` | 間に合わなかったフレーム | `rollout1` | `rollout10` | 実効ランク |
| ---- | ------ | ------------------------ | ---------- | ----------- | ---------- |
| SGD            | **0.307** | 3 / 54000（0.01%） | 0.54 | 1.62 | 44.0 |
| 射影（rank 4） | 0.335 | 6686 / 54000（12.4%） | 0.55 | 1.60 | 42.3 |

- `preq` の順位（SGD が上）は実時間でも変わらない。「実時間でも保つ」
- 射影は 1 フレームの計算が実時間に追いつかず、8 フレームに 1 つは予測が間に合わなかった。`rollout10` の差（段 2 の手で回す実行では 7〜18%）も、実時間では 1% まで縮んだ
- どちらも、手で回した同じ seed（SGD 0.278、射影 0.297）より `preq` が 1 割ほど悪い。実時間ではフレームあたりのステップ数が揃わないためと見ている（未検証）

**M10 の判定: 完了**
- 段 3（EgoDex）に持ち込む optimizer は **SGD**（M9 の設定: `stop_target` あり、$\kappa=0.8$、学習率 0.01）。relaxer は mujou の `pc.relax.Euler` のまま
  - SGD は `preq` で負けず、最も軽い。射影は `rollout10` をよくするが、`preq` を悪くし、実時間では追いつかない
  - Adam 系は、この設定では使えない（崩壊か発散）
- mujou に上げる候補: **なし**。白色化・射影・直交化のどれも、mujou の optimizer として足す根拠になる改善を示さなかった。relaxer も足さない（上の測定）
- 段 3 の前に残る課題
  - `rollout10` は 1.5〜1.9 で、10 フレーム先はまだ $z$ の平均を言うより悪い
  - SIGReg が $\lvert z\rvert$ を外へ押す不安定さが残る。BP とシャッフルは学習率 0.01 でも seed 1 で発散し、Adam 系はこれで崩れた
