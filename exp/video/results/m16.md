# 視覚と動力学の同時の学習（M16、2026-11-03〜）

[README](../README.md) の結果の 1 節。MILESTONES.md の M16。M15 のエンコーダ（視覚の損失だけで学ぶ）と M14 の動力学（エンコーダの $z$ の次を予測する）を、1 つの run で同時に学ぶ。動力学の予測誤差はエンコーダに credit を送らない（`programs/joint.py`）。

実行は fleet（`exp/lib/fleet/README.md`）。preset は `exp/video/conf/experiment/m16/`、表は `just fleet table`（`exp.lib.runs`）。

## 設定

- **データ**: M15 と同じ 3 つの玉（半径 0.06・0.08・0.10）を 32×32 に描いた動画、B=128 のストリーム、$N=1$
- **視覚**: M15 の受け渡しの設定（`m15-balls-n1-broadcast-bp-v1` の #13: `vit_t`、patch 4、JEPA と spatial broadcast decoder（幅 64）による最後のフレームの再構成の項 $\mu=22$、sg なし、SIGReg はトークンに 0.056、マスク 0.5、AdamW 2.0e-4、warmup 60）
- **動力学**: 小（M14 の段 2 と同じネットワーク）。入力と目標は $z$（128 次元）で、M14 の観測（6 次元、標準化済み）と尺度が違うので、M14 の段 2 の #45 から始めて、optimizer の値とトレース・残差・`open_loop` を BP の study（seed 100/101、val、目的は `roll10/mean10`）で選び直した。選んだのは #14（トレースなし、AdamW 6.6e-5、`tau_m` 0.33、`tau_v` 12、warmup 300、残差、`open_loop` 0.5）
- **学習**: PC-ALM と BP。動力学の誤差はエンコーダへ戻らない（PC-ALM は `z_out` が送るだけのポート、BP は detach）。同じ seed とデータでは、エンコーダの重みは M15 の視覚だけの run とビット単位で同じになる（`tests/video/programs/test_joint.py::TestNoCreditToTheEncoder`）
- **対照**（`m16/balls_frozen`）: エンコーダを、同じ設定・seed・学習則の M15 の確認の run の最後のチェックポイントに固定し、動力学だけを学ぶ
- **評価**（`measure.every` 秒ごと）: 視覚の行（M15 と同じ probe、実効ランク、`z_spread`）と、固定した窓（16 フレームを観測し、そこから開ループで予測）の潜在の誤差 `roll{h}`、`copy{h}`（最後の $z$）、`mean{h}`（平均の $z$）
- **後から学ぶデコーダ**（`task=posthoc`）: 各チェックポイントで $z$ から画像へのデコーダを学び、動力学が予測した $z$ を画像に戻す。画素の誤差 `img_roll{h}` を、写し（最後の観測のフレーム、`pix_copy{h}`）と平均の画像（`pix_mean{h}`）と比べる。`img_recon` は観測した $z$ を戻した誤差で、デコーダの下限の目安
- **コード**: snapshot と mujou（`881c4ee`）の SHA は各節に書く

## 判定基準（回す前に決めた、2026-11-03）

**test** の窓、run の最後のチェックポイント、**PC-ALM と BP、seed 0/1/2 のすべて**（同時に学ぶ run）で次を満たせば M16 を通ったとする。run の長さと動力学の設定は BP の study（seed 100/101、val）で決め、確認の seed は選択に使わない。

2. 5・10 フレーム先で、デコードした予測が写しと平均の画像の両方を下回る（`img_roll5 < min(pix_copy5, pix_mean5)` かつ `img_roll10 < min(pix_copy10, pix_mean10)`）。20 フレーム先は書くだけ
3. 後から学ぶデコーダの画像（posthoc の `post/decode/<t>.png` の予測の行）で、3 つの玉が正しい向きへ動き、壁と床で跳ね返り、薄れない。見たファイル名をここに書く
4. エンコーダは視覚だけの run と同じものを学ぶ: 最後の評価の `probe_pos_min` が M15 の受け渡しの条件（0.9 以上）を満たす。同じ seed・学習則・GPU の種類なら、M15 の確認の run とビット単位で同じ重みになるはず（テストのとおり）なので、`probe_pos_min` が一致するかも書く
5. 局所性・非同期性を崩さない（ノードをまたぐ `.backward()` と `.grad` が無い、動力学からエンコーダへ credit が無い: `test_joint.py`）

あわせて書くもの（判定には使わない）: 対照（固定したエンコーダ）との `roll{h}/copy{h}`・`img_roll{h}` の差。同時に学ぶことで動力学が損をするか（エンコーダが動く間の非定常さ）を見る。潜在の `roll{h}/copy{h}`・`roll{h}/mean{h}`。

条件 2 に届かなければ、潜在で予測できているか（`roll{h}/copy{h}` < 1）とデコーダの下限（`img_recon`）を見て、動力学の問題か、デコーダ（後から学ぶ道具）の問題かを分ける。

## 二度目の探索（`m16-balls-joint-img-bp-v1`）

判定基準（上の「判定基準」の節）は変えない。変えるのは設定の選び方だけで、study の目的を画像の判定に合わせる。

- **学習中の画像の評価**（`programs/joint.py`）: 視覚の再構成の項のデコーダ（spatial broadcast decoder、学習に使っているもの）で、動力学が予測した $z$ を画像に戻す。キーは `rec_roll{h}`、`rec_recon`、`pix_copy{h}`、`pix_mean{h}`、`rec_roll{h}/pix{h}`（= `rec_roll{h}` / min(`pix_copy{h}`, `pix_mean{h}`)）。後から学ぶデコーダ（`img_*`）とは別のキーにする。評価だけで、学習の状態は変えない
- **目的**: h = 5・10 の $\log$(`rec_roll{h}/pix{h}`) の大きい方（小さいほど良い）。0 未満になるのは 2 つの比がどちらも 1 未満のときだけで、条件 2 の「かつ」と同じになる（平均にすると、5 フレーム先の得で 10 フレーム先の損を埋められてしまう。#19 は平均なら 0 未満だが、条件 2 は満たさない）。val、seed 100/101
- **探索の空間**: 動力学の大きさ（小・大）、トレース、AdamW の学習率（1e-5〜1e-3）・`tau_m`・`tau_v`・warmup、残差、`open_loop`。最初の探索の #14 と #19 を最初に入れる
- 選んだ設定を、最初の確認と同じ形（同時に学ぶ run と対照、PC-ALM と BP、seed 0/1/2、4090、test、後から学ぶデコーダ）で確認する。最初の確認の test の結果を見て探索をやり直したことはここに書いたとおりで、選択そのものは val だけで行う

### 結果（1800 秒の val、seed 100・101）

完了した trial はどれも、5 フレーム先では平均の画像を下回った（`rec_roll5/pix5` 0.65〜0.75。最初の確認では平均の画像とほぼ同じ）。10 フレーム先は、設定によらず 1.2〜1.3 で止まる（目的の最良は #33 の +0.21: 大、トレース、AdamW 9.2e-5、`tau_m` 0.38、`tau_v` 90、warmup 60、残差、`open_loop` 0.25）。上位は大とトレースの組。時間の変化を見ると、`rec_roll10/pix10` は 300 秒から先は下がらない。`roll1/copy1` は 420 秒ごろの 0.46〜0.55 から 1800 秒の 0.62〜0.66 へ悪くなる（エンコーダが鋭くなるにつれ、1 フレームでの $z$ の変化 `copy1` が大きくなる）。失敗した 3 trial（#43・#50・#51）は、4060 に詰め込んだときの起動時の `CUBLAS_STATUS_ALLOC_FAILED` で、設定のせいではない。

ハイパーパラメータでは 10 フレーム先に届かないので、確認の前に、$z$ に足りないのか、オンラインの学習が足りないのかを分ける。

## オフラインの上限（`m16-offline-v1`、val、snapshot `6e40cf4`）

`task=offline`（`programs/joint.py`、preset `m16/offline`）。エンコーダと学習に使うデコーダは M15 の確認の BP seed 0（`m15-confirm-v1/m15-balls_n1-c32db57e-s0`）に固定し、動力学だけを Adam 1e-3 で窓（観測 16 + 先 20 = 36 フレーム、各ストリーム 54000 フレーム = オンラインの 1800 秒と同じデータ）に合わせる。BPTT（窓全体を時間を通して）と 1 フレーム（`offline.local`、トレースの無いノードと同じ）、小と大の 4 本、12000 ステップ。

**判定**（このコードを書く前に決めたが、ここに書いたのは 1000 ステップの評価を見たあと）: 大の BPTT が `rec_roll5/pix5` と `rec_roll10/pix10` の両方で 1 を下回れば、$z$ と動力学の大きさは足りていて、律速はオンラインの学習（トレースの近似、時間の局所性）とみる。下回らなければ、$z$ が予測に向かない（表現の問題）とみて、エンコーダの側を見直す。
