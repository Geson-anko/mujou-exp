# 段 3: EgoDex（M12、2026-11-01）

[README](../README.md) の結果の 1 節。ファイル名とパスは当時のもの。

## 段 3 の準備: EgoDex とノードの数

**データ**（`exp/video/egodex.py`。縮小したデータは `datasets/egodex64/` に置き、git に入れない）
- 学習のストリームは part1 から作る。24 タスク（エピソードが 50 本未満の fry_bread・fry_egg を除く）をタスク名の順に並べ、各タスクから約 75 秒分の連続したエピソードを 1 ブロックとする。全タスクを 2 周し、2 周目は同じタスクのまだ使っていないエピソードにする（保持を測れる）。計 70.2 分（126,408 フレーム）、363 エピソード
- 評価クリップは test から作る。48 タスクから 1 本ずつ選び、先頭の 128 フレームを使う（48 × 128）
- 1080p の動画を ffmpeg（`imageio-ffmpeg`）で高さ 64 に縮小し、中央の 64×64 を切り出す。16 並列で約 100 秒、1.6 GB
- 隣のフレームはほとんど変わらない。初期のエンコーダでも `persist10` は 0.11〜0.16 で、合成動画の 2.1 よりずっと小さい

**モデル**（`ModelConfig.enc_nodes`・`dyn_nodes`、`model.egodex_stages`）
- エンコーダは 3 段: Conv(3→32, s2)・Conv(32→64, s2) / Conv(64→128, s2)・Conv(128→128) / Conv(128→256, s2)・`Linear(4096, 128)`。$D=128$
- 動力学は `Dynamics`（minGRU、$d_s=512$）の上に `DynamicsLayer` を重ねる。各層は $y = x + \mathrm{minGRU}(\mathrm{GELU}(x), h_{k-1})$ で、入力は同じフレームの下の層の出力なので、credit は層を下りる。評価と BP では、同じ計算を 1 つのモジュール `DynamicsStack` にまとめる
- 1 ノードに 1 段を置く。エンコーダ 3 段を 1〜3 ノードに分けても、同じ seed なら同じ関数になる（テストで確認）

**ノードの数: エンコーダ 3、動力学 3**（`exp/video/latency.py`、RTX 4060）
- 学習を止めて EgoDex を流し、フレームの各ステップで、各ノードの `r + lam` を、同じ時点の状態から autograd で求めた BP の credit と比べた（相対誤差の中央値、100 フレーム）
- 時定数（$\tau_\lambda=2$ ms）が周期と同じなので、各ホップの緩和はほぼ 1 ステップで終わる。遅れはホップの数でほぼ決まる
- 全ノードの誤差が 5% 以内に入るまでの時間（書き込みから）:

| エンコーダ + 動力学 | Gauss-Seidel（手で回す順） | Jacobi（実時間と同じく、どの向きも 1 ホップ 1 周期） |
| ------------------- | -------------------------- | ---------------------------------------------------- |
| 1 + 1 | 4 ms | 8 ms |
| 2 + 1 | 8 ms | 10 ms |
| 3 + 1 | 12 ms | 14 ms |
| 2 + 2 | 8 ms | 14 ms |
| 3 + 2 | 12 ms | 16 ms |
| 2 + 3 | 12 ms | 18 ms |
| **3 + 3** | 12 ms | **20 ms** |

- 学習は書き込みから 26 ms のステップで起きる（`learn_interval` 25 ms）。どの分け方でも credit は学習までに回り切る。3 + 3 は Jacobi で 20 ms なので、残りは 3 ステップ。動力学をもう 1 ノード増やせば 22〜24 ms になり、余裕がほとんど無くなる。そこで **3 + 3** を使う（入力・SIGReg・Compare を足して 9 ノード）
- 実時間（`mujou.run`）では回せない: 3 + 3 を 4090 で 20 秒回すと、フレームの 47% で予測が間に合わなかった。9 ノードがそれぞれ 2 ms ごとに CUDA のカーネルを起動し、それが 1 つの GPU の上で直列になるため。段 1〜2 と同じく、手で回す仮想時間（`mujou.testing.run`）で回す。そこでの遅れは上の Gauss-Seidel の列にあたる
- 速さ: 手で回すと、4090 で実時間の約 6 倍かかる（CPU の 1 コアが律速。GPU は空いている）。5 本を同時に回しても 1 本あたりの時間はほぼ変わらないので、4090 に 2 本、4060 に 1 本の割合で並べる

**M9 の設定（`z_norm` なし）は EgoDex で発散した**
- 3 seed とも、$z$ の RMS が 0.34〜0.42 から 25〜40 まで伸び、ストリームの 1.9〜3.7 秒で NaN になった（1 を超えてから 1.3〜3.0 秒）。隣のフレームがほとんど同じなので、バッファに今の $z$ とほぼ同じ標本が溜まり、自分のコピーからの斥力で外へ押し出される。M11 で見立てた機構が、合成動画よりずっと速く起きた
- `z_norm` だけを入れると（学習率 0.01）、3 seed とも 6 分まで発散しなかった（GPU を空けるためにそこで止めた）

## 段 3: EgoDex の学習

**設定**: 3 + 3 ノード、M11 の設定（`z_norm`、開ループ (0.5, 20)、SGD 0.03、$\kappa=0.8$、`stop_target`）。SIGReg のバッファは容量 1023、8 フレームに 1 回入れる（平均約 4.5 分にわたる標本）。ストリームの最初の 30 分（1 周目の約 20 タスク）、seed 0/1/2。実行は `uv run python -m exp.video.stage3 run --variants ...`

- 残差なし（`fix`）で回すと、1 フレーム先の予測すら写すだけに遠く及ばず（`rollout1` 0.7〜0.9、`persist1` は 0.003）、開ループで発散する（`rollout10` 5〜6）。読み出し $W_o$ は、ほぼ恒等の写像を minGRU と線形写像を通して学び直す必要があり、その間は乱数の $W_o$ が毎フレーム雑音を足す
- そこで予測を残差にした（`residual`: $\hat z_k = z_{k-1} + W_o s_k$、$W_o$ はゼロから始める）。最初の予測は「写すだけ」になり、そこから変化を学ぶ

**結果**（最後の評価、seed 0/1/2。`rollout` は評価クリップの、クリップ間の分散で割った値）

| 設定 | 学習 | 実効ランク | $z$ の分散 | `rollout1` | `rollout10` | `persist10` | `mean10` |
| ---- | ---- | ---------- | ---------- | ---------- | ----------- | ----------- | -------- |
| 残差なし | BP | 8.3 / 8.0 / 7.9 | 0.10 / 0.15 / 0.07 | 0.84 / 0.72 / 0.72 | 5.52 / 5.68 / 5.23 | 0.12 / 0.11 / 0.10 | 0.95 / 0.92 / 0.93 |
| **残差** | BP | 11.0 / 7.1 / 8.5 | 0.14 / 0.12 / 0.13 | 0.009 / 0.006 / 0.008 | **0.48 / 0.39 / 0.50** | 0.14 / 0.12 / 0.12 | 0.94 / 0.93 / 0.93 |
| **残差** | PC-ALM | 10.9 / 9.3 / 8.6 | 0.18 / 0.22 / 0.14 | 0.008 / 0.007 / 0.007 | **0.43 / 0.40 / 0.37** | 0.13 / 0.12 / 0.11 | 0.93 / 0.96 / 0.94 |

- EgoDex では、残差の予測で `rollout10` が 1 も定数の予測（0.93）も下回った。PC-ALM（0.37〜0.43）と BP（0.39〜0.50）は同じ水準で、ストリームの上の 1 フレーム先の誤差 `preq` は PC-ALM の方が小さい（0.004〜0.006 に対し BP は 0.015〜0.017）。ただし、写すだけ（`persist10` 0.10〜0.14）にはまだ 3〜4 倍及ばない。動画がゆっくり変わるので、10 フレーム先の最良の答えは「ほとんど変わらない」で、モデルはその変化をまだ大きく見積もりすぎている
- 評価クリップの上では、ランクが 7〜11、クリップ間の分散が 0.07〜0.22 と低い。評価クリップは test の 48 タスク（学習の 24 タスクに無いものが多い）なので、見たことの無い場面を似た $z$ に写している。ストリームの上の表現の広がりとは別の問題として残る

**保持（70 分、2 周、BP の残差、seed 0/1/2）**: タスクが切り替わった直後の 10 秒の `preq` を、その前のブロックの最後の 10 秒の `preq` で割った値（切り替えの跳ね上がり）を、2 周目と 1 周目で比べた（`stage3.retention`、両方の周で測れた 23 タスクの平均）。1 未満なら、戻ってきたタスクは初めてのときより楽に予測できている

| | 1 周目の跳ね上がり | 2 周目の跳ね上がり | 2 周目 / 1 周目 |
| - | ------------------ | ------------------ | --------------- |
| BP の残差 | 1.14 / 1.08 / 1.18 | 1.21 / 1.15 / 1.21 | 1.13 / 1.14 / 1.13 |

- 2 周目の方が跳ね上がりが大きい。約 35 分前に見たタスクの分は残っておらず、むしろ戻るほうが切り替えに弱い。SGD の継続学習で、直前のタスクに合わせて上書きされている。忘却を減らす手立て（M8 の射影や replay）は段 3 ではまだ試していない
- 70 分の時点の `rollout10` は 0.55 / 0.57 / 0.51 で、30 分の時点（0.48 / 0.39 / 0.50）からよくなっていない
- PC-ALM の 70 分（1 本 7 時間超）は回していない
