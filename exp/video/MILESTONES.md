## 進め方

- 1 マイルストーン 1 PR。ブランチは `exp/<日付>/continuous-stream-<マイルストーン>`（例: `exp/2026-11-02/continuous-stream-m1-optim`）
- 部品は「理論から導いたオラクル」のテストで検証する。「損失が下がった」は完了の条件にしない
- 実験は、回す前に判定基準を README に書き、回した後に結果の数字を README に書く
- 完了の条件はどれも `just run` が通ることを含む（下では省く）
- 時間のかかるテスト（数十秒以上）には `@pytest.mark.slow` を付ける。反復中は `just test-fast`
- テストは `tests/` にミラーし、モジュールと 1 対 1 にする（`exp/lib/optim.py` ↔ `tests/lib/test_optim.py` など）

## M13: 合成動画を簡単にして、正確に予測できる土台を作る

**状態**: 未達のまま中断（2026-11-02）。ユーザーの判断で M14 に移った。数字は [results/m13.md](results/m13.md)

**ねらい**: 動きを当てられない段階で実動画へ進んでも、何が足りないのかを切り分けられない。そこで合成動画を簡単にし、10 フレーム先を画像で正確に当てる設定を作る。

**データ**（`easy.EASY`）: 引き直しなし（1 本のストリームが最後まで連続）、$e=1$、抵抗 0、一定の重力 $\gamma_0=1$、エネルギーを保つ跳ね返り（`conserve`）。B=128 本のストリームをそれぞれ別の初期状態から始める。

**完了の条件**（当時）: 30 分、PC-ALM と BP、seed 0/1/2 で、発散しない、再構成誤差 0.001 以下、デコードした予測の画素誤差が 5・10 フレーム先で平均の画像の 0.5 倍未満、潜在で `rollout{n}` < `shrink{n}`、見た目で玉が正しく動き跳ね返る。

**分かったこと**

- モデルの大きさは効く（幅 64、$d_s$ 512、動力学 3 ノード）。小さいモデルは $z$ が情報を保っても 10 フレーム先を当てられない
- 予測誤差が目標 $z$ に credit を送ると（$w=1$）、エンコーダは当てにくい小さい玉を捨てる。再構成の項（`ModelConfig.recon`、`nodes.Reconstruct`）で $z$ は玉を保つが、玉 3 つのオフラインの上限は 10 フレーム先 0.59 倍にとどまる（小さい玉の予測が消える）
- 玉 1 つ（`DataConfig.radii`）ではオフラインの上限が 0.24・0.43 倍で、見た目も合う
- オンラインの律速の 1 つは時間の局所性。minGRU の適格度トレース（`ModelConfig.trace`、RTRL、局所性を保つ）で、玉 1 つの BP が 0.69・1.17 倍 → 0.49・0.92 倍になった
- 残りの律速は optimizer。オフラインでも SGD は Adam より遅い。オンラインの AdamW は最初は速いが後でランクが上がって悪くなる。Adam の向きに SGD の大きさを掛ける grafting も 0.61・0.89 倍で、SGD を超えない
- 表現の問題と、動力学をオンラインで学ぶ問題が絡み合い、切り分けられなかった（→ M14）

## これからの流れ（2026-11-02、ユーザー）

M13 で、視覚のエンコーダの潜在空間で予測誤差をとって同時に学ぶと、潜在空間が予測しやすいように学んでしまう問題があった（当てにくい玉を捨てる、予測しやすい方向に折り畳む）。そこで、動力学と視覚を分けて 1 つずつ確かめ、最後に合わせる。

```text
M14 動力学だけ（観測の上の誤差） ──┐
                                   ├─▶ M16 視覚と動力学の同時の学習
M15 画像・動画の JEPA（視覚だけ） ──┘
```

M14 と M15 は互いに独立で、並べて進められる。

**どれにも共通: 見た目で確かめる**（[memory の方針](../../memory/feedback_metrics_need_qualitative_check.md)）

- 予測と表現は、画像に戻して見て確かめる。数値の条件は、見た目と合うことを確かめてから使う
- エンコーダがある実験（M15・M16）では、各チェックポイントに軽量のデコーダを後から学び（`decode.py` と同じ。エンコーダは止めたまま）、それで $z$ と、動力学が予測した $z$ を画像に戻す
- デコーダはデバッグの道具で、システムには入れない。mujou の実行の中では学ばない（M13 の再構成のノード `nodes.Reconstruct` は使わない）
- 動力学とエンコーダを同時に学ぶ run（M16 から）では、夢も必ず見る（2026-11-11、ユーザー）。夢は、観測なしで動力学を 150 フレーム（5 秒）先まで開ループで回し、デコーダで画像に戻したもの。観測は学習と同じ 16 フレームと、最後の 1 フレームだけの 2 通り。後から学ぶデコーダ（posthoc）が各チェックポイントで計算する（`measure.joint.dream`）。報告書の動画は PC-ALM だけでよい

## M14: 合成データで動力学だけを学ぶ

**状態**: 完了（2026-11-04、[results/m14.md](results/m14.md)）。段 1・2 は PC-ALM と BP の 3 seed で条件を満たした。段 3（画素を観測に）は届かず、エンコーダを持つ M15・M16 に回した

**なぜ**: M13 では、画像のエンコーダと潜在空間の予測誤差のために、2 つの問題が絡み合っていた。1 つは表現の問題（$w=1$ のエンコーダが当てにくい玉を捨てる、潜在の二乗誤差が小さい玉の方向に重みを置かない）。もう 1 つは動力学をオンラインで学ぶ問題（時間の局所性、optimizer の標本効率）。誤差を潜在空間ではなく観測の上でとる問題に直し、動力学そのものの学習がうまくいくかを確かめる。ここで通らなければ、画像に戻っても通らない。

**データ**: M13 の物理（`easy.EASY`: $e=1$、抵抗 0、一定の重力、`conserve`、引き直しなし、B=128 のストリーム）。画像は作らず、毎フレームの玉の状態（`Frame.state`）から観測を作る。

| 段 | 観測 | ねらい |
| -- | ---- | ------ |
| 0 | 玉 1 つの位置と速度 $(x, y, v_x, v_y)$ | マルコフなので記憶は要らない。学習の仕組みの確認 |
| 1 | 玉 1 つの位置 $(x, y)$ だけ | 速度は見えないので、$s$ に履歴から推して持つ必要がある（画像と同じ状況） |
| 2 | 玉 3 つの位置 | M13 の本来のデータ。玉どうしは衝突しないので、玉ごとの動力学の重ね合わせ |
| 3 | 玉の画像（32×32） | 観測を画像にし、誤差も画素の上でとる（潜在空間の誤差は使わない）。組み方と条件は段 2 が通ってから決める |

観測は、評価クリップの平均と標準偏差で各次元を標準化する（位置は箱の中で $[0, 1]$、速度は約 0.03/フレームと尺度が違うため）。

**モデル**: `Input`（観測）→ `Dynamics`（minGRU、$d_s$ と動力学のノードの数は M13 の大と小）→ `Compare`（読み出し $W_o$ で次のフレームの観測を予測）。エンコーダ、SIGReg、`z_norm`、再構成の項は使わない。予測誤差の目標は観測そのものなので、目標へ送る credit はない。適格度トレース（`ModelConfig.trace`）は使う（あり・なしも比べる）。学習は PC-ALM と BP（`WorldBP`）。

**物差し**（評価クリップ。16 フレームを観測し、そこから開ループで $n$ フレーム先まで予測する。観測の空間での 1 次元あたりの二乗誤差）

- 平均（評価クリップの平均の観測）、写し（最後の観測）
- 等速の外挿: 最後の 2 フレームの位置の差を速度として、重力も壁も入れずに進める。これを下回れば、重力と跳ね返りを学んでいる
- 真の物理は誤差 0（上限の確認にだけ使う）

**作るもの**（名前と置き場所は実装のときに決める。`exp/video/` の中に置き、`balls.py`・`nodes.py`・`bp.py`・ホストのループを使い回す）

- 状態から観測を作るストリーム（段 0〜2 を設定から選ぶ）と、観測の評価クリップ
- エンコーダのない `Network` と `WorldBP` の組み方
- 観測の空間での rollout の評価と、上の 3 つの物差し
- オフラインの上限（窓、Adam、BPTT）。M13 の `offline.py` と同じ窓の作り方
- 見た目の確認: 予測した状態を `balls.render` で画像に描き、真のフレームと並べる。予測した軌跡と真の軌跡を重ねた図も描く（観測が状態なのでデコーダは要らない）

**オラクル**

| テスト | 理論から言えること |
| ------ | ------------------ |
| 観測 | 段 0 の観測を標準化から戻すと `Frame.state` と一致する。段 1・2 は位置の列だけ |
| 等速の外挿 | 重力 0 で壁に当たらない区間では誤差 0 |
| エンコーダなしの平衡点 | 1 フレームを長く見せ、学習を止めると、各ノードの `lam` が BP 版の同じフレームの credit と一致する（M5 と同じ） |
| トレース | 重みを止めたときの勾配が、入力を固定した BP through time と一致する（M13 のテストを使い回す） |

**手順**

1. 物差しを測る（段 0〜2）
2. オフラインの上限を段 0〜2 で測る。通らない段はオンラインの前に原因を切り分ける
3. オンライン: 段 0 → 1 → 2 の順に、30 分、BP で探索してから、PC-ALM と BP、seed 0/1/2
4. 段 1・2 が通ったら、段 3（画像）の組み方と完了の条件を決めて回す（2026-11-02、ユーザー: 状態の後に画像へ）

**完了の条件**（閾値は手順 1 の物差しを見て確定し、回す前に README に書く）

段 1 と段 2 で、30 分、PC-ALM と BP、seed 0/1/2 のすべてで次を満たす。

- 発散しない
- 5 フレーム先と 10 フレーム先の予測誤差が、平均・写し・等速の外挿のどれよりも十分に小さい（目安: 等速の外挿の 0.5 倍未満）。20 フレーム先も記録する
- 予測した軌跡を見て、玉が正しい向きへ動き、壁で跳ね返っている
- 変えたところが mujou の原則（局所性・非同期性）を崩さない

オフラインの上限とオンラインの差、適格度トレースと optimizer が効いたかも README に書く。

**通った後**: 学んだ動力学の設定を M16 に持ち込む。物理の難しさ（重力の時間変化、反発係数、抵抗）を戻すかは、そのときに決める。

## M15: 画像・動画の JEPA

**状態**: 完了（2026-11-04、[results/m15.md](results/m15.md)）。JEPA に spatial broadcast decoder による最後のフレームの再構成を足した設定で、玉の位置が $z$ から線形に読めた（PC-ALM と BP の 3 seed で `probe_pos_min` 0.957〜0.979）

**ねらい**: 生の画像・動画を潜在空間へ圧縮するエンコーダを、JEPA をもとに視覚だけの損失で学ぶ。動力学の予測誤差は使わない。

**方針**（ユーザー、2026-11-02）

- V-JEPA をもとに、動画を $N$ フレームのまとまりで扱う（$N=1$ が画像）。画像と動画を 1 つの形で扱えるため
- 崩壊の防止に SIGReg を使う（LeJEPA）。エンコーダは Transformer（ViT）になる見込み
- 動画のデータは EgoDex を使わない（レポートにフレームを直接載せられない）
- 実動画は [Walking Tours](https://huggingface.co/datasets/shawshankvkt/Walking_Tours)（DoRA、ICLR 2024）に決めた（2026-11-02、ユーザー）。CC BY 4.0 で、レポートに出典を書けばフレームを載せられる。一人称の街歩きの動画が 10 本と野生動物の 1 本（1〜3 時間、4K・60 fps）で、1 本の長い連続したストリームとしてそのまま流せる。動画は YouTube から取る（一覧は `WTour.txt`）。取るときに、動画ごとのライセンスと、顔とナンバーのぼかしの有無を確かめる。動きはカメラの移動が主で、物を扱う動きは少ない
- この研究は非商用（2026-11-02、ユーザー）なので、CC BY-NC のデータも使える。物を扱う動きが要るときの候補は EPIC-KITCHENS-100（CC BY-NC 4.0、一人称の台所の作業）

**読むもの**: [I-JEPA](https://arxiv.org/html/2301.08243v3)、[V-JEPA](https://arxiv.org/html/2404.08471v1)、[V-JEPA 2](https://arxiv.org/html/2506.09985v1)、[LeJEPA](https://arxiv.org/html/2511.08544v3)

**着手のときに決めること**

- マスクの作り方と予測器（I-JEPA・V-JEPA のブロックのマスク）、ターゲットのエンコーダ（EMA か、LeJEPA のように SIGReg だけで EMA と stop-gradient を外すか）
- ストリームへの載せ方: 1 フレームずつ届くストリームで $N$ フレームのまとまりをどう作るか。ノードの分け方（エンコーダ、予測器、SIGReg）と局所性
- データ: 合成動画（玉）から始めるか、最初から Walking Tours か。解像度とフレームの間引き（4K・60 fps から）
- 判定の基準: 各チェックポイントに学んだデコーダでの再構成の見た目。合成動画なら玉の状態への線形の probe、実効ランク

## M17: Walking Tours でエンコーダを詰める

**状態**: 実施中（2026-11-11〜）

**なぜ**（ユーザー、2026-11-11）: M15 で JEPA に再構成の項（$\mu L^{\mathrm{rec}}$）を足して玉の位置を読めるようにしたのは、玉の画像が単純すぎたためとみる。本来の JEPA は再構成の誤差で学ばない。現実的な動画の Walking Tours で、再構成の項なしの JEPA（V-JEPA・V-JEPA 2 + SIGReg）でエンコーダを詰める。

**ねらい**: PC-ALM で学ぶ、一番よいエンコーダの設定を見つける。よいエンコーダの条件は次の 2 つで、どちらも小さいことを求める。

| 指標 | 小さいと言えること |
| ---- | ------------------ |
| 特徴量からの再構成の誤差 | 画像の重要な特徴を捉えている |
| 特徴量の上の線形の動力学の予測誤差 | 線形に扱いやすい、よい特徴量になっている |

片方だけが小さいときは、うまく disentangle できていないか、潜在空間が崩壊している可能性がある。ゆっくり変わる成分（場面の明るさなど）だけを持つ $z$ は線形に当てやすいが、画像を描き戻せない。画像を描き戻せても、非線形に絡み合った符号では線形の動力学で当てられない。

**学ぶものと評価で学ぶもの**

- PC-ALM で学ぶのはエンコーダだけ（JEPA の予測器は、エンコーダの損失を作る部品として一緒に学ぶ）。損失は JEPA の予測誤差と SIGReg だけで、再構成の項（`vision.recon`）は 0 に固定する
- デコーダと線形の動力学は、評価のときに各チェックポイントで、エンコーダを止めて学ぶ（`task=posthoc`）。システムにも mujou の実行にも入れない（[memory の方針](../../memory/project_decoder_for_debug.md)）
- 対照として、同じネットワークを BP で学ぶ版（`JEPABP`）も回す（M15 と同じ）

**制約**（ユーザー、2026-11-11）

- 入力の画像は 128×128×3（49152 次元）
- 特徴量 $z$ は pool した 1 本のベクトルで、次元 $D \le 1024$（入力の約 2%）、主に $D = 256$。トークンを並べたものは特徴量にしない

**データ**

- 元の動画は 854×480（Wildlife は 640×360）、30 fps（`data/walking_tours/manifest.json`）。中央の正方形を 128×128 に縮め、30 fps のまま新しい data_version を作る。10 本で約 14.4 時間、約 156 万フレーム、u8 で約 76 GB。NAS に置き、各ホストのローカルにコピーする
- split は M15 と同じ。Zurich を評価だけに使い（calib・val・test）、残りの 9 本で学ぶ。posthoc のデコーダと動力学も、学ぶ 9 本から取ったフレームで学び、Zurich で測る
- ストリームは 30 fps で進み（B=128、時定数は 16.7 更新/フレームのまま）、学ぶのは 3 フレームに 1 回（10 fps）
- エンコーダの入力は、間隔 $\Delta$ で $N$ 枚を積んだ $x_t = (f_{t-(N-1)\Delta}, \dots, f_t)$。既定は $\Delta = 0.1$ 秒（3 フレーム、学ぶ時刻ごとの画像をそのまま積む）、$N = 16$（1.5 秒）。V-JEPA の 30 fps から 4 フレームおきに 16 枚とほぼ同じ形。1 秒おきでは変化が大きすぎる（ユーザー）

**エンコーダ**

- ViT。patch は 16×16、tubelet は $\tau = 2$（V-JEPA・V-JEPA 2 と同じ）。tubelet は同じ位置の patch を $\tau$ 枚束ねて 1 つのトークンにする単位で、$N=16$ では時間 8 × 空間 64 = 512 トークン（M15 の Walking Tours $N=8$ と同じ数）。今の M15 の実装は $\tau = N$
- $z$ は target view の全トークンの pool。幅と $D$ を別に選べるよう、必要なら pool の後に線形の射影を置く
- マスク: 空間のブロック $m_1, \dots, m_k$ の和集合を、全フレームの同じ位置に掛ける（tube、M15 の `block_masks`）。隠した位置のすべてのトークンの潜在を、見えるトークンから予測器で当てる。比率は 0.5〜0.9 を探索する（V-JEPA は 9 割前後を隠す）。V-JEPA の短い範囲と長い範囲の 2 種類のブロックも候補にする
- V-JEPA 2 の変更（3D-RoPE の位置の符号など）は、着手のときに原文で確かめ、採るものを results に書く
- 崩壊の防止は SIGReg（LeJEPA）。EMA のターゲットは使わない。かける先（`z`・`tokens`・`both`）、重み、sg は探索で選ぶ
- $N=1$（画像、$\tau=1$）と $N=8$（0.7 秒、256 トークン）を対照に回す

**評価**（posthoc、各チェックポイント、Zurich の val・test）

1. **再構成**: $z_t$ から最後のフレーム $f_t$（128×128×3）を戻すデコーダ。構造と学ぶステップ数・データはどの run でも同じにする。指標は画素の二乗誤差を平均の画像の誤差で割ったもの `recon`（1 が平均の画像）
2. **予測器を通した復元**（ユーザー、2026-11-11）: マスクした context view をエンコーダと予測器に通し、見えるトークンと予測したトークンから画像を描き戻す。誤差（隠した領域と画像全体）と復元した画像を結果に載せる。描き戻しは target view のトークンから画素を戻す、後から学ぶトークンのデコーダで行う
3. **線形の動力学**: $\hat z_{k+1} = A z_k + b$。1 ステップは $\Delta$（0.1 秒）。学ぶ 9 本の $z$ の列から最小二乗（ridge）で閉じた形で解く。1・5・10 ステップ先（0.1・0.5・1 秒先）まで $A$ を繰り返して回し、次を測る
   - `dyn_h`: 予測誤差を目標の $z$ の分散で割ったもの（$1 - R^2$）。$z$ の尺度を縮めても小さくならない
   - `dyn_h/copy_h`: 写し（$\hat z_{k+h} = z_k$）の誤差との比。ゆっくり変わる成分だけでは 1 を下回らない
4. **見た目**（[memory の方針](../../memory/feedback_metrics_need_qualitative_check.md)）: 再構成の画像と、動力学が予測した $\hat z_{k+h}$ をデコーダで戻した画像を、真のフレームと並べる。予測を戻した画像の画素の誤差（平均の画像と、写したフレームとの比）もあわせて書く
5. **崩壊の監視**: 実効ランク、`z_std_min`、`z_spread`（1e-3 未満は崩壊）

**物差し**（`baselines.json`、同じ評価をそのまま通す）: 画素の PCA で $D$ 次元にした符号（線形で学習の要らない符号。再構成と線形の動力学の両方の基準）、学習前の同じ ViT、平均の画像（`recon` = 1）、写し（`dyn_h/copy_h` = 1）

**選び方**: 探索の目的は、2 つの誤差を PCA の値で割った比の大きい方 $\max(\mathrm{recon}/\mathrm{recon}_{\mathrm{PCA}},\ \mathrm{dyn}_1/\mathrm{dyn}_{1,\mathrm{PCA}})$（悪い方を下げる）。2 つの誤差の散布図（Pareto の前線）も結果に載せる。

実装での変更（2026-11-12、レビューを受けて）: 目的は $J = \log \max(\mathrm{recon}/\mathrm{recon}_{\mathrm{PCA}},\ r_1/r_{1,\mathrm{PCA}})$、$r_1$ = `dyn_1/copy_1` とし、上限と崩壊・非有限の罰は $\log 10$（発散した seed と同じ）。ViT は $N$ 枚の積みを符号にし、隣り合う積みは $N-1$ 枚を共有するので、`dyn_1` は学習しなくても PCA（最後の 1 枚）より小さく出る（学習前の ViT で 1/23）。写しの誤差で割るとこの重なりが打ち消される。比のまま $\log 10$ で上限を切ると、比 2.3 を超える trial がすべて同点になっていた。理由と数字は [results/m17.md](results/m17.md)

**探索する軸**（BP の study、seed 100/101、val）: $N$（8・16）、$\Delta$（0.067・0.1・0.2 秒）、$D$ と ViT の幅、マスクの比率とブロック、SIGReg のかけ先と重み、sg、学習率

**手順**（std-00〜03 の 4 台、fleet）

**完了の条件**（閾値は手順 3 の物差しを見て確定し、回す前に results に書く）

- 発散しない、崩壊しない（`z_spread` ≥ 1e-3）
