承認された案（[../../project_jepa_plan.md](../../project_jepa_plan.md) の末尾、方針は [../../feedback_eval_matches_objective.md](../../feedback_eval_matches_objective.md)）を、実装できる形に詰めた。コードは書いていない。読んだのは `exp/vision/README.md` の V18c の各節、`plans/jepa.md` の V18c の節、`jepa.py`・`jepa_eval.py`・`fill_eval.py`・`gen_eval.py`、`exp/lib/regions.py`・`metrics.py`・`readout.py`、[main-metric-v2.md](main-metric-v2.md)・[main-metric-v3.md](main-metric-v3.md) と Codex さんの 2 つの批判である。

確かさは 3 段階に分ける。**既存の数値**（README と `runs/` にある値）、**導いた**（定義から論理で出した。数値では確かめていない）、**推測**（実データでの予想、計算時間）。

## 0. 要点

1. **測る量は 3 つに分ける。** (a) 自然な候補での同定（予測 $\hat t_U$ が本物 $t_U$ を他のフレームの同じ位置の候補から当てる）、(b) 対照との差（`pool`・`flat`・`interp`）と `swap`、(c) **移植した候補での同定**と局所性。(c) が今回の新しい部分で、承認された「局所性の確かめ」を同定の中に組み込んだものである
2. **逃げ道「エンコーダが周りの情報を隠した所のトークンに詰める」は、(a)(b) では原理的に捕まらない**（導いた。8 節の「鏡の符号」は (a) が 1、`swap` が 1、`pool` との差も正になる）。塞ぐのは (c) だけである。候補を「中立な文脈のフレーム $j$ に、候補 $m$ の領域 $Q$ の画素だけを移植した画像」の $Q$ のトークンにすると、$Q$ のトークンが $Q$ の画素を反映しない符号では候補がすべて同じ値になり、同定は引き分け（`top1` = 0、勝率 0.5）に厳密に落ちる
3. **読み出しを当てはめない。外部の特徴もラベルも使わない。** 当てはめるものは位置ごとの平均（中心化）だけ。$\alpha$ も、当てはめの組も、白色化も無い
4. **合否に使う確かめは、恒等式と閉じた式だけにする**（定数、位置だけの符号、合成の複製 K3、局所な符号、鏡の符号、雑音を足した本物の勝率の式、隠した画素への非依存）。学習前・ランダムな予測器・M・`shuf` のような「実物の対照」は期待値が厳密に決まらないので、記述にとどめる。旧 E1 が V-E1（`shuf`）と V-E3（M）で外れたのは、この区別をしなかったためである
5. **採点は 2 つ並べる。** `top1`（最近傍が自分。偶然 $1/c$）と、対の勝率 $A$（自分との類似度が各候補より大きい割合。偶然 0.5）。$A$ は候補の数によらず、hub に鈍く、合成の対照で値が閉じた式になる。1 回目の失敗（`top1` の目盛りが 0.002〜0.024）への備えである
6. パッチ 16・8・4 は、粗い 4×4 のマスの単位でそろえる。1 マスのベクトルは P16・F・V18c とも 64 次元（M は 1024 次元）になる。評価のコードは `JEPAModules.tokens` と `jepa.predict` だけを通るので、旧 checkpoint と V18c で同じである
7. V19 からの主の指標の候補として推すのは、**移植した難しい候補での $A$ の、`pred` と `flat` の差**（と `pred` そのものの 0.5 との差）である。ただし、これは「自分の空間の中での補完」を測る量で、空間が何を持つか（情報の量）は測らない。崩壊の検出（K1〜K3）と必ず並べて読む（13 節）

## 1. 記号と、パッチ・空間のそろえ方

- stack $x_n$。全体を見たエンコーダと射影のトークン $t_{n,p} = P f(x_n)_p \in \mathbb{R}^d$（`JEPAModules.tokens`。V18・V18b は学習した $P$、V18c は固定の $R$）。マスク $U$ のもとの予測 $\hat t_{n,p}$（$p \in U$、`jepa.predict`）。文脈の側のトークン $c_{n,q} = P f(x_n; V)_q$（$q \in V$、見える位置だけを通したエンコーダの出力に同じ射影をかけたもの）
- **そろえる単位は粗い 4×4 のマス**（`regions.COARSE`）。1 マスは $s \times s$ 個の細かい位置（$s$ = 1・2・4）で、マスのベクトルは $s^2 d$ 次元。P16（1×64）、V18c（4×16）、F（16×4）はどれも 64 次元、M（16×64）は 1024 次元（導いた。画素あたりの圧縮率を 96 分の 1 にそろえた設計の帰結）
- 採点する領域は四半分 $Q_q$（2×2 マス、$q$ ∈ tl・tr・bl・br）。領域のベクトル $v_{n}$ は、$Q_q$ の細かい位置を番号順に並べた $4 s^2 d$ 次元（256。M は 4096）
- 予測器が当てる空間をそのまま使う。射影の前の $h$ や $z = W \mathrm{vec}(t)$ には写さない。理由: 損失 $L_{\mathrm{pred}}$ が定義されているのはこの空間で、別の空間へ写すと、予測器が学んでいない量を採点することになる
- **中心化**: 本物は位置と座標ごとに格子（Zurich の 3899 個）の平均を引く（$r_{n} = v_n - \bar v$）。予測は段ごとに、問い合わせの組の上の自分の平均を引く（$e_n = \hat v_n - \overline{\hat v}$）。別々に引く理由: 定数のずれは「どのフレームか」の情報を持たず、ずれが残ると全問い合わせが同じ候補へ寄る（G の `pick_max` 0.08〜0.11 の原因。既存の数値）。平行移動より先の補正（線形の当てはめ直し）はしない

## 2. 隠すマスク

`fill_eval.e1f_masks()` の 12 個をそのまま使う。四半分 $Q_q$ を常に隠し、$k$ = 4（$Q_q$）、8（$Q_q$ の行の半分 `H_t` か `H_b`）、12（行の半分と列の半分の和。対角の四半分だけが見える）。採点はいつも $Q_q$ の位置だけ。

- どれも学習の族 $F_k$ に入る（導いた。$Q$ は長方形 1 個、半分は長方形 1 個、L 字は長方形 2 個の和で 8 + 8 − 4 = 12 マス）
- 採点する領域と次元が $k$ によらないので、$k$ をまたいで比べられる。run の学習の $k$ と同じ行を「分布の中」（`in_dist`）とし、長い run（$r$ = 0.5）は $k$ = 8 を主に読む。旧 checkpoint は $r$ = 0.25 が $k$ = 4、0.75 が $k$ = 12
- `swap` 用に `S_1`・`S_2`（対角の 2 つの四半分、$k$ = 8、$F_8$ に入る）。$r$ = 0.5 の run でだけ分布の中
- `H_l`・`H_r`・`R` は足さない（採点する領域が変わり、$k$ をまたぐ比べが崩れる。部品の再利用も減る）

## 3. 候補

`gen_eval.candidates` と `hard_sets` をそのまま使う（定数も既存の `FillConf` のまま）。

| 名前 | 問い合わせ | 候補 | 偶然（`top1` / $A$） |
| -- | -- | -- | -- |
| 易しい | 格子から等間隔の 512 個（7〜8 秒おき） | その 512 個 | 1/512 / 0.5 |
| 難しい | 同じ 512 個のうち両端を除く約 503 個 | 自分と、同じ動画の前後 ±2〜±32 秒（2 秒おき）の格子の 32 個 | 1/33 / 0.5 |

- 最も近い候補は 2 秒離れている。stack の幅は 0.8 秒なので画素は重ならない。`shift_top1` の誤り（問い合わせ自身が候補に入る）の形にはならない。問い合わせと正解は同じ stack の「予測」と「本物」で、正解のほかに 1 秒以内の候補は無い
- **時間の相関**: 難しい候補は場面・天気・照明を共有する。ゆっくり変わる成分だけを持つ予測でも、自己相関が 2 秒で落ちていれば自分を当てうる（導いた。遅れ 0 が最も近いので）。だから「難しい候補で偶然を超える」ことを、位置ごとの補完の証拠にはしない。受け持つのは 5 節の対照との差である
- **偶然の値が厳密に成り立つ条件**（導いた）: 予測が全問い合わせで同じなら、中心化の後は零ベクトルで、すべて引き分けになり `top1` = 0、$A$ = 0.5（引き分けは 1/2）。予測が的と独立で符号について対称なら、$A$ の期待値は 0.5、`top1` の期待値は $1/c$。それ以外の「情報の無い予測」（別のフレームの予測など）は、1 本の非定常な動画では偶然の値を保証しない（Codex さんの反例と H-time。既存の数値: `shuf` の勝率 0.455〜0.476）
- 遅れごとの記述（追加の計算なし）: 難しい候補の類似度の行列から、遅れ別の平均の類似度と、外したときに選んだ候補の遅れの分布を出す。合否には使わない
- V18c では設定を選ばないので、格子全体を使う。V19 で設定を選ぶのに使うなら、`zurich_split` の sel で選び final で読む

## 4. 比べ方

- **類似度は中心化した cos**: $s(n, m) = \langle e_n, r_m \rangle / \lVert r_m \rVert$（$e_n$ の長さは順位に効かない）。`metrics.identification` に、中心化を済ませたベクトルと `center` = 0 を渡せば足りる
- cos にする理由（導いた）: (1) 二乗誤差を最小にする予測は条件つき平均で、本物より短い。どれだけ縮むかは当てやすさで決まり、「どのフレームか」とは別の量である。cos は縮みに不変。(2) 距離 $\lVert e_n - r_m \rVert^2 = \lVert e_n \rVert^2 - 2\langle e_n, r_m \rangle + \lVert r_m \rVert^2$ は、短い候補（平均に近いフレーム）を全問い合わせで有利にし、hub を作る。(3) 表現の全体の尺度は $\lambda$・学習率・腕で変わるが、cos はそれに不変
- 距離の版（`l2`: 自分との二乗誤差が候補の中で最小か。損失と同じ計量）は副として並べる。cos と距離で順序が食い違えば、そう書く
- **白色化はしない**。256 次元の共分散を数千個で推定して逆をかけると、分散の小さい方向の雑音を拡大する（2 回目の失敗の「下位の成分が全体を決める」と同じ形）
- **hub の補正はしない**。CSLS などは近傍の統計で判定則を変える手直しで、ここでの導出が無い。代わりに (1) 予測と本物を別々に中心化する、(2) cos で候補の長さをそろえる、(3) `pick_max` を `oracle` のものと並べて記録する、(4) hub に鈍い $A$ を並べる
- **対の勝率 $A$**: $A_n = \frac{1}{c - 1} \sum_{m \ne n} \left( [s(n,n) > s(n,m)] + \tfrac12 [s(n,n) = s(n,m)] \right)$、$A$ はその平均。`metrics.py` に足す部品はこれ 1 つ

## 5. 段（予測の代わりに入れるもの）

どの段も、採点する $Q_q$ の位置のベクトルを作り、自分の平均で中心化して、同じ候補と比べる。`pred`・`pool`・`flat`・`interp` は**見える画素だけの関数**である。

| 段 | 定義 | 役目 |
| -- | -- | -- |
| `pred` | 予測器の出力 $\hat t_{n,p}$（$p \in Q_q$） | 測りたいもの |
| `pool` | 文脈の側のトークンの平均 $\bar c_n = \frac{1}{\lvert V \rvert} \sum_{q \in V} c_{n,q}$ を、$Q_q$ のすべての位置に置く | 承認された定義。「見える部分の平均を写すだけ」の基準 |
| `flat` | `pred` の中心化したベクトルを、$Q_q$ の位置の平均で置き換える（`fill_eval` の `pred_k3` と同じ操作） | 予測から「領域の中の位置ごとの違い」だけを消した基準 |
| `interp` | 隠した $U$ の画素を見える画素から調和補間（`regions.harmonic_fill`）した stack を、全体を見たエンコーダに通した $Q_q$ のトークン | 学習の要らない滑らかな延長の基準。画素は入力の介入にだけ使う |
| `oracle` | 本物そのもの | 天井（`top1` = 1） |
| `const` | 全問い合わせで同じ値 | 床（`top1` = 0、$A$ = 0.5、全部が引き分け） |

**K3 の族での値**（導いた）

- 複製の K3（$t_{n,p} = u_n + g_p$、予測も $\hat t_{n,p} = \hat u_n + \hat g_p$）: 中心化の後、`pred` の各位置は $\hat u_n - \overline{\hat u}$ で同じ。`flat` はその平均なので **`pred` と同じベクトル**になり、候補が何であっても `top1` も $A$ も一致する。予測器の良し悪しによらない
- `pool` は、文脈の側も同じ $u_n$ を返す複製の K3 では $\bar c_n = u_n + \bar g_V$ で、中心化の後は `oracle` と同じになる。完全な予測器なら `pred` と同じ値、そうでなければ `pred` ≤ `pool`。つまり複製の K3 では `pred` − `pool` ≤ 0
- 一般の族 $t_p = A_p u$（$A_p \ne I$）では、当てはめ直さない直接の比べなので、`flat` も `pool` も `pred` と一致しない。この族を受け持つのは局所性（7 節の $L \approx 0$）と既存の `token_r2` である。`e1f` のように当てはめ直せば族全体で一致させられるが、当てはめの組・$\alpha$・過学習を持ち込むので採らない（2 回目の失敗の原因の 1 つ）

**2 つの差の意味**

- `pred` − `pool`: 場面の平均を写す以上のことをしているか。負にもなりうる（予測器が平均の複製に負ける）
- `pred` − `flat`: 予測の、四半分の中の位置ごとの違いが、本物の位置ごとの違いと合っているか。`flat` は `pred` から情報を消して作るので、差はふつう 0 以上。四半分の平均の中身は `flat` にも残るので、これは高い基準である（四半分の中の配置まで要求する）

## 6. `swap`

`S_1`・`S_2` で対角の 2 つの四半分 $A$・$B$ を同時に隠す。$e_A$・$e_B$ はそれぞれの位置の予測を中心化したもの（`fill_eval._deviation` と同じく、先に 1 行目を引いてから平均を引き、等しい行が厳密に 0 になるようにする）、$r_A$ は $A$ の本物を中心化したもの。$\langle e_A - e_B, r_A \rangle > 0$ なら 1、等しければ 1/2（`metrics.swap` をそのまま）。$(A, B)$・$(B, A)$ と 2 組の平均。

- 複製の K3 では $e_A = e_B$ がビットまで等しく、ちょうど 0.5、引き分けの数は候補の数（導いた）
- 読み出しを通さないので、旧 `swap` の「$A$ の読み出しに $B$ の入力を通す」分布のずれが無い
- $A_B = -A_A$ の族では 0.5 にならない（Codex さんの例は直接の比べでも成り立つ）。族全体の対照ではない

## 7. 局所性と、移植した候補

**介入**: 中立な文脈の stack $j$ の、四半分 $Q_q$ の画素だけ（stack の全フレーム。early fusion の管）を、Zurich の格子の stack $m$ のものに入れ替えた画像 $x_{j \leftarrow m}$ を作り、全体を見たエンコーダに通す。

- $j$ は Zurich でない学習の動画から 4 個（当てはめの組の stack を、動画が互いに違うように固定の番号で選ぶ）。Zurich の中から選ぶと、近い問い合わせで中立でなくなる
- 入れ替えの境界は粗いマスの境界で、パッチ 16・8・4 のどれでもパッチの境界に重なる。**どのパッチも中身は自然な画像のまま**で、不自然なのはパッチどうしの組み合わせだけである（導いた）
- 入れ替えるのは採点する $Q_q$ だけにする。$U$ の残りまで $m$ のものにすると、$m$ の文脈が候補に入る。したがって移植はマスクの $k$ によらず、四半分 4 つ × 文脈 4 つ × 格子の 1 回ずつで済む

**局所性の量**（移植の副産物。追加の計算なし）: $\Delta_p = t_p(x_{j \leftarrow m}) - t_p(x_j)$、$\delta_p = t_p(x_m) - t_p(x_j)$ として

$$a_U = \frac{\sum_{p \in Q} \langle \Delta_p, \delta_p \rangle}{\sum_{p \in Q} \lVert \delta_p \rVert^2}, \qquad a_V = \frac{\sum_{p \notin Q} \langle \Delta_p, \delta_p \rangle}{\sum_{p \notin Q} \lVert \delta_p \rVert^2}, \qquad L = a_U - a_V$$

と、動いた大きさ $\rho_V = \sum_{p \notin Q} \lVert \Delta_p \rVert^2 / \sum_{p \notin Q} \lVert \delta_p \rVert^2$。$m$ と $j$ について平均する。

| 符号 | $a_U$ | $a_V$ | $L$ |
| -- | -- | -- | -- |
| 局所な符号（各トークンが自分のパッチの画素だけの関数） | 1 | 0 | 1（厳密） |
| 複製の K3（$t_p = u(x) + g_p$） | $a_V$ と同じ | $a_U$ と同じ | 0（厳密。どの位置も同じ $\Delta$ と $\delta$ を持つ） |
| 一般の K3 の族 $A_p u$ | — | — | $\Delta u \propto \delta u$ なら 0。そうでなくても符号の決まった偏りは無い |
| 鏡の符号（8 節） | 0 | 正 | 負（$a_U$ = 0 は厳密） |
| attention で文脈を混ぜる健全なエンコーダ | 1 未満 | 正 | 理論では決まらない（記述） |

**移植した候補での同定**: 問い合わせ $n$ の予測（自然な $x_n$ の見える部分から。5 節の段のまま）を、候補 $\{t_Q(x_{j \leftarrow m})\}_m$ と比べる。正解は $m = n$。候補は $(j, q)$ ごとに自分の平均で中心化する。易しい・難しいの候補の組は 3 節と同じ番号。4 つの $j$ で平均する。

- 候補はどれも同じ文脈 $j$ を持つので、文脈から来る成分は候補の間で共通で、中心化で消える。候補の間の違いは、**$Q$ の画素が $Q$ のトークンに起こす違いだけ**になる（導いた）
- 正解も含めて全候補が同じだけ不自然なので、「自然な画像はどれか」では当たらない。正解だけを自然な画像にする設計（候補が $x_{n \leftarrow m}$）は、不自然さの共通の成分 $s$ が距離に $\lVert s \rVert^2$ を足し、中身を知らなくても正解が選ばれるので採らない（導いた）
- $t$ を加法的に $a(Q \text{ の画素}) + b(\text{文脈})$ と置くと、自然な候補での勝敗は $\langle \hat a + b_n, (a_n - a_m) + (b_n - b_m) \rangle$ の符号で、$\langle b_n, b_n - b_m \rangle$（文脈を写すだけで稼げる項）を含む。移植した候補では $\langle \hat a + b_n, a_n - a_m \rangle$ になり、その項が消える（近似の説明。厳密な主張は 8 節の表）

## 8. 逃げ道を、どの量が塞ぐか

「鏡の符号」: 各マスのトークンが、180° 回したマス（$(a, b) \to (3 - a, 3 - b)$）の画素の局所な符号であるもの。$Q_q$ の本物は対角の四半分の画素で決まり、対角の四半分は $k$ = 4・8・12 のどのマスクでも見えている。つまり「隠した所のトークンに、周りの情報だけが詰まっている」符号の、厳密な例である。予測は本物そのものを使う（見える画素から計算できる）。

| 符号と予測 | 自然な候補の `top1` | `pred` − `flat` | `swap` | 移植した候補の `top1` / $A$ | $L$ |
| -- | -- | -- | -- | -- | -- |
| 局所な符号 + 本物 | 1 | 正 | 1 | 1 / 1（候補は自然なものとビットまで同じ） | 1 |
| 複製の K3 + 任意の予測 | 任意 | **0（厳密）** | **0.5（厳密）** | `flat` と同じ | **0（厳密）** |
| 位置だけの符号（$t_{n,p} = g_p$） | 0（全部が引き分け） | 0 | 0.5 | 0 / 0.5 | 定義されない（分母が 0。そう記録する） |
| 鏡の符号 + 本物 | **1** | **正** | **1** | **0 / 0.5（厳密。候補が全部同じ）** | **負** |
| 定数の予測 | 0 | 0 | 0.5 | 0 / 0.5 | — |

- 鏡の符号は、自然な候補の量（同定、`pool`・`flat` との差、`swap`）をすべて満点で通る。**承認された案の対照のうち、これを捕まえるのは局所性だけ**である。局所性を別の数として並べるだけだと「同定は高いが $L$ は中くらい」のときに、同定のどれだけが逃げ道によるのか分からない。移植した候補での同定は、その分を同定の値そのものから除く
- 逆に、複製の K3 は移植した候補では捕まらない（$u(x_{j \leftarrow m})$ は $m$ ごとに違う）。こちらは `flat`・`swap`・$L$ が受け持つ。2 つの対照は別々の逃げ道を塞ぐので、両方が要る
- 当てやすい的への逃げ（トークンがフレームを区別する情報を捨てる）: 候補どうしが似るので、難しい候補の同定は下がる。完全に捨てれば引き分けで 0 になる。予測の誤差の比（`pred_ratio`）と違い、同定は的の崩壊を得点にしない

## 9. 有効性の確かめ（run の値を読む前に。合否は恒等式と閉じた式だけ）

| 名前 | 条件 | 根拠 | 外れたとき |
| -- | -- | -- | -- |
| V-s0 | 隠した $U$ の画素を乱数で置き換えても、`pred`・`pool`・`interp` がビットまで変わらない（すべてのマスク） | 見える画素だけの関数（文脈の側は隠した位置を落とす） | 漏れ。実装の誤り |
| V-s1 | `oracle` の `top1` = 1、$A$ = 1（自然な候補。易しい・難しい） | 自分との cos は 1。候補が互いに違う限り | 重複した候補があるか、実装の誤り。重複の数を報告 |
| V-s2 | `const` と、位置だけの符号（本物を $g_p$ に置き換え）で、`top1` = 0、$A$ = 0.5、引き分けが全部。大きな $g_p$ を本物と予測の両方に足しても、すべての値がビットまで変わらない | 中心化で $g_p$ は消える | 実装の誤り |
| V-s3 | 合成の複製 K3（各 checkpoint の本物と予測を、全位置の平均で置き換える）で、`pred` と `flat` の問い合わせごとの値が一致、`swap` = 0.5 で引き分けが候補の数。文脈の側も同じ平均に置き換えた版で `pool` = `oracle` | 5・6 節 | 実装の誤り |

| V-s5 | 鏡の符号（`ColorCode` のマスを 180° 回したもの）と本物の予測で、自然な候補の `top1` = 1、`swap` = 1、移植した候補の `top1` = 0・$A$ = 0.5・引き分けが全部、$a_U$ = 0 | 8 節 | 移植した候補が逃げ道を塞いでいない。(c) を読まない |
| V-s6 | 各 checkpoint の本物に雑音を足した合成の予測 $r_n + \sigma \xi$（$\xi$ は標準正規、中心化し直さない）で、$A$ が式 $\frac{1}{n(c-1)} \sum_{n} \sum_{m \ne n} \Phi\!\left( \frac{\langle r_n, \tilde r_n - \tilde r_m \rangle}{\sigma \lVert \tilde r_n - \tilde r_m \rVert} \right)$（$\tilde r = r / \lVert r \rVert$）と、乱数の標準誤差の 3 倍以内で一致。$\sigma$ は式の値が 0.6・0.75・0.9 になる 3 つ | 内積は正規分布（導いた） | 採点の実装の誤り。あわせて、その checkpoint の空間で $A$ が 0.5 と 1 の間を動くこと（目盛りがあること）を示す |

- V-s0〜V-s5 は小さなテンソルのテストにもする（`tests/vision/`）。V-s3 と V-s6 は実 checkpoint でも毎回出す
- **合否に使わない対照（期待と、決まらない理由）**
  - 学習前（step 0）: 予測器の出力の層は符号について対称な初期値なので、初期値についての期待値は $A$ = 0.5、`top1` = $1/c$（導いた）。ただし 1 つの初期値では、問い合わせの数の標準誤差に収まる保証は無い。エンコーダは初期値でほぼ局所とみる（推測。残差のブロックの重みが小さい）ので、$L$ は 1 に近いと予想する。既存の数値では、旧 E1 の step 0 の `pred` は `id_easy` 0.002（偶然）だった
  - ランダムな予測器（学習したエンコーダに初期値の予測器）: 上と同じ。記述
  - 崩壊した M: 厳密な K3 ではなかった（既存の数値: `oracle` の色の `id_easy` 0.76、`pred` の `swap` 0.63〜0.85）。負の対照に使わない。$L$ が P16・F より低いと予想する（推測）
  - 別のフレームの予測（遅れごとの曲線）: H-time により帰無にならない。記述
- 外れたら止めて報告する。通るまで定数（候補の数、遅れ、$j$ の数）を変えない

## 10. 揺れと閾値

- 問い合わせごとの値（`top1` の当たり、$A_n$、`swap` の値）を残し、連続した問い合わせのブロックのブートストラップで標準誤差を出す（`metrics.block_bootstrap`。$e = 1 - \text{値}$、$v = 1$ と置けば今の形のまま使える）。ブロックは問い合わせ 8 個（約 61 秒）と 16 個の両方で出し、$\mathrm{SE}^* $ は大きいほう。段どうしの差は同じ引き直しで対にする。4 つの四半分と 4 つの $j$ は、問い合わせごとに先に平均する
- 8 個の根拠: 2 回目の $m$ で実測した積分時間から決めたブロック長が 60 秒だった（既存の数値）。$L$ と $2L$ の両方を見るのは Codex さんの修正を引き継ぐ
- V18c では**判定しない**（ユーザーの決定）。値と $2\,\mathrm{SE}^*$ を並べるだけにする
- V19 で主の指標にするときの形（提案）: 差を「上回る」と書くのは、2 seed とも同じ向きで、それぞれ $2\,\mathrm{SE}^*$ を超えるとき。見分けたい最小の差 $\Delta_*$ は理論では決まらない（Codex さんの指摘のとおり、判断が変わる最小の幅として決めるもの）。V18c の 12 本の値と $\mathrm{SE}^*$ を見てから、ユーザーに諮る

## 11. 旧 checkpoint（V18・V18b）と V18c

- 同じコードで測れる。違いは $s$（1・4・2）と $d$ だけで、マスクは `expand_masks` が広げる
- 並べるときの注意
  - 空間が違う。V18・V18b の $P$ は学習した射影で、V18c は固定の $R$。値は「それぞれの空間の中での補完」で、腕をまたいだ大小は、空間が持つ情報の量が違えば比べにならない。`participation`（領域のベクトルの有効な次元）を並べる
  - M は 1 マスが 1024 次元で、SIGReg は平均だけにかかっている。記述だけ
  - 分布の中の $k$ が違う（旧は $r$ ごと、長い run は 8）。同じ $k$ の行どうしを比べ、分布の外の行はそう書く

## 13. 過去の失敗を繰り返さない理由と、残る弱点

| 失敗 | 原因 | 今回 |
| -- | -- | -- |
| 1 回目（生成画像の Inception の同定） | 64 px の生成と 32 px の切り出しを 299 px のネットに通した。生成の雑音。目盛りが 0.002〜0.024 | 外部のネットも生成も通さない。予測と候補は同じ空間。天井は `oracle` で厳密に 1。目盛りは V-s6 が checkpoint ごとに示す |
| 2 回目（高解像度の Inception の特徴の $R^2$） | 的が 64 px の入力の関数でない成分を多く持つ。約 3000 個で 1024 次元の当てはめ。白色化 | 的はエンコーダ自身の出力で、入力の関数。当てはめも白色化も無い |
| 3 回目（Places365 のカテゴリ） | 教師のラベルがこのデータに合わない | ラベルも教師も無い |
| 旧 E1 の V-E1 | `shuf` を帰無の基準にした（時間の構造で 0.5 にならない） | 合否は恒等式と閉じた式だけ |
| 旧 E1 の V-E3 | M を負の対照にした（厳密な K3 でなかった） | 合成の厳密な対照だけ。M は記述 |
| 旧 E1 の step 0 の `r2` −10 | `oracle` で当てはめた読み出しに予測を通した | 読み出しが無い |
| `shift_top1` | 問い合わせ自身が候補に入った | 問い合わせと正解は同じ stack の予測と本物。V-s1 が候補の重複を見る |

**残る弱点**（導いた。隠さず書く）

1. **自分の空間の中の量である。** 空間が何を持つかは測らない。ぼかした色のような、滑らかに延長できる量だけを持つ空間は高い値を出しうる。`interp` との差がその分を示すが、「情報が豊かか」は別の量（崩壊の検出、`participation`）と並べて読むしかない。外部の物差し（`pca`・VAE）と同じ目盛りに載せることは、原理的にできない
2. 移植した画像は、エンコーダが学習で見ていないパッチの組み合わせである。$L$ と移植した候補の値は、この分布の外での振る舞いを含む
3. 健全な、文脈をよく混ぜるエンコーダは、移植した候補で値が下がる。「下がった」は逃げ道の証拠ではなく、「同定のうち、$Q$ の画素に帰せる分がそれだけ」という読みになる
4. `flat` は四半分の中の配置まで要求する高い基準で、四半分の単位の中身を当てているだけの予測は `pred` − `flat` が 0 に近く出る。そのときは `pool`・`interp` との差と `swap` で読む

## 14. 予想（推測。数値はどれも推測）

1. V-s0〜V-s6 は通る
2. 長い run の 60000、$k$ = 8、自然な候補: `pred` の `top1` は易しい候補で 0.1〜0.6、難しい候補で 0.08〜0.4。根拠は `pred_ratio_calib` が step 6000 で 0.67〜0.87（既存の数値）で、256 次元の向きの一致は弱くても候補を分けうること。学習率 $10^{-4}$ が $10^{-5}$ より高い
3. `pred` > `pool`、`pred` > `interp`（60000、2 seed とも）。`pred` − `flat` は正だが小さい
4. 移植した候補の値は自然な候補より低いが、0.5（$A$）を超える。$L$ は step 0 で 0.9 以上、60000 で下がる
5. $k$ が大きいほど `pred` は下がる
6. `swap` の `pred` は 0.6〜0.9
7. M は $L$ が最も低い

## 15. 決めてほしい点

- 私たち（Claude）が決めて、ユーザーが覆せる点: 主の候補を「移植した難しい候補の $A$ の `pred` − `flat`」にすること、`pool` を文脈の側の平均にしたこと（承認の文面どおり。全体を見た側の平均は隠した画素の情報を含むので使わない）、cos を主・距離を副にしたこと、中立な文脈を学習の動画の 4 個にしたこと、マスクを `e1f_masks` の 12 個にしたこと
- Codex さんに見てほしい点: (1) 移植した候補が、鏡の符号のほかの逃げ道（たとえば $Q$ の画素のごく粗い統計だけを $Q$ のトークンに残し、残りを文脈で埋める符号）をどこまで塞ぐか、(2) 予測と候補を別々に中心化することが得点を作らないか、(3) V-s6 の式が、cos と中心化のもとで厳密か、(4) `top1` と $A$ のどちらを主にするか
