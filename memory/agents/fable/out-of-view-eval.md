# 見えていない部分の特徴を測る評価（調査と提案、2026-11-24）

JEPA が「見えている部分だけから、見えていない部分の特徴までを持てるか」を測る評価の提案である。コードは書いていない。計算の時間は見積もりで、実測ではない。リポジトリで読んだのは `exp/vision/report-jepa.html`、`plans/jepa.md`、`memory/project_jepa_plan.md`、`jepa.py`、`jepa_eval.py`、`jepa_diag.py`、`exp/lib/video_io.py`、`exp/lib/tours/manifest.json` である。

確かさは 3 段階に分ける。

- **文献**: 論文のページを今回読んで確かめた（出典は 8 節。2025〜2026 年のものは要旨か本文の一部までで、全文は読んでいない。根拠に使う前に読み直してほしい）
- **導いた**: 定義・不等式・このリポジトリのコードから論理で出した。数値では確かめていない
- **推測**: 実データでどうなるかの予想、計算時間の見積もり

## 0. 要点

1. 「未観測の部分の情報を持つ」は、情報量だけでは定義できない。見える部分 $V$ のどんな符号 $c(V)$ も、$V$ の画素そのものより多くの情報は持てない（データ処理不等式）。測れるのは「**小さい決まった読み出しで取り出せる形になっているか**」である。そのため読み出しの容量を固定し、「見える部分の画素の PCA」と「学習前の ViT」を同じ読み出しに通した値との差を読む（導いた）
2. 的は 3 種類ある。(a) 枠の中で隠した所、(b) 画面の外、(c) まだ視野に入っていない所（未来）。(b) には本物の正解がある。元の動画は 854×480 で、いまの 64×64 は中央の正方形だけを使っているので、左右に 25 画素ぶんずつ、エンコーダが一度も見ていない帯が残っている（導いた。`ffmpeg_filter` と manifest から）
3. おすすめは 3 つの組である
   - **主: E1「補完の同定」**。枠の中の決まった領域（四半分・半分・外周）を隠し、予測器の出力を、**全体を見たときのトークンで当てはめて凍結した線形の読み出し**に通して、隠した領域だけを切り出した画像の Inception の特徴を当てる。採点は、同じ場面の前後の時刻を候補にした同定の正解率と、位置を入れ替えた 2 択。読み出しは予測を一度も見ないので、probe が帳尻を合わせる余地がない
   - **副: E2「画面の外」**。マスクなしの普通の入力の符号から、左右の帯の特徴を ridge で当てる。予測器が要らず、VAE や物差しにもそのままかけられ、V19〜V21 でも変えずに使える
   - **副: E3「まだ見えていない所」**。いまの符号から $\delta$ 秒後のフレームの外部の特徴を当てる。`dyn_1/copy_1` を、自分の $z$ ではなく外部の的に替えたもの
4. 拡散のデコーダができたら、E1 の変種 **E1g「仮想の $z$」** を足せる。隠した位置を予測で埋めた $\hat z$ をデコーダに入れ、隠した領域の同定の正解率を主の指標と同じ手順で測る。追加の学習は要らない
5. 的に同じエンコーダの特徴を使う指標（`pred_ratio`、自分の空間での検索）は、K3 に近い解で満点になるので判定に使わない。位置を入れ替えた 2 択を必ず添える（導いた）
6. 計算は軽い。的の特徴は checkpoint によらないので 1 回だけ作る（数分）。そのあとは checkpoint 1 個あたり 1〜3 分の見込み（推測）。V18 の長い run と V18b の F には、予測器が checkpoint に入っているので後からかけられる

## 1. 何を測るのか

### 1.1 情報量では測れない

見える部分を $V$、見えない部分を $U$、的の特徴を $T(U)$ とする。符号 $c(V)$ は $V$ の関数なので

$$I\bigl(c(V);\, T(U)\bigr) \le I\bigl(V;\, T(U)\bigr)$$

である。右辺は表現によらないデータの性質で、見える部分の画素をそのまま並べた符号が上限に届く。「学習によって観測から得られる情報を最大化する」を情報量で読むと、学習前から上限にあることになる。

ユーザーの言う性質は、**その情報が使える形で出ているか**と読むのが妥当である。つまり「未観測の部分の特徴 $T(U)$ が、$c(V)$ から小さい決まった読み出しで取り出せる」こと。V-JEPA が線形ではなく attentive probe を使う理由も同じ所にある（特徴が線形に分かれる保証がないので、読み出しの形を決めて測る。文献 [2]）。

ここから評価の骨組みが決まる（導いた）。

- 読み出しは線形（ridge）に固定し、当てはめの組の数（約 6000）と次元（PCA で 1024 以下）をそろえる
- 同じ読み出しに「見える部分の画素の PCA」「パッチごとの平均の色」「学習前の ViT」を通す。これらとの差が、学習で使える形になった分である
- いちばん強い読み方は、読み出しに予測を当てはめさせないこと。全体を見たトークンで読み出しを当てはめて凍結し、それを予測器の出力に使う（E1）。DINO-world と DINO-Foresight が、いまの特徴で当てはめた頭を未来の予測にそのまま使うのと同じ形である（文献 [6][7]）

### 1.2 的の 3 種類

| 種類 | 見える部分 | 当てる的 | 正解の出どころ | 予測器 |
| -- | -- | -- | -- | -- |
| (a) 枠の中 | 64×64 のうち残したトークン | 隠した領域 | 同じ画像 | 使う（学習した課題） |
| (b) 画面の外 | 64×64 の全部 | 左右の帯 | 元の動画（854×480）から切り直す | 使わない |
| (c) 未来 | いまの stack の全部 | $\delta$ 秒後のフレーム | 同じ動画の先 | 使わない |

(a) は学習した課題そのものなので、予測器の出力を直接読める。(b) と (c) は予測器が学んでいない的なので、符号からの読み出しで測る。そのかわり入力は普段どおりで、どんな符号にもかけられる。

カメラが前に進むとき、像は消失点から外へ流れる（導いた。前進の光学的流れの形）。新しいものは中央から小さく現れ、端のものは外へ出ていく。「画面の外のものが数秒後に入ってくる」のは主に向きを変えたときである。したがって (b) の帯は「少し前に中央寄りに見えていたもの」であることが多く、(c) の未来のフレームは「いまの中央の拡大」に近い。この 2 つの近道は 3 節の対照で扱う。

## 2. 評価の案

### 記号と共通の部品

- **評価のマスク**: 粗い 4×4 の格子の上で決める。V18b の `expand_masks` と同じく細かい格子へ広げれば、パッチ 16・8・4 で画素の領域がまったく同じになる
  - `Q`: 四半分（2×2、$k$ = 4）を隠す。4 通り
  - `H`: 半分（左・右・上・下、$k$ = 8）を隠す。4 通り
  - `R`: 外周を隠して中央の 2×2 だけを見せる（$k$ = 12）。1 通り。枠の中で作る「視野の外」
- `Q` は $F_4$、`H` は $F_8$ に入る。`R` も $F_{12}$ に入る（導いた。トーラスの上で、行 $\{3, 0\}$ × 全列の 2×4 と、行 $\{1, 2\}$ × 列 $\{3, 0\}$ の 2×2 の和集合が外周の 12 個になる）。つまり V18 の $r$ = 0.25・0.5・0.75 の run は、それぞれ `Q`・`H`・`R` を学習の分布の中で受けられる。実装のときに `mask_family` に含まれることをテストで確かめてほしい
- **外部の的 $T$**: 凍結した Inception V3 の pool の特徴（2048 次元）。**隠した領域だけを切り出して**から 299 に拡大して入れる。stack の最後の 1 フレームを使う（拡散のデコーダと同じ対象）。当てはめの組で PCA をかけ、256 次元にして標準化する
  - 画像の全体を入れた特徴マップの 1 マスを的にしてはいけない。Inception の最後の層の受容野は画像のほぼ全体なので、隠した位置のマスにも見える部分の情報が入り、見える部分から当たるのが当然になる（導いた）
  - 32×32 の切り出しを 9 倍に拡大した Inception の特徴は、色と質感の統計が大半だと思われる（推測）。そこで的を 2 本並べる。`color`（隠した領域の、パッチごとの平均の色。既存の `ColorCode`）と `incep`
- **読み出し**: 切片つきの ridge。$\alpha$ は Zurich の calib で選ぶ（`linear_dyn.select_alpha` と同じ流儀）。当てはめは学習のストリームの span の約 6000 組、評価は Zurich
- **採点**
  - `r2`: 的の座標ごとの $R^2$ の平均
  - `id_easy`: 予測した的に最も近い候補が正解である割合。候補は Zurich の離れた時刻の 64 個
  - `id_hard`: 候補を同じ動画の前後 ±2〜±32 秒（2 秒おき、32 個）にしたもの。`jepa_diag.ZurichGrid`（1 秒おきの stack）が使える。場面・天気・照明は候補どうしで共通なので、「同じ街角」だけでは当たらない
  - `swap`: 3 節の位置の入れ替えの 2 択
- 同定の採点は、IWM が予測器を測るのに使った形（予測した表現で、256 個の候補から正解を引く MRR）と同じ考えである（文献 [4]）

### E1: 補完の同定（主、おすすめ）

**入力**: Zurich の stack と評価のマスク。文脈側は見えるトークンだけをエンコーダに通す（`TokenEncoder.forward(images, keep)`）。

**当てるもの**: 隠した領域 $U$ の外部の的 $T(U)$。

**手順**

1. 読み出し $g_U$ を当てはめる。入力は**全体を見たとき**の、領域 $U$ の位置のトークン $h_U$（パッチ 8 なら 4×4 個、PCA で 1024 次元以下に落とす）。出力は $T(U)$。領域ごとに 1 本。当てはめの組で求めて凍結する
2. 4 段を同じ $g_U$ に通す
   - `oracle`: 全体を見たトークン $h_U$ → $g_U$。上限。エンコーダの特徴が、その位置の中身をどれだけ持つか
   - `pred`: 予測器の出力 $\hat h_U$ → $g_U$。**これが測りたい値**
   - `mean`: 位置ごとの平均のトークン → $g_U$。下限（同定では当て推量）
   - `shuf`: 別の stack の $\hat h_U$ → $g_U$。実装の確かめ（当て推量になるはず）
3. 指標は `r2`・`id_easy`・`id_hard`・`swap` を、的 `color` と `incep` で。まとめの数は $\text{gain} = (\texttt{pred} - \texttt{mean}) / (\texttt{oracle} - \texttt{mean})$

**利点**（導いた）

- $g_U$ は予測を見ていないので、予測が的と同じ空間の同じ意味の所に出ていなければ値が出ない。probe の容量で帳尻が合わない
- `oracle` が低ければ「エンコーダの特徴がその位置の中身を持っていない」（K3 に近い、または細部を捨てた）、`oracle` が高く `pred` が低ければ「予測器が当てられていない」と分けて読める
- 的が外部なので、エンコーダが自分の的を当てやすく変える近道（H-target）では値が上がらない。その近道をとると `oracle` が下がる

**エンコーダだけの版（E1e）**: 予測器を使わず、文脈側のトークン $h_V$（平らにして PCA 1024）から $T(U)$ へ、マスクごとに ridge を当てはめる。こちらは物差し（学習前の ViT の文脈側、見える部分の `color`、見える部分の画素の PCA、見える部分の Inception の特徴）と同じ読み出しで比べられる。1.1 のとおり、物差しとの差だけを読む。

**V18・V18b への当てはめ**: 予測の的が $z_p$（射影の後）なので、$h$ を $z_p$ に読み替える。ほかは同じ。

### E1g: 仮想の $z$ を拡散のデコーダへ（拡散のデコーダができてから）

I-JEPA と V-JEPA は、エンコーダと予測器を凍結し、予測器の出力を条件にした拡散のデコーダで、隠した領域を画素に戻して見せている（I-JEPA は RCDM、V-JEPA は見えない領域の予測だけを条件にしたデコーダ。文献 [1][2]）。どちらも目で見るだけで、数値にはしていない。これを、いま作っている主の指標と同じ採点につなぐ。

- 隠した位置を埋めたトークンの列 $\tilde h$ を作り、$\hat z = W \cdot \mathrm{vec}(\tilde h)$ を、**全体の $z$ で学んだデコーダ**にそのまま入れる。デコーダの学習は増えない
- 4 段: `full`（全部が全体を見たトークン。主の指標そのもの）、`oracle`（見える位置は文脈側のトークン、隠した位置は全体を見たトークン）、`pred`（隠した位置は予測器の出力）、`mean`（隠した位置は位置ごとの平均）
- 採点: 生成した画像の**隠した領域だけ**を切り出し、Inception の特徴で、本物の同じ領域を候補から当てる（`id_easy`・`id_hard`）。見える領域の同定も並べる（こちらは `mean` でも高いはず）
- `full` と `oracle` の差は、文脈側のトークンが、全体を見たときと違う値になることの大きさである。V-JEPA 2.1 は、隠した位置だけに損失をかけると、見えるトークンが大域の情報の集め役になり、局所の構造が崩れると報告している（文献 [3]）。この差が大きければ同じことが起きている可能性がある（推測）
- 同じ $\hat z$ から数枚サンプルして、隠した領域の画素ごとの標準偏差を見ると、予測が決めていない所が分かる（PLAN.md の「目視」と同じ）

絵として人に見せられるのが E1g の強みで、ユーザーの言う「広い知覚を virtual に可能にする」に最も近い。一方で、デコーダの質と $W$ の混ぜ合わせを経るので、数値の解像度は E1 より落ちると思われる（推測）。判定は E1、絵と裏づけは E1g がよい。

### E2: 画面の外（副）

**入力**: 普段どおりの 64×64 の stack（マスクなし）。符号は `z`、`h_flat` の PCA、VAE の $\mu$、物差しのどれでもよい。

**当てるもの**: 同じ時刻の、中央の正方形の**左右の外側の帯**の特徴。元の動画は 480p（854×480）で、いまのデータは中央の 480×480 を 64×64 に縮めたもの。同じ縮尺で左右に約 25×64 画素の帯が残る（導いた）。帯を切り出して `color`（8×8 のブロックの平均）と `incep` にする。

**読み出しと採点**: 符号 → 帯の的の ridge。`r2`・`id_easy`・`id_hard`。

**読める問い**: 「この符号は、入力に一度も入っていない場所の特徴を、線形に取り出せる形で持つか」。学習前との差、VAE（`v16`・`v17`）との差が、そのままユーザーの主張（JEPA は経験から外を補う）の検証になる。JEPA が VAE を上回らなければ、「補完の力は JEPA に固有」とは言えない。

**準備**: Zurich と当てはめの span の帯を、元の動画から切り直す（`ffmpeg` の `crop` を変えるだけ。`/datasets/walking_tours` の元の動画が要る）。新しいデータ版になるので、既存の `data_version` には触れず、評価専用の別の出力にするのがよい。

**帯を外側だけにする版**: 見える端に接する画素は、端の延長で当たる。帯の外側の 16 画素だけを的にした版を並べると、接している分を除ける。

### E3: まだ視野に入っていない所（副）

**入力**: 時刻 $t$ の stack の符号（マスクなし）。

**当てるもの**: $t + \delta$（$\delta$ = 1・2・4 秒。stack の幅 0.8 秒より長い）の stack の最後のフレームの外部の的（`color` と `incep`、全体と、E2 の帯の両方）。

**採点**: `r2`、`id_hard`（候補は同じ動画の、$t + \delta$ の前後の時刻）。`copy` の対照（3 節）で割った比も出す。

**位置づけ**: `dyn_1/copy_1` は自分の $z$ の 1 つ先を当てるので、$z$ が当てやすい成分だけになれば良くなる。E3 は的が外部なので、その近道が効かない。V20 の手法 3 は $\delta$ 秒前の stack も符号化するので、E3 は V20 の評価にそのまま合う。V18c の空間のマスクの学習は未来を当てる目的ではないので、E3 が学習前より良くならなくても欠陥とは言えない。並べるだけにして、V19 以降の段どうしを比べる物差しにする。

### 採らない案

- **`pred_ratio` と、自分の空間での検索を判定に使う**: 予測 $\hat h_U$ で、候補の $h_U$ から正解を引く（IWM の MRR の形）。安く、読み出しも要らない。しかし、全トークンが同じ大域の符号を持つ解（K3 の族）では、隠した位置のトークンが見える部分で決まるので満点になる（導いた）。診断として並べるなら、`swap` と `oracle` を必ず添える
- **attentive probe**: 文献では標準だが（文献 [2][3]）、評価のマスクを固定すれば入力の形が決まるので、マスクごとの ridge で足りる。注意の層を足すと読み出しの容量が増え、1.1 の物差しとの差が読みにくくなる
- **amodal completion のベンチマーク**（SAIL-VOS、TAO-Amodal、Kubric など）: 物体のマスクの正解が要り、Walking Tours には無い。合成の動画を足すとデータが変わる。今回は採らない（文献 [9][10]）
- **意外さによる検査**（IntPhys など。予測と実際の表現の差を意外さとする。文献 [5]）: 物理に反する動画が要る。今回は採らない

## 3. 近道の対照と、言えること・言えないこと

### 対照

| 近道 | 何で当たってしまうか | 対照 | 使う評価 |
| -- | -- | -- | -- |
| 位置ごとの平均 | 空は上、道は下 | `mean`（同定では当て推量） | すべて |
| 場面の持続 | 同じ街・天気・照明 | `id_hard`（候補が同じ場面の前後） | すべて |
| 見える部分と似ている | 隠した所も同じ質感・色 | 見える部分の的 $T(V)$ → $T(U)$ の ridge（`ext`） | E1e・E2 |
| 隣の画素からの補間 | 端の色が続く | 見える端の画素を隠した領域へ調和補間（または端の列の複製）して $T$ をとる（`interp`）。E2 は外側だけの帯 | E1・E2 |
| 大域の符号 | 全トークンが同じ内容 | `swap`、`oracle` | E1 |
| 読み出しの容量 | probe が自分で補完を学ぶ | 凍結した $g_U$（E1）。E1e・E2 は画素の PCA と学習前の ViT | すべて |
| 時間の持続 | 未来はいまとほぼ同じ | `copy`: $T(x_t)$ をそのまま出す。`ext_dyn`: $T(x_t)$ → $T(x_{t+\delta})$ の ridge | E3 |
| 前進による拡大 | 未来は中央の拡大 | いまのフレームの中央を拡大した画像の $T$（`zoom`） | E3 |
| 自分の的を楽にする | 的が当てやすい成分だけになる | 的を外部にする。`oracle` の低下で見える | E1 |
| マスクが分布の外 | 学習で見ない形の文脈 | run の $k$ に合うマスクを主にし、ほかは「分布の外」と明記 | E1 |

`swap`（位置の入れ替え）: 離れた 2 つの領域 $A$・$B$（対角の四半分）を同時に隠し、$g_A(\hat h_A)$ が $T(A)$ と $T(B)$ のどちらに近いかを当てる。当て推量は 50%。場面や時刻だけを表す符号は、$A$ と $B$ を区別できないのでちょうど 50% になる（導いた）。上限は `oracle` の同じ 2 択で測る（空と空のように本当に似ている組があるので、100% にはならない）。2 つ隠すと $k$ = 8 になるので、$r$ = 0.5 の run では分布の中、$r$ = 0.25 の run では分布の外である。

### 「未観測の部分の特徴を持つ」と言える条件

次がそろったとき（閾値は回す前に README に書く）。

1. E1 の `pred` が、外部の的で `mean` を超える。`id_hard` と `swap` でも超える
2. E1e または E2 で、学習後の符号が、学習前の ViT・見える部分の `color`・見える部分の画素の PCA を、同じ読み出しで超える
3. 2 の差が `interp` を超える（隣の画素の延長では説明できない）
4. 学習が進むと（6000 → 60000 step）1 の値が上がる、少なくとも下がらない

1 だけなら「予測器は当てている」まで。2 までで「学習で、見えない部分の特徴が取り出せる形になった」。3 までで「端の延長ではない補完」。

### 言えないこと

- `pred_ratio` や自分の空間での検索だけが良い → 言えない（K3 の族と H-target で良くなる）
- `id_easy` だけが良い → 「どの場面かは分かる」まで。見えない部分の中身を持つとは言えない
- `color` の的だけが良く `incep` が物差しと同じ → 「おおまかな配色の補完」まで
- どの条件がそろっても、物体の単位の補完（amodal completion）や、物の永続性は言えない。2026 年 10 月の報告では、V-JEPA 2 の予測器は、隠れて動く物体を 0.3 秒ほどで見失い、情報はエンコーダの側には残っていたという（文献 [8]。要旨だけを読んだ）。「エンコーダが持つ」と「予測器が出す」を分けて測る理由になる
- 64×64 の切り出しの Inception の特徴は、意味というより質感と色に寄ると思われる（推測）。「抽象的な特徴」と呼ぶなら、Imagenette の線形 probe の上がり方と並べて読む

### 予想（推測。回す前の README に書く候補）

- V18 の長い run では、`pred_ratio` が 0.19〜0.62 まで下がっている一方で `recon_blur` は悪くなった。E1 の `oracle` が 6000 → 60000 step で下がり、`gain` は上がる、という形が H-target の読みと合う。`pred` の絶対値がどちらへ動くかが、ユーザーの見立て（抽象的な情報は残り、補完は進んでいる）と Codex さんの見立て（当てにくい成分を捨てただけ）を分ける
- $r$ が大きいほど（`R`）、`pred` と `mean` の差は小さくなる。$r$ ごとにマスクが違うので、$r$ どうしの比べには使わない

## 4. 的の選び方

| 的 | 利点 | 欠点 | 使い方 |
| -- | -- | -- | -- |
| 同じエンコーダのトークン | 追加の計算なし。学習の目的そのもの | 自分の的を楽にできる。K3 の族で満点 | 診断だけ |
| 学習前の同じ形の ViT のトークン | 凍結していて、形がそろう | V18 では学習前が `recon_blur` で最良だった。画素に近い的になる | 採らない（`color` で足りる） |
| 画素（ぼかし） | 正解がはっきりしている | 「JEPA に細部を求めない」という決定に合わない | 採らない |
| パッチごとの平均の色（`color`） | 細部を含まない。既存の部品 | 配色だけ | 副の的 |
| Inception V3（領域を切り出して） | 凍結した外部の特徴。主の指標と同じ道具 | 低解像度では質感に寄る。ImageNet の教師あり | 主の的 |
| DINOv2 など密な特徴 | パッチごとの特徴が強い（文献 [6][7] が的にしている） | 依存が増える。64×64 では 14 画素のパッチが粗い | 今回は採らない。Inception で差が出ないときの次の手 |
| 別の時刻のフレームの外部の特徴 | 「まだ見えていない所」を直接測る | 学習の目的と違う | E3 |

的に SALT のような凍結した教師を使う学習（文献 [11]）もあるが、評価の話とは別なので扱わない。

## 5. 計算の重さと、既存の checkpoint

見積もりはすべて推測である（4090 を 1 台、AMP）。

| 部品 | 量 | 目安 | 回数 |
| -- | -- | -- | -- |
| 的の Inception の特徴（E1） | （当てはめ 6000 + calib 1024 + val 1024 + 格子 約 4000）× 9 領域 ≈ 11 万枚 | 2〜5 分 | 全 checkpoint で 1 回（キャッシュする） |
| 帯の切り直し（E2） | Zurich と span の動画を `ffmpeg` で 1 回 | 10〜30 分（CPU） | 1 回 |
| 帯と未来の的（E2・E3） | 約 3 万枚 | 1 分 | 1 回 |
| エンコーダと予測器の順伝播（E1） | 約 1.2 万 stack × 9 マスク | 1 分以内（パッチ 4 の F は数分） | checkpoint ごと |
| ridge（PCA 1024 → 256、約 6000 組） | 領域 9 本 + 物差し | 数秒 | checkpoint ごと |
| E1g のサンプリング | val 512 × マスク 3 通り × 4 段 = 6144 枚 | 主の指標のサンプリングの約 6 倍 | checkpoint ごと（デコーダは主の指標のものを使う） |

E1・E2・E3 を合わせて、checkpoint 1 個あたり 1〜3 分、最初の 1 回だけ的の準備に 15〜40 分とみる。

**既存の checkpoint**

- V18 の長い run（パッチ 16、4 本）: かけられる。`JEPAModules` に予測器が入っており、`CodeStats.pred` が同じ経路（`predict` と `take`）を通っている。$r$ = 0.25 の 2 本は `Q`、0.5 は `H`、0.75 は `R` が分布の中
- V18b の F（パッチ 4）: かけられる。`expand` = 4 で同じ領域。$r$ = 0.25 なので `Q`。トークンが 256 個で、順伝播は重くなる
- V18b の M: かけられるが、K3 に崩れているので、`swap` が 50%・`oracle` が低い、という**負の対照**として使う。評価が K3 を見分けることの確かめになる
- 学習前（step 0）: 同じ評価をかけて物差しにする。予測器も学習前なので、E1 の `pred` は `mean` 付近のはずである
- E2・E3 は予測器を使わないので、VAE の `v16`・`v17`、`color`、`pca` にもかけられる

**先の段で使えるか**

- E2・E3 は「stack → 符号」の関数だけで足りる。V19（ストリーム）、V20、V21（PC-ALM）で変更なし
- E1 は、見えるトークンだけを通す文脈側の経路と予測器が要る。V21 でノードに分けても、評価は checkpoint の重みを読んで BP なしの順伝播をするだけなので、局所性の制約には触れない

## 6. おすすめの進め方

1. **先に E1 を V18 の長い run の 6000・60000 step と学習前、V18b の M にかける**。`recon_blur` の悪化が「補完は進み、細部だけ捨てた」のか「当てやすい的に変えただけ」のかが、既存の checkpoint だけで分かる。M で `swap` が 50% になることを、評価の確かめにする
2. パッチ 8 の学習（V18c）の評価に E1 を入れる。学習のマスクの族に `Q`・`H`・`R` が入るようにしておくと、分布の中で測れる
3. 拡散のデコーダができたら E1g を足し、資料に絵を載せる
4. E2 は、帯の切り直しができしだい。JEPA と VAE を同じ物差しで比べられるので、V19 以降の段の共通の物差しに向く
5. E3 は V19 から（`dyn_1/copy_1` の隣に並べる）

閾値の決め方（推測を含む）: 同定の正解率の標準誤差は、val の 1024 個が独立なら最大 1.6 ポイント。Zurich は 1 本の動画で標本が相関するので、時間のブロックで分けたブートストラップで幅を出し、seed 0・1 の差と大きいほうを「差がある」の閾値にするのがよい。

## 7. ユーザーに決めてほしいこと

1. 主を E1（凍結した読み出し）にし、E1g（拡散で描く）を裏づけにする順でよいか。逆（E1g を主）にすると、主の指標と手順がそろうが、数値の解像度は落ちると思われる
2. E2 のために、元の動画から左右の帯を切り直してよいか（評価専用の別のデータ。既存の `data_version` は変えない）
3. 的は Inception V3 と `color` の 2 本でよいか。DINOv2 などの密な特徴を足すかは、Inception で差が出なかったときに決める案
