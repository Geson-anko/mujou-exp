# V18c の主の指標 m の 3 回目の作り直し: 粗い場面のカテゴリを的にする（提案、2026-11-25）

[main-metric-v2.md](main-metric-v2.md) の続きである。コードは書いていない。読んだのは `exp/vision/README.md` の V18c の節（とくに「主の指標を作り直す」と 2 回目の結果）、`plans/jepa.md` の V18c の節、`results/v18c/judge_m_checks.json`・`sem_probe.json`、`exp/lib/tours/manifest.json`、`exp/vision/sem_eval.py` の組の作り方、`memory/project_jepa_plan.md`、Codex さんの批判（[../codex/main-metric-v2-critique.md](../codex/main-metric-v2-critique.md)）である。外部は Places365 の GitHub のページ（`CSAILVision/places365`）だけを読んだ。

確かさは 4 段階に分ける。

- **既存の数値**: `runs/` と `results/v18c/` にある値
- **確かめた**: 今回、外部のページで読んだこと
- **導いた**: 定義・不等式・コードから論理で出した。数値では確かめていない
- **推測**: 実データでどうなるかの予想、記憶に頼った外部の仕様、計算時間の見積もり

## 0. 要点

1. **的は、Places365 で学習済みの ResNet-50 が 320 px のフレームにつけるラベルを、公式の場面の階層（第 2 階層）でまとめた $K$ 個の粗いカテゴリにする。** 重みは CC BY、コードは MIT（確かめた）。torchvision の `resnet50` に読み込めるので、新しい依存は増えない（推測。読み込みの形は実装で確かめる）
2. **$m$ は、符号から粗いカテゴリを線形に読んだときの balanced accuracy にする。** 偶然の値はちょうど $1/K$ である。読み出しは、既存の Imagenette の probe と同じ ridge の one-hot 回帰に、クラスの重みをつけたもの
3. **組は、動画を単位にした入れ子の交差検証にする。** 都市の動画 9 本（Wildlife を除く）のそれぞれを 1 本ずつ採点に回し、残りの 8 本で当てはめる。$\alpha$ は残りの 8 本の中で、やはり動画を単位に選ぶ。当てはめと採点が別の動画なので、時間の相関が組をまたがない。ユーザーの決定「複数の都市をまたぐ」は、この形で満たす
4. 2 回目が 0 の近くに沈んだ原因は、白色化のほかに 2 つあるとみる。$\alpha$ の格子の上端に全部の物差しが当たっていたこと（既存の数値）と、当てはめの組の独立な場面が 100 個ほどしかなかったこと（導いた）。今回の設計は 3 つとも外す（11 節）
5. 有効性の確かめは、有限の標本でも成り立つものに替える。入れ子の順序（V-m2）は母集団でしか成り立たず、2 回目は当てはめの誤差で逆転した。代わりに、**雑音のはしご**（同じ符号に独立な雑音を足すと、線形の読み出しの最良の誤差は増える）、**ラベルをずらした帰無**（偶然の値と標準誤差を実データで確かめる）、**64 px から決まるか**（データ処理不等式の前提を先に確かめる）を置く
6. **この $m$ は K3 の崩壊を見分けない**（導いた）。場面のカテゴリは画面全体の量なので、位置の平均だけを持つ符号でも読める。V-m4 と Eckart–Young の上限は外し、崩壊の検出は L1（K1〜K3）に任せる
7. 物差しの間（色 → 意味の特徴）は見分けられる見込みだが、**run どうしの差は閾値の中に入る見込みが 5〜6 割ある**（推測）。Imagenette の線形 probe で、$z$ は全部の run で 39.0〜40.4% と step 0 の 39.9% から動かなかった（既存の数値）。有効性を通ったうえで差が出なければ、物差しの失敗ではなく結果として読む
8. `e1f` の的は、同じラベル付けを隠した四半分の切り出しにかけたものにできる。ただし四半分は Places365 の学習の分布から外れるので、ラベルの確かめを別に置き、外れたら `e1f` を読まない（12 節）

## 1. 2 回目の失敗の読み直し

2 回目は、物差しがすべて −0.023〜0.016 だった（既存の数値）。README は白色化を原因と推測している。同じ数値から、ほかに 2 つの原因が読める。

- **$\alpha$ の格子の上端**: `mean` を除くすべての物差しで、選ばれた尺度が上端の 1 だった（`alpha_edge`）。`sem_probe.json` では、どの符号も尺度を上げるほど値が上がり、上端でも上がり続けている。最良の $\alpha$ は格子の外にあり、選ばれた値は「最も縮めた読み出し」の値にすぎない
- **独立な場面の数**: 当てはめの組は 0〜6000 秒の約 6000 組で、Amsterdam と Bangkok の先頭だけである。的の相関時間は 30 秒（$L$ = 60、既存の数値）なので、独立とみなせるブロックは 6000 / 60 = 100 個ほどしかない（導いた）。1024 次元の読み出しを 100 個の場面で当てはめると、強く縮めるしかなくなる。上の $\alpha$ の挙動と合う
- **白色化**: `inc64` は四半分の的（`sem`）で 0.153、画面全体の的（`scene`、PCA 32・白色化）で 0.442 だった（既存の数値）。同じ白色化でも、的が粗いほうが読める。一方、画素の物差しは `scene` でも 0.012 以下で、白色化だけを外しても画素の符号は上がらない見込みである

読み直しの帰結は、的を粗くすることに加えて、当てはめの場面を増やすことと、$\alpha$ の範囲を定数の予測まで広げることが要る、である。

## 2. カテゴリの作り方

| 案 | 作り方 | 長所 | 短所 |
| -- | -- | -- | -- |
| A | 既存の Inception の画面全体の特徴の上位成分をクラスタにする | 新しい重みが要らない。上位 4 成分は目視で場面の種類に沿った（既存の数値） | 成分の数・$K$・クラスタの初期値が自由に選べる。都市をまたぐと、上位の成分が動画（カメラ・天気）の違いになる恐れがある（推測）。クラスタに名前が無く、意味は目視でしか確かめられない |
| B | Places365 の分類器のラベルを公式の階層でまとめる | カテゴリに名前があり、分け方が公開されている。選ぶ自由は階層の段だけ。歩行の動画（通り・広場・市場・屋内）は Places365 の対象そのもの | 新しい重み 1 つ。階層の表は Google のスプレッドシートで、リポジトリに写して固定する必要がある |
| C | 都市・動画の別をラベルにする | ラベルが無料で正確 | 動画の違いは天気・照明・カメラの色が大半で、`color` で当たる見込み（v2 の 3 と同じ理由）。動画を単位に組を分けると、採点の動画のクラスが当てはめに無い |
| D | セグメンテーションで空・建物・路面・植生などの占有率を出す | Codex さんの言う理想の形。四半分ごとの的が自然に作れる | 重みと実装の依存が大きい（torchvision の重みは 21 クラスで、空や建物が無い）。色で読める部分が大きく、「抽象的」の度合いが下がる（推測） |
| E | CLIP に文を与えてゼロショットで分類する | カテゴリを歩行の動画に合わせて作れる | 文の書き方が自由に選べる。依存が増える |

**推奨は B である。** ユーザーの決定は「粗い場面のカテゴリ」で、B はそれを、公開された分け方のまま使える。A と E は、通るまでカテゴリを作り直す余地が大きい。C は対照にもならない（動画を単位に分けると測れない）。D は `e1f` の的としては筋がよいので、12 節で触れる。

### B の入手と固定

- **重み**: `http://places2.csail.mit.edu/models_places365/resnet50_places365.pth.tar`（確かめた）。「The pretrained places-CNN models can be used under the Creative Common License (Attribution CC BY)」（確かめた）。コードは MIT（確かめた）
- **ResNet-50 を選ぶ理由**: 公開されている PyTorch の重み（AlexNet・ResNet-18・ResNet-50・DenseNet-161）のうち、torchvision の標準の構造にそのまま載り、精度が高い側である。ラベルの誤りは、どの符号にも同じだけ天井を下げる。計算は 2 分ほどで、軽いモデルにする理由が無い
- **固定**: Inception と同じ扱いにする。ダウンロードした日とファイルの sha256 をコードに書き、`.fleet/data/places365/` に置き、読み込むときに sha256 を確かめる。引用の文（CC BY の表示）を README と `exp/lib` の docstring に書く
- **前処理**: 公式のデモ（`run_placesCNN_basic.py`）は 256 への縮小、中央の 224 の切り出し、ImageNet の平均と標準偏差だったと記憶している（推測。実装のときにスクリプトを読んで合わせる）。320 px の正方形のフレームをそのまま入れる
- **階層の表**: 公式の「Scene hierarchy」のスプレッドシート（README からリンクされている。確かめた）を CSV にして、取得日と sha256 とともにリポジトリに入れる。第 2 階層は 16 個のグループで、1 つのクラスが複数のグループに入ることがあると記憶している（推測）。入手できない、または形が記憶と違うときは、止めて報告する
- **実装の確かめ**: 公式のデモ画像で、README に載っている上位のクラスが再現すること

### ラベルの作り方

1. 320 px のフレームから、365 クラスの softmax の確率 $p_c$ を出す
2. 階層の所属 $M_{cg}$（クラス $c$ がグループ $g$ に入れば 1）で、グループの確率 $q_g = \sum_c p_c M_{cg} / \sum_{g'} M_{cg'}$ を出す。複数のグループに入るクラスは等分するので、$\sum_g q_g = 1$ になる
3. ラベルは $\arg\max_g q_g$

365 クラスの 1 位をそのまま使わない理由は、`street`・`downtown`・`alley`・`crosswalk` のような近いクラスの間でラベルが揺れ、その揺れが「場面の種類」の違いではないためである。グループの確率の和は、この揺れを足し合わせて消す。

## 3. カテゴリの数と釣り合い

カテゴリを残す規則を、ラベルの分布を見る前に決めておく。

- グループ $g$ を残すのは、9 本の動画を合わせた割合が 5% 以上で、かつ 5 本以上の動画で割合が 1% 以上のとき。残したグループの数が $K$ である
- 残さなかったグループのフレームは、当てはめにも採点にも使わない。その割合を書く
- **止める条件**: $K < 3$、最大のグループが 70% を超える、使わないフレームが 30% を超える、のどれか。止めたら報告し、階層の段や閾値を替えて探さない

数値の理由は次のとおりである。どれも設計の選択で、理論から 1 つに決まる値ではない。

- 5%: 9 本で約 800 個の 60 秒のブロックがある（4 節）。5% で約 40 個になり、そのクラスの再現率の標準誤差が 0.08 ほどに収まる（導いた。$\sqrt{0.25/40}$）
- 5 本以上: 動画を 1 本抜いても、当てはめにそのクラスが 4 本以上残る
- 70%: 最大のクラスがこれを超えると、残りのクラスのブロックが合わせて 240 個を下回る

予想（推測）: 歩行の動画では「商業の建物・店・市場・街」と「屋外の交通（道路）」が大半を占め、「文化・歴史の建物」「公園・余暇」「水辺」「屋内の買い物と食事」が 5〜15% ずつ入る。$K$ は 4〜6（6 割）。最大のグループが 70% を超えて止まる確率は 2 割。

## 4. 組の分け方

**動画**: `manifest.json` の 10 本のうち、Wildlife を除く 9 本（Amsterdam・Bangkok・Chiang_Mai・Istanbul・Kuala_Lampur・Singapore・Stockholm・Venice・Zurich、合わせて 48227 秒）。Wildlife を除く理由は、街の歩行でない唯一の動画で、カテゴリが動画の別と重なるためである。9 本とも 64 px のデータは用意されている（学習は Zurich を除く 479350 個の単位から引いている。既存の数値）。

**格子**: 各動画の 2 秒おきの stack（約 24100 個）。stack は 0.8 秒なので、隣とフレームを共有しない。高解像度のフレームは、各 stack の最後のフレームを、既存の `hires prepare`（RGB の順序、位置の確かめ (a)〜(c) つき）で切る。

**入れ子の交差検証**（動画が単位）

- 外側: 動画 $v$ を採点に回し、残りの 8 本で当てはめる。9 通り。どのフレームも、ちょうど 1 回採点される
- 内側: 残りの 8 本の中で、1 本を抜いて 7 本で当てはめ、抜いた 1 本で採点する（8 通り）。8 通りの予測を合わせた balanced accuracy が最大の $\alpha$ を選び、8 本で当てはめ直す
- 前の calib・sel・final の 3 分割は使わない。長い run の設定はユーザーの決定で既に決まっており、$m$ で選ぶものは $\alpha$ だけになったためである。L2・L3 の「final」は、外側の採点を合わせたものに読み替える

**時間の相関**: 当てはめと採点が別の動画なので、同じ場面が両方に入ることがない。区間の先頭を 30 秒捨てる処置は要らない。

**独立な場面の数**: 48227 秒は、60 秒のブロックで約 800 個である（導いた。ラベルの相関時間が的と同じ 30 秒ほどなら）。2 回目の当てはめの約 100 個、採点の約 20 個（sel の 1238 秒）から、どちらも 1 桁近く増える。Zurich だけで採点すると 65 個で、balanced accuracy の標準誤差は 0.05 を超える見込みである（推測）。これが、採点を 9 本に広げる理由である。

**JEPA が見た動画で採点すること**: 9 本のうち 8 本は JEPA の学習に使った動画である。ラベルは学習に使っていないので、線形 probe としては ImageNet の慣行と同じ形である。ただし step 0・6000・60000 で、同じフレームを見た回数が 0・約 1.6・約 16 回と違う（導いた。768 万 stack / 479350 単位）。そこで、Zurich だけの値を必ず並べ、次の読み方を先に決めておく。

- $\Delta = m(60000) - m(6000)$ を、Zurich と、残りの 8 本で別々に出す。8 本の $\Delta$ が Zurich の $\Delta$ を、差の $2\,\mathrm{SE}_{\mathrm{blk}}$ を超えて上回ったら、「伸びの一部は、学習で見た動画に限られる」と書く。判定（L2・L3）は変えない

## 5. 読み出し

- **形**: 符号を当てはめの組の平均と標準偏差で標準化し、one-hot のラベルへ ridge で回帰する。予測のラベルは出力の最大。Imagenette の probe（README 1869 行）と同じ形である
- **クラスの重み**: クラス $k$ の標本に $1/(K n_k)$ の重みをつける。balanced accuracy を最大にする決め方は、事前確率を一様にしたときの事後確率の最大である（導いた。再現率の平均は、各クラスの中での正解率の平均だから）。重みつきの最小二乗は、その事後確率の最良の線形近似を当てはめる
- **$\alpha$ の格子**: $\alpha = c \cdot \mathrm{tr}(X^\top W X)/D$、$c \in \{10^{-6}, 10^{-5.5}, \dots, 10^{3}\}$ の 19 点。$c = 10^3$ では予測がほぼ定数になるので、格子は「縮めない」から「定数」までを覆う。同点は大きい $\alpha$ を選ぶ
- **端の扱い**: 下端に当たったら格子が足りないので止める。上端に当たった符号は「読めない」と書く（定数の予測が最良という意味で、格子の誤りではない）
- **線形にする理由**: SIGReg は $z$ を等方的なガウスに寄せる。LeJEPA の主張は、その分布が線形の下流の課題の最悪の誤差を小さくする、である。学習目的が保つはずの形で測る（`feedback_eval_matches_objective.md`）
- **ロジスティック回帰にしない理由**: 反復の止め方という自由度が増える。閉じた形の ridge は決定的で、$\alpha$ の全部の値を 1 回の固有値分解で出せる

## 6. 採点と偶然の値

- **主**: balanced accuracy（クラスごとの再現率の平均）。外側の 9 通りの予測を合わせた 1 つの混同行列から出す
- **偶然の値**: ちょうど $1/K$。ラベルと独立な予測では、クラス $k$ の再現率が $P(\hat y = k)$ になり、その平均は $1/K$ である（導いた）。`mean`（定数の符号）は出力がすべて同点になり、同点を先頭のクラスに倒すと、ちょうど $1/K$ になる
- **天井**: one-hot のラベルそのものを符号にすると、縮めても最大の位置は変わらないので、ちょうど 1 になる（導いた）
- **副（並べるだけ）**: クラスごとの 1 対他の AUC の平均（最大をとる処理によらない）、動画ごとの balanced accuracy、Zurich だけの値
- **対数尤度を使わない理由**: ridge の出力は確率ではない。確率のモデルにすると、都市ごとの較正のずれが点数を決め、上限の無い罰が少数のフレームに集まる
- **中心化はしない**: 2 回目は予測と的から採点の組の平均を引いた。今回は引かない。都市をまたいで同じ決め方で当たることが、測りたい性質そのものである

## 7. 物差しと、見分けられる見込み

**符号**: 長い run の $z$（主）。並べるだけのものとして `z_k3` と `h_mean`。

**物差し**: `mean`、`label`（one-hot、天井）、`color`、`color8`、`pca16`〜`pca1024`、`v16`・`v17`、`init_c`（各 run の step 0）、`inc64`（64 px の Inception pool3）、`places64`（ラベル付けと同じ ResNet-50 に 64 px のフレームを拡大して入れた、最後の層の前の特徴）。

- `inc64` は、2 回目では的と同じネットだったので参考に下げた。今回は的が Places365 の ResNet になるので、`inc64` は**的と別のネット・別のデータで学んだ意味の特徴**として使える
- `places64` は的と同じネットなので、上限の参考にとどめる

**見込み**（既存の数値からの類推。推測）

- Imagenette の線形 probe（10 クラス、偶然 10%）は、`color` 38.5、V18c の $z$ 39.0〜40.4、`h_mean` 47.1〜52.3、F の `h_mean` 58〜59 だった（既存の数値）。同じ形の読み出しで、色だけの符号も偶然の 4 倍近く当たり、符号の間に 20 ポイントの幅がある
- 場面のカテゴリは Imagenette の物体より粗く、色と大まかな配置で分かる部分が大きい（屋内は暗い、水辺と公園は色が違う）。$K$ = 5 なら、`color` は 0.35〜0.50、`inc64` は 0.55〜0.75、`places64` は 0.65〜0.85 とみる
- 標準誤差: 5% のクラスの再現率の誤差 0.08 が、balanced accuracy には $0.08/K$ で入る。全体で 0.02〜0.03、同じフレームで比べる対の差で 0.008〜0.015、$\delta_w$ は 0.016〜0.03 とみる
- したがって、`color` から `inc64` までの幅（0.15〜0.3）は $\delta$ の 10 倍前後で、物差しは見分けられる見込みである（7 割）
- **run どうしは別である。** $z$ の Imagenette は全部の run で 39.0〜40.4 で、step 0 の 39.9 から動かなかった。同じことが起きれば、$m(z)$ の run の間の差は 0.01 前後で、$\delta_w$ の中に入る。L2・L3 が 2 seed とも成り立つ確率は、どちらの学習率でも 3 割とみる

**予想される順**: `mean`（$1/K$）< `color` ≲ `color8` ≈ `pca`・`v16`・`v17` ≈ `init_c` ≈ 長い run の $z$ < `h_mean` < `inc64` ≤ `places64` < `label`（1）。「≈」の中の順は予想しない。

## 8. 有効性の確かめ

物差しだけで、長い run の値を読む前に確かめる。JEPA が上に来ることは条件に入れない。

| 名前 | 条件 | 根拠 | 前回との対応 |

| V-c0（データとラベル） | 新しく切る動画で、高解像度のフレームの位置の確かめ (a)〜(c) が通る。重みと階層の表の sha256 が合う。公式のデモ画像の上位クラスが再現する。3 節の止める条件に当たらない | 実装とデータの誤りを先に除く | V-m0 の (a)〜(c) を活かす。`shift_top1` は外す（候補に自分が入る誤りがあり、的がラベルになったので役目も無い） |

- どれか 1 つでも外れたら、$m$ を判定に使わず、止めて報告する。カテゴリ・$K$・閾値を替えて探さない

## 9. 閾値

- **$\mathrm{SE}_{\mathrm{blk}}$**: 前回と同じブロックのブートストラップ（2000 回、全符号で同じ引き方、比べる 2 つを対でとる）。ブロックは動画ごとに切り、動画の中で引き直す。$L$ はラベルの指示変数の自己相関から、前回と同じ式 $L = \min(\max(\lceil 2\tau \rceil, 16), L_{\max})$ で 1 回決める。$L_{\max}$ は、最も短い動画（Zurich、約 1950 個）に 8 ブロックを残す 243 個
- **$\delta_w = \delta_{yy} = 2\,\mathrm{SE}_{\mathrm{blk}}$**: 登録済みの式のまま。L2・L3 は同じ run の step どうしなので $\delta_w$ で読む
- **$\sigma_{\mathrm{seed}}$**: 長い run の 6 設定 × 2 seed の、step 60000 の $m$ の設定の中の分散を合わせたもの（自由度 6）。run と物差しを並べる $\delta_y$ にだけ使う。判定には入らない
- **ブートストラップが見ない誤差**: 当てはめの組の引き方による揺れは入らない。V-c4 の 9 個の散らばりと、V-c7 が、その見落としの確かめを受け持つ

## 10. 計算量（推測）

- 高解像度のフレーム: 9 本を `hires prepare` で切る。前回は 3 本で 2.5 分（既存の数値）なので、CPU で約 10 分。約 24100 枚で 7.4 GB（評価専用の `hires-…`）
- ラベル: ResNet-50 に、320 px・64 px の拡大・3 つの変換・4 つの四半分で 24100 × 9 枚ほど。4090 で数分
- 符号: checkpoint ごとに 24100 個の stack を通す。数秒
- 読み出し: 1 つの符号につき、1024 次元の固有値分解が 81 回（外側 9 × 内側 8 + 当てはめ直し 9）。動画ごとのグラム行列を足し合わせて作れば、1 つの符号で 20 秒ほど
- 全体: 12 本 × 9 checkpoint × 3 符号と、物差し・はしご・帰無を合わせて約 400 個の符号。4090 の 1 枚で 1〜2 時間。長い run が使っていない GPU に 1 本ずつ置く

## 11. 2 回目の失敗を繰り返さない理由

| 2 回目の原因 | 今回の対処 |

## 12. `e1f` の的

**作れる。ただし主の指標より弱い根拠で、確かめを別に置く。**

- **的**: 隠す四半分 $Q_q$ の 160 px の切り出しに、同じラベル付けをかけたもの。カテゴリは四半分ごとに、3 節と同じ規則で残す（$K_q$）
- **入力と読み出し**: 登録済みの `e1f` のまま（`pred`・`pool`・`pred_k3`・`vis_color`・`oracle`・`mean`、どれも自分の入力で当てはめ直す）。組は 4 節の入れ子の交差検証、採点は balanced accuracy、4 つの $q$ の平均を 1 つの値にする
- **読み方**: C1′・C4′ は式を変えずに、$m$ をこの値に読み替える
- **確かめ**: V-E1′1・V-E1′2 はそのまま。V-E1′3 は「`mean` がちょうど $1/K_q$。`pred_k3` と `pool` で予測のラベルが食い違う数が 0」に、V-E1′4 は「step 0 の `oracle`（$k$ = 4）が $1/K_q$ を $\delta_w$ を超えて上回る」に読み替える。加えて、四半分のラベルに V-c2 をかける。外れたら `e1f` を読まない
- **弱い点**: 四半分の切り出し（建物の上部と空だけ、路面と人だけ）は「場面」ではなく、Places365 の学習の分布から外れる。ラベルが安定しない恐れがある（推測。V-c2 が外れる確率は 4 割）。四半分のラベルは画面全体のラベルから当たる部分が大きいとみられ、`pred` と `pool` の差は小さく出る（推測）
- **筋のよい的は案 D**（四半分の中の空・建物・路面・植生・人の占有率）である。「隠した四半分に何があるか」を直接表し、Codex さんの言う理想の形でもある。ただしセグメンテーションの重みと実装が要るので、四半分のラベルの確かめが外れたときに、ユーザーに諮る次の手とする。自動では替えない
- **副の量**: 全体を見た $z$ から四半分のラベルを読む値（4 つの平均）を、`z` と `z_k3` で並べる。主の $m$ が見ない「配置の情報」の目安になる。判定には使わない

## 13. 弱点と、この提案で言えないこと

1. **run どうしを分けられない見込みが 5〜6 割ある**（7 節）。有効性を通って差が出なければ、「この目的と設定では、場面のカテゴリの線形の読みやすさは学習で変わらない」という結果になる。物差しを 4 回目に作り直す理由にはしない
2. **$m$ は K3 を見分けない**（8 節）。$m$ だけで run を良いと言わない
3. **ラベルは教師ありの分類器の出力で、正解ではない。** V-c2 は安定を確かめるが、正しさは確かめない。目視（カテゴリごとに 16 枚）を、数値を読む前に 1 回見ることを勧める。目視は合否に使わない
4. **線形の読み出しは、次元の大きい符号と、情報を線形でない形で持つ符号に辛い。** 判定（L2・L3）は同じ 1024 次元の $z$ どうしなので、次元の不利は打ち消される。次元の違う物差しとの比べは、並べるだけにする
5. **8 本は JEPA が見た動画である**（4 節）。読み方の規則で分けて書くが、Zurich だけの値は誤差が大きく、単独では判定できない
6. **階層の表の中身を、私は今回読んでいない。** 第 2 階層が歩行の動画で 3 節の止める条件に当たる確率を 2〜3 割とみる。当たったら止めて報告する
7. カテゴリの割合は都市で違う。balanced accuracy と重みで事前確率の違いは除くが、同じカテゴリの見え方が都市で違う分（アジアの市場と欧州の市場）は、点数に入る。これは測りたい性質の一部とみる
