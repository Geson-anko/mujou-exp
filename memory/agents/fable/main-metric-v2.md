# V18c の主の指標 m の作り直しと、E1 の修理（提案、2026-11-25）

前回の [out-of-view-eval.md](out-of-view-eval.md) の続きである。コードは書いていない。読んだのは `exp/vision/README.md` の V18c の 4 節、`plans/jepa.md` の V18c の節、`results/v18c/judge.json`、`runs/` の `posthoc_gen/rows/`、`exp/lib/metrics.py`・`readout.py`・`regions.py`・`tours/wide.py`、`exp/vision/gen_eval.py`・`fill_eval.py` である。今回は文献を新しく読んでいない。

確かさは 3 段階に分ける。

- **既存の数値**: `runs/` と `judge.json` にある値
- **導いた**: 定義・不等式・このリポジトリのコードから論理で出した。数値では確かめていない
- **推測**: 実データでどうなるかの予想、計算時間の見積もり

## 0. 要点

1. **推奨は、生成を通さない直接の読み出しである。** 符号 $z$ から、**元の解像度（480 px）の画像を Inception に通した特徴**を、容量を固定した ridge で読む。的は四半分ごとの pool3 を並べたもの（場面の中身と、どの四半分に何があるか）。主の指標 $m$ は、Zurich の格子の上の中心化した $R^2$（`sem_r2`）にする。生成（拡散のデコーダ）は、絵と裏づけに回す。E1 と E1g を分けたときと同じ分け方である
2. 前の $m$ が弱かった原因は 2 つに分けられる。(a) 64 px の生成画像 1 枚の Inception の特徴は、自分の本物からも他の候補の本物からもほぼ同じだけ遠い（`feat_ratio` は `pca` でも 0.945。既存の数値）。符号の情報より、サンプルの雑音と共通のずれが大きい。(b) Inception は 299 px で学んだネットで、64 px や 32 px を拡大した入力は苦手である（32 px の切り出しは `oracle` からも読めず `r2` −0.02。既存の数値）。推奨案は (a) を生成を外すことで、(b) を的を高解像度にすることで外す
3. 候補を複数の都市に広げる案は採らない。動画どうしの違いは、天気・照明・カメラの色という動画ごとに一定の量が大半で、`color` でも当たると見込まれる（推測）。同じ動画の中で比べるほうが、場面の中身を測れる。「配置の細部を要求する」問題は、候補ではなく**的**（領域の中で平均をとった特徴）と**採点**（最近傍の 1 位ではなく $R^2$）を替えて外す
4. 物差しの序列は、理論で順序が決まるもの（入れ子の画素の PCA、厳密な K3 の上限 $16/64$、定数の 0）と、「意味を持つ 64 px の符号」の上限（64 px の本物の Inception の特徴 `inc64`）で確かめる。JEPA が上に来ることは、有効性の条件に入れない（入れると、JEPA が勝つまで物差しを直すことになる）
5. **M は負の対照に使わない。** 既存の数値では、M は情報の量を測るどの物差しでも健全な run と同じか上にいる（四半分の色の `oracle` 0.76 に対し P16・F の 60000 は 0.29〜0.43）。$m$ でも M は下に来ないと予想する。崩壊の検出は K1〜K3 と修理した `swap` の役目のままにし、$m$ の側は合成した厳密な K3 で確かめる
6. E1 の `shuf` の偏りは、動画の時間の構造で説明できる（導いた）。候補ごとの平均を引くと、ずらし幅についての内積の和は恒等的に 0 になる。ずらし 0 と近いずらしが正なら、遠いずらしは負に寄る。しかも「26 か所で外れた」は 26 回の独立な出来事ではなく、同じ的と同じずらし 256 を使った 1 回の出来事の繰り返しである。確かめは、$n \times n$ の内積の行列 1 枚から全部のずらしの `swap` を出すだけで済む
7. 厳密な K3 の対照は、実データのトークンを**位置の平均で置き換えた**符号にする。`swap` がビットまで引き分けになるうえ、「場面だけを表す符号・予測器がどこまで当てるか」の基準にもなる。条件 1 は「`pred` が `mean` を上回る」から「`pred` が `pred_k3` を上回る」に強める

## 1. 何が弱かったのか（既存の数値から）

`runs/v18c-gen/yardsticks/posthoc_gen/rows/` と長い run の `posthoc_gen/rows/` の値を並べ直す。

| 符号 | `top1` | `top5` | `hard_top1` | `feat_ratio` | `pick_max` |
| -- | -- | -- | -- | -- | -- |
| `uncond` | 0.002 | 0.011 | 0.028 | 1.132 | 0.096 |
| `color` | 0.014 | 0.059 | 0.062 | 0.987 | 0.097 |
| `pca` | 0.023 | 0.087 | 0.079 | 0.945 | 0.099 |
| `v16` | 0.024 | 0.095 | 0.082 | 0.931 | 0.088 |
| P16 の 60000 の `z`（seed 0 / 1） | 0.009 / 0.012 | 0.050 / 0.044 | 0.055 / 0.049 | 0.999 / 1.000 | 0.091 / 0.092 |
| M の 60000 の `z` / `z_w` | 0.010 / 0.013 | 0.049 / 0.059 | 0.056 / 0.062 | 0.989 / 0.972 | 0.086 / 0.089 |

- $\sigma_{\mathrm{seed}}$ は `top1` 0.0016・`feat_ratio` 0.0040、$\sigma_{\mathrm{dec}}$ は 0.0014・0.0031（`judge.json`）
- **読み 1（既存の数値）**: `feat_ratio` は、生成と元の本物の特徴の距離を、本物どうしの距離で割ったものである。`pca` と `v16` でも 0.93〜0.95 で、生成画像の特徴は自分の本物に、別の候補の本物とほとんど同じだけ遠い。E1g では同じ生成画像を色で採点すると 0.46〜1.0 当たるので、符号の情報は画像には入っている。失われるのは Inception の特徴に写すところである
- **読み 2（導いた）**: 生成の特徴を $g_{ij} = s(c_i) + b + \xi_{ij}$ と書く（$s$ は符号で決まる分、$b$ は全候補に共通のずれ、$\xi$ はサンプルの雑音で決まる細部）。`_draw` は候補とサンプルごとに別の雑音を引くので、$\xi_{ij}$ は候補ごとに独立である。最近傍は $\arg\max_l \cos(g_{ij} - \bar r, r_l - \bar r)$ で、$b$ はどの問いにも同じ候補を推し（hub、`pick_max` 0.09〜0.11）、$\xi$ は問いごとに無関係な候補を推す。`top1` は $\lVert s \rVert^2$ と $\lVert b \rVert^2 + E\lVert \xi \rVert^2$ の比で決まり、符号の情報の差は分子の小さな差にしか出ない
- **読み 3（既存の数値）**: 幅を閾値の単位で見ると、`top1` は `uncond`〜`pca` の 0.021 が $\delta_w$（約 0.007）の 3 倍、`feat_ratio` は `uncond`〜`v16` の 0.20 が $\delta_w$（約 0.011）の 18 倍ある。連続の量のほうが目盛りは細かい。ただしどちらでも、学習した JEPA は `color` と同じ所に、M は健全な run と同じ所にいる。採点の形を替えるだけでは、JEPA と `color`、健全と M は分かれない
- **読み 4（既存の数値）**: 直接の読み出しは、同じ 512 個の候補でも幅が 1 桁広い。E2 の `color` の的の `id_easy` は `v16` 0.179・`pca` 0.166・`init` 0.107〜0.129・`color` 0.076・JEPA 0.017〜0.076、`r2` は 0.11〜0.52 である。E1 の `oracle` の四半分の色は 0.95（学習前）〜0.29（F の 60000）まで動く

## 2. 「抽象的な特徴」を、測れる形に定義する

前回の 1.1 節と同じ立場をとる。符号は入力の関数なので、情報の量では入力の画素そのものに勝てない。測れるのは「容量を固定した読み出しで取り出せる形になっているか」である。今回はそこに、的の選び方を足す。

- **的は、64 px の画素の関数ではなく、場面の関数にする。** 同じフレームの元の解像度の画像 $x^{\mathrm{hi}}$（中央の 480×480）を、299 px で学ばれた Inception に通した pool3 を的にする。全体は 480 → 299 の縮小、四半分は 240 → 299 の 1.25 倍の拡大で、どちらもネットが学んだ入力の範囲にある。いまの `incep` の的は 32 px を 9.3 倍に拡大していた
- **pool3 は 8×8 の特徴の地図の平均**なので、切り出しの中の位置を持たない。数画素のずれや細い線の位置は的に入らない。的が表すのは「この四半分に、どういう種類のものがあるか」である（導いた。平均の層の定義から）
- **場面と配置を、1 つの的の中で分ける。** 四半分 $q$ の特徴を $y_q$ として、場面の分 $\bar y = \frac14 \sum_q y_q$ と、配置の分 $y_q - \bar y$ に直交に分けられる。全トークンが同じ内容を持つ符号（K3 の族）は、場面の分は持てても、配置の分は場面との相関を通してしか読めない
- 符号は 64 px の stack しか見ていないので、的のうち 64 px から分からない部分は、どの符号からも読めない。どこまで読めるかの上限は、64 px の本物のフレームを Inception に通した特徴 `inc64` を符号とみなして、同じ読み出しに通して測る（データ処理不等式の右辺を、同じ読み出しで見たもの）

## 3. 検討した案

### 案 D（推奨）: 符号から、高解像度の Inception の特徴を直接読む

**的**（checkpoint によらないので 1 回だけ作る）

- 各 stack の最後のフレームについて、元の動画から中央の 480×480 を切り直す。保存は 320×320（64 px のちょうど 5 倍）にする。`exp/lib/tours/wide.py` と同じ流儀で、評価専用の別のデータにし、既存の `data_version` は変えない。位置の確かめは、5×5 の平均で 64 px に戻したものが既存のデータと画素値で ±2 以内に合うこと（480 → 320 → 64 の 2 段の丸めがあるので、バイトの一致は求めない）
- 要るのは当てはめの組（約 6000）・calib（1024）・Zurich の格子（3899）の最後のフレームだけで、約 1.1 万枚、3.3 GB になる
- 四半分の 4 枚（160×160 → 299）と全体（320 → 299）を Inception に通す。約 5.5 万枚
- **主の的 $Y$**: 四半分の pool3 を並べた 8192 次元を、当てはめの組の PCA で $K$ = 64 成分にし、成分ごとに当てはめの組の標準偏差で割る（白色化）。既存の `Space.fit` と違うのは、全成分に 1 つの尺度ではなく成分ごとの尺度にする点だけである。理由は下の K3 の上限と、分散の大きい 1〜2 成分（明るさ・空の量と思われる。推測）が $R^2$ を決めてしまうのを避けるため
- **副の的**: 全体の pool3 の PCA 32 成分（`scene`）と、E2 の左右の帯の高解像度版（180×480 → 299、`out`）

**読み出しと採点**

- 符号（1024 次元。超えるものは既存の `Reducer` で 1024 に）→ $Y$ の ridge。当てはめは span の組、$\alpha$ は Zurich の calib で選ぶ。`readout.select_ridge` をそのまま使う
- **主の指標 `sem_r2`**: Zurich の格子の全 stack（3899）で、予測と的のそれぞれから格子の上の平均を引いたうえで、成分ごとの $R^2$ を 64 成分で平均する。$m = \frac{1}{K} \sum_k \bigl(1 - \sum_i (\tilde y_{ik} - \hat{\tilde y}_{ik})^2 / \sum_i \tilde y_{ik}^2\bigr)$
  - 平均を引く理由は `identification` と同じである。学習の動画と Zurich のずれは全 stack に共通で、符号ごとに読み出しを通った大きさが違う。引かないと、step 0 の `pred` の `r2` が −10 になったような、定数のずれだけで決まる値が混ざる
  - $R^2$ にする理由: ridge の当てはめの損失そのものである。最近傍の 1 位と違って hub が起きず、当たり外れの 2 値でないので目盛りが細かい。checkpoint が決まれば決定的に計算でき、デコーダの乱数（$\sigma_{\mathrm{dec}}$）が無い
- 副: 同じ予測で `id_easy`・`id_hard`（既存の `fill_eval.score`）、場面の分と配置の分に分けた $R^2$、`scene`、`out`

**理論で決まる値**（導いた）

- 定数の予測（`mean`、条件なし）: 中心化した予測が 0 なので、$m$ はちょうど 0
- **厳密な K3**（$t_{n,p} = A_p u_n$、$u_n \in \mathbb{R}^{16}$）: $z = W \mathrm{vec}(t)$ はランク 16。線形の読み出しの予測は、64 次元の的の空間の中の 16 次元以下の部分空間に入る。的を白色化してあるので、当てはめの組の上では $\sum_k R^2_k \le 16$、つまり $m \le 16/64 = 0.25$。Zurich では的の共分散が単位行列からずれるので、上限は近似になる（合成の対照で直接測る）
- **入れ子の画素の PCA**: `pca16` ⊂ `pca64` ⊂ `pca256` ⊂ `pca1024` は部分空間が入れ子なので、$\alpha$ を選んだ ridge の $m$ は、推定の誤差を除いて $k$ について減らない

**利点と弱点**

- 利点: 1 checkpoint が 1 分以内。掃引の 15 本 × 保存した 5 つの step と、既存の 17 個の checkpoint、物差しの全部にかけられる。seed を足した run にもすぐかけられる
- 弱点 1: 線形の読み出しは、情報を線形のまま持つ符号（画素の PCA、学習前のランダムな ViT）に甘い。$m$ は「JEPA に固有の力」ではなく「符号が持つ抽象的な特徴の量」を測る。JEPA に固有の力（見えない部分の補完）は、同じ的を使う E1 と `out` で別に見る
- 弱点 2: 的が Inception（ImageNet の教師あり）である点は前回と同じ
- 弱点 3: 帯のときと同じく、元の動画からの切り直しが要る

### 案 G′: 生成 + Inception の枠を保ち、採点を直す

デコーダの ckpt は NAS にあり、サンプリングは 1 個 154 秒なので、既存の 43 個はデコーダを学び直さずに採点し直せる（生成の特徴は保存していないので、描き直しは要る）。1 節の式から、直す所は 3 つある（導いた）。

1. **サンプルの平均の特徴で当てる**: $\bar g_i = \frac1K \sum_j g_{ij}$。$\xi$ の分散が $1/K$ = 1/8 になる
2. **生成の側は生成の平均で中心化する**: $\bar g_i - \frac1n \sum_i \bar g_i$。共通のずれ $b$ がちょうど消える。いまは本物の平均 $\bar r$ を引いているので $b$ が残る
3. **1 位ではなく連続の量で採点する**: 自分の本物の順位の平均（偶然 0.5）や、中心化した特徴どうしの $R^2$

候補の数と間隔（512 個、7〜8 秒）は変えない。

- 利点: ユーザーの元の希望の形のまま。線形でない情報も、デコーダが画像にできれば拾う
- 弱点: (i) 直しても 64 px の生成画像を拡大して Inception に通す点は残る。デコーダが雑音から作った質感を Inception が読む。(ii) 1 つの符号に 18〜20 分かかり、$\sigma_{\mathrm{dec}}$ が要る。(iii) 既存の数値では JEPA ≈ `color`、M ≈ 健全で、1〜3 でこの並びが変わる根拠は無い。(iv) どれだけ良くなるかは、回すまで分からない（推測すらできない）

### 採らない案

- **候補を複数の都市・場面にまたがらせる**: 動画どうしの違いは動画ごとに一定の量（天気・時刻・カメラ）が大半で、`color` で当たると見込む（推測）。同じ動画の中で比べれば、それらは候補どうしで共通になり、残るのが場面の中身である。前回 `id_hard` を同じ場面の前後にとったのと同じ理由である。確かめたければ、案 D の副の量として、学習の動画の held-in の窓でも `sem_r2` を出せば足りる
- **Imagenette の線形 probe を主にする**: 掃引の step 6000 では、`h_mean` は学習率だけで決まり（$10^{-4}$ で 47.1〜47.5、$10^{-5}$ で 52.2〜52.3）、$\lambda$ と $r$ では 0.4 ポイントしか動かない（$\delta_a$ = 2.3）。$\lambda$ と $r$ を選ぶ物差しにならない。$z$ は 39.0〜40.4 で `color`（38.5）と変わらない。物体の位置が画像ごとに違う Imagenette では、位置を並べた符号の線形 probe は効かないためと読む（推測）。副の量のままにする
- **64 px のフレーム全体の Inception の特徴を的にする**: 切り直しが要らず、`real_shift` 0.84 から候補を見分ける力はある。しかし的が 64 px の画素の関数になり、`inc64` という上限の対照が作れない。切り直しができないときの代わりにとどめる
- **自分の符号の空間での、時間の近さの検索**: 外部の的が無く、ゆっくり変わる成分（明るさ）だけの符号で高くなる

### 推奨

**案 D を主の指標にし、案 G′ は絵と裏づけにする。** 理由は 3 つある。(1) 弱さの 2 つの原因を両方外すのは案 D だけである。(2) 順序が理論で決まる対照を持てる。(3) 安いので、seed の揺れと学習の曲線（step 0 → 6000）を直接測れる。掃引は seed 0 の 1 本ずつしか無く、$\sigma_{\mathrm{seed}}$ を測る手段が要る。

G′ は、長い run を選んだあとで、選んだ設定と物差しの絵を資料に載せるときに使えば足りる。先に軽く試すなら、物差しの `uncond`・`color`・`pca` の 3 個を描き直して 1〜3 を当てはめる（3 個で約 15 分）。

## 4. どれが上に来るか（予想と理由）

| 符号 | 予想 | 根拠 |
| -- | -- | -- |
| `mean`・条件なし | ちょうど 0 | 定義（導いた） |
| 合成した厳密な K3（V18c、$d$ = 16） | 0.25 以下。元の符号より下 | ランクの上限（導いた） |
| `color` < `color8` < `pca` | この順 | 4×4 の色 → 8×8 の色 → 画素、と情報が増える。E2 の `r2` でも `color` 0.39 < `pca` 0.52（既存の数値） |
| `pca16` < `pca64` < `pca256` ≤ `pca1024` | この順。どこかで頭打ち | 入れ子（導いた）。頭打ちの位置が「$m$ が求める細かさ」を表す |
| `v16`・`v17`・`init_m` | `pca` と同じ程度 | E2 の `r2` が 0.51〜0.52 で並ぶ（既存の数値） |

**M と健全な run を見分けられるか**、という問いへの答えを分けて書く。

- **厳密な K3** は、ランクの上限で分かれる（導いた）
- **V18b の M** は、$m$ では下に来ないと予想する。V18b で M を崩壊と判定した根拠は、位置ごとに違う成分の分散の割合（`rho_in` 0.08）と `token_r2` 0.90 で、情報の量ではなかった。分散が小さくても ridge は拾う（README の V-E3 の調べと同じ読み）。M が健全な run と違うのは、Imagenette の `h_mean`（47.3〜47.9% に対し F は 58.3〜59.4%）と、トークンの統計である
- したがって、$m$ に「M を下に置く」ことを求めない。長い run の候補はすでに K1〜K3 を通った run に限られるので、崩壊の検出は $m$ の前段のままでよい。$m$ の側で確かめるのは、厳密な K3 を下に置くことと、位置ごとの成分を少しずつ戻したときに単調に上がること（6 節の $\varepsilon$ のはしご）である

## 5. 閾値・有効性の確かめ・選び方

### 揺れと閾値

- **標本の誤差**: Zurich は 1 本の動画で、隣の stack は相関する。格子を 64 個（約 1 分）ずつのブロックに分け、ブロックを復元抽出するブートストラップで、2 つの符号の $m$ の差の標準誤差 $\mathrm{SE}_{\mathrm{blk}}$ を出す。ブロックの長さは、6 節のずらしの曲線で相関が消える幅を見てから確定する
- **seed の揺れ $\sigma_{\mathrm{seed}}$**: 掃引は seed 0 だけなので、次の 2 つから求める。(a) 旧 checkpoint の seed の違う 8 組（P16・F × step 0・6000・20000・60000）。有効性の確かめの段で使う。(b) 掃引の設定の seed 1 を 4 本足す（学習率 $10^{-4}$ と $10^{-5}$ のそれぞれで 2 設定。6000 step は 1 本 10〜13 分）。選ぶ段ではこちらを使う
- **1 seed どうしの比べ**: $\delta_{\mathrm{sel}} = 2\sqrt{\mathrm{SE}_{\mathrm{blk}}^2 + 2\sigma_{\mathrm{seed}}^2}$。物差し（seed が無い）との比べは $\delta_y = 2\sqrt{\mathrm{SE}_{\mathrm{blk}}^2 + \sigma_{\mathrm{seed}}^2}$

### 有効性の確かめ（掃引にかける前に、物差しと旧 checkpoint だけで満たす）

| 名前 | 条件 | 外れたとき |
| -- | -- | -- |
| V-m0（的） | 切り直しの位置が合う。高解像度の的で、1 秒後の本物が元を 512 個から当てる割合が 0.5 以上 | データか的の誤り。読まずに調べる |
| V-m1（0 点） | `mean` がちょうど 0。予測を候補 64 個以上ずらした組の $m$ が 0 + 2 SE 以下 | 実装の誤り |

- 細部を求めていないことの目安として、`color8` と `pca64` の $m$ が `pca1024` のどれだけの割合かを書く（条件ではなく記述）

### 掃引への当てはめ（学習率ごと）

1. 対象は K1〜K3 を通った run の step 6000 の $z$。学習率 $10^{-4}$ は 9 本（$\lambda$ × $r$）、$10^{-5}$ は 3 本（$r$ = 0.5、判定保留だが候補）。step 0・1000・2000・4000 にもかけて曲線を出す（選ぶのには使わない）
2. $m$ が最大の run を選ぶ。最大から $\delta_{\mathrm{sel}}$ 以内の run は同点とする
3. 同点の中では、順に: (i) 高解像度の帯の `out` の $R^2$（マスクを使わないので $r$ どうしで比べられる。ユーザーが JEPA に求める「見えない所を補う」に対応する）、(ii) $\lambda$ が大きいもの（学習の側の導出 6: 見えるトークンで分け持つ大域の解を目的の最小値から外すのは $\lambda$ = 0.95 だけ）、(iii) 事前登録の `pred_ratio_calib`
4. `pred_ratio_calib` を先頭の同点決めにしない理由: $r$ が小さいほど課題が易しく、$\lambda$ が小さいほど予測の重みが大きいので、機械的に $r$ = 0.25・$\lambda$ = 0.5 を選ぶ（掃引の表でどの $\lambda$ でも $r$ = 0.25 < 0.5 < 0.75）
5. 選んだ設定と次点には、長い run の前に seed 1 の 6000 step を足し、順序が $\delta_{\mathrm{sel}}$ を超えて入れ替わらないことを確かめる

長い run の判定（$m$(60000) が $m$(6000) と $m$(`init_c`) を $\delta_m$ を超えて上回る）は、$\delta_m$ を同じ run の中の比べ $2\,\mathrm{SE}_{\mathrm{blk}}$ と、物差しとの比べ $\delta_y$ に読み替えれば、そのまま使える。

### 言えること・言えないこと

- $m$ が `pca` と `init_c` を超える → 「学習で、場面の中身と大まかな配置が、線形に取り出せる形になった」
- $m$ が `init_c` 以下 → 「高解像度の意味の特徴についても、学習前より取り出しにくい」。物差しの作り直しは今回で 2 度目なので、有効性の確かめを通った $m$ がこう出たら、それを結果として読むことを先に決めておくのがよい
- $m$ が高くても、JEPA に固有の力（補完）は言えない。それは E1（`pred` と `pred_k3` の差、`swap`）と `out` で読む
- $m$ は予測器を見ない。予測器の質は E1 で見る

## 6. E1 の修理

### `shuf` の `swap` が 0.5 より下にずれる原因の仮説

`_swap_rows` の `shuf` は、予測を候補の番号で 256（$n/2$）ずらして使う。候補 $i$ の 2 つの位置の予測の差を読み出しに通したものを $d_i$、的を $t_i$ とすると、ずらし $\tau$ の `swap` は $s(\tau) = \frac1n \sum_i [d_{i+\tau} \cdot t_i > 0]$ である（添字は $n$ を法とする）。

**H-time（時間の構造。第一の仮説。導いた）**

- `_deviation` が候補の平均を引くので $\sum_j d_j = 0$。したがって、どの $i$ でも $\sum_\tau d_{i+\tau} \cdot t_i = 0$ が**恒等的に**成り立つ。$C(\tau) = \frac1n \sum_i d_{i+\tau} \cdot t_i$ と書けば $\sum_\tau C(\tau) = 0$
- 予測が当たっていれば $C(0) > 0$（`pred` の `swap` 0.69〜0.90）。候補は時間順に並び、2 つの四半分の中身の違い（左上が空で右下が路面、など）は数十秒〜数分は続くので、小さいずらしでも $C(\tau) > 0$ になる。和が 0 なので、遠いずらしの $C$ は負に寄る
- 候補の番号についてのフーリエ成分で書くと $C(n/2) = \sum_k (-1)^k P_k$（$P_k$ は $d$ と $t$ の周波数 $k$ の交差スペクトル）。半周ずらすと奇数の成分はすべて符号が反転する。1 時間の動画を通したゆっくりした変化（$k$ = 1）が大きければ、$C(n/2)$ は遠いずらしの平均よりさらに負になる
- 大きさの目安: $s = \frac12 + \frac1\pi \arcsin \rho$（正規分布の近似）で、観測の 0.455〜0.476 は $\rho \approx -0.08$〜$-0.14$ にあたる。$\rho(0)$ は `color` で約 0.94、`incep` で約 0.56 なので、ずらし 0 の近くの正の相関が候補 ±60 個（±7.5 分）ほど続けば、和が 0 の条件だけで届く大きさである（推測）
- 既存の数値との整合: 外れた 28 か所のうち、0.5 より下の 26 か所はすべて学習した checkpoint である。予測器が学習前の step 0 では、P16 は外れず、F の seed 1 は逆向き（0.525）に外れた。$C(0) \approx 0$ なら向きが決まらない、という H-time の予言と合う

**H-se（標準誤差の過小評価。H-time と両立する）**

- V-E1 の幅 $2\,\mathrm{SE}$ は、候補が独立だとして出している。当たり外れは時間方向に相関するので、実際の幅はもっと広い
- 26 か所は 26 回の独立な出来事ではない。どの checkpoint も同じ的 $t_i$ と同じずらし 256 を使い、学習した予測の $d_i$ は互いに似ている。**「この動画のずらし 256 で $C$ が負」という 1 回の出来事を 26 回数えている**

**H-skew（符号の統計量の偏り）**

- $d$ と $t$ が独立でも、$d \cdot t$ の分布が 0 について非対称なら、中央値が 0 からずれて $s \ne 0.5$ になる（V-E1 の但し書き「0 について対称なとき」）。この場合、偏りはずらし幅によらない

**H-bug（実装の誤り）**: `mean` はちょうど 0.5 で、合成の K3 のテストも通っているので可能性は低いが、下の恒等式で確かめる。

### ずらし幅を変えて確かめる手順

読み出しを通した $D$（$n \times F$、$d_i$ を並べたもの）と $T$（$t_i$）から、$n \times n$ の行列 $M = D T^\top$ を 1 枚作れば、すべてのずらしの値が出る。checkpoint ごとに 512 × 512 × 256 の積が数回で、計算は無視できる。`fill_eval` が $D$ と $T$ を保存するか、その場で曲線を出す。対象は P16 の seed 0 の step 0・6000・60000、F の seed 0 の 60000、M で足りる。

1. **恒等式**: $\sum_j M_{ji} = 0$ がすべての $i$ で丸め誤差の範囲で成り立つこと（外れたら H-bug）
2. **曲線**: $s(\tau)$ を $\tau = 0, \dots, n-1$ で描く。巻き戻しを使わない版（$i + \tau < n$ の組だけ）も並べる
3. **順序を壊した基準**: 候補の番号をランダムに並べ替えた $s$ を 1000 回とり、平均と幅を出す。$s$ の全ずらしの平均も出す

| 観察 | H-time | H-skew |
| -- | -- | -- |
| $s(1)$、$s(2)$（7.5 秒・15 秒） | 0.5 を大きく超える | 0.5 より下 |
| $\tau$ についての形 | なめらかに下がって 0.5 を横切り、遠いずらしで負の側。隣の $\tau$ どうしはほぼ同じ値 | ずらしによらず一定で 0.5 より下 |
| ランダムな並べ替えの平均 | 0.5（ずれは $1/(2(n-1))$ = 0.001 以下。$\rho$ の平均が $-\rho(0)/(n-1)$ なので） | 0.5 より下（0.46〜0.48） |
| 時間のゆっくりした成分を $d$ と $t$ から引いたあとの $s(n/2)$（候補 ±32 個の移動平均を引く） | 0.5 ± 2 SE に戻る | 戻らない |
| step 0 の checkpoint | 向きが決まらない | 学習後と同じ向きとは限らない |

4. **判定**: ランダムな並べ替えの平均が 0.5 ± 0.005 に入り、$s(1) > 0.5$ で、ゆっくりした成分を引くと $s(n/2)$ が戻れば H-time。並べ替えの平均が 0.5 から外れれば H-skew で、符号の統計量そのものを見直す（そのときは改めて提案する）

### V-E1 と `swap` の判定の直し方（H-time だったとき）

- **`shuf` を 1 つのずらしで読むのをやめる。** 実装の確かめは、ランダムな並べ替えの平均 `shuf_perm` が 0.5 ± 0.005 に入ること、にする。予測と的の対応を壊せば偶然になる、という元の狙いはこれで確かめられる
- **`pred` の `swap` の有意さは、ずらしの分布で読む。** 候補 64 個（8 分）以上離れたずらし $\tau \in [64, n - 64]$ の $s(\tau)$ を帰無分布にし、$s(0)$ がその中で上から何番目かを p 値にする。巡回のずらしは、2 つの系列それぞれの時間の相関を保ったまま対応だけを壊すので、時間の相関があっても成り立つ（H-se の対策）。64 は曲線が 0.5 を横切る位置を見てから確定する
- $\delta_E$ の標準誤差は、候補を 32 個ずつのブロックにしたブートストラップに替える（E1・E1e・E2 のすべて）
- `id_easy` の `shuf` は今のままでよい（外れたのは 1 か所で、上限と同じ値）

### 合成した厳密な K3 の負の対照

**作り方**（checkpoint ごと。実データのトークンから作るので、その checkpoint が持つ場面の情報はそのまま残る）

- `oracle_k3`: 全体を見たトークン $z_{n,p}$ を、**位置の平均 $h_n = \frac1T \sum_p z_{n,p}$ で全位置を置き換えた**符号。当てはめの組・calib・候補のすべてで置き換え、読み出し $g_U$ もこの符号で当てはめる
- `pred_k3`: 予測器の出力 $\hat z_{n,p}$（隠した位置）を、隠した位置の平均で置き換えたもの。読み出しは本物の `oracle` で当てはめた $g_U$ のまま（`pred` と同じ条件）
- 位置ごとの定数 $g(p)$ は足さない。$g(p)$ を足した族でも `swap` が 0.5 になることは代数と既存の合成のテストで分かっている。実データでは $(h_n + g_A) - (h_0 + g_A)$ と $(h_n + g_B) - (h_0 + g_B)$ が浮動小数点の丸めで一致せず、引き分けにならない。$g = 0$ なら 2 つの位置の入力がビットまで同じテンソルになり、`_deviation` の差がちょうど 0 になる

**期待する値**（導いた）

- `swap`: `oracle_k3`・`pred_k3` とも、全候補が引き分けでちょうど 0.5。どのずらしの `shuf` でも 0.5
- $m$（5 節の V-m4）: V18c の $d$ = 16 では 0.25 以下
- `id_easy`・`id_hard`・`r2`: 0 にはならない。場面だけを表す符号・予測器がどこまで当てるかの基準になる。README の結果 6 で M の `pred` が 0.083 を出して読めなくなった値に、基準ができる

**$\varepsilon$ のはしご**（M の位置づけ）

- $z^{(\varepsilon)}_{n,p} = h_n + \varepsilon (z_{n,p} - h_n)$、$\varepsilon \in \{0, 0.03, 0.1, 0.3, 1\}$。$\varepsilon$ = 1 が元の符号、0 が厳密な K3
- 各 $\varepsilon$ で `rho_in` と、`oracle` の `swap`・$m$ を出す。`swap` と $m$ が $\varepsilon$ について減らないこと、`rho_in` が M と同じ 0.08 になる $\varepsilon$ で `swap` がどの値になるかを見る。そこで 0.6〜0.9 が出れば、M の 0.63・0.85 は「評価が K3 を見分けない」のではなく「分散で 8% の位置ごとの成分を ridge が拾う」ことの現れだと確かめられる
- 読み出しは入力を標準化して当てはめるので、$\varepsilon$ が小さくても位置ごとの成分は読める見込みである（推測）。そのため、**`rho_in` の小ささと `swap` の高さは両立する**。崩壊の検出（`rho_in`・`token_r2`）と `swap` は別のものを測る、と README に書いておくのがよい

**条件の直し方**

- V-E3: 「M の `pred` の `swap` が 0.5 付近」をやめ、「`oracle_k3` と `pred_k3` の `swap` がちょうど 0.5（引き分けの数 = 候補の数）、$\varepsilon$ のはしごで `swap` が減らない」にする
- 条件 1: 「`pred` が `mean` を上回る」を、「`pred` が `pred_k3` を `id_easy`・`id_hard` で $\delta_E$ を超えて上回り、`swap` のずらしの p 値が 0.01 未満」にする。位置を持たない予測器でも届く分を引いた残りだけを、補完として数える
- E1 の `incep` の的は、5 節の高解像度の四半分の的に替える。V-E2 は余裕が小さかった（+0.0083、$\delta_E$ 0.0048）。高解像度の的で `oracle` が読めるかを V-E2 で確かめ直す
