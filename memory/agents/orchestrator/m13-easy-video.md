ブランチ: `exp/2026-11-02/continuous-stream-m13-easy-video`（main 5897f06 から）。mujou 881c4ee。

## 段階 1: 計画

### 公開インターフェース

- `balls.Video(episode: tuple[float, float] | None = (3.0, 6.0))`: `None` は引き直しなし（最初のフレームだけ `reset`）
- `DataConfig`: `gamma0=1.0`、`gamma_amp=0.5`、`e0=0.6`、`e_amp=0.5`、`drag=0.1`（`balls.Physics` と同じ名前と既定値）、`redraw: bool = True`。`DataConfig.physics() -> Physics`
  - 引き直しなしを `episode_max=None` でなく `redraw` にした理由: `episode_min` だけ残る形が読みにくい。`redraw=False` は `episode_*` を無視する
- `ModelConfig.width: int = 32`: 合成動画のエンコーダの最初のチャンネル数（w / 2w / 4w）。`encoder_modules(..., width=32)`
- `offline.py --config <json>`: モデルとデータを `Config` から取る（省略時は今と同じ D=64、d_s=256、`z_norm`、既定のデータ）。データは `run.source` から。窓は各ストリームの中で reset をまたがない位置から切る（`window_starts(resets (T, B), window) -> (n, 2)`）。動力学は `dynamics_modules`（`dyn_nodes`）、`residual` も設定から

### 変えないもの

- `model.calibration_images` と offline の較正は既定の物理の `Video` のまま（エンコーダのスケールを合わせるだけ。変えると今までの run の初期値が変わる）

### テスト観点（オラクル）

1. 引き直しなし: 隣り合うフレームの位置の差 ≤ 速さの上限（エネルギー保存から $\sqrt{2E}$）× 1 フレーム。reset は最初だけ
2. エネルギー: $e=1$・抵抗 0・一定の重力で 30 分、全エネルギーの誤差が有界（slow）
3. 既定の物理: `DataConfig().physics()` は `Physics()` と等しく、`run.source(Config())` のフレーム列は `Video(seed=0)` と同じ
4. 幅: `width=64` でチャンネルが 64/128/256、既定はパラメータ数が変わらない
5. 窓: `window_starts` が reset をまたぐ窓を返さず、それ以外はすべて返す

### 実験の手順と判定

MILESTONES.md の M13 のとおり。閾値は手順 1 の物差しを見て README に書いてから回す。

## 段階 2〜4

- テスト中に、$e=1$・抵抗 0・一定の重力でもエネルギーが 30 分で玉ごとに最大約 10% ずれることが分かった。半陰的 Euler は跳ね返りの間では $\tilde E = v^2/2 + \gamma y - \gamma h v_y/2$ を厳密に保つが、床・天井での位置の反射が $\tilde E$ を $\gamma(2\delta - h|v_y|)$ だけ変え、跳ね返りの周期とステップの刻みが共鳴すると一方向に溜まる。`Physics.conserve`（反射後の速さを $\tilde E$ が変わらないように決める）を足した。既定は off で、既定の物理のフレーム列は main とビット単位で同じ（2 seed × 10 分と評価クリップで確認）
- offline の窓: 旧コードは `range(len(frames) - WINDOW)` で最後の 1 窓を落としていた。`window_starts` は含めるので、既定の設定でも乱数の引きが M11 とわずかに違う（結果への影響は無視できる）
- 較正画像（`calibration_images`）は既定の物理のまま（計画どおり）
