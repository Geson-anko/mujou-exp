### 1. 目的・マスク・SIGReg

- **条件付き分散の式には \(U,n\) も条件に入ります。** 固定エンコーダに対する Bayes 下限は \(\mathbb E\,\mathrm{tr}\,\mathrm{Cov}(t_U\mid c_V,U,n)\) を座標数で割ったものです。Schur 補は同じ入力に対する最良の線形誤差です。管では `keep` 付きの符号と全視野から切り出した符号が異なり、現案の予測器は \(Rh\) より多くの情報を持つ \(h\) を受け取ります。したがって現案と Schur 補の差を非線形性だけに帰せません。変更 7 を次段に置くのは妥当です。発動条件にするなら、同じマスク・標的・予測器容量で \(h\) と \(Rh\) を比較してください。`own` と PCA64 の MLP の差には容量と射影も混ざります。 [Fable §1・§5](/Users/geson/Projects/mujou-exp/memory/agents/fable/st-completion.md:42)
- **一様なのはセルの隠蔽率です。** 管は別時刻の文脈も使えるので、同じ stack 内の補完を測るには、管で他時刻を遮断した比較が要ります。既存 dyn/copy と同じ「等間隔の隣接 2 点から 1 歩先」の標的は、未来・過去それぞれ全標的の \(1/12\) です。厳密に空間と時間の手がかりを同時に使わせたいなら、次の候補は各時刻の隠蔽数が `(64, 32, 32, 0)` の混合マスクです。半面を相補的にし、補集合・時間反転・空間平行移動込みで引けば、隠蔽数 128 とセル周辺率 1/2 を保てます。主の族を今すぐ替える根拠はありません。 [Fable §2](/Users/geson/Projects/mujou-exp/memory/agents/fable/st-completion.md:63)
- **番号別 SIGReg は妥当ですが、\(N=128\) から期待値の一致は出ません。** 独立に復元抽出した clip なら同一統計量に clip 内の相関は入りません。一方、端の除外で各番号の周辺分布は V18c とずれ、4 項の平均で勾配の分散も変わります。K3 の「約 1.9」は典型的なランク 16 ガウスの近似で、族全体の下界ではありません。健全解の損失 \(\le 1\) にも、\(z\) を正則化する式から \(t\) についての保証は出ません。また分散収縮の 2% 上限は有限標本の一次項を落としています。現行の 17 点則で、等方ガウス・\(N=128,\lambda=0.5\) の分散最適値は SIGReg 単独で約 0.984、予測項を \(0.5\,\mathrm{Var}\) としたモデルで約 0.969 です。 [SIGReg 実装](/Users/geson/Projects/mujou-exp/exp/lib/sigreg.py:26) [V18c の導出](/Users/geson/Projects/mujou-exp/exp/vision/plans/jepa.md:755) [LeJEPA 原論文](https://arxiv.org/abs/2511.08544)

### 2. 実装と帰属

- **変更 1〜3 は妥当です。** 位置符号から保証できるのは、時刻の原点を符号に渡さないことまでです。有限・丸め付きの刻み分布に尺度不変性はなく、マスクの反転閉包も予測器やデータの反転対称性を保証しません。64/64 はデータと独立に割り当てれば同じ期待勾配を持ちます。全視野の `h` の再利用も現行の決定的なエンコーダなら数学的に同値です。`40960` は `keep` 適用後のエンコーダのトークン数で、パッチ埋め込みは間引き前、予測器の注意行列は 64→256 で要素数 16 倍です。`K=1` のビット一致は既存経路・乱数消費まで揃えて確認し、共有対再計算は損失と全勾配を許容誤差で比較してください。 [エンコーダと予測器](/Users/geson/Projects/mujou-exp/exp/vision/jepa.py:236) [注意の実装](/Users/geson/Projects/mujou-exp/exp/vision/models.py:117)
- **変更 6 の `ST-perm` は計算量を揃えますが、動画全域から引き直すと帰属が広すぎます。** 役割ごとの端の分布、局所場面の共有、管で使える別時刻の文脈も変わり、復元抽出ではフレーム重複も起こりえます。最低限、ST と同じ動画・\(n\) を使い、各役割の許容範囲から独立に引いて周辺分布を保ち、重複率を監査してください。局所場面の共有と時間配置を分けたいなら、同一場面内で間隔・順序だけを壊す対照も要ります。V18c との差は、空間損失の実効重み、全視野の文脈、系列長、勾配の相関まで含む方式全体の効果です。 [既存サンプラー](/Users/geson/Projects/mujou-exp/exp/vision/iid.py:136) [対照の定義](/Users/geson/Projects/mujou-exp/memory/agents/fable/st-completion.md:330)

### 3. 評価と判定

- **N には位置由来の copy の穴があります。** `keep` の経路は patch 単位なので、入力側の隠れた画素は attention に入りません。ただし \(R\) の共有と位置の並べ替えでは、半面の符号の座標は揃いません。例えば左右の符号に異なる定数を足すだけで、切片付き予測の残差を変えずに copy の分母を大きくできます。絶対位置符号を持つ ViT と画素 PCA にはこの点で非対称性があります。各軸で両半面を合わせた訓練参照だけから共通 PCA64 を作り、平均は方向別の訓練標的平均に固定してください。通常の copy に加え、訓練平均で補正した copy \(w_H-\bar w_H+\bar w_{\sigma H}\) と、全方式で同じ隠れ半面の観測を標的にした結果があると判別できます。N が測るのは部分視野の符号間の転移です。管で使う 4 時刻の文脈や全視野の標的とは違います。 [PatchEmbed](/Users/geson/Projects/mujou-exp/exp/vision/models.py:146) [N の定義](/Users/geson/Projects/mujou-exp/memory/agents/fable/st-completion.md:223)
- **P は同じ三つ組の両端を交換すれば対称です。** 評価点・白色化・抽出・探索格子を共通にし、入力順は常に中心が先、平均の作り方も F と共通にします。stack 内の順序を保つので、測るのは自然順の stack 間の逆向き予測です。F 用の ridge・MLP をそのまま流用するのではなく、同じ手続きで P を学習します。N・P に F の MLP 較正結果を自動適用しないでください。矢 \(A\) は記述でよいです。例えば白色化ガウス VAR(1) の遷移が \(\begin{pmatrix}0&a\\0&0\end{pmatrix}\) でも、前後とも 1 点で十分で誤差トレースは等しく、非正規性だけで差は出ません。 [dyn/copy の評価規則](/Users/geson/Projects/mujou-exp/exp/vision/plans/dyn.md:37) [Fable §7](/Users/geson/Projects/mujou-exp/memory/agents/fable/st-completion.md:237)
- **両比と内容ガードを通っても、観測の予測改善は残ります。** 観測を読む座標を保ったまま、別の雑音座標を正確に予測できる周期成分に替えると、\(E,E^d\) を保って両比を下げられます。逆に中身が同じでも、PCA64 の切断や Zurich への分布ずれで順位は変わります。旧案の「共通の未来観測への予測」を残す価値があります。非劣性の式は \(E_b\) の下端が正のときに使い、比較不能や区間が 0 をまたぐ場合は保留にしてください。F/P/N のいずれかを独立に成功と宣言するなら多重性の規則を固定し、同一 Zurich を共有する 2 seed は再現の確認として扱うのが妥当です。 [共通観測への評価](/Users/geson/Projects/mujou-exp/exp/vision/plans/v18d.md:134) [非劣性の実装](/Users/geson/Projects/mujou-exp/exp/lib/fidelity.py:437)

### 4. 掃引と選択

**旧 `time_val` の 128 秒ブロックはそのまま使えません。** \(n=512\) の 4-stack は \(3\cdot512+8=1544\) フレーム必要です。256 秒などに変更し、全候補で検証 clip・マスク・ラグの重みを固定してください。相対誤差の平均標的は少なくとも位置別に定義します。位置を混ぜた平均では、位置だけを当てても勝てます。管と時間の値は個別に残し、片側が平均予測に勝てなくても他方で相殺して採択できるかを事前に決めてください。 [旧 `time_val`](/Users/geson/Projects/mujou-exp/exp/vision/time_val.py:85)

6000 step 用 cosine と 60000 step 用 cosine の途中では、同じ step でも学習率がほぼ 0 対ピークの約 98% です。可能なら長い schedule の先頭 6000 step を選択に使い、V18c 側も同じ schedule の時点と比較してください。旧案どおり検証動画を JEPA 学習に含めるなら、選択は訓練分布内です。適格ゼロ、比較不能、同点、対応する V18c 長期 run がない場合の扱いまで固定すれば、どの設定が選ばれても問いが変わりません。 [学習率の実装](/Users/geson/Projects/mujou-exp/exp/vision/iid.py:197) [旧案の選択規則](/Users/geson/Projects/mujou-exp/exp/vision/results/v18d/README.md:41)
