## 1. Codex さんの指摘（要約）

### (a) `sem_r2` は何を測るか

- pool3 の空間平均で消えるのは特徴の地図の座標だけで、色・質感・配置への感度は残る。`inc64` > `pca` は「同じ系統の非線形の特徴が有利」というだけでも成り立つ。的がどの手がかりで稼がれるかは確かめていない（Codex さんの意見）
- 的そのものの感度を先に確かめるべき: 照明・色・軽いぼかしだけを変えた組と、色の統計をそろえて粗い内容（カテゴリ・配置）を変えた組で、pool3 の的がどちらに強く反応するか
- 1 回目の答えでは、主の指標を「予測器の出力 $\hat t_U$ から、隠した領域の粗い意味の的を読む」形（E1 を土台にしたもの）にすることを勧めた。反論（下の 2 節）を受けて、**案 D を主に戻し、マスク補完は副のゲートにする**と修正した

### (b) 上限と見分ける力

- **K3 の上限 0.25 は Zurich では保証されない**（導いた）。Zurich の上で各成分を中心化・標準化した的の相関行列を $C$ とすると、ランク 16 以下の予測の $m$ の上限は $\sum_{j=1}^{16} \lambda_j(C) / 64$。0.25 になるのは採点の組で $C = I$ のときだけ。当てはめの組での白色化は効かない
- **当てはめの組での白色化は、そもそも何も変えない**（導いた）。ridge は出力の列ごとに独立に解けるので、的の成分を定数倍しても係数が同じだけ倍になり、成分ごとの $R^2$ は変わらない。「分散の大きい 1〜2 成分が決めてしまう」のを防いでいるのは、白色化ではなく成分ごとの $R^2$ の平均である。Zurich で分散の小さい成分は誤差に敏感になる
- `inc64` は上限ではない。1 枚のフレームを圧縮した参考の値に下げるべき。画素の PCA の入れ子も、1 回当てはめた基底の先頭をとって作り、有限の標本での単調さは数値で確かめる（理論の順序ではない）
- **calib と採点の組が重なっている**（確かめた: `runs/v18c-fill/yardsticks/posthoc_fill/config.json` で、calib の 1024 個のうち 102 個が Zurich の格子と開始フレームまで一致し、格子の 3899 個のうち 1274 個が calib の時間の範囲 0〜12735 に入る）。今の分け方を流用すると、$\alpha$ を選んだ区間が採点に入る。時間に間をあけて calib・選ぶ組・最終の評価の組に分け、calib と採点で同じ中心化をする。`select_ridge` は予測を評価の組で中心化し直さない（Codex さんの指摘、`exp/lib/readout.py` 52 行あたり）
- **$\sigma_{\mathrm{seed}}$ を旧 checkpoint から借りられない**。P16・F の同じ軌跡の複数の step は seed の繰り返しではないうえ、構造も違う。seed の揺れは V18c の設定どうしで測る
- 物差しが大きく離れていても、近い $\lambda$・$r$ や M を分けられるとは限らない。V-m6（当てはめの数を半分にする）だけでなく、当てはめのブロックを入れ替えて候補どうしの差が保たれるかを見る

### (c) 学習率ごとの選び方の偏り

- 「初期値に近い run を選ぶ」懸念は妥当だが、今は仮説（Codex さんの意見）。学習率 1e-5 の `h_mean` は 49.2 → 52.2〜52.3 と上がり、SIGReg も下がっている
- 同じ seed なら、共通の `init_c` を引いても腕の順位は変わらない（導いた。差をとっても順位の比べには効かない）。だから正規化では偏りは消えない
- 同点決めから `out` を外す。`out` は画面の外への外挿を測るもので、$\lambda$・$r$ を選ぶ理由とは別の要件である
- **seed の数**: 学習率ごとに上位と僅差の候補に同じ追加の 2 seed（合計 3 seed / 設定）が最低限。候補が学習率ごとに 2 つなら、短い run を 8 本足す。3 seed でも小さな差は確定できない。最小の実用の差を先に決め、追加の seed でも向きがそろって平均の差がその幅を超えたときだけ選ぶ。分かれなければ同点と報告し、事前に決めた設定で両方の学習率の長い run に進む（Codex さんの例は $(\lambda, r) = (0.8, 0.5)$。ただし事前登録の同点決めの最後は `pred_ratio_calib` 最小で、$10^{-4}$・0.5・0.25 になる。どちらを既定にするかは決める必要がある）

### (d) `swap` の偏りと K3 の対照

- **恒等式 $\sum_\tau C(\tau) = 0$ は成り立つが、勝率（`swap` は正の符号の割合）については何も言えない**（確かめた）。`_swap_rows`（`exp/vision/fill_eval.py` 815 行）は候補で中心化した差 $D$（`_deviation`）と、格子の平均を引いた的 $T$ の内積の符号をとる。$\sum_j D_j = 0$ なので内積の平均の和は 0 だが、負の平均と過半数の勝ちは両立する。反例: $D = T = (-5, 1, -1, 5, 1, -1)$ を半周ずらすと、内積の平均は −7.67、勝率は 2/3（Claude が手で確かめた）。多次元の内積に 1 変数の正規分布の arcsin の式を当てる根拠も無い
- ランダムな対応でも、勝率の期待値は 0.5 とは限らない。Fable さんの「ランダムな並べ替えの平均が 0.5 ± 0.005 なら H-time」の判定は、その前提が崩れる
- 1 本の非定常な動画で、曲線を見てから選んだ遠いずらし（$\tau \in [64, n-64]$）を帰無分布にして p 値を出す根拠は無い
- 代わりに、方向ごとの内積の行列から **内積の平均と勝率の両方**を、巻き戻しのないずらしと、対角以外の全組の勝率と並べて出す
- **位置の平均で置き換えた複製は、厳密な引き分けを確かめる対照としては使える**（導いた。$g = 0$ なら 2 つの入力が同じテンソル）。ただし学習の側の K3 の族 $t_p = A_p u$ 一般では `swap` は 0.5 にならない。例: $A_B = -A_A$ で、各位置の的が対応する符号とそろえば、共有する $u$ だけで両方向に勝てる。$A_p$ の族は `token_r2` とランクで別に見張る
- **$\varepsilon$ のはしごは、凍結した読み出しでは何も見分けない**（導いた）。$z^{(\varepsilon)}_A - z^{(\varepsilon)}_B = \varepsilon (z_A - z_B)$ なので、`_deviation` と線形の読み出しを通しても符号は変わらず、`swap` は $\varepsilon > 0$ で一定。当てはめ直す版でも単調の保証は無い。記述にとどめ、部分的な崩壊への感度を測るなら、固定した雑音に対して位置ごとの成分の強さを振るほうがはっきりする
- `pred` > `pred_k3` は「凍結した読み出しが位置の差を使ったか」のアブレーションとしては残す。条件 1 には、同じ見える入力から作る位置をプールした対照に、対で勝つことも求める

## 3. Claude の判断（同意・反論・Fable さんの案への修正案）

### 同意する点

1. K3 の上限は Zurich の $C$ の上位 16 個の固有値から実測して出す。0.25 を理論の値として書かない
2. 白色化の理由づけは誤り。成分ごとの $R^2$ の平均がすでに等しい重みになっている。白色化は外すか、「結果を変えない」と書く
3. calib と格子の重なり（102 個一致、1274 個が範囲内）は確かめた実害である。時間に間をあけた 3 分割（calib・選ぶ組・最終の評価）にする。E1・E1e・E2 の既存の数値も、この重なりを含んだまま出ている
4. `inc64` は上限ではなく参考の値。V-m3（`inc64` − `pca` > $3\delta_y$）は「的が画素の線形の関数を超える」ことの十分な証拠にならない。代わりに的の感度の確かめ（色・照明・ぼかしを変えた組 vs 粗い内容を変えた組）を V-m0 の後に置く
5. $\sigma_{\mathrm{seed}}$ は V18c の設定の seed を足して測る。旧 checkpoint の step 違いは seed の揺れではない
6. `swap` の H-time の議論は、内積の平均には成り立つが勝率には成り立たない。反例は手で確かめた。E1 の修理では、内積の平均の曲線と勝率の曲線を両方出し、arcsin の換算と「並べ替えの平均が 0.5」の判定は使わない
7. $\varepsilon$ のはしごは、凍結した読み出しでは `swap` を変えない。M の位置づけの道具にはならない
8. 位置の平均の複製は「引き分けがビットまで出る」実装の確かめとしてだけ使う。K3 の族 $A_p u$ 全体の負の対照にはならない

### 反論する点・保留する点

1. **的を「粗いカテゴリの有無・占有率」にする案は今は採らない。** セグメンテーションのネットという新しい外部の依存が要り、その出力の正しさをまた確かめる必要がある。pool3 の四半分の的に、Codex さんの言う感度の確かめを足すほうが小さい変更で済む。感度の確かめで pool3 が色・照明に強く反応したときに、次の手として検討する
2. **「初期値に近い run を選ぶ」偏りは仮説だが、案 D の構造からは起こりやすい側にある。** 線形の ridge は情報を線形のまま持つ符号に甘い（Fable さん自身の弱点 1）。Imagenette の `h_mean` も線形 probe で、学習率だけで決まった。Codex さんの言うとおり `init_c` を引いても順位は変わらないので、正規化では直せない。対策は、(i) 学習率をまたいだ比べに $m$ を使わない（ユーザーの決定 (3) どおり、学習率ごとに選ぶ）、(ii) 学習率の中でも、$m$ の差が追加の seed で再現しなければ同点とし、事前に決めた既定の設定に倒す、の 2 つで足りる。これは Codex さんの 4 の規則と同じ
3. 2 回目の Codex さんの例の既定 $(\lambda, r) = (0.8, 0.5)$ は、事前登録に根拠が無い。既定を何にするかはユーザーに諮る（候補: 事前登録の同点決めの最後の `pred_ratio_calib` 最小、または $\lambda$ が大きいもの。後者は学習の側の導出 6「見えるトークンで分け持つ大域の解を外すのは $\lambda$ = 0.95 だけ」に裏づけがある）
