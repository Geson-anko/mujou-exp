2026-11-23、V17 の後に JEPA へ移るにあたり、ユーザーと次を決めた。計画は exp/vision/plans/jepa.md。

- 順序: V18（BP・i.i.d. なミニバッチ・標準の SIGReg）→ V19（BP・単一ストリーム、順を並べ替えた対照つき）→ V20（BP・時間相関の SIGReg）→ V21（PC-ALM）→ V22（長いストリーム）。VAE の V16 → V17 と同じく、普通の学習で学べることを先に確かめる
- SIGReg の過去の $z$ のバッファは FIFO にする。ランダムな置き換え（`exp/lib/sigreg.py` の `insert_`）は生存時間が確率的になるため
- 時間相関の SIGReg は、ユーザー自身も「見当もつかない」。Fable に指揮をとらせて文献調査（Deep Research）し、いくつかの手法を考案させる。報告は memory/agents/fable/temporal-sigreg.md
- ユーザーの仮説: SIGReg がストリームで効かないのは、相関のためにデータポイントを独立に扱えないこと。時間相関はそれ自体が手がかりにもなる
- 推奨案で進めたこと（ユーザーは異を唱えていない）: exp/vision の V18 から続ける、LeJEPA の形（EMA・stop-gradient なし）+ stack ごとの SIGReg（D = 1024）
- 2026-11-23、ユーザーが明示的に決めた（「early fusion, 良いですね。マスク率に注意しつつ」）: early fusion のまま（8 枚 × 3 チャネル、patch 16 で 4×4 = 16 トークン、空間の補完だけ）。マスク率に注意する: 隠すトークンの数をちょうど k 個に固定し、マスク率 r ∈ {0.25, 0.5, 0.75}（k = 4, 8, 12）を掃引の軸にする

**Why:** M17 は i.i.d. の BP で学べることを確かめないままストリームで崩壊への対処に追われ、原因（実装・学習の設定・相関）を分けられなかった。

**How to apply:** 各段の判定が外れたら次の段に進まない。V19 で何を測るかと V20 の手法は、Fable の報告を読んでから決める。背景は [[project-m17-wt-encoder]]、[[project-m17-stream-sigreg]]、[[project-m17-gauss-kl]]、[[project-v17-to-jepa]]。

2026-11-23（ユーザー）: 詰まるところがなければ、V18 から最後の V（V22）まで、確認を待たずに進めてよい。段ごとに Workflow で回し、判定が外れたら次の段に進まず報告する。

2026-11-23、Fable さんの調査（memory/agents/fable/temporal-sigreg.md）を受けて、ユーザーが推奨どおりに決めた:
- D = 1024 のデータポイントの SIGReg のまま進む。V19 で方向ごとの相関を測り、Fable さんの予測（標準の SIGReg + FIFO では遅い方向から分散が消え、選別は D 倍に効く）を確かめてから、V20 で次元を変えるかを決める
- V20 の本命は手法 3（δ 秒前の stack も符号化した自己回帰の残差の SIGReg）。δ 秒前の入力を持つことは単一ストリームの範囲に入れる。手法 1 は参照に 1 本、手法 2 は最小の変更の腕、手法 4 は対照、手法 5 は診断だけ
- V18 は LeJEPA と同じ V 統計量のまま、V19 から U 統計量に替える
- δ は stack の幅 0.8 秒より長くとる（候補は 1 秒・4 秒、V19 の残差の白色性で決める）。r̂ は当てた値を本命にし、固定の φ は回さない。平均の拘束は V20 で導出してから決める
- V20 の前に、Fable さんの主張（崩壊の閾値 0.646、D 倍の選別）を tests/ の理論値のオラクルで確かめ、Codex さんに読み取り専用で意見を求める。2026 年の文献は根拠に使う前に読み直す

2026-11-23、V18 の結果（exp/vision/README.md「V18: 結果」）: 掃引 18 本（6000 step）では、学習率 1e-4・λ0.5 の 3 本（r = 0.25・0.5・0.75）だけが合格し、λ0.005 の 6 本と λ0.05 の 3 本は導出どおり K3（stack の中で一定の族）で崩壊した。長い run 4 本（60000 step、768 万 stack）は崩壊せず、予測の損失と SIGReg は下がり続けた（`pred_ratio` 0.19〜0.62、`sigreg_heldin` 1.18〜1.24）。一方で、射影の後の z の zurich `recon_blur` は 6000 step の 0.44〜0.47 から 60000 step の 0.56〜0.65 に悪くなり、`color`（0.417）にも `init`（0.223）にも負けた。`dyn_1/copy_1` も 1.04〜1.13 になった。規則 5 は 4 本とも不成立で、V19 には進まない。次は、射影の前のトークン h を同じ probe にかけて、情報が射影で捨てられただけか、エンコーダ自身が失ったかを切り分ける（評価だけの変更。LeJEPA は backbone を評価する）。そのあと、標本数 N を軸にするかどうかをユーザーが決める。

2026-11-23、V18 の診断（exp/vision/README.md「診断の結果」、学習は回し直さず checkpoint に評価を足した）: 射影の前の `h_flat` も 4 本中 3 本で 6000 → 60000 step に閾値を超えて悪くなり（+0.025〜+0.056、`z` の上がり幅の 3〜35%）、規則では「エンコーダ自身が失う」に当たった。ただし悪化の大半は 0 → 6000 step（0.106〜0.109 → 0.261〜0.273）で、後半は少し戻る。`h_mean` は学習前から 0.64 で、`z` と比べる物差しにならなかった。Imagenette の線形 probe では `h_mean` が学習前の 40.2〜40.6% から 44.7〜46.4% に上がったが、「意味に寄せた」とは言わない（Codex さんの指摘で弱めた）。Zurich の `sigreg_zurich` の大きな値は主に評価の標本の相関によるもので（$n$ = 128 で相関の分は分布のずれの 4.3〜6.0 倍、Fable さんの式で 84〜85% を予測）、表現の診断に使わず、V19 以降は間隔をあけた組（`spaced`、$n$ = 128）に替える。Codex さんの第一の説明は「空間マスクの予測が、標的 $z$ を当てやすいように変える」で、私たちも同意した。次の候補は、(1) 目的を直す計画（重ならない未来の $z$ を線形に予測し、入力の歪みの制約と $\mathrm{Cov}(z) = I$ の等式制約）、(2) checkpoint のままの切り分け（凍結した $z$ の当て直し）、(3) 安い反証の掃引（学習率 1e-5・λ 0.8、規則 6 を変える）。推奨は 1 で、どれにするかはユーザーが選ぶ。`autocov` の長いラグの修正は未着手。

2026-11-23、V18 の診断を受けたユーザーの決定（V18b、計画は exp/vision/plans/jepa.md「V18b」、事前登録は exp/vision/README.md「V18b」）: トークンが粗い可能性を確かめるため、パッチを 16×16 から 4×4 にする（64 px で 256 トークン、トークンの入力は 384 次元）。その後で未来予測の学習（V18c）に進む。ハイパラを広げて調べる（学習率 {1e-5, 3e-5, 1e-4} × λ {0.5, 0.8, 0.95}）。SIGReg のデータ点としてトークン平均の腕（M、d = 64、z̄ ∈ R^64 に SIGReg）を試す。ただし平均だけの SIGReg は K3 を罰しないので（導出: S は z̄ だけで決まり、どの λ でも K3 が目的の下限に届く）、平らに並べる腕（F、パッチ 4、d = 4、D = 1024）と V18 と同じ P16 と並べて比べる（ユーザー「ですね、試しましょう」）。推奨で進めたこと（ユーザーは異を唱えていない）: マスクは V18 の 4×4 の族から引いて細かい格子の 4×4 ブロックに広げ、画素の領域を V18 とまったく同じにする。Imagenette の線形 probe（h_mean、M では z̄ も）を副の基準にする。Codex さんの助言どおり pred と S を別々に追い、同じ λ の学習率 1e-4 の run より pred・S が進んでいない run は判定保留にする。

2026-11-23、V18b の結果（exp/vision/README.md「V18b: 結果」、集計は exp/vision/results/v18b/judge.py）: 長い run 4 本（60000 step）はどれも規則 5 を満たさなかった。F（パッチ 4、d = 4、学習率 1e-4・λ0.5・r0.25）は崩壊せず、目的の値は下がり続けた（`pred_ratio_calib` 0.58〜0.59 → 0.27）が、zurich の `recon_blur` は 6000 step の 0.412・0.333 から 60000 step の 0.634・0.596 に悪くなった（$\Delta_F$ +0.222・+0.263、P16 の V18 は +0.162）。事前の読み方で **H-coarse を棄却し、H-target を支持**した（トークンを細かくしても悪化は止まらず、小さくもならない）。span でも同じく悪くなったので、Codex さんの言う目的の不整合の形である。F の `h_pool`（4×4 ブロックの平均）は 6000 step 以降は変わらず（学習前 0.279 → 0.346）、後半の悪化は射影の後の $z$ で起きていたが、`h_pool` はブロックの中の細部を測れない。M（トークン平均の SIGReg、学習率 3e-5・λ0.8）は導出どおり K3 に崩れ（`token_r2` 0.90、`rho_in` 0.08）、Imagenette の `h_mean` も 50.8 → 47.3〜47.9% に下がった。F の `h_mean` は 50.8 → 58.3〜59.4% に上がった（静止した Imagenette のクラスが読みやすくなったことまでしか言わない）。事前の規則で V18c に渡すトークンの設定に選ばれたのは P16（パッチ 16、F と `recon_blur` が δ_r 以内で、`dyn_1/copy_1` で P16。2 seed の平均で比べたのは私たちの読み方）。V18c は、トークンではなく目的を変える方向（重ならない未来の $z$ の線形予測 + 入力の歪みの制約 + Cov(z)=I）で、計画を書く前にユーザーに報告する。

2026-11-24、V18b の結果と資料（exp/vision/report-jepa.html）を受けたユーザーの決定: 悪化の原因は JEPA の学習目的と評価の仕方が合っていないこととみる。**未来予測（V18c の推奨案）には進まず、空間のマスク予測の V-JEPA のまま学習・評価する**。`recon_blur` は判定から外す（再構成は悪化したが同一画像と判別できる程度には描けており、JEPA は細部ではなく抽象的な特徴量を得る仕組みなので、再構成の向上は期待できない）。新しい評価は、潜在から軽量の拡散モデルで画像を生成し、Inception で評価する（2026-11-18 に exp/vision/PLAN.md「評価の拡張: 軽量の拡散デコーダ」で決めて未実装だったもの）。パッチは 8×8（64 px で 8×8 = 64 トークン）。潜在空間はトークン数 N とトークン次元 d に依存しない形にし、重みを学習しない（定数かランダムに初期化した）全結合の線形写像で決める。細部（写像の重み・SIGReg をかける相手・生成の対象・Inception の指標）は確認中。

2026-11-24、V18c（作り直し）の細部をユーザーが決めた: (1) 潜在の写像 W は seed を固定したランダムのガウス行列（学習しない、1/√(N·d) で正規化、D = 1024）。(2) 学習する射影 P をなくし、予測の的はエンコーダの出力のトークン h_p、SIGReg と評価は z = W·vec(h) にかける。(3) 主の指標は、拡散のデコーダ（flow matching の小さな U-Net、z を FiLM で入れ、最後の 1 フレームを生成）で生成した画像の Inception V3 の特徴で、元の画像を候補から最近傍で当てる同定の正解率（とりあえず）。副は FID・特徴の距離・Imagenette・`dyn_1/copy_1`・崩壊の検出。(4) 評価の実装と既存の checkpoint への適用、パッチ 8 の学習は**並行して**進める。加えて、JEPA の重要な性質（観測した部分だけから、未観測の部分の特徴量まで得られる。経験から観測できない場所の情報を補い、広い知覚を仮想的に可能にする）を測る評価を加えたい。その評価方法は Fable さんに提案してもらう（報告は memory/agents/fable/out-of-view-eval.md）。

2026-11-24、Fable さんの提案（memory/agents/fable/out-of-view-eval.md）を、ユーザーが推奨どおりに採った: (1) 未観測の部分の評価は E1「補完の同定」を主にする（全体を見たトークンで当てはめて凍結した ridge の読み出しに予測器の出力を通し、隠した領域だけを切り出した画像の外部の特徴を当てる。`oracle`・`pred`・`mean`・`shuf` の 4 段、`id_easy`・`id_hard`・`swap`）。E1g（予測で埋めた z を拡散のデコーダへ）は絵と裏づけ。(2) E2「画面の外」のために、元の動画から左右の帯を切り直す（評価専用の別のデータ。既存の data_version は変えない）。(3) 的は Inception V3 と `color` の 2 本（DINOv2 などは差が出なかったときの次の手）。E3（未来）は V19 から。先に E1 を V18 の長い run（step 0・6000・60000）と V18b の M（負の対照）にかける。パッチ 8 の学習のマスクの族に Q・H・R（粗い 4×4 を広げたもの）が入るようにする。

2026-11-24、学習の側の写像をユーザーが決めた（案 B）: 学習する射影 P は無くし、各トークンを固定のランダム行列 R（1024 → d = 16、学習しない）で写した t_p = R h_p を予測の的にし、潜在 z = W·vec(t)（W は固定のランダムのガウス、D = 1024）に SIGReg をかける。射影なし（d = 1024）では典型の K3 が目的の最小値になるため（Claude の導出。最初に推奨した「P なしで h_p を的に」はこの穴があった）。固定の R は、学習する P と違って当てやすい方向を選べない（H-target の対策）。見えるトークン全体で分け持つ大域の解は batch 128 の SIGReg では罰しにくく、どの案でも残るので、崩壊の検出と swap で見張る。ユーザーの指示「全て完了するまで、タスクを回しきって」。学習の側は git worktree（.claude/worktrees/v18c-train、ブランチ exp/2026-11-24/vision-v18c-train）で評価の側と並行し、あとで合流させる。

2026-11-24、V18c の学習の側の設計と事前登録（exp/vision/plans/jepa.md「V18c: パッチ 8 と固定のランダム写像（学習の側）」、exp/vision/README.md「V18c: パッチ 8 と固定のランダム写像で JEPA を学ぶ」）: パッチ 8（64 トークン）。R（16 × 1024）と W（1024 × 1024）は評価の側と同じ `exp/lib/randproj.py` の `gaussian_projection` で作り（W は W_SEED = 61、R は 67、run の seed に足さない）、persistent な buffer（module `proj` と `mix`）として checkpoint に入れ、optimizer に入れない。学習の z = W·vec(t) は、評価の側の `z_w`（W·vec(h)、65536 次元から）とは別の符号で、評価の側の「パッチ 8 の学習は W·vec(h)」の記述は合流のときに t に読み替える。CLI は `--patch 8 --token-dim 16 --proj fixed --sigreg-on mix`（既定は V18・V18b のまま）。導出（N = 128、M = 1024）: 等方的な t を W で写した z の S は 1.07〜1.09（健全 1.05、W の条件数は SIGReg にほとんど見えない）、d = 16 の K3 は 2.9〜3.0（超過約 1.9、λ ≥ 0.5 で排除）、射影なし（d = 1024）の K3 は 1.08（どの λ でも最小値）、見えるトークンで分け持つ大域の解は q = 128 で 1.31・768 で 1.10〜1.14（λ = 0.95 だけが外す）。掃引は第 1 段 r = 0.5 の学習率 {1e-5, 3e-5, 1e-4} × λ {0.5, 0.8, 0.95}、第 2 段は λ ごとに短い run の合格のうち学習率が最大の設定を r = 0.25・0.75 で。短い run の合格は「崩壊（K1〜K3）なし・判定保留でない・`pred_ratio_calib` < 0.95・`sigreg_heldin` < 2.0」で、`recon_blur` と `dyn_1/copy_1` は並べるだけ。長い run（2 seed、60000 step）の設定は、新しい評価の主の指標（同定の正解率）を掃引の step 6000 の checkpoint にかけてから選び、数値が無いうちは選ばない。長い run の判定は m(60000) が m(6000) と m(init_c) をどちらも δ_m を超えて上回ること（δ_m は評価の側の閾値、無ければ 0.044）。
