2026-11-23、V17 の後に JEPA へ移るにあたり、ユーザーと次を決めた。計画は exp/vision/plans/jepa.md。

- 順序: V18（BP・i.i.d. なミニバッチ・標準の SIGReg）→ V19（BP・単一ストリーム、順を並べ替えた対照つき）→ V20（BP・時間相関の SIGReg）→ V21（PC-ALM）→ V22（長いストリーム）。VAE の V16 → V17 と同じく、普通の学習で学べることを先に確かめる
- SIGReg の過去の $z$ のバッファは FIFO にする。ランダムな置き換え（`exp/lib/sigreg.py` の `insert_`）は生存時間が確率的になるため
- 時間相関の SIGReg は、ユーザー自身も「見当もつかない」。Fable に指揮をとらせて文献調査（Deep Research）し、いくつかの手法を考案させる。報告は memory/agents/fable/temporal-sigreg.md
- ユーザーの仮説: SIGReg がストリームで効かないのは、相関のためにデータポイントを独立に扱えないこと。時間相関はそれ自体が手がかりにもなる
- 推奨案で進めたこと（ユーザーは異を唱えていない）: exp/vision の V18 から続ける、LeJEPA の形（EMA・stop-gradient なし）+ stack ごとの SIGReg（D = 1024）
- 2026-11-23、ユーザーが明示的に決めた（「early fusion, 良いですね。マスク率に注意しつつ」）: early fusion のまま（8 枚 × 3 チャネル、patch 16 で 4×4 = 16 トークン、空間の補完だけ）。マスク率に注意する: 隠すトークンの数をちょうど k 個に固定し、マスク率 r ∈ {0.25, 0.5, 0.75}（k = 4, 8, 12）を掃引の軸にする

**Why:** M17 は i.i.d. の BP で学べることを確かめないままストリームで崩壊への対処に追われ、原因（実装・学習の設定・相関）を分けられなかった。

**How to apply:** 各段の判定が外れたら次の段に進まない。V19 で何を測るかと V20 の手法は、Fable の報告を読んでから決める。背景は [[project-m17-wt-encoder]]、[[project-m17-stream-sigreg]]、[[project-m17-gauss-kl]]、[[project-v17-to-jepa]]。

2026-11-23（ユーザー）: 詰まるところがなければ、V18 から最後の V（V22）まで、確認を待たずに進めてよい。段ごとに Workflow で回し、判定が外れたら次の段に進まず報告する。

2026-11-23、Fable さんの調査（memory/agents/fable/temporal-sigreg.md）を受けて、ユーザーが推奨どおりに決めた:
- D = 1024 のデータポイントの SIGReg のまま進む。V19 で方向ごとの相関を測り、Fable さんの予測（標準の SIGReg + FIFO では遅い方向から分散が消え、選別は D 倍に効く）を確かめてから、V20 で次元を変えるかを決める
- V20 の本命は手法 3（δ 秒前の stack も符号化した自己回帰の残差の SIGReg）。δ 秒前の入力を持つことは単一ストリームの範囲に入れる。手法 1 は参照に 1 本、手法 2 は最小の変更の腕、手法 4 は対照、手法 5 は診断だけ
- V18 は LeJEPA と同じ V 統計量のまま、V19 から U 統計量に替える
- δ は stack の幅 0.8 秒より長くとる（候補は 1 秒・4 秒、V19 の残差の白色性で決める）。r̂ は当てた値を本命にし、固定の φ は回さない。平均の拘束は V20 で導出してから決める
- V20 の前に、Fable さんの主張（崩壊の閾値 0.646、D 倍の選別）を tests/ の理論値のオラクルで確かめ、Codex さんに読み取り専用で意見を求める。2026 年の文献は根拠に使う前に読み直す

2026-11-23、V18 の結果（exp/vision/README.md「V18: 結果」）: 掃引 18 本（6000 step）では、学習率 1e-4・λ0.5 の 3 本（r = 0.25・0.5・0.75）だけが合格し、λ0.005 の 6 本と λ0.05 の 3 本は導出どおり K3（stack の中で一定の族）で崩壊した。長い run 4 本（60000 step、768 万 stack）は崩壊せず、予測の損失と SIGReg は下がり続けた（`pred_ratio` 0.19〜0.62、`sigreg_heldin` 1.18〜1.24）。一方で、射影の後の z の zurich `recon_blur` は 6000 step の 0.44〜0.47 から 60000 step の 0.56〜0.65 に悪くなり、`color`（0.417）にも `init`（0.223）にも負けた。`dyn_1/copy_1` も 1.04〜1.13 になった。規則 5 は 4 本とも不成立で、V19 には進まない。次は、射影の前のトークン h を同じ probe にかけて、情報が射影で捨てられただけか、エンコーダ自身が失ったかを切り分ける（評価だけの変更。LeJEPA は backbone を評価する）。そのあと、標本数 N を軸にするかどうかをユーザーが決める。
