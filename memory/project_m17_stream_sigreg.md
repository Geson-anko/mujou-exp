2026-11-13、ユーザーの仮説: i.i.d. でない 1 本のストリームでも SIGReg が効くかもしれない。変化の乏しい観測どうしを独立にさせると、見分ける特徴を学ぶ。EMA はモデルを 2 つ持つのでユーザーはあまり好まず、こちらを早く確かめたい。

- 計画と基準は exp/video/results/m17.md の「ストリームの SIGReg（回す前に決めたこと、2026-11-13）」、MILESTONES.md の M17。作業はブランチ `exp/2026-11-13/m17-stream-sigreg`（worktree）
- 回すのは表現 `z` を貯める腕だけ。入力を貯める腕は 1 run が 4090 で約 5〜44 時間の見積もり。一部の行だけ符号化し直す手当ては作らない
- `z` を貯めると、バッファの時間の幅 $k$ と、貯めた表現の古さが一緒に変わる。$k$ の差を時間の範囲だけの効果として書かない
- λ の下限（`ssig bound`）と窓の下端（`ssig_window`）が除くのは、積みごとに $d$ 個の数の符号だけ。文脈から決まるもっと高次元の符号は、どの λ でも健全な解より安い。それかどうかは学んだ符号の rank で見る
- 未決定: λ の格子、入力を貯める腕を回すか、意味のない差の判定（`sens_*` ≤ `_pix`）の物差し

**Why:** 導出のない λ で回すと、結果が仮説の検証にならない（[[feedback-simple-fundamental]]）。

**How to apply:** EMA の run が終わっても、λ がユーザーに決まるまで `m17/ssig_*` を submit しない。格子を直すなら、データのあるホストで各腕の学習前の `stream_stats repr` を測り、`ssig_window` に通す。背景は [[project-m17-wt-encoder]]。
