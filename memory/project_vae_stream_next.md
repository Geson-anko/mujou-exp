2026-11-14、層ごとの学習率の結果（どの設定でも最後は広がりが潰れて held-out の J が上がる）を受けて、ユーザーは「JEPA ではなく、一旦 VAE といったモデルで取り組む必要があるかもしれない」と判断した。

- M17 の JEPA は λ（目的の式の釣り合い、η = 1e-5 の層ごとの学習率に固定）の実験で締めくくる
- 評価の確認（学習前の ViT の recon_blur が平均の色だけで説明できるか）も締めくくりに含める
- 次のマイルストーンは、Walking Tours のストリームから VAE を学ぶ。計画はユーザーと詰める

**Why:** 再構成なしの JEPA では、optimizer・学習率・層ごとの学習率のどれでも崩壊を止められなかった。再構成の項がある VAE なら、目的の式そのもの（ELBO）が自明な解を罰する。

**How to apply:** VAE の run は M17 の「vision.recon を 0 以外にしない」（[[project-m17-wt-encoder]]）の対象外で、新しいマイルストーンとして扱う。β のアニーリングなど理論の裏付けのない工夫は入れない（[[feedback-simple-fundamental]]）。学習の設定を先に探す（[[feedback-learn-setting-first]]）。

**2026-11-15 のユーザーの回答**（計画の下書き `exp/video/plans/m18-vae-stream.md` の確かめたいこと 1〜10）:
1. x は積み全体、エンコーダは M17 の t128 の ViT でよい
2. デコーダは軽い形に収める（大きいと、デコーダの性能で再構成の誤差が下がりうる）
3. 尤度は dequantize したガウスと学ぶスカラーの σ でよい
4. デコーダはエンコーダと同じくシステムの中で学ぶ（VAE は Decoder Free ではない。[[project-decoder-for-debug]] の例外）
5. 段 1 は RMSProp・η = 2.9e-5・1800 秒でよい。AdamW と SGD も回す
6. 並べ替えの対照はデバッグとして許可（原因の切り分けにだけ使う）。目的はあくまでストリームから本質的に学べる方法を探ること。並べ替えで学べることを手法の成果にしない
7. B = 32 は学習効率を見るために回す
8. M17 はいったん main にマージした（PR #25、2026-11-15）。マスクした事後分布は後で決める
9. リアルタイムを目指す。B が増えたら B 倍の時間を許す（[[feedback-realtime-speed]]）
10. 新しいブランチ `exp/2026-11-15/continuous-stream-m18-vae` で始める

**段 1 の結果（2026-11-15）**: 12 本とも R に届かず、過学習の確かめも外れた。読みは「実装かモデルが原因」で、段 2 には進まない。追加の確かめで「最後の写像の初期値が雑音として残る」は棄却した。重みは初期値から 18% 未満しか動かず、システムのデコーダは同じ符号から後から学ぶデコーダより取り出せていない。次の一歩（段 3 の掃引を過学習の確かめの腕で先に回すか）はユーザーと決める（exp/video/results/m18.md）

2026-11-15（段 1 の結果を受けて、ユーザー）: η の掃引を前倒しで回してよい（事前登録からの逸脱として明記）。デコーダは大きくしてもよいが、目的はエンコーダの性能（よい潜在空間）。デコーダの大きさは、システムのデコーダの再構成ではなく、符号の側の指標（後から学ぶデコーダの `recon_blur`、`dyn_1/copy_1` など、同じ物差し）で選ぶ。

2026-11-15（ユーザー）: ストリームで学ぶので、ある程度の忘却はよい。M18 の判定は U（符号の側の指標と学習前の ViT の比べ）を主にし、R（オフラインの PCA-1024）は参考、過学習の確かめ（256 個の積み）は診断だけにする。段 2 へ進む条件も U。results/m18.md の「判定の役割の変更」

**デコーダの大きさの結果（2026-11-15）**: RMSProp・η = 1e-3 で深さ 2・4・8 とも U を満たし、posthoc の `recon_blur` が最小の深さ 4（0.132）を選んだ。段 2 に進む条件（U）は満たすが、深さ 2 が役割の変更の前に U を満たしていたので、規則の上で決まっていた結果である。Q9（深さ 8 が 2 より良い）は外れ、深さ 8 は 0.150 で 16 は回さない。R と過学習の確かめはどの深さも外れ、段 1 の読み「実装かモデル」は解けていない。符号は画素の PCA の `recon_blur`（0.051）や平均の色の符号の `dyn_1/copy_1`（0.169）に届かず、U を満たすことはよい潜在空間の証拠ではない（exp/video/results/m18.md）

2026-11-15（ユーザー、デコーダの軸の後）: 段 2（ELBO）に進む。設定は深さ 4・RMSProp・η = 1e-3 のまま、深さ 4 での η の測り直しはしない。計画の「学べた」は新しい役割（U が主）にそろえる。U の表には画素の PCA の符号と平均の色の符号を物差しとして並べる。

**段 2 の実装（2026-11-15）**: `program=vae`（`exp/video/vae/`、`exp/lib/elbo.py`、preset `m18/vae_t128`）。エンコーダの頭は $\mu$ の行を自己符号化器の重みのまま、$\log s^2$ の行を 0（事前分布の分散）にした。$u$ と $\varepsilon$ はホストが引いてノードに渡す。段 2 の物差しは val の held-out の bpd で pPCA-1024 が 6.887、平均の積みのガウスが 8.127（8 を上回る）。損失を $P$ で割らない判断は確かめた（割らなければ、正確な勾配が 0 の key の bias を除いて $\sqrt{\hat v}/\varepsilon \ge 4 \times 10^6$）。回す前に決めたことは exp/video/results/m18.md の「段 2：VAE（回す前に決めたこと）」

**段 2 の結果（2026-11-16）**: ストリームの B = 1 の VAE は U を満たし（posthoc の `recon_blur` 0.138、`dyn_1/copy_1` 0.300、学習前の μ は 0.318、0.653 で段 1 と全桁一致）、新しい役割で「学べた」に入る。ただし同じ設定の自己符号化器（0.132、0.283）に近く、seed 1 本の中では dyn_1/copy_1 が 6 つの checkpoint のすべてで VAE のほうが 0.015〜0.027 大きく、recon_blur は 600 秒より後に VAE だけが上がった（ELBO で符号が良くなった印は無い）。画素の PCA の符号（0.051）や平均の色の符号（0.169）には届かない。R は外れ（val の bpd 7.198 > 6.887、差のほとんどは歪みで、率は pPCA-1024 の 1.09 倍とほぼ同じ）、崩壊はしない（8.127 より 0.93 下、次元ごとの KL は pPCA-1024 とほぼ同じ所）。σ は σ*_train と 7〜8 秒で交わったが、σ*_train が下がってきたためで、Q4 の 0.94 の見積もりは確かめていない。過学習の確かめは pool_bpd 7.173 で外れ、pool_stack_mse の 1800 秒は自己符号化器の深さ 2・4・8 と揃って 0.241（どれも η = 1e-3 で、まだゆっくり下がる。深さ 2 は η = 1e-2 で 0.204〜0.212 まで下がった）。予測 Q11〜Q15 は B = 1 ですべて当たり（Q13 は 1800 秒の 1 点の判定で、60 秒ごとでは 21 回中 11 回）、B = 32 に当てると Q13 は外れ。積みの PCA-1024 の最後のフレームは run の後に測って recon_blur 0.066。次の候補（0.241 が深さ 4 の VAE でも η で動くかを過学習の確かめの腕で掃引する、seed を足す、PC-ALM に載せる）はユーザーと決める（exp/video/results/m18.md の「段 2：VAE の結果」）

2026-11-16（ユーザー、段 2 の結果を受けて）: M18 の VAE の目的は、mujou + PC-ALM でエンコーダが学べるかを確かめることで、PCA を上回る性能は求めない。BP の段 0〜2 は PC-ALM の比べる相手として読む。結果は TensorBoard で詳しく見たい（`tools/tb`、run の名前に job の label が付く）。seed を足すのは「やってもよい」。PC-ALM にまだ載せていないことには驚いていたので、PC-ALM への移行を先延ばしにしない。

**段 4 の実装（2026-11-16）**: PC-ALM の VAE を実装した（`exp/video/vae/pc.py`、preset `m18/vae_t128_pc`、mujou への追加なし）。小さなネットで、15 歩目（29 ms）の勾配は BP と float32 の丸めの範囲で一致し、14 歩目では `enc1` だけが外れる。bench と run はまだ（exp/video/plans/m18-vae-stream.md の「実装（2026-11-16）」）
