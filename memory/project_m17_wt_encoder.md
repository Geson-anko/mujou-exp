2026-11-11、ユーザーの方針で M17（exp/video/MILESTONES.md）を始める。目的は PC-ALM で学ぶ一番よいエンコーダ。

- 損失は JEPA（V-JEPA）+ SIGReg だけ。M15 で足した再構成の項は、玉の画像が単純すぎたための手当てとみる。本来の JEPA は再構成の誤差で学ばない
- PC-ALM で学ぶのはエンコーダだけ。デコーダと線形の動力学は評価のときに BP で学ぶ
- 評価は 2 つで、両方が小さいことを求める: 特徴量からの再構成の誤差（重要な特徴を捉えている）、特徴量の上の線形の動力学の予測誤差（線形によい特徴量）。片方だけ小さいのは disentangle の失敗か崩壊を疑う
- 特徴量の次元は入力より十分に小さい。画像は 128×128 以上。フレームは 30 fps、V-JEPA の入力は 0.1 秒の間隔で 16 枚を積み、tubelet は 2。評価には予測器を通した復元も載せる

2026-11-12 の見直し（ユーザー）: 目的は再構成なしで視覚の主要な特徴を取り出すこと（LeJEPA の形も可）。課題は時空間の補完（未来のフレームの補完を含む）。次フレームの予測だけでは、その予測に要る情報しか入らない。held-out の補完の誤差を主な指標に入れ、画素の再構成の誤差は重視しすぎない。学習率・warmup・BP でも学べない設定という不具合の可能性を先に調べる。study の目的は held-out の潜在空間のマスクの予測の損失そのもの。評価の再構成の誤差は `recon_blur`（σ = 2 px でぼかした二乗誤差、平均の画像で割る）で判定し、画素の `recon` は併記する。

**Why:** 実動画で、再構成に頼らない表現が、描き戻せることと線形に予測できることを両立するかを確かめるため。

**How to apply:** M17 の run で `vision.recon` を 0 以外にしない。片方の指標だけで設定を選ばない。補完の誤差を必ず見る。デコーダの扱いは [[project-decoder-for-debug]]、データは [[project-video-data]]、見た目との照合は [[feedback-metrics-need-qualitative-check]]。

- Imagenette（線形 probe）は部品が壊れていないかの確認にだけ使い、M17 の主目的にしない（ユーザー、2026-11-12）。主目的は Walking Tours の held-out での潜在のマスク予測の損失。
- 2026-11-13（ユーザー）: トークンごとの SIGReg は棄却。トークンの添字（入力×位置）では標本が i.i.d. でなく、位置だけの解が安く通るため。SIGReg はデータポイント（積み 1 つ）ごとにかけ、表現は平らにしたトークン列（D = T × d）とする。制約は D が十分小さいことだけで、T と d の分け方は自由（D≈1024 で (512,2)・(128,8)・(64,16) を比べる）。過去のデータポイントは、画像が直交する（相関が別の動画どうしの水準まで落ちる）時間の間隔で、長期のバッファに保存する。保存するのは入力（今のエンコーダで符号化し直す）と表現 z（detach）の 2 つの腕で比べる。B=1 と B=32 の両方を回す。これでも崩れるなら、SIGReg をやめて I-JEPA の EMA のターゲットモデルにする。
- 2026-11-13（ユーザー）: 画素の相関は 11 分〜36 分以上かけて下がり、単一ストリームでは i.i.d. な標本を集められない。表現の空間でも相関を測ったうえで、SIGReg をやめて I-JEPA の EMA のターゲットモデルに移る。今後の課題として、EMA 以外で、SIGReg のように目的の式として書けて、時間相関のある単一ストリームでも崩壊を防げる手法を探す。
- 2026-11-13（ユーザー）: EMA はモデルを 2 つ持つのであまり好みではない。仮説: i.i.d. でないストリームでこそ SIGReg が効くかもしれない。変化の乏しい観測どうしを独立にさせることで、わずかな違いを見分ける特徴を学ばせる。EMA の実験の後に、データポイントの SIGReg を B=1 で、バッファの時間の幅を変えて確かめる（ノイズで見分けていないかの検査つき）。
- 2026-11-13（ユーザー、EMA の結果を受けて）: EMA は採らない。SIGReg のような本質的な手法がうまくいく設定を、optimizer（RMSProp・SGD・Adam）と学習率の掃引から探す（[[feedback-learn-setting-first]]）。今後の判定の基準には「学習前の ViT を上回る」を入れる。B=1 の seed は同じフレーム列を見てよい（seed ごとにデータをずらさない）。`Following` はまだ mujou に入れない。
- 2026-11-13（ユーザー）: 対比学習の負例（InfoNCE/CPC など）は採らない。負例の選び方がアドホックになり、高次元では収束も難しいため。崩壊を防ぐ本質的な正則化を考案する（Fable に考案させてよい）。予測器の入力の写像（`PackedPredictor.embed`）の初期化は、std 0.02 から LeCun（std 1/√fan_in）に替える。
- 2026-11-14（ユーザー、Fable に相談のうえ）: 最初の 1 分の縮みの大部分はパッチの埋め込み（fan-in 6144）の出力の動きだった。Adam 系の学習率をテンソルごとに $\eta$/fan-in（ベクトルは $\eta$）にする（spectral condition / muP。`optim_vision.scale=fan_in`、`exp.lib.optim.fan_ins`）。変えるのは学習率だけで、初期化はいまのまま（一度に 1 つ）。SGD は入れず、weight decay は 0、warmup なし。層をそろえても積みの中の広がりが潰れるなら、次の軸は $\lambda$（目的の式の釣り合い）。設計は results/m17.md の「層ごとの学習率」
- 2026-11-14 結果（`m17-plr-v1`、seed 100）: 層ごとの学習率でも学べた $\eta$ は無い（8 本とも L・U・C で外れ）。1 秒で埋め込みが最も動くことはなくなり、縮みは遅くなった（$\eta$ = 1e-5 で 60 秒の `tok_within` 0.29、掃引 0.002〜0.003）が、1800 秒までに 0.007 まで縮んだ。遅くなったことは、テンソルごとの学習率が掃引より小さいことと分けられない（同じ数値の $\eta$ では行列の学習率が $1/n$）。1 つのモジュールを戻す帰属が加法的なのは $\eta$ = 1e-5 だけで、そこでは縮みは多くのモジュールに分かれる。$\eta$ = 1e-5 の L の ○（300・600 秒）は最初の 1 分の低下が残っていただけ。L を満たす $\eta$ が無いので、回す前の反証（次は $\lambda$）は不明のまま。1 つのモジュールを戻す帰属の加法性は「(戻す + それだけ) / (すべて + 時刻 0) = 1」で確かめる（`plr_attribution` の `add_*`）。掃引はどの lr でも加法的でない。次の軸はユーザーが決める
- 2026-11-14 評価の確認（`mean_color_ref`、results/m17.md の「評価の確認：平均の色の結果」）: U の再構成の基準は平均の色しか求めていなかった。tubelet ごとの平均の色（$D$ = 384、学習した特徴なし）を最小二乗の affine 写像で描き戻すと val の `recon_blur` は 0.254 で、学習前の ViT（t128、0.318）より小さい。同じ評価のデコーダを通すと 0.333 で、学習前の ViT と seed の幅 0.021 の中で並ぶ。`dyn_1/copy_1` も平均の色の符号で 0.169（学習前の ViT 0.653）。(B) は評価のデコーダと族が違い、学習前の ViT と学習した run の符号には (B) をかけていないので、run との比べは同じデコーダの 0.333 とだけ行う（下回るのは 3 本）。平均の色の線形の描き戻しを今後の再構成の物差しに入れるかは未決定（ユーザーが決める）
- 2026-11-14 結果（`m17-lam-v1`、results/m17.md の「λ の掃引の結果」）: $\eta$ = 1e-5 の層ごとの学習率に固定し、$\lambda$ を導いた窓の 5 点（0.112〜0.373）で RMSProp と AdamW の両方に回したが、学べた $\lambda$ は無い（10 本とも L・U・C で外れ、10 本とも ncomp で外れて積みの中で崩れた。spread は成立）。回す前の反証が成り立ち、`datapoint_store` = z（$N$ = 256、$k$ = 6）の推定のもとで、導いた窓の中の釣り合いは崩壊の原因ではないとして M17 の JEPA の線を閉じた。$\lambda$ を上げると 1800 秒の `tok_within` は単調に大きくなる（0.0065 → 0.019）。$J(1800)/J(0)$ も大きくなる（1.06 → 1.40）が、ほぼ式の上の効果である。1800 秒の held-out の $S$ は、どの $\lambda$ でも L に要る上限 $S^*$ を上回った。次は [[project-vae-stream-next]]
- 2026-11-14 締めくくり（ユーザーの判断）: M17 は終了。再構成の項のない JEPA は、単一ストリームの Walking Tours から、どの学習の設定と $\lambda$ でも学べなかった。$\lambda$ の掃引では、学習側の $S$ は $\lambda$ によらず 600 秒以降 66〜94 でほぼ横ばいになり（$\lambda$ の重みを 4.7 倍にしても約 15 % しか下がらない）、切り離したバッファの推定では $\lambda S$ の項が制御されていなかった。`store=input` は試していない。次は M18 のストリームの VAE（exp/video/plans/m18-vae-stream.md）
