# マイルストーン: 最初の実験（段 0〜2）

[PLAN.md](PLAN.md) の段 0〜2（合成動画まで）を、実装と検証の単位に分けたもの。段 3（EgoDex）は使い方が決まってから足す。

## 進め方

- 1 マイルストーン 1 PR。ブランチは `exp/<日付>/continuous-stream-<マイルストーン>`（例: `exp/2026-11-02/continuous-stream-m1-optim`）
- 部品（M0〜M5）は「理論から導いたオラクル」のテストで検証する。「損失が下がった」は完了の条件にしない
- 実験（M6〜M8）は、回す前に PLAN.md の判定基準を確定させ、回した後に結果の数字を `README.md` に書く
- 完了の条件はどれも `just run` が通ることを含む（下では省く）
- 時間のかかるテスト（数十秒以上）には `@pytest.mark.slow` を付ける。反復中は `just test-fast`
- テストは `tests/continuous_stream/` に置き、`experiments/continuous_stream/` のモジュールと 1 対 1 にする（`test_optim.py` など）

```text
M0 足場 ──┬─▶ M1 optimizer ──────────┬─▶ M2 段 0 の部品 ─▶ M6 段 0 の実験
          ├─▶ M3 合成動画 ──┐        │
          └─▶ M4 ノード ────┴─▶ M5 評価と組み立て ─▶ M7 段 1 の実験 ─▶ M8 段 2 の実験
```

M1・M3・M4 は互いに独立で、並べて進められる。

## M1: optimizer

**状態**: 完了（PR #4）

5 節の optimizer を `pc.optim.Optimizer` / `BoundOptimizer` の実装として書く。ストリームにもノードにも依存しない、素のテンソルの上の部品。

**作るもの**（`optim.py`）

| クラス         | 中身                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| `Whitened`     | $D = (L + \epsilon I)^{-a}\, G\, (R + \epsilon I)^{-b}$。$L, R$ は時定数 $\tau_L, \tau_R$ の正確な指数移動平均 |
| `Projected`    | 今の $G$ を足す前の $L, R$ の上位 $k$ 個の固有方向を外す                                                     |
| `AdamDirection`| `pc.optim.AdamW` と同じ moment の向き（grafting と組むため、大きさを外へ出す）                               |
| `Grafted`      | 中の optimizer の向きに、SGD の大きさ $\frac{\text{elapsed}}{\tau}\lVert G \rVert_F$ を掛ける               |

- 2 次元以上の重みだけを対象にし、畳み込みは $(c_\text{out}, c_\text{in} k^2)$ に並べ替える。バイアスなどは SGD
- 逆の根はタイマーの 1 秒ごとに固有値分解で計算し直し、間は前の値を使う

**オラクル**

| テスト                         | 理論から言えること                                                                                    |
| ------------------------------ | ----------------------------------------------------------------------------------------------------- |
| $a = b = 0$                    | `pc.optim.SGD` と同じ更新（`allclose`）                                                               |
| $\tau \to 0$、$a = b = 1/4$、$\epsilon \to 0$ | 更新の向きが $G$ の極分解の直交因子 $UV^\top$（SVD から作ったもの）と一致する（Muon 型）  |
| 移動平均の刻み                 | $G$ が一定なら、`elapsed` $= e$ の 1 歩と $e/2$ の 2 歩で同じ $L, R$                                  |
| 射影                           | 更新 $\Delta W$ が $U_L^\top \Delta W = 0$、$\Delta W\, U_R = 0$ を満たす                             |
| 射影の $\tau \to 0$            | 1 歩前と同じ $G$ が来たら、更新は 0                                                                   |
| grafting                       | $\lVert \Delta W \rVert_F = \frac{\text{elapsed}}{\tau}\lVert G \rVert_F$                             |
| 畳み込み                       | 4 次元の重みで、並べ替えた 2 次元の `Linear` と同じ更新                                               |
| 状態                           | `state_dict` → `load_state_dict` で、以後の更新が元と一致する                                         |

**完了の条件**

- 上のテストが通る。`pc.Layer` に `optimizer=` として渡して 1 歩学べる（型も通る）

## M2: 段 0 の部品

**状態**: 完了（PR #5）

線形回帰のストリームと、ストリームを手で回すホストのループ、BP の基準。

**作るもの**

- `stream0.py`: $x_k$ が平均のゆっくり動く OU 過程（相関時間 $\tau_x$）、$y_k = w_*^\top x_k + \text{noise}$。i.i.d. 版（同じ周辺分布で時間相関なし）も
- `host.py`: `mujou.testing.run` の上で「`write` → 1 フレーム分の `step` → 読む」を繰り返すループ。フレームの周期、`reset`・`mask` の書き込み、`metrics.jsonl` への記録。M7・M8 でも使う
- `bp.py`: 同じモジュールをノード内 BP で学ぶ基準（1 ノード、同じ optimizer の向きを使える形）

**オラクル**

| テスト                       | 理論から言えること                                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| OU 過程                      | 長い系列で平均の自己相関が $e^{-\Delta/\tau_x}$ に一致する（統計的な許容幅で）                                            |
| 1 層の PC-ALM と BP          | `pc.Chain` の 1 層（`Input → Output`）は緩和する `r` を持たないので、同じストリーム・同じ SGD で重みの軌跡が BP と一致する |
| 2 層の平衡点                 | 1 つのサンプルを長く見せ、学習を止めると、隠れ層の `lam` が BP の credit と一致する（PC-ALM の平衡点の性質）              |
| 決定性                       | 同じ seed で 2 回回すと `metrics.jsonl` が一致する                                                                         |

**完了の条件**

- 1 層の線形回帰が、i.i.d. のストリームで $w_*$ に収束する（最適解が分かっているので、これはオラクルになる）

## M3: 合成動画

**状態**: 完了（PR #6）

**作るもの**（`video.py`）

- 箱の中の 3 つの円の物理（重力 $\gamma(t)$、空気抵抗、反発係数 $e(t)$、1 フレーム 8 小刻みの半陰的 Euler）
- 32×32 のガウスの塊の描画、30〜90 秒ごとの動画の切り替え（配置と速度を引き直す）
- 毎フレームの潜在状態（位置・速度）と物理のパラメータ、動画の切り替えの旗
- 評価用クリップ（物理の位相 8 通り × 4 本 × 128 フレーム）を固定の seed で作る関数

**オラクル**

| テスト             | 理論から言えること                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------- |
| 保存則             | 重力 0・抵抗 0・反発係数 1 で、運動エネルギーが保たれる（壁との衝突をまたいでも）               |
| 半陰的 Euler       | 重力あり・抵抗 0・反発係数 1 で、全エネルギーの誤差が時間とともに増え続けない（有界）           |
| 反発係数           | 壁に垂直に当たった円の速さが $e$ 倍になる                                                       |
| 描画               | 円が 1 つの画像で、画素の重心が円の位置と 1 画素以内で一致する                                  |
| 物理の時間変化     | $\gamma(t)$ と $e(t)$ が式どおりで、動画の切り替えをまたいで連続                                |
| 決定性             | 同じ seed で同じフレーム列                                                                      |

**完了の条件**

- 30 分（54,000 フレーム）を、学習の計算に比べて無視できる時間（目安 1 分以内）で作れる

## M4: ノード

**状態**: 完了（PR #7）

3〜4 節の自作ノード。公開 API（`pc.functional`・`pc.clock.LearnClock`・`pc.msg`）だけで書く。

**作るもの**（`nodes.py`）

- `SIGReg`: 方向 $M = 256$ をフレームごとに引き直し、今の $z_k$ と容量 255 のランダム置き換えのバッファで EP を計算し、$\kappa\,\mathrm{SIGReg}$ の `g_in` を返す
- `Compare`: 入力 2 つ（`Dynamics` の $s_k$ と `Z` の $z_k$）、読み出し $W_o$、$(1 - \kappa)$ の予測誤差の `g_in` を両方へ
- `Dynamics`: minGRU、`r`・`lam`、フレームの切り替えで $z_{k-1}, s_{k-1}$ を記憶、動画の切り替えで $s := 0$、$z_{k-1}$ への `g_in` は 0

**オラクル**

| テスト                 | 理論から言えること                                                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| EP の積分              | ガウスの重みでは積分が閉じた形（標本の対ごとの指数の和）になる。17 点の台形則がそれと許容幅で一致する                  |
| EP の大きさ            | $N(0, I)$ の標本では EP の期待値が小さく、尺度をずらした標本では大きい（単調性）                                       |
| SIGReg の勾配          | `g_in` が有限差分と一致する。バッファの要素には勾配が流れない                                                          |
| バッファ               | 容量までは全部入る。以後、要素の年齢が平均 255 の幾何分布に従う（統計的な許容幅で）。同じ seed で同じ置き換え          |
| `Compare` の勾配       | 両方への `g_in` が、エネルギー $(1 - \kappa)\frac{1}{D}\lVert W_o s - z \rVert^2$ の有限差分と一致する                  |
| `Dynamics` と minGRU   | 同じ $z$ の列で、引き継ぐ $s_k$ が素の PyTorch の minGRU の逐次計算と一致する                                          |
| 時刻合わせ             | `Z` の `time` が変わった更新でだけ記憶を更新する。動画の切り替えで $s = 0$、そのフレームは予測しない                   |
| 局所性                 | `Z` へ返す `g_in` のうち `Dynamics` からの分が 0。各ノードの autograd が自分のモジュールの外に届かない（`.grad` が他のノードのパラメータに付かない） |

**完了の条件**

- 上のテストが通る。`mujou/.claude/skills/locality-and-async/SKILL.md` と突き合わせ、結果を PR の説明に書く

## M5: 評価と組み立て

**状態**: 完了（PR #8）

**作るもの**

- `model.py`: 3〜4 節のネットワーク（`Input → G1 → Z`、`Dynamics`、`Compare`、`SIGReg`）を組む `Network`。CNN の寸法は 7 節のとおり
- `evaluate.py`: モジュールの複製、評価用クリップでの rollout（$n = 1, 5, 10, 20$）、ridge の probe、実効ランク、勾配の時間自己相関 $\rho(\Delta)$ の記録
- `bp.py` の拡張: 同じネットワークの BP 版（$z_{k-1}$、$s_{k-1}$ を detach）
- `run.py` の中身: 設定から M3 のストリームを M2 のホストのループで流し、60 秒ごとに評価する

**オラクル**

| テスト                 | 理論から言えること                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| 実効ランク             | 等方ガウスで約 $D$、階数 $r$ のデータで $r$                                                            |
| probe                  | $z$ が状態の線形変換なら $R^2 \approx 1$、無関係なノイズなら $R^2 \approx 0$                           |
| rollout                | $f$ を恒等写像にした模型で、誤差が「$n$ フレーム先との差」に一致する                                   |
| ネットワークの平衡点   | 1 フレームを長く見せ、学習を止めると、各ノードの `lam` が BP 版の同じフレームの credit と一致する       |
| 評価が学習を乱さない   | 評価あり・なしで、同じ seed の学習の軌跡が一致する                                                     |

**完了の条件**

- 合成動画の 10 秒のストリームが最後まで流れる（`slow` の結合テスト）
- 1 フレームあたりの計算時間を測り、30 分のストリームが 1 時間以内に収まるかを README に書く。収まらなければ寸法を見直す
