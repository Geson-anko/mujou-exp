# 計画書: 動画のストリームから世界のシミュレータを PC-ALM で学ぶ

- 作成: 2026-10-30
- 状態: 草案（未着手）。12 節の「仮決め」はユーザーの確認待ち
- mujou: `881c4ee`（v0.1.0 以降の main）
- 学習則: PC-ALM（`mujou.pc`）が中心。ノード内 BP は同じネットワークの基準としてだけ使う

## 1. 何を調べるか

動画を 1 本の連続したストリームとして流し、PC-ALM のネットワークに世界のシミュレータを自己教師ありで学ばせる。

- 連続は continual ではなく continuous の意味。タスクの境界もエポックも無く、フレームは時間の順に一度だけ届く
- ストリームは 1 本（バッチは 1）。動画（エピソード）が切り替わったら、再帰の状態をリセットする
- 教師は未来そのもの。フレーム $k$ の予測の答えが、次のフレームの観測として連続的に届く

中心の問いは**最適化**にある。ストリームでは近い時刻の勾配がほぼ同じ向きを向く。i.i.d. を前提にした optimizer（momentum、Adam の正規化）はこの相関を信号と取り違える。そこで、i.i.d. を期待しない optimizer を作る。鍵は、すでに押した方向に直交する成分だけで進むこと（直交化）だと考えている。

## 2. 記号

PC-ALM の量と、モデルの時間方向の状態を分ける。

| 記号                    | 意味                                                                                              |
| ----------------------- | ------------------------------------------------------------------------------------------------- |
| $k$                     | フレームの番号。時刻 $t_k = k\,\Delta t$、$\Delta t = 1/30$ 秒                                     |
| $o_k$                   | フレーム $k$ の観測                                                                               |
| $z_k$                   | 潜在の表現 $z_k = g(o_k)$                                                                         |
| $s_k$                   | minGRU の状態（モデルの時間方向の記憶）                                                           |
| $\hat z_k$              | $z_k$ の予測                                                                                      |
| $g$                     | エンコーダ $g: o_k \mapsto z_k$                                                                   |
| $f$                     | ダイナミクス $f: (z_{k-1}, s_{k-1}) \mapsto (\hat z_k, s_k)$                                      |
| `mu`・`r`・`lam`        | PC-ALM の各ノードの予測・ずれ・双対変数（mujou の名前のまま。`Activity` のフィールド `h` は `mu`） |
| $\kappa$                | SIGReg の重み（LeJEPA の論文の $\lambda$。`lam` と区別するため改名）                              |

## 3. アーキテクチャ

$f$ は minGRU と読み出し $W_o$ に分かれる。

$$
s_k = \mathrm{minGRU}(z_{k-1}, s_{k-1}),\qquad \hat z_k = W_o\, s_k
$$

minGRU（Feng ら, [arXiv:2410.01201](https://arxiv.org/abs/2410.01201)）の式（原文で確認済み）:

$$
u_k = \sigma(W_u z_{k-1}),\qquad \tilde s_k = W_s z_{k-1},\qquad s_k = (1 - u_k) \odot s_{k-1} + u_k \odot \tilde s_k
$$

- ゲートと候補が入力だけで決まる。$s_{k-1}$ への依存は要素ごとの線形で、ヤコビアンは対角の $1 - u_k$。$0 < 1 - u_k < 1$ なので縮小的で安定する
- 原文の log 空間版（候補を正にする）は並列 scan のためのもの。ストリームでは逐次に回すので素の版を使う
- 原文は層の間に残差接続を入れる。ここでは 1 層から始める
- 動画が切り替わったら $s := 0$

損失は LeJEPA（Balestriero & LeCun, [arXiv:2511.08544](https://arxiv.org/abs/2511.08544)）に合わせ、予測誤差と SIGReg を $1 - \kappa$ と $\kappa$ で重み付ける（原文の式 9）。

$$
L_k = (1 - \kappa)\, \frac{1}{D} \lVert \hat z_k - z_k \rVert^2 + \kappa\, \mathrm{SIGReg}(z_k;\ \mathcal{B}_k)
$$

- $D$ は $z$ の次元、$\kappa = 0.05$（原文の既定）。$\mathcal{B}_k$ は過去の $z$ のバッファ（下記）
- 崩壊（$g$ が定数を出して予測誤差を 0 にする）を SIGReg が防ぐ。stop-gradient も EMA の教師も要らない
- $g$ が学ぶ信号は「予測できる $z$ にする」（予測誤差）と「$z$ を等方に広げる」（SIGReg）の 2 つ。$f$ は予測誤差だけで学ぶ
- SIGReg は表現の空間で $z$ の各方向をそろえる。5 節の直交化は重みの更新の空間で同じことをする。片方だけで足りるのか、両方が要るのかも段 2 で見る

### SIGReg（原文で確認済み）とストリームでの使い方

$$
\mathrm{SIGReg} = \frac{1}{M} \sum_{m=1}^{M} \mathrm{EP}(\{a_m^\top z_n\}_{n=1}^{N}),\qquad
\mathrm{EP} = N \int \lvert \hat\varphi(t) - e^{-t^2/2} \rvert^2\, w(t)\, dt
$$

原文はミニバッチの $N$ 個（$N \ge 16$ で偏りは小さい）で計算する。ストリームは 1 本なので、1 フレームには $z_k$ が 1 つしかない。そこで**過去の $z$ のバッファ**と合わせて計算する。

- $\mathcal{B}_k$: 過去の $z$ を detach して持つ、容量 $N - 1 = 255$ のバッファ。$\{z_k\} \cup \mathcal{B}_k$ の $N$ 個で EP を計算し、勾配は $z_k$ にだけ流す
- バッファの入れ方（ランダム置き換え）: 容量に達するまでは全部入れる。達した後は、毎フレーム一様に選んだ 1 か所を今の $z_k$ で置き換える。どこを置き換えるかは `SIGReg` ノードの `self.generator` で引き、seed で再現する
- 各要素は 1 フレームごとに確率 $1/(N-1)$ で消えるので、バッファにいる年齢は平均 $N - 1$ フレームの幾何分布になる。期待値では時定数 $(N - 1)\,\Delta t \approx 8.5$ 秒の指数移動平均と同じ重み付けで、FIFO より時間的に広く散らばる（直近だけに偏らず、たまに古い $z$ も残る）
- 教科書どおりのリザーバーサンプリング（$n$ 個目を確率 $(N-1)/n$ で入れる）は使わない。全履歴から一様な標本になり、ストリームが長いほど昔の $g$ で作った $z$ ばかりになる
- EP に掛かる $N$ と $\hat\varphi$ の $1/N$ が打ち消し合うので、$z_k$ への力は $N$ によらず同じ桁に保たれる
- 容量は 256 で固定する
- 動画が切り替わってもバッファは捨てない（$z$ の分布は動画をまたいで整えたい）
- 経験特性関数を時定数で平均する案もあるが、方向を毎フレーム引き直せなくなる。バッファなら引き直せる

| 項目        | 原文                                          | この実験                                             |
| ----------- | --------------------------------------------- | ---------------------------------------------------- |
| 方向 $a_m$  | 単位球から一様。勾配の 1 歩ごとに引き直す     | フレームごとに引き直す（1 フレームの緩和の間は固定） |
| 方向の数 $M$ | コードの既定 256、推奨の出発点 1024           | 256                                                  |
| 重み $w(t)$ | 論文 $e^{-t^2/\sigma^2}$、コード $e^{-t^2/2}$ | コードに合わせる                                     |
| 積分        | $t \in [-5, 5]$ の 17 点の台形則              | 同じ                                                 |
| 標本        | ミニバッチ $N$                                | 今の $z_k$ と、ランダム置き換えの 255 個のバッファ   |

## 4. PC-ALM への載せ方

```text
host ─o_k─▶ Input ─▶ G1 ─▶ Z ─z_k─┬──────────────────────────────▶ Compare ◀── s_k ── Dynamics
                                  ├──▶ SIGReg（バッファ）                              ▲
                                  └────────── z_k（フレームの切り替えで z_{k-1} として記憶）┘
```

| ノード     | 種類                          | 持つもの                                         | 送る / 返す                                                     |
| ---------- | ----------------------------- | ------------------------------------------------ | --------------------------------------------------------------- |
| `Input`    | `pc.Input`                    | なし                                             | $o_k$                                                           |
| `G1`, `Z`  | `pc.Layer`                    | エンコーダの各段、`r`、`lam`                     | `mu`。`Z` の `mu` が $z_k$                                      |
| `Dynamics` | 自作                          | minGRU、`r`、`lam`、記憶した $z_{k-1}, s_{k-1}$   | `mu` $= s_k$。$z_{k-1}$ への `g_in` は 0（過去は変えられない） |
| `Compare`  | 自作（入力 2 つの出力ノード） | 読み出し $W_o$                                   | $(1-\kappa)$ の予測誤差の `g_in` を `Dynamics` と `Z` の両方へ  |
| `SIGReg`   | 自作（重みなし）              | 方向 $a_m$、$z$ のバッファ                       | $\kappa\,\mathrm{SIGReg}$ の `g_in` を `Z` へ                   |

- **時刻合わせは構造で解く。** `Dynamics` は `Z` の活動の `time` が変わった（新しいフレームが届いた）更新で、直前のフレームの $z_{k-1}$ と $s_{k-1}$ を記憶し、$s_k$ を予測する。`Compare` が比べる $\hat z_k$ と $z_k$ はどちらも今のフレームのもので、credit も今のフレームについて一貫する
- **予測の経路の credit は $f$ で止まる。** $z_{k-1}$ は記憶した定数なので、予測誤差が過去の $g$ に戻る経路は無い。$g$ に戻るのは答えの経路（$z_k$ を $\hat z_k$ に寄せる）と SIGReg だけ
- **$s$ の引き継ぎ。** フレームの中では `Dynamics` の `r` と `lam` が緩和し、minGRU の重みの credit を作る。フレームの切り替えで次へ引き継ぐ $s_k$ は `mu`。PC-ALM の平衡点では `r = 0`（`lam` が credit を持つ）なので、`mu + r` も平衡点では `mu` と一致する。temporal PC（Millidge ら 2024）のように観測で状態を補正する効果は、PC-ALM では入らない。切り替えで `Dynamics` の `r` と `lam` は 0 に戻す
- **動画の切り替え。** 新しい動画の最初のフレームで、ホストは `reset=True`（全ノードの `r` と `lam` を 0 に）と `mask=False` を書く。`Dynamics` は $s := 0$ とし、前のフレームが無いので予測しない。`mask=False` によりそのフレームでは誰も学ばない（動画あたり 1 フレームの損失）
- **局所性。** 自作ノードの中の autograd は自分のモジュールと自分の入力の範囲に閉じる（`pc.functional.vjp` は入力を detach する）。ノードをまたぐ `.backward()` は無い。実装時に `mujou/.claude/skills/locality-and-async/SKILL.md` と突き合わせる（このリポジトリでは mujou の hook が効かない）

フレームの間の 33.3 ms が、ネットワークが 1 フレームを処理する予算になる。その間に credit が往復し、1 回学ぶ。

## 5. 最適化: i.i.d. を期待しない optimizer

### 何が壊れると考えるか

ストリームでは、時間的に近い勾配がほぼ同じ向きを向く（$G_{k+1} \approx G_k$）。バッチが 1 なので、1 フレームの勾配に平均でならす効果も無い。

- **momentum**: 時定数 $\tau_m$ の移動平均は、その間に勾配のゆらぎが打ち消し合うことを前提にしている。i.i.d. なら場面ごとの偏りは $\tau_m$ の平均でおよそ $\sqrt{\Delta t / \tau_m}$ に縮むが、相関時間が $\tau_m$ より長いと縮まず、今の場面の偏りがそのまま更新に残る。場面が移った後も、古い方向が $\tau_m$ の間残る（`pc.optim.AdamW` の momentum は和ではなく移動平均なので、持続する方向が増幅されるわけではない。heavy ball のような和の momentum なら $\tau_m / \Delta t$ 倍に増幅される）
- **Adam の正規化**: 勾配のゆらぎをノイズの大きさとみなす。時間相関した成分は一貫した信号に見え、その方向に毎回ほぼ全幅で進む
- **SGD**: 積み上げは無いが、同じ方向を毎フレーム押し続ける。今の場面への過剰な適合と、過ぎた場面の忘却が起きる

### 直交化の候補

重み行列 $W$（`Linear` は $(d_\text{out}, d_\text{in})$。畳み込みは $(c_\text{out}, c_\text{in} k^2)$ に並べ替える）の勾配は $G = \sum_i \delta_i x_i^\top$。$\delta$ はノードの credit、$x$ はノードの入力（畳み込みではパッチ、$i$ はその位置）。直交化の対象は 2 つあり、どちらも $G$ だけから推定できる。畳み込みも同じ形なので、`pc.Layer` に入力を見る口は要らない。

| 対象                 | 推定                                                  | 意味                                                                                                                                                  |
| -------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 列空間（誤差の方向） | 時定数 $\tau_L$ の移動平均 $L = \overline{G G^\top}$ | すでに繰り返し押した誤差の方向を抑える。本計画の主な動機                                                                                              |
| 行空間（入力の方向） | 時定数 $\tau_R$ の移動平均 $R = \overline{G^\top G}$ | 過去の入力への写像を変えない。OGD（Farajtabar ら, [arXiv:1910.07104](https://arxiv.org/abs/1910.07104)）を層ごとに局所化したもの、GPM・OWM と同じ形 |

- バッチが 1 なので、`Linear` の 1 フレームの勾配は階数 1（$\delta x^\top$）。$L$ と $R$ は時間で積んで初めて意味を持つ
- 更新の方向は $D = (L + \epsilon I)^{-a}\, G\, (R + \epsilon I)^{-b}$ にまとめられる
  - $a = b = 0$: 素の SGD
  - $a = b = 1/4$: 時間で白色化した更新。$\tau$ を秒で持つ Shampoo にあたる。持続する方向ほど固有値が大きく、抑えられる
  - 上位 $k$ 個の固有方向を外す射影 $(I - U_L U_L^\top)\, G\, (I - U_R U_R^\top)$: 硬い直交射影（OGD）。$U_L, U_R$ は今の $G$ を足す**前**の $L, R$ から取る（今の $G$ を足した後だと、$\tau \to 0$ で $G$ 自身を消してしまう）
- 時定数 $\tau_L, \tau_R$ が「どれだけ前まで同じ方向とみなすか」を決める
- $\tau \to 0$ では $L = GG^\top$、$R = G^\top G$ になる。$G = U \Sigma V^\top$ とすると $a = b = 1/4$ の更新は $U V^\top$ で、1 歩ごとの直交化（Muon 型）と一致する。つまり Muon 型の対照は、時間で白色化した更新の $\tau \to 0$ の極限であり、H3 は $\tau$ だけを動かす比較になる
- 移動平均は時間で正確に進める: $L \leftarrow L + (1 - e^{-\text{elapsed}/\tau_L})(G G^\top - L)$。$G$ が一定なら、刻み方によらず同じ $L$ になる

OGD を元の形で使わないのは、守る勾配 $\nabla_\theta f(x)$ がネットワーク全体の出力の勾配でノードをまたぐからである。層ごとの形なら `pc.optim.Optimizer` の中に閉じる。

### 歩幅をそろえる（grafting。使うかは段 0 で決める）

optimizer どうしは「進む向き」と「進む大きさ」の両方が違う。そのまま比べて直交化が勝っても、向きが良かったのか、単に歩幅が小さくて安定しただけなのかを区別できない（直交化は持続する方向を抑えるので、歩幅も小さくなりがち）。

そこで、比べる optimizer からは向きだけを取り、大きさは全員 SGD と同じにする。層ごとに次のようにする。

$$
\Delta W = -\frac{\text{elapsed}}{\tau}\, \lVert G \rVert_F\, \frac{D}{\lVert D \rVert_F}
$$

これで差が出れば、それは向き（直交化）の効果である。AdamW と Muon 型の向きも同じくそろえる。大きさもそのままの `pc.optim.AdamW` は、実用上の参考として別に回す。

### 対照

| optimizer                                   | 調べること                                                |
| ------------------------------------------- | --------------------------------------------------------- |
| `pc.optim.SGD`                              | 基準                                                      |
| AdamW の向き（$\tau_m$ を振る、grafting）   | momentum の病理が出るか                                   |
| `pc.optim.AdamW`（grafting なし）           | 実用上の参考                                              |
| 1 歩ごとの直交化（Muon 型 = 白色化の $\tau \to 0$） | 直交化は 1 歩の中で足りるのか、時間をまたぐ必要があるのか |
| 時間で白色化（$L$ のみ / $R$ のみ / 両方）  | 誤差の側と入力の側のどちらが効くか                        |
| 硬い射影（階数 $k$）                        | 白色化との差                                              |

### 実装の決め事

- 逆の根 $L^{-1/4}$ などは固有値分解で求め、タイマーの 1 秒ごとに計算し直す（Shampoo と同じく、毎歩は計算しない）。間は前の根を使う
- $\epsilon$ は $L$ の最大固有値の $10^{-4}$ 倍（相対の減衰）
- 対象は 2 次元以上の重み（畳み込みは並べ替えて 2 次元）。バイアスと正規化層のパラメータは SGD
- 振る値: $\tau_L, \tau_R \in \{0.3, 1, 3, 10\}$ 秒、$\tau_m \in \{0.1, 0.3, 1, 3\}$ 秒、$k \in \{4, 16\}$。段 1 で測った勾配の相関時間を見て範囲を直す

## 6. データ

| 積分           | 1 フレームを 8 小刻みの半陰的 Euler で                                                              |
| 長さ           | 段 1 は 10 分、段 2 は 30 分（54,000 フレーム）。$T$ の 3 周期                                       |

- 物理は動画をまたいで連続に変わる。周期的なので同じ物理に何度も戻ってくる。戻ってきた直後の予測誤差で保持を、そこからの下がり方で再学習の速さを測れる
- 潜在状態（位置・速度）と物理のパラメータを毎フレーム記録し、probe の正解にする
- 生成は torch で行い、seed から決定的に作る。ストリームの外で、評価用のクリップを固定の seed で作っておく

### 実動画: EgoDex（段 3）

| 項目       | 内容                                                                                       |

| 動画       | 30 Hz、1080p の MP4。エピソードごとに `<i>.mp4` と `<i>.hdf5` の組                         |
| 注釈       | カメラ・両手・約 64 関節（指先・指の関節）の SE(3) 姿勢、関節ごとの信頼度、カメラの内部パラメータ |

## 7. モデルの寸法

### 合成動画（32×32×1）

| 部分       | 構成                                                                                             | パラメータ |
| ---------- | ------------------------------------------------------------------------------------------------ | ---------- |
| `G1`       | Conv(1→32, 3×3, stride 2) → GELU → Conv(32→64, 3×3, stride 2) → GELU（→ 8×8×64）                  | 約 2 万    |
| `Z`        | Conv(64→128, 3×3, stride 2) → GELU（→ 4×4×128）→ flatten → `Linear(2048, 64)`（$D = 64$。正規化しない） | 約 21 万   |
| `Dynamics` | minGRU（$d_s = 256$。$W_u, W_s$: 64 → 256）                                                      | 約 3 万    |
| `Compare`  | 読み出し `Linear(256, 64)`                                                                       | 約 2 万    |

- 正規化層は入れない（バッチが 1 なので `BatchNorm` は使えない。要れば `GroupNorm`）
- 初期化は `torch.manual_seed` の後に作る。BP の基準は同じ初期重みから

### EgoDex（64×64×3）

- `G1` を 1 段深くし（3 段の stride 2 で 8×8）、チャンネルを倍にする。寸法は段 2 の結果を見て決める。GPU（RTX 4090）

## 8. 段階と判定基準

各段の数値の閾値は仮のもの。段の冒頭で前の段の結果を見て確定し、ここを直してから回す。seed は 3 つ（0, 1, 2）で、判定は 3 つすべてで同じ向きのときだけ「支持」とする。

### 段 0: 現象の確認（小さな問題）

- データ: 線形回帰のストリーム $y = w_*^\top x + \text{noise}$。$x \in \mathbb{R}^{32}$ は平均がゆっくり動く OU 過程（相関時間 $\tau_x$ を振る）。$w_*$ は固定で、各時刻の最適解が分かる。バッチは 1
- モデル: `pc.Chain` の 1 層（`Linear(32, 1)`）。BP の基準も同じ
- 測るもの: $\lVert w - w_* \rVert$ の時間平均、i.i.d. の $x$ での損失
- 仮説 H0: 歩幅をそろえると、AdamW の向き（$\tau_m = 1$ 秒）は SGD より $\lVert w - w_* \rVert$ の時間平均が 1.5 倍以上大きい。$x$ を i.i.d. にすると差は 10% 以内に縮む
- 棄却: 差が出ないなら、momentum の病理は前提にしない。直交化の動機を忘却の側（行空間）に絞る
- grafting の要否: 同じ比較を grafting なし（各 optimizer の歩幅のまま）でも回す。順位が歩幅で入れ替わるなら、段 2 は grafting ありで比べる
- ついでに測ること: `learn_interval` を 25 ms と `None` で比べ、ストリームでの PC-ALM の BP からの遅れを見る。計算の速さも測る

### 段 1: 合成動画での勾配の観測

- 内容: 3 節のモデルを SGD で 10 分のストリームから学ばせる。学習率は $\{0.01, 0.03, 0.1\}$ / フレームから、prequential 予測誤差が最も小さいものを選び、段 2 で固定する
- 測るもの: ノードごとの勾配の時間自己相関 $\rho(\Delta) = \cos(G_k, G_{k+\Delta})$、$z$ の実効ランク
- 仮説 H1: エンコーダの層で $\rho(10\ \text{フレーム}) > 0.5$（相関時間がフレームの周期より十分長い）
- 棄却: $\rho(10\ \text{フレーム}) < 0.2$ なら、勾配は実質 i.i.d.。最適化の問いはこの設定では立たない
- 前提の確認: $z$ の実効ランクが $D/2 = 32$ 以上（崩壊していない）。満たさなければ段 2 の前に $\kappa$ と SIGReg のバッファの長さを直す

### 段 2: 世界のシミュレータと optimizer の比較

- 内容: 5 節の対照をすべて 30 分のストリームで回す
- 仮説 H2: 時間で白色化した optimizer のどれかが、SGD と AdamW のよい方より、最後の 10 分の prequential 予測誤差と 10 ステップ rollout の誤差の両方を 10% 以上下げる
- 仮説 H3: 1 歩ごとの直交化（Muon 型）で得られるのは、その改善の半分未満
- 仮説 H4: 白色化した optimizer は保持（物理が戻った直後の予測誤差）も良い
- 棄却: 歩幅をそろえた SGD と区別できないなら、直交化は効いていない
- 最後に、残った optimizer を `mujou.run`（非同期・実時間）で回し、順位が変わらないことを確かめる

### 段 3: EgoDex

- 内容: 段 2 で残った optimizer だけで、EgoDex のテスト分割を 1 本のストリームとして回す
- 見ること: 合成動画での結論が保たれるか。手と指の位置の probe、rollout の誤差

## 9. 評価

### 手順

- タイマーの 60 秒ごとに、`step` の合間でモジュールを複製し、評価する。学習中のネットワークは止めない（手動の実行なので、合間に読んでも競合しない）
- 評価は複製したモジュールを素の PyTorch で順伝播して行う。PC-ALM のノードが送るのは予測 `mu` なので、順伝播の値はネットワークが緩和の前に出す予測と同じ
- 評価用のクリップ: 物理の位相を 8 通りに固定し、各 4 本 × 128 フレーム

### 指標

| 指標                 | 定義                                                                                                                                          | 見るもの         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| prequential 予測誤差 | 届いたフレームで、学ぶ前の $\hat z_k$ と $z_k$ の誤差。毎フレーム記録                                                                         | 追従             |
| rollout の誤差       | 評価用クリップで 16 フレーム観測した後、観測なしで $f$ を $n$ ステップ回す（$\hat z$ を次の入力に戻す）。$g(o)$ との誤差を $n = 1, 5, 10, 20$ で | シミュレータの質 |
| 線形 probe           | $z$ と $s$ から位置・速度・物理のパラメータを ridge 回帰で読む $R^2$。評価用クリップを半分に分けて学習とテスト                                | 表現の質         |
| 実効ランク           | 評価用クリップの $z$ の共分散の固有値のエントロピーの指数                                                                                     | 崩壊             |
| 保持                 | 物理が前の周期と同じ位相に戻った直後の 10 秒の prequential 予測誤差                                                                           | 忘却             |
| 再学習の速さ         | 同じ区間で、予測誤差が戻る前の水準の 1/e まで下がる時間                                                                                       | 可塑性           |
| 勾配の時間自己相関   | ノードごとの $\rho(\Delta)$。$\Delta = 1, 10, 100, 1000$ フレーム                                                                            | 前提             |
| 計算の速さ           | 実時間 1 秒あたりに進むタイマーの秒数                                                                                                         | 実用性           |

- $z$ の尺度は学習で変わるので、予測誤差は SIGReg が保つ $z$ の分散（1）に対する比として読む。崩壊していれば実効ランクで分かる

### 基準

- **上限**: 同じフレームを 1 秒のクリップ単位でシャッフルして見せたもの。各クリップを動画の切り替えとして扱う（`reset=True`、$s := 0$）
- **よくある対策**: 容量 4096 フレームのリザーバーの replay バッファ。ストリームを 2 本にし、2 本目にバッファから引いたクリップを流す（比べるときは、ライブのストリームの学習の量をそろえる）
- **BP**: 同じモジュール・同じ初期重み・同じストリームを、ノード内 BP の 1 ノードで。$z_{k-1}$ と $s_{k-1}$ は detach（PC-ALM と同じく 1 フレームで切る）

## 12. 決めたこと・仮決め

### 決めたこと（ユーザー、2026-10-30）

- $s$（minGRU の状態）は PC-ALM の活動として緩和で扱い、$f$ の再帰は minGRU にする
- ストリームは 1 本。動画が切り替わったら $s$ をリセットする
- 30 fps。フレームの間の 33.3 ms が 1 フレームの予算で、1 フレームに 1 回学ぶ
- エンコーダは軽量 CNN から
- 実動画は EgoDex。非営利の研究としてだけ使う
- 実験側で書いたノードや optimizer を mujou に上げるのは、汎用性が明らかになってから
- $s$ の引き継ぎは予測 `mu`。temporal PC の観測による補正は入らないことを受け入れる
- SIGReg の標本は、今の $z_k$ と、容量 255 のランダム置き換えのバッファ（容量までは全部入れ、以後は毎フレームランダムな 1 か所を置き換える）

### 仮決め（推奨で進める）

| 項目           | 仮決め                                                                      | 主な理由                                               |
| -------------- | --------------------------------------------------------------------------- | ------------------------------------------------------ |
| 予測の構造     | `Dynamics` が $z_{k-1}, s_{k-1}$ を記憶して $z_k$ を予測                     | 比べる 2 つが同じフレームになり、credit が一貫する     |
| 時定数         | MNIST と同じ `TimeConstants`、`learn_interval` 25 ms                        | 実績のある設定から始め、ストリーム特有の差だけを見る   |
| 合成動画       | 32×32、円 3 つ、重力と反発係数を周期 10 分で変える。30〜90 秒で動画を区切る | 潜在状態が分かり、同じ物理に戻ってくるので保持を測れる |
| 評価           | 60 秒ごとにモジュールを複製し、素の PyTorch で順伝播                        | 決定的で、学習を止めない                               |
| 判定           | seed 3 つすべてで同じ向きなら支持                                           | 少ない seed で偶然を拾わない                           |
