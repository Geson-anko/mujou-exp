# 計画書: 動画のストリームから世界のシミュレータを PC-ALM で学ぶ

- 作成: 2026-10-30
- 状態: 草案（未着手）
- mujou: `881c4ee`（v0.1.0 以降の main）
- 学習則: PC-ALM（`mujou.pc`）が中心。ノード内 BP は同じネットワークの基準としてだけ使う

## 1. 何を調べるか

動画を 1 本の連続したストリームとして流し、PC-ALM のネットワークに世界のシミュレータを自己教師ありで学ばせる。

- 連続は continual ではなく continuous の意味。タスクの境界もエポックも無く、フレームは時間の順に一度だけ届く
- 教師は未来そのもの。時刻 $t$ の予測の答えが、$t + \Delta t$ に観測として連続的に届く

中心の問いは**最適化**にある。ストリームでは近い時刻の勾配がほぼ同じ向きを向く。i.i.d. を前提にした optimizer（momentum、Adam の正規化）はこの相関を信号と取り違える。そこで、i.i.d. を期待しない optimizer を作る。鍵は、すでに押した方向に直交する成分だけで進むこと（直交化）だと考えている。

## 2. アーキテクチャ

| 記号             | 意味                                                         |
| ---------------- | ------------------------------------------------------------ |
| $o_t$            | 時刻 $t$ の観測（動画のフレーム）                            |
| $z_t$            | 潜在の表現                                                   |
| $h_t$            | 履歴（再帰の状態）                                           |
| $g$              | エンコーダ $g: o_t \mapsto z_t$                              |
| $f$              | ダイナミクス $f: (z_t, h_t) \mapsto (\hat z_{t+\Delta t}, h_{t+\Delta t})$ |

損失は埋め込み空間の予測誤差（JEPA）と、崩壊を防ぐ正則化の和。

$$
L_t = \lVert \hat z_{t+\Delta t} - g(o_{t+\Delta t}) \rVert^2 + \lambda \,\mathrm{SIGReg}(z)
$$

- 崩壊（$g$ が定数を出して予測誤差を 0 にする）を防ぐため、LeJEPA（Balestriero & LeCun, [arXiv:2511.08544](https://arxiv.org/abs/2511.08544)）の SIGReg で $z$ の分布を等方ガウスに寄せる。stop-gradient も EMA の教師も要らない
- SIGReg の credit は $z$ から $g$ にだけ戻る。$g$ が学ぶ信号は「予測できる $z$ にする」（答えの経路の予測誤差）と「$z$ を等方に広げる」（SIGReg）の 2 つで、$f$ は予測誤差だけで学ぶ
- SIGReg は表現の空間で $z$ の各方向を無相関にそろえる。4 節の直交化は重みの更新の空間で同じことをする。片方だけで足りるのか、両方が要るのかも段 2 で見る
- SIGReg はバッチを周辺分布の標本とみなす。ストリームの $z$ は時間相関しているので、経験特性関数を時定数 $\tau_\text{sig}$ の指数移動平均で持つ案を試す（現在の寄与にだけ勾配を流す）
- 得られたシミュレータは、観測を与えずに $f$ を回す open-loop の rollout で評価する

（LeJEPA の式・既定の値は着手時に原文で確かめ、この節を直す。）

## 3. PC-ALM への載せ方

```text
video ─o_t─▶ Input ─▶ g（Layer…）─z_t─┬──────────────▶ f（Layer…, h を持つ）─ẑ_{t+Δt}─┐
                                       │                                                 ▼
                                       ├──────────────── z_{t+Δt} ──────────────▶ Compare（予測誤差）
                                       └──▶ SIGReg（z の分布の正則化）
```

- フレームはホストが `run.write` でフレームの周期 $\Delta t$ ごとに書く。`reset=False`（動画の最初だけ True）、`learn_interval=None` で毎回学ぶ
- 規模の目安: 30 fps なら $\Delta t \approx 33$ ms。MNIST の example の見せる時間（32 ms、16 周期）と同じ桁で、小さなモデルなら実時間の動画を流せる
- **$h$ の持ち方**: PC-ALM の credit は経路を後ろへだけ流れ、時間をさかのぼらない（BPTT は無い）。$h$ は時間的予測符号化（temporal PC。Millidge ら 2024 を要確認）と同じく、前の時刻からの予測を事前分布として毎時刻に緩和で推定する活動として持つ。ノードをまたぐ `.backward()` を持ち込まない
- **$f$ の再帰は minGRU**（Feng ら, [arXiv:2410.01201](https://arxiv.org/abs/2410.01201)）。ゲート $u_t = \sigma(W_u x_t)$ と候補 $\tilde h_t = W_h x_t$ が入力 $x_t$（ここでは $z_t$）だけで決まり、$h_t = (1 - u_t) \odot h_{t-1} + u_t \odot \tilde h_t$。$h_{t-1}$ への依存が要素ごとの線形（ヤコビアンが対角の $1 - u_t$）なので、前の時刻からの予測が単純で、$0 < 1 - u_t < 1$ により縮小的で安定する。並列 scan の利点はストリームでは使わない（式は原文で確かめる）
- **予測の時刻合わせ**: $\hat z_{t+\Delta t}$ は $t$ に作られ、答えの $z_{t+\Delta t}$ は $\Delta t$ 後に届く。`Compare` は活動の `time` を見て、1 フレーム前の予測と今の表現を組にする
- **2 本の credit**: 予測誤差は $f$（予測の経路）と $g$（答えの経路）の両方へ戻る。予測の経路を $g$ まで戻すと、$g$ がもう次のフレームを見ている間に 1 フレーム前の入力の credit が届く。まずは予測の経路の credit を $f$ で止める版から始め、段 2 で戻す版と比べる。フレームがゆっくり変わるなら $o_t \approx o_{t+\Delta t}$ で、1 フレーム遅れた credit でもほぼ正しい見込み

今の `mujou.pc` に足りないもの:

| 必要なもの                        | 今の mujou                                        | 方針                                                                                    |
| --------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 別の枝の出力を目標にする `Compare` | `pc.Output` の目標は `Input` から活動と一緒に運ぶ | 公開 API で自作のノードとして実験側で書く。mujou に上げるのは汎用性が明らかになってから |
| バッチ統計の損失（SIGReg）        | `pc.Output` の損失はサンプルごとの形              | 同じく自作のノードで書く。サンプルごとの勾配は出るので、エネルギーとして扱える見込み    |
| 時間で進む直交化の optimizer      | `pc.optim.Optimizer` を自作できる。勾配だけが届く | 実験側で `Optimizer` として書く（4 節）。mujou に上げるのは汎用性が明らかになってから |
| 畳み込みでの入力の部分空間        | optimizer に層の入力が届かない                    | 勾配だけで足りなければ、入力を見られる口を `pc.Layer` に足す案を mujou に出す           |

局所性の確認は `mujou/.claude/skills/locality-and-async/SKILL.md` と自分で突き合わせる（このリポジトリでは mujou の hook が効かない）。

## 4. 最適化: i.i.d. を期待しない optimizer

### 何が壊れると考えるか

ストリームでは、時間的に近い勾配がほぼ同じ向きを向く（$g_{t+\Delta} \approx g_t$）。

- **momentum**: 持続する方向を積み上げる。時定数 $\tau_m$ の momentum では、相関時間が $\tau_m$ より長い方向の実効の歩幅が、i.i.d. のときより約 $\tau_m / \Delta$ 倍になる。場面が移った後も、古い方向へ進み続ける
- **Adam の正規化**: 勾配のゆらぎをノイズの大きさとみなす。時間相関した成分は一貫した信号に見え、その方向に毎回ほぼ全幅で進む
- **SGD**: 積み上げは無いが、同じ方向を毎フレーム押し続ける。今の場面への過剰な適合と、過ぎた場面の忘却が起きる

### 直交化の候補

ノード $l$ の重み（まず `Linear`）の勾配は $G = \sum_i \delta_i h_i^\top$。$\delta$ はノードの credit、$h$ は入力。直交化の対象は 2 つあり、どちらも $G$ だけから推定できる。

| 対象                     | 推定                                       | 意味                                                                               |
| ------------------------ | ------------------------------------------ | ---------------------------------------------------------------------------------- |
| 列空間（誤差の方向）     | 時定数 $\tau_L$ の移動平均 $L = \overline{G G^\top}$ | すでに繰り返し押した誤差の方向を抑える。本計画の主な動機                           |
| 行空間（入力の方向）     | 時定数 $\tau_R$ の移動平均 $R = \overline{G^\top G}$ | 過去の入力への写像を変えない。OGD（Farajtabar ら, [arXiv:1910.07104](https://arxiv.org/abs/1910.07104)）を層ごとに局所化したもの、GPM・OWM と同じ形 |

更新は $\Delta W \propto -\,L^{-a}\, G\, R^{-b}$ の形にまとめられる。

- $a = b = 0$: 素の SGD
- $a, b > 0$: 時間で白色化した更新。$\tau$ を秒で持つ Shampoo の因子にあたる。持続する方向ほど固有値が大きく、抑えられる
- $a, b \to \infty$ の極限（または上位 $k$ 個の固有方向を外す）: 硬い直交射影（OGD）
- 時定数 $\tau_L, \tau_R$ が「どれだけ前まで同じ方向とみなすか」を決める。$\tau \to 0$ で直交化は消える

OGD を元の形で使わないのは、守る勾配 $\nabla_\theta f(x)$ がネットワーク全体の出力の勾配でノードをまたぐからである。層ごとの形なら `pc.optim.Optimizer` の中に閉じる。

### 対照

| optimizer                                 | 調べること                                                     |
| ----------------------------------------- | -------------------------------------------------------------- |
| `pc.optim.SGD`                            | 基準                                                           |
| `pc.optim.AdamW`（$\tau_m$ を振る）       | momentum の病理が出るか                                        |
| 1 歩ごとの直交化（Muon 型、時間の記憶なし） | 直交化は 1 歩の中で足りるのか、時間をまたぐ必要があるのか      |
| 時間で白色化（$L$ のみ / $R$ のみ / 両方） | 誤差の側と入力の側のどちらが効くか                             |
| 硬い射影（階数 $k$）                      | 白色化との差                                                   |

比べるときは 1 秒あたりの歩幅（学習率）を揃える。揃えないと「歩幅が小さいから安定」と区別できない。

## 5. 段階と仮説

各段で、着手前に「何が見えれば支持/棄却か」を確定させる。下はその草案。

### 段 0: 現象の確認（小さな問題）

- データ: ゆっくりドリフトする線形回帰・小さな MLP の回帰のストリーム（時刻ごとの最適解が分かる）
- 内容: ストリームを書くホスト、スナップショット評価、i.i.d. に並べ替えた基準、BP の基準。`mujou.testing.run` で決定的に回す
- 仮説 H0: 歩幅を揃えると、momentum を持つ optimizer は SGD より最適解からの追従誤差が大きく、ドリフトの向きが変わったときに行き過ぎる。i.i.d. に並べ替えると差は消える
- 棄却条件: 相関したストリームでも差が出ないなら、momentum の病理は前提にしない。直交化の動機を忘却の側（行空間）に絞る

### 段 1: 合成動画でのストリーム上の勾配の観測

- データ: 潜在状態（位置・速度）が分かる合成動画（跳ね回るスプライトなど）。物理のパラメータ（重力・摩擦）がゆっくり変わる
- 内容: 2 節のモデルを SGD で学ばせ、各ノードの勾配の時間自己相関（$g_t$ と $g_{t+\Delta}$ の cos 類似度）、momentum と現在の勾配の向きのずれを測る
- 仮説 H1: 勾配の相関時間はフレームの周期より十分長く、場面の時間尺度に近い
- 棄却条件: 相関時間が数フレームに収まるなら、ストリームの勾配は実質 i.i.d.。最適化の問いはこの設定では立たない

### 段 2: 世界のシミュレータと optimizer の比較

- 内容: 4 節の対照をすべて同じストリームで回す。$\tau_L, \tau_R$ と $a, b$（または $k$）を振る
- 仮説 H2: 時間で白色化した optimizer は、SGD と AdamW より prequential の予測誤差・rollout の誤差が小さく、崩壊しにくい
- 仮説 H3: 効くのは時間をまたぐ直交化で、1 歩ごとの直交化（Muon 型）では足りない
- 棄却条件: 歩幅を揃えた SGD と区別できないなら、直交化の効果は歩幅の効果にすぎない

### 段 3: 実動画

- データ: 長く途切れない 1 本の実動画（一人称視点・車載など。候補は着手時に決める）
- 内容: 段 2 で残った optimizer だけで回し、合成動画での結論が保たれるかを見る

## 6. 評価の指標

| 指標                 | 定義                                                                                    | 見るもの |
| -------------------- | --------------------------------------------------------------------------------------- | -------- |
| prequential 予測誤差 | 届いたフレームで、学ぶ前の $\hat z$ と $z$ の誤差の時間平均                             | 追従     |
| rollout の誤差       | 観測を与えず $f$ を $k$ ステップ回した予測と、実際の $g(o)$ の誤差。$k$ ごとに          | シミュレータの質 |
| 線形 probe           | $z$ と $h$ から潜在状態（位置・速度・物理のパラメータ）を読む精度。合成動画のみ        | 表現の質 |
| 実効ランク           | $z$ の共分散の固有値のエントロピーの指数                                                | 崩壊     |
| 保持                 | スナップショットで、過去の物理のパラメータの区間の動画に対する予測誤差                  | 忘却     |
| 勾配の時間自己相関   | ノードごとの $\cos(g_t, g_{t+\Delta})$ を $\Delta$ の関数として                          | 前提     |
| 計算の速さ           | 実時間 1 秒あたりに進められる動画の秒数（`time_scale` の上限）                          | 実用性   |

基準は 2 つ置く。

- **上限**: 同じクリップを時間について i.i.d. に並べ替えて見せたもの（$h$ を持つので、短いクリップ単位でシャッフルし、クリップの頭で `reset=True`）
- **よくある対策**: 容量を揃えたリザーバーの replay バッファ

## 7. 再現性と記録

- 環境: RTX 4090（24 GB）と RTX 4060（8 GB）、32 コア。段 0 は CPU、段 1 以降は GPU

## 8. 決めたこと

- $h$ は緩和で推定する活動として持ち、$f$ の再帰は minGRU にする（2026-10-30）
- 実験側で書いたノードや optimizer を mujou に上げるのは、汎用性が明らかになってから（2026-10-30）
- 予測の経路の credit は、まず $f$ で止める。段 2 で $g$ まで戻す版と比べる
