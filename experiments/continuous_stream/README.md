# continuous_stream: 動画のストリームから世界のシミュレータを PC-ALM で学ぶ

計画は [PLAN.md](PLAN.md)、実装と検証の単位は [MILESTONES.md](MILESTONES.md)。

## 仮説

PLAN.md 8 節の H0〜H4。各段の冒頭で閾値を確定させ、ここに写す。

## 実行方法

```bash
uv run python -m experiments.continuous_stream.run --config <path>  # 設定は JSON（config.py の Config）
```

出力は `runs/<日付>-<名前>/` の `config.json`（設定、mujou とこのリポジトリの SHA、未コミットの変更の有無）と `metrics.jsonl`。commit しない。

## 結果

### 段 0: 線形回帰のストリーム（M6、2026-10-30）

**設定**
- $x\in\mathbb R^{32}$、平均は OU 過程（$\sigma_\mu=1$、ゆらぎ 0.3）、$y=w_*^\top x+0.1\,\eta$、600 秒（18,000 フレーム）、30 fps、バッチ 1
- 時間相関は $\tau_x\in\{1,10,100\}$ 秒と i.i.d.（同じ周辺分布）。seed は 0, 1, 2
- `pc.Chain` の 1 層 `Linear(32, 1)`、`learn_interval` 25 ms
- SGD は `tau=10`（1 フレームあたりの学習率 1/300）
- AdamW の向き（`AdamDirection`）は `tau_m` $\in\{0.1,0.3,1,3\}$ 秒、`tau_v=30` 秒。grafting あり（大きさを SGD にそろえる）となし（`tau=10`、要素ごとの歩幅 1/300）
- 指標は後半 300 秒の $\lVert w-w_*\rVert$ の時間平均
- 実行: `uv run python -m experiments.continuous_stream.stage0 run|summarize`（120 本、8 並列で約 25 分）

閾値は PLAN.md 8 節のまま（1.5 倍、10%）で、回す前に変えていない。

**H0 の判定: 棄却**（前半は支持、後半が棄却）
- 前半「歩幅をそろえると、AdamW の向き（$\tau_m=1$ 秒）は時間相関のあるストリームで SGD の 1.5 倍以上」: 支持。3.6〜5.0 倍で、$\tau_x=1$ では発散した。3 seed すべてで同じ
- 後半「i.i.d. にすると差は 10% 以内に縮む」: 棄却。i.i.d. でも 4.4〜4.5 倍のまま。差の大部分は時間相関ではなく、この問題での AdamW の向きそのものの悪さから来る
- 時間相関に固有の害は、$\tau_x\lesssim\tau_m$ のときにだけはっきり出る（grafting なし、$\tau_m=1$、$\tau_x=1$ で i.i.d. の 5〜6 倍）。ストリームが変わった後も、古い方向が momentum に $\tau_m$ の間残るためと読める。$\tau_x\gg\tau_m$（相関時間が momentum より長い）では 1.1 倍程度で、PLAN.md 5 節の「相関した偏りが打ち消されない」という害は、この問題ではほとんど見えない
- SGD は時間相関の影響をほとんど受けない（0.96〜1.25 倍）
- 但し書き: 最適解 $w_*$ が固定の線形回帰では、どの時刻の勾配も同じ $w_*$ を指すので、相関した偏りが害になりにくい。段 2 の世界モデルで見え方が変わるかは別に確かめる

**grafting を使うか: 使う**
- 歩幅で順位が入れ替わった。i.i.d. の grafting なしでは $\tau_m$ による差が無い（2.23〜2.40 倍）。grafting ありでは、$\tau_m$ とともに 1.5 倍から 4.4 倍、そして発散へと順に悪くなる
- PLAN.md 8 節の規則（順位が歩幅で入れ替わるなら、段 2 は grafting ありで比べる）に従う。大きさもそのままの `pc.optim.AdamW` は、実用上の参考として別に回す
- 注意: grafting は、向きが $G$ から遅れると発散しうる（$\tau_m=3$ では i.i.d. でも発散）。歩幅は $\lVert G\rVert$ に比例するのに、向きが誤差を減らす向きとずれるため。段 2 で直交化の向きが発散したら、その結果として記録する

**`learn_interval` と、PC-ALM と BP の差**（2 層 MLP 32-32-1、tanh、$\tau_x=10$、SGD、i.i.d. 損失の後半平均、seed 0/1/2）

| `learn_interval` | PC-ALM                    | BP                        | PC-ALM ÷ BP        |
| ---------------- | ------------------------- | ------------------------- | ------------------ |
| 25 ms            | 0.0154 / 0.0121 / 0.0135  | 0.0154 / 0.0121 / 0.0135  | 1.00 / 1.00 / 1.00 |
| `None`（毎周期） | 0.0162 / 0.0122 / 0.0138  | 0.0158 / 0.0121 / 0.0136  | 1.03 / 1.01 / 1.01 |

- **25 ms を使う**。PC-ALM は 3 桁まで BP と同じで、ストリームでの遅れは見えない。`None` は PC-ALM が BP より 1〜3% 悪く、25 ms より 1〜5% 悪い。計算も多い
- 計算の速さ: 線形回帰 600 秒分のストリームが約 80 秒（CPU 1 スレッド）

### 段 1: 合成動画での勾配の観測（M7、2026-10-30）

**最初の試行で分かったこと（崩壊）**
- $\kappa=0.05$（LeJEPA の既定）で回し始めたところ、180 秒で $z$ の分散がほぼ 0 になった。probe の値も初期から動いていなかった（9 本とも途中で止めた）
- 原因は 2 つ
  - 既定の初期化では $z$ の標準偏差が約 0.002 しかない（フレームの大半が黒いため）
  - $z\approx0$ の近くでは、SIGReg の 1 標本への勾配が $z$ に比例して消える（$\partial\hat\varphi/\partial x\propto t\sin(tx)\approx t^2x$）。概算すると、広げる力は $\kappa C z/D\approx0.0016\,z$ で、予測誤差が縮める力 $2(1-\kappa)/D\approx0.03$ の 1/20 しかない
- 対策 1（コード）: `model.standardize_`。LSUV と同じく、各畳み込みと線形写像の出力の標準偏差を、別の seed の 256 フレームで 1 にそろえる初期化を入れた。最後の写像だけを約 500 倍すると、`G1` へ返る credit も同じだけ増えて発散した（NaN）
- それでも $\kappa=0.05$ では 10〜30 秒で縮む。2 分の試し（学習率 0.03）では、$\kappa=0.5$ と $0.8$ でストリーム上の $z$ の標準偏差は 1.5〜2.5 を保ったが、実効ランクは 5〜36 で揺れた
- そこで段 1 は $\kappa\in\{0.05,0.5,0.8\}$ × 学習率 $\{0.01,0.03,0.1\}$ × seed 3（27 本）で回す。崩壊していたら $\kappa$ を直す、という PLAN.md の規則を前倒しした形になる

**回す前に確定した判定基準**

- 前提（崩壊していない）: 最後の評価で、$z$ の実効ランクが $D/2=32$ 以上、かつ評価クリップの上での $z$ の分散が 0.1 以上。後者は、尺度の崩壊を実効ランクでは検出できなかったので足した

### 段 2: 世界のシミュレータと optimizer の比較（M8、2026-10-30）

**回す前に確定した判定基準**（PLAN.md 8 節を数値の規則にしたもの。`stage2.judge`）
- 共通: 合成動画 30 分、seed 0/1/2。最初の試行は $\kappa=0.05$、学習率 0.01 / フレーム。回し直しは $\kappa=0.8$、学習率 0.1（段 1 の回し直し）
  - 向きはすべて grafting で SGD の歩幅にそろえる（段 0）
  - 白色化と射影は `refresh=5` 秒、$\tau_L,\tau_R\in\{0.3,3\}$ 秒
- 指標
  - `preq`: 最後の 10 分の prequential 誤差を、$z$ の分散で割ったもの
  - `rollout10`: 最後の 10 分の評価での、10 ステップ rollout の誤差（同じく相対値）
  - `retention`: 物理が 3 周期目に入り、8 つの位相に戻った直後の 10 秒の prequential 誤差（相対値）
- 基準: seed ごと・指標ごとに、SGD・AdamW の向き（$\tau_m=0.3, 1$）・`pc.optim.AdamW` のうち最もよいもの
- H2: 白色化か射影のどれかが、`preq` と `rollout10` の両方を、3 seed すべてで基準より 10% 以上下げる
- H3: Muon 型（`orth`）の改善が、H2 で最もよかったもの（平均の改善で選ぶ）の改善の半分未満。両指標・3 seed すべてで
- H4: その最もよかったものの `retention` が、3 seed すべてで基準より小さい
- 但し書き: 段 1 の前提（崩壊していない）は満たされていない。誤差は $z$ の分散で割って比べる

### 表現の崩壊への対処（M9、2026-10-31）

段 2 の比較は崩壊した表現の上になるので中断し、optimizer を SGD に固定して、崩壊の原因を先に切り分けた（MILESTONES.md の M9）。

**完了の条件**（回す前に確定。SGD、PC-ALM、合成動画 30 分、seed 0/1/2 のすべてで）
- 発散しない
- 最後の評価で、実効ランクが 32 以上、かつ評価クリップの上での $z$ の分散が 0.1 以上
- `rollout1` が 1 未満
- 変えたところが局所性・非同期性を崩さない

**切り分け**（GPU で BP の短い試し。数字は 10 分後）
- 物差し: 評価クリップの線形 probe は、画素から引くと位置の $R^2$ が −14.8 になる。クリップが少なく（位相ごとに学習 2 本）相関しているので、特徴が多いと過学習する。probe の値は表現に状態が入っているかを測れていない。以後は判定に使わず、記録だけにする
- SIGReg そのもの: i.i.d. のミニバッチ（256 枚）で SIGReg だけを学習すると、実効ランク 58.8、分散 1.03 まで広がる
- ストリームでの SIGReg（今のフレームだけに勾配、過去の $z$ はバッファ）: SIGReg だけなら実効ランク 39.3、分散 0.74 を保つ（i.i.d. の順なら 46.9、バッファ 4095 でも 39.7）。推定の弱さはあるが、崩壊の原因ではない
- 残る原因は予測誤差の勾配。予測誤差は目標の $z_k$ も予測 $\hat z_k$ の側へ引くので、フレームごとに変わる成分を $z$ から削る。JEPA 系が目標の側を stop-gradient や EMA にするのと同じ問題

**対策（コード）: `ModelConfig.stop_target`**。`Compare` が `Z` へ返す予測誤差の勾配を 0 にする（目標を定数として扱う）。エンコーダは SIGReg からだけ形を受け、動力学と読み出しは予測誤差から学ぶ。`Compare` の中だけで閉じる変更で、局所性・非同期性は変わらない。平衡点で `lam` が、目標を detach した BP の credit に一致することをテストで確かめた（CPU と CUDA）
