動画ストリームで世界モデルを学ぶ

32×32 ピクセルの合成動画を 1 フレームずつ流し、モデルに次のフレームの中身を予測させ続けました。学習と予測は同時に進み、同じフレームが二度来ることはありません。このような流れ続けるデータに合う optimizer を探すことが、この実験の中心の問いです。段 0〜2（マイルストーン M0〜M10）まで終えたので、その結果をまとめます。

1

実験の仕組み

モデルは、画像を潜在の表現に写すエンコーダと、その表現の時間変化を予測するダイナミクスでできています。エンコーダ g は画像 ok を 64 次元のベクトル zk に写し、ダイナミクスの minGRU はひとつ前の z と自分の状態 s から、次の z の予測 ẑk を出します。予測と、実際に届いた zk のずれ（予測誤差）が学習の信号です。

z が定数に縮むと、予測誤差は簡単に 0 になります。これを防ぐために、SIGReg という正則化で z の分布を標準正規分布に近づけます。予測誤差と SIGReg の重みの比は 1−κ : κ です。

学習は mujou の PC-ALM で行います。ネットワーク全体で誤差逆伝播（BP）をする代わりに、各ノードは隣のノードとのずれだけを見て自分の重みを更新し、非同期に動き続けます。比べるために、同じネットワークを BP で学ぶ版も回しました。

指標の読み方

preq
最後の 10 分間の、毎フレームの予測誤差の平均を、z の分散で割った値です。ストリームを見ながら、その場で次を当てられているかを表します。小さいほど良い指標です。
rollout1, rollout10
評価用の動画で、1 フレーム先と 10 フレーム先まで予測を自分でつないだときの誤差です（z の分散で割った値）。1 は「z の平均を答えるだけ」と同じ水準で、1 を下回れば平均より良い予測です。
実効ランク
z が 64 次元のうち、実質いくつの方向に広がっているかを表します。小さくなるのが次元の崩壊です。
z の分散
z の広がりの大きさです。0 に近づくのが大きさの崩壊です。
retention
物理の設定が前と同じ値に戻った直後 10 秒間の予測誤差です。忘れにくさの目安にしました。
崩壊、発散
崩壊は、最後まで走ったものの z が使えなくなった run です（実効ランクが SGD の半分未満、z の分散が 0 など）。発散は、途中で値が NaN になった run です。
2

入力の動画

入力は、箱の中を 3 つの球が跳ねる 32×32 の白黒動画です（30 fps）。球には重力と空気抵抗が働き、壁で跳ね返ります。3〜6 秒ごとにエピソードが切り替わり、球の位置と速度を引き直します。モデルが見るのは左の画像だけです。右の位置と速度はモデルには渡しません。

学習の最初の 20 秒の平均は 1.91 で、z の平均を答えるより悪い予測でした。最後の 20 秒では 0.41 まで下がります。壁で跳ね返った直後や、エピソードが切り替わった直後の数フレームを取り出しても、平均は他のフレームと変わりませんでした。

進め方

M0〜M5 で足場（optimizer、合成動画、ノード、評価）を作り、M6 から実験を回しました。途中で見つかった問題を先に片づけたので、計画の順序とは少し違います。

  1. M6 · 段 0

    線形回帰のストリーム。時間相関が optimizer にどう効くかを、答えの分かる問題で確かめました。Adam の向き（歩幅は SGD にそろえる）は SGD の 3.6〜5.0 倍悪くなりました。ただし時間相関のない i.i.d. でも 4.4〜4.5 倍悪いままで、差の大部分は時間相関ではなく、この問題での Adam の向きそのものから来ていました。PC-ALM の損失は BP と 3 桁まで一致しました。

  2. M7 · 段 1

    勾配の時間相関を測る。動く世界では、勾配の相関は 10 フレーム（0.3 秒）でほぼ消えました。相関がフレームよりずっと長く続く、という前提は弱まりました。

  3. M8 · 段 2

    止まった世界の発見。最初の比較で、評価の 1 フレーム先の誤差が平均より悪い（rollout1 1.9〜2.4）のに、preq は 0.07 と小さい、という食い違いが出ました。調べると、球は抵抗と壁での損失で約 20 秒で床に止まり、30〜90 秒あったエピソードの約 6 割が止まった球でした。エピソードを 3〜6 秒に縮め、段 1 から回し直しました。回し直すと、今度は表現の崩壊が見えてきました。

  4. M9

    表現の崩壊への対処。optimizer を SGD に固定し、崩壊の原因を先に切り分けました。目標の側の勾配を止める stop_target で崩壊が止まりました。

  5. M10

    optimizer と relaxer の比較。崩壊しない設定の上で、段 2 の比較を回し直しました。仮説 H2〜H4 の判定はここで出しました。

4 · M9

表現の崩壊と stop_target

回し直した段 1 では、z が崩壊していました。κ（SIGReg の重み）が小さいと z の分散が 0.0003〜0.002 まで縮み（大きさの崩壊）、大きいと実効ランクが 7〜17 まで落ちました（次元の崩壊）。

原因は予測誤差の勾配でした。予測誤差は予測 ẑ を目標 z に近づけるだけでなく、目標 z も予測の側へ引きます。フレームごとに変わる成分ほど予測しにくいので、その成分が z から削られていきます。JEPA 系の手法が目標の側を stop-gradient や EMA にするのと、同じ問題です。SIGReg だけで学ぶと、ストリームの上でも実効ランク 39、分散 0.74 を保てたので、SIGReg は原因ではありませんでした。

そこで、Compare ノードがエンコーダへ返す予測誤差の勾配を 0 にしました（stop_target）。エンコーダは SIGReg だけから形を受け取り、ダイナミクスと読み出しは予測誤差から学びます。変更は Compare の中で閉じていて、ノード間の局所性と非同期性は変わりません。

stop_target なしの 8 本はすべて崩壊し、ありの 8 本はどれも崩壊しませんでした。ありの 8 本は rollout1 も 1 未満です。ただし rollout10 はどれも 1 を超え、10 フレーム先はまだ平均を答えるより悪い予測でした。

5 · M9

学習率を決める

探索で選んだ学習率 0.1 は、30 分に延ばすと seed 1 と 2 で発散しました。探索を seed 0 だけで回したので、たまたま持つ学習率を選んでいました。発散した run では、似たフレームが続く区間で |z| が 30 フレームかけて 12 から 76 まで伸び、それを受けた層が NaN になっていました。stop_target のもとでエンコーダを動かすのは SIGReg だけなので、z を押し出したのは SIGReg です。

3 seed すべてで条件を満たす最大の学習率は 0.01 でした。最後の評価で、実効ランクは 40.5〜43.4、z の分散は 0.63〜0.74、rollout1 は 0.49〜0.56 です。同じ学習率で BP は 3 本中 1 本が発散しました。PC-ALM の方が発散しにくいという結果ですが、余裕の範囲で持っただけで、SIGReg の押し出しは残っています。

6 · M10

optimizer の比較

ストリームでは、時間的に近い勾配がほぼ同じ向きを向きます。i.i.d. を前提にした optimizer（momentum や Adam の正規化）は、この相関を信号と取り違えると考えていました。そこで、すでに押した方向を抑える optimizer を用意し、SGD と比べました。どれも向きだけを使い、歩幅は SGD にそろえています（grafting）。こうすると、向きが良かったのか、単に歩幅が小さかったのかを区別できます。

  • 白色化は勾配 G の時間平均 L=⟨GG⊤⟩ と R=⟨G⊤G⟩ で G を割ります（L−1/4GR−1/4）。時定数は 0.3 秒と 3 秒です。
  • 射影は L と R の上位 4 個か 16 個の固有方向を G から外します。
  • 直交化（Muon 型）は 1 歩ごとに G を直交化します。白色化の時定数を 0 にした極限にあたります。
  • Adam は要素ごとに勾配を正規化します。grafting した版（momentum の時定数 0.3 秒と 1 秒）と、pc.optim.AdamW そのままの版を回しました。

preq はどの候補も SGD を下回りませんでした。R を入れた白色化は 13〜21% 悪くなりました。射影（rank 4）は rollout10 を 3 seed とも 7〜18% 下げましたが、その代わりに preq が 7〜10% 上がりました。白色化（時定数 3 秒）と射影（rank 16）も 2 seed で rollout10 を下げましたが、残りの 1 seed で崩壊か発散しました。

時間方向の相関を崩すシャッフルは SGD より rollout10 が悪くなりました。過去のクリップを混ぜて見せる replay は preq と retention では SGD と同じくらいか良いものの、rollout10 は 2.0 を超えて最も悪い結果でした。

Adam 系は要素ごとに歩幅をそろえるので、勾配の小さい方向にも大きく歩きます。その結果、SIGReg が |z| を外へ押す力をそのまま強めてしまいました。pc.optim.AdamW では z の分散が 1 前後から 104〜105 まで伸びました。grafting した Adam は、実効ランクが SGD の半分未満に落ちるか、z が定数になるか、発散しました。全体の歩幅を SGD にそろえても防げなかったので、比べる基準はすべての seed で SGD だけになりました。

relaxer の扱い

PC-ALM は 1 フレームの間に 16〜17 回の更新で平衡点に近づきます。フレームの最後の更新で、平衡点までの残り（|r|/|λ| の中央値）は 0.7〜2.9% でした。relaxer は平衡点への道筋を変えるだけなので、縮められるのはこの数 % だけです。決めておいた規則に従い、relaxer は候補から外しました。

7 · M10

実時間での確認

ここまでの run はフレームを手で 1 つずつ進めて回しました。最後に、SGD と射影（rank 4）を mujou.run で実時間に回しました（seed 0、30 分）。実時間では、計算が間に合わなかったフレームの予測は出せません。

SGD の preq0.307間に合わなかったフレーム 3 / 54,000（0.01%）
射影（rank 4）の preq0.335間に合わなかったフレーム 6,686 / 54,000（12.4%）

preq の順位（SGD が上）は、実時間でも変わりませんでした。射影は 8 フレームに 1 つ予測が間に合わず、rollout10 の差（手で回した run では 7〜18%）も、実時間では 1% まで縮みました。どちらも、手で回した同じ seed の run（SGD 0.278、射影 0.297）より preq が 1 割ほど悪くなっています。実時間ではフレームあたりの更新回数がそろわないためと見ていますが、まだ確かめていません。

仮説の判定

判定の閾値はどれも run を回す前に決めて README に書きました。

仮説判定根拠
H0: 歩幅をそろえると、Adam の向きは時間相関のあるストリームで SGD の 1.5 倍以上悪い。i.i.d. にすると差は 10% 以内に縮む棄却前半は支持（3.6〜5.0 倍）。後半は i.i.d. でも 4.4〜4.5 倍のままで棄却
H1: エンコーダの層で、勾配の 10 フレーム離れた相関 ρ(10) が 0.5 を超える棄却回し直した段 1 では、規則で選ぶ設定でも選び直した設定でも ρ(10) が 0.2 未満（−0.12〜0.17）。相関時間は 0.1〜0.3 秒
H2: 白色化か射影が、preq と rollout10 を 3 seed とも 10% 以上下げる棄却preq を下げた候補はない。最も良かった射影（rank 4）は preq が 6.6〜9.5% 悪く、rollout10 は 7.3〜17.7% 良い
H3: 直交化（Muon 型）の改善は、H2 の最良の半分に届かない規則の上では支持意味は薄い。比べる相手（射影）の preq の改善が負なので、半分という比較が成り立っていない
H4: H2 の最良は SGD より忘れにくい（retention）棄却射影 0.318 / 0.294 / 0.268 に対し、SGD は 0.302 / 0.271 / 0.244

段 3 に持ち込むものと残る課題

段 3（実写の EgoDex）には SGD を持ち込みます。設定は M9 のもの（stop_target あり、κ=0.8、学習率 0.01）で、relaxer は mujou の pc.relax.Euler のままです。SGD は preq で負けず、計算も最も軽い optimizer でした。白色化、射影、直交化のどれも、mujou の optimizer として足す根拠になる改善を示さなかったので、mujou に上げる候補はありません。

段 3 の前に、課題が 2 つ残っています。

  • rollout10 は 1.5〜1.9 で、10 フレーム先の予測はまだ z の平均を答えるより悪い状態です。
  • SIGReg が |z| を外へ押す不安定さが残っています。学習率 0.01 でも、BP とシャッフルは seed 1 で発散しました。Adam 系が崩れたのも、この押し出しを強めたためです。

段 3 のマイルストーンはまだ決めていません。
